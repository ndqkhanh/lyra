keywords:
  - changelog

  - keep a changelog
  - releases
---

1. Follow the keepachangelog.com format: Added, Changed, Deprecated, Removed, Fixed, Security.
2. One section per release version; most recent release first.
3. Write for end users, not for the dev team: describe the impact, not the implementation.
4. Link each release to its git tag and full diff.
5. Update the changelog as part of the release PR, not after.
