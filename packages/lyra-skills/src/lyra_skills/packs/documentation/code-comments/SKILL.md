keywords:

  - inline docs
---

1. Review the code; identify places where intent is non-obvious.
2. Write comments that explain WHY the code does something, not WHAT it does (the code already says what).
3. Add docstrings to public functions: one-line summary, parameter descriptions, return type.
4. Remove stale or misleading comments that contradict the code.
5. Never comment out code; delete it and trust git history.
