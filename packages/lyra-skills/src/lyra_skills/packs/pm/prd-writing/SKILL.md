name: PRD Writing
description: Write clear Product Requirement Documents: problem, users, solution, success metrics.
keywords:

---

1. Start with the problem, not the solution. Who has this problem? How do we know it's real (data, user interviews)?
2. Define the user: persona, context, current workflow, pain points. "As a [persona], I want [goal] so that [reason]."
3. Define success metrics: what numbers move if this succeeds? Leading indicators (adoption) and lagging (revenue, retention).
4. Describe the solution at the user-experience level, not implementation. Mockups > prose for UX changes.
5. Scope: must-have (MVP), should-have (fast follow), could-have (future). Be ruthless about cutting scope.
6. List assumptions and risks. What must be true for this to succeed? How do we validate cheaply?
7. Define the rollout plan: internal dogfood → beta → GA. What's the rollback plan if metrics go the wrong way?
