## Brainstorming Techniques

### Classic Brainstorming
```
Rules:
1. Quantity over quality (generate many ideas)
2. No criticism (defer judgment)
3. Welcome wild ideas (think outside the box)
4. Build on others' ideas (combine and improve)

Process:
1. Define problem clearly (5 minutes)
2. Silent ideation (5 minutes)
3. Round-robin sharing (15 minutes)
4. Group discussion (10 minutes)
5. Clustering and voting (10 minutes)

Example:
Problem: How to increase user engagement?

Ideas:
- Gamification (points, badges, leaderboards)
- Personalized recommendations
- Social features (sharing, comments)
- Push notifications
- Email digests
- In-app tutorials
- Referral program
- Community forums
```

### SCAMPER Method
```
Substitute: What can be replaced?
Combine: What can be merged?
Adapt: What can be adjusted?
Modify: What can be changed?
Put to other use: What else can it do?
Eliminate: What can be removed?
Reverse: What can be inverted?

Example: Improve a coffee shop

Substitute: Replace paper cups with reusable mugs
Combine: Combine coffee shop with bookstore
Adapt: Adapt mobile ordering from fast food
Modify: Change seating to standing desks
Put to other use: Use space for evening events
Eliminate: Remove physical menu (digital only)
Reverse: Customers make their own coffee (self-serve)
```

### Six Thinking Hats
```
White Hat (Facts):
- What data do we have?
- What information is missing?

Red Hat (Emotions):
- How do I feel about this?
- What's my gut reaction?

Black Hat (Caution):
- What could go wrong?
- What are the risks?

Yellow Hat (Benefits):
- What are the advantages?
- Why would this work?

Green Hat (Creativity):
- What are alternative ideas?
- How can we think differently?

Blue Hat (Process):
- What's the agenda?
- What have we learned?

Example: Should we build a mobile app?

White: 60% of users access via mobile web
Red: Excited about native features, worried about cost
Black: High development cost, maintenance burden
Yellow: Better UX, push notifications, offline access
Green: Progressive web app, hybrid app, mobile-first web
Blue: Need to research costs, create prototype, test with users
```

### Reverse Brainstorming
```
Instead of: How to increase sales?
Ask: How to decrease sales?

Ideas:
- Make website slow and confusing
- Provide poor customer service
- Charge high prices
- Offer low-quality products
- Ignore customer feedback

Reverse to solutions:
- Optimize website performance
- Train customer service team
- Competitive pricing strategy
- Quality assurance process
- Customer feedback loop
```

## Problem Decomposition

### 5 Whys
```
Problem: Website is slow

Why? Server response time is high
Why? Database queries are slow
Why? Missing indexes on frequently queried columns
Why? Database schema wasn't optimized
Why? Initial design didn't consider scale

Root Cause: Lack of performance planning in initial design

Solution: Add indexes, optimize queries, implement caching
```

### Fishbone Diagram (Ishikawa)
```
Problem: Low customer satisfaction

People:
- Insufficient training
- High turnover
- Low morale

Process:
- Complex checkout
- Slow shipping
- No order tracking

Technology:
- Website crashes
- Slow page load
- Mobile issues

Materials:
- Out of stock items
- Poor packaging
- Damaged goods

Environment:
- Warehouse location
- Seasonal demand
- Competition

Measurement:
- No feedback loop
- Unclear metrics
- Delayed reporting
```

### First Principles Thinking
```
Question: How to reduce transportation costs?

Break down to fundamentals:
- Transportation = moving goods from A to B
- Cost = fuel + labor + vehicle + time

Challenge assumptions:
- Must we own vehicles? (No → rent/lease)
- Must we use trucks? (No → rail, ship, drone)
- Must we move goods? (No → local production)
- Must we move all at once? (No → batch optimization)

Rebuild solution:
- Hybrid fleet (own + rent)
- Multi-modal transport (truck + rail)
- Regional warehouses (reduce distance)
- Route optimization (reduce time)
```

## Creative Thinking Exercises

```
Problem: Improve team collaboration

Random word: Ocean

Associations:
- Waves → Regular sync meetings (rhythm)
- Deep → Deep work sessions (focus time)
- Currents → Information flow (communication channels)
- Tides → Predictable patterns (routines)

Problem: Increase app engagement

Unrelated concepts: Restaurant, Library, Gym

Restaurant:
- Menu → Feature menu in app
- Specials → Daily challenges
- Reservations → Scheduled sessions

Library:
- Quiet space → Focus mode
- Borrowing → Temporary access to premium features
- Late fees → Streak penalties

Gym:
- Workout plans → Learning paths
- Personal trainer → AI coach

```

### What-If Scenarios
```
Problem: Design a new product

What if money was no object?
- Hire best designers, unlimited features, premium materials

What if we had only $1000?
- MVP, focus on core feature, bootstrap

What if we had 1 week?
- No-code solution, existing tools, minimal features

What if we had 10 years?
- Research, perfect UX, build ecosystem

What if users were experts?
- Advanced features, keyboard shortcuts, customization

What if users were beginners?
- Simple interface, guided tutorials, defaults
```

## Decision-Making Frameworks

```
Options: A, B, C
Criteria: Cost, Time, Quality, Risk

| Criteria | Weight | Option A | Option B | Option C |
|----------|--------|----------|----------|----------|
| Cost     | 30%    | 8 (2.4)  | 6 (1.8)  | 9 (2.7)  |

|----------|--------|----------|----------|----------|

```

### Pros and Cons Analysis
```
Option: Build in-house vs Buy SaaS

Build In-House:
Pros:
+ Full control and customization
+ No recurring fees
+ Intellectual property ownership
+ No vendor lock-in

Cons:
- High upfront cost ($500K)
- Long development time (12 months)
- Ongoing maintenance burden
- Team needs to learn new skills

Buy SaaS:
Pros:
+ Fast implementation (1 month)
+ Lower upfront cost ($50K/year)
+ Vendor handles maintenance
+ Regular updates and features

Cons:
- Limited customization
- Recurring costs
- Vendor dependency
- Data security concerns

Decision: Buy SaaS (faster time to market, lower risk)
```

### Cost-Benefit Analysis
```
Project: Implement chatbot for customer support

Costs:
- Development: $100,000
- Integration: $20,000
- Training: $10,000
- Maintenance: $30,000/year
- Total Year 1: $160,000

Benefits:
- Reduce support tickets by 40% = $80,000/year
- 24/7 availability = $50,000/year
- Faster response time = $30,000/year
- Total Benefits: $160,000/year

ROI:
- Year 1: Break even
- Year 2: $130,000 profit
- Year 3: $130,000 profit
- 3-year ROI: 162%

Decision: Approve project (positive ROI)
```

## Facilitation Techniques

### Session Planning
```
1. Define objective (What do we want to achieve?)
2. Identify participants (Who should attend?)
3. Choose technique (What method to use?)
4. Prepare materials (What do we need?)
5. Set agenda (How long for each activity?)

Example Agenda (60 minutes):
- Introduction (5 min)
- Problem framing (10 min)
- Silent ideation (10 min)
- Group brainstorming (20 min)
- Clustering and voting (10 min)
- Action planning (5 min)
```

### Idea Capture
```
Tools:
- Sticky notes (physical)
- Miro/Mural (digital)
- Google Docs (collaborative)
- Voice recording (for later transcription)

Organization:
- Group similar ideas
- Label categories
- Identify themes
- Prioritize top ideas
```

### Voting Methods
```
Dot Voting:
- Each person gets 3 dots
- Place dots on favorite ideas
- Ideas with most dots win

Fist to Five:
- 0 fingers = Strongly disagree
- 5 fingers = Strongly agree
- Quick consensus check

Weighted Voting:
- Assign points (e.g., 10 points total)
- Distribute across ideas
- Allows nuanced preferences
```

## Problem-Solving Frameworks

### Design Thinking
```
1. Empathize: Understand users
2. Define: Frame the problem
3. Ideate: Generate solutions
4. Prototype: Build quick mockups
5. Test: Validate with users

Example: Improve onboarding

Empathize: Interview new users, observe struggles
Define: Users don't understand core features
Ideate: Interactive tutorial, video guide, tooltips
Prototype: Build clickable prototype
Test: 5 users complete onboarding, gather feedback
```

### Lean Startup
```
1. Build: Create MVP
2. Measure: Collect data
3. Learn: Analyze results
4. Iterate: Improve and repeat

Example: New feature

Build: Simple version with core functionality
Measure: Track usage, completion rate, feedback
Learn: Users love feature but find it hard to discover
Iterate: Add prominent CTA, improve onboarding
```

### Jobs to Be Done
```
Framework: When [situation], I want to [motivation], so I can [outcome]

Example: Music streaming

When I'm commuting to work,
I want to listen to energizing music,
So I can start my day in a good mood.

Solution: Create "Morning Commute" playlist
```

## When to Escalate

- Group conflict → Bring in neutral facilitator
- Technical feasibility unclear → Consult technical expert
- Strategic alignment needed → Engage leadership
- Resource constraints → Discuss with project manager
- Scope too large → Break into smaller sessions
