## Architecture/Mechanism Details

### Classic Memory (current baseline)
- Functions as a "continuously rolling sticky note" -- compresses all user knowledge into a single summary
- Problems: information overflow, old overwrites new, important details displaced by trivial ones
- Essentially a flat, append-only representation

### Memory Files (new system)
- Auto-creates structured documents during conversation, organized by topic/project/context
- Selectively reads relevant files at retrieval time (tech docs during coding chats, travel preferences during trip discussions)
- Three claimed advantages:
  1. **Unlimited capacity** -- file-based memory theoretically scales infinitely
  2. **Precision improvement** -- retrieves only context-relevant files
  3. **User control** -- users browse, edit, or delete any memory file (Wiki-style)

### Dreams (memory consolidation engine)
- Triggers when agent is "idle" between work sessions
- **Four consolidation operations:**
  1. **Merge duplicates** -- consolidates same-topic information scattered across files
  2. **Replace outdated entries** -- temporal resolution (e.g., "'We decided to use Redis yesterday'" becomes "'On May 15, 2026, we decided to use Redis'")
  3. **Resolve contradictions** -- keeps newer, more reliable record when memories conflict
  4. **Discover hidden patterns** -- identifies regularities neither human nor AI noticed during real-time chat
- **Trigger conditions** (from Claude Code "Auto Dream"):
  - Minimum 5 accumulated sessions, OR
  - >24 hours since last consolidation, OR
  - Manual `/dream` command

### Conway Agent Platform
- Independent runtime with three zones: Search, Chat, System
- Capabilities: persistent background execution, external event listening, proactive task triggering, Webhook reception, browser control, Claude Code invocation
- Custom extension format: "CNW ZIP"
- Departs from passive chat window paradigm entirely
