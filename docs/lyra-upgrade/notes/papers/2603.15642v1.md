## 1. Mechanism (Step-by-Step)

CraniMem is a neurocognitively-inspired, gated, bounded, multi-stage memory architecture for LLM agents operating over long horizons. It separates transient episodic traces from consolidated semantic knowledge, with explicit control gates regulating what enters memory, what is rehearsed into long-term storage, and what is retrieved for downstream reasoning.

### Architecture Pipeline (5 stages)

**Stage 1: Input Gating (RAS-inspired Gate)**

Given user message `u_t` and agent goal state `g_t`, CraniMem computes semantic relevance via an embedding model `E(·)`:

```
Sim(u_t, g_t) = CosineSimilarity(E(u_t), E(g_t))
```

- If `Sim(u_t, g_t) < τ_noise`: input is discarded as noise (similar to thalamic filtering).
- If `Sim(u_t, g_t) >= τ_noise`: input proceeds to utility tagging.

A secondary "Cortex Gate" handles low-vector-similarity inputs by categorizing them as commands, goal changes, relevant context, or noise using an LLM-based classifier, preventing false rejection of important context shifts.

**Stage 2: Utility Tagging (Importance + Surprise + Emotion)**

An LLM-based tagger produces three scalar signals per accepted input:
- `I(u_t)` — Importance (is it technical/goal-oriented?), range [0, 1]
- `S(u_t)` — Surprise (is it new or unexpected?), range [0, 1]
- `E(u_t)` — Emotion (is there strong sentiment?), range [0, 1]

Base utility score is the unweighted average:

```
BaseUtility(u_t) = (1/3) * (I(u_t) + S(u_t) + E(u_t))
```

**Stage 3: Episodic Buffer (Bounded FIFO)**

Accepted items are stored in a bounded FIFO episodic buffer over the most recent `N` turns. Each entry contains:

- Raw text snippet
- Timestamp and turn ID
- Extracted entities
- Utility metadata (importance, surprise, emotion scores)

The buffer supports short-range continuity and provides the candidate set for consolidation. Oldest/least-accessed items are evicted when buffer is full.

**Stage 4: Replay Selection and Consolidation**

Triggered every `N` turns or during idle states. For each buffer item `m`, a replay score combines intrinsic utility with a frequency bonus:

```
ReplayScore(m) = BaseUtility(m) × (1 + α × FreqBonus(m))
```

where `FreqBonus(m)` increases with repeated entity occurrences and repeated access patterns.

Only items with `ReplayScore(m) > τ_consolidation` are selected for transfer to long-term memory. Items below threshold are pruned to "Trash" — this is the "selective forgetting" mechanism that keeps memory bounded.

**Stage 5: Linkage Engine and Knowledge Graph**

Selected episodic memories are converted into a structured knowledge graph:
1. **Entity extraction**: LLM extracts typed entities (Person, Organization, Project, Date, Location, etc.).
2. **Relation extraction**: LLM extracts typed relations as `(source, relation_verb, target)` triples.
3. **Schema**: entities have `{type, name}`; relations have `{source, relation, target}`.
4. **Upsert and merge**: New triples are upserted; repeated facts are reinforced rather than duplicated. Deduplication via entity linking.

**Stage 6: Dual-Path Retrieval**

At generation time, CraniMem retrieves evidence from two sources:
1. **Episodic buffer**: vector similarity search for short-range continuity (recent turns).
2. **Knowledge graph**: graph traversal for multi-hop semantic recall (long-range facts).

The two streams are merged into a compact context block that conditions the LLM for answer generation.

### Algorithmic Summary

```
for each turn t:
    u_t = user_message
    g_t = current_goal

    // Gating
    sim = cosine(E(u_t), E(g_t))
    if sim < τ_noise: discard u_t, continue

    // Utility Tagging
    (I, S, E_emo) = LLM_Tagger(u_t)
    utility = (I + S + E_emo) / 3

    // Store in episodic buffer
    buffer.append(entry=(u_t, t, utility, entities))

    // Consolidation (every N turns)
    if t % N == 0:
        for m in buffer:
            replay_score = utility(m) * (1 + α * freq_bonus(m))
            if replay_score > τ_consolidation:
                triples = ExtractRelations(m)
                KG.upsert(triples)  // reinforce or add
            else:
                buffer.remove(m)  // trash/prune

    // Retrieval
    episodic_hits = buffer.semantic_search(u_t)
    semantic_hits = KG.graph_traverse(entities(u_t))
    context = merge(episodic_hits, semantic_hits)
    answer = LLM.generate(context, u_t)
```

## 3. Trade-offs (Wins vs Loses)

| Aspect | Win | Lose |
|--------|-----|------|
| **Distraction robustness** | 3.7x–4.6x higher noisy F1 vs. Vanilla RAG; near-zero noise drop (0.004) on some backbones | Requires embedding model + LLM-based tagger for gating, adding pipeline complexity |
| **Memory boundedness** | Selective forgetting via replay scoring prevents unbounded growth; FIFO buffer enforces hard cap | Thresholds (τ_noise, τ_consolidation) and α must be manually tuned; wrong values can over-prune |
| **Semantic recall** | Knowledge graph supports multi-hop traversal impossible with flat vector stores | KG entity/relation extraction is lossy — extraction errors cascade into retrieval failures |
| **Latency** | Clean condition latency is competitive with RAG for some backbones (54s vs. 68s) | Noisy condition latency is 1.9x–69x higher than baselines due to consolidation overhead |
| **Generalization** | Consistent improvements across 4 LLM families (Qwen, Gemma, Mistral) | Sample size of only 100 instances limits statistical strength |
| **Deployability** | Available as PyPI package with released prompts | No ablation studies isolating individual components (gating alone, KG alone, etc.) |

## 4. Design Rationale (Why This Approach)

The authors argue that **existing agent memory systems treat memory as an external database with ad-hoc read/write rules**, leading to three failure patterns: (1) brittle retention where important events are overwritten by noise, (2) weak consolidation across time, and (3) poor synchronization when multiple agents produce overlapping beliefs. Their central thesis is that **agentic memory should mimic biological memory systems**: gated (like thalamic filtering), bounded (like working memory capacity limits), and multi-stage (like hippocampal-cortical consolidation pathways).

The design choices follow directly from neuroscience principles:
- **Attentional gating** (RAS-inspired): Prevents low-salience inputs from entering memory at all — analogous to how the thalamus filters sensory input before it reaches the cortex.
- **Utility tagging with importance/surprise/emotion**: Mirrors how biological systems prioritize memories based on emotional salience and novelty.
- **Buffer → KG consolidation + selective forgetting**: Mimics hippocampal replay — during sleep/idle, high-value episodic traces are replayed and consolidated into cortical semantic stores, while low-value traces decay.
- **Dual-path retrieval**: Matches the cognitive science finding that humans use both recent episodic memory and consolidated semantic memory when answering questions.

This approach was chosen over flat RAG (which lacks consolidation and boundedness) and Mem0 (which lacks gating and has heuristic write policies) because the neuroscience literature predicts better resistance to interference when memory is gated, bounded, and consolidated.

## 5. Limitations and Failure Modes

1. **Small evaluation set (n=100)**: Only 100 sampled HotpotQA instances were used due to computational constraints, limiting statistical power and precluding significance testing. All reported numbers should be treated as preliminary.

2. **No ablation studies**: The paper attributes gains to the full CraniMem pipeline but does not ablate individual components (gating alone, KG alone, utility tagging alone, consolidation alone). It is impossible to determine which component drives the improvement.

3. **No comparison to HippoRAG**: Despite citing HippoRAG as the most directly comparable neuro-inspired memory system, there is no head-to-head benchmark against it — only against Vanilla RAG and Mem0.

4. **Parameter sensitivity unexplored**: Thresholds τ_noise, τ_consolidation, α, and buffer size N are never tuned or reported. Over-pruning or under-gating could silently degrade real-world performance.

5. **Latency variability**: CraniMem latency varies wildly across backbones (9s–381s for clean, 113s–381s for noisy with CraniMem), making performance unpredictable without backbone-specific tuning.

6. **KG extraction cascading errors**: Entity/relation extraction is LLM-based. Extraction errors (missed entities, hallucinated relations) cascade into incorrect graph traversal results, with no error recovery mechanism described.

7. **Single-dataset, single-domain**: Evaluated only on HotpotQA (multi-hop QA). No evidence of effectiveness on agent tool-use, dialogue, planning, or other agentic tasks.

8. **No multi-agent evaluation**: Despite claims of multi-agent relevance, all experiments are single-agent. Synchronization across agents with overlapping beliefs is not tested.

9. **Identity of utility tagger unclear**: Whether the utility tagger uses the same LLM as the reasoning agent, a smaller model, or a different one is not specified; costs are not counted.

10. **Cold-start problem**: A new agent with an empty episodic buffer and empty KG has no dual-path retrieval advantage; performance relies entirely on the LLM's parametric knowledge until enough turns accumulate.

## 6. Transfer to Lyra

### The One Transferable Idea

**Gated, utility-scored memory ingestion with bounded episodic buffer and consolidated knowledge graph retrieval.** Lyra's current memory design should adopt CraniMem's three-part pattern: (a) a goal-conditioned relevance gate that discards low-cosine-similarity inputs before they pollute context, (b) an LLM-based utility tagger that scores each retained input on importance/surprise/emotion, and (c) a bounded FIFO episodic buffer that auto-prunes low-utility items while consolidating high-utility traces into a structured KG for durable multi-hop recall. This directly addresses the distractor-vulnerability problem Lyra faces in long multi-turn sessions.

### §4 Mapping: §4.2 (Memory Subsystem)

This paper maps to the Lyra upgrade plan's **§4.2 Memory Subsystem** workstream. CraniMem provides a concrete, benchmarked architecture pattern for the memory rewrite that plans `02-memory.md` calls for — specifically the transition from flat context-window concatenation to structured, gated, bounded storage with consolidation pathways.

### Recommended Phased Adoption

1. **Phase 1 (quick win):** Add the goal-conditioned cosine-similarity gating layer to filter inputs before they enter Lyra's context. Zero structural changes needed — just a pre-filter.
2. **Phase 2:** Implement FIFO episodic buffer with utility tagging (drop the KG initially, just use the buffer for bounded short-term memory).
3. **Phase 3:** Add KG consolidation and dual-path retrieval once buffer utility is validated.
