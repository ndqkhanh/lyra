## 1. Mechanism (Step-by-Step)

Feedback Descent is an inference-time optimization framework that widens the information bottleneck in preference learning by preserving structured textual feedback rather than compressing judgments into binary preferences or scalar rewards.

### Algorithm (Algorithm 1 in paper)

```
Input: Initial text x_0, Language model M, budget T
1: Current best: x* ← x_0, Rationale history: R ← ∅
2: for t = 1 to T do
3:     x_t ← M(x*, R)                         // Propose: LLM generates candidate conditioned on best + all accumulated feedback
4:     (p_t, r_t) ← Compare(x_t, x*)           // Evaluate: returns binary preference + textual rationale
5:     R ← R ∪ {(x_t, r_t)}                    // Accumulate feedback regardless of whether candidate wins
6:     if p_t = 1 then
7:         x* ← x_t                            // Update best if candidate preferred
8:         R ← ∅                               // Reset feedback history on improvement
9: return x*
```

### Core Innovation: Accumulated Feedback as Directional Signal

The evaluator function E(x, x*) returns a tuple:
```
E(x, x*) → (p ∈ {0,1}, r ∈ S)
```
where p=1 indicates x ≻ x* (candidate preferred) and r is textual feedback explaining why the winner is better and how to improve.

Key design decisions:
- **Feedback accumulation**: All feedback is appended to history R, even when the candidate loses. This provides a trajectory-level signal rather than pointwise conditioning.
- **History reset on improvement**: When the candidate wins, R is cleared. This prevents stale feedback from polluting the optimization; the new search starts from the improved baseline.
- **Binary preference + textual feedback combined**: The binary signal ensures monotonic improvement (never regress), while the textual feedback provides the direction for the next step.

### Theoretical Intuition (Section 2.3, Appendix A)

Under the Polyak-Lojasiewicz (PL) condition with rationale-guided directions:

- Assume a direction vector v_t satisfies: E[v_t|z_t] = α∇r(z_t) with bounded variance
- With step size η = α/(L·κ_1), convergence is:
  ```
  E[r(z*) - r(z_T)] ≤ (1 - μα²/(L·κ_1))^T · [r(z*) - r(z_0)]
  ```
- This yields **dimension-free** convergence: T = O(L(α²+σ²)/(μα²) · log(1/ε))
- In contrast, zeroth-order methods (exhaustive grid search, best-of-N) scale exponentially with dimension d: N ≥ (μR²d/(8ε))^(d/2)
- Textual feedback approximates the directional information of a gradient, enabling first-order-like optimization in semantic space

### Domain-Specific Instantiations

**SVG Optimization** (Section 4.2): GPT-5-mini as both generator and judge. Double-evaluation with swapped order (A-B and B-A) to mitigate order bias. Declare winner only if both judgments agree; retry up to 3 times.

**Prompt Optimization** (Section 4.3): Multi-stage DSPy programs. Pairwise feedback constructed by partitioning training examples into quadrants (A_wins, B_wins, tie_fail, tie_success), generating hypotheses about performance differences via LLM, and statistically validating (Fisher's exact test, p < 0.1, lift ≥ 2.0).

**Molecule Discovery** (Section 4.4): SMILES string representation. Evaluator = DOCKSTRING docking pipeline (Vina scores + QED drug-likeness). Rich feedback includes RDKit molecular descriptors, similarity to DrugBank/CHEMBL compounds, and UniProt protein target metadata.

## 3. Trade-offs

| Win | Lose |
|-----|------|
| **Dimension-free convergence** (theoretical): avoids exponential slowdown of zeroth-order search in high-dimensional spaces | **No formal convergence guarantees**: feedback is heuristic, not a true gradient; can be contradictory or noisy |
| **Domain-agnostic**: same algorithm works on SVG, prompts, molecules with zero domain-specific engineering | **Requires strong evaluator**: judge quality is the limiting factor; poor evaluators → poor optimization |
| **Pure inference-time**: no weight updates, no fine-tuning, no GPU training needed | **Inference cost scales with T**: each iteration costs one generation + one comparison call |
| **+1.74 docking score from textual feedback alone** (vs binary-only) — high-bandwidth signal matters | **May plateau**: fixed budget T; creative domains may suffer from "follow the gradient" trap (local optima) |
| **Robust to 50% noise**: still above 99.9th percentile on ADRB1/PGR | **Random feedback worse than none**: the method's power comes from feedback quality, not iterative structure |
| **Discovers genuinely novel outputs** (weak correlation with known compounds) | **LLM-dependent**: relies on model's ability to translate feedback into targeted edits |
| **Competitive with specialized methods** (GEPA, GraphGA, GP-BO) without domain engineering | **GEPA still wins on some prompt tasks** (HotpotQA, PUPA) — general-purpose vs specialized trade-off |

## 4. Design Rationale

The core insight is that **preference learning compresses rich human judgment into single bits**, discarding the "why" that explains how to improve. The authors widen this information bottleneck by preserving the textual rationale alongside the binary preference. 

The gradient analogy provides theoretical motivation: just as first-order methods achieve dimension-free convergence while zeroth-order methods scale exponentially with dimension, textual feedback provides directional information that enables efficient search in semantic space. The accumulated feedback buffer (vs. TextGrad's pointwise conditioning) is critical — it gives the model a trajectory-level view of what works and what fails.

The design is intentionally minimal: prompts are "intentionally minimal" — the optimization signal comes from accumulated feedback, not heavy prompt engineering. This distinguishes it from specialized methods like GEPA that use coordinate descent and Pareto frontier maintenance.

## 5. Limitations & Failure Modes

1. **Evaluator dependence**: The method is only as good as its judge. In domains without reliable evaluators (subjective tasks, long-horizon planning), performance will degrade. Training models to produce reliable feedback remains a prerequisite for harder tasks.

2. **No convergence guarantees**: Unlike gradient descent, textual feedback is approximate and occasionally contradictory. The theoretical results are motivational (idealized assumptions) rather than rigorous guarantees for discrete text domains.

3. **Creative mode collapse**: "Strictly following the gradient" may converge to evaluator-pleasing but locally-optimal solutions. The authors explicitly note that balancing refinement with exploration is an important next step.

4. **Fixed budget**: Algorithm runs for T iterations or until k consecutive failures. Long-horizon tasks may require more iterations than budget allows.

5. **Cost scales linearly with iterations**: Each step requires one generation + one comparison call. For expensive evaluators (e.g., experimental docking), this may be prohibitive.

6. **History reset may discard useful information**: Resetting R on improvement removes potentially valuable feedback. The authors validate this choice empirically but don't explore alternatives.

## 6. Transfer to Lyra

### The One Idea

**Accumulated comparative feedback buffer for inference-time self-improvement.** Lyra should maintain a structured history of its own outputs paired with evaluator critiques, and condition subsequent improvements on this full trajectory rather than only the last attempt. This is qualitatively different from typical self-critique loops (which are pointwise) — the accumulated history provides directional information that approximates a gradient in semantic space.

### Lyra-Specific Application

Lyra's agent loop could implement a Feedback Descent variant where:
1. Each tool invocation or plan execution produces a "comparison pair" (expected vs. actual outcome)
2. A judge (stronger model or evaluation harness) provides textual feedback on why the outcome differed
3. The accumulated feedback drives prompt/tool/plan refinement at inference time
4. The feedback buffer is reset only when a new best output is achieved

### Workstream Route: §4.14 Autonomy (self-improvement loop)

The Autonomy workstream covers Lyra's ability to self-correct and improve its own outputs. Feedback Descent provides a principled alternative to naive self-critique by introducing an accumulated feedback buffer and pairwise comparison structure.

### Dependencies
- Strong evaluator/judge for Lyra's output quality (could use a stronger model or a structured rubric)
- Feedback buffer data structure (likely a time-ordered queue with reset-on-improvement semantics)
- Prompt template design for conditioning the generator on accumulated feedback
