## 1. Mechanism (Step-by-Step)

SEAL is a two-loop meta-learning framework where an LLM learns to generate its own synthetic training data and optimization directives (called "self-edits") via reinforcement learning, then applies those self-edits through gradient-based weight updates.

### Outer Loop (RL Policy Optimization — ReSTEM)

The outer loop trains the model's self-edit generation policy via **ReSTEM** (Rejection Sampling + SFT), an EM-style algorithm chosen over PPO/GRPO due to training stability:

**E-Step (Sampling):**
1. Sample a context `C` from the training distribution (e.g., a passage with held-out QA pairs from SQuAD).
2. The current model `LM_θt` generates `K` candidate self-edits `SE ∼ LM_θt(·|C)` at temperature 1.0. Each self-edit is a natural-language directive specifying what synthetic data to produce and optionally what training hyperparameters to use.

**Reward Computation (Inner Loop):**
3. For each self-edit `SE_i`:
   a. **Inner Loop Update:** Apply the self-edit via supervised finetuning: `θ' ← SFT(θ, SE_i)`. In the knowledge incorporation domain, SE_i is synthetic implication text used as training data. In few-shot learning, SE_i is a JSON object specifying data augmentation flags (`use_basic_augmentations`, `use_size_augmentations`, `use_chain_augmentations`, `use_repeat_augmentations`) and training hyperparameters (`learning_rate`, `num_train_epochs`, loss strategy `train_using_all_tokens` or `train_using_output_tokens`).
   b. **Evaluation:** Query the updated model `LM_θ'` on the downstream task `τ` (held-out questions for the passage, or ARC test input).
   c. **Binary Reward:**
   ```
   r(SE, τ, θ) = 1 if adaptation using SE improves LM_θ's performance on τ
               = 0 otherwise
   ```
   Each evaluation takes ~30-45 seconds (finetuning + inference). Each candidate is evaluated over 3 random seeds and averaged.

**M-Step (Behavior Cloning):**
4. Among all `K` candidates for each context, retain only the **single best** self-edit (highest average reward).
5. Supervised-finetune `LM_θt` on the `(context, best_self_edit)` pairs across the batch — this produces `θ_{t+1}`.

The RL objective is:
```
L_RL(θ_t) := -E_{(C,τ)~D} E_{SE~LM_θt(·|C)} [r(SE, τ, θ_t)]
```

Since `r` is non-differentiable w.r.t. `θ`, the reward is treated as fixed for the gradient estimator, producing an SFT loss over only the high-reward samples.

### Inner Loop (Weight Update)

The inner loop applies self-edits via standard SFT with LoRA adapters:
- **Knowledge incorporation (Qwen-2.5-7B):** LoRA rank 64, alpha 128, on all MLP and attention projection layers. Self-edits are implication text split by newlines into training documents. Finetuned 2 epochs, learning rate 3e-4, batch size 10.
- **Few-shot learning (Llama-3.2-1B-Instruct):** LoRA rank 128, alpha 16, on q_proj, v_proj, gate_proj, down_proj, up_proj. LR and epochs chosen by model.

### Key Algorithm (Pseudocode from Algorithm 1)
```
Input: LM_θ, dataset D = {(C, τ)}
for outer iteration t = 1, 2, ... do:
    Sample (C, τ) ~ D
    Generate self-edit SE ~ LM_θ(· | C)
    Inner Loop Update: θ' ← SFT(θ, SE)
    Evaluate: Ans ~ LM_θ'(· | τ)
    Compute reward: r ← r(Ans, τ)
    Update: θ_{t+1} ← RL_Update(θ_t, r, SE)
```

### Two Instantiations

1. **Knowledge Incorporation:** Context = a passage. Self-edit = a list of logical implications derived from the passage. The model is prompted with "Let's read the following passage and produce a list of implications..." Inner loop finetunes on the generated implications. Evaluation = QA on the passage without the passage in context.

2. **Few-Shot Learning:** Context = few-shot demonstrations from ARC-AGI. Self-edit = JSON specifying data augmentation tools (basic/size/chain/repeat) and training hyperparameters. Inner loop performs Test-Time Training (TTT) with LoRA using the augmented few-shot examples. Evaluation = correctness on held-out ARC test input.

## 2. Results (Benchmark Numbers)

### Knowledge Incorporation (SQuAD, no passage in context)

| Method | Single-Passage (n=1; LoRA) | CPT (n=200; full-FT) | CPT (n=2067; full-FT) |
|--------|---------------------------|---------------------|----------------------|
| Base model (no training) | 32.7% | 32.7% | 29.0% |
| Train on Passage Only | 33.5% | 36.0% | 31.2% |
| + Base Synthetic Data | 39.7% | 50.6% | 43.4% |
| + GPT-4.1 Synthetic Data | 46.3% | **59.4%** | **49.2%** |
| **SEAL (RL-trained)** | **47.0%** | 58.2% | 46.4% |

- **Key win:** SEAL (47.0%) outperforms GPT-4.1 synthetic data (46.3%) in single-passage setting, despite Qwen-2.5-7B being far smaller than GPT-4.1.
- **Improvement over base:** 33.5% → 47.0% = +13.5 percentage points.
- **GPT-4.1 pulls ahead at scale:** In CPT n=2067, GPT-4.1 synthetic (49.2%) > SEAL (46.4%).

### Few-Shot Learning (ARC-AGI subset, 8 held-out tasks)

| Method | Success Rate (%) |
|--------|-----------------|
| ICL (In-Context Learning, no adaptation) | 0% |
| TTT + Self-Edit (w/o prior RL) | 20% |
| **SEAL (RL-trained self-edits)** | **72.5%** |
| Oracle TTT (human-crafted optimal config) | 100% |

- **3.6x improvement** over base self-edit (20% → 72.5%).
- Still trails Oracle TTT (72.5% vs 100%), indicating headroom.

### Model Size Scaling

| Model | Base (No Training) | Base Model Self-Edit | SEAL |
|-------|-------------------|---------------------|------|
| Qwen2.5-3B | 25.1% | 31.9% | 37.0% |
| Qwen2.5-7B | 32.7% | 39.7% | 47.0% |

- Relative improvement ratio (SEAL vs base self-edit): **1.75x for 3B**, **2.04x for 7B** — RL benefits compound with model scale.

### Prompt Format Ablation (Single-passage, after 2 rounds ReSTEM)

| Prompt Format | Base Self-Edit | Round 2 SEAL | GPT-4.1 Syn |
|--------------|---------------|-------------|-------------|
| Implications | 39.7 | 47.0 | 46.3 |
| Implications-long | 49.3 | 54.4 | 54.1 |
| Implications-very-long | 45.0 | 52.1 | 40.9 |
| Rewrite | 49.4 | 55.6 | 54.4 |
| Self-QA | 37.3 | 48.7 | 39.2 |
| No-Prompt | 13.8 | 18.9 | 28.6 |

- **Prompt engineering matters significantly:** "Rewrite" format achieves 49.4% even without RL, and 55.6% with SEAL.
- **RL consistently adds ~6-11 points** across all formats except no-prompt.

### Comparison to Competing Methods

| Method | Single-passage (n=1) | CPT (n=200) |
|--------|---------------------|-------------|
| SEAL | 47.0% | 58.2% |
| Generative Adapter (hypernetwork LoRA) | 66.8% | 28.0% |
| Entigraph (pairs only) | — | 46.2% |
| Entigraph (pairs+triples) | — | 56.0% |

- **Generative Adapter excels at n=1 (66.8%) but collapses at scale (28.0%).**
- **SEAL maintains/improves at scale** (47.0% → 58.2%) due to synthetic data reuse across documents.
- **Entigraph competitive at larger scale** (48.6% at n=2067).

### Catastrophic Forgetting

- Sequential self-edits on 8 passages show gradual decline from ~0.58 to ~0.08 on earliest passages by iteration 8 — confirming forgetting is a significant concern.

### Compute Cost

- **RL training:** ~6 hours per ReSTEM round on 2xH100 (750 inner-loop iterations for 50 passages x 5 completions x 3 seeds).
- **Per self-edit evaluation:** 30-45 seconds (finetuning + inference).
- **Few-shot ReSTEM:** ~2-3 hours on single A100/H100/H200 (11 tasks, 15 self-edits each).
- **Proxy reward alternative:** ~5 minutes vs ~6 hours, achieving 45.6% vs 47.0%.

## 3. Trade-offs

| Win | Lose |
|-----|------|
| Outperforms GPT-4.1 synthetic data (47.0% vs 46.3% single-passage) despite 7B vs large model | Massive compute: each ReSTEM round ~6 hours on 2xH100, inner loop 30-45s per self-edit |
| 3.6x improvement over base self-edits on few-shot ARC (20% → 72.5%) | CPT at scale underperforms GPT-4.1 (46.4% vs 49.2% at n=2067) |
| No manual heuristic needed — model autonomously discovers effective self-edit strategies | Catastrophic forgetting: prior knowledge degrades ~50% after 8 sequential edits |
| Works across diverse prompt formats (implications, rewrite, self-QA); RL consistently adds 6-11 pts | Requires labeled downstream supervision (QA pairs per passage); cannot scale to unlabeled corpora |
| Synthetic data approach allows reuse for CPT, unlike hypernetwork methods (Generative Adapter: 66.8% n=1 → 28.0% CPT) | Training instability with PPO/GRPO; limited to simpler ReSTEM (rejection sampling + SFT) |
| RL improvement compounds with model scale (1.75x → 2.04x from 3B → 7B) | Small-scale experiments only (max 7B model, 11 ARC tasks), uncertain scalability to frontier models |
| Framework agnostic to self-edit format; works with implications, QA pairs, rewrites | Proxy reward (45.6%) still trails true reward (47.0%), and manual rubric design is fragile |
| Inner loop reuses standard SFT/LoRA infrastructure — no custom architecture | No guarantee self-edits are factually correct; model can learn to generate plausible but wrong implications |

## 4. Design Rationale

**Why RL for self-edit generation policy?** Static prompting to generate synthetic data (base model self-edits) underperforms (39.7%). Manual heuristics like Entigraph require domain expertise. RL directly optimizes for downstream utility — the model discovers which data formats, augmentation strategies, and hyperparameters produce the best downstream performance.

**Why ReSTEM (rejection sampling + SFT) over PPO/GRPO?** The authors report that PPO/GRPO training was unstable for this problem. ReSTEM is simpler: it treats each batch independently as an EM procedure (sample candidates, filter by reward, SFT on winners). This avoids reward hacking, KL divergence penalties, and value function estimation challenges.

**Why synthetic data generation over direct weight prediction (hypernetworks)?** Three reasons: (1) Synthetic data is reusable — same generation can be used for CPT across many documents, while hypernetworks (Generative Adapter) collapse from 66.8% to 28.0% at scale. (2) Data generation leverages the model's existing in-context learning and reasoning capabilities. (3) Framework is not tied to LoRA — any update mechanism (full-FT, RL inner loop) can be parameterized via text.

**Why self-edit rather than direct RLHF on QA?** RLHF/RLVR directly optimizes answer quality per query, requiring gradient through the generation. SEAL instead optimizes the *data generation* process — the output is training data that persists in weights, enabling generalization beyond the training context.

## 5. Limitations and Failure Modes

1. **Catastrophic Forgetting:** Sequential self-edits cause monotonic degradation on earlier tasks. By edit 8, accuracy on the first passage drops from ~0.58 to ~0.08. No explicit retention mechanism is included.

2. **Computational Overhead:** Each self-edit evaluation requires full finetuning + inference (30-45s). One ReSTEM round = 750 inner-loop iterations = ~6 hours on 2xH100. This is 70x more expensive than proxy-reward alternatives.

3. **Supervision Dependency:** Every training context must be paired with explicit downstream labels (QA pairs, test inputs). Cannot apply RL to unlabeled corpora. The proposed mitigation (model generates its own evaluation questions) is conjecture only.

4. **Scale Limitations:** Experiments max out at 7B parameters and 11 ARC training tasks. No evidence the approach works at frontier scales (70B+), where RL training of the reward loop would be prohibitively expensive.

5. **Training Instability:** PPO/GRPO found unstable, forcing adoption of the simpler but less sample-efficient ReSTEM algorithm. ReSTEM may not scale to complex self-edit spaces.

6. **Factual Drift Risk:** RL optimizes for downstream QA performance, not factual accuracy of generated implications. The model could learn to generate implications that are easy to finetune on but factually wrong — this failure mode is not evaluated.

7. **Narrow Domain Validation:** Only tested on SQuAD (factoid QA) and simplified ARC (abstract reasoning). No evaluation on open-ended generation, code, mathematics, or safety-critical domains.

8. **Prompt Sensitivity:** Performance varies dramatically with prompt format (13.8% to 49.4% at baseline). No-prompt setting fails (18.9% after RL), suggesting meta-learning doesn't generalize to fully free-form self-edits.

## 6. Transfer to Lyra

### The One Idea

**RL-trained self-synthetic data generation for autonomous model adaptation:** Lyra should implement a ReSTEM-style inner loop where the model generates its own training signals from interaction context (conversation histories, tool outputs, user feedback), evaluates the downstream utility of those generated signals via lightweight proxies, and uses rejection sampling + SFT to continuously improve its data-generation policy. This is more scalable than fixed-prompt synthetic data approaches and avoids the collapse seen in hypernetwork-based adaptation at scale.

### Workstream Route

**§4.2 Memory / Continual Learning** — SEAL directly addresses the problem of persistent knowledge incorporation without forgetting. Lyra's memory subsystem needs exactly this: the ability to generate high-utility training signals from raw interaction data and apply them through lightweight weight updates. The proxy-reward variant (5-minute training, 45.6% accuracy) is particularly relevant as a practical starting point for Lyra's context-constrained deployment.

### Assessment

- **Impact:** 4 (direct path to self-improving agent capabilities; addresses §4.2 memory/continual learning core requirement; aligns with Lyra's agentic architecture)
- **Effort:** 4 (requires: (1) implementing ReSTEM training loop with inner SFT evaluation, (2) designing self-edit prompt formats for Lyra's interaction data, (3) building proxy reward rubrics, (4) integration with existing LoRA infrastructure; ~2-3 weeks for MVP)
- **Tier:** **Investigate** — Compelling mechanism with strong results, but the computational overhead and catastrophic forgetting issues are real blockers. Start with proxy-reward variant and explicit anti-forgetting mechanisms (replay buffer, elastic weight consolidation) before committing to full RL loop. The prompt format findings (rewrite > implications, 49.4% → 55.6%) suggest that even without RL, better prompt engineering for synthetic data generation is worth immediate exploration.
