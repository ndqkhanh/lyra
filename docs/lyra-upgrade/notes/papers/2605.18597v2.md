## 1. Mechanism (step-by-step, with equations/algorithms)

LAR is a four-stage pipeline that reparameterizes LLM agent action spaces by collapsing multi-step structural segments into single latent tokens. The core insight: LLM agents make decisions at token-level granularity, creating unnecessarily large effective decision horizons dominated by recurring structural scaffolding (tool invocation formats, reasoning templates, system prompts) rather than semantically novel content.

### Stage 1: Transition-Equivalent Segment Identification (Algorithm 1)

From agent rollout trajectories D = {τ₁, ..., τ_N}, extract word-level n-grams within sentence boundaries, then apply three filters:

1. **Frequency filter:** Retain segments where freq(s) ≥ f_min
2. **Entropy filter:** Compute next-token entropy H(s) = -Σ_{w∈V_s} p(w|s) log₂ p(w|s). Retain segments where H(s) ≤ H_max. Low H(s) indicates predictable continuation regardless of preceding history — the operational surrogate for transition equivalence: T(h ∘ a) ≈ T(h ∘ a′).
3. **Ranking and deduplication:** Rank by score(s) = freq(s)/(H(s) + 1), remove substrings and overlapping segments (overlap threshold ρ = 0.7), retain top-K as latent action set Z.

Per-benchmark configs: TriviaQA (f_min=2000, n-gram [3,5], K=200-1000), KodCode (f_min=10, n-gram [2,6], K~100), Mind2Web (f_min=1000, n-gram [2,6], K~100). H_max = 10.0 across all benchmarks.

### Stage 2: Vocabulary Construction

Each segment in Z is assigned a dedicated vocabulary symbol with new embedding and output-head entries. These are additional tokens, not replacements for existing ones.

### Stage 3: Trajectory-Level Distillation

Training data is dual-format:
- **Teacher trajectory τ:** Original uncompressed agent rollout
- **Student trajectory τ̂:** Reparameterized version where segments matching Z are replaced by latent action symbols via longest-first matching

A frozen copy of the original LLM (teacher) processes τ. A student (same base model + LoRA adapter rank r=8, α=16 on q/k/v/o projections + new latent embeddings) processes τ̂. Only ~0.1% of parameters are trainable (LoRA weights + new embeddings). All pretrained weights frozen.

Training objective is pure KL distillation over shared content positions M:

L_KL = (1/|M|) ∑_{i∈M} D_KL(softmax(z_i^T / τ) || softmax(z_i^S / τ))

where M = token positions with identical textual content in both teacher and student (excluding latent action symbols), τ = 2.0 is distillation temperature. Restricting loss to M is the mechanism by which latent embeddings acquire semantics: the student must reproduce the teacher's full predictive distribution on non-compressed content despite receiving compressed input.

Hardware: 8×H200 140GB GPUs. Optimizer: AdamW, lr=1e-4, cosine schedule, 100 warmup steps, weight decay 0.01, 3 epochs, fp16.

### Stage 4: Inference

Latent action symbols are processed identically to ordinary vocabulary tokens through the same embedding lookup and transformer forward pass. No expansion, post-processing, or additional computation required. Token-level compression translates directly into proportional savings in prefill, KV-cache memory, and end-to-end latency.

Reparameterization rate r = ∑|τ̂_i| / ∑|τ_i| measures compression (smaller = higher compression). Segments ranked by score(s) are abstracted first, creating a natural priority ordering.

### Key Design Constraint: Executability

A latent action z is executable iff all segments in z are transition-equivalent: for any a, a' ∈ z and any preceding history h, T(h ∘ a) ≈ T(h ∘ a'). The entropy filter H(s) ≤ H_max enforces this by excluding parameter-binding segments (queries, entity names, code identifiers) whose continuations depend on context-specific bindings. LAR is conservative by default — it only abstracts when statistically safe, not seeking maximal compression.

## 3. Trade-offs (wins vs loses table)

| Wins | Loses |
|------|-------|
| 9-27% action token reduction across 3 benchmarks/2 models | Requires N×1000 rollout trajectories per domain for latent action identification |
| Maintains or improves accuracy in all main benchmarks (best-in-class among efficiency methods) | Domain-specific latent actions lose compression rate in unified cross-domain training (-12.3% vs -27.3% on TriviaQA for unified model) |
| Zero inference overhead (latent tokens process identically to ordinary tokens) | Slight accuracy regression possible at high structural compression (Llama TriviaQA: 72.46 vs 73.63 vanilla, -1.17pp) |
| Training is parameter-efficient (0.1% trainable params, 3 epochs, all pretrained weights frozen) | Conservatism limits compression — only abstracts segments with low entropy and high frequency |
| Drop-in deployment (no framework changes needed — demonstrated on OpenClaw) | Not effective for reasoning-heavy, free-form tasks where structural redundancy is minimal |
| Held-out generalization works (zero-shot transfer to Musique, HumanEval, MBPP) | Phase III collapse is abrupt (not graceful degradation) — compression ratio must be tuned per domain |
| Faster GRPO convergence (~5x fewer samples needed on Llama TriviaQA) | Only demonstrated on text-based tasks; multimodal/vision agents untested |
| GPU memory reduced (1-3.5 GB savings depending on task) | Peak GPU memory slightly increased in some configs (KodCode Qwen +0.3 GB) |
| Scales to 32B with consistent gains | No evaluation above 32B; uncertain scaling to 70B+ production models |

## 4. Design Rationale (why this approach over alternatives)

**Why not system-level optimizations?** The paper argues prior approaches (prompt engineering, token pruning, context compression, speculative decoding) address the wrong bottleneck — they reduce per-step cost but leave the number of decision steps unchanged. The decision horizon dominates cost in multi-step agents, so the unit of decision-making itself must change.

**Why not hand-crafted macros or hierarchical RL?** Manual action macros require expert design per domain. Hierarchical controllers (options framework) add complexity without guaranteeing executability — abstract actions may not translate to valid tool calls. LAR learns from data and guarantees executability via the entropy filter.

**Why entropy as the transition-equivalence surrogate?** Direct verification of T(h∘a) ≈ T(h∘a') over all histories is intractable. Next-token entropy provides a tractable proxy: low entropy means the continuation of a segment is predictable regardless of context, precisely the condition for safe abstraction. The composite score freq/(H+1) balances coverage (frequency) with behavioral stability (entropy).

**Why pure KL distillation (not supervised fine-tuning)?** SFT on compressed trajectories would train the model to predict compressed outputs only. KL distillation forces the student to match the teacher's full distribution over the original vocabulary at shared positions, ensuring latent embeddings encode the complete semantics of the abstracted segments without losing the ability to produce uncompressed text when needed.

**Why conservative abstraction (not maximal compression)?** The Phase III collapse empirically demonstrates that abstracting parameter-binding content causes categorical breakdown of environment-facing transitions. LAR is designed to identify the largest safe subset rather than maximizing compression, making it deployable without runtime fallback mechanisms.

## 5. Limitations & Failure Modes

1. **Phase III Collapse (Critical):** When the entropy threshold H_max is raised aggressively, parameter-binding segments (search queries, entity names, code identifiers) enter the latent vocabulary. The resulting latent actions violate executability: tool interactions break entirely because the specific query/argument is replaced by a generic latent token. This failure is abrupt, not gradual — a categorical breakdown in environment-facing transitions rather than a smooth accuracy decline.

2. **Domain-Specificity of Latent Actions:** Unified cross-domain training (Table 7) shows reduced compression rates across 5 of 6 settings. Latent action tokens specialized for code syntax do not transfer well to web navigation or QA — the shared vocabulary dilutes compression. Domain-specific LAR models outperform unified models on domain-specialized tasks.

3. **Data Requirement:** LAR requires N×1000 agent rollout trajectories per domain for reliable frequency/entropy estimation. On low-data domains, statistical estimates of transition equivalence may be unreliable, causing either overly conservative abstraction (missed opportunity) or overly aggressive abstraction (Phase III collapse risk).

4. **Limited Scale Evaluation:** Only tested up to 32B parameters. Behavior at 70B+ (Llama-4, Claude-scale models) is unknown. Larger models may have different entropy profiles and structural redundancy patterns.

5. **Free-Form Reasoning Limit:** Tasks dominated by diverse, non-recurring free-form reasoning (rather than structured tool use or code generation) admit smaller compressible subsets. The method provides diminishing returns as structural regularity decreases.

6. **Training Overhead:** Each new domain and backbone model requires a full identification + distillation cycle (3 epochs on 8×H200 GPUs). This is not a one-time cost but scales with adoption breadth.

7. **No Multimodal Support:** The method operates on token-level text representations. Extension to visual or multimodal action spaces (GUI agents, embodied agents) is not addressed.

8. **Conservative Design Constraint:** The entropy filter is intentionally conservative (H_max = 10.0), which means some potentially abstractable patterns are left uncompressed. There is likely some efficiency headroom that the method deliberately leaves on the table for safety.

## 6. Transfer to Lyra (the one idea + §4.x workstream + Impact/Effort/Tier)

### The One Transferable Idea

**Entropy-guided action abstraction for agent inference efficiency.** Learn which spans of Lyra's agent prompt/tool-call traffic are structurally redundant (low next-token entropy, high frequency — system prompts, tool-format specifications, reasoning templates) vs semantically essential (high-entropy — user queries, parameter values, generated code). Then compress the redundant spans into learned latent tokens through lightweight LoRA distillation. This reduces Lyra's effective decision horizon by 9-27%, cutting token costs and inference latency without sacrificing task performance, while being deployable as a drop-in prompt-level optimization (no framework changes). The key safety property: the entropy filter prevents compressing parameter-binding content, so tool calls and environment interactions remain executable by construction.

### Workstream Route: §4.3 Context

LAR directly addresses Lyra's context/generation efficiency by reparameterizing the action space rather than applying post-hoc compression. It feeds into context window management (reducing the effective horizon of agent decisions) and token economics (§4.21 Economics). Secondary relevance to §4.2 Memory (compressing recurrent interaction patterns in memory) and §4.5 Router (compressed representations could enable cheaper routing decisions).

### Impact: 4 / Effort: 3 / Tier: breakthrough

**Impact 4:** Direct 9-27% token reduction with maintained/improved accuracy. Validated across 3 agent domains, 2 model families, and an industrial runtime (OpenClaw). Drop-in deployment — no Lyra framework changes needed.

**Effort 3:** Requires (a) collecting ~20K Lyra agent rollout trajectories, (b) running the segment identification pipeline (Algorithm 1), (c) LoRA fine-tuning (~3 epochs on 8 GPUs), and (d) integrating latent tokens into Lyra's prompt templates. Per-domain cost is moderate but recurring.

**Tier breakthrough:** LAR reframes agent efficiency as an action representation problem rather than a model/hardware optimization problem — a genuinely novel perspective on a core Lyra bottleneck. The entropy-guided executable-latent boundary is a principled design pattern that generalizes beyond the paper's benchmarks.
