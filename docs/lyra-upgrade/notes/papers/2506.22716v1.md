## 1. Mechanism (Step-by-Step)

BEST-Route combines two core innovations: (a) a memory-efficient best-of-n sampling pipeline using a proxy reward model, and (b) a multi-head router that dynamically selects the optimal (model, n) pair per query.

### Phase 1: Proxy Reward Model Training (Best-of-N Scorer)

1. For each training query q, generate n=20 candidate responses from each small model.
2. Score all 20 responses using armoRM (Llama3-8B fine-tuned for multi-perspective evaluation) as ground truth R_GT(s).
3. Select three responses per query: worst (s_worst), median (s_median), best (s_best). Form ordered pairs: (s_worst, s_median) and (s_median, s_best). Aggregate across all queries to form training set P.
4. Train proxy reward model R_proxy (fine-tuned from OpenAssistant RM, DeBERTa-v3-large, 300M parameters) by minimizing pairwise ranking loss:

   L_rank = -(1/|P|) * Σ_{(s,s')∈P} log σ(R_proxy(s) - R_proxy(s'))

   where σ(x) = 1/(1+e^{-x}) is the sigmoid function (Eq. 1).

5. Using only worst-median-best triples (rather than all n² pairs) focuses training on pairs with largest ground-truth score differences, reducing training complexity while preserving ranking fidelity.
6. At inference: generate n candidate responses, score each with R_proxy, return s* = arg max_{s∈S} R_proxy(s).

### Phase 2: Multi-Head Router Training

1. **Shared Backbone:** DeBERTa-v3-small (44M parameters) encodes query q into shared representation h_q.
2. **K × N Classification Heads:** For K small models and N maximum samples, train lightweight heads:

   p_{k,n}(q) = σ(w_{k,n}^T · h_q + b_{k,n})  for 1 ≤ k ≤ K, 1 ≤ n ≤ N    (Eq. 5)

   where p_{k,n}(q) is the "match probability" — the predicted probability that the best-of-n response from model k is at least as good as a single response from M_ref.

3. **Training Labels:** For each training query, compute:

   y_n(q) = Pr[R_GT(s*_small) ≥ R_GT(s_ref)]

   Then train with cross-entropy loss:

   L_pair = -(1/|Q|) Σ_{q∈Q} [y_n(q) log p_n(q) + (1-y_n(q)) log(1-p_n(q))]    (Eq. 4)

4. The multi-head design avoids training K × N separate pair-wise routers, dramatically reducing memory and latency.

### Phase 3: Inference-Time Routing (Algorithm 1)

```
Input: query q, max samples n, threshold t, proxy RM R_proxy,
       models {M_1,...,M_K}, reference M_ref, cost tables

1. PREDICT: For each (M_k, i) where 1≤i≤n:
     match_prob[(M_k,i)] ← MultiHeadRouter.predict_match_prob(q, M_k, i, M_ref)

2. FILTER & COST: valid_comb ← ∅
   For each (M,i) where match_prob[(M,i)] ≥ t:
     cost[(M,i)] ← i × avg_output_len[M] × output_price[M] + input_len × input_price[M]
     valid_comb ← valid_comb ∪ {(M,i)}
   (Note: input tokens charged once because modern LLMs support returning multiple sequences per query)

3. SELECT: If valid_comb ≠ ∅:
     (M*, i*) ← arg min_{(M,i)∈valid_comb} cost[(M,i)]
   Else:
     (M*, i*) ← (M_ref, 1)

4. EXECUTE: Generate i* responses from M*, score with R_proxy, return arg max score.
```

**Key design:** Output length unknown at inference — estimated using average training data lengths. Average estimation error: $0.0001-$0.0027 per query (Table 7).

|---|---|---|
| 10% | **0.19%** | 0.63% |

- N-class: 0.07% cost reduction (essentially always used GPT-4o)
- Clustering: 0% cost reduction (always used GPT-4o)

### Best-of-N Alone vs BEST-Route (Figure 5)
- Best-of-n with n=5 alone: 4.9% quality drop for Phi-3-mini, 1.1% for Llama-3.1-8B
- BEST-Route with max n=5: 0.21% quality drop at 20% cost reduction, 0.47% at 40%

- Before Codestral-22b: 0.50% quality drop at 10% cost reduction
- After adding Codestral-22b: **-0.10%** quality drop at 10% cost reduction (quality GAIN over GPT-4o), -0.50% at 20%

| Cost Red. | Cascade (exact match) | Cascade (BLEU) | Cascade (ROUGE) | **BEST-Route** |
|---|---|---|---|---|
| 60% | 7.26% drop | 6.61% drop | 7.02% drop | **0.80%** drop |

All cascading methods incurred significantly higher costs to deliver comparable quality.

### Latency Overhead (Figure 7)
- Multi-Head Router match probability prediction: 0.04s
- Best-of-n sampling (proxy RM scoring at n=20): 0.58s
- Total overhead: ~0.62s — **18.7× faster** than fastest local LLM (Llama-3.1-8B)
- Increasing n from 1 to 20 increases LLM generation latency by only 30-59%

### Models Used
GPT-4o ($5/$15 per 1M input/output tokens), GPT-3.5-turbo ($3/$6), Llama-3.1-8B ($0.3/$0.61), Mistral-7B ($0.25/$0.25), Mistral-8x7B ($0.7/$0.7), Phi-3-mini ($0.3/$0.9), Phi-3-medium ($0.5/$1.5), Codestral-22B ($1/$3)

### Dataset
10K instruction examples: 6K QA (MixInstruct), 2K Coding (RewardBench + CodeUltraFeedback), 2K Safety (RewardBench + BeaverTails). Split: 8K/1K/1K train/val/test.

## 3. Trade-Offs

| Win | Loss/Cost |
|---|---|
| 60% cost reduction with <1% quality drop vs. always-using-GPT-4o | Requires training proxy reward model (300M DeBERTa) and multi-head router (44M DeBERTa) |
| Routed quality CAN exceed GPT-4o by routing to specialized models (e.g., Codestral-22b on coding: -0.5% quality drop) | Output length unknown at inference; uses average-length estimate with up to $0.0027/query error |
| Tunable threshold t provides continuous cost-quality Pareto frontier | Training data requires 20 samples per query per model (expensive to construct) |
| Multi-head design: K×N lightweight heads over shared backbone vs. K×N separate routers | Not tested beyond 8 models; scaling properties unknown |
| Router overhead negligible (0.62s at n=20) vs. LLM inference (10-20s) | Best-of-n input tokens still charged once but relies on API support for multi-sequence generation |
| Generalizes OOD (MT-Bench) and across metrics (BLEU, ROUGE, armoRM) | Proxy RM ranking misalignment risk; evaluated only on English tasks |
| Adaptively allocates more compute to harder queries; prevents over-use of expensive models | Threshold t must be set manually per deployment; no automatic calibration |

## 4. Design Rationale

**Why Best-of-N + Routing combined:** Prior LLM routing (Ding et al. 2024, Ong et al. 2024) used only single responses from small models. When the quality gap between small and large models was substantial, routers defaulted to the large model on all but trivial queries, yielding negligible cost savings. Best-of-n sampling enables small models to close the quality gap through additional compute, which remains cheaper than a single large-model call.

**Why Multi-Head Router (not K×N separate routers):** Training and deploying separate pair-wise routers for each (model, n) combination would be computationally prohibitive. The shared backbone extracts a universal query representation, and lightweight classification heads (Equation 5) add negligible overhead. This enables routing across arbitrary model pools with a single model.

**Why Pairwise Ranking Loss (not pointwise regression):** The proxy RM only needs to rank responses correctly (ordinal), not estimate absolute quality scores. The pairwise loss (Equation 1) with worst-median-best triples focuses on clearly distinguishable pairs, avoiding training noise from similarly-scored responses.

**Why Cost Estimation via Average Lengths:** True output length is unknown at inference time. The average-length estimator has error bounded at $0.0027/query (Table 7), which is sufficient for distinguishing models at different cost tiers ($0.25 to $15/M tokens).

**Why Threshold-Based Selection (not learned):** The tunable threshold t gives deployment operators explicit control over the cost-quality trade-off. This is preferable to a fixed learned policy because real-world cost budgets and quality requirements vary across deployments.

## 5. Limitations & Failure Modes

1. **Proxy RM Misalignment:** The best-of-n selection depends on R_proxy ranking fidelity. If R_proxy misranks responses (reward hacking), the returned response may not be the true best. While Figure 2 shows consistent improvement in armoRM scores with increasing n (suggesting no reward hacking), this was evaluated only in-distribution.

2. **Scalability to Large Model Pools:** Only tested with 7-8 models. The multi-head router requires K×N classification heads. For hundreds of models (K large), the head count grows linearly. Efficiently scaling to vast model pools is unexplored.

3. **Output Length Estimation Error:** Uses training-set average lengths ($0.0001-$0.0027 error/query). For queries with unusually long outputs, the cost estimate systematically underestimates true cost, potentially selecting suboptimal (model, n) combinations.

4. **Training Data Construction Cost:** Requires generating 20 responses per query per model on the training set. For 8 models × 8K training queries, that is 1.28M LLM API calls just for training data construction.

5. **Single-Language, Single-Turn:** Evaluated only on English instruction-following tasks. Multi-turn conversational routing and cross-lingual settings unexplored.

6. **Dependency on Reference Model:** The framework requires a strong reference model M_ref (GPT-4o) as the quality target. If M_ref is unavailable or changes (new model release), the router must be retrained.

7. **No Formal Guarantees:** The cost-quality trade-off is empirical; there are no theoretical bounds on worst-case cost overruns or quality degradation.

## 6. Transfer to Lyra

**The One Transferable Idea:** BEST-Route's **multi-head router with test-time compute allocation via best-of-n sampling** is the direct idea to port. Lyra already needs model routing — dynamically choosing between cheap/fast and expensive/capable models per query. Instead of a simple binary router, Lyra can use a shared BERT encoder with lightweight classification heads to predict match probabilities for each (model, n) pair, then select the cheapest configuration that meets a quality threshold. Combined with it's own proxy reward model (trained via pairwise ranking on Lyra-specific task distributions), Lyra can achieve cost savings while maintaining quality by adaptively sampling more responses from smaller models instead of always falling back to the most expensive model.

**Tier:** breakthrough (the combination of best-of-n sampling + model routing is a significant improvement over the standard binary-routing baseline, with strong empirical results and clear transfer path)
