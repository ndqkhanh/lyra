## 1. Mechanism (step-by-step)

SERM is a **two-module multi-agent framework** that wraps a generative relevance model and enables it to continuously improve from live query streams without human annotation.

### Architecture

The system operates on a base LLM (Qwen2.5-7B or 1.5B) trained first with continual pre-training (100B-token corpus) then SFT (3.6M labeled query-document pairs with scores 0-3). The generative relevance model outputs a relevance label y in {0,1,2,3} and a rationale via:

```
Lg = -E_{(q,d,y)~Dr} log Pr_θ(y | q, d)        (cross-entropy over label tokens)
```

The relevance score f(q,d) is the expectation over label probabilities:
```
f(q,d) = Σ_{y∈Y} y · Pr_θ(y | q, d)
```

SERM then runs iterative self-evolution loops (every ~2 weeks), each processing ~700K query-document pairs:

### Module 1: Multi-Agent Sample Miner (MSM)

Identifies *informative and challenging* query-document pairs from massive streams. Four agents operate in parallel:

**A) User Feedback Agent**
- Detects pairs where user shows strong engagement (click OR dwell time > τ_u = 5s) BUT model confidence is low (f(q,d) < τ_c = 0.4)
- Signal: `1_click(q,d) = 1 ∨ U(q,d) > τ_u` AND `f(q,d) < τ_c`

**B) Click Model Feedback Agent**
- Uses a pre-trained click model R_cm to estimate click probability, compensating for position/presentation bias and sparse raw clicks
- Treats pair as clicked if predicted click probability > τ_cm = 0.1

**C+D) Intrinsic Feedback Agent**
- **Model Disagreement** (MD): Generate K relevance judgments with temperature sampling, measure max score spread:
  `MD(q,d) = max_{i,j} |f^i(q,d) - f^j(q,d)|`
- **Model Uncertainty** (MU): Entropy of relevance label distribution:
  `MU(q,d) = -Σ_y Pr_θ(y|q,d) · log Pr_θ(y|q,d)`
- High MD + high MU = sample where model is both inconsistent and unsure

For each query, up to `n=4` candidate documents are selected per agent, deduplicated, and passed to MRA.

### Module 2: Multi-Agent Relevance Annotator (MRA)

Two-level agreement framework using multiple external LLMs (GPT-4o, Gemini 2.5 Pro):

**Inner-Agreement Agent:**
- Retrieves external knowledge relevant to the query-document pair
- Generates 3 independent reasoning paths (multi-path CoT) per LLM
- Consolidates via majority voting for stable label prediction
- Mitigates single-pass LLM randomness

**Inter-Agreement Agent:**
- Reconciles outputs across multiple inner-agreement agents
- Retains only pairs where agents reach consensus (cross-model agreement)
- Aggregates all reasoning paths supporting the agreed label into a unified rationale
- Ensures only high-confidence signals propagate to training

### Self-Evolution Loop

Each iteration:
1. MSM mines informative samples from recent query stream
2. MRA annotates selected samples with labels + rationales
3. New data is mixed with previous iteration data + original SFT data (to prevent catastrophic forgetting)
4. Model is retrained with learning rate 3e-6

## 2. Results (real benchmark numbers)

### Offline — Qwen2.5-7B (3 iterations)

| Language Family | CT+SFT NDCG@1 | SERM Iter 3 NDCG@1 | SERM Iter 3 NDCG@4 | Gain NDCG@1 |
|---|---|---|---|---|
| Germanic | 84.74 | 87.56 | 87.71 | **+2.82** |
| Romance | 85.61 | 88.14 | 88.27 | **+2.53** |
| Minor Lang | 82.02 | 84.99 | 85.12 | **+2.97** |

Accuracy gains: Germanic +2.49pp, Romance +2.77pp, Minor +2.18pp

### Offline — Qwen2.5-1.5B (3 iterations)

| Language Family | CT+SFT NDCG@1 | SERM Iter 3 NDCG@1 | Gain |
|---|---|---|---|
| Germanic | 84.59 | 87.30 | **+2.71** |
| Romance | 85.99 | 87.83 | **+1.84** |
| Minor Lang | 81.75 | 84.75 | **+3.00** |

### SERM vs Self-Training baseline
- SERM consistently outperforms self-training by **1-2 points NDCG@4** at Iteration 3
- Self-training shows instability (e.g., Germanic NDCG@1 drops 84.95→84.78 from iter 2→3) due to error propagation; SERM shows monotonic improvement

### Distillation to 0.5B model
- SERM-distilled: Germanic NDCG@1 86.78 (vs CT+SFT 84.74 baseline 7B), outperforms self-training-distilled (83.86)

### Online A/B Test (distilled 0.5B model, ~70M users per group)

| Metric | Gain | p-value |
|---|---|---|
| User Negative Feedback | **-1.2081%** | 0.0001 |
| Change Query Ratio | **-0.0839%** | 0.0023 |
| Change Query Ratio (Longtail) | **-0.1312%** | 0.0015 |
| 14-Day Retention | **+0.0359%** | 0.0278 |

Absolute impact: +25,130 user-days of retention. At ByteDance scale, even 0.01% improvements are considered statistically and practically significant.

### Side-by-Side Human Eval (ΔSBS over baseline)

| Query Type | Germanic | Romance | Minor |
|---|---|---|---|
| Random | +7.7% | +4.7% | +8.0% |
| Longtail | +3.8% | +2.4% | +2.6% |

### Iterations 4-5: Saturation on static test set, but continued gains on evolving test set
- On static testing set: SERM plateaus near iteration 4 (NDCG@1 Germanic: 87.64 at Iter 4, 87.47 at Iter 5)
- On testing-v2 (new queries from most recent month): SERM continues monotonic improvement through Iter 5 (Germanic NDCG@1: 71.69→74.07→75.42→75.43→76.21→76.67), while self-training plateaus early

## 3. Trade-offs

| Win | Cost/Loss |
|---|---|
| +2.5-3.0 NDCG@1 across all language families vs static training | Requires external LLM API calls (GPT-4o + Gemini 2.5 Pro) per iteration — ~700K pairs per iteration at 3 reasoning paths each |
| Self-evolves continuously from live traffic — no human annotation needed after initial SFT | Two-week cadence between iterations needed for meaningful distribution shift; not real-time adaptive |
| MRA two-level agreement prevents error propagation that plagues self-training | External LLM annotation introduces dependency on third-party model quality and API stability |
| User satisfaction gains (-1.2% negative feedback) and retention (+0.036%) validated in production A/B | Gains measured as small percentages — only meaningful at massive scale (70M users) |
| Works with smaller models (1.5B, 0.5B distillation) | Performance plateaus on static test sets; continued evolution requires genuinely shifting query distributions |
| Multilingual: covers Germanic, Romance, and Minor language families | Only validated on document search; image/video search claimed as applicable but not tested |
| Distillation preserves gains (~1-2 NDCG points carry over to 0.5B model) | Catastrophic forgetting risk requires mixing new data with original SFT data in each iteration |

## 4. Design Rationale

**Why self-evolution over static training**: Real-world query streams continuously introduce novel expressions and cultural references (e.g., "remember me pets arriving on 10/27"). Static data cannot capture these, but live streams provide a perpetual source of adaptation signal.

**Why multi-agent mining over random sampling**: Most query-document pairs are easy/wrong for the model. Only informative samples (model disagrees with user behavior, or is internally uncertain) contribute to improvement. Four complementary agents catch non-overlapping failure signals.

**Why two-level agreement over single-LLM annotation**: Single-pass LLM labels are noisy. Inner-agreement (multi-path CoT + majority voting) reduces intra-LLM variance. Inter-agreement (cross-model consensus) filters out unreliable pairs entirely — only consensus cases train the model. This prevents the error propagation that causes self-training to degrade after iteration 2-3.

**Why external LLMs instead of pure self-training**: Self-training (model labels its own data) accumulates errors because the model cannot correct its own blind spots. External LLMs bring knowledge the model lacks — analogous to weak-to-strong generalization (Burns et al., 2024). The ablation shows removing inter-agreement drops performance significantly.

## 5. Limitations & Failure Modes

1. **Modality scope**: Only validated on document search. Image/video relevance tasks are claimed as applicable but untested in this work.

2. **Distribution-dependent saturation**: Performance plateaus on static test distributions (Iter 4→5 on original test set shows marginal gain). Gains only continue under genuinely shifting query distributions (testing-v2). In a stable query environment, SERM's advantage shrinks.

3. **External LLM dependency**: MRA relies on GPT-4o and Gemini 2.5 Pro for annotation. If these models have systematic biases on certain query types (e.g., cultural references, niche domains), those biases propagate into SERM's training data. The ablation shows that using GPT alone (without Gemini for inter-agreement) significantly degrades performance (NDCG@4 Germanic: 86.48 vs 87.71 full SERM).

4. **Two-week iteration latency**: The framework requires sufficient distribution shift between iterations to justify retraining. Not suitable for real-time or daily adaptation without modification.

5. **Catastrophic forgetting**: Requires careful data mixing (new + old + original SFT) in each iteration. The paper does not ablate the mixing ratio.

6. **Scale requirement**: The A/B gains (0.036% retention lift) are only meaningful at massive user bases (~70M users). Smaller platforms may not recoup the cost of external LLM annotation.

7. **No open-source data**: All datasets are proprietary ByteDance internal data. Reproducibility is limited.

8. **Confidence threshold sensitivity**: τ_c (0.4) and τ_cm (0.1) were tuned on a validation set. The sensitivity analysis (Figure 3) shows NDCG@4 varies by ~1 point across threshold values — suboptimal thresholds could erode gains.

## 6. Transfer to Lyra

**The ONE transferable idea**: The **Intrinsic Feedback Agent** — using model disagreement (multi-sample temperature spread) and model uncertainty (label entropy) as an *internal* signal to identify where the model is weak, entirely without user data or external oracle. This is directly applicable to Lyra's self-assessment loop.

**How it maps**: Lyra, as an agentic system, makes decisions (tool selection, reasoning paths). When Lyra generates multiple candidate action plans with temperature > 0, the spread of action choices and the entropy of its action distribution can identify situations where Lyra is internally conflicted. These "high-disagreement / high-uncertainty" states become prioritized for review, reflection, or human escalation — implementing an intrinsic quality gate without external labels.

**Workstream route**: §4.2 (Reliability/Self-Correction) — this idea directly feeds the verification subsystem (`src/verification/`) by providing a self-diagnostic signal that can trigger deeper verification passes or human-in-the-loop review on high-uncertainty decisions.

**Impact**: 4 (provides a principled, lightweight self-diagnostic that requires zero external annotation and works with any generative model)

**Effort**: 2 (entropy and disagreement computation are already available from logits; the main work is wiring them into Lyra's action-routing and verification pipeline)

**Tier**: **investigate** — high promise but requires empirical validation on Lyra's specific action distribution (the entropy signal may be less informative for tool-choice than for relevance scoring).
