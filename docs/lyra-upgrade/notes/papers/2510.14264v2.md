# AlphaQuanter: An End-to-End Tool-Augmented Agentic Reinforcement Learning Framework for Stock Trading

**Authors:** Zheye Deng (HKUST), Weixiang Yan (UC Santa Barbara), Changlong Yu (HKUST), Jiashu Wang (HKUST)

**Venue:** arXiv preprint 2510.14264v2 (19 Apr 2026); code at https://github.com/horizon-llm/AlphaQuanter

---

## 1. Mechanism

AlphaQuanter is a **single-agent RL framework** that trains an LLM to autonomously orchestrate tools and acquire information on demand for stock trading decisions. The approach has four layers:

### 1.1 MDP Formulation
Trading is modeled as a **tool-augmented Markov Decision Process** (MDP) with:
- **State** `s = (initial_context, query_history, query_results)` — accumulated information including stock symbol, date, past tool calls, and their outputs.
- **Action Space A** = `A_q ∪ A_d`: Query actions `A_q = {f_1, ..., f_11}` invoke external tools (market data, technical indicators, news, Reddit sentiment, macro indicators, balance sheet, cash flow, income statement, insider transactions, dividends, earnings estimates); Decision actions `A_d = {BUY, SELL, HOLD}` terminate the episode.
- **Transition** is deterministic: each query action appends the call and result to state; a decision action ends the episode.
- **Reward** `R(τ) = Σ R(s_t, a_t)` across the trajectory until the first decision action.

### 1.2 Cognitive Workflow (ReAct-style)
The agent follows a structured loop:
1. **Plan** (`P_0`): Generate initial hypothesis about the stock based on date/symbol.
2. **Acquire** (`A_i`): Identify information gap, execute ONE tool call.
3. **Reason** (`R_{i+1}`): Analyze tool output within `<think>` tags, update beliefs.
4. **Act**: Either loop back to Acquire (max 8 tool calls) or commit via `<answer>BUY|SELL|HOLD</answer>`.

The prompt enforces: one tool call per turn, structured reasoning inside `<think>` tags, adaptive hypothesis testing (not a fixed script).

### 1.3 Reward Formulation
The total reward is a **weighted sum of three components**:

```
R = α·R_result + R_format + R_tool
```

Where `α = 5` (emphasizes outcome over process):

**R_result** (Outcome Score): Uses exponentially weighted forward return to smooth market noise:
```
r_t = Σ_{h=1}^{H} ω_h · (p_{t+h+1} / p_{t+1} - 1)
ω_h = η^h / Σ_{i=1}^{H} η^i,  η ∈ (0,1), H = 7
```
Threshold `θ = 0.015` classifies market state, then assigns discrete rewards:

| Market State | BUY | SELL | HOLD |
|---|---|---|---|
| Highly Bullish (r_t > θ) | +1.0 | -1.0 | -0.75 |
| Highly Bearish (r_t < -θ) | -1.0 | +1.0 | -0.75 |
| Sideways (|r_t| ≤ θ) | -0.5 | -0.5 | +1.0 |

Asymmetric penalties: wrong side of strong trend (-1.0) penalized more than missed opportunity (-0.75).

**R_format** (Format Score): Penalizes reasoning traces outside target token interval [200, 600]; rewards proper `<think>` tag usage with +0.005 per segment; applies quadratic penalty `0.01·(len-200)(len-600)/30000` outside range (Algorithm 1).

**R_tool** (Tool Score): Penalizes duplicate tool calls (-0.05 each), invalid arguments (-50.0 for future-date references), tool counts outside [4, 8], and malformed JSON blocks (-|tool_list|²/10). This specifically prevents the "collect-then-conclude" degenerate pattern (Algorithm 2).

### 1.4 Training
- **Algorithm**: GRPO (Group Relative Policy Optimization) via the `verl` framework
- **Backbone models**: Qwen2.5-3B-Instruct, Qwen2.5-7B-Instruct
- **Key hyperparams**: LR = 1e-6, KL loss coef = 0.05, clip ratio [0.1, 0.1], max user/assistant turns = 32, rollout n = 16, train batch size = 32
- **Hardware**: NVIDIA A100 GPUs (80GB)
- **Inference**: Deterministic decoding (temperature = 0), 3 independent runs per config

## 2. Results

### 2.1 Main Backtesting (Jan–Jun 2025, 122 trading days)

| Model | Avg ARR | Avg SR | Avg MDD |
|---|---|---|---|
| **AlphaQuanter-7B** | **34.94%** | **0.65** | 24.93% |
| AlphaQuanter-3B | 23.03% | 0.43 | 25.16% |
| TradingAgents (GPT-4o) | 16.49% | 0.50 | 21.82% |
| FinMem (GPT-4o) | 13.71% | 0.30 | 29.14% |
| Market (Buy & Hold) | 12.90% | 0.57 | 31.13% |
| FinRL-PPO | 12.22% | 0.51 | 33.72% |
| TradingAgents (Qwen2.5-7B) | 1.50% | -0.08 | 6.43% |

Key deltas: AlphaQuanter-7B outperforms strongest baseline by **+18.45% absolute ARR**. On NVDA alone: 45.41% ARR, on TSLA: 42.67% ARR. The 7B model outperforms ALL baselines on 3 of 5 stocks.

## 3. Trade-offs

| Win | Cost / Loss |
|---|---|
| **+18.45% ARR** over strongest baseline (GPT-4o multi-agent) | Requires RL training infrastructure (A100 GPUs, verl/GRPO pipeline) — not zero-shot deployable |
| **0.15× token cost** vs multi-agent (4.1K vs 27.2K per decision) | Slightly higher token cost than prompt-only single-agent (3.1K) which achieves only 4.49% ARR |
| **Highest faithfulness** across all three human-rated metrics (alignment, grounding, conciseness) | Training dynamics are model-size sensitive: 3B model prematurely converges to simplistic exploitation; only 7B successfully enters refinement phase |
| **High information selectivity** — 7B model learns expert-like heuristic (prioritizes trend/momentum/volume, downweights low-frequency fundamentals) | Bounded by predefined toolset — cannot invent new analytical functions |
| Controllable risk-return via θ threshold: higher θ → lower MDD (9.18%) but lower ARR (21.25%); lower θ → higher ARR potential but higher MDD (32.67%) | Single-asset scope only — not directly applicable to portfolio-level decisions |
| Process rewards (R_format + R_tool) prevent degenerate strategies (collapsing to single action, collect-then-conclude) | Removing either format or tool score causes 40-53% ARR degradation, showing fragility to reward design |
| Deterministic decoding (temp=0) ensures reproducibility | Eliminates exploration diversity at inference — may miss opportunistic trades |

## 4. Design Rationale

1. **Single-agent over multi-agent**: For smaller LLMs (3B-7B), multi-agent debate injects noise and amplifies hallucinations rather than yielding complementary insights. Except GPT-4o, all multi-agent backbones underperform. Single-agent produces consistent, traceable decisions without conflicting signals.

2. **RL over prompt-based reasoning**: Prompt-based baselines (except GPT-4o) **fail to beat the market** on average. The core failure mode is inability to calibrate the BUY-vs-HOLD decision boundary from market signals. RL explicitly trains this mapping. Specialized training matters more than model scale.

3. **Three-component reward (outcome + format + tool)**: Pure outcome optimization leads to degenerate tool-use (single-round collection, then answer). Format and tool scores act as behavioral regularizers that enforce structured, efficient, evidence-grounded workflows — mirroring the discipline expected of professional analysts.

4. **Asymmetric penalty scheme**: Wrong-direction trades penalized more (-1.0) than missed opportunities (-0.75). This reflects professional risk management where capital preservation takes priority over capturing every move.

5. **ReAct + tool augmentation over black-box RL**: Enables step-by-step inspection of decision traces, supporting regulatory audits and user trust — a deliberate move away from opaque models.

---

## 5. Limitations & Failure Modes

1. **Bounded toolset**: The agent can orchestrate existing tools but cannot generate novel analytical methods — it cannot innovate beyond its predefined information sources.
2. **Single-asset scope**: Decisions are per-stock; the framework does not handle portfolio-level allocation, correlation, or cross-asset hedging.
3. **Context accumulation problem**: As tool calls accumulate, the input context grows linearly with observations — acknowledged need for agent memory/summarization mechanisms.
4. **Limited market coverage**: Only 5 large-cap US tech stocks, and only a 6-month test period (Jan–Jun 2025). No evaluation across diverse market regimes (e.g., 2008 crisis, 2020 COVID crash).
5. **Backtesting only**: No live trading, no paper trading, no consideration of market impact or execution latency.
6. **Model-scale fragility**: The 3B model prematurely converges to simplistic exploitation (few tool calls, decreasing response length) while only the 7B model successfully enters a policy refinement phase.
7. **No cross-stock generalization reported**: Each stock requires separate training; it is unclear whether a policy trained on one stock transfers to another.

## 6. Transfer to Lyra

**The ONE transferable idea:** The **three-component reward decomposition** `R = α·R_outcome + R_format + R_tool` trained via GRPO, which jointly optimizes decision quality, reasoning structure, and tool-use efficiency. Crucially, `R_tool` includes a specific penalty for the "collect-then-conclude" anti-pattern (acquiring all data in one round then answering immediately), and `R_format` enforces stepwise reasoning within bounded token intervals. This reward architecture transforms tool use from a prompt-level suggestion into a learnable, optimized policy behavior.

**Workstream routing:** §4.2 (Agent Training & Optimization) — directly applicable to training Lyra agents to use tools in a structured, evidence-grounded manner with verifiable decision traces.

**Impact:** 4/5 — Addresses a core weakness in current LLM agents (degenerate tool use, unverifiable reasoning) and produces measurable improvements in both performance (+18% ARR) and faithfulness (+35% overall score).

**Effort:** 4/5 — Requires GRPO training infrastructure (verl or similar), domain-specific reward engineering (defining R_result for each task), and careful hyperparameter tuning (θ, α, token ranges). Not a drop-in solution.

**Tier:** **breakthrough** — The reward-engineering pattern (outcome + format + tool) is generalizable beyond trading to any agentic task requiring structured tool use, and the empirical gains are large and well-ablated.
