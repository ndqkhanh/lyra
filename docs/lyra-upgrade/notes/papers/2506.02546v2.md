## 1. Mechanism

### Step 1: Six-Dimensional Trust Definition
The authors distill trustworthiness into six orthogonal dimensions drawn from Grice's (1975) cooperative principle in human communication theory:
1. **Factual accuracy** — verifiably true claims supported by evidence
2. **Logical consistency** — internally coherent, no contradictions or fallacies
3. **Relevance (to context)** — addresses the prompt/question without off-topic content
4. **Bias** — maintains objectivity, avoids prejudice or emotional/ideological slant
5. **Clarity** — unambiguous, concise, easy to understand
6. **Language quality** — fluent, grammatically correct, stylistically appropriate

### Step 2: Trust Violation Dataset
A controlled dataset of >20k samples across six violation classes plus a benign class. Each untrustworthy sample is crafted to breach exactly one dimension while satisfying the other five, enabling isolated, fine-grained analysis. Sources: FEVER (fact), StereoSet (bias), GPT-4o-generated (logic, relevance, clarity, quality). Tasks drawn from math reasoning, code generation, and general QA, contextualized as realistic LLM-MAS communications with agent profiles and task instructions.

### Step 3: Attention Extraction
For an LLM with L layers and H heads, given input P = C|M (context concatenated with message):
- Extract attention weights α^i_{l,h}: weight from the last token to the i-th token of M in layer l, head h
- Aggregate across tokens using geometric mean (more stable than arithmetic mean per Liang et al., 2024):

  **Attn_{l,h}(M) = Π_{i=1:|M|} (α^i_{l,h})^{1/|M|}**

- Average across layers per head: **Attn_h(M) = Mean({Attn_{l,h}(M)}^{L}_{l=1})**
- The attention vector Attn(M) = (Attn_1(M), ..., Attn_H(M)) serves as the input feature

### Step 4: A-Trust Score Computation
For each of the six trust dimensions r, train a logistic regression classifier f_r using a one-vs-rest strategy:
- Positive samples: messages violating dimension r (1500 samples)
- Negative samples: equal number from other classes
- At inference, compute: f_r(Attn(M_test)) ∈ [0,1] — probability that M_test violates dimension r
- The six probabilities collectively form the A-Trust score vector

### Step 5: Trust Management System (TMS)
Three-layer architecture operating independently of agents:

**Layer 1 — Message-level trust evaluation**: Extract attention matrices from a dedicated LLM (separate from agent LLMs), run A-Trust models to produce six per-dimension raw trust scores (s_fact, ..., s_clarity).

**Layer 2 — Trust-aware action policy**: Apply per-dimension thresholds τ = (τ_fact, ..., τ_clarity). If any dimension's score exceeds its threshold, the message is flagged untrustworthy and filtered. Thresholds are optimized to maximize: **max_{τ_r} TVR + TBR - FVR - FBR**, where:
- TVR = P(score > τ | violation) — True Violation Rate
- FVR = P(score > τ | non-violation) — False Violation Rate
- TBR = P(score ≤ τ | non-violation) — True Benign Rate
- FBR = P(score ≤ τ | violation) — False Benign Rate

**Double-threshold for factual dimension**: When s_fact falls between τ_low and τ_high, invoke Gemini-2.0-flash with Google Search as an external verifier.

**Layer 3 — Agent-level trust records**: Maintain timestamped records R_{A_i} = {(t_k, (s^r_k), (v^r_k))}^{K_i}_{k=1} for each agent, tracking raw scores and violation flags. Compute violation rate VR_r over a sliding window (20 queries); if VR_r > 80%, flag and remove the agent.

### Key Empirical Findings from Attention Analysis
- Untrustworthy messages elicit higher overall attention than benign ones
- Different violation types activate distinct attention head patterns (e.g., head 2 for Relevance, head 21 for Clarity, head 27 for Quality)
- Some heads (4, 29, 30) are general-purpose high-level semantic detectors
- Attention-based signals separate violation/non-violation distributions far more cleanly than perplexity or prompt-based methods

## 3. Trade-offs

| Win | Cost / Loss |
|-----|-------------|
| MDR >80% across diverse attacks and agent structures | Requires white-box access to LLM attention matrices |
| 28x faster than prompt-based trust evaluation (0.41s vs 11.71s) | 7.7x slower than perplexity baseline (0.41s vs 0.053s) |
| Interpretable per-dimension scores with clear semantics | Only 6 dimensions covered; may miss novel violation types |
| Works across backbone LLMs (Llama3.1, GPT-4o, Qwen2.5, Gemma3) without retraining | Gemma3-4B with only 8 heads has insufficient head diversity for fine-grained detection |
| Agent-level records enable 100% ADR and near-zero ASR (0.8-2.5%) | Agent-level intervention requires ~20 query warm-up window before flagging |
| Clean accuracy degradation <2% (preserves utility) | Clean false positive rate 6.7-9.6% (some benign messages filtered) |
| Optional external fact verification via double-threshold | Fact dimension has weakest TBR (67%); factual accuracy requires external knowledge |
| Logistic regression models are lightweight and fast | Requires dedicated LLM instance for attention extraction from TMS |

## 4. Design Rationale

The authors argue that existing LLM-MAS security research addresses trustworthiness in piecemeal fashion (factual accuracy alone, logical consistency alone) without a unifying framework. By anchoring their definition in Grice's (1975) cooperative principle from human communication theory, they provide a principled, comprehensive vocabulary for trust. The choice of attention-based signals over prompting is motivated by empirical findings that prompt-based trust scores show a "notable mismatch between the model's internal attention patterns and its final outputs" — LLMs often fail to explicitly flag untrustworthy content even when their attention heads react to it. Logistic regression was chosen over deep classifiers because the attention vectors are low-dimensional (equal to number of heads, e.g., 32 for Llama3.1-8B) and the dataset is moderately sized (~20k samples), making lightweight models deployment-friendly and fast. The one-vs-rest training strategy balances class sizes (1,500 positives each) and produces calibrated probability scores per dimension.

## 5. Limitations & Failure Modes

1. **Incomplete trust coverage**: The six Gricean dimensions may not capture all factors affecting inter-agent communication reliability (e.g., intent, authority, timeliness, source credibility). Scaling to additional dimensions is acknowledged as future work.
2. **Balanced-resource assumption**: Experiments assume roughly equal compute allocation across agents. Resource imbalances may affect trust assessment accuracy.
3. **Stealthy evasion**: Highly subtle malicious messages that weakly violate trust dimensions or deliberately mimic benign patterns may evade detection. Lowering thresholds to catch such cases would increase false positives.
4. **White-box requirement**: A-Trust requires direct access to internal attention matrices, limiting applicability to API-only or black-box LLM deployments.
5. **Weak factual dimension**: The factual accuracy dimension achieves only 67% TBR (vs >90% for other dimensions), indicating LLMs lack sufficient internal knowledge for fact-checking. The double-threshold external verifier partially addresses this but introduces latency and dependency.
6. **Head count sensitivity**: Models with few attention heads (e.g., Gemma3-4B with 8 heads) show less discriminative power than models with 32 heads.
7. **No adaptive attack evaluation**: The system has not been tested against adversaries who know the TMS mechanism (trust evasion / camouflage attacks are discussed theoretically but not empirically evaluated).
8. **Single trusted LLM**: TMS relies on a separate LLM for attention extraction; if that LLM were compromised, the entire trust mechanism would fail.

## 6. Transfer to Lyra

### The One Transferable Idea
**Attention-based internal trust scoring for inter-agent message filtering in Lyra's multi-agent orchestration layer.** Rather than relying on prompt-based evaluation (slow, inconsistent) or external verifiers (latency, dependency), Lyra could instrument its agent communication channels with a lightweight, attention-derived trust signal that flags untrustworthy messages across multiple dimensions before they corrupt agent reasoning. This is particularly valuable for Lyra's planned A2A-style agent interoperability, where agents from diverse/untrusted sources may exchange messages.

### Workstream Route
**§4.6 — Safety & Guardrails** (primary) or **§4.7 — Agent Communication Protocols** (secondary). The mechanism directly addresses Lyra's need for a principled trust layer in multi-agent communication, complementing existing safety work on prompt injection and output filtering with an internal-signal approach.

### Impact / Effort / Tier
- **Impact**: 4 — Directly strengthens Lyra's security posture for multi-agent deployments; interpretable dimensions align with Lyra's transparency goals; works cross-model
- **Effort**: 3 — Requires white-box LLM access (available for Lyra's local models); logistic regression models are simple to implement; Trust Violation dataset construction is the main cost (~20k samples with LLM generation)
- **Tier**: **breakthrough** — This is a novel, principled approach that no existing agent framework (AutoGen, CrewAI, MetaGPT) has adopted; implementing it would give Lyra a differentiated security capability and directly addresses the A2A trust problem identified in Lyra's architecture debates
