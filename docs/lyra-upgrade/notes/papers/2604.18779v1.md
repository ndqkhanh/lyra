# MANGO: Multi-Agent Web Navigation via Global-View Optimization (Weixi Tong, Yifeng Di, Tianyi Zhang — Purdue University, 2025)

## 1. Mechanism (step-by-step)

MANGO rethinks web agent navigation by constructing a **global view of website structure before navigation begins**, then using a **Thompson Sampling bandit** to allocate a fixed navigation budget across the most promising entry-point URLs.

### Step 1: Global Structure Analysis (pre-navigation)
1. **Lightweight BFS crawl** from the root URL, capped at τ=1000 pages, filtering non-HTML files and external domains. Uses Crawl4AI's `BFSDeepCrawlStrategy` with markdown extraction.
2. **BM25 ranking** of crawled page content against user query q — top 10 URLs added to candidate set U.
3. **Google site-search augmentation** — LLM recommends search keywords from the query (see prompt Table 6), then `site:` operator retrieves additional relevant pages; top 10 added to U. This handles websites too large to crawl fully (e.g., arXiv with 2.9M+ pages).

### Step 2: Multi-Armed Bandit URL Selection with Thompson Sampling
- Formulate URL selection as a **finite-lifetime MAB** (inspired by Chakrabarti et al. 2008), but with *dynamic* arm deactivation decided by a reflection agent rather than fixed lifetimes.
- **Initialization**: For each URL u in candidate set U, initialize Beta(α_u, β_u) from the normalized BM25 score ρ_u:
  - α^(0)_u = 1 + κ·ρ_u
  - β^(0)_u = 1 + κ·(1 - ρ_u)
  - κ is a weight parameter (optimal κ=3 in experiments)
- **Selection**: At each step t, sample θ_u ~ Beta(α^(t)_u, β^(t)_u) for each active arm; select u* = argmax θ_u.
- **Update**: After navigation, the reflection agent outputs a status. Assign Bernoulli reward r ∈ {0,1}:
  - α^(t+1)_u = α^(t)_u + r
  - β^(t+1)_u = β^(t)_u + (1 - r)
- **Arm deactivation**: If status = dead_end, mark URL exhausted (removed from active set).

### Step 3: Web Navigation Agent
- Takes (query q, selected URL u*) as input, operates with budget b=10 per URL.
- If URL was previously visited, retrieves trajectory + reflection summary from episodic memory.
- Browser environment is **pluggable** — uses Playwright for WebVoyager, Crawl4AI for WebWalkerQA (matched to SOTA baselines).
- Ends in two states: task_completion (hand off to success reflection agent) or budget_exhaustion (hand off to failure reflection agent).

### Step 4: Reflection Agent + Episodic Memory
- **Task completion case**: LLM evaluator judges output as "adequate" (r=1, stop) or "inadequate" (r=0, needs more navigation).
- **Budget exhaustion case**: LLM evaluator judges trajectory as "feasible" (r=1, URL still promising) or "infeasible" (r=0, dead end, arm deactivated).
- Status, trajectory, output, and reflection stored in episodic memory for future iterations.
- On revisiting a URL, prior trajectory is retrieved to avoid repeating failed actions.

### Step 5: Iteration
- Repeat Steps 2-4 for up to 10 Thompson Sampling iterations total (navigation budget per URL × bandit iterations both capped at 10).

### Key Equations
```
ρ_u = (λ_u - min(λ)) / (max(λ) - min(λ) + ε)  [BM25 normalization]
α^(0)_u = 1 + κ·ρ_u, β^(0)_u = 1 + κ·(1-ρ_u)  [Beta prior initialization]
u* = argmax_{u∈U_act} θ^(t)_u, θ^(t)_u ~ Beta(α^(t)_u, β^(t)_u)  [Thompson Sampling]
α^(t+1)_u = α^(t)_u + r^(t), β^(t+1)_u = β^(t)_u + (1 - r^(t))  [Posterior update]
```

### Hyperparameter sensitivity (optimal values, Qwen3-32B on 100-task subset)
- Navigation budget b: peak at 15 actions/URL (SR ~30%), drops at 20 (confabulation)
- TS iterations: monotonically increases with more iterations
- Weight κ: peak at κ=3 (SR 26%), drops to 18% at κ=9 (overpowers reward signal)
- Crawl limit τ: peak at τ=1000 (SR 26%), no gain at 2000
- Candidate set size: Top-10 optimal from both crawl and Google sources

## 3. Trade-offs (wins vs loses)

| Win | Lose |
|-----|------|
| +26.8% absolute on WebWalkerQA over best baseline (GPT-5-mini) | Higher action count per successful task (14-19 actions vs 7-10 for baselines with GPT-5-mini) |
| +54.1% absolute on WebVoyager over best baseline (GPT-5-mini) | Pre-navigation crawl cost: up to 1000 pages crawled per task, adding latency |
| Works across model sizes (4B→32B monotonic scaling) and both open/closed-source | BM25 initializes bandit weakly on pages with subtle semantic differences vs embedding methods |
| Thompson Sampling beats MCTS by 5-17% absolute across all settings | Episodic memory adds storage/retrieval overhead |
| Pluggable browser backend for fair comparison | Partial structural visibility: tasks with deeply buried targets exceed budget |
| Episodic memory reduces redundant exploration (8% gain) | Google search dependency for sites where `site:` fails |
| No fine-tuning required; works with API-only models | High κ values (>5) harm performance by overpowering bandit feedback |

## 4. Design Rationale

MANGO's core insight is that **starting web navigation from the homepage is needlessly inefficient** — it forces agents to discover website structure incrementally through trial and error. Instead, MANGO constructs a global structural view once (via cheap BFS crawl + site-specific Google search) and then uses that view to select optimal entry-point URLs.

**Why Thompson Sampling over MCTS?** The authors argue MCTS expands a massive search tree from the root, which wastes computation on irrelevant branches. Thompson Sampling directly allocates budget to the most promising URLs based on both BM25 relevance priors AND reflection feedback — a much leaner exploration strategy.

**Why BM25 over embeddings?** BM25 is cheaper to compute for 1000 crawled pages per task than running embedding models. The embedding variant (KaLM-Embedding-V2.5) performs slightly worse (53% vs 55% on the subset), possibly due to BM25's superior sensitivity to subtle keyword differences in page URLs.

**Why episodic memory?** Without memory, the agent repeats the same actions when revisiting a URL. The 8% absolute degradation when memory is removed confirms the value of avoiding redundant exploration.

## 5. Limitations & Failure Modes

**Failure mode distribution** (323 manual inspections, GPT-5-mini on WebWalkerQA):
1. **Navigation Error (77.0%)**: Agent fails to locate the correct page — follows ambiguous links, gets lost in tangential branches.
2. **Reasoning Error (15.4%)**: Agent reaches the correct page but extracts/reads the wrong information (e.g., class of 2022 instead of 2020).
3. **Out-of-date Golden Answers (5.6%)**: Agent answers correctly but benchmark gold labels are stale.
4. **Reflection Error (2.0%)**: Reflection agent prematurely classifies partial output as "adequate."

**Structural limitations**:
- Purely text-based crawling (markdown extraction) — misses information embedded in images, videos, interactive elements.
- Partial structural coverage: no guarantee of reaching deeply buried target pages on large sites (100K+ pages).
- BM25 initialization may misrank pages with high semantic but low lexical overlap with the query.
- Thompson Sampling prior can overpower reward signal if κ is set too high (>5).
- Google site-search dependency: some websites block search indexing or have non-standard URL structures.
- Navigation budget × TS iterations both capped at 10 — tasks requiring >20 total navigation steps inherently fail.

## 6. Transfer to Lyra

**The one transferable idea**: Use **Thompson Sampling bandits for budget-constrained resource allocation across candidate entry points** — just as MANGO treats URLs as bandit arms and allocates navigation budget based on dynamic reward signals from a reflection agent, Lyra could use Thompson Sampling to allocate its computational/search/research budget across candidate information sources, hypotheses, or sub-tasks, dynamically reallocating based on reflection-agent feedback rather than following a predetermined search order.

**Workstream route**: §4.2 (Agent Memory & Context Management) — the episodic memory + bandit framework directly extends Lyra's context management and decision-making architecture.

**Impact**: 4 (high — fundamentally improves budget allocation for multi-step agent tasks; directly applicable pattern)
**Effort**: 3 (moderate — requires implementing Thompson Sampling posterior updates and reflection agent reward signal; BM25 ranking and web crawling are Python-stdlib-adjacent)
**Tier**: investigate (strong pattern but requires adaptation from web-navigation domain to Lyra's general-agent domain; worth prototyping on a constrained sub-problem first)
