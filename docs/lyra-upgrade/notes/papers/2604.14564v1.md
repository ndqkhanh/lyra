## 1. Mechanism (Step-by-Step)

MARS² addresses two intertwined challenges: (1) diminishing exploration gains in single-policy search-augmented RL, and (2) the lack of structured search integration in existing multi-agent collaboration methods. The framework embeds multiple independently-optimized policies into a shared tree-structured search environment.

### 1.1 Problem Formulation

Given input problem x and reasoning budget N, standard parallel sampling draws N i.i.d. candidates from a single model distribution: y_i ~ f_M(· | x). MARS² replaces this with multi-agent collaborative tree search where N expansion steps produce nodes ŷ = {ŷ_1, ..., ŷ_N}, each a complete candidate solution.

The generation of each tree node is formalized as a joint distribution:

```
ŷ_i ~ g_i(m) · f(· | x, m, ŷ_{τ(i)}, o)
```

where g_i(m) is the probability of selecting agent m ∈ {M_1, ..., M_m} at step i, ŷ_{τ(i)} is the parent node, and o is observable environment feedback (e.g., execution results, error messages).

### 1.2 Agent-Node Selection via Thompson Sampling

At each expansion step, the search is formulated as a **two-level multi-armed bandit** over agent-node pairs:

1. **Level 1 — Agent Selection**: Beta priors model selection probabilities over agents. Thompson sampling selects the most promising agent.
2. **Level 2 — Node Selection**: Thompson sampling again selects a node associated with the chosen agent for expansion.

**Two functional node types**:
- **Generation node** (virtual): Propose a brand-new candidate solution → horizontal expansion
- **Refinement node** (existing): Extend an existing node previously generated by that agent along the current path → vertical refinement

This design enables dynamic trade-off between exploitation (refining high-quality trajectories) and exploration (generating diverse new candidates).

### 1.3 Tree-Node-Level Reward Assignment (Eq. 1-2)

Extending GRPO's group-relative advantage to the tree level:

```
Â_{k,jk} = (r_{k,jk} - mean(r_{1,j1}, ..., r_{N,jN})) / std(r_{1,j1}, ..., r_{N,jN})   (2)
```

where r_{k,jk} is the reward of the node generated at the k-th expansion by agent j_k.

However, nodes are not generated independently — agents iteratively refine/diversify solutions. A purely global advantage fails to capture hierarchical dependencies (a child should improve upon its parent and outperform siblings).

### 1.4 Tree-Consistent Reward Shaping (Eq. 3-5)

**Mixed baseline** for any non-root node v:

```
b(v) = (1-λ) · r_{p(v)} + λ · μ_{C(p(v))\v}   (3)
```

where r_{p(v)} is the parent node reward, μ_{C(p(v))\v} is the mean reward of sibling nodes sharing the same parent, and λ ∈ [0,1] balances vertical improvement vs. horizontal competition. When a parent has only one child, the baseline degenerates to the parent reward.

**Structural consistency gain**:

```
Δ(v) = r_v - b(v)   (4)
```

**Shaped reward**:

```
r̂_v = r_v + γ · Δ(v)   (5)
```

where γ controls shaping strength. This mechanism preserves original task reward semantics while explicitly encouraging both parent-child improvement and sibling-level competition.

### 1.5 MARS² Optimization Objective (Eq. 7-8)

Building on GRPO, the optimization unit is extended from parallel trajectories to tree nodes. Each agent j is optimized independently using rewards collected at tree nodes it generates:

```
J_{MARS²}(Θ) = E_{q~D, {o_i}~π_{Θ_old}} [ (1/N) Σ_{j=1}^{m} Σ_{v∈T_j(q)} Σ_{t=1}^{|o_v|}
    min(w(v,t,θ_j) · Â_{v,j}, clip(w(v,t,θ_j), 1-ε_low, 1+ε_high) · Â_{v,j})
    - β D_KL(π_{θ_j} || π_{ref}) ]   (7)
```

The advantage estimator combines tree-level group advantage with reward shaping:

```
Â_{v,j} = (r̂_{v,j} - mean(r̂_{1,j1}, ..., r̂_{N,jN})) / std(r̂_{1,j1}, ..., r̂_{N,jN})   (8)
```

Key design: Θ = {θ_1, ..., θ_m} — each agent has independent parameters, enabling heterogeneous policy distributions that collaboratively expand the exploration frontier.

### 1.6 Training Stabilization (Appendix B)

- **GSPO**: Replaces token-wise importance aggregation with geometric mean over the whole sequence
- **Overlong Penalty**: R_length(y) = 0 when |y| ≤ L_max - L_cache; linear penalty in cache zone; R_length(y) = -1 when |y| > L_max
- **TIS (Token-wise Importance Sampling)**: Aligns rollout probabilities from vLLM with FSDP training distribution via log-ratio correction
- **Asynchronous Updates**: Buffer-based updates to avoid synchronization bottlenecks from stochastic tree search
- **Training Budget**: 8/16 MCTS nodes, max prompt length 4096, max generation length 32768, LR 1×10⁻⁶, ZeRO Stage 3, bfloat16

### 1.7 Inference Protocol

- Unified MCTS-based inference with fixed 60-node budget for all methods
- **Latest-wins rule**: Select the response that passes public tests and was generated at the latest (deepest) expansion step
- Two evaluation dimensions: (1) single-pass sampling (Pass@1), (2) MCTS-based search (Pass@1(MCTS), Pass@N)
- Pass@N: probability at least 1 out of N generated solutions passes all unit tests

## 4. Design Rationale

**Why multi-agent + tree search rather than either alone?** Single-policy search (e.g., TreeRL, RS2) remains bounded by the model's prior distribution — as training progresses, search concentrates on high-probability branches (verified by diminishing returns in Fig. 5). Multi-agent dialogue/debate methods (MAPoRL, MARTI) lack structured exploration — they treat agent interaction as lightweight coordination rather than systematic search. MARS² unifies both: heterogeneous policies induce non-stationary exploration distributions (MARL property) while the tree topology provides structured branching, backtracking, and principled budget allocation.

**Why Thompson sampling?** Models agent-node selection as a multi-armed bandit over Beta priors, providing Bayesian uncertainty-driven exploration. This naturally balances exploiting agents/nodes with high historical reward against exploring uncertain ones.

**Why tree-consistent reward shaping?** A naive global tree advantage ignores that a child node's contribution depends on improvement over its parent and outperformance of siblings. The mixed baseline b(v) = (1-λ)r_parent + λ·μ_siblings captures both vertical (refinement quality) and horizontal (competitive diversity) credit signals.

**Why independent per-agent optimization?** Each agent maintains independent parameters Θ = {θ_1, ..., θ_m}, trained on nodes it generates. This preserves policy heterogeneity — agents specialize in different exploration strategies without collapsing to a shared distribution.

## 5. Limitations and Failure Modes

1. **Sequential tree expansion bottleneck**: Training throughput degrades because tree nodes must be expanded sequentially, reducing rollout parallelism compared to i.i.d. sampling. Performance gains come from structure, not more compute — but the structure itself is slower.

2. **Single-agent search saturation**: RS2 training exhibits clear plateau behavior — Pass@1 stops improving, reward variance decreases, and KL divergence trends suggest policy collapse toward narrow high-probability regions. Tree search alone cannot escape single-policy prior bounds.

3. **Weaker agent interference**: Introducing a weaker model (DeepCoder-14B) into the ensemble reduces individual agent gains (Qwen3-14B: +5.1% → +3.4% under RS2), as noisier trajectories contaminate shared search space. System-level metrics remain robust, but individual optimization suffers.

4. **Domain scope restriction**: Evaluated only on code generation (LiveCodeBench v6) and MATH. Not tested on general reasoning, multi-hop QA, tool use, or agentic tasks. Reward shaping assumes answer-matching or execution-based binary rewards.

5. **Scale ceiling**: Only tested at 8B and 14B parameter scales. Scaling behavior (beyond 14B, more than 2 agents, larger node budgets) is unknown. Cluster configuration uses 8 GPUs per model — substantial infrastructure requirement.

6. **λ sensitivity**: Reward shaping coefficient λ = 0.4 is optimal for code generation. At λ = 0.8 performance drops sharply (0.4571 → 0.4000 Pass@1), indicating the mechanism is structurally important but brittle to hyperparameter choice.

7. **Inference cost**: 60-node MCTS budget means 60x inference cost compared to single-pass. The "latest-wins" selection rule (Table 5) provides only marginal improvement over random selection (0.4224 vs 0.4171), suggesting node depth is a weak quality signal.

## 6. Transfer to Lyra

### The One Idea

**Multi-agent collaborative tree search with tree-consistent credit assignment.** Lyra should structure its multi-model agent orchestration as a shared search tree where heterogeneous policies (different LLM providers, temperature settings, system prompts, or tool configurations) collaboratively expand candidate solutions. Each agent contributes generation and refinement nodes, with a tree-level advantage function that credits agents based on: (a) improvement over the parent node (vertical refinement quality), and (b) outperformance of sibling candidates (horizontal diversity). Thompson sampling over Beta priors selects which agent expands which node, dynamically balancing exploration vs. exploitation across the agent pool.

### Lyra Architecture Mapping

- **§4.2 Search & Planning**: The MCTS tree topology and two-level bandit agent-node selection directly inform Lyra's search strategy
- **§4.3 Multi-Agent Architecture** (PRIMARY): MARS² is the first framework to embed multi-agent collaboration directly into structured search — directly applicable to Lyra's multi-model orchestration patterns
- **§4.6 Training & Optimization**: GRPO-style tree-level optimization with reward shaping can inform Lyra's policy improvement loop
