# BOOK AGENT: Orchestrating Safety-Aware Visual Narratives via Multi-Agent Cognitive Calibration

**Authors:** Bo Gao (CMU), Chang Liu (USTC), Yuyang Miao (Imperial College London), Siyuan Ma (NTU), Ser-Nam Lim* (UCF)
**Venue:** arXiv preprint, April 2026 (arXiv:2604.16541v1, cs.CV)
**Code:** https://github.com/bogao-code/BookAgent/tree/main
**Backend:** Google Gemini 3.0 (reasoning), Nano-Banana (image generation)

---

## 1. Mechanism

BOOK AGENT is a multi-agent system that synthesizes end-to-end illustrated storybooks (text + images) from a user-provided draft. It decomposes the problem into three stages operating in a closed loop.

### Stage 1: Value-Aligned Storyboarding (VAS)

**Goal:** Transform a raw user draft into a safety-audited, character-anchored story blueprint.

1. **Reviewer-Refiner (A_ref):** Rewrites draft x to match target page count K with global style s:
   ```
   x̂ = A_ref(x, K, s)
   ```
   Output x̂ is audited by text safety auditor A_Tsafe → {S_T ∈ {0,1}, ρ_T}. If S_T=0, safety critique ρ_T guides constrained rewriting until compliant.

2. **Character Extractor (A_char):** Extracts up to C ≤ 5 recurring characters, each with a stable identifier and concise visual descriptor d_j (species, colors, clothing):
   ```
   C = {c_j}^C_{j=1} = A_char(x̂, s)
   ```

3. **Character Sheet Renderer (G_sheet):** Generates canonical neutral-background reference images for each character:
   ```
   r_j = G_sheet(d_j, s), ∀j ∈ {1, ..., C}
   ```
   These sheets serve as ground truth for identity verification in subsequent stages.

4. **Page Planner (A_plan):** Decomposes the refined story into a page-wise plan:
   ```
   P ≜ {(t_i, p_i^(0))}^K_{i=1} = A_plan(x̂, I_0, K, s)
   ```
   where t_i is the narrative script and p_i^(0) is the initial image prompt for page i.

---

### Stage 2: Iterative Cross-modal Refinement (ICR)

**Goal:** Generate page-level images via a budgeted generate-verify-revise loop.

For each page i (up to R attempts):

1. **Retrieve** relevant character sheets: R_i = {r_j | c_j ∈ Entities(t_i)}

2. **Generate** candidate image using reference-conditioned generator G:
   ```
   y_i^(r) ∼ G(p_i^(r), R_i)
   ```

3. **Dual-branch verification:**
   - **Frame Director (A_frame):** Evaluates text-image faithfulness, outputs score α_i^(r) and semantic issues Δ_i^(r)
   - **Identity Director (A_id):** Checks character consistency against reference sheets R_i, outputs score η_i^(r) and issues Ω_i^(r)

4. **Prompt update** using local memory M_i to prevent regression:
   ```
   p_i^(r+1) = {
     p_i^(r) ⊕ Ψ(ρ_I),                    if S_I(y_i^(r)) = 0  (safety failure)
     p_i^(r) ⊕ Φ(Δ_i^(r), Ω_i^(r), M_i),  otherwise
   }
   ```
   where Ψ converts safety reasoning into negative constraints, Φ aggregates current critiques with historical issues.

5. **Acceptance criterion:** Candidate accepted if safe, faithful (α_i ≥ τ_α), and identity-consistent (η_i ≥ τ_η). If budget exhausted, select best safe candidate:
   ```
   y_i = arg max_{y ∈ {y_i^(r)}} (α(t_i, y) + η(y, R_i))
   s.t. S_I(y) = 1
   ```

---

### Stage 3: Temporal Cognitive Calibration (TCC)

**Goal:** Global verification-and-repair across the entire sequence.

1. **Sequence Director (A_seq):** Performs global audit of the full sequence B^(m):
   ```
   (β^(m), Γ^(m), I^(m)) = A_seq(B^(m), s)
   ```
   where Γ^(m) contains global critiques and I^(m) is the set of indices for inconsistent pages.

2. **Selective Repair:** If consistency score β^(m) < τ_β, for each problem page k ∈ I^(m):
   - Update prompt with global context constraints derived from Γ^(m)
   - Re-enter ICR loop (Stage 2) with stricter reference conditioning
   - Produce refined book B^(m+1)

3. **Termination:** Cycle repeats until convergence or max round limit reached (default: 1 sequence retry).

### Agent I/O Contracts

Each agent has fixed input/output contracts enabling independent verification:

| Agent | Input | Output | Responsibility |
|-------|-------|--------|----------------|
| Reviewer-Refiner | x, K, s | x̂, mode, feedback | Polish/rewrite draft, enforce ≤5 characters |
| Page Planner | x̂, I_0, K, s | P = {(t_i, p_i)} | Decompose story into pages |
| Character Extractor | x̂, s | C = {c_j} | Extract ≤5 chars with descriptors |
| Sheet Renderer | d_j, s | r_j | Neutral-background reference sheets |
| Frame Director | (t_i, y_i^(r)) | α_i, Δ_i | Page-level text-image faithfulness |
| Identity Director | (t_i, y_i, {r_j}, s) | η_i, Ω_i | Character identity verification |
| Sequence Director | B^(m), s | β^(m), Γ^(m), I^(m) | Cross-page continuity audit |
| Safety Auditor (Text) | z ∈ {x, x̂} | S_T(z), ρ_T | Child-safety text audit |
| Safety Auditor (Image) | y_i^(r) | S_I(y), ρ_I | Child-safety image audit |

### Hyperparameters (default)
- Frame-level verification threshold τ_f = 0.75
- Max frame retry attempts: 3
- Sequence-level threshold τ_s = 0.8
- Max sequence retries: 1
- Loose: (0.6, 0.7, 1 retry), Strict: (0.85, 0.9, 5 retries)

## 3. Trade-offs

| Win | Loss/Cost |
|-----|-----------|
| +2.3 cross-frame consistency vs. baseline (2.0 → 4.7) | 3-4x inference cost increase vs. single-pass (default: ~13K tokens for 5 pages vs. ~9K loose) |
| +0.6 safety score (4.2 → 4.8) from VAS pre-audit | Backend-locked: Gemini 3.0 + Nano-Banana (proprietary) |
| Global repair eliminates irreversible appearance drift | 5-char limit restricts complex ensemble casts |
| End-to-end paradigm enables bidirectional text-image refinement | Iterative retries add proportional latency (strict: 5x retries costs 17K vs 13K tokens at 5 pages) |
| No model retraining needed—purely agentic coordination | Quality ceiling bounded by backbone model capabilities |
| Works for offline storybook generation | Not real-time: 20-page story takes 18-21 min default |

## 4. Design Rationale

The authors argue that single-pass or feed-forward generation of illustrated storybooks is structurally insufficient because **(a)** errors in character identity, object binding, and spatial relations often only become visible after multiple pages are produced (non-local detectability), and **(b)** existing safety methods are post-hoc filters that cannot prevent unsafe plot trajectories. Therefore, their approach:

1. **Multi-agent decomposition** with fixed I/O contracts: Enables independent verification at each stage (text, page-level, sequence-level) rather than trusting a monolithic model.
2. **Closed-loop verify-then-rectify:** Transforms generation from "static probabilistic sampling into a dynamic, self-correcting cognitive loop" — the key philosophical shift.
3. **Pre-generation safety audit (VAS):** Elevates safety "from a passive post-hoc filter to an active, structural constraint within the narrative planning process."
4. **Character sheet anchoring:** Canonical reference images serve as immutable ground truth for identity verification, preventing gradual appearance drift across autoregressive steps.
5. **Selective repair (TCC):** Only retouches inconsistent pages rather than regenerating entire sequences, saving compute while maintaining global coherence.

This design is explicitly positioned as a paradigm shift from "linear autoregressive accumulation to holistic temporal reasoning and self-correction."

## 5. Limitations and Failure Modes

1. **Backbone dependency:** Performance bounded by Gemini 3.0 and Nano-Banana capabilities. Low-level visual errors and rare semantic misunderstandings from these models persist regardless of agent coordination.
2. **Limited entity tracking:** Explicit consistency maintained over ≤5 characters and small object sets. Scaling to larger casts introduces memory capacity issues, interference between entity representations, and increased global calibration complexity.
3. **Computational overhead:** Iterative refinement costs 3-4x more tokens than single-pass generation. For a 20-page story: ~52K tokens and ~18-21 min runtime.
4. **Not real-time:** Unsuitable for interactive or low-latency applications.
5. **Single-vision-model evaluators:** All metrics use automated LLM evaluators on 1-5 scale; no human inter-annotator agreement statistics reported. User study is "small-scale" with undisclosed N.
6. **Style rigidity:** All generation shares a single global style descriptor s; no mechanism for style variation across pages within a storybook.
7. **Fixed page count:** K must be specified upfront; no support for dynamic story length adaptation.
8. **Proprietary stack:** Entire system depends on Google's Gemini ecosystem, limiting reproducibility and open-source adoption.

## 6. Transfer to Lyra

**The ONE transferable idea:** Multi-Agent Cognitive Calibration via Fixed-Contract Verify-Then-Rectify Loops.

BOOK AGENT demonstrates that decomposing a complex generative task into agents with immutable I/O contracts — where each agent verifies a specific dimension (safety, faithfulness, identity, sequence) and feeds structured critiques back into refinement — dramatically improves output consistency without retraining any model. The three key patterns are:
- Pre-generation audit (guard before generate)
- Budgeted iterative refinement (generate → verify dual-branch → revise prompt from accumulated memory)
- Global selective repair (audit full sequence → identify problem pages → retarget only those)

**Lyra workstream routing:** §4.1 (Agent Architecture / Multi-Agent Orchestration) — The fixed I/O contract pattern and the three-stage loop architecture (plan→refine→calibrate) directly informs Lyra's multi-agent design for complex reasoning tasks.

**Impact:** 4 (structural improvement, not incremental)

**Effort:** 4 (requires defining agent contracts, verification loops, and memory accumulation patterns — but no model training)

**Tier:** Breakthrough — This is a genuinely novel agent orchestration pattern (verify-then-rectify with fixed contracts) that transcends the visual narrative domain and applies to any multi-step generative agent system. The core insight — that errors in long-horizon generation are non-locally detectable, requiring global retrospective audit — is directly applicable to Lyra's planning and execution loops.
