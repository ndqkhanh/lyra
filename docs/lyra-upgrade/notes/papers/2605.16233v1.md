## 1. Mechanism (step-by-step)

### 1.1 Agent Architecture: Hierarchical ReAct with Dynamic Memory Injection

At each environment step, a top-level **Planner** selects the final defense action while delegating two sub-tasks to on-demand (implemented as tools) ReAct sub-agents:
- **Analyst**: interprets host-level observations
- **ActionChooser**: ranks valid actions with justification

All agents use the **same underlying LLM** — no distillation from a stronger model. They differ only in role-specific system prompts and injected memory.

Each instance i maintains persistent + dynamic memory organized per role:
```
M_i = (M_i^Planner, M_i^Analyst, M_i^ActionChooser)
```

Persistent memory holds user-supplied instructions (only the ActionChooser and learning agents receive the environment action reference table). Dynamic memory is initially empty and accumulates knowledge artifacts.

### 1.2 Inner Loop: Failure-Triggered Reflexion (Algorithm 1)

```
Algorithm 1: Failure-Triggered Reflexion Loop
Require: Agent instance with memory M_i, attempts k_A, failure trigger τ, representation
1: for a = 1 to k_A do
2:     Track per-step reward r_step
3:     Run episode with memory M_i
4:     if ∃ step such that r_step < τ then
5:         Abort; snapshot ← trajectories, M_i, metadata, environment state
6:         Δ ← UpdateMemory(snapshot, representation)  // Reflector/Exemplifier
7:         Apply edits: M_i ← Apply(M_i, Δ)
8:     end if
9: end for
10: return Updated memory M_i
```

**Key design choices:**
- Failure trigger τ = -1.1: derived from environment reward distribution analysis — the smallest threshold that excludes legitimate Restore penalties (exactly -1.0) while capturing real failures with 100% precision and 74% recall
- Upon failure, the episode **aborts immediately** (does not continue to step 30)
- A dedicated learning agent (same LLM) produces artifacts:
  - **Reflector** → conditional heuristics (Rules)
  - **Exemplifier** → structured ReAct demonstrations (Examples)
  - **Both** → Mixed condition
- Artifacts are appended to memory; the episode restarts from step 0

### 1.3 Outer Loop: The FORGE Protocol (Algorithm 2)

```
Algorithm 2: FORGE: Staged Population Memory Training
Require: N instances, S stages, k_A attempts, graduation threshold θ, failure trigger τ, representation
1: Initialize dynamic memory M_i ← ∅ for i ∈ {1, ..., N}
2: Initialize graduated set G ← ∅
3: for s = 1 to S do                         // Outer loop: staged knowledge transfer
4:     Initialize each instance i in uniquely seeded environment with M_i
5:     Initialize attempt graduated set H ← ∅
6:     Initialize checkpoint Return R_i = 0
7:     for instance i ∉ G in parallel do      // Concurrent Independent Instances
8:         M_i ← ReflexionLoop(M_i, k_A, τ, representation)  // Algorithm 1
9:         R_i ← Checkpoint(M_i)              // frozen evaluation, no learning
10:    end for
11:    H ← {i ∉ G | R_i > θ}                  // new graduates
12:    Freeze memories of H; G ← G ∪ H
13:    if condition = FORGE and |{i ∉ G}| > 0 then
14:        i* ← argmax_{i∉G} R_i              // champion selection
15:        for instance i ∉ G do
16:            M_i ← M_i*                     // broadcast: full memory replacement
17:        end for
18:    end if
19: end for
20: return Final evaluation of all N frozen instances.
```

**Three critical mechanisms:**
1. **Staged Training**: S = 6 stages create periodic synchronization points; all instances complete inner-loop attempts before any between-stage mechanism is applied.
2. **Champion Broadcast**: After each stage, the instance with the highest checkpoint return among non-graduated instances has its complete memory state copied to every other active instance. This is a **destructive full replacement** — no merging, because merging NLP rule sets requires unreliable conflict resolution.
3. **Graduation**: Instances whose checkpoint return exceeds θ = -15 (roughly 10× improvement over random) are frozen and excluded from further stages. This prevents regression and conserves compute.

**Adaptation from Population-Based Training (PBT):**
- PBT exploit step → champion broadcast (full replacement, not interpolation)
- PBT explore step → Reflexion inner loop (semantically grounded reflection, not random perturbation)

### 1.4 Memory Representations (Experimental Variable)

| Representation | Format | Injected via | Token Cost Profile |
|---|---|---|---|
| **Rules** | Ordered conditional heuristics per role | `<reflection_knowledge>` section | Most compact (~40% fewer tokens) |
| **Examples** | Structured ReAct demonstrations (Thought-Tool-Observation-Answer) | `<TOOL_USE_EXAMPLES>` section | Most verbose |
| **Mixed** | Both Rules and Examples generated separately | Both sections | Intermediate |

### 1.5 Evaluation Modes

- **Checkpoint**: single-episode frozen probe used during training for champion selection and graduation decisions
- **Post-Session Evaluation**: separate multi-episode frozen evaluation after full FORGE session completion — this is what the paper reports as primary metrics

**Protocol parameters:** N = 10 instances, S = 6 stages, k_A = 3 attempts per stage, τ = -1.1, θ = -15

## 2. Results (real benchmark numbers with units)

### 2.1 CybORG CAGE-2 B_line, 30-step horizon

**Environment reference points:**
- CardiffUni PPO (DRL top score): **-3.47**
- Rule-based heuristic: **-58.83**
- Random action: **-154.06**
- No-action (sleeping): **-218.65**

| Model | Zero-Shot | Reflexion (best) | FORGE (best) | Δ Zero-Shot | Δ Reflexion |
|---|---|---|---|---|---|
| **Gemini-2.5-Flash-Lite** | -189.6 ± 53.9 | -62.7 ± 60.5 (Rules) | **-24.5 ± 21.1** (Examples) | **7.7×** | +69% |

**Best single checkpoint return: -3.60** (Gemini Rules) — approaching the DRL top score of -3.47.

### 2.3 FORGE vs. Reflexion Improvement (ΔRefl, all 12 conditions)

FORGE outperforms Reflexion in **all 12 model-representation conditions** by **29-72%** (Table 3, ΔRefl column).

| Representation | Total Tokens | Per-Instance Adaptation Tokens |

### 2.5 Variance Compression

- Zero-shot heavy tail: ~90% of episodes below -100 (catastrophic failure)
- FORGE: **~1% catastrophic failure rate** under strongest configurations
- FORGE steadily compresses score variance across stages (Figure 5B), while Reflexion remains near zero-shot volatility levels

### 2.6 Graduation Dynamics (Gemini Rules, τ = -1.1)

- Graduation rate: 83% (mean across 7 sessions)
- Active instances decline from 10 to ~2-3 by S6 (Figure 6A)

### 2.7 Failure Trigger Sensitivity Sweep (Gemini Rules)

| τ | Mean Return | SD | Graduation Rate | Episodes |
|---|---|---|---|---|
| -1.1 (default) | -30.6 | 37.0 | 83% | 140 |
| -2.0 | -52.0 | 59.6 | 65% | 40 |
| -3.0 | -46.0 | 52.9 | 75% | 40 |
| **-11.0** | **-24.6** | 28.2 | **93%** | 60 |

τ = -11.0 (severe failures only) unexpectedly outperforms the default τ = -1.1 — results are **non-monotone**.

### 2.8 No-Graduation Ablation

- No-graduation variant also outperforms Reflexion in all 12 conditions → **broadcast is the essential mechanism**
- Graduation primarily contributes **compute savings** (~2× fewer adaptation tokens per instance by S6)
- Model-dependent effect on final performance: removing graduation helps Grok (+67%) and Qwen (+39%), hurts Gemini (-8%) and Llama (-7%) in some representations

### 2.9 Cross-Model Pattern

Improvement magnitude inversely correlates with baseline strength:
- Gemini (worst baseline -189.6): **7.7× gain**
- Grok (best baseline -58.4): **1.7× gain**

FORGE appears to **mitigate capability gaps** rather than amplify strong models.

**Scale:** 116 experiments, 2,640 evaluated episodes, 12,364.0M total tokens.

## 3. Trade-offs

| Dimension | Win | Loss / Cost |
|---|---|---|
| **Performance vs. Zero-Shot** | 1.7–7.7× improvement across all 4 model families | Requires 10 parallel instances × 6 stages (significant compute) |
| **Broadcast vs. Isolated Reflexion** | 29–72% improvement in all 12 conditions; variance compression | Destructive full replacement — loses population diversity; single-best selection can amplify a lucky-but-fragile strategy |
| **Examples vs. Rules** | Examples: best mean return for 3/4 models (Gemini -24.5, Llama -28.3, Qwen -24.3) | Examples: ~40% more tokens; longer prompts; lower graduation rates |
| **Rules vs. Examples** | Rules: best cost-reliability profile; higher graduation rates; ~40% fewer tokens | Rules: higher variance (SD 37.0 vs 21.1 for Gemini); worse mean for 3/4 models |
| **Graduation** | Saves ~2× compute per instance by S6; prevents regression; locks strong artifacts | Can terminate learning prematurely (removing graduation improves Grok +67%, Qwen +39% in some representations) |
| **Weak vs. Strong Baselines** | Disproportionately helps weak models (mitigation, not amplification) | Strong models (Grok at -58.4 zero-shot) gain least (1.7×) — diminishing returns for already-competent agents |
| **Failure Trigger τ = -1.1** | Simple, data-derived; 100% precision on legitimate vs. failure penalties | Suboptimal: τ = -11.0 outperforms it (-24.6 vs -30.6 mean), suggesting cleaner signal from severe-only triggering |
| **Prompt-only vs. Fine-tuning** | No gradient updates needed; interpretable artifacts; model-agnostic | Limited by context window; artifacts can grow unbounded; no theoretical convergence guarantees |
| **Single-best Champion** | Simple, effective selection pressure | Brittle: a single lucky checkpoint can propagate suboptimal memory to entire population |

## 4. Design Rationale

**Why prompt-only self-improvement?** Fine-tuning is expensive and often infeasible (API-only models, infrastructure constraints). Prompt-injected memory is model-agnostic, interpretable, and requires no weight access.

**Why population-based?** Isolated single-stream Reflexion lacks selection pressure to distinguish genuine policy improvement from noise. In stochastic POMDPs, individual instances accumulate counterproductive artifacts that degrade performance below zero-shot. A population introduces competition: only the best-discovered memory survives and propagates.

**Why failure-triggered (not success-triggered)?** In CAGE-2, zero-shot performance is near-catastrophic (Gemini -189.6), so successes are extremely scarce. Failure-triggered reflection converts the abundant failure signal into learning opportunities.

**Why full memory replacement (not merge)?** Merging two natural-language rule sets requires conflict resolution (contradictory heuristics, ordering conflicts) that is itself unreliable when performed by an LLM. Full replacement is simpler and avoids introducing merge errors.

**Why hierarchical ReAct?** The Planner-Analyst-ActionChooser decomposition mirrors the POMDP structure: observation interpretation, strategic reasoning, and action selection are separated, allowing memory to target specific failure modes per role.

**Why same-LLM for reflection?** No external oracle or stronger teacher model — this tests whether an agent can bootstrap its own improvement from failure alone, which is the hardest and most general setting.

## 5. Limitations & Failure Modes

1. **Single attacker type (B_line only):** All evidence is confined to CAGE-2 B_line at 30-step horizon. Generalization to other CAGE-2 attacker types (e.g., B_line at 50/100 steps, other red agents) and other POMDP environments is untested.

2. **Brittle single-best broadcast:** Champion selection based on a single checkpoint episode can propagate a lucky-but-fragile strategy. No diversity preservation mechanism exists (e.g., tournament selection, ensemble broadcast).

3. **Checkpoint-evaluation misalignment:** Champion selection uses a single frozen episode per stage; post-session evaluations use multiple episodes. A champion may look good on one seed but perform poorly on others.

4. **Directional cross-family evidence only:** Non-Gemini models receive only 3–4 FORGE sessions per representation. The paper explicitly states these are "directional" findings, not statistically robust.

5. **Suboptimal failure trigger:** τ = -1.1 was chosen from reward distribution analysis, but the sensitivity sweep reveals τ = -11.0 yields better performance. The optimal threshold and multi-threshold strategies remain unexplored.

6. **Graduation can terminate learning prematurely:** In some model-representation pairs (notably Grok and Qwen), graduation freezes artifacts too early, and the no-graduation variant achieves 27–67% better final performance.

7. **No comparison to parameter-efficient fine-tuning (PEFT):** The paper argues for prompt-only learning but does not empirically compare FORGE against LoRA/QLoRA or other PEFT methods that might achieve similar or better results at comparable or lower cost.

8. **Single domain:** Cyber defense only. Whether the population-broadcast mechanism transfers to other stochastic POMDP domains (e.g., robotics, game-playing, dialogue) is unknown.

9. **No cross-model artifact transfer:** Artifacts generated by one LLM are not tested on another LLM. Rules from Gemini might not help Qwen, or might even harm performance.

10. **Cost scaling:** FORGE requires N=10 parallel instances × S=6 stages = significant API costs (e.g., ~106M tokens for Gemini Rules). Cost scales linearly with population size and stages.

11. **Potential for degenerate strategies:** The system could learn to exploit environment quirks rather than develop generalizable defensive competence. No out-of-distribution evaluation is performed.

## 6. Transfer to Lyra

### The One Transferable Idea

**Population-based broadcast of failure-triggered, prompt-injected memory artifacts across parallel agent instances as a gradient-free self-improvement mechanism for Lyra agents operating in stochastic, partially observable environments.**

Lyra could implement a FORGE-like outer loop where N parallel Lyra agent instances independently explore a task, accumulate failure-triggered memory artifacts (rules/heuristics or few-shot examples), and periodically synchronize by broadcasting the best-performing instance's memory to the population. This would:
- Enable Lyra agents to bootstrap competence in domains where zero-shot performance is poor
- Provide a selection mechanism that distinguishes genuine improvement from noise
- Work without weight updates — compatible with API-only model access
- Scale with population size and stages (configurable cost-quality trade-off)

### Workstream Route: **§4.2 — Learning & Agency** or **§4.1 — Memory Systems**

This feeds both workstreams:
- **§4.1 (Memory Systems):** The artifact representation question (Rules vs. Examples vs. Mixed) directly informs how Lyra should structure its persistent memory. The finding that Rules offer the best cost-reliability profile (~40% fewer tokens) while Examples achieve the strongest returns for 3/4 models gives Lyra a concrete trade-off to parameterize.
- **§4.2 (Learning & Agency):** The population-broadcast outer loop is fundamentally a learning mechanism. FORGE demonstrates that prompt-only learning can achieve 1.7–7.7× improvements without gradient updates — directly relevant to Lyra's self-improvement capabilities.

### Impact: **4** (significant — directly applicable architecture for gradient-free agent self-improvement)
### Effort: **4** (requires implementing population orchestration, failure-trigger detection, champion broadcast, and artifact management — but all in prompt space, no model training)
### Tier: **investigate** (high potential but domain-specific evidence; needs validation in Lyra's target environments before full adoption)

### Concrete Lyra Implementation Sketch
1. Wrap Lyra agents in a FORGE outer loop with configurable N (population size) and S (stages)
2. Implement failure-trigger detection (per-step quality threshold) using Lyra's existing evaluation infrastructure
3. Build Reflector/Exemplifier agents that analyze failed Lyra trajectories and produce Rules/Examples
4. Store artifacts in Lyra's context/memory system, tagged per role
5. Champion broadcast via context replacement between stages
6. Evaluate in a Lyra-relevant POMDP or multi-step task environment
