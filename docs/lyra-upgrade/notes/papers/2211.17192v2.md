# Fast Inference from Transformers via Speculative Decoding (Leviathan, Kalman, Matias — ICML 2023 Oral)

> arXiv: 2211.17192v2 | Submitted Nov 2022, revised May 2023 | Google Research

## 1. Mechanism (Step-by-Step)

Speculative decoding accelerates autoregressive generation by exploiting the observation that hard language tasks "often include easier subtasks that can be approximated well by more efficient models." Instead of generating tokens one-by-one with the large target model M_p, a small cheap draft model M_q proposes multiple candidate tokens, then M_p verifies them in a single parallel forward pass.

**Algorithm 1 — SpeculativeDecodingStep(M_p, M_q, prefix, γ):**

1. **Draft γ tokens autoregressively from M_q:**
   ```
   for i = 1 to γ:
       q_i(x) ← M_q(prefix + [x_1, ..., x_{i-1}])
       x_i ~ q_i(x)   // sample one token
   ```
   Produces a candidate sequence of length γ.

2. **Run M_p in parallel on all γ+1 prefixes:**
   ```
   p_1(x), ..., p_{γ+1}(x) ← M_p(prefix), M_p(prefix + [x_1]), ..., M_p(prefix + [x_1,...,x_γ])
   ```
   All forward passes execute in one batch, exploiting idle compute during memory-bound inference.

3. **Determine accepted count n via rejection sampling:**
   ```
   r_1 ~ U(0,1), ..., r_γ ~ U(0,1)   // sample random thresholds
   n ← min({i-1 | 1 ≤ i ≤ γ, r_i > p_i(x_i) / q_i(x_i)} ∪ {γ})
   ```
   A drafted token x_i is accepted if r_i ≤ p_i(x_i) / q_i(x_i). The first rejection terminates the acceptance run. This is a sequential rejection criterion — accept while each token passes the test.

4. **Adjust final distribution from M_p if any rejection occurred:**
   ```
   p'(x) ← p_{n+1}(x)
   if n < γ:
       p'(x) ← norm(max(0, p_{n+1}(x) - q_{n+1}(x)))
   ```
   The adjustment p'(x) = norm(max(0, p(x) - q(x))) subtracts the draft model's overconfident mass from the target's distribution, then renormalizes. This is the key mathematical innovation that preserves exact distribution matching.

5. **Sample final token and return:**
   ```
   t ~ p'(x)
   return prefix + [x_1, ..., x_n, t]
   ```
   The step produces between 1 (all rejected) and γ+1 (all accepted) tokens.

**Core Theoretical Results:**

- **Acceptance rate (Theorem 3.5):** β = 1 - D_LK(p,q), where D_LK(p,q) = 1 - Σ_x min(p(x), q(x)). The per-token acceptance probability equals one minus the L1-like divergence between p and q.

- **Expected α (Corollary 3.6):** α = E[Σ_x min(p(x), q(x))]. This is the expected per-step acceptance fraction. α → 1 when the draft is very close to the target; α → 0 when distributions are disjoint.

- **Expected tokens per step (i.i.d. assumption):** E[#generated] = (1 - α^{γ+1}) / (1 - α).

- **Walltime improvement factor (Theorem 3.8):** (1 - α^{γ+1}) / ((1 - α)(γc + 1)), where c = cost ratio of M_q single-run time to M_p single-run time.

- **Existence condition (Corollary 3.9):** If α > c, there exists some γ that yields walltime improvement. Minimum guaranteed factor: (1 + α) / (1 + c).

- **Total arithmetic operations factor (Theorem 3.11):** (1 - α)(γĉ + γ + 1) / (1 - α^{γ+1}), where ĉ = ops-per-token ratio M_q:M_p. Arithmetic ops always increase, but walltime decreases because ops are parallelized.

**Distribution Preservation Guarantee (Appendix A.1):** For any distributions p(x) and q(x), tokens sampled via speculative sampling are distributed identically to those sampled from p(x) alone. The output distribution is mathematically identical — not approximate.

**Lenience Extension (Appendix A.5):** When strict distribution matching is relaxed with a lenience parameter l ∈ [0,1], the draft distribution q(x) is effectively multiplied by l before comparison. This trades exact distribution matching for higher acceptance. With T5-XXL and T5-small (temp=1, EnDe): l=1 → α=0.62 (~2.5X); l=0.5 → α=0.71 (~3.1X); l=0.1 → α=0.84 (~5X).

## 3. Trade-offs (Wins vs Loses)

| Wins | Loses |
|------|-------|
| **2-3.4X walltime reduction** without architectural changes | **Increased total arithmetic operations** — rejected tokens waste compute (Theorem 3.11: up to 1.63X more FLOPS) |
| **Identical output distribution** guaranteed mathematically — no quality degradation | **Compute resource requirement** — needs spare parallel compute; useless if all units are already saturated |
| **No retraining, no architecture changes** — works with off-the-shelf models | **Draft must share vocabulary/tokenization** with target — same-family models implicitly, cross-family untested |
| **Works at any temperature** (0 and 1 tested, supports stochastic sampling unlike Blockwise Parallel Decoding) | **Diminishing returns from larger drafts** — T5-large (800M) gives only 1.4-1.7X vs T5-small (77M) giving 2.6-3.4X |
| **Negligible-cost drafts viable** — bigram model gives α=0.20, enabling ~1.25X improvement with near-zero overhead | **γ selection is non-trivial** — depends on α and c; suboptimal γ can reduce or eliminate gains |
| **Lenience trades strict fidelity for more speed** — up to 5X with l=0.1, still bounded quality | **Lenience hurts output diversity** — "could hurt the diversity of the samples" with no minimum probability guarantee |
| **KV cache and weight memory reads decrease** per-step (weights read once per parallel batch) | **I.i.d. assumption in theory** — theoretical walltime predictions differ from empirical (Table 4) due to non-i.i.d. acceptance rates |

## 4. Design Rationale (Why This Approach)

The authors argue that large-model inference is typically bottlenecked by **memory bandwidth** (reading model weights and KV cache), not arithmetic throughput. This creates idle arithmetic units during autoregressive generation — each step does a small amount of compute before waiting for the next memory read. The key insight: **increase concurrency to exploit idle compute** rather than reduce per-step operations.

Compared to alternatives:
- **Knowledge distillation:** Requires retraining, changes output distribution, lowers model quality
- **Quantization/pruning:** Changes model behavior, may degrade quality, requires hardware-specific optimization
- **Early exits / adaptive computation:** Requires architectural changes, custom training procedures
- **Blockwise Parallel Decoding (Stern et al. 2018):** Only supports greedy decoding (temp=0), requires custom training with auxiliary prediction heads, has no distribution guarantee
- **Shallow Aggressive Decoding (Sun et al. 2021):** Limited to input-copying tasks, no stochastic sampling support

Speculative decoding's killer feature is that it **guarantees identical outputs** with no retraining — you drop it in and get 2-3X faster inference immediately. The rejection sampling derivation p'(x) = norm(max(0, p(x) - q(x))) is the mathematical innovation that makes this possible: it corrects the distribution after any rejection so the overall sampling process remains exact.

## 5. Limitations & Failure Modes

1. **Requires spare parallel compute:** The method exploits idle arithmetic units during memory-bound inference. On already-saturated hardware, it provides no benefit and may degrade throughput. Single-batch, single-TPU experiments only.

2. **Increased total arithmetic operations:** Rejected speculative tokens mean wasted computation. Theorem 3.11 shows operations can increase by 1.53-1.63X even at optimal γ. This matters for energy-constrained or cost-per-FLOP scenarios.

3. **α ≤ c is a hard failure condition:** If the draft model's acceptance rate α is not strictly greater than the cost coefficient c (ratio of draft inference time to target inference time), **no γ provides walltime improvement** (Corollary 3.9). A draft that is too slow relative to its quality improvement is worse than no draft.

4. **Same-family draft assumption:** All tested drafts shared architecture and tokenization with the target (T5 family, LaMDA family, same-vocab GPT). Cross-architecture drafting (e.g., Gemma drafting for Claude) received no evaluation. Tokenizer mismatch would break the probability comparison step.

5. **Fixed γ throughout inference:** The algorithm uses a static γ across all decoding steps. The authors acknowledge that dynamically varying γ (by predicting β per-step) could yield "up to ~60% higher" improvement but leave this unexplored.

6. **I.i.d. acceptance rate assumption:** Theoretical formulas assume token acceptances are i.i.d., which they are not — early tokens are often easier to predict. Table 4 shows discrepancies between theory and empirics partially attributable to this.

7. **Single batch-size evaluation:** All walltime measurements used "batch size of 1 on a single TPU-v4." Behavior at larger batch sizes, where memory bandwidth becomes even more critical, was not explored.

8. **Walltime measured only for T5:** While α was measured for GPT-like and LaMDA models, actual speedup measurements were T5-exclusive. Other architectures may show different walltime characteristics.

9. **Beam search complexity:** Adaptation to beam search is noted as "more involved" with "some performance penalty" — left as future work.

10. **Lenience safety concern:** With lenience l < 1, token selection is bounded only by p(x)/l rather than p(x), meaning low-probability tokens can be sampled with effectively higher frequency, potentially producing less coherent or more diverse-but-worse outputs.

## 6. Transfer to Lyra

**The One Idea:** Use speculative decoding within Lyra's multi-model routing layer — a cheap draft model (Haiku) proposes responses speculatively, then the expensive target model (Sonnet/Opus) verifies in a single parallel API call. The rejection sampling mechanism guarantees the exact output distribution of the expensive model while cutting latency 2-3× and reducing cost by avoiding redundant expensive serial decoding. This integrates directly with Lyra's existing plan for speculative decoding in §4.21 Economics ("Haiku drafts tokens → Sonnet/Opus verifies in parallel. 2-3× latency reduction").

**Workstream Route:** §4.21 (Performance & Cost Economics) — primary; §4.5 (Intelligent Model Router) — secondary (the draft→target pairing is a routing decision).

**Implementation note for Lyra:** Unlike the paper's token-level speculative decoding (which requires same-tokenizer models), Lyra would implement this at the **response-chunk level** via the Anthropic API. Haiku drafts N candidate responses or completions, Sonnet/Opus scores and selects/refines. The lenience parameter maps to Lyra's quality-cost slider.

**Impact:** 4 | **Effort:** 3 | **Tier:** (A) Parity — already in §4.21 plan as "Speculative Decoding (Anthropic-only)."

**Provider Limitations:** Speculative decoding at the token level requires both draft and target to share vocabulary and be served by the same inference system. Anthropic does not currently expose token-level speculative decoding as a public API feature. Lyra's chunk-level approximation sacrifices the exact distribution guarantee but is API-implementable today.
