## 1. Mechanism (step-by-step)

ERROR PROBE is a three-stage pipeline for semantic failure attribution in LLM-based Multi-Agent Systems (MAS). Given a failed interaction trace `x` (sequence of inter-agent messages and tool outputs) and a failure symptom (e.g., exception, wrong final answer), the system predicts the responsible agent `a*`, the decisive error step `t*`, and failure mode `f*` (from the 14-mode MAST taxonomy).

### Stage 1 — MAST-Guided Structural Decomposition
- Parse the raw trace into a structured representation `Sx = {(agent_t, role_t, action_t)}^L_{t=1}`, where `role_t` is the assigned persona (Architect, Engineer, Tester), `action_t` is the semantic type (NL Instruction, Tool Call, Execution Output).
- Apply a taxonomy-conditioned prompt to tag **local anomalies** (e.g., "Tool output ignored at Step 5").
- These weak signals serve as **heuristic priors** to narrow the search space from L steps to a smaller candidate set, rather than asking the model to diagnose the full trace directly.

### Stage 2 — Symptom-Driven Backward Tracing
- **Dependency Parsing:** Build a dependency graph `G = (V, E)` where nodes are messages and edges represent information flow (e.g., Agent B cites Agent A's output).
- **Recursive Pruning:** From the symptom node `v_L`, breadth-first search on incoming edges identifies the Effective Receptive Field of the error.
- **Context Compression:** Mask unconnected branches (e.g., parallel subtasks that succeeded), retaining only the causal lineage `x' ⊂ x`.
- This solves the "lost-in-the-middle" problem where root cause at `t=5` is 45 steps away from symptom at `t=50`.

### Stage 3 — Multi-Agent Diagnosis Team
Three specialized LLM agents mimic human debugging workflow:

1. **Strategist (Evaluation Lead):** Receives condensed trace `x'` and MAST tags. Queries long-term memory `M` for `k` similar failure patterns. Generates hypotheses `H = {(s_j, suspected_mode)}`. In cold-start (empty memory), degrades gracefully to first-principles reasoning using only MAST tags.

2. **Investigator (Bug Checker):** Strictly tool-grounded — cannot merely claim "code is wrong." Must produce evidence `E_h` via:
   - **CodeExec:** Re-runs code snippets in sandbox to confirm runtime errors.
   - **LogicProbe:** Verifies pre-/post-conditions (e.g., "Check if variable X at step t matches constraints at step t-5").
   - Must generate a diff or execution log proving discrepancy.

3. **Arbiter (Verifier):** Aggregates `{(h, E_h)}`, filters hypotheses with empty/inconclusive evidence, outputs final prediction `ŷ = (a, t, f)` with confidence `c ∈ [0,1]`. Decides whether the diagnosed pattern is novel/robust enough for memory commitment.

### Self-Evolving Sequential Diagnosis Loop (Algorithm 1)
```
Require: Failed trace x_t, Memory M_{t-1}
Ensure: Diagnosis ŷ, Updated Memory M_t
 1: Compression: x'_t ← BackwardTrace(x_t, MastPriors)
 2: Retrieval: P ← Retrieve(M_{t-1}, x'_t, k)
 3: Plan: H ← Strategist(x'_t, P)
 4: for hypothesis h in H do
 5:     E_h ← Investigator(h, Tools)
 6: end for
 7: Verdict: (ŷ, c, E) ← Arbiter(H, {E_h})
 8: if c ≥ τ and Verify(E) then
 9:     M_t ← Update(M_{t-1}, ŷ, E)
10: else
11:     M_t ← M_{t-1}
12: end if
13: return ŷ
```

### Verified Episodic Memory (Novel component)

Each memory entry: `⟨s_e, v_e, σ_e⟩` where:
- `s_e`: structured signature (MAST anomaly tag, tool/API involved, argument types, agent role, task domain)
- `v_e`: diagnosis recipe (canonical error pattern + verification guard)
- `σ_e`: meta-statistics (recency, frequency, impact, performance delta)

**Strict Verification Gate:** A new diagnosis `ŷ_t` with evidence `E_t` is committed to memory only if `Verify(E_t) ∧ c_t > τ` (τ=0.7). This prevents hallucinated error patterns from polluting memory.

**Relevance Scoring (Eq. 3):** `S(x, e) = Sim(s_x, s_e) × S_RFI(e)` — combines structural similarity (requiring exact match on MAST tag) with quality-weighted RFI score (recency, frequency, impact). Cold-start threshold `τ_ret = 0.75`; if no match exceeds threshold, retrieval returns empty set and system defaults to first-principles reasoning.

**Key hyperparameters:** k=5 (retrieved memory entries), τ=0.7 (confidence threshold), α=0.6 (semantic similarity weight), d=1536 (embedding dimension), T=0.7 (decoding temperature). All tuned on 10% held-out TracerTraj subset and fixed across all evaluations.

## 3. Trade-offs (wins vs loses)

| Win | Lose |
|---|---|
| Step localization +20-31pp over LLM-as-a-Judge across benchmarks | 45s inference latency per diagnosis (impractical for real-time production) |
| Verified memory enables OOD cross-domain transfer without retraining (KodCode→AgenTracer) | Requires detectable anomaly signals; silent/semantically-correct-but-wrong failures slip through |
| Tool-grounded verification (CodeExec + LogicProbe) reduces hallucinated diagnoses | Three-agent team multiplies API calls and compute cost vs. single-pass judging |
| Cold-start graceful degradation: works without memory, improves as memory populates | Only tested with 3 backbone models (Claude 3.7, GPT-OSS-120B, Qwen3 32B); unknown with other architectures |
| Structured MAST tags provide interpretable failure-mode signals | Strict verification gate (τ=0.7) may reject valid but low-confidence diagnoses |
| Memory avoids corruption via verified-before-write gate | Memory retrieval requires exact match on MAST tag; may miss semantically similar but differently-tagged failures |
| Works across 3 distinct MAS frameworks (MetaGPT, CaptainAgent, MagenticOne) | Does not handle stealthy malicious agent behaviors (explicitly scoped to benign debugging) |

## 4. Design Rationale

The authors argue that existing approaches are insufficient: (1) LLM-as-a-Judge fails at step localization because single-pass over long traces overweight late-stage symptoms (TracerTraj Step < 10% for Claude/GPT); (2) Agent-as-a-Judge from Zhuge et al. (2025) improves step attribution but is protocol-sensitive and can hurt agent-level accuracy; (3) Specialized tracers (Zhang et al., 2026) require costly data generation and retraining under distribution shift. The three-stage pipeline mirrors human expert debugging workflow: narrow the search space (MAST tags), prune irrelevant context (backward tracing), then verify hypotheses with tools (Strategist-Investigator-Arbiter). The verified-before-write memory design is motivated by observing that naive caching mechanisms suffer from drift under distribution shift (Yu et al., 2026) — the explicit verification gate ensures only reproducible, tool-grounded error patterns enter long-term memory, balancing self-improvement with robustness.

## 5. Limitations & Failure Modes

1. **Silent failures:** The backward tracing mechanism depends on detectable anomalies (exceptions, logic inconsistencies, verifiable constraints). "Silent failures" where agents produce technically valid but semantically incorrect outputs without triggering MAST detectors remain unhandled. Future work could integrate test-time oracle feedback.

2. **Inference latency:** The multi-agent diagnosis team (Strategist, Investigator, Arbiter) incurs ~45s per diagnosis via API calls. The iterative tool-assisted verification constrains applicability in ultra-low-latency production environments. Authors frame this as acceptable for offline/asynchronous debugging workflows.

3. **Backbone model diversity:** Only tested on 3 model families (Claude 3.7 Sonnet, GPT-OSS-120B, Qwen3 32B). Due to computational cost, unable to exhaustively validate against other proprietary models. Architecture-agnostic generalizability not fully confirmed.

4. **Cold-start dependency on MAST tags:** When memory is empty, the system relies entirely on MAST structural decomposition. If the MAST detector misses relevant anomalies, the Strategist operates with degraded signal quality.

5. **Ethical scope:** Framework is designed for benign debugging only; explicitly does not handle stealthy malicious agent deviations.

## 6. Transfer to Lyra

**The ONE transferable idea:** A **verified-before-write episodic memory** for multi-agent diagnosis, where error patterns are committed to long-term memory only after passing a strict tool-grounded verification gate (reproducible evidence + Arbiter confidence > τ). This prevents memory corruption from hallucinated diagnoses while enabling cross-domain transfer of reusable diagnostic patterns — directly applicable to Lyra's self-diagnosis and failure recovery subsystems.

**Workstream route:** §4.4 — Reliability & Self-Healing (plans/16-reliability.md). The verified episodic memory architecture and Strategist-Investigator-Arbiter diagnosis team provide a concrete blueprint for Lyra's error attribution and automated root-cause analysis capabilities.

**Impact:** 4 — Lyra's multi-agent pipelines already produce long traces where delayed failure manifestation is a known issue. Verified episodic memory for diagnosis would directly improve operator debuggability and enable automated self-correction.

**Effort:** 4 — Requires implementing: (a) MAST-like taxonomy operationalization for Lyra's specific agent roles, (b) backward tracing via dependency graph construction, (c) the three-agent diagnosis team with tool grounding (sandbox + logic probes), (d) the verified-before-write memory gate with signature embedding and retrieval. Substantial plumbing but no new model training needed.

**Tier:** **investigate** — High potential value but needs feasibility study on whether Lyra's trace structure and failure modes justify the ~45s latency overhead. Worth prototyping on Lyra's most common failure patterns first.
