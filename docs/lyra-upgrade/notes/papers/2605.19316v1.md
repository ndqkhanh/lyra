# MAFIG: A Multi-Agent Framework for Feature-Constrained Difficulty Control in Reading Comprehension Item Generation

**Authors:** Seonjeong Hwang, Jun Seo, Hyounghun Kim, Gary Geunbae Lee (POSTECH, Graduate School of AI / Dept. of CSE, Republic of Korea)
**Venue:** arXiv preprint (arXiv:2605.19316v1), May 19, 2026 — [cs.CL]
**Code:** https://github.com/SeonjeongHwang/mafig

## 1. Mechanism (Step-by-Step)

MAFIG generates multiple-choice reading comprehension (RC) items that strictly satisfy multi-dimensional feature constraints through a closed-loop multi-agent revision system. The key insight is that single-pass LLM prompting systematically fails to satisfy multiple simultaneous constraints, and iterative multi-agent refinement with role specialization and external knowledge retrieval is necessary.

### Task Formulation
An item is a triplet: (reading passage, question stem, option set). Six feature variables govern cognitive demand or validity:
- **Vocabulary level** (CEFR A1-A2, B1-B2, C1-C2)
- **Passage length** (short: 5-10 sentences, medium: 11-20, long: 21-30)
- **Average sentence length** (short: <10 words, medium: 10-15, long: 15-20)
- **Reasoning complexity** (5 levels: word matching, paraphrasing, single-sentence inference, multi-sentence inference, not enough information)
- **Factuality** (true/false/not given per option)
- **Neutrality** (options must be logically independent — no entailment/contradiction relationships)

### Two-Stage Pipeline with Closed-Loop Revision

**Stage 1: Passage Generation** — generates a passage from a source document conditioned on passage-level constraints (vocabulary, length, sentence length).

**Stage 2: Option Generation** — given the generated passage, produces 4 options (A-D) satisfying option-level constraints (factuality, reasoning complexity, vocabulary, neutrality). One option must be factually true; three must be false.

Each stage runs an iterative generation-and-revision loop:

### Agent Architecture

```
Source Document → [Drafter] → state_0 → [Evaluator] → error_report_0
                                                         ↓
                                              [Planner] ← revision_memory
                                                  ↓
                                    Action 1: Call_Editor OR Action 2: Call_Reworder
                                                  ↓
                                            state_{i+1} → [Evaluator] → error_report_{i+1}
                                                  ↓ (repeat until all constraints satisfied or max iterations)
                                            [Refiner] → final_item
```

**Drafter:** Generates initial item state_0 from source document + constraints. Samples n=5 parallel candidates to enable diverse revision paths and early termination.

**Evaluator:** Suite of specialized modules measuring each feature variable:
- Rule-based: NLTK for passage/sentence length; CEFR word-list lookup for vocabulary level
- LLM-based (CoT + self-consistency, Qwen3-32B): reasoning complexity (two sub-dimensions: Evidence Scope and Transformation Level, Macro F1 69.0/70.8), factuality, neutrality
- Produces comprehensive error report identifying each violation

**Planner:** Central coordination agent with *revision memory* — stores all past modification plans to avoid redundant edits. Decision logic:
1. Analyzes current state_i, error_report_i, and revision memory
2. Routes to either **Editor** (holistic revision of non-vocabulary constraints) or **Reworder** (vocabulary-level adjustments via RAG)
3. Generates granular instruction specifying exactly what to modify
4. In option generation, designates which specific option needs intervention
5. **Creativity Enhancement Prompting:** If any constraint remains unsatisfied for t consecutive iterations, Planner shifts from incremental adjustments to radical strategies (e.g., excising and regenerating problematic segments from scratch)

**Reworder:** Vocabulary-specific agent using Retrieval-Augmented Generation (RAG) with an external CEFR-graded vocabulary database. Three-step pipeline:
1. Suggests contextually appropriate alternatives for level-violating words
2. Rule-based retriever assigns CEFR level to each candidate from external DB
3. Replaces problematic terms with level-aligned alternatives
If no valid replacement exists, notifies Planner of infeasibility.

**Editor:** Revises item to satisfy all non-vocabulary constraints (passage length, sentence length, reasoning complexity, factuality, neutrality). Deliberately restricted from self-evaluating (preliminary experiments showed inaccurate self-evaluations confuse the Planner).

**Refiner:** Final-pass minimal revision for readability and inter-sentence coherence. Prohibited from adding/removing/replacing words.

### Difficulty-Calibrated Constraint Sequence Construction

To map feature constraints to monotonic difficulty progression:

1. Define 16 candidate constraint sets by incrementally adjusting individual features toward higher cognitive demand
2. Generate items for each candidate set using MAFIG on 15 source documents (disjoint from test)
3. Compute **Difficulty Alignment Score (DAS)** for constraint pairs using LLM judge (GPT-5-mini) with pairwise comparison and stochastic sampling (N=4):
   ```
   DAS(Q_i, Q_j) = (Σ x_f^(n) + Σ (-x_r^(n))) / (2N)
   where x_f^(n) = D^(n)(Q_i, Q_j), x_r^(n) = D^(n)(Q_j, Q_i)
   D(Q_i, Q_j) = +1 if Q_i ≻ Q_j, -1 if Q_j ≻ Q_i (via CoT prompting)
   ```
4. Filter constraint pairs with DAS < ρ (threshold ρ=0.4)
5. From remaining candidates, identify 8-level sequence with strictly monotonic difficulty increase

### Key Algorithmic Details
- Maximum iterations: 20 for passage, 100 for option generation
- Parallel drafts: n=5 (default); if none achieves full satisfaction, random candidate returned
- Decoding: top-p=0.8, top-k=20, temperature=0.7
- Revision memory: Planner retains all past instructions to sub-agents, enabling avoidance of redundant edits
- Option generation processes multiple options concurrently; Planner designates specific option requiring intervention

## 2. Results (Real Benchmark Numbers)

All experiments on 320 generated items (40 source documents × 8 difficulty levels from Brown Corpus via NLTK, spanning 10 genres). Backbone LLM: Qwen3-32B (non-reasoning mode) for MAFIG; compared against Direct Prompting with Qwen3-32B and GPT-5 (reasoning effort: medium).

### Constraint Satisfaction

| Method | Success Ratio (SR) | Achievement Ratio (AR) |
|--------|-------------------|------------------------|
| Direct (Qwen3-32B) | 0.00% | 59.10% |
| Direct (GPT-5) | 2.50% | 77.81% |
| **MAFIG (Qwen3-32B)** | **92.29%** | **99.32%** |

SR = proportion of items satisfying ALL constraints simultaneously. AR = average fraction of individual constraints satisfied. Even GPT-5, a frontier reasoning model, achieves only 2.50% SR via direct prompting — demonstrating that single-pass generation fundamentally cannot satisfy multi-dimensional constraints.

### Difficulty Calibration (Automatic — LLM Judge)

| Method | DAS (mean ± std) |
|--------|-------------------|
| Level-based Direct (Qwen3-32B) | 0.1037 ± 0.5434 |
| Level-based Direct (GPT-5) | 0.2949 ± 0.6309 |
| Level-based Incremental (Qwen3-32B) | 0.1804 ± 0.4430 |
| Level-based Incremental (GPT-5) | 0.2750 ± 0.5706 |
| Feature-based Direct (Qwen3-32B) | 0.2759 ± 0.4941 |
| Feature-based Direct (GPT-5) | 0.4952 ± 0.4502 |
| **MAFIG (Qwen3-32B)** | **0.5229 ± 0.4495** |

DAS range: [-1, +1]. +1 = perfect monotonic alignment, 0 = inconsistent, -1 = complete reversal.

### Difficulty Calibration (Human Evaluation — 3 domain experts)

| Method | DAS | CAR |
|--------|-----|-----|
| Direct (Qwen3-32B) | 0.2817 | 42.86% |
| Direct (GPT-5) | 0.4722 | 57.14% |
| **MAFIG (Qwen3-32B)** | **0.6190** | **76.19%** |

CAR = Complete Alignment Ratio (proportion of pairs where all 3 experts unanimously confirm intended difficulty ordering). Human-LLM judge correlation: Spearman's ρ=0.34 (p<0.001). 65.9% of evaluated pairs received consistent ratings from all three annotators.

### Item Quality

| Method | Validity [1-3] | Coherence [0-1] | Fluency [0-1] |
|--------|---------------|-----------------|---------------|
| Direct (GPT-5) | 2.9105 | 0.9094 | 0.9241 |
| **MAFIG (Qwen3-32B)** | **2.9242** | **0.9518** | **0.9429** |

### Ablation — Convergence Speed Impact

Removing Planner's instruction mechanism → substantially slower convergence in option generation. Removing Reworder's feedback message → slower convergence. Removing Creativity Enhancement → slower convergence. All three auxiliary mechanisms were critical for option generation (complex semantic/reasoning revisions) but had minimal impact on passage generation (surface-level revisions).

### Computational Cost

- Passage generation: 90% SR within ~10 rounds, ~20K cumulative output tokens
- Option generation: ~90% SR requires up to 100 rounds, ~130K cumulative tokens
- Baseline single-pass prompting: negligible token cost but 0-2.5% SR

### Model Generalization (MAFIG with different backbones)

With parallel drafting (n=5), all tested models (Qwen3-32B, Mistral-Small-24B, Phi-4-14B) achieved 100% SR — notably, lighter models with parallel revision (Phi-4-14B/n=5, Mistral-24B/n=5) outperformed the larger Qwen3-32B with single-draft revision (n=1), demonstrating that diversity in revision paths is more important than model size.

### Qualitative: Expert-Perceived Difficulty Factors

Answer verification difficulty cluster dominated expert citations at 57.85%, followed by passage vocabulary difficulty (50.52%), syntactic/structural complexity (45.81%), and passage length/word count (45.29%). Figurative language/tone/metaphors and option vocabulary contributed only ~6% combined.

## 3. Trade-offs

| Win | Lose |
|-----|------|
| 92.29% constraint satisfaction vs. 0-2.5% for single-pass baselines | ~130K output tokens for option generation vs. negligible for single-pass (6.5x-100x more tokens) |
| Human DAS 0.6190 (MAFIG) vs. 0.4722 (best baseline) — 31% better calibration | Up to 100 revision rounds; not suitable for real-time or large-scale deployment |
| 76.19% complete alignment ratio vs. 57.14% (GPT-5 Direct) | Requires external knowledge bases (CEFR vocabulary DB) for Reworder agent; not purely LLM-driven |
| Coherence (0.9518) and Fluency (0.9429) both exceed baselines | Maximum 100-round cap means some items may be returned partially non-compliant |
| Parallel drafting with lighter models (Phi-4-14B/n=5) beats single-draft with larger models | Framework assumes availability of feature-specific evaluators; creating new evaluators for new features requires engineering effort |
| Model-agnostic: works with Qwen3-32B, Mistral-24B, Phi-4-14B | Creativity Enhancement only triggers after t consecutive failures; t is a hyperparameter needing tuning |
| Provides interpretable difficulty control (explicit feature manipulation) vs. black-box level-based control | No psychometric validation against actual student performance data |

## 4. Design Rationale

The authors' central argument: **single-pass LLM prompting cannot simultaneously satisfy multiple fine-grained constraints**, regardless of model capability. Even GPT-5 with reasoning mode achieves only 2.5% SR. This is not a model-capability problem but a **task-decomposition problem** — LLMs lack the internal verification mechanisms to check their own outputs against multi-dimensional specifications during generation.

The multi-agent architecture is therefore not optional but necessary: role-specialized agents (Drafter, Editor, Reworder) handle distinct constraint types, while the Planner with revision memory coordinates across them. The key design choices:
- **Planner routes to specialized agents** rather than having a single agent handle all revisions, because vocabulary-level control requires external knowledge (CEFR DB via RAG) that LLM heuristics alone cannot provide
- **Revision memory** prevents cyclical failures where the Planner repeats ineffective strategies
- **Creativity Enhancement** addresses stagnation plateaus where incremental adjustments are insufficient
- **Parallel drafting** exploits diversity: different initial drafts require different revision paths, increasing the probability that at least one path converges
- **Editor restricted from self-evaluation** because preliminary experiments showed inaccurate self-assessments introduce noise that confuses the Planner

The difficulty-calibrated sequence construction is a practical workaround for the absence of large-scale psychometric data — using LLM-judge pairwise comparisons to empirically validate theoretical difficulty ordering.

## 5. Limitations & Failure Modes

1. **Single item format (MCFI):** Experiments limited to "Which statement is true?" format. Extension to other formats (summary, main idea, inference questions) requires new evaluators and possibly different pipeline structure. Topic-question type mismatch (e.g., highly coherent logical passages unsuited to factual information format) causes persistent neutrality violations.

2. **No psychometric validation:** Difficulty calibration is validated only via expert judgment (prior difficulty perspective), not against actual student error rates or IRT parameters. Items are not psychometrically calibrated in any absolute sense.

3. **Evaluator dependency:** Framework quality depends on accuracy of feature-specific evaluators. LLM-based evaluators for reasoning complexity (Macro F1 ~69-71) and factuality introduce noise. Erroneous evaluations misdirect the Planner.

4. **Computational cost:** ~130K output tokens for a single option set at n=1; latency unsuitable for real-time applications. Not viable for large-scale item bank generation without cost optimization.

5. **Feature independence assumption:** Framework treats features as independently controllable, but expert analysis reveals inherent correlations (e.g., longer sentences introduce more complex syntax and vocabulary). Unmodeled interdependencies can introduce unintended difficulty variation.

6. **CEFR database dependency:** Vocabulary control requires an external, level-specific word database. Applicability to non-English languages or testing frameworks with different vocabulary standards requires equivalent databases.

7. **Maximum iteration cap:** 100 rounds for option generation is a hard cutoff. Items failing to converge are returned partially non-compliant (random selection from final pool). The paper does not report exact non-convergence rate at n=1.

8. **Brown Corpus source documents:** Limited to first 50 sentences of English-language texts from a specific corpus; generalization to other languages, domains, or document lengths untested.

## 6. Transfer to Lyra

### The One Transferable Idea

**Closed-loop multi-agent refinement with constraint-specific evaluators and revision memory.** MAFIG demonstrates that decomposing a multi-constraint generation task into specialized sub-agents (each responsible for a constraint domain) coordinated by a Planner with revision memory dramatically outperforms single-pass approaches — even when the single-pass model is substantially more capable (GPT-5 vs. Qwen3-32B). The core pattern is: (1) generate multiple parallel drafts, (2) evaluate each draft against domain-specific evaluators, (3) route revision to a specialized agent based on violation type, (4) maintain revision memory to avoid repeating failed strategies, and (5) employ creativity escalation when incremental fixes stall.

### Lyra Application

Lyra's autonomous agent loop can adopt this pattern to replace single-pass LLM calls for complex multi-constraint tasks (code generation, plan generation, verification report writing). Instead of requesting "generate a plan" and accepting the output, Lyra would: draft multiple candidate plans, evaluate each against constraint-specific checks (safety, completeness, cost, feasibility), route failed plans to specialized reviser agents, and escalate to radical restructuring when incremental fixes plateau. The Creativity Enhancement Prompting mechanism directly addresses the stagnation problem identified in autonomous agent loops.

### Workstream Route

**Planning (reactive trigger + revision loop)** — §4.7 in the Lyra MASTER-PLAN. The Planner agent with revision memory and creativity enhancement feeds directly into Lyra's planning architecture, which currently gates MCTS/AFlow behind workflow complexity thresholds. MAFIG provides a lighter-weight alternative: the Planner-Evaluator loop with revision memory can serve as the default planning mechanism, with MCTS gated only when complexity exceeds a threshold AND the revision loop has stalled.

### Impact / Effort / Tier

- **Impact:** 4 — Directly addresses a known Lyra weakness (LLM single-pass unreliability on complex multi-constraint tasks). The pattern is proven with 92% vs. 2.5% SR improvement.
- **Effort:** 4 — Requires building evaluator infrastructure (constraint-specific checks), Planner agent with revision memory, parallel draft management, and creativity escalation logic. Moderate but non-trivial engineering.
- **Tier:** Breakthrough — The multi-agent revision loop architecture represents a novel capability for Lyra that existing harnesses (Claude Code, Aider, Cline) do not employ. Combined with Lyra's planned worktree isolation, this enables "draft in parallel worktrees, evaluate, revise, merge best" — a pattern no current harness supports.
