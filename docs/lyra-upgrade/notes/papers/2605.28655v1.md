## 1. Mechanism (Step-by-Step)

AUTOSCIENTISTS is a decentralized multi-agent system for long-horizon computational scientific experimentation. It replaces a central orchestrator with a **shared state S** that agents read and write to self-organize into teams. The system deploys `n` agents (default: 6 experiment agents + 3 analyst agents), all using the same LLM backend (Claude Sonnet 4.6 via Claude Code).

### Core Loop: Heartbeat Dispatch (Algorithm 1)

Each agent is invoked in a heartbeat loop via a deterministic monitor process. On each invocation, the agent reads the shared roster `R` and forum `F` from state `S`, then enters one of four branches:

1. **Discussion branch** — triggered when an unresolved `[DISCUSSION-TRIGGER]` exists or roster `R` is empty (cold start or stagnation). Agents run Algorithm 2 (team formation).
2. **No-team exit** — agent is not assigned to any team; returns immediately.
3. **Resume branch** — experiment agent has an unposted result from a prior session; posts `[RESULT]` and exits.
4. **Normal cycle** — agent runs role-specific logic (Algorithm 4 for analysts, Algorithm 3 for experiment agents).

### Shared State S (Four Layers)

1. **Champion p\*** — current best model with full hyperparameters and reproduction instructions.
2. **Experiment Log L** — every completed experiment with outcome, metric delta, and training diagnostics.
3. **Shared Forum F** — structured posts for proposals, critiques, result announcements, mechanistic analyses.
4. **Team-local state** — per-team experiment queues `Q_k`, dead-end registries `D_k`, and hypothesis documents (readable cross-team).

### Self-Organized Team Formation (Algorithm 2)

Agents write the roster `R = {(T_k, axis_k, members_k)}^K_{k=1}` themselves through structured discussion:

1. Each agent reads task specification, current champion `p*`, and the active `[DISCUSSION-TRIGGER]` thread.
2. Agents post: (i) candidate research directions, (ii) ranked hypotheses with reasoning, (iii) critiques of earlier posts identifying gaps.
3. Agents cast a self-termination vote: `[DISCUSS-MORE]` or `[DISCUSS-DONE]`.
4. When a majority votes `[DISCUSS-DONE]`, the **alphabetically-last analyst** consolidates proposals into roster `R` and writes it to `S`. This is purely a tie-breaker — there is no privileged consolidator agent.
5. Teams can be created, merged, split, retired, or rebalanced during reformation, with changes requiring endorsement from affected teams.

### Experiment-Agent Cycle (Algorithm 3)

1. Claim a queued experiment `q` from team queue `Q_k`.
2. Apply diff to champion `p*`, train candidate `p'`, compute improvement `Δ = ℓ(p') - ℓ(p*)`.
3. **Noise-aware champion gate** (Equation 1): Let `σ` = per-run standard deviation (noise floor calibrated via Equation 2), `M = 2`:
   - If `Δ > Mσ`: promote directly.
   - If `0 < Δ ≤ Mσ`: re-run on a second seed; promote iff both runs strictly improve.
   - If `Δ ≤ 0`: discard.
4. Record outcome to log `L`, release claim, post `[RESULT]` to forum `F`.

**Noise floor calibration (Equation 2):** After ≥3 duplicate-seed pairs accumulate, `σ` is set to the within-pair pooled standard deviation: `σ = sqrt( (1/(2n)) Σ_{i=1}^n (ℓ_{1,i} - ℓ_{2,i})^2 )`. Locked after 5 pairs to prevent retroactive reclassification of prior decisions. This prevents **champion pollution** — an erroneous promotion that corrupts all downstream comparisons.

### Analyst Cycle (Algorithm 4)

1. **Stagnation detection**: If recent experiments produced no improvement, or proposals concentrate on a narrow class of changes, post `[DISCUSSION-TRIGGER]` to `F` to trigger reformation.
2. **Coverage audit**: Audit untested parameters of `p*`.
3. **Empirical priors**: Compute axis priors `μ_{a,d}` from experiment log `L`.
4. **Proposal generation**: Draft 2 new experiments subject to:
   - **Ambition quota**: ≥1 proposal must satisfy a bold-move criterion (≥10% parameter-count change, confirmed bug fix, axis flagged as untested in ≥2 discussion threads, or hypothesis-tension probe). If neither qualifies, post a public `[EXEMPT]` justification.
   - **Diversity rules**: (i) Two proposals target different research directions, (ii) no run of ≥3 recent same-axis proposals all push the same direction, (iii) no proposal falls inside a previously rejected range in `D_k` unless the proposer explicitly states what differs.
5. **Post-KEEP step**: If champion was updated since last cycle, ≥1 proposal must follow up on the property responsible for the recent improvement via a different mechanism.

### Queue Protocol (Appendix A.5)

The team queue `Q_k` uses **optimistic locking** with a version token. A write arriving stale is rejected and the agent retries against the latest version. Each experiment agent releases its own claim immediately after recording the outcome — no experiment is claimed twice.

## 3. Trade-Offs

| Win | Lose |
|-----|------|
| +8.33 leaderboard percentile on BioML-Bench over strongest prior agent | ~4.4x higher LLM API cost than single-agent Autoresearch |
| 1.9x fewer GPU experiments to reach target val_bpb on GPT optimization | Higher token consumption from multi-agent reasoning/discussion overhead |
| Continues discovering improvements after single-agent saturates (7 vs 0) | Optimal team size is task-dependent; n=14 degrades every task |
| No central coordinator = resilient to planner failure | Naive promotion gate without noise floor would cause champion pollution (compounding errors) |
| Self-organization adapts to shifting search landscape mid-run | Adding more agents beyond optimum causes oversubscription (coordination overhead dominates) |
| Dead-end registry + cross-team sharing reduces duplicate work | Requires careful lock-step serialization via optimistic locking on shared state |
| Multi-seed noise gate (Eq. 2) prevents champion pollution with zero calibration budget | Second-seed re-runs consume experimental budget in noisy regimes |

## 4. Design Rationale

1. **Decentralized over centralized planning**: Prior multi-agent systems (STELLA, Virtual Lab, Coral) use central planners or fixed decompositions. AUTOSCIENTISTS argues that research directions cannot be partitioned stably at the start — productive directions shift as evidence accumulates. Self-organization through shared state allows the system to adapt without a bottleneck coordinator.

2. **Discussion for filtering, not consensus**: Unlike debate frameworks (Du et al., Chan et al.) that use discussion to converge on a single hypothesis, AUTOSCIENTISTS uses discussion to filter weak proposals before compute is spent, while agents continue pursuing different directions in parallel. This preserves parallel exploration.

3. **Noise-aware gate**: The stochastic nature of ML metrics means naive promotion would accept noise as improvement, corrupting the shared baseline. The empirically calibrated noise floor with second-seed confirmation prevents compounding errors (champion pollution) without spending experiments specifically on calibration.

4. **Ambition quota + diversity rules**: Analyst proposals enforce bold exploration and prevent local-optimum trapping via explicit criteria (≥10% change, untested axes, hypothesis-tension probes) and anti-convergence rules (direction diversity, dead-end avoidance).

---

## 5. Limitations and Failure Modes

1. **Higher LLM token cost**: AUTOSCIENTISTS uses ~4.4x more LLM tokens than single-agent Autoresearch (Table S8). The system optimizes for experimental compute efficiency, not LLM-call efficiency.

2. **Oversubscription at large team sizes**: n=14 degrades every task. Task-dependent optimal crew size is not auto-selected; dynamic scaling remains future work.

3. **Sequential GPU constraint on BioML-Bench**: Under the matched 1-H100-per-task budget, GPU-bound experiments run sequentially, not exploiting AUTOSCIENTISTS's parallel experimentation capacity. Scaling with larger GPU budgets is untested.

4. **Single-run ablation evidence**: Most ablation comparisons use n=1 runs per condition; multi-replicate studies (n≥3) would be needed for statistical confidence on ablation gaps.

5. **Single-task transfer claim**: ProteinGym findings are from optimizing on the ACE2-Spike development assay; whether other seed assays yield similarly transferable methods is not explored.

6. **No multi-objective optimization**: The noise gate optimizes a scalar metric; ProteinGym results show Spearman ρ improvement but slight MSE regression (+0.006), indicating single-objective optimization.

7. **Stagnation detection heuristics**: The "no improvement in last 10 experiments" trigger is a fixed threshold. More nuanced stagnation detection (learning curves, effect-size trends) could improve sensitivity.

## 6. Transfer to Lyra

**The one transferable idea:** The **shared-state decentralized multi-agent coordination pattern** with self-organized team formation, noise-aware champion gating, and dead-end registries. This directly maps to Lyra's multi-agent orchestration needs: instead of a central Router deciding all agent assignments, Lyra agents could read a shared context/state (the current champion solution, experiment log, dead-end registry), self-organize into teams around competing hypotheses, and use a noise-aware gate to prevent polluted state propagation — reducing single-point-of-failure risk in long-running autonomous coding sessions.

**Workstream route:** §4.2 (Agent Orchestration & Multi-Agent Coordination) — specifically the Router/Orchestrator subsystem. The pattern of replacing a central planner with a shared-state forum where agents self-organize into teams aligns with Lyra's need for resilient, decentralized task decomposition. The noise-aware gate is additionally relevant to §4.3 (Safety & Guardrails) as a mechanism to prevent cascading errors.

**Impact:** 4 | **Effort:** 4 | **Tier:** breakthrough

**Rationale for tier:** This is a novel coordination paradigm (decentralized agent teams with self-organization) backed by strong empirical evidence across 3 domains. It challenges the dominant assumption that multi-agent systems need central planners. Integrating it into Lyra would require substantial architectural changes to the orchestration layer but could unlock Lyra's ability to sustain long-running autonomous development sessions without human intervention — a core Lyra goal.
