## 1. Mechanism (step-by-step)

SIA is a **two-lever self-improvement loop** driven by three LLM components. The core insight is that harness/scaffold updates and model-weight updates are **complementary change spaces** — harness edits produce external infrastructure improvements (tools, parsers, retry logic), while weight updates (via LoRA RL) internalise domain-specific knowledge that no prompt or scaffold can encode.

### Architecture (3 components)

1. **Meta-Agent (M)** — Claude Sonnet 4.6. Reads the task specification `U` and reference implementations `R`. Generates the initial scaffold `A₁ = M(U, R)`: a system prompt, tool-dispatch loop, answer extractor, and (optionally) utility code.

2. **Task-Specific Agent (A_g)** — gpt-oss-120b with optional LoRA adapter `θ_k`. Executes against the evaluation dataset `D` inside a sandbox (read-only dataset dir, read-write working dir). Produces the full execution trajectory `τ_g`.

3. **Feedback-Agent (F)** — Claude Sonnet 4.6. The decision-maker. After each generation, F reads the scaffold `A_g`, the full trajectory `τ_g` (every prompt, model response, tool call, tool result, extracted answer for every instance), the performance metrics `E_g`, and the task spec `U`. F then **dynamically selects** between two actions:

   - **Harness Update (H):** F synthesises an improved scaffold `A_{g+1} = F(A_g, τ_g(π_θ), E_g, U)` holding weights `θ` fixed.
   - **Weight Update (W):** F triggers RL training on LoRA weights using one of five algorithms, holding scaffold `A_g` fixed. The model is gpt-oss-120b with LoRA rank r=32, learning rate 4×10⁻⁵, trained on H100 GPUs via Modal.

### Per-generation protocol (3 phases)

1. **Execution** — `A_g` runs on `D` in sandbox; trajectory `τ_g` captured.
2. **Analysis** — F reads source code, `τ_g`, metrics `E_g`, sample task descriptions (to discourage overfitting).
3. **Improvement** — F emits an improvement report (prose analysis + proposed changes) and the next artifact (either `A_{g+1}` or `θ_{k+1}`).

### Weight-update algorithm zoo (5 RL algorithms, selected by F)

F conditions its choice of training algorithm on the observed reward structure:

| Algorithm | When observed | Mechanism |
|-----------|--------------|-----------|
| **PPO w/ GAE** | Dense step-level rewards, stability critical | Learned value head `V_φ`; per-token advantage `Â_t = Σ_l (γλ)^l δ_{t+l}`; clipped surrogate `min(r_t Â_t, clip(r_t, 1±ε) Â_t)` |

### Key design property: interleaving, not sequencing

The Feedback-Agent is NOT forced into a fixed phase order (e.g., "harness first, then weights"). It interleaves freely — the typical observed pattern is: harness iteration until reward stalls → switch to weight updates → possibly resume harness — creating a **co-evolutionary dynamic** where each lever shapes the distribution the other sees.

### Sample-task regularisation

During scaffold generation, the Meta-Agent sees diverse task specifications to prevent overfitting the initial scaffold to a single benchmark instance.

## 2. Results (real benchmark numbers)

Evaluated across three contrasting domains: law, systems, biology. All comparisons include: Baseline (gpt-oss-120b through Meta-Agent’s initial scaffold A₁), Prior SOTA, SIA-H (harness only, best generation), and SIA-W+H (harness + weight updates, best).

### LawBench (191-class Chinese criminal charge classification)

| Operating Point | Top-1 Accuracy |
|----------------|---------------|
| Baseline (initial A₁) | 13.5% |
| Prior SOTA | 45.0% |
| SIA-H (harness only) | 50.0% |
| **SIA-W+H** | **70.1%** |

- **Gain:** +25.1 pp over prior SOTA (70.1% vs 45.0%); +20.1 pp over harness-only
- Harness edits built: TF-IDF + LinearSVC pipeline with tuned character n-gram range and regulariser C; structured answer-extraction layer; SVC re-ranker over top candidates
- Weight edits applied: PPO with GAE — sharpened disambiguation of 191 adjacent legal charge categories

### AlphaEvolve TriMul (CUDA kernel optimisation on H100)

| Operating Point | Reward Score (=1500/runtime) | Runtime (µs) |
|----------------|------------------------------|--------------|
| Baseline (initial A₁) | 0.105 | ~14,286 |
| Prior SOTA | 1.292 | 1,161 |
| SIA-H (harness only) | 0.120 | 12,483 |
| **SIA-W+H** | **1.475** | **1,017** |

- **Gain:** 12.4% faster than prior SOTA (1,017 vs 1,161 µs); 14.02× speedup over Baseline; 91.9% runtime reduction from SIA-H to SIA-W+H
- Harness edits built: compilation-error parser feeding CUDA diagnostics as structured context; timing harness returning median runtime; memory layout hints; compilation flags; retry logic
- Weight edits applied: Entropic advantage weighting — internalised H100-specific patterns (shared-memory tiling, fp32 register accumulation, block-size selection)

### MAGIC scRNA-seq Denoising (single-cell RNA imputation on pancreas data)

| Operating Point | MSEnorm (higher = better, 1.0 = perfect) |
|----------------|------------------------------------------|
| Baseline (initial A₁) | 0.048 |
| Prior SOTA | 0.240 |
| SIA-H (harness only) | 0.241 |
| **SIA-W+H** | **0.289** |

- **Gain:** 20.4% over prior SOTA (0.289 vs 0.240); 20% over harness-only
- Harness edits built: batched configuration driver sweeping k, t, α; result-parsing tool organising (param-set, score) pairs
- Weight edits applied: GRPO — crucially, the first weight-update checkpoint introduced a `np.clip + np.rint` post-processing invariant (rounding imputed counts to non-negative integers) that **zero harness iterations had ever proposed**

## 3. Trade-offs (wins vs loses)

| Win | Loss/Cost |
|-----|-----------|
| 25.1 pp over prior SOTA on LawBench; 12.4% faster GPU kernels; 20.4% denoising gain | Requires H100 GPUs for weight updates (Modal platform); not runnable on consumer hardware |
| Harness updates produce *externalised* improvements (tools, parsers, retry logic) — composable, debuggable, inspectable | Weight updates produce *internalised* knowledge — opaque, non-transferable to other tasks |
| Weight updates discover solutions (np.clip+np.rint invariant, H100 tiling patterns) that harness search alone never finds | Coupled co-evolutionary Goodhart risk: both levers optimise against the same fixed verifier V, shaping distributions the other sees |
| Algorithm selection is adaptive (PPO/GRPO/entropic/reinforce/cold-start), not fixed | Dual actor-critic (PPO w/ GAE) is computationally expensive; algorithmic zoo complexity adds engineering burden |
| Single gpt-oss-120b base model across all tasks; no per-task base model tuning needed | LoRA rank 32 is a fixed hyperparameter; no evidence that this is optimal across all task types |
| Trajectory-conditioned decisions (not summary-statistic-conditioned) enable diagnosis of specific failure modes | Full-trajectory analysis by Feedback-Agent requires long-context LLM calls (Claude Sonnet 4.6) — adds per-step latency and API cost |
| Sample-task regularisation mitigates single-instance overfitting during scaffold generation | The 3-task evaluation (law, systems, biology) while diverse is limited in breadth; no evidence on open-ended or multi-turn interactive tasks |

## 4. Design Rationale (why this approach)

1. **Two levers > one lever, because harness and weights occupy orthogonal change spaces.** Harness edits govern *how the agent searches* (external infrastructure: prompts, tools, retry logic, output parsing). Weight edits govern *what the model knows* (internalised domain intuition: H100 tiling patterns, legal charge disambiguation, biological invariants). Neither saturates the gain available from the other — the observed plateau behaviour confirms this empirically.

2. **Adaptive algorithm selection beats fixed pipelines.** The Feedback-Agent conditions its choice of RL algorithm on observed reward dynamics (dense vs. sparse, right-skewed vs. uniform, ordinal vs. cardinal). This is more principled than prior work that ran a single training recipe regardless of task structure.

3. **Full-trajectory feedback beats aggregate metrics.** Giving F the complete execution log (every prompt, response, tool call, result) enables diagnosis of *specific failure modes* rather than reaction to summary statistics — the difference between "accuracy is 50%" and "the answer extractor truncates multi-line responses."

4. **Interleaving beats sequencing.** The Feedback-Agent can freely interleave harness and weight updates rather than running them in rigid phases. This allows the system to exploit synergies (e.g., a weight update improving the model's CUDA knowledge → a subsequent harness edit restructuring the kernel search strategy around that improved capability).

## 5. Limitations & Failure Modes

1. **Coupled co-evolutionary Goodhart (major).** Both harness search and RL weight updates optimise against the same fixed verifier V. Each pass shapes the distribution the other sees — the harness finds scaffolds exploitable by the current policy; the weights train on data collected through a scaffold that will subsequently change. The joint fixed point is a Nash equilibrium between two optimisers blind to each other's update history, not a point that maximises V under distributional shift. These fixed points can appear strong on the training verifier while being fragile under any perturbation to either component.

2. **No out-of-distribution evaluation.** All three benchmarks evaluate on the same distribution used for training; generalisation to novel inputs or tasks is untested.

3. **Action-selection policy is heuristic, not learned.** F uses a frozen LLM prior (Claude Sonnet 4.6) to decide when to switch levers. The authors explicitly flag this as future work (Meta-RL over the selection policy). The current heuristics may be poorly calibrated for tasks with different reward dynamics.

4. **Limited task breadth.** Only 3 tasks evaluated (classification, code optimisation, hyperparameter tuning). No multi-turn interactive tasks, no open-ended generation, no embodied or tool-use-intensive benchmarks.

5. **Computational cost.** Weight updates require H100 GPU clusters (Modal). The dual actor-critic PPO variant is particularly expensive. Cost analysis is absent from the paper.

6. **LoRA rank fixed.** No evidence that r=32 is optimal across task types; lower-rank adapters may underfit complex reward landscapes while higher ranks inflate cost.

7. **Base model lock-in.** All experiments use gpt-oss-120b; no evidence that gains transfer to other base models or architectures.

8. **v2 artefacts deferred.** Algorithm-selection analysis across broader tasks deferred to v2; the paper reports only three tasks with algorithm descriptions based on "broader experimentation not included."

## 6. Transfer to Lyra

### The ONE transferable idea

**The Feedback-Agent as an interleaving selector between harness-mutation and model-adaptation levers in a single self-improvement loop.**

Lyra should implement a meta-agent that reads full execution trajectories (not summary statistics), detects whether the bottleneck is in the *harness* (tools, prompt structure, retry logic, output parsing) or in the *model's domain knowledge*, and dynamically selects between scaffold-editing and weight-adapting actions. This is directly mappable to Lyra's existing agentic architecture: the "harness engineer" role already exists in the upgrade plans; SIA adds the weight-update counterpart and — critically — the adaptive switching logic between them.
