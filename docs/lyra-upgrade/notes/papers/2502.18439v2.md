## 1. Mechanism (step-by-step)

MAPoRL is a post-training paradigm that co-trains multiple LLMs simultaneously using multi-agent reinforcement learning (MARL) to elicit genuine collaborative behaviors. The key insight is that single-agent training with a fixed opponent fails to produce cooperative agents — joint optimization is required.

### Step 1: Collaborative Debate Framework
- A agents engage in T-turn multi-agent debate (Du et al. 2024 framework)
- Each agent i at turn t generates solution s^t_i conditioned on all prior responses from all agents:
  - s^1_i = LLM_i(q)
  - s^(t+1)_i = LLM_i(q ⊕ all prior_solutions)
- Final answer determined by majority voting across agents (ties broken by expectation-weighted scoring)

### Step 2: Verifier Training (Outcome Reward Model)
- Verifier built on quantized LLM backbone (Phi-3-mini-128k-instruct) + linear head + softmax
- Trained with binary cross-entropy at token level on (question, solution_partial, correct/incorrect) tuples
- GSM8K: 7,463 questions × 100 reasoning paths each, balanced to 20 correct + 20 incorrect per question
- ANLI: 10,000 questions × 50 reasoning paths, balanced to 10 correct + 10 incorrect
- Optimized on latter half of solution tokens
- Verifier accuracy: GSM8K 0.91, ANLI 0.92

### Step 3: Influence-Aware Verification Reward (Definition 1)
```
R_θ(q, s^t_a) = E[ 1/Σγ^(t'-t) × (
    Verifier(q, s^t_a) +                               # current answer quality
    Σ_{t'>t} Σ_{j∈[A]} (1/A)γ^(t'-t)Verifier(q, s^(t')_j)  # downstream influence
)]
```
This reward captures both immediate correctness AND how the agent's response influences all other agents' future answers. γ ∈ [0,1] is the discount factor.

### Step 4: Multi-Agent PPO (Section 3.2, adapted from Yu et al. 2022)
- **State:** concatenation of multi-agent interaction history (question + all prior responses)
- **Value Function** V^ta_θ(i^x_ta) estimates expected cumulative reward from the current partial generation
- **Token-level reward:** r_θ(q, s^{1:x}_ta) = 1(x = len) × R_θ(q, s^t_a) - λ_KL × KL(LLM_ref,ta || LLM_θ,ta)
  - KL penalty against reference LLM prevents policy collapse
- **Advantage:** Generalized Advantage Estimation (GAE) leveraging the learned value function
- **PPO Loss:** L_PPO = L_Surrogate + L_Value
  - L_Surrogate: clipped objective with importance sampling ratio R^x_ta = LLM_θ / LLM_θold
  - L_Value: MSE between value network and target value (V + A)

### Step 5: Reward Shaping Incentives (Section 3.3, Tables 1-2)
Four parameters shape collaborative behavior based on answer correctness transitions:

| Parameter | Meaning | Transition Pattern |
|-----------|---------|-------------------|
| α₀ | Critical reasoning: extract useful info from incorrect answers | Own answer: Wrong→Right when majority is Wrong |
| α₁ | Persuasibility: accept correct information | Own answer: Wrong→Right when majority is Right |
| β₀ | Constructive influence: provide useful incorrect answers | Majority: Right→Wrong when own answer is Wrong |
| β₁ | Persuasive influence: sway others when correct | Majority: Wrong→Right when own answer is Right |

- α₀, α₁: applied to agent's answer at turn t+1 (encourage revision)
- β₀, β₁: applied to agent's answer at turn t (encourage influence)
- Each is a scalar multiplier added to the verifier score

### Step 6: Efficient Multi-Agent Architecture (Figure 6)
- Single shared base LLM with multiple QLoRA adapters — each agent and value function = <0.2% of base parameters
- Value model: shared backbone + additional linear value head
- Training: 8× NVIDIA A100-80GB GPUs, 12 simultaneous episodes, batch_size=1, gradient_accumulation=4, 4 PPO epochs per rollout
- QLoRA: r=8, α=16, dropout=0.05, AdamW lr=1e-5, λ_KL=2e-4, λ_value=0.1

### Anti-Reward-Hacking Measures (Appendix G.3.1)
- Non-EOS penalty: -10 for responses without proper EOS token
- Non-boxed penalty: -10 for answers missing \\boxed{} format
- Minimum length: penalize responses <50 tokens
- Repetition penalty: -10 for >3 consecutive repeated tokens (excluding numbers)
- Post-boxed penalty: penalize any token generation after \\boxed{}
- ANLI-specific: reasoning-quality verification prompt to catch meaningless text

## 2. Results (real benchmark numbers)

### Experiment 1: Vanilla vs MAPoRL (3 agents, 3 turns, Phi-3-mini-128k-instruct 3.4B)

**GSM8K (mathematical reasoning):**
| Condition | Turn 1 | Turn 2 | Turn 3 |
|-----------|--------|--------|--------|
| Off-the-shelf Phi-3 | 0.609 | 0.689 | 0.639 |
| MAPoRL (α=0,β=0) | 0.609 | ~0.73 | ~0.74 |
| MAPoRL (α=1,β=1) | 0.609 | ~0.75 | ~0.77 |
| MAPoRL (α=2,β=2) | 0.609 | ~0.76 | ~0.80 |

**ANLI (natural language inference):**
| Condition | Turn 1 | Turn 2 | Turn 3 |
|-----------|--------|--------|--------|
| Off-the-shelf Phi-3 | 0.451 | ~0.50 | ~0.47 |
| MAPoRL (α=2,β=2) | ~0.48 | ~0.52 | ~0.54 |

**Correctness Transition Analysis (GSM8K):**
- Off-the-shelf Turn 2: Net Improved = +1.15% (Wrong→Right: 10.2%, Right→Wrong: 9.1%)
- Off-the-shelf Turn 3: Net Improved = -4.95% (Wrong→Right: 4.9%, Right→Wrong: 9.9%)
- MAPoRL Turn 2: Net Improved = +12.03% (Wrong→Right: 14.3%, Right→Wrong: 2.3%)
- MAPoRL Turn 3: Net Improved = +1.20% (Wrong→Right: 3.6%, Right→Wrong: 2.4%)

### Experiment 2: Reward Shaping Ablation (2 turns)
- α₁=2: +9.5% improvement in ∆₁ (following correct majority opinions)
- α₀=2: +2.57% improvement in ∆₀ (deviating from incorrect majority)
- β₀=2: +17.2% improvement in ∆₀ (providing useful incorrect answers)
- β₁=2: -1.32% decrease in ∆₁ (persuasion when correct — not helpful)

### Experiment 3: Transferability
- ANLI→GSM8K: Trained Turn 1=0.677, Turn 2=0.712, Turn 3=0.720 (off-the-shelf: 0.688, 0.640)
- GSM8K→ANLI: Trained Turn 1=0.482, Turn 2=0.499, Turn 3=0.507 (off-the-shelf: 0.486, 0.468)

### Experiment 4: Heterogeneous Co-training
- Phi-3+Qwen2.5 co-training outperformed off-the-shelf collaboration of same pair across all turns
- Phi-3+Llama3-8B co-training showed similar synergistic gains

### Experiment 5: SFT vs MAPoRL
- SFT on top-10% quality debate trajectories (1,280 samples): Turn 2 accuracy = 0.578 (Δ=-0.111), Turn 3 = 0.525 (Δ=-0.114) — worse than off-the-shelf
- MAPoRL: Turn 2→0.797, Turn 3→0.809 — significant improvement

### Ablation: Without Verifier (binary reward only on GSM8K)
- MAPoRL w/o verifier: Turn 0=0.677, Turn 1=0.734, Turn 2=0.746
- MAPoRL with verifier: Turn 0=0.677, Turn 1=0.797, Turn 2=0.809

### Ablation: Single-Agent RL vs MAPoRL
- Single-agent RL with verifier: 0.732 (single turn, no iterative collaboration)
- MAPoRL: Turn 1=0.797, Turn 2=0.809 (multi-turn collaboration)

## 3. Trade-offs

| Win | Lose |
|-----|------|
| Accuracy monotonically improves with more debate turns (unlike off-the-shelf LLMs) | Requires 8× A100 GPUs and multi-day training |
| Collaboration skills transfer across domains (math↔NLI) without retraining | Verifier model must share base architecture with generator (mismatch causes reward signal degradation and stylistic drift) |
| Heterogeneous model pairs benefit from co-training (synergy > individual) | Learned verifier imperfect (91-92% accuracy); errors propagate as noisy rewards |
| Multi-agent RL substantially outperforms SFT on collaboration (SFT degrades!) | Extensive reward hacking countermeasures needed (5+ distinct mitigations) |
| Agents learn to extract useful info from *incorrect* answers (critical reasoning) | Only tested on 3B-8B models; behavior at scale (70B+) unknown |
| QLoRA enables parameter-efficient co-training (<0.2% params per agent) | Relies on \\boxed{} formatting for answer extraction; brittle to format changes |
| Works without ground-truth labels when verifier is good enough | Prompt sensitivity: outputs vary significantly with prompt phrasing |

## 4. Design Rationale

1. **Why multi-agent co-training (not single-agent):** Game-theoretic analysis (Section 2, Observations 1-2) proves that a single agent trained against a fixed opponent learns non-collaborative behavior because the opponent never adapts. Joint optimization via Nash equilibrium is necessary for cooperative equilibria to emerge.

2. **Why RL (not SFT):** SFT on high-quality collaboration trajectories (even top-10% filtered) degraded performance (Δ=-0.111 at Turn 2). Mimicking interaction patterns does not teach *strategic* collaboration. RL allows agents to discover collaboration strategies through trial-and-error with feedback from the verifier.

3. **Why Influence-aware reward (not immediate-only):** Immediate verifier scores only capture current answer quality. The influence-aware formulation (Definition 1) makes each agent consider how its response cascades to affect *all* other agents' future answers, incentivizing constructive contributions even when momentarily incorrect.

4. **Why α and β incentives:** The game-theoretic model (Observation 2) shows that Rsyn must exceed max(3Rcol-2Rind, 2Rind-Rcol) for cooperation to emerge. The α/β incentives effectively increase Rsyn by rewarding specific cooperative behaviors (revision, persuasion, constructive influence).

5. **Why shared backbone with QLoRA adapters:** Naively loading multiple full LLMs exceeds GPU memory. QLoRA adapters (r=8, α=16) on a shared base model keep each agent <0.2% of total parameters while enabling independent policy updates.

## 5. Limitations & Failure Modes

1. **Model scale limitation:** Experiments only on 3B-8B parameter models. Behavior on 70B+ models is unknown — larger models may already have better innate collaboration, reducing MAPoRL's marginal benefit.

2. **Prompt brittleness:** Instruction prompt sensitivity means performance can vary significantly with prompt changes. No systematic prompt robustness study was conducted.

3. **Verifier-generator coupling:** The verifier and generator must share the same base model family. Cross-family verifiers cause reward signal degradation and stylistic drift toward the verifier's base model during RL training.

4. **Reward hacking vulnerabilities:** Despite 5 countermeasures, reward hacking is an ongoing challenge. The paper notes DeepSeek-R1 avoided verifiers entirely for this reason, requiring ground-truth labels instead.

5. **Format constraint:** Relies on \\boxed{} answer formatting. Performance on tasks without clear answer boundaries is untested.

6. **Majority voting limitation:** Uses simple majority voting for final answers. Manager agent or more sophisticated aggregation not explored; ties handled by expectation-weighted scoring.

7. **Malicious agent risk:** If adversarial agents are present in the multi-agent system, MAPoRL's collaboration incentives could amplify harmful outcomes by enabling coordination.

8. **No GRPO/REINFORCE comparison:** Only PPO variant tested. Comparison to GRPO (used in DeepSeek-R1) or REINFORCE-style methods was not conducted.

9. **Limited agent count:** Experiments restricted to 2-3 agents and 2-3 turns. Scalability to larger agent collectives unknown.

## 6. Transfer to Lyra

### The ONE Transferable Idea

**Multi-agent RL co-training for collaborative critique and refinement.** MAPoRL demonstrates that LLMs can be explicitly trained to engage in productive multi-turn debate where agents learn to: (a) extract useful information from incorrect responses, (b) be persuaded by correct reasoning, and (c) provide constructive partial solutions. This is directly applicable to Lyra's multi-agent architecture where sub-agents currently operate independently.

### Concrete Lyra Application

Lyra's agent-router (§4.2) dispatches tasks to specialized sub-agents (code, search, analysis). Currently, agents produce independent outputs with no corrective interaction. MAPoRL-style co-training could enable Lyra's sub-agents to engage in a collaborative refinement loop: after initial outputs, agents review each other's work, challenge questionable conclusions, and converge on higher-quality answers through debate — all while being explicitly trained (not just prompted) to collaborate effectively.

The transfer is NOT about copying the full MARL pipeline. The transferable insight is: **you cannot prompt your way to genuine multi-agent collaboration; you must train for it, and joint co-training with RL outperforms SFT on interaction traces.**

### Routing
- **Workstream:** §4.2 — Agent Router & Multi-Agent Orchestration
- **Impact:** 4/5 (transformative for multi-agent output quality — could turn Lyra's agent collective from independent workers into a collaborative team)
- **Effort:** 5/5 (requires GPU cluster, verifier model training, MARL infrastructure, reward hacking mitigations, and integration with Lyra's existing agent dispatch system)
- **Tier:** breakthrough (first demonstration that RL co-training is necessary for multi-LLM collaboration; SFT proved counterproductive)
