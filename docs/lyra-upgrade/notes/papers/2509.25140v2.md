## 1. Mechanism (step-by-step)

### Problem Setting: Streaming Test-Time Learning
Given a sequential stream of tasks Q = {q1, q2, ..., qN}, the agent must complete each without ground-truth feedback. The agent policy π_L(·|M, A) is parameterized by backbone LLM L, memory module M, and action space A (web navigation operations or bash commands).

### Memory Schema
Each memory item is a structured knowledge unit with three components:
- **Title**: concise identifier summarizing the core strategy/reasoning pattern
- **Description**: one-sentence summary
- **Content**: distilled reasoning steps, decision rationales, operational insights (1-5 sentences)

### Three-Step Closed Loop (Figure 2)

**Step (i) — Memory Retrieval:**
Given a new task query qi, compute embedding-based similarity search over existing memory items. Retrieve top-k relevant items and inject them into the agent's system instruction. The agent then interacts with the environment using this memory-augmented context.

**Step (ii) — Memory Extraction:**
After task completion, the trajectory H is processed:
1. **LLM-as-a-Judge**: A binary classifier (same backbone LLM, temperature 1.0) evaluates the trajectory, outputting "success" or "failure" without ground-truth labels
2. **Success extraction**: Distills validated strategies — "why did it work?" — producing up to 3 memory items per trajectory
3. **Failure extraction**: Distills counterfactual signals and pitfalls — "why did it fail, what to avoid?" — also up to 3 items
4. Both extractors use carefully designed prompts (Figures 9-11 in appendix) that forbid specific website/query references, forcing generalizable abstractions

**Step (iii) — Memory Consolidation:**
Simple addition — new items are appended to the memory pool without pruning or deduplication (intentionally minimal to isolate content-quality effects).

### MaTTS: Memory-Aware Test-Time Scaling

**Parallel Scaling (k trajectories):**
- For a given task qi, generate k diverse rollouts
- Apply self-contrast: compare and contrast trajectories to identify consistent reasoning patterns while filtering spurious solutions
- At most 5 memory items extracted across all k trajectories
- Compute Best-of-N (BoN) using a separate LLM evaluator (Figure 12 system instruction)

**Sequential Scaling (k refinement steps):**
- After initial trajectory completion, iteratively re-examine the trajectory with self-refinement
- Intermediate correction notes are captured as memory signals
- Prompt: "Let's carefully re-examine the previous trajectory, including your reasoning steps and actions taken..."

**Bidirectional synergy:**
Better memory guides scaling toward more promising rollouts; diverse rollouts enrich memory with higher-quality contrastive signals, forming a virtuous cycle.

### Key Architectural Distinction
Unlike Synapse (stores raw trajectories) and AWM (stores successful workflows), ReasoningBank stores high-level, transferable reasoning strategies abstracted away from specific URLs/elements. Crucially, it uses *both* successes and failures — the only baseline that converts failures into constructive signals rather than noise.

## 3. Trade-offs

| Win | Loss/Cost |
|-----|-----------|
| +20.5% relative SR improvement over No Memory on WebArena | Additional LLM calls for Judge (2,186 tokens) and Extraction (1,562 tokens) per task |
| 4.3% token overhead vs No Memory (much cheaper than Synapse's +15.1% or AWM's +16.8%) | Requires at least one complete trajectory per task before memory can form (cold-start problem) |
| Learns from failures where baselines degrade (49.7 vs 46.5 success-only) | Simple additive consolidation with no pruning — memory pool grows unboundedly; retrieval cost and noise increase over long streams |
| Works across 3 model families (Gemini Flash/Pro, Claude Sonnet) and scales down to 12B open-source model | MaTTS requires k-fold compute multiplier per task during training phase |
| Robust to judge noise (stable at 70-90% accuracy) | Embedding-based retrieval (not reasoning-aware) may miss compositional memory patterns |
| Reduced interaction steps (up to 2.1 fewer on successful cases, 26.9% relative reduction) | Sequential scaling saturates quickly — once model is confident (correct or wrong), further refinement adds no value |
| Emergent strategy evolution over time (Figure 6): atomic → procedural → generalized complex strategies | Pass@1 for Synapse/AWM *degrades* with scaling — memory quality gate is critical, not all memory benefits from TTS |

## 4. Design Rationale

**Why reasoning abstractions, not raw trajectories or workflows?**
Prior methods (Synapse stores full trajectories, AWM extracts workflows) capture *what* happened but not *why*. By forcing the extraction LLM to produce title+description+content with explicit prohibitions against website-specific references, ReasoningBank creates transferable reasoning primitives that generalize across domains. This is the core bet: abstraction quality > retrieval sophistication.

**Why include failures?**
The authors argue that failures provide unique counterfactual signals — knowing what *not* to do (pitfalls, guardrails) is complementary to knowing successful strategies. Empirically, AWM *degrades* when failures are included because its workflow extraction cannot separate noise from signal in failed trajectories. ReasoningBank's dedicated failure extraction prompt ("reflect on why it failed") converts noise into actionable guardrails.

**Why minimal consolidation (simple addition)?**
Intentional design choice to isolate the effect of memory *content quality* from memory *management sophistication*. The argument: if content quality is high enough, even simple retrieval+addition suffices. This also keeps the system deployable without complex infrastructure.

**Why MaTTS (memory-aware TTS)?**
Standard TTS generates more rollouts but doesn't feed improvements back. MaTTS creates a bidirectional loop where (a) retrieved memories guide exploration toward promising regions, and (b) contrastive signals from diverse rollouts produce higher-quality memory than single-trajectory extraction.

## 5. Limitations & Failure Modes

1. **Unbounded memory growth**: Simple-additive consolidation means the memory bank grows monotonically. Over very long streams, retrieval latency increases and noise/redundancy accumulates. No decay, pruning, or forgetting mechanism exists.

2. **Cold-start problem**: Memory starts empty. Early tasks in a stream receive no benefit. The agent must accumulate enough diverse experiences before memory becomes useful.

3. **LLM-as-a-Judge dependency**: Judge achieves only 72.7% accuracy on WebArena-Shopping. While the framework is robust to moderate noise (stable at 70-90% accuracy range), systematic judge biases could propagate into memory quality.

4. **Domain specificity**: All evaluations are on web browsing (WebArena, Mind2Web) and SWE (SWE-Bench-Verified). No evidence of transfer across fundamentally different action spaces.

5. **No compositional memory**: Each memory item is retrieved and used independently. The framework cannot compose multiple items into higher-level strategies or macros, limiting complex multi-step reasoning.

6. **Embedding-only retrieval**: Simple similarity search may miss relevant memories that are semantically distant but structurally analogous. Reasoning-aware retrieval is noted as future work.

7. **Sequential scaling saturation**: After 2-3 refinement steps, gains plateau. Parallel scaling dominates at larger k but requires more independent rollouts.

8. **No explicit safety/alignment guardrails**: Memory items are auto-generated without human review, potentially encoding harmful strategies or biases.

## 6. Transfer to Lyra

### The One Transferable Idea

**Dual-source memory extraction from both successes and failures with LLM-as-a-Judge self-supervision**, creating a closed-loop self-evolving memory system that requires no ground-truth labels. ReasoningBank's key innovation is not the retrieval mechanism (simple embeddings) but the *content schema*: structured reasoning abstractions (title+description+content) distilled from contrastive success/failure signals.

### Workstream Route: §4.5 (Memory Systems)

This directly feeds the Memory subsystem workstream. Lyra's memory architecture can adopt:
1. The three-field memory schema (title/description/content) for storing reasoning strategies
2. LLM-as-a-Judge binary classification for automatic success/failure labeling of agent trajectories
3. Separate extraction prompts for success (validated strategies) and failure (counterfactual guards)
4. Simple additive consolidation as a baseline, then iterate on pruning/decay policies

### Impact/Effort/Tier Assessment
- **Impact**: 4/5 — Directly addresses a core gap: Lyra agents currently lack self-improving memory that learns from failures
- **Effort**: 3/5 — Requires prompt engineering for extraction, embedding DB, judge integration; the architecture is intentionally simple
- **Tier**: **Breakthrough** — This paper establishes memory-driven experience as a new scaling dimension with strong empirical evidence across models and domains, and the mechanism is directly portable to Lyra's agent loop
