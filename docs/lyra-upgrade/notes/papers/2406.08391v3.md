## 1. Mechanism (Step-by-Step)

### Problem formulation
Given a question Q, model-generated answer A_hat, and ground-truth answer A, predict P(correct) — the probability that the model's answer is correct. This is a binary classification task learned from a small labeled dataset of (Q, A_hat, correctness_label) tuples.

### Step 1: Construct a graded dataset
1. **Generate answers** via greedy decoding on questions from 16 benchmark datasets (ARC, BoolQ, CommonsenseQA, CosmosQA, HellaSwag, MathQA, SNLI/RTE, OpenBookQA, PIQA, SciQ, CB, MultiRC, CoPA, TREC, Winogrande, Adversarial NLI). Total ~20,000 samples.
2. **Grade correctness** using an auxiliary LLM (GPT-3.5 Turbo) with the prompt:
   ```
   The problem is: Q
   The correct answer is: A
   A student submitted: A_hat
   [instructions: be lenient on formatting, strict on substance]
   Did the student provide an equivalent answer? yes/no
   ```
   GPT grading matches human grading within 8.7% absolute accuracy error (vs 16.8% for substring match).
3. Hold out 2000 samples for temperature scaling calibration.

### Step 2: Parameterize P(correct) — Three methods
| Method | Description | Trainable params | Prompt? |
|--------|-------------|------------------|---------|
| **Probe** | Small feed-forward NN on last-layer hidden features of base LLM | ~few thousand | No |
| **LoRA** | LoRA adapters (r=8, α=32, dropout 0.1) on base LLM, output head for binary classification | ~few million | No |
| **LoRA + Prompt** | LoRA fine-tuning with language prompt framing correctness as MC choice ("i" = no, "ii" = yes) | ~few million | Yes |

### Step 3: Fine-tuning procedure
1. **Quantization:** 8-bit quantization for memory efficiency.
2. **LoRA config:** rank r=8, α=32, dropout 0.1.
3. **Optimizer:** AdamW, learning rate 10^-4, cosine decay, batch size 32, 10000 steps with 1000 warmup steps.
4. **Regularization (CRITICAL):** Jensen-Shannon Divergence (JSD) between base model's logit distribution pθ0 and fine-tuned model's logit distribution qθ, applied only to the target answer sequence tokens. Weighted by κ.
   ```
   Loss = CrossEntropy(ŷ, y) + κ × JSD(pθ0 || qθ)
   where JSD(p||q) = ½[KL(p||m) + KL(q||m)], m = ½(p+q)
   ```
   Without regularization: ECE = 29.9%. With KL: ECE = 10.8%. Forward-KL and reverse-KL alone were insufficient — JSD found to be optimal empirically.

### Step 4: Temperature scaling
After fine-tuning, apply temperature scaling on the 2000-sample holdout set. The temperature T is learned by minimizing NLL on the holdout set, then applied to scale the logits before softmax at inference.

### Step 5: Inference
Given new (Q, A_hat): feed through fine-tuned model → output P(correct) ∈ [0,1].

### Evaluation metrics
- **ECE (Expected Calibration Error):** Lower is better. ECE = Σ(b_j/N) × |conf(b_j) - acc(b_j)| across B equally-spaced bins.
- **AUROC (Area Under ROC):** Higher is better. Measures selective prediction ability — separating correct from incorrect answers.

### Computational cost
- 1-3 GPU days on 4× NVIDIA RTX8000 (48GB) GPUs.
- Inference adds negligible overhead (single forward pass, same as base model with LoRA adapters loaded).

### Baseline comparisons
- **Zero-Shot Classifier:** P("True") / (P("True") + P("False")) from yes/no prompt appended to Q+A.
- **Verbal Elicitation:** Prompt model to output "Confidence: X%" as text, parse float.
- **Sampling:** Generate K=10 samples with top_p=0.95, cluster by semantic similarity (O(K²) comparisons via auxiliary model), estimate P(correct) from cluster proportions.

## 2. Results

### Main results on Open-Ended MMLU (averaged over 6 base models: LLaMA-2 7B/13B & Mistral 7B, base+chat)
| Method | ECE (OE MMLU) | AUROC (OE MMLU) |
|--------|---------------|------------------|
| Zero-Shot Classifier | ~35% | ~55% |
| Verbal Elicitation | ~40% | ~60% |
| Sampling (likelihood accumulation) | ~15% | ~52% |
| Probe (frozen features) | ~20% | ~60% |
| LoRA | ~15% | ~65% |
| **LoRA + Prompt** | **~10%** | **~72%** |

### Multiple Choice MMLU results
| Method | ECE (MC MMLU) | AUROC (MC MMLU) |
|--------|---------------|------------------|
| Max Softmax Probability | ~15% | ~72% |
| Zero-Shot Classifier | ~20% | ~60% |
| Probe | ~8% | ~70% |
| LoRA | ~8% | ~72% |
| LoRA + Prompt | ~5% | ~75% |

### Data efficiency (OE MMLU, LoRA + Prompt)
| Training samples | ECE | AUROC |
|-----------------|-----|-------|
| 200 | ~15% | ~62% |
| **1,000** | **~12%** | **~65%** |
| 5,000 | ~10% | ~68% |
| 20,000 | ~10% | ~70% |

Key finding: ~1,000 labeled examples are enough to beat all zero-shot baselines. Diminishing returns after 5,000.

### Regularization ablation (critical result)
| Regularization | ECE | AUROC |
|---------------|-----|-------|
| Without KL/JSD | 29.9% | 70.2% |
| With JSD | 10.8% | 71.6% |

Without regularization, the fine-tuned model becomes miscalibrated even with good discriminative performance.

### Cross-model transfer (AUROC on OE MMLU)
- **Mistral 7B estimating LLaMA-2 7B:** AUROC ≈ 0.72
- **LLaMA-2 7B estimating itself:** AUROC ≈ 0.68
- **LLaMA-2 7B estimating Mistral 7B:** AUROC ≈ 0.65

Mistral is a better uncertainty estimator for LLaMA than LLaMA is for itself.

### Generalization across distribution shifts (LoRA + Prompt)
| Shift type | ECE | AUROC |
|-----------|-----|-------|
| MC → OE (transfer) | ~15% | ~68% |
| OE → MC (transfer) | ~12% | ~65% |
| In-distribution (OE) | ~10% | ~72% |

### Out-of-distribution: Coding tasks (LiveCodeBench, LeetCode easy subset)
| Model | Zero-Shot Classifier ECE/AUROC | LoRA + Prompt ECE/AUROC |
|-------|-------------------------------|--------------------------|
| LLaMA-2 7B | 41.0% / 56.9% | 46.4% / 80.0% |
| Mistral 7B | 70.2% / 66.2% | 21.4% / 85.1% |
| Mistral 7B Instruct | 52.7% / 47.1% | 56.1% / 70.2% |

### Unanswerable question detection (SelfAware dataset)
LoRA + Prompt assigns **lower confidence to unanswerable questions** than Zero-Shot Classifier, enabling opt-out behavior.

### User study (N=181 participants, 20 per variant)
- **LoRA + Prompt:** Users modulated reliance on LLM based on confidence — agreed more at high confidence, disagreed more at low confidence (visually clear separation in density plots).
- **Zero-Shot Prompt:** Mass clustered — users could not discriminate based on confidence.
- **Random confidence (control):** No signal — users unable to modulate reliance.
- **Biggest effect:** Improving lowest-performing users; average accuracy differences were modest.
- **User quotes:** "if it had a confidence of less than 50% it made me very skeptical"; "if the model's confidence fell below 45 I decided to investigate it myself."

## 3. Trade-offs

| Win | Loss / Cost |
|-----|-------------|
| ECE drops from ~35% (zero-shot) to ~10% (LoRA+Prompt) on OE MMLU | Requires 1,000+ labeled correctness examples (annotation cost) |
| AUROC improves from ~55% to ~72% for selective prediction | 1-3 GPU days of fine-tuning with 4× RTX8000 (48GB) GPUs |
| Single forward pass at inference (fast) vs 10+ samples for sampling methods | Additional model weights loaded (LoRA adapters) during inference |
| Generalizes across subjects, formats (MC↔OE), and to unseen coding tasks | Calibration degrades on very hard tasks where base model accuracy is very low (e.g., LLaMA-2 7B on coding: ECE worsens to 46.4%) |
| Cross-model uncertainty estimation works — one strong model can serve multiple others | Cross-model transfer has ~2-5 AUROC point penalty vs in-model estimation |
| Calibrated confidence improves human-AI collaboration (user study evidence) | Effect mainly benefits low-performers; average accuracy gains are modest |
| JSD regularization is critical (ECE: 29.9% → 10.8%) | Adds hyperparameter κ that needs tuning per base model |
| Works with 8-bit quantization + LoRA (accessible hardware) | Two-model architecture (separate weights for answering vs uncertainty) — not a unified model |
| LoRA+Prompt > Probe: training through model features is necessary for OE generalization | LoRA modifies base model features, which may affect other downstream uses of the same weights |

## 4. Design Rationale

**Why fine-tuning over prompting alone?** The authors argue that prompting relies on LLMs having learned calibration from human text during pre-training. But humans are poorly calibrated on unfamiliar tasks, and pre-training data includes writing from non-experts. Therefore, good calibration requires a deliberate intervention beyond prompting. They frame LLM pre-training as "behavior cloning" on human writing — optimal outcome is recapitulating human calibration, which is itself poor.

**Why LoRA + Prompt over Probe?** Frozen features (Probe) contain some signal about correctness but are insufficient for open-ended generation where the model must assess semantic equivalence, not just token-level patterns. Training through features (LoRA) allows the model to reshape representations for the uncertainty task. Adding a language prompt (LoRA + Prompt) further leverages the model's pre-trained language understanding.

**Why JSD over forward/reverse KL?** Forward-KL encourages zero-avoiding (covering all modes), reverse-KL encourages zero-forcing (covering one mode). Neither is obviously optimal for LLM distributions. JSD provides a symmetric compromise that empirically outperforms both.

**Why open-ended evaluation?** Most prior work evaluates on multiple choice, where max softmax probability already works well. But real-world LLM use is primarily open-ended (chat), where perplexity is not predictive of correctness. The paper introduces open-ended MMLU as a more realistic benchmark.

**Why cross-model uncertainty?** If uncertainty estimation required self-knowledge specific to a model's internals, it would not transfer. The finding that Mistral estimates LLaMA's uncertainty better than LLaMA itself suggests uncertainty estimation is about learning general correctness-assessment skills, not introspection.

## 5. Limitations and Failure Modes

1. **Two-model architecture:** Fine-tuning produces a separate model for uncertainty estimation. The question-answering model and uncertainty model have different weights, requiring switching. A unified single-model approach is left to future work.

2. **Does not handle creative/generative tasks:** The method applies only to fact-based QA with verifiable answers. For open-ended generation (stories, advice, creative writing) where no ground-truth correctness exists, this paradigm cannot be applied. The authors explicitly acknowledge this in the Broader Impact statement.

3. **Calibration degrades on very hard tasks:** On coding tasks where base model accuracy is extremely low (LLaMA-2 7B at 3.2%), calibration actually worsens after fine-tuning (ECE: 41% → 46.4%), though AUROC still improves (56.9% → 80.0%).

4. **No exploration of sampling temperature interaction:** Fine-tuning on greedy-decoded answers may not generalize well to answers generated with different decoding parameters (temperature, top_p).

5. **User study limitations (explicitly acknowledged):** (a) Users received trial-by-trial feedback, letting them learn model reliability independently of confidence scores — confidences might matter MORE without feedback. (b) MMLU questions are hard for non-experts; results may differ when humans are confident in their own abilities. (c) Only numeric confidence was tested; alternative displays (verbal, visual) might improve human utilization. (d) N=20 per variant is small.

6. **Grading noise:** GPT-3.5 Turbo grading has ~8.7% error vs human grading. Using GPT-4 would reduce error to ~4.5% but at higher cost. Grading errors propagate as label noise to the fine-tuning data.

7. **Subjectivity of correctness:** Ground truth in ML benchmarks is contested. What is "correct" can be subjective (moral, philosophical questions). The method inherits this ambiguity.

8. **No batch or online uncertainty-aware pre-training:** The authors hypothesize that an uncertainty-aware training phase (e.g., RLHF with calibration penalty) could produce inherently calibrated models, but this is left to future work.

## 6. Transfer to Lyra

**The one transferable idea:** Fine-tune Lyra with LoRA on a small corpus (~1,000) of agent action-outcome pairs (graded as correct/incorrect) to produce a calibrated confidence head that outputs P(success) for each action. This directly enables the §4.19 self-knowledge pipeline: (a) the router escalates actions with P(success) < threshold to stronger models, (b) the autonomy system requests human input when uncertainty exceeds bounds, and (c) the user sees calibrated confidence alongside Lyra's outputs. The cross-model transfer finding (Mistral estimating LLaMA's uncertainty) is particularly powerful for Lyra: a single calibration-tuned judge model can serve as an uncertainty oracle for multiple worker agents, including closed-source models via API.

**Workstream:** §4.19 — Self-Knowledge / Uncertainty Estimation

**Impact:** 5 (Foundational — this is the core mechanism already named in the §4.19 plan; provides the calibration methodology, regularization technique, data efficiency numbers, and cross-model transfer result)

**Effort:** 3 (Requires constructing a ~1,000-example graded corpus of Lyra action outcomes, running LoRA fine-tuning on 1-3 GPU days, and integrating the confidence head into the router pipeline. The code is open-source and the procedure is well-documented. Principal engineering challenge is corpus construction, not the training pipeline.)

**Tier:** Breakthrough
