## 1. Mechanism (step-by-step)

Q-DAPS estimates question difficulty for LLMs by measuring the entropy of plausibility scores across candidate (incorrect but plausible) answers. The method has three stages:

### Stage 1: Candidate Generation + Validation

Given a question `q` and its ground-truth answer `gt`, prompt an LLM (default: LLaMA 3.3 70B) to generate N=20 candidate answers — plausible but incorrect alternatives — each with a plausibility score (0-100) and a textual justification. The prompt (Fig 3) explicitly says: _"Assume that you do not know that the answer to `<question>` is `<ground_truth>`."_

**Validation:** (a) semantic deduplication via BEM (Bulian et al., 2022); (b) scores must be in [0,100]; (c) exactly N unique candidates. If any check fails, increment temperature by 0.1 and regenerate. Loop until all checks pass.

### Stage 2: Popularity Debiasing

Candidates receive Wikipedia page-view counts (Jan 2015–Dec 2024), normalized to [0,1] with IQR outlier removal. The plausibility score is debiased via:

```
DePls_i = Pls_i × (1 − α × Pop_i)         [Equation 1]
```

where α ∈ [0,1] controls debiasing strength. The multiplication by Pls_i ensures the debiasing effect is proportional to plausibility — popularity is a fixed attribute, plausibility is question-dependent. α is tuned via grid search (optimal ~0.5).

### Stage 3: Entropy Scoring

Normalize debiased scores to a probability distribution:

```
DePls_norm_i = DePls_i / Σ_j DePls_j      [Equation 2]
```

Compute Shannon entropy:

```
H(q) = − Σ_i DePls_norm_i × log₂(DePls_norm_i)    [Equation 3]
```

Scale to [0,1]:

```
Diff_q = H(q) / log₂(N)                     [Equation 4]
```

**Interpretation:** High entropy → many candidates similarly plausible → harder question. Low entropy → one/few candidates dominate → easier question.

### Evaluation Protocol

10 LLMs (3B to GPT-4 class) each answer every question. Correctness is judged by GPT-Eval with 3-judge majority voting (GPT-4, Gemini 2.5 Flash, Claude Sonnet 4.5). Cohen's d measures standardized effect-size separation between Easy vs Hard halves (median-split on Diff_q). Spearman's ρ measures monotonicity between difficulty and model success count.

### Scoring Paradigms Compared

- **Pointwise:** prompt LLM separately for each candidate → O(n) prompts, tends to assign score=1 to most candidates (poor discrimination)
- **Pairwise:** compare all pairs, aggregate via Bradley-Terry model → O(n²) prompts, hallucination-prone
- **Listwise:** generate all candidates+scores in one prompt → O(1) prompts, best diversity of scores, chosen as primary

### Ablation Results (Cohen's d, Table 4-6)

- **Without gold answer:** Still beats all baselines (MuSiQue 0.8325, QASC 0.5144, NQ 0.6319, TriviaQA 0.6647)
- **Without debiasing:** Still beats baselines (MuSiQue 0.894, QASC 0.5614, NQ 0.88, TriviaQA 0.6511)

### Generalization (Table 15)

- Optimal α ≈ 0.50 (robust across Simple/Complex/Entire)
- Optimal N ≈ 7-8 candidates (much less than 20 — efficiency win)
- Alpha robustness: Debiased-Plausibility outperforms raw Plausibility across nearly all α ∈ [0,1]

### Human Evaluation

- **Multiple-choice QA:** All 6 evaluators had higher accuracy on Easy vs Hard questions (e.g., Evaluator 1: Easy=0.65, Hard=0.68; Evaluator 5: Easy=0.68, Hard=0.75)
- **Difficulty Rating alignment:** Mean accuracy 0.68 (Easy), 0.74 (Hard) — humans more consistent identifying hard questions

### Efficiency

- Listwise: O(1) prompts per question, ~56 words average output
- Pointwise: O(n), ~60 words per prompt × n
- Pairwise: O(n²), ~296 words per prompt × n(n-1)/2

## 3. Trade-offs

| Win | Loss / Cost |
|-----|-------------|
| Outperforms all 5 baseline categories across 4 datasets | Requires ground-truth answer at training time for best results (δ ≈ 0.2-0.3 Cohen's d lost without it) |
| Computationally efficient (1 prompt/question, O(1)) | LLM-dependent; quality varies with model size (Qwen 7B: d=0.84 vs LLaMA 70B: d=1.09 on MuSiQue) |
| Interpretable — exposes all candidates + plausibility scores | English-only; not tested on multilingual/multimodal |
| Works on both simple (TriviaQA, NQ) and complex (MuSiQue, QASC) questions | Limited to question types where plausible candidates can be constructed (entity, temporal, numeric, boolean, categorical, MCQ) |
| Robust without gold answer (still beats all baselines) | Popularity debiasing depends on Wikipedia coverage; domains without Wikipedia entries (medicine, finance, specialized tech) lose debiasing benefit |
| Robust without debiasing | Entropy can overestimate difficulty for list-based questions (many equally-plausible alternatives) or underestimate for annotation-ambiguous questions |
| Only needs 7-8 candidates (not 20) for optimal performance | Uses proprietary GPT-4 for final evaluation; core generation uses open-weight models but evaluation pipeline is not fully open |

## 4. Design Rationale

The authors argue that existing difficulty metrics (readability formulas, retrieval signals, direct LLM prompting) measure surface properties rather than the **reasoning uncertainty** an LLM experiences when multiple answers appear similarly compelling. The key insight: difficulty is fundamentally about **how convincing wrong answers are**, not about text complexity or retrieval ease.

Entropy was chosen over mean plausibility because entropy captures distributional spread — a question with one clearly-plausible distractor (and all others implausible) may have the same average plausibility as one with many moderately-plausible distractors, but the latter is much harder. Experimental validation confirms entropy consistently outperforms average plausibility.

Popularity debiasing is necessary because LLMs generate more popular answers earlier (confirmed via Kendall's τ / Spearman's ρ between generation order and Wikipedia page views), which would otherwise distort plausibility distributions.

The listwise approach was chosen over pointwise (which assigns score=1 to almost everything) and pairwise (which introduces hallucination-driven inconsistencies) because it forces the model to compare candidates in context, producing more discriminative scores.

## 5. Limitations & Failure Modes

### Stated Limitations
1. **Question type restriction:** Suited to entity, temporal, numeric, boolean, categorical, and MCQ formats — not open-ended essay, procedure, or creative questions.
2. **English-only:** No evidence of cross-lingual transfer.
3. **Model dependency:** Pipeline behavior varies with LLM choice; smaller models produce weaker candidate answers.

### Observed Failure Modes (Error Analysis, Appendix H)
1. **Entropy-overestimated difficulty:** For list-type factual questions (e.g., "Types of skiing in Winter Olympics 2018"), many semantically related disciplines all receive high plausibility → high entropy, yet all QA models answer correctly. The entropy reflects answer-space richness, not actual model uncertainty.
2. **Entropy-underestimated difficulty:** For annotation-ambiguous questions (e.g., "What nationality was Aristotle Onassis?" — gold: Turkish, all models: Greek), low entropy correctly reflects consensus on "Greek," but evaluation penalizes because the gold label encodes birthplace rather than ethnicity. Q-DAPS captures ambiguity in the plausible space, not annotation idiosyncrasies.
3. **Wikipedia dependency for debiasing:** In specialized domains (medicine, finance, niche technical fields), Wikipedia page view data may be sparse or misleading, reducing debiasing effectiveness.

### Unstated Limitations
- No evaluation on truly open-ended or generative QA tasks (all benchmarks are factoid or MCQ)
- No adversarial robustness testing (e.g., intentionally misleading candidates)
- No latency/throughput benchmarks for production deployment
- Single-turn QA only; no multi-turn conversation difficulty estimation

## 6. Transfer to Lyra

### THE ONE IDEA: Plausibility-Entropy Difficulty Estimation for Adaptive Model Selection

Q-DAPS provides a **lightweight, interpretable signal** that predicts how likely an LLM is to fail on a given question — without running the full QA system first. For Lyra, this directly enables **adaptive model routing**: before invoking an expensive frontier model to answer a user question, Lyra can run Q-DAPS (using a small, cheap model like LLaMA 3.1 8B as the generation core) to estimate question difficulty. Low-difficulty questions go to a fast/cheap model; high-difficulty questions get escalated to a stronger model or trigger additional safeguards (citation requirements, human-in-the-loop).

### Workstream Route: §4.5 — Adaptive Model Router

The difficulty score Diff_q ∈ [0,1] is a natural threshold signal for Lyra's model router. High-difficulty predictions also serve as a **hallucination risk early-warning** — triggering the §4.3 verification pipeline or the §4.7 safety guardrail before the costly model even runs.

### Impact / Effort / Tier

- **Impact:** 4 — directly improves cost-performance tradeoff via smarter routing; hallucination early-warning is a genuine safety plus
- **Effort:** 2 — requires only 1 additional LLM call per incoming question (Listwise, O(1)), Wikipedia page view data (free via Wikimedia API), and no fine-tuning; can wrap as a pre-processing middleware
- **Tier:** **breakthrough** — novel metric with strong empirical validation, directly applicable to Lyra's core routing architecture, low implementation friction
