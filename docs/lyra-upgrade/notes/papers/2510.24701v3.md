# Tongyi DeepResearch Technical Report (Tongyi DeepResearch Team, Tongyi Lab / Alibaba Group, arXiv:2510.24701v3, May 2026)

## 1. Mechanism

Tongyi DeepResearch is a 30.5B-parameter (3.3B activated/token) MoE agentic LLM for long-horizon deep research, built from Qwen3-30B-A3B-Base through an end-to-end pipeline that unifies agentic mid-training and post-training.

### 1.1 Formal Rollout Model
The agent operates in the ReAct framework as a sequence of thought-action-observation triplets:

```
HT = (τ0, a0, o0, ..., τi, ai, oi, ..., τT, aT)                                            (1)
τt, at ~ π(·|Ht-1)                                                                        (2)
```

Where τt = thought (internal reasoning), at = action (tool call or final answer), ot = observation (environment feedback). Actions include Search, Visit, Python Interpreter, Google Scholar, and File Parser.

### 1.2 Context Management (Key Innovation)
To prevent context overflow in long-horizon tasks, the agent uses **Markovian state reconstruction** rather than conditioning on full history. At each step t, the agent works from a strategically reconstructed workspace containing only: the original question q, an evolving report St (compressed memory), and immediate context from the last interaction (at, ot):

```
St, τt+1, at+1 ~ π(·|St-1, at, ot)                                                        (3)
```

This enforces structured reasoning by requiring explicit synthesis at each step, aligning with human research patterns of periodic synthesis and reflection.

### 1.3 Agentic Mid-Training
Two-stage **Agentic Continual Pre-training (Agentic CPT)** bridges pre-training and post-training:
- **Stage 1:** 32K context length, standard next-token prediction loss
- **Stage 2:** 128K context length, large corpus of long-sequence (64K-128K) agentic behavior data
- Both stages interleave a small proportion of general pre-training data
- Data synthesized across the complete agent lifecycle: Question Synthesis, Planning Action, Reasoning Action, Decision-Making Action
- Questions generated via entity-anchored open-world memory with multi-hop and numerical patterns
- General function-calling data produced through environment scaling (heterogeneous simulated environments)
- Optimization: standard next-token prediction loss

### 1.4 Agentic Post-Training
**Stage 1 - High-quality Data Synthesis:**
Fully automated pipeline (zero human annotation):
1. Graph Construction: Build interconnected knowledge graph via random walks with web search, incorporating isomorphic tables from real websites
2. Subgraph Sampling: Generate initial QA pairs from subgraphs/subtables
3. Uncertainty Injection: Strategically increase question difficulty via "atomic operations" (e.g., merging entities with similar attributes) grounded in a formal set-theoretic model of information-seeking problems
4. PhD-level engine: Iterative complexity upgrades via question-crafting agent that progressively expands scope and abstraction

**Stage 2 - Supervised Fine-Tuning (Cold Start):**
- Mixed training paradigm: ReAct Mode samples (full history input) + Context Management Mode samples (summary + last interaction input)
- Rigorous rejection sampling filters out low-quality trajectories
- Two sub-stages: first at 40K context (all Context Management Mode + short ReAct), second at 128K (long ReAct + stability samples)

**Stage 3 - Agentic Reinforcement Learning:**
Adapted GRPO (Group Relative Policy Optimization) with on-policy training:


Key modifications from standard GRPO:
- Token-level policy gradient loss (from DAPO)
- Clip-higher strategy to encourage exploration
- Leave-one-out advantage estimation to reduce variance
- Selective exclusion of degenerate negative samples (e.g., length-limit truncations)
- No format reward (cold start already ensures format adherence)
- Pure 0/1 reward signal of answer correctness (RLVR)

### 1.5 Infrastructure
- **Async Rollout Framework:** Built on rLLM; separate async servers for model inference and tool invocation; centralized interaction handler formats unified message lists
- **Unified Sandbox:** Central scheduling layer with concurrency controls, fault-tolerance (QPS rate constraints, result caching, auto-timeout-and-retry, graceful degradation, failover to backup APIs)
- **Simulated Environment:** Local Wikipedia-based environment with RAG tools for fast algorithm validation ("wind tunnel")
- **Automatic Data Curation:** Background process monitors training dynamics, removes mastered/always-failing problems, adds newly-challenging problems from a continuously sampled backup pool; runs independently without interrupting RL training

### 1.6 Model Merging
Final weighted average of model variants from the same base with different capability preferences:

```
θmerged = Σ αk · θ(k),  s.t. Σ αk = 1, αk ≥ 0                                         (6)
```

### 1.7 Heavy Mode (Test-Time Scaling)
- Parallel Research Phase: n independent agents with different exploration strategies produce (STu, answeru)
- Integrative Synthesis Phase: Synthesis model consolidates compressed reports: answer_final = Synthesis({(STu, answeru)})

## 3. Trade-offs

| Win | Lose / Cost |
|-----|-------------|
| SOTA on 7/8 deep research benchmarks with only 3.3B active params | Trails ChatGPT-5-Pro significantly on xbench-DS-2510 (55.0 vs ~75+) |
| Fully open-source (model, framework, tools, prompts) | 128K context limit insufficient for extreme long-horizon tasks |
| Zero human annotation cost (fully automated synthetic data pipeline) | Synthetic data may contain hidden biases from teacher LLMs and graph construction |
| Mid-training provides stronger agentic prior than vanilla post-training-only approaches | Two-phase CPT adds training cost and complexity vs single-phase |
| Context Management enables arbitrary-depth exploration without overflow | Requires model to learn explicit synthesis; adds cognitive overhead per step |
| Simple ReAct + Bitter Lesson philosophy; avoids brittle prompt engineering | Limited to pre-defined tool set; may not handle novel interaction patterns |
| Heavy Mode boosts scores 5-15pp via parallel agents | Requires separate synthesis model and n× compute at test time |
| Stable RL training through environment engineering rather than algorithmic innovation | Heavy infrastructure dependency (async servers, sandbox, caching, failover) |
| Simulated environment enables fast iteration | Sim-to-real gap: simulated data coverage limited vs real web |
| MoE efficiency: 30.5B total / 3.3B active | No larger model variant released yet |

## 4. Design Rationale

The core philosophy derives from **"The Bitter Lesson"** (Sutton, 2019): general methods leveraging scalable computation ultimately outperform complex, human-engineered designs. This drives three key architectural decisions:

1. **Simple ReAct over multi-agent frameworks**: Rather than elaborate prompting or rigid workflows, use a minimal ReAct loop and let RL discover optimal research strategies through environment interaction. This avoids brittle prompt engineering that would become obsolete as model capabilities scale.

2. **Mid-training as bridge**: General foundation models pretrained on plain text lack agentic inductive bias. Loading all agentic learning into post-training creates optimization conflicts (learning agentic behavior and alignment simultaneously). Mid-training endows the model with agentic priors first, enabling more effective post-training RL.

3. **Environment as design variable, not given**: Instead of treating environments as fixed external reality, actively design them in three forms (Prior World, Simulated, Real) tightly coupled to training stage needs — each optimized for stability, fidelity, and cost at the appropriate phase. The insight is that stable environments and high-quality data matter more for agentic RL success than algorithmic novelty.

4. **Synthetic data flywheel**: Human annotation cannot scale to research-level problems. Automated synthesis enables unlimited complexity scaling, verifiability, targeted meta-capability enhancement, and a data flywheel where trained models generate better data for the next iteration.

## 5. Limitations & Failure Modes

1. **Context ceiling:** 128K context still insufficient for the most complex long-horizon tasks; extended contexts or advanced management needed.
2. **Scale ceiling:** No larger model variant released; current 30.5B total parameters may cap performance on hardest tasks.
3. **Tool rigidity:** Training focused on specific prompt instructions and predefined tool sets (Search, Visit, Python, Scholar, File Parser); may not generalize to novel tool environments.
4. **Report quality:** Report generation fidelity and user preference alignment still being actively improved — outputs may lack coherence or faithfulness.
5. **RL efficiency:** Current full-rollout RL is computationally expensive; partial rollouts would require solving off-policy distribution shift.
6. **Sim-to-real gap:** Simulated Wiki environment lacks the diversity, noise, and adversarial content of the real web; strategies that work in simulation may not transfer perfectly.
7. **Heavy Mode cost:** Test-time scaling via parallel agents requires n× compute; synthesis model adds another inference pass.
8. **Benchmark recency:** xbench-DeepSearch-2510 results (55.0) show meaningful gap behind ChatGPT-5-Pro (~75+ on same benchmark), suggesting headroom remains.
9. **Language coverage:** While BrowseComp-ZH demonstrates Chinese capability, most benchmarks and training focus on English; multilingual deep research coverage is uneven.
10. **Synthetic data risks:** Fully automated pipeline may propagate errors from teacher models, knowledge graph construction, or verification heuristics without human catches.

## 6. Transfer to Lyra

**The one idea: Context Management via Markovian State Reconstruction (Equation 3).**

The agent maintains a bounded workspace (question + evolving compressed report + last interaction) rather than the full history. At each step, the model explicitly synthesizes observations into an updated report St, which serves as both compressed memory and the conditioning state for the next step. This enables arbitrarily deep research trajectories within fixed context budgets, while the forced synthesis step naturally produces structured, self-consistent reasoning.

**Lyra integration:** Feed this into **§4.2 (Memory/Context subsystem)**. Lyra's current architecture likely grows context linearly with tool calls. Adopting this paradigm would let Lyra:
- Maintain a persistent "research notebook" state that is incrementally updated via explicit synthesis
- Condition each new tool call on only the notebook + question + last observation
- Scale to longer research sessions without context-window pressure
- Produce intermediate synthesis checkpoints that are independently useful

**Impact:** 4 — Core architectural change to how Lyra manages context; enables longer-horizon autonomous research.
**Effort:** 3 — Requires modifying the agent loop's state representation, implementing synthesis pass, and tuning the synthesis prompt/model behavior.
**Tier:** breakthrough — This is a fundamental capability unlock for long-horizon agent operation, not parity catch-up.
