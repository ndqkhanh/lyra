**Venue/Year:** arXiv preprint, April 2026 (arXiv:2604.16175v1 [cs.AI], 17 Apr 2026)

**Code/Data:** Not released at time of publication. Model weights not mentioned. Dataset: RadGenome-ChestCT (25,692 chest CT scans from 21,304 patients), publicly available.

## 1. Mechanism (Step-by-Step)

MARCH is a three-stage hierarchical multi-agent framework that emulates the Resident-Fellow-Attending workflow of real radiology departments. It uses N=3 Fellow agents by default (optimal cost/fidelity balance per the ablation on 100-sample subset).

### Stage 1: Initial Report Drafting (Resident Agent)
- **Input:** 3D chest CT scan I
- **Encoder:** Frozen dual-stream ViT3D backbone pretrained on RadFM
- **Multi-region segmentation:** SAT (Segment Anything with Text) module partitions CT into 10 anatomical subregions (abdomen, bone, breast, heart, esophagus, lung, mediastinum, pleura, thyroid, trachea/bronchi)
- **Generator:** LLaMA-2-Chat-7B fine-tuned via LoRA (AdamW, lr=1e-5, batch_size=1, 10 epochs, ~40 hours on single H100)
- **Output:** Preliminary report T = A_res(I; θ_res)
- **Equation:** `T = A_res(I; θ_res)`

### Stage 2: Retrieval-Augmented Report Revision (Fellow + Retrieval Agents)
- **Three retrieval paradigms from clinical database D:**
  1. **Image-to-Image:** 3D vision encoder retrieves visually similar CT volumes
  2. **Image-to-Text:** Same encoder retrieves corresponding reports
  3. **Logits-based:** Classification head atop A_res predicts 18 canonical clinical abnormalities (pleural effusion, atelectasis, etc.); logit vectors used to retrieve reports with similar diagnostic profiles
- **Retrieval output:** R = A_ret(I, D), top-3 cases per agent, concatenated as structured evidence
- **Revision:** Each Fellow Agent A_fel(i) refines draft by validating findings against R and resolving inconsistencies: T'_i = A_fel(i)(T, R)
- **Equation:** `T'_i = A_fel(i)(T, A_ret(I, D))`

### Stage 3: Consensus-Driven Finalization (Attending Agent orchestrating iterative multi-round discourse)
- **LLM Backbone:** GPT-4.1 for Fellow agents, GPT-4o for Attending agent, temperature=0 for determinism
- **Round 1 (Consensus Synthesis):**
  - Attending aggregates all fellows' refined reports into initial consensus T^(0): `T^(0) = A_att({T'_i}^N_i=1)`
  - Produces explicit feedback: key findings, diagnostic rationales tracing which fellow introduced each modification, and targeted guidance
- **Round t+1 (Iterative Refinement):**
  - Each fellow reviews current consensus T^(t) and provides stance S_i^(t): `S_i^(t) = A_fel(i)(T'_i, T^(t))`
  - Stance includes: agree/disagree, confidence (1-3), reasons, evidence citations
  - Attending adjudicates: `T^(t+1) = A_att(T^(t), {S_i^(t)}^N_i=1)`
- **Termination conditions (Attending determines):**
  1. All fellows agree → stop
  2. Disagreers not confident + no convincing evidence → stop
  3. Strong opposition with credible evidence → continue
  4. Majority disagree → continue
- Continues until consensus or max rounds T_max; case study shows convergence in 2 rounds

## 3. Trade-offs (Wins vs Loses)

| Dimension | Win | Cost/Loss |
|-----------|-----|-----------|
| **Clinical Fidelity (CE-F1)** | +57.6% over best baseline Reg2RG (0.253→0.399), +82% over Resident-only (0.219→0.399) | Requires GPT-4.1/GPT-4o API calls per round × N agents |
| **Linguistic Quality (BLEU-4)** | +3.2% over Reg2RG (0.249→0.257), marginal gains on NLG metrics | Diminishing beyond MR-MA; multi-round adds only +0.002 BLEU-4 over single-round multi-agent |
| **Rare Abnormality Detection** | Large gains on subtle/small findings (hiatal hernia, pericardial effusion) | Still reliant on retrieval DB coverage; no cold-start provision for novel findings |
| **Inference Cost** | 3 agents = good balance; 10 agents peak CE-F1 (0.337 on subset) | Cost scales O(N × rounds × API tokens); 20 agents degrade (CE-F1=0.327) due to discursive noise |
| **Interpretability** | Every modification traced to a specific fellow + evidence | Substantially more complex pipeline than single-model baselines |
| **LLM Portability** | Works across GPT-4.1-mini/4.1/4o/5 with narrow CE-F1 spread (0.391-0.399) | Not tested on open-weight LLMs (DeepSeek, Llama-3, etc.) |
| **Determinism** | temperature=0 ensures reproducibility | Loses sampling diversity; no ensemble-of-ensembles |

## 4. Design Rationale

**Core hypothesis:** Monolithic VLMs lack the iterative verification (overread, read-out sessions) that defines real radiology quality control. Rather than building a larger single model, MARCH explicitly models the clinical hierarchy (Resident → Fellow → Attending) as a multi-agent system.

**Why hierarchy over flat ensemble:** The staged design imposes clinical workflow constraints: (1) draft from images, (2) ground against evidence, (3) debate to consensus. A flat ensemble would average outputs without the adversarial stance-taking that catches subtle errors. The paper argues this aligns with how radiologists use "devil's advocate" roles in read-out sessions.

**Why retrieval-augmented revision:** Pure VLM generation hallucinates without grounding. Three complementary retrieval modalities (visual similarity, textual similarity, diagnostic logit similarity) maximize the chance of finding relevant precedents for any given finding. This diversifies the evidence base beyond what any single embedding space would capture.

**Why iterative consensus over single-round:** Single-round aggregation treats disagreements as noise to average out. Multi-round stance-based discourse forces fellows to reconcile contradictions with explicit evidence, mirroring clinical case conferences. The Attending's explicit reasoning trace and instruction feedback creates a structured learning signal that single-round approaches miss.

**Why 3 Fellow agents:** Ablation shows 5 agents peak linguistically, 10 peak clinically, but 3 offers the best cost/fidelity Pareto point for full-dataset experiments (1,564 test cases).

## 5. Limitations & Failure Modes

**1. No open-weight LLM validation.** All Fellow/Attending experiments use GPT-series models (4.1-mini, 4.1, 4o, 5). No results for open-source alternatives (Llama-3, DeepSeek, Qwen), so reproducibility outside OpenAI API is unknown.

**2. No long-term memory.** The framework operates on single-CT encounters. It lacks longitudinal patient history integration, cannot learn from prior errors across cases, and has no mechanism for accumulating institutional knowledge.

**3. No human-in-the-loop.** The system is fully autonomous. In real deployment, radiologists review and sign reports. The paper acknowledges this gap but does not evaluate hybrid configurations where agents provide preliminary consensus for human review.

**4. Single-dataset evaluation.** Only RadGenome-ChestCT tested. No cross-dataset generalization (e.g., MIMIC-CXR, CheXpert). 3D CT only — no 2D X-ray or MRI evaluation.

**5. Agent count sensitivity.** Performance degrades at 20 agents (CE-F1 drops from 0.337→0.327). The optimal count is dataset-specific and must be tuned per deployment. No theoretical framework for determing optimal N.

**6. Retrieval dependence.** Quality degrades if the retrieval database lacks relevant precedents for a rare condition. The three-modality approach mitigates but does not eliminate this.

**7. Cost scaling.** Each round requires N × API calls. The paper does not report latency or dollar cost, making practical deployment assessment difficult.

**8. No statistical significance testing.** Tables report raw metric values without confidence intervals, standard deviations, or significance tests against baselines.

## 6. Transfer to Lyra

### The ONE Transferable Idea
**Structured multi-agent hierarchy with iterative stance-based consensus.** MARCH demonstrates that decomposing a generation task into role-specialized agents (drafter, evidence-grounder, consensus-arbiter) with explicit agree/disagree/confidence/reason/evidence stances in iterative rounds produces higher-fidelity outputs than single-pass generation or flat ensembling. The key insight is that forcing agents to take EXPLICIT stances with confidence scores and evidence citations creates a structured adversarial dynamic that catches errors a monolithic model would miss.

### Workstream Route
**§4.2 (Multi-Agent Orchestration)** — This directly informs the architecture of Lyra's agent coordination layer. The stance-based consensus protocol (agree/disagree/confidence/reason/evidence) can replace simple voting in Lyra's agent ensembles. The three-layer hierarchy (drafter → retriever+reviewer → arbiter) maps cleanly to Lyra's existing agent roles.

### Impact/Effort/Tier Assessment
- **Impact: 4** — The stance-based consensus protocol meaningfully improves output quality (82% CE-F1 gain over single-agent). Adapting this pattern to Lyra's agent coordination could substantially reduce hallucination rates in multi-agent code generation and planning tasks.
- **Effort: 3** — Requires designing stance prompt templates, an Attending (arbiter) agent role, and consensus termination logic. The core mechanism (JSON-structured stances with agree/disagree/confidence/reason/evidence) is straightforward to implement. The retrieval component (Stage 2) can be deferred to a later iteration.
- **Tier: Breakthrough** — This is a paradigm-level idea (hierarchical medical workflow → general agent orchestration) with strong empirical backing and clear transferability to Lyra's core architecture. The 82% improvement magnitude justifies prioritization.
