**Venue:** arXiv preprint (2604.15710v1), 17 Apr 2026
**Institutions:** Zhejiang University, China University of Petroleum-Beijing at Karamay, Xiamen University

## 1. Mechanism (step-by-step)

The core is a **"Think-before-Speak"** (TbS) reasoning mechanism within an end-to-end speech agent, augmented by a **Multi-Agent Dynamic Tool Management** architecture for scalable tool use. The system state at time t: `S_t = (O_t, H_t, A_t)` where O_t = observations (user input + tool feedback), H_t = history, A_t = action space (verbal responses + tool subset).

### Step-by-step execution:

**Step 1: Reasoning Generation ("Think-before-Speak")**
Before producing any output or invoking tools, the speech model generates an explicit Chain-of-Thought (CoT) reasoning trajectory conditioned on the current observation, history, and local tool set:
```
c_t ~ pi_theta_think(c | o_t, H_{t-1}, T_t^local)
```
This forces the model to internalize intent understanding, contextual analysis, and task decomposition before acting.

**Step 2: First Action + Parallel Tool Retrieval**
After the reasoning trajectory is generated, two processes execute in parallel:
(a) The main agent samples its next action conditioned on the current local tool set: `a_t ~ pi_theta_act(a | c_t, o_t, H_{t-1}, T_t^local)`
(b) An auxiliary LLM proposes candidate tools from the global tool pool: `T_t^cand ~ pi_LLM(c_t, T^all)` — the auxiliary model searches the full pool using the reasoning trajectory as context.
```
(a_t, T_t^cand) ~ pi_theta_act(. | c_t, T_t^local), pi_LLM(c_t, T^all)
```

**Step 3: Dynamic Tool Space Update**
If the agent emits a `retrieve` action (`a_t = a_retrieve`), indicating local tools are insufficient, the candidate tools from the auxiliary LLM are incorporated:
```
T_{t+1}^local = T_t^local UNION T_t^cand
```
Otherwise, the local tool set remains unchanged. This decouples inference latency from global tool pool size.

**Step 4: Final Action**
At time t+1, the agent performs its final decision using the updated tool set:
```
a_{t+1} ~ pi_theta_act(a | c_{t+1}, o_{t+1}, H_t, T_{t+1}^local)
```

**Step 5: Side-by-side parallelism**
The auxiliary LLM's retrieval runs asynchronously alongside the main agent's next reasoning step. Since retrieval latency (1.3s-2.6s) is fully hidden by the reasoning + speech generation time, the waiting overhead is < 15ms (effectively O(1) with respect to tool pool size).

### Dataset Construction (AgentChat):
- **470-hour corpus**: 14,805 tool-interaction samples (109h) + 38,681 general dialogue samples (361h)
- Source: ToolACE + APIGen-MT (filtered), GSM8K, ARC, SciQ, self-built dialogues
- Text-to-speech synthesis via CosyVoice2 with 600+ SeedTTS timbres
- **Reverse CoT generation**: Given (Q, A), generate reasoning chain R ~ p_LM(R | Q, A)
- **Quality filter**: Score S(R) in [0,10], keep if >= 7, regenerate up to 3 times if below
- **Compression**: LLM-based refinement for conciseness

### Formal Agent Definition (4 dimensions):
1. **Profile**: P_static (timbre, gender, persona) + P_dynamic (context-driven tone/prosody)
2. **Memory**: Dual-channel — Semantic (M_sem) + Acoustic (M_acous); Short-Term + Long-Term
3. **Planning**: Must transform x -> z -> y (input -> reasoning -> output), not x -> y directly
4. **Action Execution**: Decision (evaluate if tool needed) then Selection+Invocation (choose tool t*, generate parameters)

## 3. Trade-offs

| Win | Loss |
|---|---|
| +113.79% task completion over base model (34.88 -> 74.57) | CoT reasoning adds ~88 tokens per turn (12.6% overhead in speech mode) |
| +3.06 points over Gemini-2.5-Pro | TTS-synthesized training data → real speech gap: -7.3% FS, -6.7% PF |
| Tool pool size decoupled from inference latency (O(1) overhead) | Auxiliary LLM adds 1.3-2.6s latency (but hidden in parallel) |
| General conversation quality preserved (64.21 vs 64.15 base) | Parameter filling remains modest (38-72% range across tasks) |
| Proactive seeking jumps from 3.12% (base) to 68.66% | Result Feedback remains low across all models (3.94% vs 4.22% GPT-4o) |
| Open-source (Apache 2.0, inferred from public release) | Requires H20-NVLink GPU hardware for training (DeepSpeed ZeRO-3) |
| Robust to disfluencies (86% FS on real speech) | AgentChat is synthesized from text corpora, not natively spoken — may encode written-language precision instead of spoken spontaneity |

## 4. Design Rationale

**Why Think-before-Speak instead of direct speech-to-action?**
The x -> y direct mapping fails for complex planning because speech tokens encode dense acoustic information that overwhelms reasoning capacity. Inserting an intermediate reasoning step z (x -> z -> y) forces the model to separate "understanding + planning" from "execution," as evidenced by the ablation: models without CoT cap at ~70.97 while CoT models reach 74.57, and more critically, CoT prevents catastrophic forgetting of general speech ability (VoiceBench: 54.80 without CoT vs 64.21 with CoT).

**Why multi-agent tool management instead of single-agent?**
A single agent processing all tool descriptions inline causes exponential latency growth with tool pool size (Fig 4a). The parallel auxiliary LLM offloads the retrieval problem to a model aligned with the reasoning trajectory, decoupling execution from scale. This is essentially a token-level search delegation pattern: the speech model stays focused on reasoning, while retrieval happens asynchronously.

**Why reverse CoT generation (Q, A -> R) instead of forward?**
Forward generation (Q -> R -> A) would require the speech model to produce high-quality reasoning during data creation, which it cannot do reliably without training. Reverse generation lets a strong text LLM (Qwen-plus) construct bridges between known inputs and outputs, then the speech model learns the mapping during supervised training.

## 5. Limitations & Failure Modes

1. **CoT latency trade-off (acknowledged)**: Think-before-Speak inherently adds reasoning latency before any verbal response — the authors call this a "necessary trade-off for correctness" but note it as an optimization target.

2. **Dataset is synthesized from text corpora**: AgentChat derives reasoning traces from text datasets (ToolACE, APIGen-MT) synthesized via TTS. Despite rigorous filtering, the semantic structure encodes written-language precision rather than the spontaneity, disfluencies, and acoustic pragmatics of natural speech. The -7.3% drop on real speech confirms a domain gap.

3. **Parameter filling ceiling**: Even VoxMind only achieves 38.10% on Task Decomposition PF and 61.59% on Parallel Processing PF — parameter instantiation from spoken context remains a hard problem, likely because acoustic encoders lose fine-grained parameter details.

4. **Result Feedback near-zero**: All models score <5% on FC (feedback completeness), including Gemini-2.5-Pro (4.16%). This metric evaluates accurate perception and summarization of tool execution results — none of the current architectures handle this well.

5. **Hardware requirements**: Training requires 2x H20-NVLink GPUs with DeepSpeed ZeRO-3, bfloat16, and gradient checkpointing — not accessible to most researchers.

6. **Tool dependency on auxiliary LLM**: If the auxiliary LLM proposes incorrect tools or fails to retrieve relevant tools, the agent's action space is limited. No ablation on auxiliary LLM quality was provided.

7. **Limited real-speech evaluation**: Only 150 real-speech utterances tested; the robustness study covers stutters, hesitations, and noise but not code-switching, accents, or open-domain conversations.

8. **Definition-first but evaluation-second**: The paper proposes a formal 4-dimensional definition of spoken agents but does not evaluate all four dimensions (Profile and Memory are not benchmarked).

## 6. Transfer to Lyra

**The One Transferable Idea:**
The **asynchronous tool space management via auxiliary LLM** pattern (equations 4-6 in Section 3.2). Rather than having the main agent process all available tools inline — which causes exponential latency growth — delegate tool retrieval to a lightweight auxiliary model that runs in parallel, conditionally expanding the action space only when the main agent detects tool insufficiency via an explicit `retrieve` action. The auxiliary model's latency is fully hidden within the main agent's reasoning and generation time, achieving O(1) latency with respect to tool pool size. This directly applies to Lyra's plugin/router subsystem: instead of the Router evaluating all M plugins per turn, a smaller "tool scout" model asynchronously prunes the plugin pool to top-K candidates, and the Router only expands to new plugins when it emits a retrieval signal. The dynamic local tool set (Eq. 5: `T_{t+1}^local = T_t^local UNION T_t^cand`) maps cleanly to Lyra's context window management.

**Workstream Route:** §4.5 — Router/Plugin Architecture (dynamic tool selection and action space management)

**Impact:** 4 (directly solves the plugin-scale latency problem; the parallel delegation pattern is concretely portable)

**Effort:** 3 (requires an auxiliary inference pass and a retrieval-action classifier, but no new model training — can use existing lightweight LLM)

**Tier:** investigate (the pattern is compelling but needs prototyping against Lyra's specific plugin dispatch latency profile; the speech-domain results may not directly transfer to text-only latency regimes where reasoning tokens are far fewer)
