## 1. Mechanism (step-by-step)

AnnaAgent is a multi-agent system that controls a seeker-simulator CA through two parallel agent groups. The seeker simulator is an LLM instantiated with a role-configuration prompt containing reserved slots for dynamic fields (emotion, complaint, situation, status). Two agent groups fill those slots at each turn.

### 1.1 Dynamic Evolution Group (within-session)

**Emotion Modulation** has two sub-components:

*Emotion Inferencer (M^e_k):*
1. Train a Qwen2.5-7B-Instruct model on the D4 real-counseling dataset. Each instance is sampled 5x with random conversation-length cuts (last utterance always from seeker).
2. Label the last utterance's emotion using GPT-4o against GoEmotions taxonomy (27 fine-grained emotions).
3. Delete the last utterance from each instance; train the model to predict the emotion of that held-out utterance given the seeker's profile cfg_c and conversation history conv_c.

Equation (1): `emo_k = M^e_k(cfg_c, conv_c)` — predict the emotion of the 2k-th utterance (seeker's next turn) from profile and existing conversation.

*Emotion Perturber:*
4. Group GoEmotions labels from positive to negative. Define distance d(G_T, G_B) between groups (0 = same group, 1 = adjacent, etc.).
5. Assign weighted probabilities to candidate target emotions by Equation (2):
   ```
   P(emo_T) = w(d(G_T, G_B) × |G_T|) / Σ_{G_j} w(d(G_B, G_j)) × |G_j|
   ```
   Closer emotion groups get higher probability weight.
6. Sample the final emotion from this distribution — adds stochastic volatility to prevent rigid patterns.

**Chief Complaint Elicitor:**
7. Train a complaint-chain generator (gen_chain) on D4 + GPT-4o annotations, then review with 3 psychology experts (mark unreasonable chains; correct if ≥2 annotators flag).
8. Before session: generate chain = {stage_1, stage_2, ..., stage_l} from seeker profile + recent events.
9. Initialize complaint = chain[0].
10. At each turn, run Algorithm 1:
    - For each utterance in conv_c: call IsRecognized(utterance, complaint) to check if the current complaint stage has been acknowledged by the counselor.
    - If recognized, advance index++; complaint = chain[index] (or chain[-1] if exhausted).
    - Return the complaint to fill the configuration slot.

11. After each dialogue round, inject a **reminder** into the seeker prompt: "The current emotional state is: {emotion}, the current chief complaint is: {complaint}, and the information involving previous sessions is: {sup_information}."

### 1.2 Tertiary Memory System (across-session)

Three memory tiers modeled after cognitive psychology (Loftus & Loftus, 2019):

| Tier | Content | Mechanism |
|------|---------|-----------|
| **Real-time** | Current session conv_c | Full context input |
| **Short-term** | Status changes (self-report scales: SCL-90, BDI, SAAS) + recent triggering events | Summarized into `situation` and `status` slots before each session; events sampled from CBT Triggering Events dataset matched on age/gender/job/relationship |
| **Long-term** | Previous session conversations + scale records | Agentic RAG: a **Querier** agent checks after each round whether the topic involves prior sessions; if yes, a **Summarizer** retrieves relevant content as supplementary info |

### 1.3 Overall Control Flow

```
Initialization:
  - Load static profile (age, gender, occupation, etc.)
  - Generate complaint chain via gen_chain
  - Populate short-term memory (scales + recent events)
  - Set initial emotion via Emotion Inferencer

Per-turn loop (after counselor utterance):
  1. Emotion Inferencer predicts next emotion from cfg + conv
  2. Emotion Perturber adds stochastic perturbation
  3. Complaint Elicitor checks if stage should advance
  4. Querier checks if long-term memory is needed
  5. Reminder template injected with {emotion, complaint, sup_info}
  6. Seeker LLM generates response
```

## 3. Trade-offs

| Win | Lose |
|-----|------|
| Realistic emotional volatility via learned inference + stochastic perturbation — avoids flat/static emotions of prior simulators | Requires fine-tuning a 7B model for emotion inference and another for complaint chain generation (compute cost) |
| Coherent multi-session memory — querier retrieves relevant prior-session info on demand, avoiding hallucinatory responses | Multi-agent architecture adds latency: at each turn, 3-4 agent calls (inferencer, perturber, elicitor, querier) before the main LLM generates |
| Strong generalization across backbone models (RSD < 10%) — not locked to one LLM family | Expert review bottleneck: complaint chains need 3 psychology experts to annotate/review — hard to scale to new domains |
| Works on both Chinese (D4) and English (DAIC-WOZ) datasets | Simplified modeling of clinical dynamics (authors acknowledge "formally simplified for technical ease") |
| Ablation-confirmed necessity of each component | Long-term memory via Agentic RAG is described as "rudimentary" — may miss subtle cross-session references |
| Ethical review board oversight for responsible deployment | Privacy risk: trained on real patient data from D4; full open-source blocked |

## 4. Design Rationale

The authors, guided by licensed counselors, identify that real seekers exhibit (a) pronounced emotional fluctuations during a single session and (b) progressive shifts in how they understand their "chief complaints." Prior simulators use static prompts that lock emotions at initial values, producing flat, unchanging responses. Separately, real counseling is multi-session — counselors reference prior sessions — but prior simulators have no memory, causing hallucinatory confusion when prior topics arise.

The dual-agent-group architecture separates concerns: **dynamic evolution** handles within-session state changes (real-time, turn-level), while **tertiary memory** handles across-session knowledge (session-level). The emotion perturber is justified because a single-source training dataset (D4) would produce overly rigid emotional patterns; stochastic perturbation introduces natural volatility. Tertiary memory tiers follow established cognitive psychology theory (Loftus & Loftus, 2019) and Agentic RAG is chosen over simple retrieval to avoid polluting every turn with irrelevant prior-session context.

## 5. Limitations & Failure Modes

1. **Simplified clinical modeling:** Dynamics are "formally simplified for technical ease" — real clinical emotional/cognitive evolution is more complex than a linear complaint chain with distance-weighted emotion perturbation.
2. **Rudimentary long-term memory:** The Agentic RAG querier makes a binary decision per turn (relevant/not relevant) and may miss nuanced cross-session connections, compounding errors, or implicit therapeutic progress tracking.
3. **Not a substitute for real seekers:** Psychological experiments conducted with AnnaAgent may not replicate real phenomena; using AnnaAgent conversations to evaluate counselor capability could be misleading.
4. **Privacy leakage risk:** Emotion modulator and complaint elicitor are trained on D4, which contains real patient data. Full open-source release is blocked — only synthesized conversations and processing code are released.
5. **Domain specificity:** System is tightly coupled to psychological counseling (GoEmotions taxonomy, complaint chains, self-report scales). Transfer to other domains would require re-engineering the state space and retraining models.
6. **Text-only:** No multimodal (voice tone, facial expression, body language) modeling, which are important affect channels in real counseling.
7. **Chinese-centric:** D4 is a Chinese dataset; DAIC-WOZ evaluation is secondary. Cross-cultural generalization not deeply tested.
8. **No adversarial evaluation:** Paper does not test whether the simulator can be jailbroken or induced to produce harmful outputs.

## 6. Transfer to Lyra

### The One Idea

**Turn-level dynamic state modulation with tiered (real-time/short-term/long-term) memory retrieval.** AnnaAgent demonstrates that injecting a dynamically updated "state reminder" (emotion + complaint + memory supplements) at each turn, produced by dedicated lightweight models/agents, substantially improves realism and coherence. For Lyra, this pattern translates to: separate the agent's "current operating mode/goal" from the conversation context, update it at each turn via a cheap classifier/retriever, and manage cross-session context through a three-tier memory system where a querier decides *if* long-term memory is needed before retrieving it (avoiding context pollution).

### Workstream Route

**§4.2 — Memory & Context.** The tertiary memory architecture (real-time context window, short-term summarized state, long-term RAG-retrieved history) directly informs Lyra's multi-session memory design. The querier pattern (decide *whether* to retrieve before *what* to retrieve) is a key optimization for context budget management.
