## 1. Mechanism (step-by-step)

IterResearch reformulates deep-research agents as an **MDP with iterative workspace reconstruction**, replacing the standard mono-contextual paradigm where all retrieved information and reasoning steps accumulate linearly in one context window.

### 1.1 MDP Formulation

The system is defined by the tuple `⟨S, D, E, T, R⟩`:

**State Space S:** Each state `s_t = (q, M_t, {a_{t-1}, TR_{t-1}})` is a bounded workspace containing:
- `q`: the original question (constant)
- `M_t`: an **evolving report** acting as compressed memory of prior validated findings
- `{a_{t-1}, TR_{t-1}}`: the immediate context from the previous step only

**Decision Space D:** At each state, the policy π generates a structured composite decision:
```
d_t = [Think_t, M_{t+1}, a_t] ~ π(·|s_t)
```
Consisting of:
- `Think_t`: internal reasoning (Chain-of-Thought)
- `M_{t+1}`: an **updated report** synthesizing new findings with prior memory
- `a_t`: external action (tool call or final answer)

**Environment E and Reward R:** The environment executes `a_t` and returns `TR_t ~ E(·|a_t)`. The terminal reward `R_T ∈ {0, 1}` is 1 iff the answer is correct (LLM-as-judge).

**Transition Function T (THE KEY INNOVATION):**
```
s_{t+1} = T(s_t, d_t, TR_t) = (q, M_{t+1}, {a_t, TR_t})
```
This **reconstructs** the workspace rather than appending to history. The full trajectory `(s_0, d_0, TR_0, ..., s_{t-1}, d_{t-1}, TR_{t-1})` is deliberately discarded — only the synthesized report `M_{t+1}` persists. This is **strategic forgetting**.

**Critical consequence:** `|s_t| ≈ O(1)` constant workspace vs. mono-contextual `|s_t| ∝ t` linear growth.

### 1.2 Algorithm (from Algorithm 1 in paper)

```
Input: Question q, Agent π, Environment E, Max rounds T_max
 1: M_0 ← ∅, s_0 ← (q, M_0, ∅), t ← 0
 2: while t < T_max do
 3:   d_t ← π(s_t)                    # Generate structured decision
 4:   Parse: (Think_t, M_{t+1}, a_t) ← d_t
 5:   if a_t = answer then break      # Agent determines sufficiency
 6:   TR_t ← E(a_t)                   # Execute tool, get response
 7:   s_{t+1} ← (q, M_{t+1}, {a_t, TR_t})  # Reconstruct workspace
 8:   t ← t+1
 9: return final answer
```

### 1.3 Efficiency-Aware Policy Optimization (EAPO)

**Discounted Reward Shaping (Eq. 5):**
```
r_t = γ^{T-t} · R_T,   γ ∈ (0, 1), typically γ = 0.995
```
Geometric discounting from the terminal step backward. Trajectories reaching correct answers in fewer steps receive exponentially higher intermediate rewards. A 5-step trajectory gives step-3 reward `r_3 = γ^2 ≈ 0.990`; a 20-step trajectory gives step-3 reward `r_3 = γ^17 ≈ 0.918` — a 7.8% penalty for the same step position.

**Policy Optimization (Eq. 7):** Uses Group Sequence Policy Optimization (GSPO) variant:
```
J(θ) = E_{q~Q, C_train~π_old} [ 1/|C_train| * Σ_i Σ_t min(ρ_{i,t}(θ)·Â_{i,t}, clip(ρ_{i,t}(θ), 1-ε, 1+ε)·Â_{i,t}) ]
```
Where all rounds from G trajectories for a question form one group, with advantages normalized across samples within the group.

**Adaptive Downsampling (Eq. 6):** Training corpus is truncated to the largest multiple of data-parallel size:
```
|C_train| = floor(|C| / DP_size) × DP_size
```
Typically <1% data loss while ensuring stable distributed training.

### 1.4 Training Pipeline

Two-stage process:
- **Stage 1 (SFT):** 30K QA pairs → synthesized into 110K trajectories using Qwen3-235B-A22B (avg 3.7 rounds/trajectory). Trained on Qwen3-30B-A3B backbone, 3 epochs, LR=1e-5, max context 40,960 tokens.
- **Stage 2 (RL):** 4,096 questions selected via difficulty calibration (20-60% success rate = "zone of proximal development"). 16 rollouts per question, G=16 group size, LR=1e-6, T_max=32 during training.

### 1.5 Tool Environment

Four tools via production APIs:
- **Google Search** (SerpAPI): top-10 results, batched multi-query
- **Google Scholar** (SerpAPI): academic papers with citations, metadata
- **Visit/Web Browser** (Jina Reader): URL content extraction with goal-oriented summarization, HTML + PDF support
- **Python Interpreter** (SandboxFusion by ByteDance): secure sandboxed execution

## 3. Trade-offs (wins vs loses)

| Aspect | Win | Cost/Loss |
|--------|-----|-----------|
| **Context scaling** | O(1) constant workspace vs O(t) linear | Requires LLM to reliably compress findings into report — imperfect compression loses information |
| **Interaction depth** | Theoretically unbounded (validated to 2048) | Training only at T_max=32; relies on extrapolation |
| **Noise resistance** | Strategic forgetting prevents cascading errors | Wrong early conclusions that get embedded in M_t are hard to correct later |
| **Efficiency** | 5.7% fewer turns via EAPO discounting | γ=0.995 is a hyperparameter that may need per-task tuning |
| **Training data** | 110K SFT trajectories from 30K QA pairs | Requires expensive trajectory synthesis (Qwen3-235B for rollouts) |
| **Cross-paradigm transfer** | IterResearch trajectories improve Mono-Agent by +5.4pp | Mono-Agent still inferior to full IterResearch (-7.2pp avg) |
| **Prompt-only use** | Up to +19.2pp on frontier models without training | Prompt complexity and format constraints increase cognitive load |
| **Computational complexity** | Attention O((|M|+|TR|)^2) constant per round vs O((t·|TR|)^2) growing | Per-round cost can be higher for short trajectories where mono-contextual is still small |
| **Implementation complexity** | Clean MDP formalism, simple algorithm | Requires structured output format (report + action), tool environment integration, distributed RL infrastructure |

## 4. Design Rationale

**Why MDP + workspace reconstruction over mono-contextual accumulation?**

The authors identify two fundamental failure modes of mono-contextual approaches:
1. **Context suffocation:** As retrieved info and reasoning steps fill the context window, remaining space for new reasoning shrinks to zero, forcing premature termination.
2. **Noise contamination:** Irrelevant search results and early exploratory errors become permanently embedded, creating cascading interference.

Their key insight is that **effective long-horizon research requires periodic synthesis and strategic forgetting** — capabilities absent from linear-accumulation designs. The MDP formalism enforces the Markov property: future decisions depend only on the current synthesized state, not the full history.

**Why geometric discounting (EAPO) over flat terminal rewards?**

Standard RL for deep research uses sparse binary rewards that treat all successful trajectories equally. The authors argue this is wasteful: a 5-step solution should be preferred over a 20-step one for the same result. Geometric discounting `r_t = γ^{T-t} · R_T` creates implicit efficiency pressure without any auxiliary loss or explicit length penalty. It emerges naturally from the MDP formulation.

**Why γ = 0.995?**

Balances exploration thoroughness vs. efficiency. Values closer to 1 allow more exploration; smaller values create stronger efficiency pressure. The 5.7% trajectory length reduction validates the choice.

**Why train at T_max=32 but evaluate at 2048?**

Deliberate constraint creates pressure for concise strategies during training. The position-agnostic state design and bounded report complexity enable extrapolation — the state distribution remains stable regardless of trajectory length.

**Why the report-as-memory design?**

Unlike explicit vector databases or separate memory modules, the report leverages the LLM's inherent synthesis capabilities. Memory evolution is intrinsically aligned with the research trajectory rather than requiring separate management overhead. The authors explicitly contrast this with MemAgent, MemOS, Memory-R1, etc.

## 5. Limitations & Failure Modes

1. **Report compression fidelity:** The evolving report `M_t` is the sole carrier of historical information. If the agent fails to include a critical finding or misrepresents it, that information is permanently lost — there is no fallback to raw history. The paper does not study report degradation or information loss rates.

2. **Early error lock-in:** If the agent makes a reasoning error or draws a wrong conclusion early, and this gets incorporated into the report, subsequent rounds may build on faulty premises with no mechanism for correction.

3. **Extrapolation gap:** Training at T_max=32 to inference at 2048 is a 64x extrapolation. While empirically successful, the paper does not analyze failure cases at extreme depths or whether report quality degrades over very long trajectories.

4. **Training data dependency:** The SFT phase relies on Qwen3-235B-A22B for trajectory synthesis. Performance may be bounded by the teacher model's capabilities. Generalizability to other backbone models is not extensively studied (only Qwen3-30B-A3B reported).

5. **LLM-as-judge reward:** Terminal reward uses Qwen3-235B-A22B as judge, which may introduce systematic biases or miss nuanced correctness.

6. **Limited benchmark diversity:** Results are on 6 English/Chinese web-research benchmarks. No evaluation on code generation, mathematical theorem proving, or multi-modal tasks.

7. **No explicit safety/misuse analysis:** The paper does not discuss risks of autonomous deep-research agents operating at unbounded depths (e.g., generating misleading reports, accessing harmful content, or running up API costs).

8. **γ sensitivity:** The efficiency-vs-thoroughness trade-off is controlled by a single hyperparameter γ. No sensitivity analysis is provided for different γ values.

## 6. Transfer to Lyra

### The One Transferable Idea

**Iterative workspace reconstruction with evolving report memory (the `s_t = (q, M_t, {a_{t-1}, TR_{t-1}})` pattern).** Lyra should adopt this bounded-context MDP architecture for its agent loop, replacing any long-accumulation context pattern. Instead of concatenating all prior tool calls and responses indefinitely, Lyra would maintain an evolving "research state" report that the agent updates each round, with only the question, current report, and immediate last interaction in context. This directly addresses context window exhaustion in long multi-turn Lyra sessions and enables theoretically unbounded agent depth.

### Workstream Route

**§4.2 (Memory Architecture)** — This is a memory/context management innovation. The evolving report `M_t` is a form of learned, compressed, task-focused memory. It complements the existing memory workstream plans (plans/02-memory.md, brainstorm/02-memory.md).

### Scoring

- **Impact:** 5 — Directly addresses the #1 failure mode of long-running Lyra agents (context exhaustion). Enables unbounded session depth. The prompt-only variant means even untrained Lyra could benefit immediately.
- **Effort:** 3 — Requires: (1) restructuring agent loop to MDP-like state transitions, (2) designing report synthesis prompts, (3) implementing workspace reconstruction logic. Moderate engineering, no training required for prompt-only variant.
- **Tier:** **Breakthrough** — This is a paradigm-level architectural change with validated +14.5pp gains across 6 benchmarks, interactive scaling to 2048 turns, and model-agnostic applicability. The independent convergent evolution noted with AlphaEvolve further validates this as a general solution pattern for long-horizon AI.
