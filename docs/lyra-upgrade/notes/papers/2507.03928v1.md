## 1. Mechanism (step-by-step)

CortexDebate improves Multi-Agent Debate (MAD) by replacing the fully-connected debate graph with a **sparse, dynamically-optimized directed graph**, inspired by how the human brain's cortical areas form sparse networks governed by white matter.

### Phase 1: Initial Answer Generation

Each of `n` LLM agents independently generates an initial answer `Oi^0` and self-confidence score `Hi^0` (0-1) for a given question Q.

**Confidence Recalibration** — To mitigate overconfidence, raw confidence scores are clipped using a threshold function:

```
H_i = 0.8 if Hi^0 >= 0.8
      0.6 if 0.6 <= Hi^0 < 0.8
      Hi^0 if 0.3 <= Hi^0 < 0.6
      0.3 if Hi^0 < 0.3
```

**Credibility Initialization** — Each agent's credibility `C_i` is computed once using the Hoffmann scaling law:

```
L(N, M) = (406.4 / N^0.28) + (410.7 / M^0.28) + 1.69
C_i = 1 / L(N, M)
```

where N = parameter count, M = pre-training tokens, L = pre-training loss.

### Phase 2: Multi-round Debate (D rounds, 4 steps per round)

#### Step 1: Edge Weight Optimization (MDM Module)

The **McKinsey-based Debate Matter (MDM)** module computes each directed edge weight `Wi→j^d` — the expected improvement of agent Aj by debating with agent Ai — using the **McKinsey Trust Formula** from sociology:

```
T = (C × R × I) / S
```

Adapted to MAD context, for edge Ei→j in round d:

| Factor | Name | Meaning in MAD | Equation |
|--------|------|----------------|----------|
| C | Credibility | Professional competence of Ai | `C_i = 1 / L(N_i, M_i)` (pre-computed) |
| R | Reliability | Rolling avg of Ai's self-confidence | `R^d = (R^{d-1} × (d-1) + H_i^{d-1}) / d` |
| I | Intimacy | Avg viewpoint difference between Ai and Aj | `Sim^d = rolling_avg(cos(O_i, O_j))` then `I^d = 1 - Sim^d` |
| S | Self-orientation | Lack of participation (higher = more selfish) | `S^d = (d-1) × (n-1) - P^d` where P^d = times Ai debated others |

Final edge weight:

```
Wi→j^d = (C_i × R_i^d × I_i→j^d) / S_i^d
```

#### Step 2: Sparse Graph Establishment

For each agent Aj, compute the **average incoming edge weight**:

```
W̄_j^d = (1/(n-1)) × Σ_{i≠j} Wi→j^d
```

Then **binary pruning**:

```
Wi→j^d = 1  if Wi→j^d >= W̄_j^d
          0  otherwise
```

Agent Aj's debating opponents: `Deb_j^d = {Ai | Wi→j^d = 1, i ≠ j}`

Only answers from agents in `Deb_j^d` are fed to Aj.

#### Step 3: Answer Regeneration

Each Aj receives answers `{Ok^{d-1}}` from its debate set, then regenerates its answer `Oj^d` and confidence `Hj^d`.

#### Step 4: Debate Termination

The debate terminates when **all agents reach consensus** on the same answer, or when max rounds D is reached (D=5 in experiments).

### Phase 3: Final Answer Generation

Majority voting across all final-round answers:

```
O_final = argmax_o Σ_i 1(O_i = o)
```

If all answers differ, the result is treated as **incorrect** (no fallback).

### Algorithm Summary (from Algorithm 1 in paper)

```
Input: n agents, question Q, max rounds D
Output: Final answer O_final

1. For each agent: generate O_i^0, H_i^0 (Phase 1)
2. For d = 1 to D: (Phase 2)
   a. Compute Wi→j^d for all edges (Step 1: MDM)
   b. Keep edges with Wi→j^d >= W̄_j^d (Step 2: Sparse graph)
   c. Each agent regenerates answer from debate set (Step 3)
   d. If consensus → break (Step 4)
3. Return majority vote (Phase 3)
```

**Key computational characteristics**:
- O(n^2) edge weight calculations per round
- Requires cosine similarity computation on text embeddings (uses OpenAI text-embedding-3-large)
- Requires model scaling-law parameters (N, M, pre-training loss)
- Binary adjacency matrix after pruning

## 3. Trade-offs (wins vs loses)

| Dimension | Win | Lose |
|-----------|-----|------|
| **Accuracy** | +2.33 to +5.33 pp across all 8 datasets vs best baselines | — |
| **Context Length** | 50-83% reduction in input tokens per agent | Requires extra computation for edge weights (O(n^2) per round) |
| **Scalability** | Performance improves as agent count and rounds increase (tested up to 25 agents × 5 rounds shown in heatmap, best at 25 agents) | Larger n increases O(n^2) MDM overhead |
| **Debate Equality** | Prevents overconfident agents from dominating; consensus proportion grows naturally (51.75%→95.50%) vs PRD's premature consensus | Lower initial consensus rate (rounds 1-2) means more agents must run longer |
| **Computational Cost** | Context savings reduce per-agent generation cost | Multi-agent inherently more expensive than single-agent; requires external embedding model |
| **Pretraining Data Dependency** | Credibility uses well-established scaling law (Hoffmann et al.) | Requires knowledge of model architecture parameters (N, M) and pretraining loss — unavailable for many API-only models |
| **Robustness** | Confidence recalibration thresholds are insensitive to configuration (0.2% variance across settings) | Binary pruning (above/below average) may discard marginally useful edges |
| **Generalization** | Validated on math, QA, reasoning, and long-context tasks | Only tested with 7-9B open-weight models; effectiveness on frontier-scale models unknown |

## 4. Design Rationale (why this approach)

**Problem framing**: Existing MAD methods suffer two failures: (1) **context bloat** — fully-connected graphs cause each agent to process all others' outputs, which degrades performance due to the "Lost in the Middle" effect (Liu et al., 2024a); (2) **overconfidence dominance** — self-confidence-weighted debate lets overconfident agents monopolize, suppressing diverse viewpoints.

**Neuroscience inspiration**: The human brain cortex establishes a *sparse, dynamic network* among cortical areas, optimized by *white matter* that governs edge-level influence rather than node-level performance alone (Thiebaut de Schotten & Forkel, 2022).

**Why McKinsey Trust Formula**: The formula `T = (C × R × I) / S` balances four dimensions:
- C and R assess individual competence (credibility + reliability of track record)
- I and S assess collaborative value (viewpoint diversity contribution + participation level)

This naturally maps to the debate setting where both individual reasoning quality AND contribution to collective reasoning matter. Prior methods (self-evaluation = RECONCILE, peer review = PRD) only capture individual competence (C/R) but miss the collaborative dimensions (I/S). The ablation confirms that removing I and S drops average score from 69.41% to 66.69%.

**Why sparse rather than fixed groups**: GroupDebate and Neighbor Debate use fixed debate groups — but optimal opponents depend on the *specific question and round*. Dynamic graph optimization per round adapts to which agents are proving most useful.

**Why binary pruning (not weighted attention)**: The authors use threshold-based binary pruning (above/below mean → keep/discard) rather than weighted aggregation. This is a design choice for interpretability and strict context reduction — a weighted approach would still require processing all inputs.

## 5. Limitations & Failure Modes

1. **Multi-agent efficiency tax** (acknowledged): Even with context reduction, multi-agent debate is inherently slower and costlier than single-agent approaches. Not suitable for latency-sensitive applications.

2. **Bottlenecked by base model reasoning**: "Mistakes may still occur due to the poor reasoning ability of LLM agents." If all agents make the same systematic error, consensus will reinforce it — the method has no external ground-truth verification.

3. **Only tested on 7-9B models**: No experiments with frontier models (GPT-4, Claude, Gemini). Unknown whether sparse debate helps when base reasoning is already very strong.

4. **Requires model metadata**: Credibility calculation needs parameter count (N), pretraining tokens (M), and pretraining loss — unavailable for proprietary models (GPT-4, Claude).

5. **External embedding dependency**: Cosine similarity uses OpenAI's text-embedding-3-large, adding API latency and cost. LLM-based similarity (R1-P) was tried but showed higher variance across runs.

6. **Heuristic threshold**: Average-based edge pruning has no theoretical optimality guarantee. The paper tests Top-3, Bot-3, and median alternatives but does not explore learned thresholds.

7. **Binary consensus check**: If all final answers differ, the result is treated as incorrect with no fallback — this is a hard failure mode.

8. **No adversarial evaluation**: All evaluations are on standard benchmarks. No testing against adversarial agents or strategic manipulation during debate.

## 6. Transfer to Lyra

### The One Idea

**Dynamically pruned multi-agent communication topology using trust-weighted edge evaluation.** Instead of Lyra's sub-agents exchanging full outputs with all peers during consensus/verification phases, maintain a directed trust graph where each agent `Aj` only receives inputs from agents `Ai` whose expected contribution (credibility × reliability × viewpoint-diversity ÷ self-orientation) exceeds a dynamic threshold. This simultaneously reduces context bloat and mitigates overconfident-agent dominance.

### Lyra Workstream Route

**§4.2 — Multi-Agent Coordination and Consensus** (primary). CortexDebate directly addresses how Lyra's sub-agent ensemble (e.g., during critique, verification, or debate phases) should selectively route information rather than broadcasting everything to every agent. The sparse debate graph concept could also inform **§4.7 — Context Management** since the core problem solved (Lost-in-the-Middle from excessive agent-to-agent context) is a context engineering challenge.

### Scoring

| Dimension | Score | Rationale |
|-----------|-------|-----------|
| **Impact** | 4/5 | Directly improves multi-agent decision quality while reducing token cost; applicable to any Lyra sub-agent ensemble |
| **Effort** | 3/5 | Requires implementing trust-weight tracking, cosine similarity computation, and graph pruning logic per round — moderate but well-specified by Algorithm 1 |
| **Tier** | **breakthrough** | Novel mechanism (McKinsey Trust Formula adapted to LLM agents) with strong empirical gains across diverse tasks; no known implementation in agent frameworks |

### Adaptation Notes for Lyra

- Replace credibility factor (Hoffmann scaling law) with Lyra-specific metrics (agent success rate on past tasks, reliability score from verification runs)
- Intimacy (viewpoint diversity) maps naturally to Lyra's ensemble diversity — encourage agents with different approaches to debate
- Self-orientation penalizes free-riders; in Lyra, this could track which agents actually contributed useful critiques
- The sparse graph concept could be applied selectively: full communication for safety-critical phases, sparse for routine consensus
- The binary pruning approach (above/below mean threshold) is simple to implement and tune; start there before exploring learned thresholds
