## 1. Mechanism (step-by-step)

AutoResearchClaw is a **23-stage pipeline** organized into three phases, unified by five interacting mechanisms. The full pipeline is formalized in Algorithm 1 (reproduced below from the paper):

**Three pipeline phases:**

| Phase | Stages | Key Operations |
|-------|--------|----------------|
| **Discovery** | 1–8 | Topic scoping, problem decomposition, literature search/collection/screening, knowledge extraction, gap synthesis, multi-agent hypothesis generation |
| **Experimentation** | 9–15 | Experiment design (YAML), cascading code generation, resource planning, sandboxed execution, iterative refinement (self-healing), result analysis with debate, Proceed/Refine/Pivot decision |
| **Writing + Verification** | 16–23 | Paper outline, draft with verified-registry tables, multi-agent peer review, revision, quality gate, knowledge archive, export/publish, citation verification |

**Five mechanisms (spanning all phases):**

**(A) Multi-Agent Debate (K=3 agents, two stages):**
- **Hypothesis-stage (Stage 8):** Innovator proposes high-risk hypotheses; Pragmatist evaluates feasibility against hardware/time budgets; Contrarian actively seeks weaknesses and confounds. A Synthesizer integrates outputs into 2–4 falsifiable hypotheses annotated with testability criteria.
- **Result-stage (Stage 14):** Optimist surfaces strong findings; Skeptic challenges statistical significance and flags confounds; Methodologist evaluates reproducibility and checks for data leakage. The Synthesizer produces a structured assessment distinguishing supported from unsupported claims.
- K=3 was ablated: K=2 degenerates into pro/con (−23% diversity); K=5 raises tokens +67% for only +8% diversity gain.

**(B) Self-Healing Execution with Pivot/Refine Loop:**
- **Cascading code generation:** A complexity scoring function rates each experiment along 6 dimensions (architectural depth, file count, domain difficulty, dependency chains, historical failure rate, control-flow complexity), producing `c ∈ [0,1]`. Experiments with `c > τ` (τ=0.6) are dispatched to an external AI coding agent ("Beast Mode"); simpler ones use a built-in multi-phase code agent that emits per-file blueprints then generates files in dependency order with AST-derived summaries for cross-file consistency.
- **Static validation gates** check for identical ablation implementations and hardcoded metric values before any execution budget is spent.
- **Sandboxed execution:** Docker containers with three-phase network isolation — Phase 0: network for dependency install; Phase 1: network for data acquisition; Phase 2: network disabled entirely during experiment execution. Metric reporting is through a read-only evaluation harness.
- **Pivot/Refine/Proceed decision (Stage 15):** After a failure, the system captures the failure signature, generates targeted fixes, then decides: **Proceed** (evidence supports hypothesis), **Refine** (adjust current experiment, up to N_r=10 times), or **Pivot** (return to hypothesis generation with failure recorded as evidence, up to N_p=2 times).

**(C) Verifiable Result Reporting:**
- **Numeric registry:** A whitelist of every value produced by experiment runs (per-condition means, SDs, individual seed measurements). Pre-built LaTeX tables populated exclusively from the registry are injected into draft prompts. Post-hoc verifier re-extracts every numeric claim and checks against registry; claims in strict sections (Abstract, Results, Experiments) that cannot be matched trigger document rejection.
- **Citation verification:** Four-layer pipeline — CrossRef DOI resolution → OpenAlex fuzzy title matching → arXiv identifier lookup → Semantic Scholar fallback. LLM relevance check classifies each reference as Verified/Suspicious/Hallucinated. Hallucinated references are removed before finalization.

**(D) Human-in-the-Loop (HITL) Collaboration:**
Seven intervention modes spanning the autonomy spectrum:
- **Full-Auto:** Zero interventions.
- **Gate-Only:** Pauses at 3 fixed checkpoints (literature screening, experiment design, final quality review).
- **CoPilot:** Targets 6 high-leverage decision points (Idea Workshop, Baseline Navigator, Paper Co-Writer, plus smart pauses at literature/experiment/quality stages).
- **Thorough:** Pauses at all 8 phase boundaries.
- **Step-by-Step:** Requires explicit approval at all 23 stages.
- **Pre-Experiment:** Intervention only at early-pipeline stages (5, 8, 9).
- **Post-Experiment:** Intervention only at late-pipeline stages (14, 17, 20).
- **SmartPause:** Monitors estimated uncertainty at each stage. When uncertainty exceeds a learned threshold, pauses and presents the decision to the researcher. Threshold adapts based on historical approval patterns.

**(E) Cross-Run Evolution:**
- Persistent lesson store extracts structured lessons from repair attempts, Pivot/Refine decisions, HITL gate feedback, and verification results.
- Each lesson records category, severity `s(l) ∈ (0, 1]`, and recommended mitigation.
- Lessons retrieved by category and ranked by time-decayed weight: `w(l) = s(l) · exp(-ln(2) · Δt / T½)` where `T½ = 30 days` (default).
- Lessons injected as natural-language overlays into prompts — no model retraining required.

**Algorithm 1 (from Appendix B):**
```
Require: Research idea I, lesson store L, max pivots Np=2, max refines Nr=10
Ensure: Verified paper P, updated lesson store L'
1: Detect hardware profile; detect research domain D via 3-level cascade
2: Select domain prompt bank B(D); instantiate PromptManager(D) and domain adapter A(D)
3: Scope topic; retrieve & screen literature; synthesise knowledge cards
4: np ← 0
5: repeat
6:    [Debate] K=3 domain-specialised agents → hypotheses H
7:    Design experiments; score complexity c; select generator via cascade
8:    Validate code: AST checks, import verification, ablation-identity detection
9:    nr ← 0
10:   repeat
11:      Execute in Docker sandbox (three-phase network isolation)
12:      while experiment fails and repair budget remains: parse failure; fix; re-execute
13:      [Debate] K=3 agents → result analysis
14:      Decide d ∈ {Proceed, Refine, Pivot}; nr ← nr+1
15:   until d ≠ Refine or nr ≥ Nr
16:   np ← np+1
17: until d ≠ Pivot or np ≥ Np
18: Build verified registry R; draft paper with pre-built tables from R; review → revise
19: Verify: reject unverified numbers in strict sections
20: Verify citations via 4-layer API pipeline
21: Extract lessons; update L → L' with time-decayed weights
22: return P with verification reports
```

**Domain-aware routing:** A three-level cascade (forced override → keyword matching of 350+ rules → LLM classification) selects domain prompt bank. ML bank uses Innovator/Pragmatist/Contrarian for hypothesis debate; HEP-ph bank uses Theorist/Phenomenologist/Experimentalist. Domain adapters inject domain-specific condition terminology, paradigm constraints, and compute budget into stage prompts.

**Experiment-stage comparison on ARC-Bench (25 ML topics, CD:CE:RA = 25:25:50):**

|-----------|----------|-----------|-----------------|---------------------------|
| AutoResearchClaw (CoPilot) | 0.968 | 0.578 | 0.523 | **0.648** |
| AutoResearchClaw (Full-Auto) | 0.938 | 0.562 | 0.442 | **0.596** |
| AIDE-ML | 0.958 | 0.415 | 0.336 | **0.511** |
| AI Scientist v2 | 0.712 | 0.442 | 0.261 | **0.419** |

- AutoResearchClaw (CoPilot) outperforms AI Scientist v2 by **54.7%** relative and AIDE-ML by **26.8%** relative.
- On Result Analysis specifically: AutoResearchClaw (0.523) vs. AI Scientist v2 (0.261) = **100.4% relative improvement**.
- Full-Auto (0.596) substantially exceeds both baselines without any human input.

## 3. Trade-offs (wins vs. loses)

| Dimension | Win | Lose |
|-----------|-----|------|
| **Result analysis quality** | +100.4% over AI Scientist v2 via debate + verified registry | K=5 debate costs +67% tokens for only +8% diversity; K=3 is sweet spot |
| **Execution robustness** | Self-healing raises completion from 10/10 to maintain ceiling; prevents 4/10 topics from failing on first error | Repair loop budget (N_r=10, N_p=2) adds latency; Pivot restarts from hypothesis generation |
| **Scientific integrity** | Verification prevents fabricated numbers and hallucinated citations from reaching output | Verification reduces apparent acceptance (3/10 vs. 5/10 without gates — the "cost of integrity") |
| **Human-AI collaboration** | CoPilot achieves 87.5% accept with 6 targeted interventions; Gate-Only achieves 100% validity with 3 | Step-by-Step requires 23 interventions but achieves only 50% accept (non-critical interventions add noise) |
| **Cross-run learning** | Evolution provides +0.48 quality and +1 completion by avoiding known failure modes | Infinite half-life (T½=∞) accumulates contradictory advice past ~15 runs; 30-day half-life is optimal |
| **Domain coverage** | 20+ domains via sandboxed skill agents; biology 0.912, statistics 0.898 | HEP-ph only 0.489 due to insufficient deliverable content and unsupported meta-claims |
| **Pipeline granularity** | 23 stages with formal input/output contracts, checkpoint-based resumption | 12-stage prototype had poor intermediate quality; 30+ stages caused excessive context-reconstruction overhead |
| **End-to-end capability** | Only system combining debate, self-healing, verification, cross-run evolution, and HITL | Writing-quality audit reveals formatting defects: abstract-before-\maketitle (20/20), markdown-style sections (17/20), duplicate figures (16/20) |

## 4. Design Rationale

The paper's central insight is that **the three core challenges of autonomous research (hypothesis quality, execution robustness, experience accumulation) are not independent and must be addressed together**. Better hypotheses reduce the need for major revisions during execution; robust execution preserves intermediate results; lessons from past runs improve both hypothesis generation and experiment design. Single-agent systems structurally lack incentive to disconfirm their own hypotheses (same model generates and evaluates). Linear execution models treat failures as termination signals rather than information. Stateless multi-run systems repeat known failures. AutoResearchClaw addresses all three through interacting mechanisms: debate stress-tests hypotheses from multiple epistemic roles, self-healing treats failure as diagnostic information via Pivot/Refine, cross-run evolution converts failures into reusable safeguards via time-decayed weights, and verification ensures outputs are grounded. The HITL design is motivated by the observation that human expertise has highest marginal impact at a small number of decision points (hypothesis co-creation, experiment design, result analysis) rather than distributed uniformly across the pipeline — empirically validated by CoPilot outperforming both Full-Auto and Step-by-Step.

## 5. Limitations & Failure Modes

1. **Silent semantic collapse (T10 case):** Full-Auto passes all numeric verification gates but produces identical zero-bias outputs across all cross-validation strategies. The registry gate only checks number existence, not whether measurements address the research question — verification is necessary but not sufficient for scientific validity.
2. **Stage-17 bottleneck:** 11 of 13 invalid HITL runs fail at paper_draft (the first hard anti-fabrication checkpoint). Subtypes include: no usable metrics from upstream stages, environment/dependency breakage (missing imblearn, LightGBM), dataset loading failures in sandbox, and design pathologies (ambitious designs exceeding budget, invalid CV configurations). The hard block conflates heterogeneous causes.
3. **Writing-quality defects:** Consistent formatting problems across 20 audited deliverables — abstract before \maketitle (20/20), Markdown-style section headings from figure captions (17/20), duplicated figure files (16/20), content leakage from internal agents (9/20). Local single-pass pdflatex compile rate: 7/10 pass.
4. **HEP-ph underperformance:** Only 0.489 on high-energy physics tasks due to insufficient deliverable content and minor unsupported meta-claims, despite correct reproduction of cross-section curves.
5. **Evolution knowledge contamination:** With T½=∞, the lesson store accumulates contradictory advice past ~15 runs. The 30-day half-life mitigates this but means useful lessons from successful lines of work fade from prominence.
6. **Citation count insufficiency:** Some papers fall below NeurIPS norms (as low as 2 citations in one case). HITL improves citation discipline more reliably than breadth.
7. **Domain bootstrapping cost:** New scientific domains require domain-specific YAML profiles, prompt adapters, Docker images with pre-installed software stacks, and debate role definitions — though the ML + adapter fallback covers many domains, quality varies.
8. **Scripted HITL:** All HITL experiments use scripted interventions rather than live human participants. Real-world researcher behavior may differ from scripted expert input.
9. **Single-backbone evaluation:** All comparisons use GPT-5.3-codex. Cross-backbone behavior is not evaluated.

## 6. Transfer to Lyra

**The ONE transferable idea:** The **Pivot/Refine/Proceed decision loop with failure-as-information semantics.** In AutoResearchClaw, when an experiment fails or produces degenerate results, the system captures the failure signature, generates targeted fixes, and makes a structured decision: Proceed (evidence supports hypothesis), Refine (adjust current approach, up to N_r=10), or Pivot (return to hypothesis generation with the failure recorded as new evidence). This transforms brittle execute-then-terminate pipelines into resilient explore-then-adapt loops where failures become diagnostic signals rather than dead ends.

**Why relevant to Lyra:** Lyra's agent architecture would benefit enormously from structured failure recovery. Currently, when a sub-agent or tool call fails, Lyra agents have no systematic mechanism for distinguishing "fix this specific thing and retry" from "this approach is fundamentally wrong, change direction" or for preserving partial progress across failures. The cascading code generation with complexity scoring (`c ∈ [0,1]`, routing to external AI coding agent vs. built-in agent) is a direct analog for Lyra's own tool-routing decisions — route simple tasks to built-in handlers and complex ones to sub-agents or external APIs based on scored complexity.

**Workstream routing:** §4.6 (Agent Execution & Self-Healing) — this is the most natural home for a Pivot/Refine decision loop integrated into Lyra's execution engine, alongside the cascading complexity-based routing and the lesson extraction mechanism for cross-run learning.

**Impact/Effort/Tier:**
- **Impact:** 4 — Structured failure recovery would significantly improve agent task completion rates, especially on multi-step research and code-generation tasks where initial attempts often fail.
- **Effort:** 4 — Requires implementing the Pivot/Refine/Proceed state machine, a failure signature taxonomy, a complexity scoring function, and integration with Lyra's existing execution loop. The lesson store with time-decayed weights adds additional infrastructure.
- **Tier:** **Breakthrough** — This is a genuinely novel architectural pattern for agent resilience that goes beyond simple retry logic, and the empirical evidence (10/10 → 6/10 completion without self-healing) is compelling.
