## 1. Mechanism (Step-by-Step)

MEMENTO is a framework that treats the open web as a cross-session **learning signal** rather than a stateless retrieval interface. It operates at two levels: within-session research (Adaptive Exploration Tree) and cross-session memory accumulation (dual-channel persistent memory). No model weights are updated — learning is stored entirely in human-readable natural-language memory artifacts.

### 1.1 Adaptive Exploration Tree (AET) — Within-Session

**Wave-Based Decomposition.** Given input x (a research question), the AET decomposes it into a tree of sub-questions Q = {q₀, q₁, ..., qₖ} where q₀ is the root. Decomposition happens in waves under a configurable budget B₀ = 25 total questions, with 5 in the initial wave and 10 each across 2 reflection checkpoints (3 waves total).

**Tool-Augmented Agents.** Each sub-question qⱼ is assigned to an independent agent with four primitives:

1. **SEARCH_MEMORY** — retrieves relevant entries from both the long-term declarative store (M₄) and local session memory, prioritizing cached knowledge before external retrieval.
2. **SEARCH_WEB** — issues a web query with date-restricted filtering and returns ranked results. Temporal cutoffs prevent leakage: 6 months before publication (sales), 2 years before decision (legal).
3. **SCRAPE_RESULTS** — fetches full textual content of selected results. Serves previously retrieved pages from an in-process cache to avoid redundant network requests.
4. **GENERATE_ANSWER** — synthesizes accumulated evidence into a final response for the sub-question.

**Reflection Agent.** Between waves, a reflection agent receives all answers generated so far, intermediate findings, and the history of prior reflection decisions. It identifies remaining gaps — unanticipated dependencies, unresolved ambiguities, overlooked dimensions — and produces a new set of targeted sub-questions. The tree is iteratively reshaped in response to accumulating evidence, not statically defined at initialization.

**Bottom-Up Synthesis.** Once all waves complete, answers are synthesized upward through the tree level-by-level (deepest to shallowest). Only nodes with children but no direct answer require synthesis. The root node's synthesized answer is the final output ŷ.

**Local Session Memory.** Grows incrementally as sub-questions are resolved. Each solved sub-question contributes its answer and supporting evidence. Available to all AET components: the reflection agent consults it when generating new waves, and tool-augmented agents query it before issuing external web searches.

### 1.2 Dual-Channel Persistent Memory — Cross-Session

Grounded in the declarative/procedural distinction from ACT-R cognitive theory (Anderson et al., 2004). Two independent memory systems with shared batch-update cadence:

**Procedural Memory (M₁, M₂, M₃)** — "knowledge of how to research":

- **M₁ — Craft Knowledge:** Free-text store of high-level research strategy. Contains heuristics about which sub-questions are informative, which sources are authoritative, how to reason under uncertainty. Learned entirely from the web without supervision: each sample's session scratchpad is distilled by an LLM into generalizable insights. Consumed at planning stage. Supports cold-start enrichment via exploratory web searches when M₁ is empty.

- **M₂ — Decomposition Rules:** Structured catalog of conditional rewrite rules of the form: `WHEN <pattern in root/sample inputs>, ADD a sub-question that COVERS <pattern>`. Encodes hard, sample-conditioned compositional patterns. Injected at every depth of the question-breakdown prompt (wave zero and reflection). Updated via supervised reflection comparing predictions to ground truth, with rules accumulating support or contradiction weighted by ratio across batches.

- **M₃ — Web Action Rules:** Structured catalog governing tool-use stage: query formulation (quoted-phrase length, language separation), URL selection (authority filters, `site:` qualifiers), scraping constraints. Injected into the system prompt of every tool-augmented agent. Updated from search execution logs.

**Declarative Memory (M₄)** — "knowledge of what is known":

- **M₄ — Domain Store:** Structured free-text repository of entity-specific factual knowledge extracted from prior samples. At inference time, a retrieval step matches the current sample against M₄'s keys and injects the matching subset as always-visible context in the tool-augmented agent's system prompt.

### 1.3 Batch Update Loop (Cross-Session Learning)

**Phase A — Forward Pass and Unsupervised Consolidation:** All b = 10 examples processed in parallel using current memory state M = ⟨M₁, M₂, M₃, M₄⟩. Post-inference, two unsupervised steps run: (i) M₁ rewritten by LLM aggregating per-sample methodology learnings, (ii) M₃ updated from search execution logs. M₄ updated by folding entity-specific facts extracted during runs.

**Phase B — Scoring:** Each predicted output ŷᵢ scored against ground truth yᵢ* using an LLM judge, producing a normalized score per sample. Failed runs excluded from supervised phase.

**Phase C — Supervised Reflection:** For each successfully scored run, the system compares predicted outputs against ground truth at fine-grained level. Rules active in runs where a value proposition was found accumulate support; rules present in runs where it was missed accumulate contradiction. An LLM proposes rule additions, reinforcements, or removals, which are canonicalized and merged into M₂ weighted by support-to-contradiction ratio.

**Training regime:** 6 batches of 10 examples (60 total training samples). 6 batches total. At test time, forward pass runs with frozen memory — no updates occur.

### Key Algorithmic Equations

Sales scoring: `normalized_score = (1 / (5|G|)) * Σ s(g)` where G = set of ground-truth pitch points, s(g) ∈ {0,1,2,3,4,5} per the 6-level rubric (0=Miss to 5=Strategic Bullseye).

Legal scoring: binary CORRECT/INCORRECT verdict on winning party prediction.

## 3. Trade-Offs

| Win | Cost / Caveat |
|---|---|
| No model fine-tuning required — all learning stored as human-readable text | Memory is frozen at inference time; no continued learning after deployment |
| Works with as few as 60 training samples (6 batches of 10) | AET computationally expensive during training (~6h for 60 samples on 32×A100) |
| **Improves both quality AND efficiency simultaneously** — score rises while search queries, scrapes, and LLM calls all drop | Requires web coverage of target domain; cannot learn what the web doesn't contain |
| Procedural memory delivers 85% of gains — knowing *how* to search matters more than caching facts | Declarative memory alone is counterproductive: increases cost (more questions, larger scratchpad, more LLM calls) without score improvement |
| Memory transfers across model backbones (Qwen and GPT-5-mini) | Small super-additive effect between memory channels (+0.003) — channels are only weakly complementary |
| Memory artifacts are auditable (human-readable text, not opaque weights) | Evaluated on only 2 domains; generalization not established |
| Training reduces repeated URL scraping by 26% — meaningful cost savings at scale | 5-shot GPT-5-mini + Memory showed regression on Legal (0.675 vs 0.692) — possible parametric/memory interference |
| Procedural strategies learned from web, not labeled data — curation-free scaling | Code not released; reproducibility depends on reimplementation from paper description |

## 4. Design Rationale

**Why web as learning signal instead of labeled data:** Human practitioners in low-data domains (lawyers, sales reps) don't wait for annotated datasets — they learn through repeated, self-directed web interaction. The web is open, requires no annotation, and carries both factual content and implicit domain expertise encoded in practitioner forums, methodology articles, and domain blogs. MEMENTO mirrors this learning pattern: it accumulates research strategies and domain knowledge across sessions without needing labeled supervision.

**Why dual-channel memory (procedural/declarative):** Grounded in ACT-R cognitive theory (Anderson et al., 2004). The integrated theory of mind distinguishes declarative knowledge (facts) from procedural knowledge (skills). Novice-to-expert progression is driven primarily by *production compilation* — converting slow deliberate strategies into efficient automatic routines. The ablation proves this empirically: procedural memory accounts for 85% of the gain (+0.0225 / +0.0265). Separating the channels allows craft and knowledge to accumulate and evolve independently, and makes failure modes auditable.

**Why AET over flat ReAct:** Linear ReAct interleaves reasoning and action but cannot dynamically restructure search based on mid-session discoveries. The AET's wave-based reflection-iteration loop treats mid-session findings as explicit signals for restructuring subsequent search, producing trajectories that are directed and self-correcting rather than exhaustive. The largest single performance jump comes from replacing ReAct with AET (+19.7% on Sales, +29.6% on Legal with Qwen).

**Why no RL:** RL-based retrieval agents (Search-R1, MemoryR1, SE-Search) require tens of thousands of rollouts — infeasible when labeled data is scarce. Weight updates mean every new domain requires retraining. MEMENTO avoids both: it needs no weight updates and operates from 60 training examples.

## 5. Limitations and Failure Modes

1. **Memory frozen at inference:** No continued learning after deployment. The agent cannot improve from deployment-time experience; procedural strategies ossify.

2. **High training compute cost:** AET requires ~6h on 32×A100 GPUs for 60 training samples. The wave-based decomposition, reflection, and multi-agent solving create substantial LLM call overhead during training. Linear retrieval baselines are much cheaper.

3. **Web coverage dependency:** Performance is bounded by what exists on the indexed web. Domains with sparse web coverage (proprietary knowledge, offline-first industries) will see degraded results. The legal task required discarding ~542 of 722 candidates due to insufficient web coverage.

4. **Declarative memory counterproductive in isolation:** When used without procedural guidance, cached facts encourage the agent to pursue *more* leads rather than *better* ones, inflating the research trajectory (most questions, largest scratchpad, most LLM calls) without score improvement.

5. **Limited domain/model evaluation:** Only 2 domains (sales, legal), 2 models (Qwen, GPT-5-mini). Performance on medical, financial, or technical domains unknown. Interaction with larger models (Opus-scale) unexplored.

6. **Parametric/memory interference:** 5-shot GPT-5-mini + MEMENTO Memory regressed on Legal Research (0.675 vs 0.692 without memory). Attributed to interference between the model's parametric knowledge and memory-injected context — unresolved.

7. **Code not released:** Reproducibility depends on reimplementation from paper description. While hyperparameters and architecture are fully specified, the lack of reference code increases barrier to adoption.

8. **Temporal leakage prevention is domain-specific:** Requires manual configuration of look-back windows per task. Overly aggressive cutoffs could exclude legitimate training signal.

9. **No multi-agent coordination:** Procedural knowledge is learned per single-agent trajectory. No mechanism for sharing procedural knowledge across multiple collaborating agents.

## 6. Transfer to Lyra

### The One Idea: Dual-Channel Procedural/Declarative Memory with Batch-Update Loop

MEMENTO's core transferable insight is the separation of agent memory into **procedural** stores (search strategies, decomposition rules, query heuristics) and **declarative** stores (domain facts, entity knowledge) with a **batch-level update loop** that distills execution trajectories into reusable memory artifacts — all without model weight updates.

**How Lyra would adopt this:**

1. **Procedural Memory (M₁-M₃ equivalent):** Lyra maintains search-strategy artifacts — query templates, source credibility heuristics, decomposition patterns for common research question types — learned from prior Lyra research sessions. These are injected as system-prompt context for future sessions, making Lyra progressively more efficient at web research.

2. **Declarative Memory (M₄ equivalent):** Lyra accumulates verified domain facts and entity-specific knowledge across sessions. When a new research task touches a previously explored domain (e.g., "transformer architectures" or "RLHF"), cached facts shortcut redundant lookups.

3. **Batch Update Loop:** After each Lyra research session, the execution trajectory (queries issued, URLs scraped, answers generated, reflection decisions) is distilled into rules that update both memory stores — procedural patterns that worked well gain support, dead-end patterns are pruned.

**Key advantage for Lyra:** Lyra is fundamentally a research agent that conducts repeated web exploration across sessions. MEMENTO's architecture directly addresses Lyra's core need: getting better at research over time without requiring fine-tuning or large labeled datasets. The finding that procedural memory delivers 85% of gains is particularly actionable — Lyra should prioritize learning *how to search* over caching *what was found*.

### §4 Workstream Route

**§4.2 — Memory Subsystem Enhancement**

This feeds directly into Lyra's memory upgrade workstream. MEMENTO provides a concrete, empirically validated architecture for (a) separating procedural from declarative memory, (b) updating both from execution trajectories via batch-loop consolidation, and (c) injecting learned strategies as system-prompt context. The ACT-R grounding provides theoretical backing for the design choices.
