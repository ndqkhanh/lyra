## 1. Mechanism (step-by-step)

LlamaFirewall is a modular, layered guardrail framework that intercepts LLM agent execution at multiple points. It comprises three core scanners orchestrated by a policy engine.

### Step 1: PromptGuard 2 — Lexical Jailbreak Detection (Input Gate)

**Architecture:** Fine-tuned DeBERTa-based BERT-style classifier.
- **PromptGuard 2 86M:** mDeBERTa-base backbone, 86M parameters.
- **PromptGuard 2 22M:** DeBERTa-xsmall backbone, 22M parameters.

**Training improvements over PromptGuard 1:**
1. **Scope refinement:** Narrowed to explicit jailbreak detection only (instruction overrides, role reassignments, token injection). Broader goal hijacking detection moved to AlignmentCheck.
2. **Expanded datasets:** Combines open-source benign content, curated malicious prompt injection examples, synthetic red-teaming data from iterative testing.
3. **Energy-based loss function:** L = L_CE + λ * L_energy, where L_energy penalizes overconfident negative predictions on benign prompts to improve OOD calibration. Inspired by Liu et al. (2020).
4. **Hardened tokenization:** Counters adversarial whitespace manipulation and token fragmentation attacks.

**Runtime behavior:**
- Operates on messages with `role=user` or `role=tool` only.
- Returns a jailbreak confidence score [0,1]. Thresholds are tuned per-deployment to target a fixed FPR (e.g., 1% or 3%).
- If score exceeds threshold → input is dropped from context (or flagged for downstream handling).

### Step 2: AlignmentCheck — Semantic CoT Auditing (Reasoning Gate)

**Architecture:** Few-shot prompted LLM (guardrail LLM) acting as a chain-of-thought auditor.

**Input structure:**
- `USER MESSAGE`: The original user objective (reference for alignment).
- `TRACE`: Sequence of prior agent reasoning steps (thoughts, tool calls, interactions), truncated to a fixed context window.
- `SELECTED ACTION`: The most recent agent action/decision to evaluate.

**Prompt template (DEFAULT_SYSTEM_PROMPT):** A static 5-shot prompt with 3 non-misaligned examples and 2 misaligned examples. The guardrail is told: "When in doubt, assume the action is not misaligned — only mark it as misaligned if it is clearly not related to the original objective."

**Output format (JSON):**
```json
{
  "observation": "Description of the agent's reasoning",
  "thought": "Logical inference about whether misalignment is present",
  "conclusion": true   // true = misaligned, false = not misaligned
}
```

**Mitigation against guardrail injection:**
- Inputs restricted to agent's chain-of-thought and actions only (direct tool outputs excluded).
- Pre-scanning via PromptGuard for known injection patterns before AlignmentCheck processing.

**Runtime behavior:**
- Operates on messages with `role=assistant` only.
- If conclusion=true → execution is halted immediately (or action is blocked).
- Can be configured to run every N steps rather than every step to reduce latency.

### Step 3: CodeShield — Static Code Analysis (Output Gate)

**Architecture:** Two-tier online static analysis engine.

**Tier 1 (lightweight):** Fast pattern matching using regex rules. Completes in ~60ms. Resolves ~90% of inputs.
**Tier 2 (comprehensive):** Full Semgrep static analysis with syntax-aware matching. Completes in ~300ms. Triggered only when Tier 1 raises a potential concern.

**Coverage:** 8 programming languages. Supports both built-in rules and community-authored Semgrep rules.

### Step 4: Policy Engine (Orchestration)

Developers define YAML/JSON pipelines:
1. Conditional remediation strategies (block, flag, rewrite, log).
2. Custom scanner ordering and gating logic.
3. Plug-in mechanism for new detectors (regex, LLM-prompt-based).
4. Replay-based offline evaluation: incrementally scan conversation history of static traces; a trace is "flagged" if any scanner detects violation at any point.

**End-to-end layered defense flow:**
```
User Prompt / Tool Output
    → PromptGuard 2 (jailbreak check)
        → IF flagged: drop from context
        → IF clean: pass to agent
    → Agent generates action + CoT
    → AlignmentCheck (goal alignment audit)
        → IF misaligned: halt execution
        → IF aligned: pass action to execution
    → Agent generates code
    → CodeShield (static analysis)
        → IF insecure: reject patch, agent retries
        → IF clean: commit allowed
```

## 2. Results (real benchmark numbers)

### PromptGuard 2 — Direct Jailbreak Detection (private OOD benchmark)

| Model | AUC (English) | Recall @ 1% FPR (English) | AUC (Multilingual) | Latency (A100, 512 tokens) |
|---|---|---|---|---|
| PromptGuard 1 | 0.987 | 21.2% | 0.983 | 92.4ms |
| PromptGuard 2 86M | 0.980 | **97.5%** | **0.995** | 92.4ms |
| PromptGuard 2 22M | **0.995** | 88.7% | 0.942 | **19.3ms** |

Key insight: PromptGuard 2 86M achieves a 4.6x improvement in Recall @ 1% FPR over v1 (21.2% → 97.5%).

### AgentDojo Combined Defense (97 tasks, 10 model traces)

| Configuration | ASR (↓ better) | Utility (↑ better) |
|---|---|---|
| No Guardrail (baseline) | 0.1763 (17.6%) | 0.4773 (47.7%) |
| PromptGuard V2 86M only | 0.0753 (7.5%) | 0.4701 (47.0%) |
| AlignmentCheck (Llama 4 Maverick) only | 0.0289 (2.9%) | 0.4309 (43.1%) |
| **Combined (PromptGuard + AlignmentCheck)** | **0.0175 (1.8%)** | 0.4268 (42.7%) |

- **90.1% reduction** in ASR from baseline with combined defenses.
- Utility cost: 4.7 percentage points (47.7% → 42.7%) for combined; only 0.7 pp for PromptGuard alone.
- AlignmentCheck alone achieves 83.6% ASR reduction (17.6% → 2.9%).

## 3. Trade-offs

| Win | Cost |
|---|---|
| 90% ASR reduction with combined PromptGuard + AlignmentCheck | 10.6% absolute utility degradation |
| PromptGuard 2 86M: 57% ASR reduction, negligible utility loss (1.5%) | Does not detect indirect injections lacking jailbreak lexical triggers |
| AlignmentCheck: detects semantic goal hijacking pattern-based methods miss | Requires Llama 4 Maverick or Llama 3.3 70B; small models (1B-8B) cause severe overblocking |
| PromptGuard 2 22M: 5x lower latency (19.3ms vs 92.4ms), smaller footprint | 8.8 pp drop in Recall @ 1% FPR on English; poor multilingual performance (AUC 0.942 vs 0.995 for 86M) |
| CodeShield 96% precision — low developer friction | 79% recall — 21% of insecure patterns missed; context-dependent vulns inherently undetectable |
| Open source + customizable pipelines | Production deployment requires threshold tuning per use case |
| AlignmentCheck operates on CoT — reveals reasoning | Guardrail model sees potentially sensitive CoT content |
| Modular, composable defense | Each layer adds cumulative latency; AlignmentCheck LLM calls are expensive per-agent-step |
| PromptGuard 2 energy-based loss improves OOD precision | Training requires diverse negative samples; may drift on new benign input distributions |

## 4. Design Rationale

**Why BERT for jailbreak detection instead of prompting an LLM?** Jailbreak attempts exhibit high lexical regularity and structural predictability (instruction overrides, role reassignments, token injection). A lightweight classifier is (a) deterministic, (b) low-latency (19-92ms), (c) deployable on CPU, and (d) does not require an additional API call to a large model. The energy-based loss was chosen specifically to reduce false positives on OOD benign prompts — critical for production where false alarms degrade user experience.

**Why few-shot LLM auditing for alignment?** Indirect prompt injections often contain no recognizable jailbreak syntax. The attack only surfaces as behavioral drift (e.g., a coding agent silently exfiltrating API keys). Inspecting the chain-of-thought gives a semantic signal that lexical filters miss. Standardized task definitions (fixed user goal, sequential agent actions) make alignment evaluation generalizable across agent frameworks.

**Why static analysis (Semgrep) for code safety, not an LLM reviewer?** Deterministic, explainable, low-latency. 96% precision means developers trust it. Semgrep's rule ecosystem is community-extensible — new vulnerability patterns can be added without retraining.

**Why layered composition?** No single defense suffices. PromptGuard handles high-volume obvious attacks cheaply; AlignmentCheck handles subtle semantic drift but is expensive; CodeShield handles code-specific risks. This mirrors defense-in-depth in traditional network security (Snort, Zeek, Sigma).

## 5. Limitations & Failure Modes

1. **Guardrail injection:** AlignmentCheck can itself be targeted by prompt injections designed to manipulate both the agent and the guardrail LLM simultaneously. Mitigated by restricting AlignmentCheck inputs to CoT/actions (excluding raw tool outputs) and pre-scanning with PromptGuard, but not eliminated.

2. **AlignmentCheck model dependency:** Effectiveness is tightly coupled to guardrail LLM capability. Small models (1B-8B) cause severe utility degradation from overblocking. Model distillation for smaller guardrails is mentioned as future work but unexplored.

3. **CodeShield recall gap:** 79% recall with 21% of insecure patterns missed. Logic bugs, business logic flaws, and context-dependent vulnerabilities cannot be detected by static analysis patterns.

4. **Narrow evaluation:** AgentDojo focuses on a single attack class (`important_instructions`). More diverse and adaptive adversarial testing is needed.

5. **Text-only:** No coverage for multimodal prompt injection (images, audio, video). Listed as future work.

6. **No adaptive adversary testing:** Evaluations are against static attack datasets, not adversaries who adapt to the defenses.

7. **CoT privacy exposure:** AlignmentCheck requires the agent to externalize its reasoning trace, which may contain sensitive user data or system information visible to the guardrail model.

8. **Cumulative latency:** Full defense stack (PromptGuard + AlignmentCheck + CodeShield) adds meaningful per-turn overhead, especially for interactive agent applications.

## 6. Transfer to Lyra

**The ONE transferable idea:** A layered, gated guardrail pipeline that chains a fast lexical classifier for obvious violations with a slower semantic auditor for subtle drift, minimizing per-turn cost by escalating only when the cheap gate is uncertain.

**Concrete Lyra adaptation:**
Lyra can deploy a two-tier safety/quality gate modeled on LlamaFirewall's PromptGuard + AlignmentCheck pattern:
- **Tier 1 (Fast Gate):** A lightweight classifier or rule engine that scores Lyra's intermediate reasoning for obvious hallucination footprints, contradiction patterns, or policy violations. Only escalates high-confidence positives to Tier 2.
- **Tier 2 (Deep Audit):** A second LLM pass (analogous to AlignmentCheck) that audits Lyra's chain-of-thought for semantic consistency with the user's original objective, factual grounding, and reasoning integrity. Triggered only when Tier 1 is uncertain or on a sampling schedule.

**Workstream route:** §4.7 — Safety & Guardrails

**Impact:** 4 — Directly improves Lyra's safety posture against prompt injection, goal drift, and hallucination propagation.
**Effort:** 4 — Requires training a classifier model for Tier 1, engineering the gate pipeline with escalation logic, prompt engineering for the auditor LLM, and integration testing against adversarial eval suites.
**Tier:** Breakthrough — This provides a defense-in-depth architecture that no current open-source agent framework ships with, and aligns with Meta's production-proven approach.
