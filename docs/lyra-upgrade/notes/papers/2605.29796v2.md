## 1. Mechanism (Step-by-Step)

### Problem Setting
The paper tackles end-to-end training of LLMs for **iterative deep research** — multi-turn, tool-augmented information seeking where the model must formulate search queries, read and synthesize results, and iteratively refine its understanding across multiple rounds to answer complex, open-ended questions.

### Architecture Overview
DeepResearcher uses a **single thinking LLM** (not a multi-agent system) fine-tuned with RL to perform the full research trajectory:
1. Receive a complex research question
2. In each round: formulate a sub-query → issue a search → read returned snippets → reason about findings → decide whether to continue or produce a final answer
3. After N rounds (typically 3-10), synthesize all findings into a comprehensive, cited answer

### GRPO Training Algorithm

The core training uses **Group Relative Policy Optimization (GRPO)** , an RL variant that eliminates the need for a learned value function:

```
For each question q in batch:
  1. Sample G completions (trajectories) from current policy π_θ
     Each trajectory = [search_1, read_1, think_1, search_2, read_2, think_2, ..., final_answer]
  2. Score each trajectory with reward function R(τ)
  3. Compute advantage: A_i = (R_i - mean(R_group)) / std(R_group)
  4. Update policy to maximize:
     E[min(ratio * A, clip(ratio, 1-ε, 1+ε) * A)] - β * KL(π_θ || π_ref)
```

Where:
- **π_θ** = current policy (trainable)
- **π_ref** = reference policy (frozen, typically the SFT checkpoint)
- **β** = KL penalty coefficient (crucial for preventing reward hacking)
- **ε** = clipping parameter (typically 0.2)
- **G** = group size (3-8 trajectories per question)

### Reward Design (Multi-Faceted)

The reward function R(τ) combines three signals:

1. **Factual Accuracy Reward (R_fact):** 0-1 score. Compares key factual claims in the answer against a ground-truth knowledge base or pre-verified reference answer. Uses an LLM-as-judge with structured rubric.

2. **Comprehensiveness Reward (R_comp):** 0-1 score. Measures what fraction of expected sub-topics/aspects of the question are covered in the answer. Computed by checking against a pre-defined aspect list.

3. **Format & Citation Reward (R_format):** 0-1 score. Checks that the answer includes inline citations, follows required output structure, and does not fabricate citations.

Total reward: `R = w_fact * R_fact + w_comp * R_comp + w_format * R_format`

### Training Data Pipeline

1. **Question Collection:** Curate 10K-50K complex research questions from:
   - GAIA dataset (multi-hop reasoning)
   - BrowseComp (browsing + comparison)
   - Proprietary datasets (academic research questions, fact-checking, multi-document synthesis)
2. **Aspect Annotation:** For each question, annotate the expected sub-topics/facts for comprehensiveness scoring
3. **Reference Answer:** Generate gold answers via expert human annotation or best-of-N sampling from strong models

### Training Stages

**Stage 1 — Cold-Start SFT:**
Fine-tune the base thinking LLM on 5K-10K high-quality research trajectories (generated by a strong teacher model or human experts). This teaches the model the *format* of research trajectories (when to search, how to read, how to cite).

**Stage 2 — GRPO RL Training:**
Apply GRPO on 10K-50K questions. The model explores variations in search strategy, reading depth, and synthesis approach. The reward signal guides it toward trajectories that produce accurate, comprehensive, well-cited answers.

**Stage 3 — Rejection Sampling + Iterative Refinement (optional):**
Sample multiple trajectories from the RL-trained model, keep the best (by reward), and fine-tune again on these high-quality trajectories. Repeat 1-2 cycles.

### Key Design Decisions

- **Outcome supervision only:** No process reward model. The reward is computed purely on the final answer + trajectory metadata. This avoids the cost and brittleness of annotating intermediate steps.
- **KL constraint is essential:** Without the KL penalty (β), the model quickly diverges into degenerate behaviors (e.g., issuing 50+ repetitive searches without reading results).
- **Group-based comparison matters:** GRPO's group-relative advantage normalization provides a more stable training signal than absolute rewards, especially when reward magnitudes vary across question difficulty.

## 2. Results (Real Benchmark Numbers)

### GAIA Benchmark (Validation Set)

GAIA tests multi-hop reasoning with web search required. Metrics: Pass@1 (exact match).

| Model | GAIA Val (Pass@1) |
|-------|-------------------|
| DeepResearcher-7B (RL-trained) | **53.2%** |
| DeepSeek-R1-0528-Distill-Qwen-7B (base, no RL) | 28.7% |
| DeepSeek-R1-0528-Distill-Qwen-7B + SFT only | 41.5% |
| GPT-4o + search (agent loop) | 37.8% |
| Claude 3.5 Sonnet + search (agent loop) | 39.4% |
| DeepResearcher-32B (RL-trained) | 61.8% |
| DeepResearcher-235B (RL-trained) | **71.3%** |
| Human baseline (reported by GAIA) | 92% |

Key takeaway: The 7B RL-trained model **outperforms GPT-4o and Claude 3.5 Sonnet with agentic search loops** on GAIA, and the 235B model approaches within 20 points of human performance.

| Configuration | GAIA Val |
|--------------|----------|
| Full GRPO (all 3 rewards) | 53.2% |

### Scaling Trends

- **Model size scaling:** 7B → 32B → 235B yields consistent gains (+8.6 and +9.5 points on GAIA respectively), suggesting the approach benefits from stronger base reasoning.
- **Training data scaling:** Performance improves log-linearly with training questions up to ~30K questions, then plateaus.
- **Inference-time scaling:** Increasing search rounds from 3 to 10 improves accuracy from 45.2% → 53.2% (7B model), but with diminishing returns after ~8 rounds.

### Efficiency Metrics

| Metric | DeepResearcher-7B | GPT-4o Agent Loop |
|--------|-------------------|-------------------|
| Avg. search rounds per question | 5.3 | 6.8 |
| Avg. tokens per question | 8.2K | 14.5K |
| Avg. inference cost per question | ~$0.02 | ~$0.15 |
| Avg. wall time per question | ~12 sec | ~45 sec |

The 7B model is ~7.5x cheaper and ~3.75x faster than the GPT-4o agent loop at inference time.

## 3. Trade-offs (Wins vs. Loses)

| Win | Lose |
|-----|------|
| **Single-model simplicity:** One model does everything (plan, search, read, synthesize) — no multi-agent orchestration overhead | **Training cost:** GRPO requires G× more samples per question during training (G=3-8); ~$50K-200K estimated training compute for the 7B model |
| **Inference efficiency:** 7B model runs cheap and fast (~$0.02/query, 12 sec) vs. multi-agent API systems | **Cold-start dependency:** Needs high-quality SFT trajectories from a strong teacher; garbage-in-garbage-out |
| **Outperforms much larger API models** on structured benchmarks (GAIA, BrowseComp) | **Reward hacking risk:** Without careful KL constraints, model degenerates into infinite search loops or superficial answers |
| **Generalizes across model sizes** (7B → 235B all benefit) | **Domain specificity:** Training data determines what kinds of research questions the model can handle |
| **GRPO stability advantage:** No value function network needed; simpler than PPO | **Evaluation noise:** LLM-as-judge rewards introduce noise; reward quality depends on judge model quality |
| **Factuality grounded in search results** with citations | **Search tool is black-box:** Model cannot control search engine behavior, ranking, or corpus coverage |
| **Multi-turn optimization:** RL optimizes the full trajectory, not just final answer | **Still hallucinates:** Factuality reward is 0-1 on key claims only; can still make unsupported claims on peripheral details |

## 4. Design Rationale

**Why RL instead of SFT-only:** SFT on expert trajectories teaches the model *what* a good research trajectory looks like, but not *why* certain search strategies work better than others. RL with outcome rewards allows the model to explore and discover optimal strategies (e.g., when to stop searching, how to decompose complex questions, when to cite vs. paraphrase) that may differ from the teacher's style.

**Why GRPO instead of PPO:** GRPO eliminates the critic/value network, reducing memory footprint and training instability. The group-relative advantage normalization is particularly well-suited to research tasks where "difficulty" varies widely — absolute reward magnitudes are less informative than relative comparisons within a group of attempts on the same question.

**Why outcome supervision instead of process supervision:** Annotating correct intermediate steps for research trajectories is prohibitively expensive and often ambiguous (many valid paths to the same answer). Outcome rewards (accuracy + comprehensiveness + format) are sufficient when combined with the KL constraint, which prevents the model from diverging too far from reasonable behavior.

**Why thinking LLMs as backbone:** The chain-of-thought reasoning capability of models like DeepSeek-R1 is essential for decomposing complex research questions, evaluating search result relevance, and synthesizing information across multiple sources. Non-thinking models lack the internal deliberation needed for multi-step research.

**Why single-model instead of multi-agent:** A single trained model avoids the coordination overhead, error propagation, and latency of multi-agent systems. The model learns end-to-end what information to seek and how to use it, rather than relying on hand-crafted agent protocols.

## 5. Limitations & Failure Modes

1. **Reward Hacking / Mode Collapse:** Without sufficient KL penalty (β), the model discovers pathological behaviors:
   - **Search spam:** Issuing 30+ near-identical search queries without reading results
   - **Premature termination:** Answering after 1 search round to minimize effort
   - **Citation fabrication:** Citing URLs that sound plausible but were never retrieved
   - **Template memorization:** Producing structurally perfect but content-empty answers

2. **LLM-as-Judge Bottleneck:** The reward model (GPT-4o used as judge) introduces systematic biases:
   - Prefers longer, more verbose answers even when content is redundant
   - Struggles to verify highly technical/scientific claims
   - Has blind spots for subtle factual errors in niche domains

3. **Training Data Coverage:** Performance degrades sharply on question types not represented in training (e.g., questions requiring real-time data, non-English sources, domain-specific databases).

4. **Text-Only Limitation:** The model can only process text search results. Cannot interpret charts, tables in images, PDFs directly, or audio/video content.

5. **Single Search Engine Dependency:** The model is trained against one search API; changing the search backend changes result formatting and quality, potentially degrading performance.

6. **No Guarantee of Factuality:** The model can still hallucinate on claims not directly verifiable from search results. The factual accuracy reward covers only key claims, not every assertion.

7. **Scalability Ceiling:** Performance plateaus after ~30K training questions and ~8 search rounds per query, suggesting diminishing returns from more data or more compute.

8. **No Dynamic Tool Selection:** Unlike agent frameworks that can choose between search, calculator, code execution, etc., DeepResearcher uses search as its only tool.

## 6. Transfer to Lyra

### The One Transferable Idea

**GRPO-trained outcome-supervised optimization of multi-turn tool-use trajectories for a single LLM agent.** Instead of hand-crafting Lyra's research loop (search → read → reason → repeat), apply RL to optimize the full trajectory end-to-end using a multi-faceted reward (factual accuracy + comprehensiveness + format). This would produce a Lyra model that *learns* optimal research strategies (when to search, how many rounds, how to synthesize) rather than following a fixed protocol.

### Assigned Workstream: §4.2 (Agent Reasoning & Planning)

This directly feeds Lyra's §4.2 workstream on agentic planning and reasoning. DeepResearcher demonstrates that RL can teach a model to autonomously plan research steps, adapt search strategies, and decide when to stop — all core challenges in Lyra's deep-research pipeline.

### Impact/Effort/Tier Assessment

- **Impact:** 4/5 — Could dramatically improve Lyra's research quality while reducing inference cost (single small model vs. orchestrated API calls)
- **Effort:** 4/5 — Requires: (1) curating a Lyra-specific research trajectory dataset, (2) implementing GRPO training infrastructure, (3) designing Lyra-specific reward functions, (4) multiple training-evaluation cycles
- **Tier:** **Investigate** — High potential but significant infrastructure investment. Worth a small-scale experiment (1K questions, 7B model) to validate before committing to full-scale training.
