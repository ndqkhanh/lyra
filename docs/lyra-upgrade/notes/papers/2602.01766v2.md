## 1. Mechanism (Step-by-Step)

CoMeT augments a standard decoder-only Transformer with a plug-in dual-memory module that achieves O(N) time and O(1) space complexity. It does **not** require training from scratch; it inserts lightweight adapters into a pre-trained model.

### Architecture Overview

A pre-trained LLM is split into sequential chunks of size C (default: 2048 tokens). Each chunk flows through the model augmented with two memory components at every Transformer layer:

| Symbol | Meaning |
|--------|---------|
| H_i^τ | Hidden states of chunk τ at layer i |
| G_i^τ | Global memory tokens for chunk τ at layer i |
| T_i^τ | Temporary memory tokens for chunk τ at layer i |
| S_i^τ | Persistent global state for chunk τ at layer i |
| C_i^τ | Compression tokens for chunk τ at layer i |
| RLA(·) | Residual Low-Rank Adapter module (rank r=8) |

### Step 1: Chunk Processing with Memory Injection

For each chunk τ, at each layer i:
1. The hidden states H_i^τ from the previous layer are concatenated with global memory G_{i-1}^τ and temporary memory tokens T_{i-1}^τ from the same chunk's previous layer.
2. This augmented sequence passes through the standard Transformer layer TL(·).
3. Compression tokens C_i^τ (inserted every 8 context tokens) and readout tokens R_i^τ (m copies, used for the next chunk) are extracted from the output.

### Step 2: Temporary Memory Update (FIFO Queue)

T_i^τ is managed as a First-In-First-Out queue:
- After processing chunk τ, the most recent compression tokens are pushed into the temporary memory.
- The oldest entries are dropped when the budget B_T (default: 2048 tokens) is exceeded.
- This ensures high-fidelity, fine-grained retention of **recent** context.

### Step 3: Global Memory Update (Gated Mechanism)

This is the core innovation. Global memory S_i^τ is updated via a learned gating function:

```
S_i^τ = Gate_i^τ ⊙ S_i^{τ-1} + (1 - Gate_i^τ) ⊙ f_update(C_i^τ)
```

Where:
- `Gate_i^τ ∈ [0,1]` is a learned gating vector (one scalar per memory state dimension).
- When `Gate ≈ 0`, the model writes new information into global memory.
- When `Gate ≈ 1`, existing information is preserved/protected from overwriting.
- `f_update` is a learned projection (via the RLA module) that maps compression tokens into the global memory space.

The global memory has a fixed budget B_G (default: 512 tokens/states), ensuring constant space regardless of total sequence length.

### Step 4: Residual Low-Rank Adapter (RLA)

Instead of full fine-tuning, CoMeT inserts low-rank adapter modules (rank r=8 by default) into each Transformer layer. These adapters project hidden states into the memory space and back, with a residual connection:

```
RLA(x) = x + A(B(x))
```

Where A ∈ R^{d×r} and B ∈ R^{r×d} are low-rank projection matrices. Ablation shows performance is stable across ranks 4-512, with r=8 being optimal (40.10 avg SCROLLS score).

### Step 5: Dynamic Soft Prompting for Next Chunk

For chunk τ+1, the global memory S_i^τ and temporary memory T_i^τ from the previous chunk are prepended to the input as a dynamic soft prompt. This allows the model to attend to compressed context from all previous chunks.

### Step 6: Layer-Level Pipeline Parallelism

For efficient distributed training on extremely long sequences:
- Instead of splitting by sequence (context parallelism, which creates large pipeline bubbles), CoMeT splits by **layer** across GPU workers.
- Each GPU owns a contiguous subset of layers (e.g., 8 layers each in a 32-layer model across 4 GPUs).
- Memory states are passed between workers via P2P communication.
- This yields a **2.7× speedup** over naive context parallelism and enables fine-tuning on 128k contexts with just 16×80GB GPUs.

## 3. Trade-offs

| Win | Loss |
|-----|------|
| **Constant O(1) memory** regardless of context length (vs O(N) for Full Attention) | Small quality gap vs FullAttn on summarization: 40.10 vs 42.23 avg SCROLLS (-5%) |
| **Linear O(N) prefill latency** (vs O(N²) for Full Attention) | Information granularity lost — model generalizes precise terms (e.g., "hierarchical phrase-based" → "phrase-based") |
| **21× inference speedup** at long context, 10× less GPU memory | Causal relationships flattened in compressed context — cannot distinguish cause from effect in "Why" questions |
| **Plug-and-play**: works on existing pre-trained LLMs without training from scratch | Multi-hop information aggregation across non-contiguous text significantly degraded |
| **Extrapolation**: trained on 32k, works at 1M+ tokens | QALT and CNLI tasks show larger gaps vs FullAttn (56.0 vs 64.2; 86.9 vs 89.1) |
| **Model-agnostic**: works on Qwen3 (4B, 14B) and Llama-3.1 (8B) | Performance gap with FullAttn on long-context subset remains substantial (GovRep: 38.6 vs 48.8) |
| **2.7× training speedup** via layer-level pipeline parallelism | No integration with episodic/test-time training memory or external knowledge bases |

## 4. Design Rationale

CoMeT occupies a deliberate middle ground between three competing paradigms:

1. **Why not compression?** Compression methods (LLMLingua, ICAE, ActivationBeacon) reduce context into shorter sequences, but under a fixed compression ratio, the compressed length still grows linearly with the original — they only improve constant factors, not asymptotic complexity. CoMeT achieves truly constant memory.

2. **Why not recurrent alternatives?** SSMs (Mamba, S4, RWKV) and Linear Attention achieve O(N) time but require training from scratch. They cannot be plugged into existing pre-trained Transformer LLMs. CoMeT's RLA adapters make it a drop-in upgrade.

3. **Why not prior finite-state Transformers?** Transformer-XL and HMT use recurrence but lack explicit gating to protect critical memories from being overwritten and treat all history uniformly. CoMeT's gated global memory explicitly decides what to preserve and what to discard.

The dual-memory design mirrors human cognition: a **short-term/working memory** (FIFO temporary memory for recent fine-grained context) and a **long-term memory** (gated global memory for distilled salient facts). The gating mechanism is the critical enabler — visualization shows gate values dropping to 0 at deep layers when encountering critical information, then locking at 1 to preserve it indefinitely.

## 5. Limitations and Failure Modes

1. **Information Aggregation Failure**: On Qasper, CoMeT fails to aggregate information from multiple non-contiguous parts of a document. Its compressed view makes it prone to finding only the first/most locally salient answer piece, missing information scattered across the text.

2. **Causal Reasoning Flattening**: The compressed memory context flattens causal chains. When asked "Why is X not effective?", CoMeT sometimes extracts the cause of a problem instead of the problem itself, unable to distinguish cause from effect.

3. **Loss of Granularity**: CoMeT retains core concepts but loses precise descriptive modifiers. Example: retrieves "phrase-based MT system" instead of the correct "hierarchical phrase-based MT system."

4. **No Episodic/External Memory**: The framework currently lacks test-time training and integration with external knowledge stores (notebooks, RAG). Authors acknowledge these as important future directions.

5. **Long-Context Summarization Gap**: Despite strong extrapolation, CoMeT still shows a meaningful gap vs FullAttn on very long summarization tasks (GovRep on >32k subset: 38.6 vs 48.8), suggesting the compressed memory is not a perfect substitute for full-context attention on tasks requiring holistic understanding.

6. **Limited Validation Range**: Only validated up to 1M tokens. Behavior beyond this is unknown. Only tested on decoder-only LLMs; encoder-decoder architectures untested.

7. **Model-Scale Dependency**: Performance relative to FullAttn improves with model scale (95.0% at 4B → 97.6% at 14B). Smaller models may show larger quality gaps.

## 6. Transfer to Lyra

**The One Idea**: CoMeT's **gated dual-memory architecture** — a FIFO temporary memory for recent fine-grained agent trajectory steps combined with a gated global memory for distilling and protecting critical long-horizon facts — is directly applicable to Lyra's agent loop context management. Lyra currently faces the problem of retaining relevant context across very long multi-turn agent trajectories without unbounded KV-cache growth. CoMeT demonstrates that training lightweight adapters (RLA, rank=8) on a fixed tiny memory budget (~2,560 tokens) can preserve 95%+ of full-context performance while achieving constant memory and 21× speedup. For Lyra specifically, the global memory could gate-protect critical user instructions, environment state changes, and tool outputs, while temporary memory maintains recent conversation turns and action-observation pairs.

**Workstream Route**: §4.2 (Memory & Context Management) — feeds directly into the long-context agent memory architecture. The layer-level pipeline parallelism strategy also feeds §4.8 (Training Infrastructure) for efficient fine-tuning of Lyra models on long agent trajectories.

| Dimension | Score | Rationale |
|-----------|-------|-----------|
| **Impact** | 5 | Constant-memory agent context is transformative for Lyra's core deployment efficiency problem |
| **Effort** | 3 | RLA adapters are low-rank (r=8), fine-tuning on 32k contexts is practical. Integration requires adapter insertion into Lyra's backbone + training on agent trajectories |
| **Tier** | **breakthrough** | Solves a first-order architectural constraint (unbounded context growth) with strong empirical evidence across 3 model families and real-world agent tasks |

**Implementation Sketch for Lyra**:
1. Insert RLA modules (rank=8) into Lyra's Transformer backbone layers.
2. Define global memory for critical persistent facts (user goal, environment state, key constraints) and temporary memory for recent turns (last N tool calls, observations).
3. Fine-tune on agent trajectories up to 32k tokens using Lyra-specific data (Terminal-Bench-style agent interactions).
4. Add gating visualization tooling to verify that critical information (e.g., user intent, safety constraints) is correctly gate-protected in global memory.
5. Deploy with chunked inference for streaming agent loops.
