# Refining embeddings with fill-tuning: data-efficient generalised performance improvements for materials foundation models

**Authors:** Matthew P. Wilson, Edward O. Pyzer-Knapp, Nicolas Galichet, Luke Dicks (IBM Research Europe / Xyme)

**Venue:** arXiv:2502.13886v1 [cs.LG], 19 Feb 2025 (preprint; no conference acceptance noted)

---

## 1. Mechanism (step-by-step)

**Core idea:** "Fill-tuning" generates a tiny continued-pretraining dataset that targets poor regions of a foundation model's embedding space, improving performance across ALL downstream tasks simultaneously — unlike standard fine-tuning which degrades out-of-distribution performance.

### Step-by-step algorithm

**Step 1 — Embedding extraction.** Take a pretrained materials foundation model (SELFIES-TED, BART-based transformer encoder-decoder). The encoder produces a 256-dim per-token embedding, projected to a 128-dim whole-sequence embedding. All roughness analysis operates on this 128-dim latent space.

**Step 2 — Similarity surface construction.** Sample 5000 points in the 128-dim embedding via Latin-hypercube sampling. For each target point, add 10 uniformly-sampled perturbation vectors (L2 norm = 0.05), decode each perturbed point to a SELFIES string, convert to Morgan fingerprints, and compute mean Tanimoto similarity between each neighbor and target. Interpolate a continuous similarity surface over the full embedding space via radial basis function (RBF) interpolation with a thin-plate kernel (smoothness = 10^-5).

**Step 3 — Frustration analysis (roughness analysis).** Decompose the similarity surface into stationary points in the full 128-dim space:
- **Minima:** Located via random initialization + gradient minimization (only positive eigenvalues of the Hessian).
- **Transition states:** Located between minima pairs using nudged elastic band (NEB) and hybrid-eigenvector following algorithms (single negative eigenvalue).

**Step 4 — Kinetic transition network (KTN).** Build a weighted graph where nodes = minima, edges = directly-connected minima pairs via a transition state. For each edge, compute the frustration F_i:

```
F_i = exp(-d(x_min, x_ts)² / (2l²)) · (f_ts - f_min)
```

where `d` = Euclidean distance, `l` = lengthscale (80.0), `f_ts` and `f_min` are the similarity values at transition state and minimum respectively. Large F_i indicates high roughness — regions where molecular similarity changes rapidly over small embedding distances.

**Step 5 — Roughness surface.** Transform frustration values into a continuous roughness surface via sum of weighted multivariate Gaussians placed along each minimum→transition state vector:

```
F = Σ_i F_i · N(μ = x_min + (x_ts - x_min)/4 | Σ = R_i Σ_i R_i^T)
```
```
Σ_i = diag(σ, δ, δ, ..., δ)
```
where σ = 0.99 (decay along frustration direction), δ = 0.25 (variance in orthogonal directions), R_i rotates the basis to align the first dimension with the frustration vector.

**Step 6 — Fill-tuning dataset generation.** Locate the 100 highest maxima on the roughness surface via basin-hopping optimization. Decode these embedding coordinates to SELFIES strings. These 100 molecules form the fill-tuning dataset.

**Step 7 — Continued pretraining.** Resume training from the base model's final checkpoint using only the 100 fill-tuning data points. Mask 15% of input tokens (same as original training). Train up to 50 epochs; select the best checkpoint by combined training + validation loss. This constitutes only 0.00001% of the original training data (O(10^9) points).

**Indirect fill-tuning variant:** Apply the fill-tuning dataset derived from the small model's latent space to continue training the larger models (medium, large). Same 100 data points, same 50-epoch protocol.

## 2. Results (real benchmark numbers)

|---------|-----------|--------|-----------|------------|----------|----------------|
| BACE    | 0.8540    | 0.8558 (+0.2%) | 0.8573 (+0.4%) | 0.8705 (+1.9%) | 0.8448 (-1.1%) | **0.8742 (+2.4%)** |
| BBBP    | 0.9057    | 0.9073 (+0.2%) | 0.9000 (-0.6%) | 0.8953 (-1.2%) | 0.9064 (+0.1%) | **0.9112 (+0.6%)** |
| ClinTox | 0.8805    | 0.8751 (-0.6%) | 0.8391 (-4.7%) | 0.8544 (-3.0%) | 0.7994 (-9.2%) | **0.8763 (-0.5%)** |

Same 100 data points from small model's latent space applied to all three model sizes:

| Task    | Small Base → FT | Medium Base → FT | Large Base → FT |
|---------|-----------------|-------------------|-----------------|
| BACE    | 0.8540 → 0.8742 (+2.4%) | 0.8628 → 0.8483 (-1.7%) | 0.8505 → 0.8793 (+2.9%) |

Key finding: The largest, most performant model (358M params, 1B training points) gains the most from indirect fill-tuning (+0.98% average).

### Baselines against which fill-tuning wins
- **Random 100 points:** Degrades ClinTox (-0.6%) and HIV (-0.5%), net negative.
- **BACE-only 100 points:** Improves BACE (+0.4%) but degrades BBBP (-0.6%), ClinTox (-4.7%), HIV (-0.3%).
- **Combined (100 from each of 4 tasks):** Degrades BACE (-1.1%), ClinTox (-9.2%).
- **Sequential (100 per task, 4 runs):** Degrades BBBP (-1.2%), ClinTox (-3.0%).

## 3. Trade-offs

| Win | Lose |
|-----|------|
| General improvement across ALL downstream tasks (no OOD degradation) | Only ~1% absolute improvement — modest gain |
| Only 100 data points needed (0.00001% of pretraining data) | Frustration analysis is computationally expensive (128-dim stationary point search with NEB) |
| Dataset transferable across model sizes (small→large indirect fill-tuning) | Requires a decoder from embedding back to input space (SELFIES strings) |
| Training cost = fine-tuning cost (50 epochs on 100 points) | Only demonstrated on one model family (SELFIES-TED, BART-based) |
| No bias toward any specific task — embedding-level improvement | Domain-specific to chemistry/materials — unclear generalization to text/code |
| Beats all baselines (random, task-specific, combined, sequential) | Roughness analysis hyperparameters (σ=0.99, δ=0.25, l=80.0) chosen without ablation |
| Fill-tuning data lies at edges/gaps of training distribution — extends model applicability | Some individual task scores still decrease (ClinTox -0.5% on small model) |

## 4. Design Rationale

**Why this approach over alternatives:**

1. **Fine-tuning degrades OOD performance.** Standard fine-tuning, LoRA, and feature-preservation methods all accept some OOD degradation as a necessary cost. Fill-tuning rejects this trade-off entirely — it improves the embedding itself rather than adapting to a task.

2. **Physics-inspired latent space analysis.** The authors extend frustration analysis (Dicks et al., 2024) — originally developed for predicting ML model performance from dataset topology — to foundation model latent spaces. This provides a mathematically principled method to identify where embeddings are "wrong" without any downstream task labels.

3. **Data quality > data quantity.** The paper demonstrates that 100 well-chosen points outperform random, task-specific, or combined datasets, providing evidence that the character of training data matters more than volume — a critical insight for data-scarce domains like scientific ML.

4. **Knowledge gap filling metaphor.** The name "fill-tuning" reflects the core analogy: the embedding has "holes" or rough patches where similar molecules are not placed close together. The algorithm fills these holes with targeted examples rather than flooding the model with task-specific data that warps the embedding elsewhere.

5. **Indirect transfer is surprising and useful.** That a dataset derived from a small model improves a larger model (+0.98%) suggests structural deficiencies persist across model scales, enabling cheaper analysis on smaller variants to benefit state-of-the-art models.

## 5. Limitations & Failure Modes

1. **Domain specificity — untested outside chemistry.** Only validated on SELFIES-TED materials foundation models with molecular string representations. Unclear whether roughness analysis translates to text embeddings, vision embeddings, or code embeddings where "decoding from latent space" is nontrivial.

2. **Requires invertible embedding.** The method needs to decode arbitrary points in the latent space back to valid inputs (SELFIES strings). For most foundation models (GPT, BERT, CLIP), there is no such decoder, limiting applicability.

3. **Modest absolute gains (~1%).** The improvement, while consistent, is small in absolute terms. Statistical significance is not reported. For production systems, the cost-benefit of implementing roughness analysis may not justify <1% gains.

4. **Computational cost of frustration analysis.** Locating stationary points in 128-dim space using NEB and hybrid-eigenvector following is expensive and scales poorly with embedding dimensionality.

5. **No comparison to parameter-efficient fine-tuning (PEFT) methods.** The paper compares only against naive baselines (random, task-specific), not against LoRA, prefix tuning, or other methods specifically designed to mitigate catastrophic forgetting.

6. **Only 4 classification benchmarks.** MoleculeNet contains many more tasks; testing on only 4 limits the "general improvement" claim.

7. **No ablation on key hyperparameters.** The lengthscale l=80.0, σ=0.99, δ=0.25, smoothness=10^-5, and 5000 sampling points are stated without sensitivity analysis.

8. **Single model architecture family.** All models are BART-based transformer encoder-decoders. No evidence the method works across architectures (e.g., encoder-only BERT variants, decoder-only GPT variants).

9. **Generated molecules are chemically unusual.** The authors note fill-tuning data shows "non-standard chemistry" and lies at edges of training distribution. Potential safety implications for molecular generation applications are not discussed.

10. **Why indirect fill-tuning works is unexplained.** The paper observes the phenomenon but does not deeply analyze why structural deficiencies persist across model scales trained on the same data.

## 6. Transfer to Lyra

### The one transferable idea

**Latent-space roughness-guided data augmentation for embedding improvement.** Lyra's RAG pipeline depends on high-quality document embeddings for retrieval. Instead of fine-tuning the embedding model on task-specific query-document pairs (which would degrade general retrieval), Lyra could apply roughness analysis to its document embedding space to identify regions where semantically similar documents are far apart (rough patches). Synthetic queries or document fragments targeting these regions could be generated and used for continued pretraining of the embedding model, improving overall retrieval quality without task-specific degradation.

### Workstream route: §4.2 — Memory & Retrieval

This directly feeds Lyra's retrieval quality improvement efforts. The fill-tuning concept recasts embedding improvement as a *data selection problem* rather than a *training objective problem* — find the worst-embedded regions and add targeted examples there.

### Scoring

| Dimension | Rating | Justification |
|-----------|--------|---------------|
| **Impact** | 3/5 | ~1% embedding improvement is meaningful but not transformative for retrieval. The core insight (roughness-guided data selection) is novel and could generalize. |
| **Effort** | 4/5 | Requires: (a) implementing frustration analysis on text embeddings, (b) building a decoder/generator to produce text from embedding coordinates, (c) integrating with existing embedding training pipeline. Significant engineering. |
| **Tier** | **investigate** | Domain transfer from chemistry to text is unproven. The decoder requirement (embedding→text) is a major blocker for standard text embedding models. Worth a small feasibility study before committing resources. |
