## 1. Mechanism

SAGE models graph memory as a **dynamic long-term memory substrate** with two coupled roles: a Memory Writer and a Graph Foundation Model (GFM)-based Memory Reader, operating in a closed self-evolution loop.

### 1.1 Memory Writer: Graph Construction via RL

The writer is a **sequential decision-making policy** W_theta. At each step t:
- **State s_t:** (query q, documents D, partial graph G_{t-1}, processed docs D^{proc}_{t-1})
- **Action a_t:** Adds entity-relation triples (u, r, v) with source anchors (u, source, d)
- **Reward:** Hybrid task reward combining three complementary signals:
  - **r_rec** (Recall): |P_k(q,G) ∩ D^+| / |D^+| — coverage of gold evidence
  - **r_pre** (Precision): |P_k(q,G) ∩ D^+| / |P_k(q,G)| — penalizes irrelevant expansion
  - **r_ded** (Deducibility): I[Judge(q, y | P_k(q,G)) = Yes] — can answer be inferred?
  - **r_ans** (Answer): max_{y'∈Y(y)} F1(ŷ, y') where ŷ = LLM(q, P_k(q,G)) — end-to-end QA alignment
  - **Hybrid reward:** r_task = (α·r_rec + β·r_pre + γ·r_ded) / (α+β+γ)
- **Repetition penalty:** ρ_rep(G) = (|T(G)| - |uniq(T(G))|) / |T(G)|
- **Training:** Clipped GRPO with trajectory return R(τ) = r_task(τ) - λ_rep·ρ_rep(G_τ) + λ_fmt·Σr^fmt_t

### 1.2 Memory Reader: GFM-based Structure-Aware Retrieval

The reader R_phi performs query-conditioned activation over the evolving graph G, outputting entity distribution, document distribution, and optional retrieval subgraph.

#### Step 1: Cognition-Inspired Structured Query Planning
Before retrieval, a planning function P_ω decomposes the raw query into rich associative probes:
```
P_ω(q) = {E_exp, A, C_rel, C_hard, τ, {(q̃_m, α_m, t_m)}^M_{m=1}}
```
Where E_exp = explicit entities, A = aliases, C_rel/C_hard = constraints, τ = answer type, q̃_m = pseudo-queries with weights α_m and types t_m. This simulates how the human brain generates multi-dimensional retrieval cues to overcome "tip-of-the-tongue" phenomena.

#### Step 2: Soft Addressing (Multi-Cue Entry Scoring)
Entity entry score s_e(q) integrates six signal types:
```
s_e(q) = λ_1·Exact(e, E_exp) + λ_2·Alias(e, A) + λ_3·max_{m≤M} cos(Emb(desc(e)), Emb(q̃_m))
        + λ_4·Type(e, τ) + λ_5·Cons(e, C_hard) + λ_6·Σ_{ξ∈NER(q)} EL(e | ξ)
```
Initial activation: p_0(e|q) = exp(s_e(q)/T_0) / Σ_v exp(s_v(q)/T_0)
Initial node representation: h^(0)_e = [p_0(e|q)]^η · (W_q·Emb(q) + W_x·x_e)

#### Step 3: Synapse-Inspired Structurally Conditioned Propagation
Instead of uniform message passing, each edge has a **vector structural gate**:
- **Node structural features:** φ(v) = [log(1+d_v), c_v, κ_v, d̄_N(v)] (degree, clustering coefficient, coreness, avg neighbor degree)
- **Edge-pair structural features:** ψ(u,v) = [|d_u-d_v|, |N(u)∩N(v)|, Jaccard(N(u),N(v))]
- **Graph-level summary:** r_G = [mean φ(v); std φ(v); dens(G)]
- **Edge structural context at layer l:** z^(l)_uv = [En(φ(u)); En(φ(v)); Ep(ψ(u,v)); Eg(r_G)]
- **Vector gate:** g^(l)_uv = 1 + δ·tanh(MLP^(l)_g(z^(l)_uv))
- **Message:** m^(l)_{u→v} = η_uv · g^(l)_uv ⊙ W^(l)_m · h^(l-1)_u
- **Update:** h^(l)_v = LayerNorm(h^(l-1)_v + PReLU(b^(l) + Σ_{u∈N(v)} m^(l)_{u→v}))

This enables three brain-like behaviors: inhibition of noisy hub edges, preservation of long-distance bridge edges, and habituation to redundant local edges.

#### Step 4: Context–Schema Dual-Channel Decomposition
- **Context channel (H_ctx):** Gated propagation on current graph G — captures immediate structural state from current writer
- **Schema channel (H_sch):** Uses cross-graph structural prompt bases {P^(l)_j}^K_{j=1} from multi-graph pre-training — captures transferable reading habits
  - ω^(l)_j = softmax_j(a^(l)/T_p), P^(l)_schema = Σ_j ω^(l)_j P^(l)_j
- **Fusion:** H(q,G) = H_ctx + β_sch·H_sch

#### Step 5: Entity-to-Document Projection
Entity scores are projected to document scores via entity-document anchoring matrix M. Uses IDF-weighted ranker. Final retrieval: P_k(q,G) = Top-K_{d∈D} s_D(d)

### 1.3 Reader Training (Two-Stage)
1. **Structural contrastive pre-training:** On multiple augmented graph views to learn transferable structural priors
2. **Supervised fine-tuning:** Weighted classification + multi-positive ranking objectives for evidence retrieval alignment

### 1.4 Self-Evolution Loop (Algorithm 1)
```
for t = 0 to T-1:
    // Writer update: fixed reader as reward environment
    for each sample x in D_train:
        Sample G graph construction trajectories from π_θt
        Obtain graph G_i and retrieve P_k(q, G_i) using f_ϕt
        Calculate return R_i
        Update writer π_θt via GRPO
    
    // Reader update: improved graphs as memory substrate
    Construct graph memories {G_x} using π_{θt+1}
    Update GFM reader f_ϕt on {G_x}
```

### 1.5 Theoretical Framework
The paper provides rigorous proofs for:
- **Proposition 1(i):** Signal–budget efficiency — soft addressing + structural gating + controlled projection jointly improve SNR and reduce top-k budget needs (Theorem B.7, B.13)
- **Proposition 1(ii):** Context–schema decomposition reduces target-graph approximation risk (Theorem C.4) and sample complexity (Theorem C.7)
- **Proposition 1(iii):** Evolution stability — under bounded graph drift, consecutive writer updates induce bounded document-score changes (Theorems E.11-E.18)
- **Proposition 9:** Writer-only updates cannot guarantee reader can read new evidence; reader-only updates cannot compensate for unwritten evidence chains — justifying the closed loop

## 3. Trade-offs

| Win | Lose |
|-----|------|
| Fastest retrieval speed (0.019-0.034s) across all benchmarks — 8-90x faster than GraphRAG | LongMemEval overall score (34.3) far behind specialized memory systems (TiMem 76.9) — not yet competitive as a full agent memory system |
| Best zero-shot NQ retrieval (R@2=82.5, R@5=91.6) — strong transfer from multi-hop QA to open-domain | Cross-domain writer transfer is weak: Base→HaluMem Precision only 0.230 vs trained 0.312; target-domain training essential |
| Self-evolution improves multi-hop QA: best average rank after 2 rounds | Additional self-evolution round can sometimes degrade (Round 1 worse than trained on some LongMemEval metrics) |
| Structural gating improves retrieval (+4.7 R@2 over uniform message passing) | Gate computation adds O(md²) worst-case complexity per layer; requires edge structural feature precomputation |
| Hybrid RL reward balances precision/recall/deducibility better than single-reward approaches | Hybrid with frozen answer API increases Deducible to 0.526 but drops Precision to 0.832 and Recall to 0.874 |
| Context–schema decomposition provides transferable priors reducing sample complexity | Dual-channel fusion requires careful β_sch tuning; schema-only reader has irreducible target-graph bias (Proposition 6) |
| Closed-loop write-read evolution via GRPO provides principled graph improvement | Training pipeline is complex: GRPO for writer + contrastive pre-training + SFT for reader + multiple evolution rounds |

## 4. Design Rationale

1. **Graph as dynamic substrate, not static index:** Unlike GraphRAG systems that use graphs only as retrieval middleware, SAGE treats the graph as a working memory object that is written, read, corrected, and self-improved. Rationale: long-term agent memory requires continuous updates, not one-time indexing.

2. **GFM reader over vanilla GNN:** Conventional GNN retrievers are tied to fixed graph distributions and generalize poorly across domains, users, and evolution stages. GFM pre-training provides transferable structural priors and lightweight calibration on new graphs. Supported by Theorem C.7: schema prior reduces sample complexity from O(dfull) to O(dres).

3. **Context–schema dual-channel decomposition:** The schema channel captures stable cross-graph reading habits (bridge recognition, community boundaries), while the context channel absorbs writer-induced graph distribution shift. Proposition 6 proves schema-only readers have irreducible bias; Theorem C.4 bounds the combined approximation risk.

4. **Hybrid RL rewards over single-reward:** Recall-only rewards encourage noise (Deducible drops to 0.502); Deduce-only rewards make writer conservative (short paths, local answer clues). Hybrid combines coverage, selectivity, and answer deducibility to mitigate individual biases.

5. **Soft addressing over anchor-only initialization:** Anchor-only initialization forces the reader to commit early to a small set of partial cues, risking missing bridge nodes outside the activated region. Soft addressing with multi-cue scoring (aliases, pseudo-queries, type constraints) activates a broader but weighted initial memory atlas.

## 5. Limitations and Failure Modes

1. **Weak agent memory performance on LongMemEval:** Overall score 34.3 vs TiMem 76.9. SAGE struggles with knowledge updates (27.8), temporal reasoning (22.8), and multi-session reasoning (12.5). The writer trained on multi-hop QA cannot capture temporal state updates, user preferences, or long-term consistency needed in agent memory.

2. **Cross-domain transfer gap:** Writer learned on HotpotQA/MuSiQue transfers poorly to agent memory domains. Base→HaluMem Precision is only 0.230. Target-domain training results improve to 0.312 but still low — suggesting fundamentally different memory structure requirements.

3. **Self-evolution non-monotonicity:** Additional evolution rounds can degrade performance on some metrics. For LongMemEval, trained→+1 round drops SS-P from 23.1→15.8 and MS from 12.5→10.7. The optimal number of rounds is task-dependent and must be tuned.

4. **Complex training pipeline:** Requires GRPO for writer, contrastive graph pre-training for reader, supervised fine-tuning, and coordinated evolution rounds. Substantial compute and engineering overhead relative to simpler retrieval baselines.

5. **Writer over-conservatism with answer feedback:** Hybrid + frozen answer API achieves highest Deducible (0.526) but Precision/Recall drop to 0.832/0.874 — writer learns to only store evidence directly supporting the answer, sacrificing broader context coverage.

6. **Structural feature computation cost:** In dense graphs, neighbor-set intersections for edge features can reach O(n³) worst-case, though O(n+m) in sparse graphs.

7. **Zero-shot SAGE not compared on all benchmarks:** The zero-shot results are limited to NQ and PopQA; missing zero-shot comparisons on multi-hop QA and agent memory tasks.

## 6. Transfer to Lyra

### The One Idea

**Self-evolving graph memory with reader-aware writing rewards.** Replace Lyra's static retrieval/memory index with a dynamic graph that improves through a write-read feedback loop: when the memory reader fails to traverse from partial cues to correct evidence (missing bridge entities, noisy hub expansion), the failure signal is fed back as an RL reward to the memory writer, which then adds/strengthens bridging edges and prunes noisy shortcuts. This creates a closed-loop memory that gets better with use — exactly what Lyra needs for long-horizon agent consistency.

### Why This Paper (Not Alternatives)

- **HippoRAG/HippoRAG 2** use static graph construction + fixed retrieval; SAGE adds the self-evolution dimension that directly addresses Lyra's need for memory that improves with agent experience
- **GraphRAG (Microsoft)** uses communities/summaries as static index; SAGE's learned structural gating is more principled for dynamically evolving graphs
- **GFM-RAG** uses GFM but without the writer-reader closed loop; SAGE's joint optimization is theoretically justified (Proposition 9: single-sided updates have irreducible bottlenecks)
- The theoretical framework (Propositions 1-9, Theorems B.7-B.13, C.4-C.7, E.11-E.18, F.1-F.5) is unusually rigorous for a systems paper and provides actionable design principles

### Implementation Sketch for Lyra
1. Extract entity-relation triples from Lyra's conversation/memory fragments using LLM-based writer
2. Build heterogeneous graph (entities, documents, temporal markers as nodes; relations, anchors as edges)
3. Implement lightweight structural gating (node degree, clustering, Jaccard edge features) on a GNN reader
4. Define reward as Recall@k of correct evidence + deducibility judge
5. Run GRPO-based writer updates using reader feedback every N interactions
6. Skip full GFM pre-training initially; use task-specific structural priors from Lyra's domain
