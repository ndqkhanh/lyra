# Collaborative Multi-Agent Scripts Generation for Enhancing Imperfect-Information Reasoning in Murder Mystery Games

**Authors:** Keyang Zhong, Junlin Xie, Hefeng Wu, Haofeng Li, Guanbin Li
**Affiliations:** Sun Yat-sen University, The Chinese University of Hong Kong (Shenzhen)
**Venue:** arXiv:2604.11741v1 [cs.AI], 13 Apr 2026

## 1. Mechanism (step-by-step, equations, algorithms)

The framework operates in two major phases: **data generation** and **model training**.

**Phase 1: Multi-Agent Script Synthesis**

Two types of agents collaborate through shared game scripts:

- **Generation Agents:**
  1. **OutlineAgent:** Constructs crime-day narrative with background, timeline, character summaries
  2. **CharacterAgent:** Elaborates detailed first-person role scripts with actions, motives, image clues in `[]` notation
  3. **CriticAgent:** Evaluates scripts on 4 dimensions: plot complexity, character development, difficulty, logical rationality; provides feedback for refinement
  4. **ClueAgent:** Generates multimodal clues (text + AI-generated images) that aid deduction without revealing culprit
  5. **RoleplayAgent:** Simulates multi-turn dialogues with role-specific behavior (murderer lies strategically, innocents tell truth)
  6. **QaAgent:** Constructs multi-hop reasoning chains and QA pairs:
     - Long Script QA: comprehension of extensive narratives
     - Text-rich Image QA: OCR-focused
     - Media-rich Image QA: spatial/diagram reasoning
     - Multi-Hop Multimodal QA: multi-step cross-modality reasoning

- **Evaluation Agents:**
  7. **ScoreAgent:** LLM-as-Judge scoring for role-specific behavior during RL training

Synthetic dataset: 34 unique Murder Mystery scripts → 1,060 long-script QA + 2,725 multimodal QA (1,249 text-rich + 1,476 media-rich)

**Phase 2: Two-Stage Agent-Monitored Training**

*Stage 1: Supervised Fine-Tuning (SFT)*
- LoRA parameter-efficient fine-tuning on Qwen2.5-VL-3B/7B-Instruct
- Standard autoregressive supervision over generated answers and reasoning traces
- Context window: 65,536 tokens; images resized to 512x512
- Trains on synthetic data + curated human-annotated data

*Stage 2: GRPO-based Reinforcement Learning*

For **unverifiable data** (Self-Introduction, Discussion — no ground truth):

S = M(R) for Self-Introduction
S = γ·M(R) + (1-γ)·S_choice(R) for Discussion

Where M(R) is the ScoreAgent's 0-10 rating of role-consistency, and S_choice(R) rewards asking the murder suspect (1.0), other players (0.5), or self (0.0).

For **verifiable data** (Long Script QA, Multimodal QA):

S = 1(α·S_correct > β) · [S_correct(A,Â) + (1-α)·S_format(R)] for Long Script QA
S = 1(α·S_correct > β) · [S_correct(A,Â) + 0.5(1-α)(S_format(R) + S_match(R))] for Multimodal QA

Where α balances correctness vs. format, β is a correctness threshold to prevent reward hacking based on format alone.

GRPO optimization (no KL penalty):
- Sample G responses R_1...R_G ~ π_θ_old(·|C, Q_i)
- Compute rewards r_i = S(R_i)
- Standardize advantages: a_i = (r_i - μ)/σ
- PPO-clipped objective: min(ratio, clip(ratio, 1-ε, 1+ε)) · a_i

## 3. Trade-offs (wins vs loses)

**Wins:**
- Scalable data generation: 34 scripts → 3,785 QA pairs with explicit reasoning chains
- GRPO RL with agent-monitored rewards bypasses need for separate reward model training
- Combined human+synthetic data outperforms either alone — complementarity confirmed
- Two-stage training (SFT→RL) consistently outperforms either stage alone
- Strong generalization: 3B variant matches or exceeds many 27B/24B open-source VLMs on perception tasks
- Multi-judge aggregation provides stable, human-aligned evaluation signal

**Loses:**
- Role-Playing (RP) scores remain low even after training (6.35/10 for 3B, 6.82/10 for 7B with slight regression) — subjective dialogue quality fundamentally hard
- This is a VLM training paper, not an agent architecture paper — the multi-agent component is for data generation only, not runtime orchestration
- Partial human verification still required for image-clue alignment in WhodunitBench
- Simulated Murder Mystery simplifies real-world imperfect-information scenarios (judicial, business negotiation)
- No direct measurement of cost for synthetic data generation (Gemini 2.5Pro API calls)
- CMD (Case Murder Detail) absolute scores remain low: 34.25/100 for 3B, 36.18/100 for 7B

## 4. Design Rationale (why this approach)

**Why Murder Mystery as testbed:** The authors argue that Murder Mystery is the minimal tractable environment capturing all critical elements of imperfect-information reasoning: role-asymmetric information (murderer has private knowledge), deception (murderer lies strategically), multi-hop multimodal inference (text clues + image clues + dialogue history), and social interaction. It is simpler than full judicial or business settings but preserves the core challenges.

**Why multi-agent data synthesis:** Manual creation of high-quality murder mystery scripts is expensive and does not scale. Multi-agent collaboration with strong LLMs (Gemini 2.5Pro) produces diverse, logically consistent scripts with explicit reasoning chains. The generation-evaluation agent split ensures quality through the CriticAgent feedback loop.

**Why two-stage training (SFT→GRPO):** SFT establishes basic role-playing and reasoning capabilities from synthetic data. But SFT alone cannot optimize for the nuanced, context-dependent behaviors required (strategic lying as murderer, evidence-based questioning as innocent). GRPO with ScoreAgent rewards directly optimizes for role-consistent behavior without needing ground-truth labels for subjective dimensions.

**Why correctness threshold β in GRPO rewards:** The 1(α·S_correct > β) gating prevents reward hacking — without it, models would learn to output well-formatted but incorrect answers. The threshold forces models to achieve minimum correctness before format rewards apply.

**Why multiple LLM judges:** Single-judge evaluation introduces model-specific biases. Aggregating across DeepSeek-R1, GPT-4o, and Gemini-2.5-Pro produces scores that correlate with human judgment (Spearman ρ = 0.71), providing reliable RL reward signals.

## 5. Limitations & Failure Modes

1. **Domain specificity:** Trained and evaluated only on Murder Mystery. Transfer to other imperfect-information domains (negotiation, diplomacy, courtroom) is untested
2. **Synthetic data quality ceiling:** Generated scripts are bounded by Gemini 2.5Pro capability. Logical inconsistencies or boring plots from the generator propagate to the training data
3. **Role-Playing regression at 7B:** 7B model RP score slightly decreased (7.11→6.82), suggesting larger scale does not help subjective dialogue quality — and may even hurt it
4. **Partial human dependency:** Image-clue alignment in WhodunitBench requires human verification; the pipeline is not fully automated
5. **GRPO without KL penalty:** Removing KL divergence term from standard GRPO may cause the policy to drift too far from the base SFT distribution, risking catastrophic forgetting
6. **Context window pressure:** 65,536 token context with 5-82 images per script at 512x512 creates significant memory and compute requirements
7. **Scalar reward oversimplification:** Compressing multi-dimensional role-playing quality into a single scalar score loses nuance; different dimensions may have conflicting optima
8. **Judge model cost:** Running 3 separate judge models for RL reward computation adds significant API cost during training

## 6. Transfer to Lyra (one idea + route + Impact/Effort/Tier)

**Idea:** Apply the **Multi-Agent Script Synthesis + CriticAgent Feedback Loop** pattern to generate diverse, high-quality training/evaluation data for Lyra's reasoning capabilities. Instead of Murder Mystery, generate complex multi-turn Lyra task scenarios with tool use, deception (e.g., adversarial user inputs), and multi-hop reasoning — using a generation-evaluation agent split to ensure quality.

**Route:** §4.2 (Agent Architecture) and §4.7 (Evaluation Harness) — extend the existing evaluation framework with a scenario generation pipeline where specialized agents collaboratively produce tasks with explicit reasoning chains, verified by CriticAgent

**Impact:** Medium - would dramatically scale Lyra's evaluation dataset from dozens to thousands of diverse scenarios with known ground-truth reasoning chains, enabling better regression testing and capability measurement

**Effort:** Medium - requires prompt-engineering multiple generation/evaluation agents (can reuse Lyra's existing LLM backend), defining scenario schema, and building CriticAgent evaluation rubric

**Tier:** Tier 2 (2-4 months) — builds on existing evaluation infrastructure, no new model training required, leverages existing LLM API access
