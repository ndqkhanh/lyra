## 1. Mechanism (step-by-step)

Proteus is a closed-loop, grey-box, self-evolving red-team framework that measures **adaptive leakage** in agent skill auditing — the residual risk after a budgeted attacker iteratively revises a malicious skill until it passes audit AND produces verified runtime harm.

### 1.1 Formal Problem

**Skill artifact:** `s = (o, τ, c, κ, d)` — a 5-axis tuple:
- **o**: Attack objective (7 oracle categories: data exfiltration, persistence, privilege escalation, cleanup-poisoning, guidance injection, supply-chain abuse, cross-skill chaining)
- **τ**: Topology (single skill or k-chain)
- **c**: Code artifact (entry scripts, bundled binaries)
- **κ**: Side-effect channel (which sensor path triggers, e.g., file write, network egress, SUID change)
- **d**: Documentation (markdown body, YAML frontmatter)

**Adaptive Leakage (ALB):**
```
ALB(Blue, M, θ) = E_{s0~Dseed}[Pr_θ(∃t ≤ T: b_t ∧ ℓ_t | s0, M, Blue)]
```
where `b_t = 1` iff audit passes (no severity ≥ high finding), `ℓ_t = 1` iff sandbox oracle confirms targeted side-effect.

### 1.2 Pipeline Architecture

Each round follows a **defender-agnostic audit → sandbox → oracle** contract:

1. **Red-team mutator agent** (LLM Tool-Use API loop) receives structured findings from prior round as in-context side-information
2. Agent applies two-stage **Reason → Mutate** operator:
   ```
   (h_t, a_t) = Reason_θ(H_{<t}, F_{<t})    // natural-language diagnosis
   s_t = Mutate_θ(s_{t-1}, a_t, S_k)        // tool-call sequence
   ```
3. Mutated variant traverses the round contract:
   - **Audit**: BluePort adapter normalizes auditor output to `{layer, reason_code, category, severity, evidence, explanation}`
   - **Sandbox**: Containerized OpenClaw 2026.3.24 executes skill against target backbone M
   - **Oracle**: Per-objective rule-based judges verify lethality from sandbox observables
4. **Feedback quadruple** `⟨b_t, ℓ_t, F_t, R_t⟩` closes loop:
   - `b_t` = bypass verdict
   - `ℓ_t` = lethality verdict
   - `F_t` = structured finding list
   - `R_t` = runtime trace/advice

### 1.3 Graph-Guided Chain Composition (τ axis)

- Crawls ClawHub into a **~47k-node skill graph**
- 16 typed `source_tag → sink_tag` risk rules (e.g., `credentials → network_egress = data_exfiltration`)
- Edges admitted only when `cos(emb(u_theme), emb(v_theme)) ≥ 0.30` (theme similarity constraint)
- Multi-hop chains enumerated via `networkx.all_simple_paths` up to `max_hops = 5`
- **thematic-chain-insert** operator: Inserts benign-looking bridge skill whose declared theme makes `source → bridge → sink` read as coherent workflow

### 1.4 Three-Layer Evolution

- **Layer 1 (Free Discovery, S1)**: Search over `(c, κ, d)` with fixed `(o, τ)` until first `b ∧ ℓ` success; uses T=5 round budget
- **Layer 2 (Path Expansion, S2)**: Off-budget; fix `(o, τ)` but find alternative `(c, κ)` implementations
- **Layer 3 (Surface Expansion, S3)**: Off-budget; release `(o, τ)` subject to `SharedMotif ≥ 2-axis` structural gate (e.g., κ overlap + tool-chain-prefix overlap)

### 1.5 Mutation Operators (12 total)

Key operators include: `reword`, `reframe`, `retarget`, `reorder`, `substitute`, `condition-hide`, `obfuscate`, `code-offload` (move shell out of SKILL.md into entry script), `code-obfuscate` (language-switch, eval-base64), `purpose-coherent-embed` (rewrite payload as natural sub-feature of sink purpose), `thematic-chain-insert`, `operational-concreteness` (name literal shell primitives so agent actually executes).

### 1.6 Verbal Gradient (not Scalar RL)

The agent consumes structured findings as in-context side-information rather than scalar reward:
```
RL:     θ ← θ + α∇_θ E[r_t]
Ours:   s_t = Mutate_θ(s_{t-1}, Reason_θ(H_{<t}, F_{<t}))
```
Structured `F_t` includes category, confidence, evidence pointer — enabling one-forward-pass diagnosis + strategy selection.

### 1.7 Metrics

- **ASR@5**: Fraction of n=20 seeds producing ≥1 `b ∧ ℓ` within T=5 rounds
- **LCS** (Learning Curve Slope): OLS fit of ASR@t = αt + β; α is LCS (ceiling ≈ 0.30 at T=5; values > 0.10 = strong learning)
- **SDG** (Strategy Diversity Growth): Cumulative count of distinct mutation-operator sets across rounds

## 3. Trade-offs

| Win | Lose |
|---|---|
| 40–90% ASR@5 across auditors, far exceeding baselines (0–43%) | Assumes greybox attacker model — closed-source commercial auditors with no finding output would degrade this to upper bound only |
| Structured findings as side-information yields ~11× LCS over scalar feedback | Both mutators (DeepSeek-V4-Pro, Kimi-2.6) from same Chinese ecosystem; GPT/Claude-class mutator results unknown |
| 87.7% cross-auditor transfer (AIG→SV) without re-mutation | One-directional only; symmetric auditor-agnosticism unproven |
| Chain topology (τ) is load-bearing — forcing τ=single drops ASR from 80%→0% | Multi-skill chains increase attack complexity and detection surface |
| Per-objective oracles provide strict, fs-confirmed lethality verification | Rule-based oracles may miss nuanced attack objectives not in the predefined 7-category taxonomy |
| 438 ★ variants generated with $125 total API spend | Seed selection uses same graph-guided chain composition as mutator (coupling concern); holdout-seed check left for future work |
| Strategy diversity grows with audit-floor strictness (+6.0/round on hard AIG) | Higher diversity = more tool calls = higher compute cost |
| Reproducibility via released harness/oracle/schema artifacts | Concrete bypass templates and full mutator prompts withheld for safety |
| Static auditor that doesn't adapt — measures snapshot risk | Arms-race dynamics (auditor learns, attacker re-evolves) out of scope |
| Co-mutation of code + documentation + topology yields 8× improvement over doc-only rewrite (PyRIT) | n=20 seeds per cell limits statistical power on per-category breakdowns |

## 4. Design Rationale

**Why this approach over alternatives:**

1. **Greybox over blackbox**: Open-source auditors publish audit code and rule sets publicly. Any skill author can locally reproduce structured findings their submissions would receive. Single-round evaluations of fixed artifacts are therefore systematically underestimating residual risk. Proteus exploits this realistic channel.

2. **Structured side-information over scalar reward**: The paper provides extensive empirical justification (Tables 2 ≈§B.3). Collapsing audit findings to scalar `b_t` drops LCS by ~11× (0.160→0.014). Structured categories, reason codes, and evidence pointers let the LLM mutator perform one-forward-pass "diagnosis + strategy selection" rather than requiring thousands of RL rollouts to estimate a gradient for a non-differentiable oracle.

3. **5-axis over prompt-only search**: Prior red-teams search over prompts/rules — but skill packages expose dual attack surface (execution via c/κ/τ + context via d). The ablation shows τ=single drops ASR 80%→0%, proving the chained-topology axis is load-bearing.

4. **Graph-guided chain composition over free LLM imagination**: Walking a ~47k-node graph with theme-similarity ≥0.30 constraint ensures synthesized chains look like what the auditor itself would enumerate, making them adversarial in the structural sense.

5. **Deployment-level success (b ∧ ℓ) over audit-verdict-only**: A skill that passes audit but never actually executes its payload is a measurement artifact, not a security event. The round contract's strict `b ∧ ℓ` filter ensures only deployment-level lethal skills count.

## 5. Limitations & Failure Modes

1. **Greybox assumption**: Requires attacker to read structured audit findings between rounds. Fully closed commercial auditors with no per-skill explanation degrade this side-channel. Current results are then an **upper bound** rather than point estimate of adaptive leakage.

2. **Limited auditor/target coverage**: Only 2 auditors (SkillVetter, AIG), 2 target backbones (GPT-5.4-mini, GLM-5), 2 mutators (DeepSeek-V4-Pro, Kimi-2.6). Unknown generalizability to Claude/Gemini ecosystems.

3. **Mutator model monoculture**: Both mutators from Chinese frontier-model ecosystem. Whether GPT-4/Claude-class mutators yield similar leakage is open.

4. **Static auditor assumption**: Modeled auditor does not adapt to attacker traces. Real-world arms races (auditor learns from Proteus traces, attacker re-evolves) are out of scope, meaning results measure snapshot vulnerability.

5. **Seed-mutator coupling**: Seed selection uses same graph-guided chain composition as mutator side. Holdout-seed baseline not performed. Could inflate ASR relative to fully independent seed selection.

6. **Rule-based oracles**: May miss nuanced objectives beyond the 7-category taxonomy. False-negative lethality judgments possible for novel attack types.

7. **Small sample sizes**: n=20 per phase-1 cell; n=57 for cross-auditor test. 95% CIs are wide (e.g., 40.0% ASR has CI [21.9%, 61.3%]).

8. **SharedMotif gate unablated**: Fixed ≥2-axis threshold over manually chosen motif set; contribution bounded above by current setting.

9. **Supply-chain seeds (SEED-09, SEED-17)**: Universal hard misses — never reached ★ within T=5 across any AIG cell, revealing a blind spot in the current mutation operator catalog for supply-chain attack types.

## 6. Transfer to Lyra

### The ONE transferable idea

**Adversarial self-play as an evaluation methodology for multi-layer defense stacks.** Proteus demonstrates that a single-layer audit verdict is insufficient — true security measurement requires a closed-loop attacker that consumes structured findings as side-information across rounds. For Lyra, this translates directly to evaluating plug-in/skill safety: instead of running a one-shot safety classifier on Lyra extensions/plugins/tools, implement a self-play loop where a red-team agent iteratively rewrites a malicious extension against Lyra's audit→sandbox→oracle pipeline, consuming structured reason codes as feedback. This reveals the `b ∧ ℓ` gap — the deployment risk invisible to single-shot audits.

The core insight is architectural: **fail-open manifests when the feedback channel between audit findings and the attacker is richer than scalar accept/reject.** Lyra's extension safety should be measured via adaptive leakage (closed-loop), not static audit accuracy (open-loop).

### §4 Workstream Route

**§4.1 (Safety & Alignment — Adversarial Robustness & Red-Teaming sub-stream)**
This is a direct match: the workstream covers adversarial evaluation, safety pipelines, and robustness measurement. Proteus provides both the measurement methodology (round contract, adaptive leakage) and the practical implementation patterns (BluePort adapter, per-objective oracle, structured feedback channel) that Lyra can adopt for its extension/plugin ecosystem.

### Impact/Effort/Tier

- **Impact: 4** — Lyra has a nascent extension ecosystem (ClawHub-style if adopted). Adaptive leakage measurement would be a differentiating safety claim and a practical hardening tool. The transfer is methodological (not code-level), making it broadly applicable.
- **Effort: 4** — Requires building: (a) a BluePort-style adapter for Lyra's extension audit layer, (b) per-objective oracles for Lyra's extension capability space, (c) a containerized sandbox with honeypot sensors, (d) a feedback-driven mutator loop. Substantial engineering but well-specified by the paper.
- **Tier: breakthrough** — Current LLM ecosystem has no standardized adaptive leakage measurement for agent extensions/plugins. Being first to adopt this as an evaluation standard for a marketplace would be a genuine differentiation. The paper's open-source release (audit harness, oracle specs, sandbox config) provides a clear implementation template.
