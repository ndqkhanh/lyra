# HAGE: Harnessing Agentic Memory via RL-Driven Weighted Graph Evolution

**Authors**: Dongming Jiang, Yi Li, Guanpeng Li, Qiannan Li, Bingzhe Li (UT Dallas, University of Florida, UC Davis)
**Venue**: arXiv preprint, 2026 (2605.09942v1)
**Code**: https://github.com/FredJiang0324/HAGE_MVPReview

## 1. Mechanism

HAGE reconceptualizes agentic memory retrieval as **sequential, query-conditioned traversal** over a weighted multi-relational memory graph, trained end-to-end via reinforcement learning.

### Step 1: Graph Construction
Memory is organized as a directed multigraph G_t = (N_t, E_t). Edges are decomposed into four relation-specific subsets:
```
E_t = E_temp ∪ E_sem ∪ E_causal ∪ E_ent
```
Each Event-Node n_i = ⟨c_i, τ_i, v_i, A_i⟩ where c_i is content, τ_i is timestamp, v_i ∈ R^d is a dense embedding (all-MiniLM-L6-v2), and A_i is metadata.

### Step 2: Trainable Edge Features
Each edge (i,j) carries a trainable relation feature vector e_ij ∈ R^R (R=4), initialized either from cached LLM heuristic scores or as one-hot vectors:
```
e_ij^(0) = [s_temp, s_sem, s_causal, s_ent]^T
```

### Step 3: Query-Conditioned Routing
Given query q:
1. **Query Analysis**: LLM classifier identifies relational intent T_q and produces dense embedding q⃗
2. **Anchor Identification**: Fusion of multiple signals to find entry points into the graph
3. **Edge Feature Modulation**: Edge features are enriched with query context:
   ```
   ẽ_ij = e_ij ⊙ g(q)    // g(q) is an LLM-derived gating vector
   ```
4. **Structural Weight via QueryRouter MLP**:
   ```
   w_ij(q) = softplus(MLP([q⃗; ẽ_ij]))
   ```
5. **Transition Score** (additive combination):
   ```
   S(n_j | n_i, q) = λ·cos(v_j, q⃗) + (1-λ)·w_ij(q)
   ```
   This additive form ensures structurally critical but semantically distant "bridge nodes" can still be traversed.
6. **Traversal Policy**:
   ```
   π(n_j | n_i, q) = exp(S(n_j | n_i, q)) / Σ exp(S(n_k | n_i, q))
   ```

### Step 4: RL-Based Joint Optimization (Co-Evolutionary Training)

**MDP Formulation**:
- State: current node n_i, query embedding q⃗, visited-node mask V_t
- Action: select neighbor n_j
- Termination: target evidence reached, dead end, or hop budget H_max exhausted

**Reward**:
```
r_t = r_hit_t - λ_step·r_step_t - λ_timeout·r_timeout_t
```
Where r_hit rewards retrieving target evidence nodes (matched against ground-truth answers).

**Policy Gradient** (REINFORCE with baseline):
```
∇_θ J(θ) ≈ E[(G_t - b(s_t)) · ∇_θ log π_θ(a_t | s_t)]
```

**Anchor Regularization** (to prevent feature drift):
```
L_anchor = λ_anchor · Σ ||e_ij - e_ij^(0)||²₂
```
Total loss: L = -J(θ) + L_anchor

**Asymmetric Learning Rates**: η_router = 10⁻³, η_edge = 10⁻⁴ (router adapts faster than edge features, preventing instability).

### Step 5: Context Synthesis
Retrieved nodes are re-ordered (temporally, causally, or by score) and serialized into compact context for the downstream LLM, truncated at context budget.

### Key Hyperparameters
| Parameter | Value |
|-----------|-------|
| Hop budget H_max | 5 |
| Hit reward R_hit | 10.0 |
| Step penalty λ_step | 0.05 |
| Timeout penalty λ_timeout | 1.0 |
| Discount γ | 0.99 |
| Baseline decay β | 0.99 |
| Anchor regularization λ_anchor | 1.0 |
| Router LR η_router | 10⁻³ |
| Edge LR η_edge | 10⁻⁴ |
| Cross-validation | 5-fold, sample-level |

## 2. Results

### LoCoMo Benchmark (Ultra-Long Conversational Memory)

**With gpt-4o-mini backbone** (LLM-as-a-Judge, 0-1 scale):
| Method | Multi-Hop | Temporal | Open-Domain | Single-Hop | Adversarial | **Overall** |
|--------|-----------|----------|-------------|------------|-------------|------------|
| Full Context | 0.468 | 0.562 | 0.486 | 0.630 | 0.205 | 0.481 |
| MAGMA (best baseline) | 0.528 | 0.650 | 0.517 | 0.776 | 0.742 | 0.700 |
| **HAGE** | 0.547 | **0.667** | 0.497 | **0.797** | **0.839** | **0.739** |

Overall improvement: +5.6% over best baseline (0.700 → 0.739). Largest gain on Adversarial: +9.7pp (0.742 → 0.839).

**With Qwen2.5-3B backbone**:
| Method | Overall |
|--------|---------|
| MAGMA (best baseline) | 0.499 |
| **HAGE** | **0.548** |

Overall improvement: +9.8% over best baseline with the smaller model.

### HotpotQA (Distractor Setting, Non-Conversational Multi-Hop QA)

| Method | gpt-4o-mini F1 | gpt-4o-mini LLM Score | Qwen2.5-3B F1 | Qwen2.5-3B LLM Score |
|--------|---------------|----------------------|---------------|----------------------|
| MAGMA | 0.640 | 0.807 | 0.337 | 0.424 |
| **HAGE** | **0.678** | **0.824** | **0.429** | **0.527** |

F1 improvement with gpt-4o-mini: +3.8pp (0.640 → 0.678). Generalizes beyond conversational memory.

### System Efficiency (LoCoMo, gpt-4o-mini)

| Method | Avg. Score | Tokens/Query (K) | Latency (s) |
|--------|-----------|------------------|-------------|
| MAGMA | 0.700 | 3.37 | 1.72 |
| A-MEM | 0.580 | 2.62 | 2.26 |
| **HAGE** | **0.739** | 3.82 | 2.17 |

HAGE achieves highest accuracy at 3.82K tokens/query and 2.17s latency — modest overhead (13% more tokens vs MAGMA, 26% more latency) for significant accuracy gain.

### Ablation Study (LoCoMo, Judge Score)

| HAGE Variant | Judge | F1 |
|-------------|-------|-----|
| Static Edge | 0.698 | 0.462 |
| LLM Scorer Edges | 0.712 | 0.500 |
| Trainable Edge (only) | 0.724 | 0.514 |
| Trainable Router (only) | 0.713 | 0.502 |
| **Full HAGE** | **0.739** | **0.548** |

Edge learning and router learning are complementary: Full HAGE > either alone.

## 3. Trade-offs

| Win | Lose |
|-----|------|
| +5.6% overall accuracy on LoCoMo vs strongest baseline | +13% token overhead vs most efficient high-performer (3.82K vs 3.37K) |
| +9.7pp on Adversarial queries (query-adaptive routing excels) | +26% latency vs MAGMA (2.17s vs 1.72s) |
| Consistent gains across both strong (gpt-4o-mini) and weak (Qwen2.5-3B) backbones | Requires 5-fold training per deployment (not plug-and-play) |
| Generalizes to non-conversational multi-hop QA (HotpotQA) | Only evaluated on 2 benchmarks; unknown on procedural/document-grounded tasks |
| Co-evolutionary training discovers efficient traversal paths (≤5 hops) | Training needs ground-truth evidence annotations for reward signal |
| Edge features learn query-dependent utility without manual feature engineering | LLM dependency for query analysis introduces cost at both train and inference time |

## 4. Design Rationale

The core insight is that **memory retrieval is a sequential decision problem, not a static lookup**. Prior graph-based memory systems (GraphRAG, AriGraph, GAM, EMG) build expressive relational structures but access them through fixed edge weights, type-level heuristics, or single-shot similarity search. These fail when the utility of a connection is query-dependent (e.g., a temporal edge is essential for sequence questions but noise for entity-centric queries).

HAGE replaces hand-designed scoring with:
1. **Learnable edge features** that evolve to encode traversal-relevant signals from downstream rewards
2. **Query-conditioned routing** that dynamically modulates which relational dimensions matter for each query
3. **RL-based co-evolution** where edge features and router mutually reinforce — edges learn what patterns predict useful transitions, the router learns to exploit those patterns

The additive transition score (semantic similarity + structural weight) ensures bridge nodes — semantically distant but structurally critical — remain traversable, unlike pure embedding similarity approaches. The anchor regularization prevents catastrophic feature drift during co-evolution.

## 5. Limitations & Failure Modes

1. **Narrow benchmark coverage**: Only LoCoMo (conversational) and HotpotQA (multi-hop QA). Performance on procedural reasoning, document-grounded tasks, or real-time streaming memory unknown.
2. **LLM dependency cascade**: Query analysis (relation intent classification) and evaluation (LLM-as-a-Judge) both require instruction-tuned LLMs. Errors in intent classification directly degrade routing quality; the paper does not report classifier accuracy independently.
3. **Training requirement**: Requires annotated evidence nodes (ground-truth token matches) for reward computation. Cannot train on arbitrary unlabeled memory corpora.
4. **Privacy/retention concerns**: Persistent per-user memory graphs accumulate personal data; RL-optimized policies may surface information reflecting training data biases.
5. **No streaming/online evaluation**: All experiments use static datasets. Behavior under continual memory growth and online graph updates is uncharacterized.
6. **Fixed 4-relation scheme**: Hardcoded temporal/semantic/causal/entity relation types may not capture all relevant relational signals for domain-specific applications.
7. **Reliance on 5-hop budget**: Queries requiring >5 hops of reasoning would be truncated; ablation on hop budget sensitivity is absent.

## 6. Transfer to Lyra

**The one transferable idea**: Replace Lyra's static/flat memory retrieval with a **query-conditioned, RL-trainable weighted graph traversal mechanism** where edge importance is not fixed but dynamically modulated by the current query's relational intent.

**Application**: Lyra's §4.2 (Memory Subsystem) workstream. Instead of flat embedding similarity search over conversation history, maintain a multi-relational memory graph with temporal, semantic, causal, and entity edges. Use an LLM classifier to identify query intent, a lightweight router MLP to compute query-conditioned edge weights, and softmax-based traversal to retrieve the most structurally relevant evidence path.

This would directly improve Lyra's long-horizon reasoning accuracy — particularly for multi-turn conversations where temporal ordering and causal relationships matter, and for adversarial queries where the right structural bridge (not just semantic similarity) is critical.

**Impact**: 4 (directly addresses Lyra's memory bottleneck for long-context agent sessions)
**Effort**: 4 (requires graph construction pipeline, RL training infrastructure, and router MLP)
**Tier**: **breakthrough** — RL-trained query-adaptive graph memory is a step-change improvement over the flat retrieval most agents use today
