## 1. Mechanism

Vision-Zero is a label-free, domain-agnostic self-play framework for post-training VLMs. It constructs a visual "Who Is the Spy?" game and alternates between self-play and RLVR (Iterative-SPO) to achieve sustained performance improvement.

### 1.1 Game Environment

**Setup:** Each round has `nc` civilians and 1 spy. Civilians receive an original image `Ic`; the spy receives a blank image `Is`. The game has two stages:

**Clue Stage:** Each player produces a one-sentence description of their image (`uk ~ πθk(· | Ik, h)`). Clues are visible to subsequent players; thought processes are hidden. The spy must infer hidden visual content from civilians' clues and generate plausible descriptions. Civilians must provide clear clues without leaking too much information.

**Decision Stage:** Civilians analyze all clues and vote for the spy. The spy does not vote. Players may answer "n/a" if uncertain. Reasoning and votes remain private.

### 1.2 Self-Play Policy Optimization (Clue Stage)

**Zero-Sum Reward** (Equation 1):
```
rs^clue = -β(vs - v̄c)
rcj^clue = (β/nc)(vs - v̄c) - λ(vcj - v̄c)
```
Where `vs` = votes spy received, `vcj` = votes civilian j received, `v̄c` = average civilian votes, `β` controls spy-civilian competition intensity, `λ` penalizes behavioral inconsistency among civilians. Total reward between spy and civilians sums to zero.

**Role-Advantage Estimation (RAE)** (Equation 2):
```
bs = α·bs + (1-α)·rs^clue
bc = α·bc + (1-α)·(1/nc)∑ r_cj^clue
A_k^clue = r_k^clue - b_k
```
RAE tracks moving averages of role-specific rewards and subtracts them as baselines, eliminating information asymmetry between roles. Critical: without RAE, performance drops below baseline (negative gains, Table 13).

**Objective** (Equation 3): KL-regularized policy gradient with zero-sum unbaselined returns to promote equilibrium-seeking.

### 1.3 RLVR in Decision Stage

**Discrete Reward** (Equation 4):
```
rc_i^dec = +1  if vote is correct
rc_i^dec = -0.5 if "n/a"
rc_i^dec = -1  if wrong
```
Encourages well-reasoned inference; penalizes guessing less than wrong answers.

**Group Normalization** (Equation 5):
```
A_ci^dec = (r_ci^dec - μr) / (σr + ε)
```
Removes round-specific difficulty by normalizing rewards within each batch.

**Objective** (Equation 6): GRPO-style advantage-weighted log-likelihood with KL regularization.

### 1.4 Iterative-SPO (Alternating Training)

The core algorithm alternates between Clue Stage (self-play) and Decision Stage (RLVR):

**Phase switching with hysteresis** (Equations 7-10):
- Maintain exponential moving averages: `acc̄_t = ρ·acc̄_{t-1} + (1-ρ)·acc_t`, `nā_t = ρ·nā_{t-1} + (1-ρ)·na_t`
- **Decision→Clue:** When `acc̄_t ≥ 0.9` AND `nā_t ≤ 0.1` (spy too easy to identify → increase difficulty)
- **Clue→Decision:** When `1-acc̄_t ≥ 0.4` OR `nā_t ≥ 0.5` (spy too hard to identify → strengthen decision-maker)
- Minimum dwell time `Kmin = 5` iterations per stage prevents chattering
- Per-iteration loss: `Lt = mt·L^clue(θ) + (1-mt)·L^dec(θ)`

**Data:** 2K CLEVR synthetic images (GPU-rendered, ~6 hours on A100), 1K ChartQA images (GPT-4o JSON extraction + Python re-plotting), 1K real-world images from ImgEdit. All label-free.

**Hyperparameters:** nc=4 civilians, β=λ=0.1, α=ρ=0.95, τ_clue=τ_dec=0.04 (KL weights), τ_acc↑=0.9, τ_err↑=0.4, τ_na↑=0.5, τ_na↓=0.1, Kmin=5, batch_size=128, 100 iterations, learning_rate=1e-5, DeepSpeed ZeRO-3, FlashAttention-2.

## 3. Trade-offs

| Win | Loss |
|-----|------|
| Zero human labeling cost — eliminates multimodal annotation bottleneck | Requires high-quality image editors or rendering pipelines (CLEVR, GPT-4o JSON→Python chart plotting) |
| Domain-agnostic: same framework works on CLEVR, charts, real-world images | Limited to domains where paired/edited images can be generated; hard for medical, scientific, remote sensing |
| 3.3-6.4× training efficiency over GRPO with better final accuracy | Multi-round interactions add implementation complexity (dynamic prompt templating, role assignment) |
| Mitigates cross-capability negative transfer (simultaneously improves reasoning, chart, vision tasks) | Performance gain on vision-centric tasks is modest (+0-2.7%) compared to reasoning gains (+3-4%) |
| Iterative-SPO prevents self-play equilibrium collapse | Hyperparameter-heavy: 10+ thresholds (β, λ, α, ρ, τ_clue, τ_dec, 4 stage-switch thresholds, Kmin, P) |
| RAE module critical — without it, performance drops below baseline (37.4 vs 41.1 avg, -3.7%) | RAE introduces additional hyperparameters and moving-average state |
| Achieves SOTA on 7B scale without task-specific datasets | Only tested up to 14B; scaling behavior to larger models unknown |
| Robust to partial editing failures (20% noise → only 0.2% avg drop) | Framework currently single-image only; video/multi-image/3D unsupported |

## 4. Design Rationale

1. **Why self-play for VLMs:** Human annotation for multimodal data is extraordinarily expensive ($60K+ per dataset, 250K+ annotation hours). Self-play eliminates this entirely while removing the knowledge ceiling imposed by human-generated supervision. The paper explicitly addresses the gap: self-play has succeeded in Go, Chess, Dota 2, and recently LLMs (SPIRAL, Absolute Zero), but extending to VLMs requires joint vision-language game design — which prior work had not solved.

2. **Why "Who Is the Spy":** Four design criteria for an ideal self-play game: (a) skills should align with target tasks, (b) scalable difficulty, (c) diverse and complex, (d) no external data needed. Existing games like Sudoku fail criteria (a) and (c). The social deduction game compels strategic reasoning across multiple roles, requires visual understanding, inference, and communication — all aligning with general VLM capabilities.

3. **Why Iterative-SPO:** Pure self-play reaches local equilibrium (known result from game theory; Yao et al. 2023, Balduzzi et al. 2019). Pure RLVR saturates once the question set is mastered. Alternating between them introduces supervisory signals that stabilize training and prevent role collapse/divergence. The hysteresis thresholds prevent chattering between stages.

4. **Why RAE:** Spy and civilians have asymmetric information (image vs blank), so win probability is inherently role-biased. Without RAE, the model gets negative performance gains (Table 13: 37.4 avg vs 41.1 base). RAE tracks a moving average per-role reward as baseline, ensuring gradients reflect relative improvement rather than role luck.

## 5. Limitations & Failure Modes

1. **Editor dependency:** Framework relies on image editors to produce differentiated image pairs. Application limited in specialized domains (medical imaging, scientific charts, remote sensing) where such editors are unavailable or unreliable.

2. **Single-image only:** Current design handles single-image observations with pairwise edits. Cannot handle extended video, complex multi-image contexts, or interactive 3D environments without significant redesign.

3. **Scale ceiling untested:** Only evaluated on 7B-14B models. Scaling behavior to larger models (32B, 72B, proprietary) is unknown.

4. **Data diversity bound by source:** Performance gains depend on diversity of input images. CLEVR provides structured reasoning but limited real-world transfer. Chart gains strongest when trained on chart data — domain-specific data needed for specialized capabilities.

5. **Hyperparameter sensitivity:** 10+ interdependent thresholds and coefficients tuned empirically. Robustness across model families/models sizes not systematically studied.

6. **Game balance sensitivity:** If spy detection is too easy (civilians dominate) or too hard (spy dominates), training signal degenerates. Iterative-SPO mitigates but doesn't eliminate this vulnerability.

7. **No explicit safety/alignment consideration:** Self-play optimizes for game-winning behavior; undesired strategies (deception, manipulation) could emerge without explicit safety constraints.

8. **Renderer cost for specialized domains:** CLEVR rendering is cheap (~6 GPU-hours), but chart data required GPT-4o JSON extraction + Python re-plotting pipeline — still low cost but not zero-touch.

## 6. Transfer to Lyra

**The One Idea:** Use self-play between multiple Lyra agent instances playing an asymmetric visual reasoning game to generate high-quality training data for Lyra's multimodal reasoning capabilities without human annotation. Specifically: deploy multiple Lyra instances in a "Who Is the Spy"-style game where one instance sees a modified/perturbed document/screenshot and others see the original. The agents must describe and vote, generating strategic reasoning traces that train Lyra's visual comprehension, cross-document comparison, and logical inference. The Iterative-SPO alternation pattern — self-play generates difficulty, RLVR provides verifiable reward — directly maps to Lyra's need for sustainable RL training loops without annotation bottlenecks.

**Workstream Route:** §4.1 (RL Training Infrastructure) — This feeds Lyra's reinforcement learning pipeline for post-training. The self-play game environment and alternating optimization directly inform how Lyra can construct scalable, label-free training loops for its multimodal agent capabilities.

**Impact:** 4 (high — addresses Lyra's critical annotation bottleneck, provides scalable self-improvement mechanism, directly applicable to document/chart/UI understanding)

**Effort:** 4 (substantial — requires implementing game environment, prompt templating system, multi-agent orchestration, RAE module, Iterative-SPO algorithm; but leverages existing Lyra multi-agent infrastructure)

**Tier:** Breakthrough — This is a new capability paradigm for Lyra: zero-human-in-the-loop multimodal post-training. If successful, it enables Lyra to continuously self-improve from arbitrary visual inputs without any labeling cost, fundamentally changing the scaling economics.
