## 1. Mechanism (step-by-step)

CFGM is a three-stage memory grounding architecture that uses the LLM's own internal knowledge to structure, enrich, and exploit memory at progressively finer granularities.

### Stage 1: Coarse-Grained Focus-Driven Experience Collection (Algorithm 1)

**Input**: Environment description `Desc_env`, manual trajectory few-shots `F_manual`, training task set `T_train`.

1. **Focus Point Generation**: `LLM_Focus` analyzes the environment description and manual examples to produce **Focus Points (FP)** — coarse-grained preliminary thoughts about how to handle tasks in this environment. These are not task-specific instructions but environment-level strategic hints (e.g., "check the desk first," "use specific search queries").

2. **Reflexion-Guided Trajectory Collection**: For each training task `t_n`, the agent `LLM_ReAct` executes up to `Z+1` trial attempts. Each trial is a ReAct loop (think-act-observe iteration up to `H` steps). On failure, `LLM_Reflect` introspects on the failed trajectory `τ_n,z` and produces a reflection `ν_n,z+1` that is concatenated with prior reflections and fed into the next trial attempt. This creates a growing chain of corrective context.

3. **Experience Pool Storage**: Both successful and failed trajectories (for eventually-solved tasks) are stored in experience pool `B`, indexed by task `t_n`. The key innovation is that FP guidance improves the *quality* of collected trajectories by directing exploration toward critical dynamics, reducing redundancy.

**Equation**: No learned parameters. Everything is prompt-based. The core loop:
```
a_i = LLM_ReAct(a_i | τ_n,z, F_manual, ν_n,z, FP)
o_{i+1}, done = env.step(a_i)
τ_n,z = τ_n,z ∪ {(a_i, o_{i+1})}
```
On failure: `ν_n,z+1 = concat(ν_n,z + LLM_Reflect(τ_n,z))`

### Stage 2: Hybrid-Grained Experience-Wise Tips Extraction (Algorithm 2)

**Input**: Experience pool `B`, training tasks `T_train`.

1. **Re-indexing**: Trajectories are regrouped into `C_compare` (tasks with both success AND failure trajectories) and `C_success` (tasks with only successful trajectories).

2. **Compare-Based Tip Extraction**: For tasks in `C_compare`, `LLM_Tips` is prompted to compare successful vs. failed trajectories and extract **tips** that help prevent the observed errors. Tips blend coarse-grained principles (e.g., "always verify location before acting") with fine-grained techniques (e.g., "for drawer 3, check desk first").

3. **Success-Refinement Pass**: After extracting error-prevention tips, `LLM_Tips` is prompted again, focusing only on the successful trajectory, to extract additional success-specific factors. This ensures tips capture both what to avoid AND what to replicate.

4. **Success-Only Extraction**: For tasks without failures, `LLM_Tips` derives tips directly from the successful trajectory, targeting moderate-generalization insights applicable to similar scenarios.

**Output**: Tips Dictionary `TD` mapping each task `t_n` to its set of hybrid-grained tips.

### Stage 3: Fine-Grained Key Information Adaptive Planning (Algorithm 3)

**Input**: Evaluation task `t_m`, experience pool `B`, tips dictionary `TD`.

1. **Similarity Retrieval**: Using Faiss with `all-mpnet-base-v2` embeddings, retrieve top-k most similar experiences `E_sim` from `B`. Successful trajectories `τ_h^success` and their tips `TD[t_h]` are integrated into Similar Trajectories content `ST` and Experience Tips `ET` — these serve as in-context planning aids.

2. **Standard ReAct Loop with Memory Context**: The policy model `LLM_CFGM` generates actions conditioned on the current trajectory, `ET`, and `ST`:
```
a_i = LLM_CFGM(a_i | τ_m, ET, ST)
```

3. **Anomaly-Triggered Self-QA Reflection**: A real-time monitor checks each observation `o_{i+1}` for abnormal states (e.g., "Nothing happens," persistent failures). On trigger:
   - `LLM_KIE` performs structured fine-grained analysis of the current trajectory `τ_m` → extracts **Key Information (KI)** (e.g., "currently facing drawer 3, haven't checked desk yet")
   - `LLM_KIR` conducts self-reflective question-answering using KI + current trajectory + similar success trajectories → produces corrective plan `ref_i`
   - `ref_i` is appended to the current step, guiding `LLM_CFGM` to recover

4. **Key Difference from Prior Work**: Unlike QuBE's fixed-question templates or Reflexion's trial-level reflection, CFGM performs *step-level*, *context-grounded* self-QA. The questions are dynamically generated from the fine-grained situation analysis, not pre-scripted.

## 3. Trade-offs

| Win | Loss/Cost |
|-----|-----------|
| +10.40 pp AlfWorld SR over ReAct, +5.93 pp over next-best | Requires separate GPT-4o for tips extraction (two-model dependency) |
| 25% fewer online interaction turns vs ReAct (14.32 vs 19.01) | Requires offline training phase: 4,068 tokens/sample |
| Works across model sizes (Qwen2.5-7B to GPT-4.1) with consistent gains | Retrieval scope is brittle: performance drops 5 pp when k goes from 2→5 |
| Out-of-domain transfer: WebShop→WebArena +14.9 pp over ReAct | Long trajectories introduce redundancy/interference from tips |
| Adaptive self-QA is more flexible than fixed-question reflection (+1.49 pp) | Small training sets limit experience quality regardless of FP guidance |
| Synergistic: removing FP drops full CFGM by 3 pp despite ET+KIR remaining | Works best on text-based environments; no experiments on multimodal/embodied settings |

## 4. Design Rationale

Prior memory-augmented agents (ExpeL, AutoGuide, QuBE) suffer from three interconnected failures: (1) inefficient exploration produces low-quality experiences, (2) single-granularity knowledge extraction yields homogenized insights, and (3) fixed-question templates lack cross-environment flexibility.

CFGM's design is rooted in the insight that **the LLM's own internal knowledge can bootstrap memory quality if systematically grounded at multiple granularities**. Rather than treating memory as passive retrieval, CFGM uses LLM reasoning to *structure* memory at collection time (coarse focus points), *distill* memory at extraction time (hybrid-grained tips), and *interrogate* memory at inference time (fine-grained self-QA). This is not a pipeline of independent modules — the coarse-grained Focus Points improve the quality of collected experiences, which in turn makes tips more actionable and reflection more effective. The "1+1>2" synergy is the core contribution.

## 5. Limitations & Failure Modes

1. **Small training sets**: When very few training tasks are available, even FP-guided collection cannot generate sufficient diverse experiences. The authors explicitly note this as a key limitation for future work on training set expansion.

2. **Very long trajectories**: Tips derived from experiences with extremely long trajectories may introduce redundancy or interference during LLM planning, reducing effectiveness. No dynamic filtering mechanism exists for this case.

3. **Retrieval sensitivity**: Performance is sensitive to the top-k retrieval scope. At k=5, SR drops from 86.57% to 81.34% (near ReAct baseline), indicating that irrelevant tips actively degrade planning.

4. **Closed-source dependency**: Tips extraction uses GPT-4o separate from the policy model (GPT-4-Turbo), creating cost and vendor lock-in.

5. **Trigger-based reflection**: The anomaly detection trigger is mentioned but its implementation details are sparse — unclear whether it is rule-based or learned, and what false-positive/false-negative rates exist.

6. **No multimodal evaluation**: All benchmarks are text-only (AlfWorld, WebShop, ScienceWorld, WebArena). No experiments in visual or embodied settings.

## 6. Transfer to Lyra

**The One Idea**: Coarse-to-fine memory grounding — use Lyra's internal knowledge to: (1) generate environment-level focus points that guide experience collection toward high-information trajectories, (2) extract hybrid-grained tips (coarse principles + fine techniques) from each experience by comparing successes vs. failures, and (3) perform fine-grained key-information extraction + adaptive self-QA reflection when anomalies are detected during planning.

**Workstream Route**: §4.2 (Memory Subsystem) — this directly addresses Lyra's need for structured, self-improving memory that spans multiple granularities and supports both offline knowledge extraction and online error recovery.

**Impact**: 4 (significant) — The three-stage grounding approach addresses core Lyra memory challenges: experience quality, knowledge diversity, and adaptive error correction. The 5-10 pp gains over strong baselines on challenging benchmarks suggest substantial practical benefit.

**Effort**: 3 (moderate) — All three stages are prompt-based (no model training). Implementation requires: focus point prompt template, compare-trajectory tips prompt, KI extraction prompt, KIR self-QA prompt, Faiss retrieval integration, and anomaly trigger logic. The prompts are provided in Appendix C of the paper. Most complexity is in prompt engineering and retrieval infrastructure.

**Tier**: **Breakthrough** — The 3-stage coarse-to-fine design is novel, synergistic (not a simple pipeline), and achieves SOTA on multiple benchmarks. It addresses a fundamental limitation in agent memory systems (single-granularity knowledge) and has strong empirical evidence of transferability across domains and model sizes.
