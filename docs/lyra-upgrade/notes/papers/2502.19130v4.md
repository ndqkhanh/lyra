## 1. Mechanism (step-by-step)

### Core Architecture: MALLM Framework
The Multi-Agent Large Language Models (MALLM) framework orchestrates debates through four modular components:

1. **Persona Generator**: Auto-generates 3 diverse expert personas per task using the same LLM that serves as agents. Each persona is presented to the model to avoid duplication. Example: for a medical question, it generates a Medical Expert, Scientist, and Student persona.

2. **Response Generator**: Defines how agents respond to prior messages:
   - *Simple* (default): Neutral, unbiased response; agrees/disagrees with prior answer; task re-presented each round to prevent drift.
   - *Critical*: Forced critical assessment of prior answers to counter sycophantic tendencies.
   - *Reasoning-only*: Agents share only reasoning paths, not final solutions, to avoid bias toward other agents' conclusions.

3. **Discussion Paradigm**: Controls turn order and information visibility:
   - *Memory*: All agents see all prior messages (default).
   - *Relay*: Each agent sees only the immediately prior agent's message.
   - *Report*: A moderator agent mediates all communication.
   - *Debate*: Agents discuss in subgroups, then report to moderator.
   - *Collective Improvement (new)*: All agents generate independently in parallel, then each sees ALL prior-turn solutions simultaneously. No direct agent-to-agent communication.

4. **Decision Protocol**: Determines final answer selection.

### Seven Decision Protocols Evaluated

**Consensus-based (3 protocols):**
Agents iteratively refine a shared answer. Each round, an agent indicates AGREEMENT/DISAGREEMENT with the prior agent's solution via regex extraction. If the required agreement threshold is met in sequence, the discussion terminates and the final answer is extracted from the last agreeing agent's message.

- **Majority Consensus**: >50% of agents must agree (threshold: ceil(N/2)+1).
- **Supermajority Consensus**: >66% of agents must agree (threshold: ceil(2N/3)).
- **Unanimity Consensus**: 100% of agents must agree (threshold: N).

Formally: Let A be the set of N agents. After round r, let agreed[r] = count of consecutive agents who agreed. Decision reached when agreed[r] >= threshold. Final answer = extract(last_agreeing_agent_message).

**Voting-based (4 protocols):**
Agents discuss for a fixed 3 rounds, then each produces a final solution. Agents vote on all proposed solutions. If tie → one more discussion round → re-vote. If no decision after max_rounds (5), first agent's solution wins.

- **Simple Voting**: Each agent casts 1 vote. Plurality wins. (v_i ∈ {1..N}, winner = argmax_j count(v_i = j))
- **Ranked Voting**: Each agent ranks all solutions. Winner = argmin_j sum(rank_i(j)).
- **Cumulative Voting**: Each agent distributes up to 25 points among solutions. Winner = argmax_j sum(points_i(j)).
- **Approval Voting**: Each agent approves any number of solutions. Winner = argmax_j sum(approve_i(j)).

### Two Novel Methods for Answer Diversity

**All-Agents Drafting (AAD):**
Each agent independently generates a full draft solution in Round 1 *before* seeing any other agent's output. Forces each agent to leverage its own persona/expertise rather than lazily improving the first agent's answer. After Round 1, normal discussion proceeds.

**Collective Improvement (CI):**
Extends AAD by prohibiting inter-agent communication entirely. Workflow:
- Round t: Each agent receives ALL solutions from Round t-1 (no turn order, no direct messages).
- Each agent independently refines its own solution using the full solution set as context.
- After final round, a voting protocol selects the best answer.
- CI only works with voting protocols (consensus requires iterative agreement-building).

### Key Control Variables
- **Number of agents** (N): 1-10, default 3
- **Discussion rounds before voting**: 1-10, default 3
- **Memory window**: 2 turns (to limit context length)
- **Confidence level**: 95% with 5% margin of error for sampling

### Sampling Formula
For dataset subset selection:
n₀ = Z² * p * (1-p) / d² where Z=1.96, p=0.5, d=0.05
n = n₀ / (1 + (n₀-1)/N) (finite population correction)

## 2. Results (real benchmark numbers)

### Models: Llama 3 8B Instruct, Llama 3 70B Instruct (via OpenAI-compatible API)

### Main Experiment: 7 Protocols across 6 Datasets (Llama 8B, 3 runs each)

| Task | Baseline (CoT) | Best Consensus | Best Voting | Voting vs Consensus Δ |
|------|---------------|----------------|-------------|----------------------|
| **MMLU** (knowledge) | 52.3% | 54.6% (Supermajority) | 53.3% (Simple) | Consensus +2.3% |
| **MMLU-Pro** (knowledge) | 51.7% | 36.4% (Majority) | 33.1% (Ranked) | Consensus +4.9% |
| **GPQA** (knowledge) | 25.8% | 32.3% (Majority) | 31.3% (Cumulative) | Consensus +1.3% |
| **SQuAD 2.0** (reasoning) | F1=58.5% | F1=43.6% (avg) | F1=56.7% (avg) | Voting +13.1% |
| **StrategyQA** (reasoning) | 55.2% | 59.9% (Majority) | 61.2% (Cumulative) | Voting +0.2% |
| **MuSR** (reasoning) | 20.5% | 43.6% (Unanimity) | 58.7% (Simple) | Voting +26.4% |

### Rounds to Decision
- Voting protocols: **3.38 rounds avg** to reach a decision
- Consensus protocols: **1.42 rounds avg** to reach a decision
- Approval voting fails to reach a decision in **59% of cases** (agents approve everything → ties)

### Compute Cost
- Consensus protocols: ~**5x** compute of CoT baseline
- Voting protocols: ~**10x** compute of CoT baseline

### SQuAD 2.0 Unanswerable Questions (F1)
- Voting overall: **56.7%** F1
- Consensus overall: **43.6%** F1
- On unanswerable samples: **Consensus wins** (stricter = higher), unanimity best
- On answerable samples: **Voting wins**

### Scaling Effects (StrategyQA, Simple Voting, Llama 8B)

**Rounds before voting (1→10):**
- Linear regression shows **slight accuracy DECREASE** with more rounds
- Exception: sharp spike at round 10 (possible recovery effect)

**Number of agents (1→10):**
- Linear regression shows **slight accuracy INCREASE** with more agents
- Resembles self-consistency effect (Wang et al., 2023)

### AAD and CI Performance (StrategyQA, Llama 8B)

| Method | Cosine Similarity ↓ | Accuracy | Δ Baseline |
|--------|---------------------|----------|-------------|
| Baseline | 0.888 | 58.3% | 0.0% |
| AAD | 0.870 | 62.8% | **+3.3%** |
| CI | 0.845 | 65.7% | **+7.4%** |
| Critical Generator | 0.843 | 59.4% | +1.1% |
| Reasoning Generator | 0.916 | 51.9% | **-6.4%** |

Lower cosine similarity = higher answer diversity = better performance (correlation observed).

### Challenge Experiment (detecting incorrect answers)
- Agents detect irrelevant solutions: **99% challenge rate**
- Agents detect incorrect solutions: **75% challenge rate**
- Providing discussion history reduces challenge rate by **10%** (60% drop for StrategyQA)
- Challenged answers lead to worse results in **3% of cases** on reasoning tasks
- Challenge has no positive effect on knowledge tasks

### Llama 3 70B Results
- Much higher baseline across all tasks
- Multi-agent gains smaller or negligible vs CoT baseline
- SQuAD 2.0 and StrategyQA still see gains (similar pattern to 8B)
- Smaller models benefit more (more hallucinations → more value from cross-checking)

## 3. Trade-offs (wins vs loses)

| Dimension | Win | Lose |
|-----------|-----|------|
| **Task-type routing** | Consensus +2.8% on knowledge; Voting +13.2% on reasoning | Wrong protocol choice drops performance (voting on knowledge, consensus on reasoning) |
| **Convergence speed** | Consensus reaches decision 2.4x faster (1.42 vs 3.38 rounds) | Consensus may converge on wrong answer via groupthink |
| **Error detection** | Consensus catches individual errors (multi-agent fact-checking); unanimity best for unanswerable questions | Voting can be tricked by plausible-but-wrong answers |
| **Exploration vs exploitation** | Voting explores multiple reasoning paths (higher diversity) | Voting requires more compute (10x vs 5x) and more rounds |
| **Agent count scaling** | More agents → monotonic accuracy improvement (self-consistency effect) | Linear increase in API cost per added agent |
| **Round count scaling** | Fewer rounds = less compute | More rounds → accuracy DEGRADES (problem drift); self-refinement claims may be unreliable |
| **AAD/CI diversity methods** | CI +7.4%, AAD +3.3% accuracy gains | CI only works with voting protocols (no consensus compatibility) |
| **Critical prompting** | Marginal gain (+1.1%) | Unreliable; can degrade discussion quality |
| **Reasoning-only prompting** | — | -6.4% accuracy; reduces answer diversity despite intent |
| **Approval voting** | Simple to implement | Fails 59% of cases (agents approve everything) |
| **Model scale** | 8B benefits dramatically from multi-agent (hallucination reduction) | 70B sees minimal multi-agent gains (higher baseline, less hallucination) |
| **Solution counting vs prompted protocols** | Prompted protocols outperform counting | Solution counting is simpler to implement |

## 4. Design Rationale (why this approach)

The paper's core thesis: **decision protocol choice is the single most impactful yet least-studied variable in multi-agent debate systems.** Prior work (Yin et al., 2023; Yang et al., 2024b; Chen et al., 2023) varied multiple parameters simultaneously, making it impossible to attribute performance changes to the decision protocol alone.

The authors chose a **controlled-variable methodology**: change only one parameter at a time (the decision protocol), keeping all else constant (same model, same personas, same number of agents, same response generator). This isolates causal effects.

**Why consensus for knowledge tasks:** Knowledge tasks require recall of facts. Individual agents hallucinate at different rates. Requiring agreement from multiple agents acts as a statistical filter — the probability that N agents independently hallucinate the same false fact is low. This is analogous to ensemble methods in ML.

**Why voting for reasoning tasks:** Reasoning benefits from exploring multiple solution paths in parallel. Voting preserves diversity by allowing competing solutions to exist simultaneously, whereas consensus forces premature convergence onto one path.

**Why AAD/CI over prompted diversity:** Directly changing agent response style (critical/reasoning prompts) degrades LLM output quality. Structural interventions (forcing independent generation, limiting communication) achieve diversity without corrupting individual agent quality.

**Why more agents > more rounds:** More agents = more independent samples (self-consistency). More rounds = more opportunity for agents to converge on shared errors through sycophancy and groupthink (problem drift per Becker 2024).

## 5. Limitations & Failure Modes

1. **Computational cost**: Multi-agent debate requires 5-10x more forward passes than single-agent CoT. This forced subset sampling (95% confidence, 5% margin) rather than full-dataset evaluation. Practical deployment at scale would be expensive.

2. **Only two model families tested**: Llama 3 8B/70B Instruct. No GPT-4, Claude, Gemini, or open-source alternatives (e.g., Mistral, Qwen). Decision protocol effects may vary across model families with different sycophancy levels or reasoning capabilities.

3. **Model-scale asymmetry**: Llama 70B shows much smaller multi-agent gains. The core mechanism (hallucination reduction through cross-checking) may not generalize to frontier models that hallucinate less.

4. **Lack of persona ablation**: Personas were auto-generated but not systematically varied. Prior work suggests limited impact (Zheng et al., 2024), but this wasn't verified here.

5. **Prompt sensitivity unexplored**: Only three response generator variants tested. The prompts themselves were not systematically ablated against alternative phrasings.

6. **Answer diversity ceiling**: Despite AAD and CI, agents still often converged on similar responses (cosine similarity 0.845-0.870, not near 0). More aggressive diversity techniques may be needed.

7. **CI incompatible with consensus**: Collective Improvement only works with voting protocols, limiting its applicability.

8. **Approval voting failure mode**: 59% failure-to-decide rate makes it impractical without modification.

9. **Problem drift in long discussions**: Accuracy degrades with more rounds, contradicting self-refinement claims (Huang et al., 2023).

10. **No real-time/interactive evaluation**: All experiments on static benchmarks. No measurement of latency, user satisfaction, or interactive task completion.

## 6. Transfer to Lyra

### The One Transferable Idea

**Task-dependent decision protocol routing with structural answer diversity (AAD/CI):** When Lyra agents debate, the decision protocol should be dynamically selected based on task type — consensus for knowledge-retrieval/fact-checking, voting for open-ended reasoning/exploration. Critically, force ALL agents to independently draft solutions in the first round (AAD) before any communication to maximize answer diversity and avoid premature convergence on the first agent's proposal. For voting-only scenarios, use Collective Improvement (CI) to further limit inter-agent contamination.
