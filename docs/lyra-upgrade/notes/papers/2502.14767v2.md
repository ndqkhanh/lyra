# Tree-of-Debate: Multi-Persona Debate Trees Elicit Critical Thinking for Scientific Comparative Analysis

**Authors:** Priyanka Kargupta, Ishika Agarwal, Tal August, Jiawei Han — Department of Computer Science, University of Illinois at Urbana-Champaign

**Venue:** arXiv preprint 2502.14767v2 [cs.CL], June 9 2025

**OpenReview:** Not yet published at a venue (preprint only). Code at https://github.com/pkargupta/tree-of-debate. BSD-style open-source. Base LLM: Llama-3.1-Nemotron-70B-Instruct-HF (open-weight). Retrieval embedding model: BAAI/bge-large-en-v1.5. Hardware: 4× NVIDIA A100 GPUs via vLLM.

---

## 1. Mechanism (step-by-step)

Tree-of-Debate (ToD) takes two scientific papers (p1, p2) and a root topic n0, then dynamically constructs a debate tree T whose non-leaf nodes represent comparative debate rounds at increasing granularity. The output is a paragraph-length abstractive comparative summary S. The framework uses three personas powered by the same base LLM: two "paper personas" (one per paper) and a moderator.

### Phase 0: Setup & Chunking

- Each paper is chunked into ~3-sentence segments.
- Segments are embedded using BAAI/bge-large-en-v1.5 (768-dim).
- Cosine similarity is used for top-δ retrieval (δ=5 segments per query).
- The paper personas receive title + abstract + retrieved segments only (not full text).

### Phase 1: Self-Deliberation (per node ni, per persona pa)

1. **Segment Retrieval:** Embed topic ni using format `"[topic name]: [topic description]"`, retrieve top δ=5 segments Sai from pa via cosine similarity against the segment embedding index.

2. **Claim Generation:** Each persona generates k claims (k=3) Cia = {c1, …, ck} about their novel contributions toward ni. Each claim cj has: (a) a brief title, (b) a 1-2 sentence description referencing specific evidence excerpts, (c) a list of supporting evidence segment IDs E(i,j)^a ⊆ Sai. (Prompt 17)

3. **Preemption:** Persona pa is shown opponent pb's claims Cib exposed in-context. pa issues a second retrieval round forming counter-evidence Ẽi^a, where for each opponent claim cb(i,j) ∈ Cib, pa retrieves additional segments from their own paper using the concatenated title+description of cb(i,j) as query. Each retrieved segment e is filtered via an LLM binary relevance check (Prompt 18) determining whether e supports/refutes/clarifies pb's claim or is irrelevant. If |Ẽ(i,j)^(a)| = 0 after filtering, the system records that pa does NOT address pb's claim.

4. **Subtopic Generation:** The moderator receives both papers' titles, abstracts, Ci, Ei, and Ẽi, then generates k=3 new subtopics Nij = {ni1, …, nik} for further debate (Prompt 14). Each subtopic maps to at least one claim from p1 and/or p2, forming the basis for child debate nodes. Topics can be overlapping or unique to one paper.

### Phase 2: Debate Round (per child node nij)

A three-turn exchange using Prompts 19, 20, and 21:

1. **Present (Turn 1, T=0.1):** Each persona presents an argument for why their paper makes a better contribution toward nij than the opponent, citing evidence. The persona may explicitly concede if they feel their paper does not contribute to this subtopic.

2. **Respond (Turn 2, T=0.4):** Each persona responds to the opponent's argument. Actions permitted: acknowledge opponent response, answer questions about their own paper, ask clarifying questions, clarify their own arguments, or concede if the opponent's claim is too strong.

3. **Revise (Turn 3, T=0.4):** Each persona constructs a new, stronger argument that addresses doubts/clarifying questions raised by the opponent. May also concede if convinced.

### Phase 3: Expansion Decision

The moderator evaluates (Prompt 15) three boolean criteria:

1. **Argument Progression:** Are new, deeper concepts being introduced?
2. **Meaningful Questions:** Are there unanswered clarifying questions?
3. **Clear Winner:** Is it obvious one paper has won (so no further deconstruction is needed)?

**Expansion rule:** If (progression==True OR meaningful_questions==True OR clear_winner==False), then the node is expanded: trigger self-deliberation for nij, generating k new child subtopics. Otherwise, the debate path terminates. Tree depth is capped at l=3.

### Phase 4: Synthesis

Once all debate paths have terminated, the moderator synthesizes the full tree T into a paragraph-length comparative summary (Prompt 16). The tree is provided in-context with each node containing: topic title, topic description, p1's revised argument, and p2's revised argument. Structure: similarities first, then differences (with greater emphasis on differences).

### Temperature Settings

| Action | Temperature |
|--------|------------|
| Paper generates arguments | 0.3 |
| Paper checks evidence relevance | 0 (greedy) |
| Paper presents argument | 0.1 |
| Paper responds | 0.4 |
| Paper revises argument | 0.4 |
| Moderator generates subtopics | 0.3 |
| Moderator decides expansion | 0.1 |
| Moderator summarizes | 0.4 |

### Hyperparameters

- δ = 5 (retrieved segments per query)
- k = 3 (generated subtopics per node)
- l = 3 (maximum tree depth)
- Top-1% token sampling (nucleus/top-p, not top-k)

## 2. Results (real benchmark numbers)

### Main Results (Table 2): 100 paper pairs, 5 domain-experts, 3 metrics normalized to 0-100

#### Overall (Method): ToD vs baselines

| Method | Breadth | Context | Factuality |
|--------|---------|---------|------------|
| Single Stage | 91.07 | 75.59 | 94.39 |
| Two Stage | 86.31 | 72.02 | 93.69 |
| ToD (No Tree) ablation | 80.36 | 67.86 | 89.82 |
| ToD (No SD) ablation | 88.10 | 88.10 | 78.21 |
| **Tree-of-Debate (ToD)** | **94.64** | **93.45** | **95.37** |

**Key deltas over best baseline:**
- Breadth: +3.57 points (+3.9%)
- Contextualization: +17.86 points (+23.6%) — described as 25.98% relative improvement in text
- Factuality: +0.98 points (+1.0%)

#### Robustness (σ = standard deviation across settings)

- ToD σ = 2.49 (breadth + contextualization)
- Single Stage σ = 5.32
- Two Stage σ = 3.39

#### Ablation impacts

- Removing tree structure (No Tree): Contextualization drops 25.59 points (from 93.45 to 67.86); Factuality drops 5.55 points
- Removing self-deliberation (No SD): Factuality drops 17.16 points (from 95.37 to 78.21); Breadth drops 6.54 points

## 3. Trade-offs

| Dimension | Win | Lose |
|-----------|-----|------|
| Contextualization | +25.98% over best baseline (summaries explain *why* differences matter, not just *what* they are) | Occasional fact-confusion between papers when topic overlap is implicit |
| Factuality | 95.37 vs 94.39 (best baseline) — competitive | Drops in niche domains (aerospace: 88.64, EE: 91.36) where base model lacks pre-training knowledge |
| Breadth (completeness) | +3.9% over best baseline — identifies more fine-grained contributions | Removing iterative retrieval causes ~6.5 point breadth drop and ~17 point factuality drop |
| Computational cost | Inference-time only (no training), domain-agnostic | Each pair generates multi-turn LLM calls at up to 3 tree levels × k=3 subtopics = O(k^l) potential nodes per branch ≈ 27+ LLM calls per paper pair |
| Model quality sensitivity | Works well with 70B models | Degrades with 8B models (breadth drops from 4/4 to 2/4 on same pair) |
| Structured reasoning | Tree decomposes multi-faceted comparisons into independently evaluable sub-ideas | Tree depth capped at 3 (deeper paths may contain unresolved arguments); personas occasionally propose future studies/synthetic ideas as depth increases |
| Retrieval quality | BGE/bge-large-en-v1.5 well-tested | Retrieval model choice matters (e5 vs BGE produce different evidence pools, which affects downstream debate quality) |

## 4. Design Rationale

The key design decisions and their motivations:

1. **Debate as outcome, not as optimization:** Unlike prior multi-agent debate work (Chan et al. 2023, Liang et al. 2024) that uses debate to improve final output quality, ToD uses the debate *itself* as the comparative analysis product. The paper argues that the reasoning path through structured disagreement is more informative than the final "winner."

2. **Tree structure over flat debate:** A single flat debate cannot independently assess contributions at different granularities. The tree decomposes complex multi-contribution papers into independently evaluable subtopics (e.g., methodology vs. evaluation metric vs. dataset novelty), mirroring how human researchers decompose comparative analysis.

3. **Iterative retrieval over full-text or abstract-only:** Full-text in-context overwhelms the LLM (long-context degradation problem, per Li et al. 2024). Abstract-only leads to surface-level extractive summaries. Iterative retrieval conditioned on evolving debate subtopics keeps context focused and relevant at each node.

4. **Self-deliberation + Preemption over blank-slate debate:** The self-deliberation phase (generate own claims → see opponent's claims → retrieve counter-evidence) mirrors formal debate preparation. Preemption allows each persona to prepare defenses against specific opponent claims before the debate round starts, improving argument quality.

5. **Inference-time only (no training):** Domain-agnostic by design. Unlike fine-tuning approaches (DIR, Wang et al. 2024a), ToD requires no labeled training data and works across any domain accessible to the base LLM's pre-training corpus.

## 5. Limitations & Failure Modes

1. **Domain knowledge gap:** Factuality drops in niche domains (aerospace/EE) where base model pre-training knowledge is sparse. The retrieval + debate framework cannot compensate for missing fundamental domain understanding.

2. **Critical response quality variance:** The usefulness of debate hinges on meaningful questions/doubts raised in the Respond stage. In challenging or poorly-understood topics, responses may be superficial or avoid genuine engagement.

3. **Depth-induced hallucination:** As debate paths deepen to level 3, personas lacking supporting evidence begin proposing "future studies" or synthetic combination methods (e.g., "a hybrid approach combining both strengths"). While presented as a feature for research ideation, this introduces factual noise.

4. **Fact-confusion across papers:** When papers have implicit/non-obvious overlap (especially task-based comparisons), ToD occasionally mixes up which paper contributed which idea (e.g., attributing "ICL" applicability to the wrong paper).

5. **Model-size sensitivity:** Performance degrades substantially with smaller models. Llama-3.1-8B achieves only 2/4 breadth vs. 4/4 for 70B on the same pair (Table 8).

6. **Single base LLM for all roles:** All three personas use the same model, which may limit the diversity of debate perspectives compared to truly heterogeneous agent backends.

7. **Scalability untested:** Only tested on paper pairs (not N>2 comparison). Scaling to multi-paper comparison would require extending the tree to multi-way debate nodes.

## 6. Transfer to Lyra

### The ONE transferable idea

**Structured multi-persona self-deliberation with iterative retrieval for evidence-backed comparative reasoning.** The core insight: when Lyra needs to compare two candidate approaches, designs, or research artifacts, encode each as a "persona" that retrieves its own evidence, preempts the other's claims, and engages in structured debate under a moderator that dynamically decides whether to drill deeper into specific subtopics. This transforms flat summarization into contested, evidence-grounded analysis with explicit failure-mode detection (concession when evidence is insufficient).

### Routing to Lyra workstream

**§4.6 — Multi-Agent Reasoning & Debate (or the broader Reasoning/Reflection subsystem).** If §4.6 isn't established yet, this feeds either §4.3 (Context/Retrieval — for the iterative retrieval pattern) or a new capability in the agent loop where Lyra uses adversarial self-play to stress-test its own conclusions.

| Metric | Score | Justification |
|--------|-------|---------------|
| Impact | 4/5 | Transforms Lyra's comparative reasoning from single-pass "read-then-summarize" to structured, evidence-backed adversarial analysis. Directly applicable to literature review, code-diff analysis, and architecture decision comparison. |
| Effort | 3/5 | Requires: (1) tree-structured debate orchestration (~200-300 LOC), (2) persona construction from artifacts, (3) iterative retrieval against local document store, (4) moderator prompts. Core pattern is prompt-engineering, not model training. |
| Tier | **breakthrough** | This is a new capability (structured multi-persona comparative reasoning with self-deliberation), not a marginal improvement. It changes *how* Lyra reasons about competing alternatives rather than making an existing capability slightly better. |
