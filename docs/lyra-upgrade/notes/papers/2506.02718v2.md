# End-to-End Optimization of LLM-Driven Multi-Agent Search Systems via Heterogeneous-Group-Based Reinforcement Learning

Guanzhong Chen, Shaoxiong Yang, Chao Li, Wei Liu, Jian Luan, Zenglin Xu — ACL 2026 Main Conference — arXiv:2506.02718v2

## 1. Mechanism

MHGPO (Multi-Agent Heterogeneous Group Policy Optimization) is a **critic-free**, **parameter-shared** RL algorithm for end-to-end optimization of LLM-driven multi-agent search systems (MASS). It eliminates the critic network entirely — the core departure from MAPPO — by estimating advantages via **intra-group relative reward normalization across heterogeneous rollout groups**.

### Step-by-step:

**A. System Architecture (3-agent MASS pipeline)**
- **Rewriter** agent: generates up to 4 rewritten queries from a user question.
- **Reranker** agent: selects 2-3 relevant documents from retrieved snippets (Contriever-based retrieval from Wikipedia).
- **Answerer** agent: synthesizes a final short answer (<10 tokens).
- All three agents share the same LLM backbone (parameter sharing), Llama3.1-8B-Instruct.

**B. Phase 1 — Multi-Agent Group Rollout Sampling**
For a query \( q \sim \mathcal{D} \), the system generates \( G \) terminal responses \(\{o_i\}_{i=1}^G\) via one of three strategies:
- **IS (Independent Sampling)**: Fork \( G \) times at each agent independently. Produces **homogeneous groups** (all samples inside a group share the same input). Cost: \( nG \) LLM calls per sample.
- **FoF (Fork-on-First)**: Fork \( G \) times only at the first agent (Rewriter); all successors inherit. Produces **heterogeneous groups** capturing full inter-agent dependencies. Cost: \( nG \) calls per sample.
- **RR (Round-Robin)**: Fork at a randomly selected agent with probability \( p_k \). Cost: \((n-1)+G\) calls per sample (lowest). Fork probabilities tuned to \((0.7, 0.1, 0.2)\) for the three agents.

**C. Phase 2 — Backward Reward Propagation**
The final response receives a shared reward \( R_i^{\text{shared}} \) (F1 score + agent-specific penalties). This reward propagates backward through predecessor agents:

\[
R_{k,i}^{\text{shared}} = \text{Aggr}(\{R_{j,r}^{\text{shared}}\}_{j>k})
\]

where \(\text{Aggr}(\cdot)\) is a simple average over direct successors. Each agent's reward adds agent-specific penalties:

\[
R_{k,i} = R_{k,i}^{\text{shared}} + R_k^{\text{spe}}(q_{k,i}, o_{k,i})
\]

Penalty design:
- Rewriter: -0.5 if >4 queries generated.
- Reranker: -0.5 for duplicate entries or out-of-bounds index.
- Answerer: -1.0 if answer excessively long.

**D. Phase 3 — Critic-Free Group Relative Advantage Estimation**
This is the core innovation. Instead of training a critic network to estimate state value, MHGPO computes the advantage as a **z-score within the heterogeneous group**:

\[
\hat{A}_{k,i} = \frac{R_{k,i} - \text{mean}(\{R_{l,j} \mid m_{l,j} = m_{k,i}\})}{\text{std}(\{R_{l,j} \mid m_{l,j} = m_{k,i}\})}
\]

Key property: the group \(\{R_{l,j} \mid m_{l,j} = m_{k,i}\}\) spans samples from **different input prompts** in FoF and RR strategies — a heterogeneous group, unlike GRPO's homogeneous-group constraint. This captures cross-trajectory dependencies.

**E. Token-Level Reward Assignment**
Reward is assigned only at the final token of each agent's output:

\[
R_{k,i}^t = \begin{cases} 0, & t < T \\ R_{k,i}, & t = T \end{cases}
\]

**F. Policy Gradient Objective**
The parameter-shared optimization aggregates losses across all agents:

\[
\mathcal{J}_{\text{MHGPO}}(\theta) = \mathbb{E}\left[ \frac{1}{n}\sum_{k=1}^{n}\frac{1}{G_k}\sum_{i=1}^{G_k}\frac{1}{|o_{k,i}|}\sum_{t=1}^{|o_{k,i}|} \min\left(r_{k,i}^t \hat{A}_{k,i}^t,\ \text{clip}(r_{k,i}^t, 1-\epsilon, 1+\epsilon)\hat{A}_{k,i}^t\right) - \beta D_{KL}(\pi_\theta || \pi_{\text{ref}}) \right]
\]

where \( r_{k,i}^t = \pi_\theta(o_{k,i}^t|q, o_{k,i}^{<t}) / \pi_{\text{ref}}(o_{k,i}^t|q, o_{k,i}^{<t}) \) and \(\beta=0.001, \epsilon=0.2\).

**G. Training configuration**: 1 epoch over HotpotQA train set (90,447 samples), group size G=4, batch size 512, LR 5e-7 to 1e-6, 8× H100 80GB, validation every 5 steps for 176 total steps.

### Efficiency and convergence

- GPU memory: **30-40% reduction** vs MAPPO (critic eliminated).
- MHGPO-IS: fastest convergence but lowest performance ceiling.
- MHGPO-FoF: slower convergence, higher final performance.
- MHGPO-RR: intermediate convergence, **15-20% lower rollout overhead** than FoF, best or near-best accuracy.
- Format penalties drop to near-zero within first 10 steps across all variants.
- Agent behavior converges to interpretable patterns: Rewriter → 2 queries, Reranker → 2-3 documents, Answerer → <10 tokens.

## 3. Trade-offs

| Win | Lose |
|---|---|
| +3.32 F1 points over MAPPO on HotpotQA (49.72 vs 46.40) without any warm-up | MHGPO-IS underperforms MAPPO on HotpotQA (45.58 vs 46.40) and MuSiQue (18.42 vs 19.74) — homogeneous groups insufficient for complex dependencies |
| 30-40% GPU memory savings by eliminating critic network entirely | RR and FoF strategies add ~15-20% rollout overhead vs IS due to more coordinated group construction |
| Critic-free design eliminates training instability and hyperparameter tuning for value function | Generalization only demonstrated on search-pipeline MAS; applicability to other MAS topologies (negotiation, game-theoretic) untested |
| No SFT warm-up needed — trains stably from scratch | 1-epoch training on single dataset (HotpotQA) — may underfit complex behaviors |
| Parameter sharing enables single-model deployment for all 3 agents | Shared backbone constrains agent specialization; heterogeneous roles may benefit from partially decoupled parameters |
| Out-of-domain generalization (trained on HotpotQA, tested on 2Wiki/MuSiQue) proves robustness | Absolute F1 on MuSiQue remains low (~21.6%) — multi-hop reasoning with >2 hops still challenging |

## 4. Design Rationale

1. **Why critic-free?** MAPPO's centralized critic scales as O(n^2) in joint action space, causing memory blowup and gradient variance for heterogeneous agent roles. MHGPO observes that multi-agent task success is a **scalar global signal** that can normalize advantages across group rollouts directly — a value function is redundant overhead.

2. **Why heterogeneous groups?** Single-agent GRPO requires group members to share the same input (homogeneous), but in MAS, a query can lead to vastly different inter-agent trajectories. FoF and RR strategies deliberately mix trajectories from different inputs in the same advantage-normalization group, forcing the policy to learn **relative quality across execution paths** rather than absolute quality of one path.

3. **Why backward reward propagation by averaging?** Joint credit assignment in MAS is unsolved in general. Simple averaging is an **unbiased heuristic** that preserves the total reward signal without introducing per-agent bias from an imperfect critic. The KL penalty (+ SFT constraint) prevents the policy from diverging too far under noisy assignments.

4. **Why RR over FoF despite FoF's higher ceiling?** Early training benefits from fine-grained per-agent optimization (RR's mixed groups); late training benefits from end-to-end pipeline optimization (FoF's heterogeneous groups). RR probabilistically blends both regimes, achieving FoF-level performance with lower compute.

## 5. Limitations & Failure Modes

1. **MAS topology restriction**: Only validated on a linear 3-agent search pipeline (Rewrite → Rerank → Answer). The authors acknowledge applicability to other MAS structures (DAG, star, fully-connected) is untested and left to future work.

2. **Single-task RL training**: All RL optimization uses only HotpotQA. While out-of-domain transfer is demonstrated, behavior may overfit to two-hop reasoning patterns characteristic of HotpotQA.

3. **Short RL horizon**: Only 1 epoch (176 steps) of RL training. It is unknown whether longer training yields continued improvement or degradation.

4. **MHGPO-IS failure mode**: Independent sampling consistently underperforms MAPPO on HotpotQA and MuSiQue, indicating that **homogeneous-group-only advantage estimation** loses critical cross-agent dependency signals. Users who naively port single-agent GRPO to MAS would encounter this degradation.

5. **Parameter sharing constraint**: All agents share one LLM. For systems where agents require fundamentally different capabilities (e.g., code generation + image understanding), shared parameters may create negative interference.

6. **Reward propagation simplicity**: Simple averaging for backward reward propagation may dilute signals when one agent's contribution dominates others. Tasks with stronger asymmetric agent contributions may see degraded credit assignment.

7. **Limited agent count**: Only tested on 3-agent systems. Scaling to 10+ agents may stress the group rollout budget and advantage estimation quality.

## 6. Transfer to Lyra

**The One Idea:** Replace Lyra's Lyra's per-agent critic/value-function training (if any) with **critic-free heterogeneous group advantage estimation** — run \( G \) end-to-end trajectories through the Lyra agent pipeline with different execution paths (forking at the router rather than at each tool), compute a shared terminal reward, and normalize advantages within the group using z-scores. This eliminates critic network overhead while capturing inter-agent dependencies (router→tool selection→execution→verification) as a single optimization signal.

**Workstream route:** This feeds **§4.2 (RL-based Agent Fine-tuning)** and secondarily **§4.7 (Multi-Agent Orchestration Optimization)**. The critic-free group RL pattern directly applies to end-to-end optimization of Lyra's agent pipeline without architectural changes to the router.

**Impact:** 4/5 — 30-40% training memory savings + convergence stability gains are high-impact for resource-constrained Lyra training; the out-of-domain generalization result suggests robustness to novel query patterns.

**Effort:** 3/5 — Requires implementing group rollout infrastructure (forking trajectories, backward reward propagation), adapting Lyra's reward signal for terminal-only assignment, and tuning group sampling strategy hyperparameters. No architectural changes to the agent backbone needed.

**Tier:** Breakthrough — This is a genuine architectural simplification (critic-free) that outperforms the standard MAPPO approach. The heterogeneous group concept is novel and directly applicable to Lyra's multi-agent decomposition.
