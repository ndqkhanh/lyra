## 1. Mechanism

Agentic Reasoning augments a reasoning LLM (DeepSeek-R1 by default) with three external agentic tools — Web-Search, Coding, and Mind-Map — invoked on-demand during chain-of-thought reasoning. The core flow is an **iterative retrieve-and-reason loop**:

### Step-by-step control flow

1. **Reasoning LLM generates chain-of-thought.** When it encounters a gap requiring external knowledge or computation, it embeds a *specialized call token* (web-search, coding, or mind-map) into its reasoning sequence, along with a natural-language query.

2. **Token detected, reasoning halts.** The harness extracts the query and the surrounding reasoning context, then dispatches both to the corresponding external agent.

3. **Agent execution** (one of three):
   - **Web-Search agent** — 4-stage pipeline:
     a. *Query Breakdown*: DeepSeek-V3 rewrites the user query into search-optimized sub-queries, using Mind-Map reasoning context (e.g., "Search external economic indicators" + context "optimal investing strategy for US retailer Q4 2024" → "U.S. Q4 2024 inflation rate", "U.S. Q4 2024 CCI").
     b. *Search Service*: Each sub-query sent to Bing; top 20 pages retrieved.
     c. *Re-Ranking*: Cohere Rerank 3.5 scores every retrieved page against the original query + context. Mean relevance score of top-10 computed. If < 0.7 threshold, iterate back to query breakdown (max 3 iterations). Pages above 0.7 pass to RAG.
     d. *RAG + Synthesis*: RAG over selected pages per sub-query → LLM synthesizes a cohesive natural-language snippet returned to the reasoning chain.
   - **Coding agent**: Reasoning model delegates code to Claude 3.5 Sonnet (specialized coding LLM). Prompt format: "Write code to perform `<code message>` given the context `<Mind-Map context>` to answer the query `<user query>`." Code executes in Python 3.11; output always formatted as natural language for seamless integration.
   - **Mind-Map agent** — dual-function structured memory:
     a. *Graph Construction*: DeepSeek-V3 extracts entities and semantic relationships from the current reasoning chain, building a knowledge graph (analogous to GraphRAG; Edge et al. 2024).
     b. *Community Clustering*: Leiden algorithm (Traag et al. 2019) partitions the graph into communities; LLM summarizes each community.
     c. *Context Provision*: Synthesized community summaries are returned to Web-Search and Coding agents so they produce context-aware outputs.
     d. *Query Retrieval*: When the reasoning model becomes uncertain/lost in long chains, it queries the Mind-Map directly; a GraphRAG retrieval over the knowledge graph returns relevant structured information.

4. **Agent results reintegrated** into the main reasoning chain. The LLM continues inference with updated knowledge until it produces a final answer.

### Key equations / algorithms
- **Re-ranking**: \(\text{avg\_score} = \frac{1}{10}\sum_{i=1}^{10} \text{CohereRerank}(q, \text{context}, \text{page}_i)\). If \(\text{avg\_score} < 0.7\), trigger query refinement (max 3 loops).
- **Community detection**: Leiden algorithm on the entity-relationship graph for modularity optimization.
- **Model routing**: DeepSeek-R1 for reasoning, DeepSeek-V3 for graph construction/RAG/query breakdown, Claude 3.5 Sonnet for code, Cohere Rerank 3.5 for page relevance.

## 3. Trade-offs

| Win | Lose |
|-----|------|
| +14.4% on Humanity's Last Exam over base R1 — largest single gain reported | Multiple sequential LLM invocations per reasoning step (Web-Search + Mind-Map + Coding) dramatically increase compute cost |
| Surpasses o3-mini-high on GPQA (81.2% vs 79.7%) despite using a weaker base model | Inference latency of 6.8 min/q for deep research — not suitable for interactive/real-time use |
| 6.8 min/q vs GPT Deep Research 17.8 min/q — 2.6x faster with comparable quality | Sequential agent invocation creates a bottleneck; all three agents can't run in parallel |
| Agent-based tools 66.13 vs direct API 47.18 on GAIA — 18.95 point gap proves agent architecture essential | Web-search quality entirely dependent on external search engine + re-ranker reliability; no built-in fact verification |
| 3 carefully chosen tools outperform 109 LangChain tools — simplicity beats breadth | Level 3 GAIA still only 45.46% — hard problems remain largely unsolved |
| Mind-Map structured memory (66.13) massively outperforms flat memory strategies (Raw: 47.84, MemGPT: 55.10) | Relies on multiple proprietary services (Bing, Cohere, Claude, DeepSeek) — expensive and vendor-locked |

## 4. Design Rationale

**Why agentic tools over direct API calls:** Three explicit reasons tested via ablation (Table 9): (1) Overcomes single-model token generation limits by distributing work across agents, enabling longer/higher-quality reasoning chains. (2) Agents can communicate uncertainty (e.g., "Given limited knowledge, a possible answer might be...") allowing the reasoning model to treat low-confidence outputs as tentative, reducing cascading errors. (3) Task-specific model routing — Claude-Sonnet for code, lightweight non-reasoning models for summarization, preserving efficiency and maximizing performance per subtask.

**Why exactly 3 agents (not more):** Ablation on GPQA (Figure 3) shows HF's 7-tool agent and LangChain's 109-tool agent both *degrade* performance vs base model. Many capabilities (translation, code interpretation) already exist inside the reasoning model — external duplicates introduce noise and inappropriate tool selection. Only web-search, coding, and Mind-Map showed positive synergy.

**Why Mind-Map over flat memory:** Raw reasoning text as memory yields only 47.84 on GAIA vs 66.13 with Mind-Map. Structured knowledge graph preserves logical entity relationships that flat text loses. Community clustering + summarization provides compressed, queryable context that scales with reasoning length. This is critically important for questions requiring long reasoning chains and many tool calls (Figure 5).

**Why re-ranking with threshold-based iteration:** Simple RAG without re-ranking (Search-O1 baseline: 74.6) is inferior to the full pipeline (76.4). Knowledge Refinement becomes redundant when Re-rank is present, hence removed.

## 5. Limitations and Failure Modes

1. **Computational overhead**: Multiple external LLM calls (DeepSeek-V3 for graph/query breakdown, Claude for code, Cohere for re-ranking, DeepSeek-R1 for reasoning) per step creates significant cost. Not suitable for budget-constrained deployments.

2. **Sequential bottleneck**: Agents are invoked serially; the reasoning LLM must halt and wait. No parallelism explored.

3. **No fact verification**: Web-Search agent has no mechanism to assess source credibility. Susceptible to misinformation, biased content, or hallucinated search results. Authors acknowledge need for "trust-aware retrieval" and "fact-checking agents."

4. **Hallucination cascade**: The entire system is LLM-dependent. A single hallucination in the reasoning chain can propagate through Mind-Map (as stored memory), corrupting downstream retrieval and tool calls.

5. **Limited base model testing**: Only DeepSeek-R1 and QwQ-32B were tested. Effectiveness on weaker reasoning models (Llama-8B class) is unknown.

6. **Level 3 GAIA ceiling**: Only 45.46% on hardest tier — complex multi-step tool-use problems remain largely unsolved. Gap to GPT Deep Research (47.60%) persists.

7. **Vendor lock-in**: Uses Bing, Cohere Rerank, Claude API, and DeepSeek API — not self-hostable without replacing multiple components.

8. **Domain transfer unverified**: Evaluated on general QA/science benchmarks. Performance on domain-specific tasks (legal, financial compliance, medical diagnosis) was not rigorously tested beyond the 56-expert-question survey, which used DeepSeek-R1 only.

## 6. Transfer to Lyra

### The One Idea: Mind-Map Structured Memory via Knowledge Graph + GraphRAG

Agentic Reasoning's Mind-Map agent demonstrates that converting raw reasoning chains into a structured knowledge graph — with entity extraction, community clustering (Leiden algorithm), community summarization, and GraphRAG retrieval — yields a **18-point GAIA improvement** over flat memory (66.13 vs 47.84). This directly addresses Lyra's core challenge: maintaining coherence over long, multi-turn, tool-augmented reasoning sessions.

### Workstream Route: §4.2 — Memory Subsystem

The Mind-Map architecture maps cleanly to Lyra's memory upgrade plan (§4.2). Lyra's current linear context window degrades over long sessions; a structured knowledge-graph memory with community-based compression and queryable retrieval would enable Lyra to:
- Track entities and their relationships across many turns
- Compress history via community summaries rather than raw text
- Answer retrospective queries ("What was the user's position on X in round 3?")
- Provide structured context to tool calls, improving tool-use accuracy

### Integration difficulty
- **Impact: 5** — Directly solves the long-context coherence problem that limits Lyra's multi-turn reliability
- **Effort: 4** — Requires implementing: (a) entity-relationship extraction from conversation turns, (b) Leiden community detection, (c) LLM-based community summarization, (d) GraphRAG retrieval. All components have open-source implementations available (GraphRAG by Microsoft, Leiden in python-igraph).
- **Tier: Breakthrough** — Mind-Map is the single component that most dramatically improves performance (Werewolf: 36%→72%, GAIA: ~48→66). It is well-defined, independently implementable, and has clear ablation evidence supporting its contribution.

### Implementation blueprint
1. Extract entities + relations from each Lyra conversation turn using a lightweight LLM call
2. Maintain an incremental knowledge graph (append-only, with edge weight updates)
3. Periodically run Leiden clustering to identify topic communities
4. Summarize communities with LLM; store as compressed memory
5. On user query, first search the knowledge graph via GraphRAG; inject retrieved context into the prompt
6. Provide graph context to any tool calls Lyra makes
