# Bridging the Pose-Semantic Gap: A Cascade Framework for Text-Based Person Anomaly Search

**Authors**: Zequn Xie, Guijin Luo, Chuxin Wang, Sihang Cai, Tao Jin, Zhou Zhao (Zhejiang University), Yixuan Tang (National University of Singapore)
**Venue**: arXiv:2604.23282v2 [cs.CV], 27 May 2026 (under review; code at https://github.com/GridNexus/SSDC)

## 1. Mechanism

SSDC is a coarse-to-fine retrieval pipeline that decouples structural filtering from semantic verification to resolve the "Pose-Semantic Gap" -- where semantically different actions (push-ups vs. falling) share near-identical skeletal geometries.

### Stage 1: Structure-Aware Coarse Retrieval

A lightweight pose-aware model recalls a candidate pool C from the full gallery G (|C| << |G|).

- **Pose Extraction**: A pose map P is extracted from input image I and encoded via a lightweight Pose Conv Module.
- **Visual Encoding**: A Swin Transformer processes I to produce patch-level embeddings f_I.
- **Pose-aware Cross-Attention Fusion**: Normalized pose features f_P act as queries attending to image features f_I:
  ```
  f_CA = Softmax( (W_q·f_P)(W_k·f_I)^T / sqrt(d) ) · (W_v·f_I)
  ```
- **Residual Connection**: f_V = f_I + f_CA (structure-enhanced representation).
- **Training Objectives**: L_stage1 = L_itc + L_itm + L_mlm, with Identity-based Hard Negative Mining (triplets where negatives share identity but perform different actions).
- **Backbone**: CMP (Cross-Modal Pose-aware) framework as default; also compatible with IRRA and RDE.

### Stage 2: Detective Squad Interaction

A multi-agent semantic verification module operating on top-K candidates from Stage 1.

**Hard-Negative Aware SFT**: Mine structural hard negatives I⁻ (images ranked high by structural similarity but semantically incorrect) from the frozen Stage I retriever to construct dataset D_sft.

**Three Specialized Agents** (all fine-tuned from Qwen3-VL-8B-Instruct via LoRA: rank=8, alpha=16, dropout=0.05):

1. **Detective (Filter)**: Binary verification -- "Is it a match? Yes or No!" Discards obvious negatives immediately. Acts as efficiency gatekeeper.
2. **Analyst (Extractor)**: Answers a 15-point fine-grained checklist (gender, clothing, action, background, etc.) to extract structured fragmented evidence.
3. **Writer (Integrator)**: Synthesizes Analyst's fragmented evidence into a precise, continuous new caption T_new.

**Generative Semantic Scoring**: Rather than black-box logits, compute interpretable cosine similarity between original query T and synthesized caption T_new:
```
S_sem(I_k, T) = E_txt(T) · E_txt(T_new) / (||E_txt(T)|| · ||E_txt(T_new)||)
```
where E_txt is a frozen text encoder (BERT or CLIP text tower).

### Stage 3: Adaptive Fusion & Re-ranking

Threshold-gated fusion mechanism with efficiency-aware dynamic inference:
```
S_final = { λ·S̃_str + (1-λ)·S_sem,  if S̃_str > ξ
          { S̃_str,                  otherwise
```
- λ = 0.4 (60% weight on semantic score, 40% on structural)
- ξ = 0.95 (confidence threshold -- only high-confidence candidates trigger semantic verification)
- Detective gates: Analyst + Writer run only if Detective outputs "Match"
- Top-K from Stage I filters >99.9% of gallery before MLLM invocation

## 2. Results

| Setting | Method | R@1 | mAP |
|---------|--------|-----|-----|
| Full (1M) | SSDC | **87.01%** | **92.74%** |
| Full (1M) | CMP (Stage 1 only) | 84.93% | 91.66% |

## 3. Trade-offs

| Win | Cost/Loss |
|-----|-----------|
| +8.34% R@1 over IRRA baseline (78.67→87.01) | Requires 2-GPU setup (RTX 3090 + A6000) |
| Cascade filters >99.9% gallery before MLLM | Latency still higher than single-stage methods |
| Analyst provides largest single-module gain (+1.92% R@1) | Without LoRA fine-tuning, drops 1.42% R@1 |
| Plug-and-play: works with IRRA, RDE, CMP backbones | 9,000 sample SFT dataset needed for role tuning |
| Generative text output is interpretable (vs black-box logits) | 15-point checklist is hand-crafted, domain-specific |
| Robust to 10 weather conditions (consistent gains) | OOD performance still modest at 59.45% R@1 on UCC |
| 2 refinement rounds sufficient (diminishing returns after) | Multi-agent orchestration adds pipeline complexity |

## 4. Design Rationale

The core insight is that **structural similarity (pose geometry) is necessary but insufficient** for semantic disambiguation. The authors observe that MLLMs have the reasoning capability to close this gap but are too expensive for brute-force gallery retrieval (1M+ images). Rather than choosing between speed and accuracy, SSDC **decouples** the problem: a lightweight model handles recall at scale, and an MLLM-based squad handles precision on a tiny candidate set. The multi-agent decomposition (Detective→Analyst→Writer) is motivated by the finding that monolithic MLLM prompting produces hallucinations; role specialization with structured intermediate outputs (binary verdicts, checklist evidence) constrains the model to produce verifiable, grounded captions. The threshold-gated fusion (Eq. 4) and dynamic inference strategy reflect a deliberate efficiency-first philosophy: expensive computation is reserved strictly for ambiguous boundary cases where it actually changes rankings.

## 5. Limitations & Failure Modes

- **Single MLLM backbone**: Only Qwen3-VL-8B extensively tested as unified squad engine; Qwen2.5 and InternVL3.5 only in ablation. Squad behavior with GPT-4V, Gemini, or Claude Vision unknown.
- **Domain specificity**: Trained/evaluated only on surveillance (PAB, UCF-Crime). Transfer to other anomaly domains (medical, industrial) untested.
- **Binary gating risk**: Detective's "Match/No" decision is a hard gate. False negatives at the Detective stage permanently exclude true positives from Analyst/Writer refinement.
- **Hand-crafted checklist**: The 15-point Analyst checklist (gender, clothing, action, etc.) requires domain expertise to construct and may miss novel anomaly attributes.
- **OOD gap**: 59.45% R@1 on UCC vs 87.01% on PAB in-domain -- a ~28-point drop suggesting significant dataset bias in the learned representations.
- **Latency not quantified**: While the cascade is described as "orders of magnitude" faster than full MLLM retrieval, no wall-clock latency numbers (ms/query) are reported.
- **No human evaluation**: All metrics are automated (R@K, mAP). No user study on whether the synthesized captions are actually useful to human operators.
- **Single-hop reasoning**: Detective Squad performs one inference chain per candidate; no cross-candidate comparative reasoning.

## 6. Transfer to Lyra

**The One Idea**: The two-stage cascade architecture with **Threshold-Gated Multi-Agent Semantic Verification** -- use a lightweight model for high-recall coarse retrieval, then activate an expensive multi-agent LLM squad only on ambiguous top-K candidates via a confidence threshold gate.

**Lyra Application**: Lyra's retrieval and verification pipelines can adopt this pattern: a fast embedding/model-based retriever produces a candidate pool with structural similarity scores; a multi-agent squad (Verify→Extract→Rewrite) is activated only when the retriever's confidence falls below a threshold, performing deep semantic reasoning on borderline cases. The key architectural insight is that the gate (Detective agent + threshold ξ) prevents wasted LLM inference on obvious negatives while the role decomposition (Analyst checklist → Writer synthesis) produces interpretable, grounded outputs instead of opaque scores.
