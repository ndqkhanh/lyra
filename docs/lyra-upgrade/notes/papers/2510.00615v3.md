## 1. Mechanism (Step-by-Step)

ACON is a model-agnostic framework that compresses both interaction histories and environment observations for LLM agents using optimization in natural language space — no model weight updates required.

### 1.1 Problem Formulation

The agent task is formulated as a POMDP. At each step t, the LLM agent M generates action a_t given history h_{t-1} and latest observation o_t:
```
M(o_t, h_{t-1}; θ, P_agent) → a_t
```
The context cost function C accumulates per-step token encoding costs across the trajectory. As interactions grow unbounded, the challenge is compressing context more effectively than naive heuristics.

### 1.2 Dual Compression Architecture

ACON compresses two context sources via an LLM compressor f(·; φ, P):

**History Compression (Eq 3):** When |h_t| > T_hist, compress raw history:
```
h'_t = f(h_t; φ, P_hist)
```
Selective — only triggered when history exceeds threshold (typically 4096 tokens).

**Observation Compression (Eq 4):** When |o_t| > T_obs, compress latest observation:
```
o'_t = f(o_t, h_{t-1}; φ, P_obs)
```

### 1.3 Optimization Objective (Eq 7)

```
max_ψ E[R(s_T(ψ))] - λ·E[C(H'(ψ))]
```
Where ψ = (φ, P) are compressor parameters (model weights + natural language guidelines). λ controls the tradeoff between reward maximization and cost minimization.

### 1.4 Compression Guideline Optimization — The Core Innovation

Since φ (LLM weights) can't be updated for proprietary models, and RL-based optimization is prohibitively expensive, ACON optimizes only the natural language guideline P via a two-stage process:

**Stage A — Utility Maximization (UT):**
1. Run agent on training set D_train both without and WITH compression
2. Collect contrastive subset D_cont: tasks where agent succeeds without compression but FAILS with compression
3. For each task in D_cont, query optimizer LLM (o3) to produce natural language feedback identifying what critical information was lost:
   ```
   Feedback = LLM(FeedbackInstr, H, H')
   ```
4. Aggregate feedback from multiple trajectories to update guideline:
   ```
   P^(1) = LLM(UpdateInstr, P^(0), concat(Feedback_1, ..., Feedback_n))
   ```
5. Sample K=5 candidate prompts, evaluate on D_cont, select best via success rate

**Stage B — Compression Maximization (CO):**
1. Take only tasks where agent SUCCEEDS with compression
2. For each, ask optimizer LLM to identify information that was unused during execution
3. Refine P^(1) → P^(2) to encourage shorter but sufficient contexts
4. Select best candidate optimizing reward-cost tradeoff

This produces two variants: ACON UT (reward-optimized only) and ACON UTCO (reward + cost-optimized).

### 1.5 Compressor Distillation (Eq 10-11)

To reduce compression overhead, the optimized teacher compressor f(·; φ_T, P*) is distilled into a smaller student model f(·; φ_S, P*) using standard cross-entropy loss on teacher-generated compressed outputs. Training uses LoRA (r=16, α=32, lr=1e-4, 3 epochs). Pipeline:
```
f(·; φ_T, P) →[prompt optim.]→ f(·; φ_T, P*) →[distill]→ f(·; φ_S, P*)
```

### 1.6 Algorithm 1 (Full Pseudocode)

```
Input: training indices I, agent M, compressor f, initial guideline P^(0), λ, R, K
Output: optimized guideline P*

1. Collect baseline trajectories without compression → H_i, r_i^base
2. I^+ ← {i ∈ I | r_i^base = 1}
3. For r = 0, 2, ..., 2R-2:
   a. Run M with compression f(·; φ, P^(r)) → H'_i, r_i, C(H'_i)
   b. D_cont ← {(H_i, H'_i) | i ∈ I^+, r_i(P^(r)) = 0}
   c. Generate contrastive feedback from D_cont
   d. Sample K candidate prompts, select best by success rate on I^+ → P^(r+1)
   e. Run M with P^(r+1), collect successful compressed trajectories D_succ
   f. Generate compression feedback identifying redundancies
   g. Sample K candidates, select by success_rate - λ·NormCost → P^(r+2)
4. Return P*
```

**Key insight:** Natural language feedback serves as a "textual gradient" — informing how to refine the compression prompt without touching model weights.

## 2. Results (Real Benchmark Numbers)

### 2.1 AppWorld (168 test-normal tasks, gpt-4.1 agent + gpt-4.1 compressor)

| Method | Avg Acc (%) | Steps | Peak Tokens (×10³) | Dependency (×10⁶) |
|---|---|---|---|---|
| No compression | 56.0 | 16.14 | 9.93 | 5.96 |
| FIFO (history) | 45.8 | 28.48 | 6.73 | 5.69 |
| Retrieval (history) | 27.4 | 33.17 | 8.39 | 6.68 |
| LLMLingua (history) | 39.3 | 24.42 | 7.50 | 6.37 |
| Prompting (history) | 43.5 | 24.01 | 6.93 | 5.29 |
| **ACON UT (history)** | **51.2** | 20.92 | 7.17 | 4.49 |
| **ACON UTCO (history)** | **56.5** | 22.82 | 7.33 | 4.69 |
| Prompting (obs) | 42.3 | 17.38 | 6.58 | 4.09 |
| **ACON UTCO (obs)** | **53.6** | 18.12 | 7.43 | 4.93 |

**Key:** ACON UTCO achieves 56.5% accuracy (matching no-compression 56.0%) with **26% peak token reduction** (9.93→7.33K) and **21% dependency reduction** (5.96→4.69M).

## 3. Trade-offs (Wins vs Loses)

| Dimension | Win | Loss/Cost |
|---|---|---|
| **Peak token usage** | 26-54% reduction across benchmarks | — |
| **Task accuracy (large model)** | ACON UTCO on AppWorld matches no-compression (56.5% vs 56.0%) | ACON UT drops ~5pp on AppWorld vs no compression (51.2% vs 56.0%) |
| **Task accuracy (small model)** | Qwen3-14B +32% relative gain on AppWorld (distraction mitigation) | — |
| **API cost** | 14-18% reduction end-to-end (with distilled Qwen3-14B compressor) | Compression call itself costs money (99.1% reduced by distillation) |
| **Latency** | — | 20-39% wall-clock increase (extra compressor call, KV-cache invalidation on history compression) |
| **Compressor deployment cost** | Distilled student preserves >95% teacher accuracy | 99.1% cheaper than teacher ($0.0004 vs $0.045/example) |
| **Model accessibility** | Works with proprietary API-only models (no weight access needed) | Optimizer quality matters: o3 > gpt-5 > gpt-4.1 (accuracy drops 3.6pp with gpt-4.1 optimizer) |
| **Combining history+obs compression** | Largest token reduction | Substantial accuracy degradation (45.8% vs 56.5% on AppWorld) |
| **Over-compression risk** | UTCO better for noisy/envs with redundant observations | UT safer for fact-dense tasks where precise retention matters |
| **Generalization** | GPT models well-tested; gpt-5-chat trends consistent | Not validated on Gemini, Claude, or massive open-source models (DeepSeek-R1, Qwen3-235B) |

## 4. Design Rationale

**Why optimize prompts instead of model weights?** The authors explicitly position against RL-based methods (MEM1, AgentFold, Context-Folding) that couple compression and reasoning into a single trainable model. These methods require full weight access and GPU-based RL training — prohibitive for proprietary/API-based LLMs (GPT-4.1, Claude, Gemini). By optimizing natural language compression guidelines, ACON is model-agnostic and works with any LLM, including API-only models.

**Why contrastive feedback?** The key insight: comparing trajectories where the agent succeeds without compression but fails with compression provides rich, dense signals about *exactly what information was lost*. This is far more informative than sparse scalar rewards (binary success/failure). The natural language "textual gradient" tells the optimizer *why* compression failed, enabling targeted guideline refinement.

**Why two-stage UT→CO?** UT alone optimizes for reward (preserving accuracy) but may produce verbose compression. CO alone would over-compress. The alternating optimization, inspired by multi-objective optimization, first ensures quality, then trims cost. Results confirm UTCO achieves the best accuracy-efficiency tradeoff on noisy environments (AppWorld) while UT is safer on fact-dense tasks (8-objective QA).

**Why distill the compressor?** An LLM compressor adds its own inference cost, potentially negating context savings. Distillation into a small model (Qwen3-14B via LoRA) reduces compressor cost by 99.1% while preserving 95%+ of teacher accuracy, making the approach economically viable.

## 5. Limitations & Failure Modes

1. **Limited model diversity in evaluation:** Primary experiments use GPT models only. No validation on Claude, Gemini, or massive open-source models (DeepSeek-R1, Qwen3-235B) due to GPU/budget constraints. Claims of model-agnosticism are empirically under-supported.

2. **Latency overhead from KV-cache invalidation:** History compression requires re-computing the entire compressed sequence's KV-cache, adding 20-39% wall-clock latency. This is a fundamental transformer limitation, not specific to ACON.

3. **No formal convergence guarantee:** The natural language optimization lacks theoretical guarantees. While sampling K=5 candidates and selecting the best mitigates drift, there's no principled reason this converges to an optimum.

4. **Distillation data bottleneck:** Only 100 training examples per domain used. The residual accuracy gap between teacher and student suggests insufficient data for complete behavioral cloning.

5. **Combined compression degrades sharply:** Applying both history AND observation compression together reduces accuracy substantially (45.8% vs 56.0% no-compression on AppWorld), limiting overall compression potential.

6. **Extra optimization round degrades performance:** Running UT→CO→UT (3 steps) hurts accuracy compared to UT→CO (2 steps), suggesting the optimization surface is non-monotonic and fragile.

7. **Benchmark-to-reality gap:** AppWorld, OfficeBench, and 8-objective QA are controlled environments. Real-world deployment with stochastic task complexity remains untested.

8. **Compression threshold sensitivity:** Performance depends heavily on threshold choice (4096 for history, 1024 for observations). Wrong thresholds either over-compress or under-compress.

## 6. Transfer to Lyra

**The ONE transferable idea:** Natural language compression guideline optimization via contrastive trajectory feedback — using an LLM optimizer to iteratively refine compression prompts by comparing failing (compressed) vs succeeding (uncompressed) agent trajectories.

**Why this matters for Lyra:** Lyra is a long-horizon agent that will accumulate unbounded context from tool calls, file operations, and multi-turn reasoning. The core insight — optimize compression quality via natural language feedback rather than model fine-tuning — is directly applicable. Lyra can use Claude (its agent model) with a smaller compressor model distilled from contrastive failure analysis, maintaining context precision while reducing KV-cache pressure.

**Workstream route:** §4.2.2 (Context Window Management / Memory System) — ACON provides the algorithmic blueprint for Lyra's context compression subsystem, including threshold-triggered selective compression, dual history+observation compression, and compressor distillation patterns.

**Impact:** 4 (high — directly addresses a known long-horizon agent bottleneck; the compression-while-preserving-critical-state pattern is universally needed)

**Effort:** 3 (moderate — requires implementing contrastive trajectory collection pipeline, guideline optimization loop, and optional compressor distillation; most logic is prompt-engineering + agent orchestration, not model training)

**Tier:** **breakthrough** — This is not parity work (Lyra doesn't have a structured compression system yet) and not merely investigative. The approach fundamentally changes how Lyra manages unbounded context, enabling longer autonomous runs without context-window exhaustion or reasoning degradation.
