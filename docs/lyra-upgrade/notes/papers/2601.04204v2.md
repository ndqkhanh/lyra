## 1. Mechanism (step-by-step)

TeachMaster implements "Generative Teaching" — educators specify pedagogical intents as lecture outlines; a multi-agent system autonomously produces complete educational videos. The key architectural innovation: **code (Python/Manim scripts) serves as the intermediate semantic medium** rather than pixel-level end-to-end generation, ensuring interpretability, editability, and precise control.

### Formal Problem Statement

Given a lecture outline `k` (keywords) and optional configurations `Φ`, the system produces:
```
O = F(k, Φ, f_human)  where O = {V_out, L_out}
```
Output: rendered video `V_out` + lecture script `L_out`.

### Stage 1: Content Planning

**Composition Agent** — cascades three sub-operations:
```
L_out = R( E( S(k) ), t )
```
- `S`: Semantic skeletonization — extracts core knowledge structure from keywords
- `E`: Content expansion — elaborates each skeleton node into full pedagogical text
- `R`: Length refinement — iteratively adjusts content to match target video duration `t`

**Pagination Agent** — segments long script `L_out` into discrete page units using a Chain-of-Agents (CoA) framework:
```
F_CoA(L_out) = ∪{i=1 to n} F_i(D_i) = {P_i}
```
Each local agent `F_i` handles one text segment `D_i`; results are aggregated into `n` pages `{P_i}`.

### Stage 2: Presentation Generation (Dual-Stream)

**Visual Stream** — a routing agent selects synthesis mode per page:
```
C_i = F_vis(P_i, Mode)   where Mode ∈ {Standard, ImageEnhanced}
```
- **Standard**: Coding agent compiles abstract logic into Python/Manim animation scripts
- **ImageEnhanced**: Invoked when content requires photorealistic assets beyond geometric primitives; integrates synthesized images as programmable objects

**Audio Stream** — narration agent conditions on page content, previous script, and visual code for cross-modal continuity:
```
T_i = F_narr(P_i, T_{i-1}, C_i)
```
TTS agent (Minimax) produces audio and quantifies speaking rate:
```
A_i, r_i = F_tts(T_i)
```

### Stage 3: Quality Validation (Three specialized agents)

**Debugging Agent** — iterative render-and-repair loop:
```
C_i^debug = F_debug( C_i, Error(C_i) )
```
On rendering failure: extracts error trace, prompts agent for targeted fix. If failure persists beyond retry threshold `τ`, fallback replaces complex elements with standardized templates.

**Synchronization Agent** — aligns visual dynamics with audio flow. Identifies event anchors in code and semantic units in script, uses speaking rate `r_i` to compute trigger timestamps, injects temporal control logic (e.g., wait statements):
```
C_i^sync = F_sync( C_i^debug, T_i, r_i )
```
Programmatic adjustment ensures traceability and reversibility.

**Layout Agent** — detects geometric overlaps, computes optimal positions via heuristic scanning order, applies code-level adjustments:
```
O_i = F_detect(C_i^sync),  Ω_i = F_retrieve(O_i, dir_{h,v})
C_i^layout = F_layout( C_i^sync, Ω_i )
```

**Human-in-the-Loop** — two interaction modes:
1. Interactive Refinement: natural-language-driven code modifications
2. Direct Code Editing: granular manual code intervention

Final code: `C_i^final = F_human( C_i^layout )`

**Final Rendering**: Each page rendered via Manim engine into video segment, merged with narration audio:
```
V_out = ∪{i=1 to n} Render(C_i^final)
```

### Implementation Details
- **Dual-engine**: Gemini-3 via API, or locally deployed Qwen3-32B (fine-tuned for Manim code generation)
- **Fine-tuning dataset**: 3,735 high-quality human-annotated pairs, categorized by difficulty, curriculum learning strategy
- **Training infra**: 8× NVIDIA A800 (40GB), LoRA (r=128, α=256), DeepSpeed ZeRO-3, LR = 1×10⁻⁵
- **TTS**: Minimax
- **Rendering**: Manim v0.19.0
- **Deployment**: Asynchronous task queue for multi-user concurrent generation

### Key Efficiency & Deployment Numbers
- **Production ratio**: ~2.46 min to produce 1 min of video (Gemini) — 10× faster than human (24.46), 5× faster than Sora 2 (12.80)
- **Cost**: Standard 45-hour semester course = **~$83.70** — approximately **0.3%** of traditional online course production (~$30,000)
- **Deployment**: >1,000 educators served (primary, vocational, QS Top 50 universities); >30,000 minutes generated; 40+ disciplines
- **Human intervention**: 75.2% of pages require zero manual edits; remaining pages finalized in average **1.88 interaction rounds**

## 3. Trade-offs

| Wins | Losses |
|------|--------|
| 10× faster production vs human (2.46 vs 24.46 ratio) | Overall video quality still below human (7.91 vs 8.29); gaps in spatial clarity (7.97 vs 8.22) and visual richness (6.98 vs 7.31) |
| 0.3% cost of traditional courses (~$83.70 vs ~$30,000) | Requires GPU cluster (8× A800 40GB) for fine-tuning and inference; barrier for under-resourced institutions |
| Editable, interpretable, debuggable output (code as medium) vs black-box video | ~24.8% of pages need manual intervention (avg 1.88 rounds) |
| Superior cross-modal alignment vs even human baseline (8.44–8.79 vs 8.13) | Gemini API dependency for top-tier quality; local Qwen variant loses 0.4 points on spatial clarity |
| Flexible duration control (35.97 min videos) vs Sora 2's short clips (0.25 min) | Code-centric approach constrained to Manim-renderable content (primarily STEM/geometric); photorealistic mode adds complexity |
| Bilingual + 40+ discipline cross-domain generalization | No multi-speaker dialogue or classroom interaction simulation |
| 81.71% human-AI judge agreement validates automated evaluation | Heuristic layout optimization (not learned) — may fail on complex overlapping layouts |

## 4. Design Rationale

Why code as intermediate medium over E2E pixel generation: (1) Education demands pedagogical structure and factual accuracy that black-box video models (Sora 2) cannot guarantee — Sora 2 scores 3.14 on script coherence vs 8.89 for TeachMaster. (2) E2E outputs are uneditable and computationally intensive (>12 min per min of video vs 2.46). (3) GUI-mimicking agent approaches require expensive multimodal trajectory datasets and training. (4) Code is inherently interpretable, modular, version-controllable, and precisely controllable — satisfying education's requirements for correctness and reproducibility. The multi-agent decomposition intentionally mirrors a human production team (planner, designer, animator, QA), enabling specialized prompts and verification per role. The dual-engine design (API + local) addresses the quality/privacy tension. Curriculum learning for fine-tuning mirrors how human animators progress from simple to complex scenes.

## 5. Limitations & Failure Modes

1. **Quality ceiling**: Overall video quality (7.91) remains below human (8.29); spatial clarity and visual richness are the primary gaps.
2. **Domain constraint**: Manim-centric rendering favors STEM content; non-geometric humanities/arts content may require image-enhanced mode with degraded quality.
3. **Heuristic layout**: Scanning-order heuristic for overlap resolution is not learned and may fail on dense, complex layouts.
4. **Template fallback risk**: After τ failed debug attempts, complex elements are replaced with standardized templates — losing pedagogical specificity.
5. **Evaluation gap**: GPT-5.2 judge achieves only 81.71% agreement with human experts (~18% disagreement); may miss subtle pedagogical quality issues.
6. **GPU dependency**: 8× A800 required for training; GPU cluster needed for production deployment — limits adoption in low-resource settings.
7. **Language scope**: Demonstrated only in Chinese and English; no evidence for low-resource languages.
8. **No learning outcome data**: Measures production efficiency and perceived quality, NOT actual student learning gains.
9. **Single-narrator TTS**: No multi-speaker scenarios, classroom dialogues, or Socratic interaction modeling.

## 6. Transfer to Lyra

**The one idea**: Use **code (executable structured representations) as an intermediate semantic medium for multi-agent communication**, replacing unstructured text handoffs with verifiable, traceable, reversible intermediate outputs. In TeachMaster, agents don't exchange raw pixels or prose — they exchange Python scripts that can be rendered, debugged, synchronized, and laid out by downstream specialized agents. Each agent's output is executable and verifiable before the next agent consumes it.

For Lyra's multi-agent orchestration, this maps directly to: instead of agents passing unstructured JSON or text, they pass structured, schema-validated, executable intermediate representations (e.g., typed action plans, verifiable function call sequences) that a "debugging agent" can validate and a "synchronization agent" can align before execution. This addresses the reliability concerns in Lyra's agent-to-agent communication and provides a principled framework for making agent outputs traceable and reversible.

**Workstream**: §4.1 (Multi-Agent Orchestration) — directly informs Lyra's inter-agent communication protocol design.

**Impact**: 4 — Foundational architectural pattern that improves reliability, debuggability, and verifiability of agent coordination.

**Effort**: 3 — Requires designing intermediate representation schemas (JSON Schema / DSLs) and one verification agent, but can leverage existing agent infrastructure.

**Tier**: Breakthrough — fundamentally changes how agents coordinate from unstructured to verifiable intermediate representations.
