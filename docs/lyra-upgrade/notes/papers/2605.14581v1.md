## 1. Mechanism (Step-by-Step)

### Problem Statement
Visual RAG systems use VLMs to encode document pages as sequences of vision patch tokens (hundreds per page). Multi-vector storage (e.g., ColPali) retains all patches for late-interaction retrieval but incurs high storage costs. Practical deployment requires compressing these patch tokens into a **single vector** via aggregation (mean pooling, [CLS] token, or max pooling). The paper asks: **does single-vector aggregation lose key numeric/semantic information in table-centric financial documents?**

### Experimental Design

**Step 1 — Diagnostic Benchmark Construction:**
- Two financial document datasets: FinQA (numerical reasoning) and TAT-DQA (complex multi-page tables)
- N = 200 document pairs total (100 each for sensitivity analysis, 100 each for visual attention analysis)
- Documents are rendered as screenshots/images (not parsed text), simulating real-world visual RAG

**Step 2 — Sensitivity Perturbation Types:**

| Category | Sub-type | Mechanism | Example |
|-----------|----------|-----------|---------|
| Numeric | Micro-Semantic | Small digit change | $5.21 → $5.29, 19.65% → 19.54% |
| Numeric | Macro-Semantic | Large digit change | $5.21 → $9.99, 10,520 → 99,999 |
| Text | Semantic Occlusion | Mask answer span with background color | "Revenue increased by $1.4B" → "Revenue increased by [MASK]" |

**Step 3 — Five Retrieval Scoring Mechanisms:**

Let $V^A = \{v_1^A, ..., v_n^A\}$, $V^B = \{v_1^B, ..., v_n^B\}$ be patch embedding sequences for original and counterfactual documents.

**Aggregation-based (single-vector):**
- **Mean Pooling:** $S_{mean} = \cos(\frac{1}{n}\sum v_i^A, \frac{1}{n}\sum v_i^B)$
- **Max Pooling:** $S_{max} = \cos(\max(V^A), \max(V^B))$ — dimension-wise maximum

**Late Interaction (multi-vector):**
- **MaxSim (ColBERT-style):** $S_{ms} = \frac{1}{n}\sum_i \max_j \cos(v_i^A, v_j^B)$
- **MeanPatch:** $S_{mp} = \frac{1}{n}\sum_i \cos(v_i^A, v_i^B)$ — spatially aligned patches
- **MinPatch (diagnostic probe, NOT a retrieval metric):** $S_{min} = \min_i \cos(v_i^A, v_i^B)$ — identifies the single worst-aligned patch

**Step 4 — Visual Attention Analysis (Structure):**
Three image versions created:
- **Reference:** Original document image
- **Signal Image:** Table content preserved, all surrounding area (headers, footers, margins) filled with background color
- **Noise Image:** Table area "erased" with background color, leaving only document template

Cosine similarity of signal and noise images against reference reveals which component dominates the single vector.

**Step 5 — Mitigation Strategies Tested:**
- **Variance-Weighted Pooling (VarWgt):** Higher weights to patches with greater variance across embedding dimensions
- **Attention-Guided Pooling (AttnGd):** Patch-level self-similarity matrix; low-diversity patches down-weighted
- **Top-k Removal (TopK-R):** Remove top-50 most similar aligned patch pairs, mean-pool the rest

**Step 6 — Models Tested:**
- Vision encoders: Qwen2.5-VL-7B, Qwen2.5-VL-32B, LLaVA-v1.5, Phi-3.5-Vision, DeepSeek-DeepEncoder
- Retrieval-optimized embeddings: Qwen3-VL-Embedding-8B, GME-Qwen2-VL-7B-Instruct

### Root Cause Mechanism: Global Texture Dominance
The single vector is dominated by background layout features (grid lines, headers, logos, margins). Sparse numeric signals (single-digit changes) occupy a tiny fraction of the total patch area and are smoothed over. This is analogous to a signal-to-noise problem where the "signal" (numbers) is <1% of the visual area but carries 100% of the semantic meaning.

## 2. Results (Real Benchmark Numbers)

### Core Sensitivity Benchmark (Table 4)

| Condition | Strategy | FinQA Score | TAT-DQA Score | Interpretation |
|-----------|----------|-------------|---------------|----------------|
| Micro-Numeric ($5.21→$5.29) | Mean Pooling | 1.0000 | 1.0000 | **Totally blind** |
| Micro-Numeric | Max Pooling | 0.9996 | 1.0000 | **Totally blind** |
| Micro-Numeric | MaxSim | 0.9975 | 0.9995 | Near-blind |
| Micro-Numeric | MinPatch | **0.7313** | **0.6959** | **Detects change** |
| Macro-Numeric ($5.21→$9.99) | Mean Pooling | 0.9998 | 0.9998 | **Totally blind** |
| Macro-Numeric | Max Pooling | 0.9985 | 0.9998 | **Totally blind** |
| Macro-Numeric | MaxSim | 0.9906 | 0.9955 | Near-blind |
| Macro-Numeric | MinPatch | **0.5160** | **0.5205** | **Strong detection** |
| Text Occlusion | Mean Pooling | 0.9980 | 0.9997 | **Totally blind** |
| Text Occlusion | Max Pooling | 0.9914 | 0.9997 | **Totally blind** |
| Text Occlusion | MaxSim | 0.9253 | 0.9669 | Marginal recovery |
| Text Occlusion | MinPatch | **0.1384** (LLaVA: -0.0903) | **0.1062** | **Strong detection, sometimes negative** |

*Scores near 1.0 = failure (can't distinguish documents); lower scores = success (can detect semantic changes). All numbers are cosine similarity on [0,1] or [-1,1] scale.*

### Model Robustness (Failure is universal)
- All 5 VLMs (7B to 32B) show mean-pooling similarity > 0.997 for all perturbations
- DeepEncoder shows slightly higher MinPatch scores (less sensitive) — its OCR-optimized encoder learns pixel-invariant representations
- Qwen2.5-VL-32B text sensitivity MinPatch: **0.0875** (strongest non-DeepEncoder sensitivity)

### Retrieval-Optimized Embeddings (Tables 5-6) — Same Blindness
- Qwen3-VL-Embedding-8B micro-numeric: 0.9992 (FinQA), 0.9999 (TAT-DQA)
- GME-Qwen2-VL-7B-Instruct micro-numeric: 0.9970 (FinQA), 0.9991 (TAT-DQA)
- Both fail identically to general VLMs — training objective doesn't fix this

### Mitigation Strategies (Table 7) — All Fail
- All three strategies (VarWgt, AttnGd, TopK-R) produce similarity > 0.99 across all conditions
- Best recovery is negligible (e.g., VarWgt text sensitivity still > 0.996)

### Visual Attention Analysis (Table 8) — Layout Dominance
- Mean Pooling bias toward layout: ∆ = +0.22 (Qwen2.5-VL-7B) to +0.27 (Phi-3.5-Vision) on FinQA
- Signal (table-only) similarity to reference: 0.717–0.911 (mean pooling)
- Layout (context-only) similarity to reference: 0.979–0.991 (mean pooling)
- **Conclusion:** Single vector is ~25% more similar to background layout than to actual table data

### Domain Specificity Check (Table 9)
- Natural images (cat vs dog) with same models: similarity 0.12–0.51 (healthy discrimination)
- Financial docs ($1.2M vs $1.3M): similarity 0.997–0.999 (collapse)
- **Domain gap: ~0.5–0.9** — confirms the problem is specific to sparse-signal-in-dominant-background documents

## 3. Trade-offs

### Wins vs Losses Table

| Aspect | Single-Vector Aggregation (Mean/Max Pooling) | Multi-Vector / Late Interaction (ColPali/MaxSim) | MinPatch Diagnostic |
|--------|----------------------------------------------|--------------------------------------------------|---------------------|
| **Storage cost** | O(1) vectors per page (low) | O(n) vectors per page, n=256-1024 patches (high) | N/A (diagnostic only) |
| **Retrieval speed** | Fast (single cosine) | Slow (n×n patch comparisons) | N/A |
| **Scalability** | Excellent for large corpora | Poor — storage explodes | N/A |
| **Numeric sensitivity** | **FAILS** (similarity ~1.0 for $5.21→$9.99 change) | Marginal (MaxSim ~0.99, still poor) | **PASSES** (similarity ~0.51) |
| **Text sensitivity** | **FAILS** (similarity ~1.0 for masked answers) | Marginal (MaxSim ~0.93) | **PASSES** (similarity ~0.09) |
| **Layout vs. data focus** | Heavily biased to layout (∆ +0.22–0.27) | Moderate bias | Isolates signal |
| **Domain robustness** | Natural images work; financial docs fail | Moderate | Domain-independent probe |

### Core Tension
**Cost vs. Accuracy.** Single-vector is 100-1000x cheaper to store and query, but the accuracy loss is catastrophic for financial documents where single-digit changes matter. There is currently no known mitigation that recovers the signal within the single-vector paradigm. The paper argues multi-vector or learned-aggregation approaches are *necessary*, not optional.

## 4. Design Rationale

### Why This Approach?

1. **Diagnostic decomposition separates encoder quality from aggregation quality.** Prior work confounded "does the VLM fail to see details?" with "does aggregation destroy details?" By using MinPatch as a diagnostic probe (not a retrieval metric), the authors prove the encoder *does* see the difference — it is the aggregation that destroys it. This is a clean experimental design.

2. **Sensitivity perturbation (not natural queries) isolates the mechanism.** Instead of evaluating retrieval on natural queries (where many confounding factors exist), they create controlled counterfactual pairs where the *only* difference is a known semantic change. This lets them measure information loss directly via cosine similarity between original/counterfactual embeddings.

3. **Visual attention analysis pinpoints the root cause.** The signal/noise image decomposition proves global texture dominance quantitatively — the single vector is 25% more similar to the page's empty layout than to its actual table content.

4. **Why not just use OCR + text RAG?** The paper implicitly argues this is insufficient because OCR linearizes tables (destroying row-column structure). Visual RAG is needed for structural fidelity, but single-vector aggregation negates that advantage for numeric details.

5. **Exhaustive model coverage.** Testing 5 VLMs + 2 retrieval-optimized embeddings proves the failure is *architectural*, not model-specific. No model escapes.

---

## 5. Limitations & Failure Modes

1. **Small diagnostic set:** N=200 document pairs across only 2 datasets (FinQA, TAT-DQA). Statistical power is limited; no confidence intervals reported.

2. **No full retrieval evaluation:** All results are pairwise cosine similarity between original and counterfactual. The paper explicitly acknowledges that Recall@k, nDCG, and other ranking metrics over a large corpus are not evaluated. The diagnostic approach proves the *microscopic* failure but does not quantify the *macroscopic* impact on end-to-end retrieval quality.

3. **Limited perturbation types:** Only single-digit numeric changes and text occlusion are tested. Real-world financial document variations (reformatting, font changes, column reordering, currency symbol changes, footnote alterations) are not covered.

4. **Domain specificity:** The paper acknowledges that results may not transfer to non-financial domains. Natural images maintain discriminability. Invoices, balance sheets with different layouts, and handwritten financial notes are untested.

5. **No proposed solution:** The paper is purely diagnostic/anatomical. It identifies the problem but offers no algorithm or architecture to fix it (beyond suggesting multi-vector retrieval as the path forward).

6. **English-only financial documents:** No cross-lingual validation. Non-English financial documents with different visual conventions are untested.

7. **Single-page analysis:** TAT-DQA has multi-page documents, but the analysis treats each page independently. Cross-page context effects are not studied.

8. **MinPatch is not a practical retrieval metric:** It requires aligned patch pairs between query and document, meaning it can only be used for diagnostic pair comparison, not actual retrieval against a corpus.

## 6. Transfer to Lyra

### The One Transferable Idea
**Single-vector embeddings are provably blind to fine-grained content changes in structured documents dominated by repetitive visual backgrounds.** When Lyra builds retrieval pipelines that ingest tabular, form-based, or template-heavy documents (financial reports, legal contracts, medical forms, invoices), naive mean-pooled visual embeddings will collapse semantically distinct documents to near-identical vectors. The encoder *does* see the differences (proven by MinPatch), but aggregation destroys them.

### Lyra Application
If Lyra's context ingestion pipeline (§4.1 — Document Understanding & Ingestion) uses visual RAG for structured/tabular documents, it MUST use multi-vector (late-interaction) retrieval or a learned-aggregation mechanism rather than mean-pooled single vectors. This is not a performance optimization — it is a correctness requirement for any pipeline that retrieves financial/numeric documents by content.

### Workstream Route
**§4.2 — Context & Retrieval Architecture (Memory Systems)**
Specifically: the retrieval quality and indexing strategy for structured document corpora. This finding should gate any decision to use visual embeddings for document retrieval in Lyra's memory layer.
