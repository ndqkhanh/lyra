## 1. Mechanism

### 1.1 Benchmarking Platform Architecture

The Open ASR Leaderboard is a **reproducible benchmarking platform** with three evaluation tracks:

1. **Leaderboard (Short-form English):** Audio ≤30s (Whisper's receptive field), tested on 9 datasets including AMI, Earnings22 (subset), GigaSpeech, LibriSpeech clean/other, SPGISpeech, TED-LIUM v3, VoxPopuli.
2. **Multilingual:** German, French, Italian, Spanish, Portuguese across CoVoST-2, FLEURS, and MLS datasets.
3. **Long-form (English):** Audio >30s, evaluated on CORAAL (159h), Earnings21 (39h), Earnings22 (119h), TED-LIUM v3 (3h).

### 1.2 Standardized Evaluation Pipeline

**Text Normalization (critical for fair comparison):**

All text is normalized prior to WER computation using a pipeline closely following Whisper's approach:
- Remove punctuation and casing
- Number normalization (e.g., "zero" → "0")
- Spelling standardization
- Removal of filler words (ah, uh, um)
- Disfluency handling varies by dataset (see Table 1 in paper)

This normalization is necessary because not all models produce transcripts with punctuation, casing, or disfluencies.

**Metrics:**

- **WER (Word Error Rate):** Standard edit-distance metric after normalization. Models ranked by average WER across all datasets in a track.
- **RTFx (Inverse Real-Time Factor):**

```
RTFx = Total duration of audio / Transcription time
```

Higher values = faster inference. Chosen over standard RTF so "higher is better" and relative speedups (10×, 100×) are easily interpretable.

### 1.3 Hardware & Batch Strategy

All evaluation runs on **NVIDIA A100-SXM4-80GB GPU** (driver 560.28.03, CUDA 12.6). Batch size starts at 64, reduced adaptively (48, 32, 16, ...) when memory constrained.

### 1.4 Model Coverage & Encoder-Decoder Taxonomy

86 models evaluated from 26 organizations. 74 open-source, 12 proprietary APIs.

**Encoder taxonomy (Table 2):**
- Conformer-based (28 models): FastConformer, standard Conformer
- Whisper-based (25 models): vanilla, fine-tuned, LoRA-adapted, distilled
- Self-supervised (15 models): wav2vec2, HuBERT, data2vec
- Custom (10 models): Moonshine, Qwen3 ASR, Voxtral Realtime, etc.

**Decoder taxonomy (Table 2):**
- Transformer: 32 models — highest accuracy
- CTC: 26 models — fastest inference
- RNN-T/TDT: 8 models — strong speed-accuracy tradeoff
- LLM-based: 12 models — leverages pretrained text language models

### 1.5 Community Contribution Protocol

External contributors add models via PR with:
1. A Python evaluation script per dataset
2. A Bash script calling the Python script for each dataset-model combination
3. Self-reported metrics

Scripts are verified in the maintainers' environment before leaderboard update. 29 PRs merged for 56 models, 34 additional maintenance PRs.

**Key quantitative findings:**
- Conformer-based + Transformer/LLM decoder achieves best accuracy (5.42% average WER)

- Best CTC model (NVIDIA Parakeet CTC 1.1B) ranks 34th overall on WER but delivers RTFx=2730
- Small models (0.6B params) with TDT achieve RTFx=3390 — competitive accuracy with extreme speed

## 3. Trade-offs

| Aspect | Win | Loss |
|--------|-----|------|
| **Architecture: Conformer+Transformer** | Best WER (5.42% avg) | Moderate RTFx (145–525), larger models |
| **Architecture: Conformer+CTC** | Fastest inference (RTFx 2730–6400) | WER 0.6–3.5pp worse than best |
| **Architecture: Conformer+TDT** | Best speed/accuracy balance (RTFx 3330–3390, WER 6.05–6.32%) | Less adoption, fewer languages supported |
| **Whisper-based encoders** | Pretrained on 99+ languages, strong multilingual baseline | 3.77× slower than Conformer-based |
| **Multilingual support** | Broader language coverage | English WER degrades (0.27–0.65pp) |
| **Long-form vs short-form** | CTC/TDT gap narrows in long-form | Closed-source models dominate long-form (7.32% vs 9.73% best open) |
| **LLM-based decoders** | Leverage pretrained text knowledge, strong accuracy | Slowest inference (RTFx 54–151 for large models) |
| **Self-supervised encoders** | 1600+ languages possible (Meta Omnilingual) | Ranks only 53rd in WER (8.14%) |

## 4. Design Rationale

**Why a leaderboard instead of a single benchmark paper:**
- No single dataset or metric suffices for ASR evaluation. Multiple datasets per track catch anomalous per-dataset performance and mitigate test-set contamination.
- Community contribution model (PR-based) enables continuous growth — 29 PRs added 56 models.
- Standardized across 4 toolkits (ESPNet, NeMo, SpeechBrain, Transformers) prevents toolkit-specific biases.

**Why RTFx instead of RTF:**
- "Higher is better" is more intuitive for leaderboard UX. 10× or 100× speedups map directly to magnitude.

**Why text normalization (punctuation/casing removal):**
- Not all models produce formatted output. Without normalization, models that don't output punctuation would be unfairly penalized on punctuated reference transcripts.

**Why separate long-form track:**
- 32% of open models are Whisper-derived with 30s receptive field limit. Chunking strategies and context window sizes significantly affect long-form quality independent of short-form accuracy.

## 5. Limitations & Failure Modes

1. **Test-set contamination risk:** Despite non-commercial license datasets as safeguards, no guarantee models haven't trained on evaluation data. Private evaluation sets suggested as future work.
2. **Hardware-dependent RTFx:** Absolute RTFx values tied to A100-80GB. Relative rankings may shift on different hardware (CPU, other GPUs, edge devices). Only useful for relative comparisons within the same environment.
3. **English-centric:** Multilingual track covers only 5 European languages (DE/FR/IT/ES/PT). No Asian, African, or low-resource languages.
4. **Single-metric emphasis:** WER is dominant despite known weaknesses (doesn't capture semantic errors, penalizes all errors equally). Token error rate suggested as future addition.
5. **No noise/robustness evaluation:** No far-field, noisy, or reverberant conditions despite acknowledgment in future work.
6. **Closed-source model opacity:** Proprietary APIs lack architectural transparency — impossible to analyze why they outperform on long-form.
7. **Self-reported metrics risk:** Contributors self-report metrics, though scripts are verified. Malicious or erroneous submissions possible.
8. **Disfluency handling inconsistency:** Some models explicitly remove disfluencies while others transcribe verbatim. Normalization removes filler words, but this may mask real transcription quality differences.

## 6. Transfer to Lyra

**The ONE transferable idea:** The **community-PR-driven evaluation protocol** — where external contributors submit standardized Python+Bash evaluation scripts verified in a controlled environment before leaderboard acceptance — provides a template for Lyra's own agent evaluation harness. Instead of a single benchmark, Lyra could maintain a continuously growing evaluation board where new agent architectures, tool-use strategies, and prompt templates are contributed via PR with verified evaluation scripts, enabling transparent, reproducible agent capability tracking across multiple dimensions (accuracy, latency, cost, reliability).

**Impact:** 3 — Useful methodology transfer to agent evaluation, requires significant adaptation from ASR to agent domains
