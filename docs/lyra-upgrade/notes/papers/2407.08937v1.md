## 1. Mechanism (step-by-step)

SE-GPT is a lifelong experiential learning framework with one memory store and five LLM-orchestrated modules. The system receives a stream of user questions, categorizes each into a task type, learns experience for new or under-learned tasks via transfer and induction, then answers using accumulated experience.

### 1.1 Task-Specific Experience Memory

A key-value store mapping task → {name, description, experience}, where experience has two parts:
- **Procedure:** Ordered steps for handling the task
- **Suggestions:** How to better accomplish or avoid low-quality responses

Memory starts empty and grows autonomously. Semantic retrieval uses Faiss indexing (cosine similarity).

### 1.2 Task Type Categorization (Module 1)

Three sub-steps:
1. **Prompt 1** — Given the user question, ChatGPT generates a task name and abstract task description (avoiding question-specific details)
2. **Faiss retrieval** — Fetch top-5 semantically most similar tasks from memory
3. **Prompt 2** — ChatGPT selects which (if any) of the 5 candidates is identical to the generated task. If match found → link question to matched task; else → create new task entry with empty experience in memory.

Stability mechanism: Prompt 2 runs multiple times until one option is output twice; that becomes the final output.

### 1.3 Experience Transfer (Module 2)

Four sub-steps:
1. **Faiss retrieval** — Top-10 semantically most similar tasks from memory
2. **Prompt 3** — Select which of the 10 should be source tasks for transfer (output: list of task IDs, possibly empty)
3. **Prompt 4** — Step-by-step transfer: (i) understand differences between source and target tasks, (ii) identify shared general experience across source tasks, (iii) rephrase general experience in target task context. Output: `E_transferred` (≤20 suggestions + ≤20 procedure steps)
4. **Prompt 5** — If existing memory experience `E_mem` is non-empty, merge `E_transferred` and `E_mem`, deduplicating and unifying.

If no source tasks selected in steps 1-2, `E_transferred = E_mem` (fallback).

### 1.4 Autonomous Practice (Module 3)

Four sub-steps, repeated 5 times to collect 5 examples:
1. **Web retrieval** — Fetch Wikipedia documents semantically most related to user question
2. **Prompt 6** — Reference one web document + user question + task description → generate a new question of the same task type (constrained to match structure/format of the example question)
3. **Prompt 7** — Answer the generated question using `E_transferred` as guidance, producing a reasoning chain and final answer
4. **Prompt 8** — Verify correctness by checking reasoning + answer against the reference web document. Output: `"correct"`, `"wrong"`, or `"inconclusive"` (discarded if inconclusive)

### 1.5 Experience Induction (Module 4)

**Prompt 9** — Summarize experience from correct and incorrect examples:
- Step 1: Summarize commonalities in correct examples, identify patterns in incorrect examples, compare correct vs incorrect differences
- Step 2: From observations, extract general task-solving insights applicable to unseen examples

If `E_transferred` is non-empty, merge `E_induced` with it via Prompt 5. Final `E_induced` replaces `E_mem` in memory.

### 1.6 Skip Learning Condition (Module 5)

Memory records the number of incorrect examples per autonomous practice. If that count = 0 for **three consecutive practices** on the same task, that task is marked as "adequately learned" and further learning is skipped.

### 1.7 Reasoning with Experience (Module 6)

**Prompt 10** — Given the stored experience (suggestions + procedure) and the user question, ChatGPT produces the final response.

### Algorithm Pseudocode

```
For each user question Q:
    (name, desc) = Prompt1(Q)
    top5 = Faiss.search(memory, desc, k=5)
    match = Prompt2(desc, top5)
    if match:
        task = memory[match]
    else:
        task = {name, desc, experience: empty}
        memory.add(task)

    E_mem = task.experience
    if skip_condition_met(task):
        return Prompt10(Q, E_mem)    // directly answer

    // Experience Transfer
    top10 = Faiss.search(memory, task.desc, k=10)
    source_ids = Prompt3(task.desc, top10)
    if source_ids non-empty:
        E_transferred = Prompt4(task, source_tasks)
        if E_mem:
            E_transferred = Prompt5(E_transferred, E_mem)
    else:
        E_transferred = E_mem

    // Autonomous Practice (5 iterations)
    examples = []
    for i in 1..5:
        doc = WebRetrieve(Q)
        new_Q = Prompt6(doc, Q, task.desc)
        (reasoning, answer) = Prompt7(new_Q, E_transferred)
        verdict = Prompt8(doc, new_Q, reasoning, answer)
        if verdict != "inconclusive":
            examples.append({new_Q, reasoning, answer, verdict})

    // Experience Induction
    E_induced = Prompt9(examples)
    if E_transferred:
        E_induced = Prompt5(E_transferred, E_induced)
    task.experience = E_induced  // update memory

    // Skip check
    task.incorrect_count = count(verdict == "wrong" in examples)
    task.consecutive_zero = track_zero_streaks(task)

    return Prompt10(Q, E_induced)
```

## 3. Trade-offs

| Win | Cost / Loss |
|-----|-------------|
| +3.8% (GPT-3.5) / +5.3% (GPT-4) accuracy gain over zero-shot | ~71x token overhead per example (13,532 vs 191 tokens) |
| Fully autonomous — zero human annotation needed for experience acquisition | 5 days runtime for GPT-3.5; 15-25 days for GPT-4 on 6K test examples |
| Experience quality is high (99.8% human-evaluated accuracy) | Autonomous practice is the dominant cost driver (52% of all tokens) |
| Experience transfer alone sustains acceptable performance after warm-up ("- w/o induction" holds at 68.3% vs 69.4% full) | Cold-start problem: empty memory means early examples get no transfer benefit |
| GPT-4 generates 56% more insights than GPT-3.5 (21.9 vs 14.0 avg per task) | GPT-4 runs 3-5x slower, making cost-performance trade-off significant |
| Skip-learning mechanism saves redundant computation for mastered tasks | Skip threshold (3 consecutive zero-error rounds) is heuristic and not tuned |
| Task-agnostic: works across reasoning, commonsense, NLI, and logic tasks | Less effective for factual-knowledge tasks (acknowledged limitation) |
| Web retrieval dramatically improves practice quality (+8% validation accuracy, +2x question diversity) | Web retrieval adds latency and introduces dependency on external source availability |
| Grows stronger over time (memory accumulates) | Memory unbounded growth — no pruning or forgetting mechanism described |

## 4. Design Rationale

The approach is grounded in theories of human cognition: **experiential learning theory** (Novak & Gowin, 1984), **transfer of learning** (Deese, 1952; Perkins et al., 1992), and **introspective multistrategy learning** (Cox, 1996). Rather than manually crafting prompts or using demonstrations (which suffer from format inconsistency, noise, and low diversity as shown in the Self-ICL case studies), SE-GPT **summarizes general task-solving insights** from multiple concrete examples. This "extract patterns, not examples" design reduces noise amplification. The two-experience-type structure (procedure + suggestions) deliberately mirrors how humans organize knowledge: procedural steps plus cautionary heuristics. The transfer-then-induce-then-merge pipeline ensures new tasks benefit from related-task knowledge before attempting practice, reducing the search space. The skip-learning condition (3x zero error) implements a basic **competence threshold** that trades perfection for efficiency. Choosing Wikipedia as the sole web source constrains the verification signal to relatively reliable, structured text instead of open web noise.

## 5. Limitations & Failure Modes

1. **Experience Failure Modes:** Even with 99.8% accurate experience, LLMs still err due to: (a) reasoning errors/hallucination during inference, (b) partial disregard of experience, (c) lacking necessary factual knowledge. The framework cannot force the LLM to follow experience faithfully.

2. **Extreme Computational Cost:** 13,532 tokens per example at inference time (71x baseline). The autonomous practice module alone consumes 52% of all tokens. Practical deployment without optimization is infeasible for most use cases.

3. **Cold Start:** The framework begins with empty memory. Early questions get no transfer benefit. The authors suggest bootstrapping from annotated corpora but do not implement this.

4. **Task Applicability Gap:** Explicitly noted that the framework works better for reasoning tasks than factual-knowledge tasks (e.g., WikiQA). No adaptive mechanism to determine when experience is needed vs. not.

5. **Unbounded Memory Growth:** No forgetting, pruning, or consolidation mechanism. Memory grows monotonically, raising retrieval latency and quality concerns at scale.

6. **Non-Determinism:** Temperature=1 throughout. Prompts 2 and 8 run multiple times until consensus, adding cost and latency variance.

7. **No Agentic Tool Use:** The framework cannot actively seek missing information or interact with users — a shortcoming Self-EXP's case study exposed when suggesting "Ask Jesse about Addison's purpose."

8. **GPT-Only Validation:** All experiments use OpenAI models only. No tests with open-weight models (Llama, Mistral, etc.).

## 6. Transfer to Lyra

**The One Idea: Autonomous Multi-Source Experience Accumulation with Competence-Gated Reuse**

SE-GPT's core transferable insight is the closed loop of **(1) categorize problem → (2) transfer from similar known problems → (3) practice against verifiable ground truth → (4) induce general patterns from successes/failures → (5) skip when competent → (6) reuse accumulated patterns.** This maps directly to Lyra's **§4.2 Memory Systems** workstream — specifically, building a long-term, self-improving memory that accumulates task-solving patterns across sessions without human annotation. Lyra could implement a lighter version: store interaction outcomes (success/failure + context), retrieve similar past interactions via embedding similarity, synthesize transferable guidance via an LLM induction call, and gate the overhead with a competence threshold (e.g., skip if last N similar tasks succeeded).

**Workstream:** §4.2 — Memory Systems (long-term self-improving memory)

**Impact:** 4 — Directly enhances Lyra's ability to learn from its own execution history without manual feedback loops
**Effort:** 4 — Requires embedding infrastructure (already planned), induction prompts, outcome logging, skip-logic; the autonomous practice loop with web verification is the heavy part
**Tier:** investigate — Worth prototyping the core "categorize → retrieve → induce → reuse" loop but the full autonomous practice module (70x token multiplier) is too expensive for current Lyra; start with the transfer-only variant which retains ~70% of gains at much lower cost
