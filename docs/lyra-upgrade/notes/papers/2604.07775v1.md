# ACIARENA: Toward Unified Evaluation for Agent Cascading Injection (Hengyu An, Minxi Li, Jinghuai Zhang, Naen Xu, Chunyi Zhou, Changjiang Li, Xiaogang Xu, Tianyu Du, Shouling Ji — Zhejiang University, Tsinghua University, UCLA, Palo Alto Networks; arXiv:2604.07775v1, April 2026)

## 1. Mechanism (step-by-step)

ACIARENA is a unified evaluation framework for measuring how Multi-Agent Systems (MAS) resist Agent Cascading Injection (ACI) attacks. The paper formalizes the problem, builds a modular benchmarking harness, generates attacks via an automated mutation loop, and proposes a defense based on semantic pruning.

### 1.1 Formal MAS Definition

An LLM agent is defined as a tuple:
```
A = (π, P, M, T)
```
where **π** is the policy function (LLM), **P** is the agent's role profile, **M** is the memory module, and **T** is the set of external tools.

A MAS **S** is defined as:
```
S = ({A_i}^N_{i=1}, E ⊆ {(A_i, A_j) | i ≠ j, 1 ≤ i,j ≤ N})
```
where **E** encodes the directed communication topology. Agents act sequentially per a predefined order: receive upstream messages, generate a new message, send to downstream agents.

### 1.2 Threat Model — Three Attack Surfaces

Attacks are modeled at the granularity of a single agent's components (superscript Δ denotes injection):

1. **Adversarial Input (AI)**: Inject malicious prompts into the agent's instruction **I**, memory **M**, or tool descriptions **T**. The resulting malicious message is: `m_malicious = π(I^Δ, P, M^Δ, T^Δ)`

2. **Malicious Agent (MA)**: Compromise agent profiles **P^Δ** so agents autonomously generate harmful messages: `m_malicious = π(I, P^Δ, M, T)`

3. **Message Poison (MP)**: Tamper with messages in transit on any edge (A_i, A_j): `m_malicious = attacker(π^Δ(I, P, M, T))`

### 1.3 Three Attack Objectives

- **Hijacking**: Deviate system from intended user instruction (e.g., force agents to send POST to attacker URL)
- **Disruption**: Inject misleading information to degrade task success rate
- **Exfiltration**: Induce agents to expose secrets (API keys, tokens) by embedding extraction instructions

### 1.4 Automated Attack Generation (Algorithm 1)

The attack optimization is a **generate-mutate-select loop** with no gradient access (black-box):

1. **Initialize** with manual attack objective `a_0`
2. **For t = 1 to T**:
   - Sample mutation operators `ω ∈ Ω` (pre-defined operator set)
   - Generate candidate attacks: `A_t = {a' = ω(a_t) | ω ∈ Ω}`
   - Execute each candidate `a'` on N target MAS to get N responses
   - Compute judge score: `J(a') = J_stealth(a' | c) + (1/N) Σ_j J_harm(S^{(j)}(a'), a_0)`
     - `J_stealth`: similarity between `a'` and benign prompts of the current attack surface
     - `J_harm`: alignment of system response with original attack objective
   - Select: `a_{t+1} = argmax J(a')`
3. Return best attack across all iterations: `a* = argmax_{t∈[1,T]} J(a_t)`

Highly effective attacks converge to patterns like enforcing explicit output formats or embedding persuasive downstream directives.

### 1.5 Evaluation Metrics

- **BU (Benign Utility)**: System utility (pass@1) without attacks
- **UA (Utility under Attack)**: System utility under attack
- **ASR (Attack Success Rate)**: Proportion of tasks where attack objective is achieved (via string matching or LLM judge)
- **PVI (Propagation Vulnerability Index)**: Weighted-ASR by minimal topological distance from malicious agent to final response: `PVI = Σ_{a_i∈A} (L_{a_i} / Σ_{a_j∈A} L_{a_j}) · ASR_{a_i}`

### 1.6 ACI-SENTINEL Defense

The key innovation: instead of detecting suspicious messages, **prune agent state after each step to retain only semantically essential information aligned with the original task** (Principle of Contextual Least Privilege). The defense prompt instructs the LLM to:
1. Read user query + previous answer
2. Perform semantic alignment check (keep only content with valid causal link to user intent)
3. Extract only sentences directly addressing the query, preserving original wording
4. Remove unrelated/speculative/off-topic content
5. Maintain original order

### 1.7 Modular Architecture

Five decoupled modules: **Agent** (LLM + memory + tools), **MAS** (bootstrap → step → conclude lifecycle), **Task** (query + ground truth + verify), **Attack** (unified interface, direct component modification or step method override), **Executor** (schedules attacks/defenses with fine-grained timing control).

## 2. Results (benchmark numbers)

### 2.1 Scale
- **1,356 test cases**, organized into 3 evaluation suites (Hijacking: 336, Disruption: 585, Exfiltration: 435)
- **28 distinct attacks** across 3 attack surfaces
- **6 MAS implementations** (MetaGPT, AutoGen, CAMEL, Self Consistency, LLM Debate, AgentVerse)
- **3 LLMs** (GPT-4o, GPT-4o-mini, Qwen2.5-7B-Instruct)

**Code Domain — Hijacking ASR**:
- MetaGPT: 100.00% ± 0.00 (worst)
- LLM Debate: 100.00% ± 0.00 (worst)
- Self Consistency: 95.00% ± 0.00
- CAMEL: 20.28% ± 1.19 (best resilience)
- AutoGen: 80.83% ± 0.00
- AgentVerse: 48.05% ± 1.19

**Code Domain — Exfiltration ASR**:

**CAMEL Utility-Robustness Trade-off**: Hijacking ASR = 7.05% but BU only 41.03% (Math) — robustness from _failure to execute_, not active resistance.

### 2.3 Defense Results (Table 2, Code Domain)

**AutoGen Exfiltration**:
- No defense: ASR = 54.00% ± 0.00
- +ACI-SENTINEL: ASR = 0.22% ± 0.00 (**53.33% absolute reduction** — near-neutralization)
- +Sandwich: ASR = 60.00% ± 0.00 (**amplified** the attack by 6pp)

**MetaGPT Hijacking**:
- No defense: ASR = 79.44% ± 1.20
- +ACI-SENTINEL: ASR = 0.00% ± 0.00 (**79.17% absolute reduction** — complete neutralization)
- +AGrail: ASR = 11.67% ± 0.00 (but BU collapses from 57.78 → 6.67)

**AgentVerse Exfiltration**:
- No defense: ASR = 61.56% ± 0.96
- +ACI-SENTINEL: ASR = 9.11% ± 0.96 (**52.45% absolute reduction**)

### 2.4 Model-Level Findings
- GPT-4o-mini achieves lowest ASR across all suites — **stronger model capability does not improve robustness**; GPT-4o shows higher ASR in Disruption suite
- LLM judge agreement with human majority vote: **98%** (Cohen's kappa: 0.92)

### 2.5 Adaptive Attack Results (Table 3)
ACI-SENTINEL defenses degrade under optimized attacks:
- AutoGen: ASR rises from 6.67% → 36.67% (UA collapses from 13.33% → 0.00%)
- AgentVerse: ASR rises from 3.33% → 13.33%
- MetaGPT: ASR rises from 0.00% → 10.00%

### 2.6 Attack Surface Variability (Figure 6)
- Adversarial Input achieves highest ASR for precision attacks (Hijacking, Exfiltration)
- Malicious Agent surpasses Adversarial Input for Disruption
- Message Poison shows extreme variance: nearly succeeds in Disruption, ineffective in Exfiltration

## 3. Trade-offs

| Dimension | Win | Loss |
|-----------|-----|------|
| **Robustness vs. Utility** | CAMEL achieves 0% Hijacking ASR (perfect), ACI-SENTINEL near-neutralizes Exfiltration (0.22% ASR on AutoGen) | CAMEL's low ASR stems from baseline incompetence (BU only 41%), not active defense; ACI-SENTINEL drops BU from 57.78 → 52.22 on AutoGen |
| **Defense Completeness vs. New Vulnerabilities** | Sandwich reduces MetaGPT Hijacking ASR from 79.44% → 10.00% | Sandwich _amplifies_ Exfiltration ASR (+6pp on AutoGen) because repeating task descriptions reinforces semantic coupling between benign task and hidden attack objective |
| **Attack Surface Coverage** | Adversarial Input consistently effective for precision attacks; Malicious Agent stable across models | Message Poison extremely unreliable — near-perfect for Disruption, useless for Exfiltration |
| **System Complexity vs. Security** | Critical oversight roles (critic in CAMEL, AgentVerse) improve robustness | Dense interaction around critical roles (AgentVerse) propagates malicious content; simpler topologies (MetaGPT) are most fragile (100% ASR) |
| **Model-Level Defense** | ACI-SENTINEL is simple (prompt-only, no training), generalizes across 3 MAS | Model-level defenses proven "inherently fragile" — adaptive attacks partially recover ASR; "safety tax" on complex tasks requiring rich context |
| **Computational Cost** | AGrail achieves good security on certain suites | AGrail's frequent security checks introduce "substantial computational overhead" and can collapse BU to near-zero (6.67 → 0.28 on MetaGPT) |

## 4. Design Rationale

The authors built ACIARENA to address three failures in existing ACI research: **(1) incomplete threat scenarios** (prior work studied single attack surfaces/objectives in isolation), **(2) non-standardized evaluation** (simplified MAS differ from real deployments, findings don't generalize), and **(3) inextensible codebases** (monolithic designs prevent adding new attacks/MAS). The shift from detection-based defense (Sandwich, BERT, Delimiter) to **semantic minimality** (ACI-SENTINEL) was motivated by the finding that agent-agent injections lack the distinctive patterns of human-agent injections — attackers exploit inter-agent trust rather than deceiving the LLM directly, making pattern-matching detectors ineffective. The Principle of Contextual Least Privilege discards everything not causally necessary for the task, which is philosophically akin to capability-based security in OS design applied to LLM context windows.

## 5. Limitations & Failure Modes

1. **Scale-restricted due to API cost**: Only GPT-4o, GPT-4o-mini, Qwen2.5-7B evaluated; no GPT-5, Gemini 3, or Claude models tested.
2. **No system-level defense design**: Only defenses bolted onto existing MAS evaluated — robustness-oriented system _architecture_ remains unexplored.
3. **Single malicious agent assumption**: Follows Byzantine Fault Tolerance model (≤1/3 tolerated); real attacks may compromise multiple agents simultaneously.
4. **ACI-SENTINEL is fragile**: Adaptive attacks reduce its effectiveness (ASR rebounds from 0% → 10-37%); semantic pruning may discard context needed for complex, multi-hop reasoning tasks.
5. **Static evaluation**: 3-turn maximum interaction limit, fixed temperature=0.0 — does not capture real-world dynamic, long-running agent conversations.
6. **Sandwich defense paradox**: Defenses targeting narrow threat models can amplify other attack types (Exfiltration ASR increases under Sandwich), highlighting the danger of incomplete security evaluation.
7. **Domain blind spots**: Code generation domain is far more vulnerable (90-100% ASR) than others, yet domain-specific risk factors are unexplored.
8. **No Claude/Anthropic models tested**: All experiments use OpenAI GPT and Qwen models — safety-tuned models like Claude may behave differently under ACI attacks.

## 6. Transfer to Lyra

**The one transferable idea**: Apply **Contextual Least Privilege (semantic pruning)** as a defense layer in Lyra's multi-agent orchestration. After each agent-to-agent message in §4.3 (Safety Guards) or §4.7 (Agent Communication Bus), add a lightweight pre-processor that prunes the downstream agent's context to only the information causally necessary for completing the assigned sub-task. This directly addresses Lyra's cascade failure risk where a compromised sub-agent (code-reviewer, executor, verifier) could propagate malicious instructions through inter-agent trust chains. The ACI-SENTINEL prompt template can be adapted as a Lyra system-level guardrail.

**Workstream route**: §4.3 (Safety Guards) — this is a defense mechanism against prompt injection cascades in multi-agent settings, directly aligned with the safety workstream's mandate to prevent unauthorized instruction propagation.

| Attribute | Value |
|-----------|-------|
| **Impact** | 4 (multi-agent security is a critical gap; 90-100% ASR on code tasks is alarming for Lyra's code-gen agents) |
| **Effort** | 2 (ACI-SENTINEL is a prompt-only defense — adapt the prompt template, add a pre-processing step in the agent communication layer; no model training required) |
| **Tier** | **Breakthrough** — First-ever systematic MAS robustness benchmark with 1,356 test cases; the finding that narrow defenses can _amplify_ other attack types is a security design principle every MAS architect must internalize |
