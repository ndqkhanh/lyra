## 1. Mechanism

FairQE is a 4-stage pipeline with 5 agents (4 LLM-based + 1 conventional QE model) that mitigates gender bias in MT quality estimation. Each stage feeds the next; the key innovation is the dynamic soft-gating aggregation at the output.

### Stage 1: Gender Cue Detection (Agent\_cue)

Agent\_cue receives a source–target sentence pair (s, t) and a taxonomy C of 12 fine-grained cue categories (C1–C6 explicit, C7–C12 ambiguous, summarized in Table 13). It outputs:

```
D = Agent_cue(s, t, C) = {(c_s^(i), c_t^(i)) | c_s^(i) ⊂ s, c_t^(i) ⊂ t}_{i=1}^k
```

If D = ∅, Stages 2 and 3 are skipped entirely for efficiency.

### Stage 2: Gender-Flipped Variant Generation (Agent\_amb, Agent\_exp)

Two specialized agents run in parallel based on cue type:

**Agent\_amb (ambiguous cues):** Source gender is unknown, so this generates ALL valid gender realizations not present in the original translation:
```
V_amb = ⋃_{(c_s,c_t) ∈ D_amb} Agent_amb(s, t, c_s, c_t)
```
Each variant is a tuple (s, t', g') where g' ∈ {F, M, N}.

**Agent\_exp (explicit cues):** Source gender is explicitly marked. The agent verifies target alignment and generates flipped variants:
```
(A_i, V_i) = Agent_exp(s, t, c_s, c_t)
A_exp = ⋀_i A_i,   V_exp = ⋃_i V_i
```

Both agents use WORD-LEVEL SUBSTITUTION ONLY — no paraphrasing, no restructuring.

### Stage 3: Dual-Stream Quality Estimation (Agent\_qe, Agent\_uqe)

Two parallel streams:

**Quantitative (Agent\_qe):** Conventional QE model (e.g., COMETKiwi-22) computes scores for the original pair and all gender variants:
```
q_orig = Agent_qe(s, t)
Q_var = {Agent_qe(s', t') | (s', t') ∈ V}
```

**LLM Reasoning (Agent\_uqe):** LLM-based MQM-style evaluator that performs explicit bias-mitigating reasoning. For ambiguous cues, it checks score consistency across gender realizations. For explicit cues, it verifies fidelity against gender constraints and penalizes violations with MQM error severities (Critical: -15, Major: -5, Minor: -1 from baseline 100):
```
q_uqe = Agent_uqe(s, t, D, V, A_exp)
```

### Stage 4: Dynamic Bias-Aware Aggregation

This is the core algorithmic contribution. Instead of static averaging, a soft-gating mechanism anchors on the QE model and increases LLM influence only when bias is detected:

**Bias quantification:**
- _Ambiguous bias_ (b_amb): max score range across gender variants — a biased model produces divergent scores:
  ```
  b_amb = |max(Q_var ∪ {q_orig}) - min(Q_var ∪ {q_orig})|
  ```
- _Explicit bias_ (b_exp): preference violation — whether a constraint-violating translation outscores a constraint-consistent one:
  ```
  if A_exp = True:  b_exp = max(0, max(Q_var) - q_orig)
  if A_exp = False: b_exp = max(0, q_orig - max(Q_var))
  ```

**Soft gating:**
```
B = α·b_amb + β·b_exp          (α = β = 5 in all experiments)
w = B / (1 + B),   0 ≤ w < 1
q_final = w · q_uqe + (1 - w) · q_orig
```

When B ≈ 0 (negligible bias), w → 0, preserving the QE backbone's segment-level precision. As B grows, w increases, shifting toward the LLM's debiased reasoning.

## 2. Results

All experiments use GPT-4.1-mini for LLM agents; α = β = 5; single NVIDIA A100 GPU.

### Gender Fairness (6 language pairs: ES, FR, IT, AR, DE, HI)

**Gender-Ambiguous (Fem. vs. Masc.) — Feminine-to-Masculine Score Ratio (ideal = 1.000):**

| Method | Avg across 6 LPs |
|---|---|
| COMETKiwi-22 | 0.9851 |
| COMETKiwi-23 XL | 0.9546 |
| MetricX-24 L | 0.9804 (ES, avg partial) |
| MetricX-24 XL | 0.9890 (est.) |
| GEMBA-MQM (GPT-4.1-mini) | 0.9713 |
| **FairQE (w/ CK22)** | **0.9936** (best/2nd-best on 6/6 LPs) |
| FairQE (w/ MX24L) | 0.9875 (est., best on 6/6 vs. backbone) |

**Gender-Ambiguous (Neutral vs. Gendered) — Neutral-to-Gendered Ratio (>1 = prefers neutral):**

| Method | DE | ES | IT |
|---|---|---|---|
| COMETKiwi-22 | 0.9737 | 0.9689 | 0.9694 |
| **FairQE (w/ MX24L)** | **0.9921** | **0.9948** | **0.9884** |

**Gender-Explicit (Binary Accuracy, %):**

| Method | AR | DE | HI |
|---|---|---|---|

FairQE improves CK22 by +18.7pp on EN–AR explicit accuracy.

### QE Performance (WMT 2023 MQM, EN–DE, 557 segments × 14 systems)

| Method | avg-corr ↑ | System Pearson ↑ | Segment acc-t ↑ |
|---|---|---|---|
| COMETKiwi-22 | 0.743 | 0.864 | 0.224 |
| MetricX-24 XL | 0.750 | 0.848 | 0.378 |
| GEMBA-MQM | **0.830** | 0.970 | **0.568** |
| **FairQE (w/ CK22)** | **0.812** | **0.985** | 0.424 |

FairQE improves CK22 avg-corr from 0.743 → 0.812 (+6.9 points), while achieving the best system-level Pearson (0.985).

### Ablation Key Findings
- Removing variant generation (FairQE-NoVar) still helps but loses 0.4-1.5% in ratio closeness
- Using only LLM score (FairQE-UQEOnly, no aggregation) is inconsistent — sometimes underperforms the backbone
- API cost: **0.0946 USD per 100 samples** (GPT-4.1-mini), 176 API calls per 100 samples (vs. 400 max possible)

### Comparison with Stronger LLMs
- FairQE (with GPT-4.1-mini) avg. abs. deviation from parity: **0.00638**
- Direct o3 evaluator avg. abs. deviation: **0.0263**
- Even GPT-4o shows greater bias than FairQE with gpt-4.1-mini

## 3. Trade-offs

| Win | Cost/Loss |
|---|---|
| Gender fairness consistently improved across 6 language pairs and 3 bias settings | Requires 4 LLM agent calls per sample (~176 calls/100 samples), adding latency |
| Model-agnostic: works with COMETKiwi-22, MetricX-24L, and COMETKiwi-23 XL as backbones | Slight avg-corr regression vs. GEMBA-MQM (0.812 vs. 0.830) — GEMBA is biased but slightly better on raw correlation |
| avg-corr improves over backbone (CK22: 0.743 → 0.812, +6.9 pts) | Variance slightly increases in some language pairs (mitigated by anchoring to QE backbone) |
| Word-level substitution preserves fluency; no paraphrasing distortion | Masculine plural as generic form (e.g., Spanish "aventureros") can evade cue detection in ambiguous cases |
| Plug-and-play: no retraining of QE backbones needed | Hyperparameters α, β may need tuning per QE backbone/dataset (though fixed α=β=5 worked across all experiments) |
| Works with cheap LLM (GPT-4.1-mini); outperforms direct use of stronger LLMs (o3, GPT-4o) on fairness | Deterministic decoding + fixed prompts required to reduce LLM variability |
| Early exit when D=∅ saves ~11% of compute (10.8% of instances have no cues) | Closed-source LLM dependency; open-source LLM evaluation not yet done |

## 4. Design Rationale

The authors chose a **multi-agent architecture over single-model debiasing** because:
1. **Decomposition enables specialization**: Cue detection, variant generation, bias reasoning, and scoring are orthogonal sub-tasks — each agent optimized with its own prompt and taxonomy.
2. **Soft-gating over hard-threshold**: Static averaging would either over-trust the LLM (losing segment-level precision) or under-use it. The dynamic scheme `w = B/(1+B)` provides smooth interpolation anchored to the proven QE backbone.
3. **Contrastive evaluation over direct scoring**: Rather than asking the LLM "is this biased?", the framework generates flipped variants and measures scoring volatility — an **empirical bias signal** rather than a self-reported one.
4. **Model-agnostic by design**: Wrapping existing QE models as `Agent_qe` means the framework inherits improvements in QE backbones without retraining. The 12-cue taxonomy provides structured coverage of gender bias sources rather than relying on LLM zero-shot gender awareness.
5. **MQM protocol for Agent_uqe** routes bias signals through an established, interpretable evaluation rubric rather than opaque score adjustments.

## 5. Limitations & Failure Modes

1. **Cue detection asymmetry**: The primary failure mode is when Agent_cue detects cues on one gender variant but misses them on the other. E.g., Spanish masculine plurals ("aventureros") used as generic forms evade detection while feminine counterparts ("aventureras") trigger cues, leading to asymmetric score adjustments that can _increase_ bias (Table 11 case study).
2. **Closed-source LLM dependency**: All experiments use GPT-4.1-mini via API; behavior with open-source LLMs is untested. Deterministic decoding (temperature=0) and fixed prompts are required to suppress variability.
3. **Hyperparameter sensitivity**: α and β control the bias-to-LLM-influence curve. While α=β=5 worked universally, the paper notes sensitivity to backbone/dataset combinations and shows overcorrection at high α values (Figure 3).
4. **Language coverage**: Only 6 target languages (ES, FR, IT, AR, DE, HI) tested; performance on low-resource languages or languages with different gender systems (e.g., noun-class languages) is unknown.
5. **Latency**: The pipeline adds 1-4 LLM API calls per sample, making it unsuitable for real-time QE at scale without batching.
6. **No enforcement mechanism**: The framework only adjusts scores; it does not prevent downstream systems from ignoring the calibrated scores.

## 6. Transfer to Lyra

### The One Transferable Idea

**Dynamic bias-aware soft-gating aggregation** — the pattern of anchoring to a fast/cheap base model (the QE backbone), quantifying a specific bias dimension via empirical score volatility across structured perturbations (gender-flipped variants), and using a smooth function `w = B/(1+B)` to interpolate between the base model and a reasoning-heavy debiasing model only when bias is detected. This is a general recipe for **cost-aware bias calibration in multi-model evaluation pipelines**.

### Workstream Route: §4.5 (Evaluation & Safety)

The bias-detection-via-perturbation pattern directly feeds Lyra's evaluation and safety workstream. For Lyra, the analogous pattern would be: (a) detect potentially biased/sensitive output regions via a lightweight classifier, (b) generate structured counterfactual perturbations of those regions, (c) measure output volatility across perturbations as an empirical bias signal, (d) use soft-gating to invoke a more expensive fairness-calibrated evaluator only when the bias signal exceeds a threshold.
