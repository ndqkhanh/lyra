**Authors**: Akari Asai, Zeqiu Wu, Yizhong Wang, Avirup Sil, Hannaneh Hajishirzi (University of Washington, Allen Institute for AI, IBM Research AI)
**Venue**: arXiv preprint (2310.11511v1), October 17, 2023

## 1. Mechanism (step-by-step)

SELF-RAG trains a single LM to adaptively decide *when* to retrieve, *how* to use retrieved passages, and *how well* its own output is supported — all unified under next-token prediction with special **reflection tokens**.

### 1.1 Reflection Token Vocabulary

Four new token types are added to the LM's vocabulary:

| Token Type | Input | Output | Purpose |
|---|---|---|---|
| **Retrieve** | x, y_<t | {Yes, No, Continue} | Decide if retrieval would help this segment |
| **ISREL** | x, d | {Relevant, Irrelevant} | Is passage d useful for input x? |
| **ISSUP** | x, d, y | {Fully Supported, Partially Supported, No Support} | Is output y supported by passage d? |
| **ISUSE** | x, y | {1, 2, 3, 4, 5} | Overall response usefulness (5-point Likert) |

### 1.2 Two-Phase Training

**Phase 1 — Critic Model Training:**
1. Sample input-output pairs (x, y) from instruction-following datasets
2. Prompt GPT-4 with type-specific instructions + few-shot demos to generate reflection token labels r for each (x, y)
3. Collect 4k–20k supervised examples per reflection type (~12.6k Retrieve, ~19.3k ISREL, ~11.2k ISSUP, ~3.8k ISUSE)
4. Train critic C (initialized from Llama2-7B) with standard LM objective:
   ```
   max_C E_((x,y),r)∼D_critic log p_C(r | x, y)
   ```
5. Results: C achieves >90% agreement with GPT-4 on Retrieve/ISSUP, 80.2% on ISREL, 73.5% on ISUSE

**Phase 2 — Generator Model Training:**
1. For each (x, y) in training data (150k instruction-output pairs from Open-Instruct + KILT + ASQA):
   - Run C to predict Retrieve token
   - If Retrieve=Yes: use retriever R (Contriever-MS MARCO) to get top-K passages, then C predicts ISREL, ISSUP, ISUSE for each
   - If Retrieve=No: C predicts only ISUSE
2. Insert reflection tokens and retrieved passages into output sequence
3. Train generator M (Llama2-7B or 13B) on augmented corpus with next-token objective:
   ```
   max_M E_(x,y,r)∼D_gen log p_M(y, r | x)
   ```
   Note: Retrieved passage text is **masked** from loss computation — only output tokens and reflection tokens contribute to loss.

### 1.3 Inference Algorithm

```
Algorithm: SELF-RAG Inference
Given: input x, preceding generation y_<t
1. M predicts Retrieve token given (x, y_<t)
2. IF soft-constraint triggered: p(Retrieve=Yes) / [p(Yes)+p(No)] > δ (default δ=0.2)
   a. Retrieve top-K passages D using R given (x, y_{t-1})
   b. FOR each d ∈ D (in parallel):
      i.   M predicts ISREL given (x, d)
      ii.  M predicts y_t given (x, d, y_<t)
      iii. M predicts ISSUP given (x, y_t, d)
   c. Rank all K continuations with segment score:
      f(y_t, d) = p(y_t | x, d, y_<t) + Σ_G w_G·s_G
      where s_G = p(r_hat) / Σ_i p(r_i) for each critique type G
      Default weights: w_ISREL=1.0, w_ISSUP=1.0, w_ISUSE=0.5
   d. Segment-level beam search (B=2) returns top continuations
3. ELSE (no retrieval):
   a. M predicts y_t given (x, y_<t)
   b. M predicts ISUSE given (x, y_t)
4. At final segment T: ISUSE evaluated for full output
```

**ISSUP score calculation:**
```
s(ISSUP) = [p(Fully) + 0.5·p(Partially)] / [p(Fully) + p(Partially) + p(No)]
```

**ISUSE weighted score** (5-point scale, weights w = {-1, -0.5, 0, 0.5, 1}):
```
s(ISUSE) = Σ_i w_i · p(ISUSE=i) / Σ_i p(ISUSE=i)
```

### 1.4 Inference-Time Customization

Segment weights w_G can be adjusted **at test time without retraining**:
- Higher w_ISSUP → higher citation precision, lower fluency (MAUVE)
- Higher retrieval threshold δ → fewer retrievals, lower latency

## 3. Trade-offs (wins vs. loses)

| Dimension | Win | Cost/Loss |
|---|---|---|
| **Accuracy vs. versatility** | Retrieves only when needed (adaptive); preserves creative generation for non-factual tasks | Potential under-retrieval when threshold δ too high; PopQA drops from 54.9→24.7 with retrieval disabled |
| **Factuality vs. fluency** | Higher w_ISSUP boosts citation precision on ASQA | Higher w_ISSUP reduces MAUVE (fluency) — longer, more fluent outputs contain more unsupported claims |
| **Inference compute** | Beam search enables quality-ranked candidates; parallel passage processing | Inference multiplies compute by B×K per segment (B=2, K=5–10); vLLM used to compensate |
| **Training simplicity** | Standard LM objective (no RL/PPO); offline critique insertion avoids hosting reward models during training | Depends on GPT-4 API for initial critic data (~47k GPT-4 calls); reproducibility tied to GPT-4 version |
| **Model size efficiency** | 7B beats much larger models (ChatGPT, Llama2-65B w/ CoVE) on several tasks | 13B sometimes worse than 7B on FactScore (80.2 vs 81.2) — larger model generates longer/more claims, harder to fully support |
| **Customizability** | Weights adjustable at inference without retraining | Practitioner must tune 3 weight hyperparameters + retrieval threshold; no automated tuning |
| **Knowledge recency** | Can incorporate fresh passages at inference | Wikipedia 2018/2020 embeddings miss entities created after those dumps; PopQA especially affected |

## 4. Design Rationale

**Why not standard RAG?** Standard RAG retrieves a fixed number of passages for every input regardless of whether retrieval helps. This hurts versatility (creative tasks don't need facts) and introduces noise (irrelevant passages reduce quality). SELF-RAG makes retrieval *conditional and on-demand*.

**Why not RLHF/PPO?** RLHF requires hosting separate reward models during training and uses expensive PPO optimization. SELF-RAG pre-computes critique offline via a distilled critic model, then trains with standard cross-entropy — dramatically simpler and cheaper.

**Why special tokens instead of natural language self-critique?** Special tokens (vs. prompted feedback) enable (a) exact probability computation for scoring, (b) hard constraints during decoding (e.g., reject segments with ISSUP=No Support), (c) controllable beam search with weighted scores, and (d) no additional decoding overhead for generating verbose feedback.

**Why GPT-4 distillation?** Manual annotation of fine-grained reflection tokens is prohibitively expensive. GPT-4 shows high agreement with human annotators (80–95% across types) and can be distilled into a smaller, reproducible critic model.

**Why segment-level processing?** Processing one sentence at a time (rather than full output) enables fine-grained retrieval decisions — different segments may need different evidence sources — and fine-grained self-critique per claim.

## 5. Limitations & Failure Modes

1. **GPT-4 dependency for training data**: Initial reflection token labels come from GPT-4 API calls (~47k). This introduces cost, latency, and reproducibility concerns (GPT-4 behavior changes over time). The entire pipeline breaks if GPT-4 API is unavailable.

2. **Critic model accuracy ceiling**: The distilled critic C achieves only 73.5% on ISUSE (usefulness scoring), 80.2% on ISREL — meaning ~20–27% of training labels may be noisy.

3. **Wikipedia-only retrieval**: Contriever uses 2018/2020 Wikipedia dumps. For PopQA (2022 WikiData entities), many answers are missing from the retrieval corpus. Authors note this limitation explicitly.

4. **No non-English or code evaluation**: All 6 benchmarks are English NLP tasks. No evaluation on multilingual QA, code generation, or other domains.

5. **Training data not saturated**: Performance continues improving with more data at 150k examples. Full potential unknown.

6. **Segment granularity limitation**: One-sentence segments may be too fine for some tasks (loses paragraph-level coherence) or too coarse for others (multiple claims per sentence cannot be independently verified).

7. **Factuality still imperfect**: Even with self-reflection, SELF-RAG generates outputs not fully supported by citations. The system can flag contradictions with ISSUP tokens but still outputs them if they score highest in beam search.

8. **Computational cost at inference**: B×K candidates per segment (default 2×5=10 forward passes per segment). For long-form generation with T segments, this scales as O(T·B·K). vLLM partially mitigates but does not eliminate the overhead.

9. **Fixed retriever**: The retriever (Contriever) is frozen during training. Joint training of retriever and generator could improve retrieval quality for instruction-following tasks.

## 6. Transfer to Lyra

### The One Transferable Idea

**On-demand retrieval gating with self-critique tokens for Lyra's context/memory subsystem.**

Lyra currently retrieves context/memory entries for every agent turn regardless of whether external context would actually help. SELF-RAG's core insight — training the model to decide *when* to retrieve (Retrieve token), evaluate *whether* retrieved information is relevant (ISREL), and verify *whether* its output is supported (ISSUP) — can be adapted to Lyra's agent loop. Instead of always injecting memory/context, Lyra could learn to emit a "need_memory" token and self-critique its own responses against retrieved memories.

### Workstream Route
**§4.2 — Memory/Context Management** (on-demand retrieval + self-verification of memory-supported claims)

### Impact/Effort/Tier Assessment
- **Impact**: 4/5 — Directly addresses Lyra's key weakness (indiscriminate context injection leading to noise and context window waste)
- **Effort**: 4/5 — Requires (a) designing reflection token taxonomy for agent actions, (b) distilling critique data from a strong judge model, (c) two-phase training pipeline, (d) custom inference with beam search scoring
- **Tier**: **investigate** — High potential but needs adaptation from QA domain to agent orchestration; start with a lightweight prototype using a single "should_retrieve" token before committing to full reflection token suite
