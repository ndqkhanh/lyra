## 1. Mechanism (step-by-step)

### Problem Formulation
Given N agents and a task query q, design a communication topology as a directed graph G = (V, E) with adjacency matrix A ∈ {0, 1}^(N×N). The objective is to maximize a composite reward:

```
max_A R(A, C) = f(Utility(A, C), Cost(A, C), Sparsity(A), Robustness(A))
```

where C is a task-condition vector encoding the query and available agents. Evaluating R requires running a full multi-agent simulation — too expensive for iterative optimization.

### Stage 1: Dataset Generation
Run multi-agent simulations with diverse baseline topologies (chain, star, complete, layered, random) across multiple tasks to produce dataset D_gen = {(A_j, C_j, P_j)} where P_j = [utility, cost] are ground-truth performance vectors.

### Stage 2: Train Surrogate Reward Model (P_φ)
A Graph Neural Network with Graph Attention (GAT) layers predicts performance of any topology without running simulation:

- **Architecture:** 2 GAT layers (hidden dim=32) → mean pool → concatenate with projected condition C → MLP → [û, ĉ]
- **Node update rule (GAT layer):** h_v^(l+1) = σ(Σ_{u∈N(v)∪{v}} α_vu^(l) · W^(l) · h_u^(l))
- **Training objective:** L_φ = (1/M) Σ ∥P_φ(A_j, C_j) − P_j∥²₂ (MSE loss)
- **Training:** 10 epochs, Adam (lr=1e-3), batch size 16
- **Fidelity:** MSE utility=0.0089, cost=0.0124; Pearson r=0.91/0.94; Top-1 ranking acc=78.4%/85.2%

### Stage 3: Train Conditional Graph Diffusion Generator (G_θ)
A denoising diffusion model that learns the distribution of high-quality topologies:

- **Forward process (noising):** Scale adjacency entries from {0,1} to {−1,1}, then apply variance-preserving Gaussian noise schedule over T=50 timesteps:
  ```
  q(A_t | A_0) = N(A_t; √ᾱ_t · A_0, (1−ᾱ_t)I)
  ```
  where ᾱ_t = Π_{s=1}^t (1−β_s) and β_t follows a predefined schedule.

- **Reverse process (denoising):** A 2-layer Graph Transformer with 2 attention heads predicts the clean graph A_0 from noisy A_t, conditioned on task C and timestep t. Trained on high-performance subset D_hq ⊂ D_gen only.

- **Training objective:** Binary cross-entropy between predicted and true A_0:
  ```
  L_θ = E_{t,A_0,C,ε} [ BCE( G_θ(√ᾱ_t·A_0 + √(1−ᾱ_t)·ε, C, t), A_0 ) ]
  ```
- Training: Adam (lr=1e-4), 50 diffusion timesteps.

**Why diffusion over VAE/GAN:** In discrete topology space, a single wrong edge can break communication flow. Diffusion allows the proxy to intervene at every construction step, gently steering toward high-reward regions gradually — avoiding mode collapse typical of one-shot generators. The Graph Transformer's global self-attention ensures edges are not predicted independently; the prediction of edge (i,j) is conditioned on all other nodes.

### Stage 4: Proxy-Guided Topology Synthesis (Inference) — Algorithm 1
For a new task condition C_new, generate optimized topology through guided denoising:

```
Algorithm 1: Guided Topology Diffusion (GTD) Generation
1. Sample A_T ~ N(0, I)
2. for t = T, ..., 1:
3.     Predict unguided clean graph: Â_0^(t) = G_θ*(A_t, C_new, t)
4.     Generate K=5 discrete candidates: A_{0,k}^(t) ~ Bernoulli(σ(Â_0^(t)))
5.     Evaluate candidates with proxy: [û_k, ĉ_k] = P_φ*(A_{0,k}^(t), C_new)
6.     Zeroth-order selection: A_{0,best}^(t) = argmax (w_u·û_k − w_c·ĉ_k)
7.     Compute posterior q(A_{t-1} | A_t, A_{0,best}^(t)) using forward process formulas
8.     Sample A_{t-1} ~ N(μ_post, Σ_post)
9. Output final discrete graph A_0
```

**Key insight (Zeroth-Order Optimization):** The proxy reward P_φ evaluates *discrete* graph samples, making its output non-differentiable w.r.t. the generator's continuous predictions. Standard classifier guidance is impossible. The ZO step approximates a gradient-ascent step on the proxy reward landscape: Δ_t = A_{0,best}^(t) − Â_0^(t) serves as a stochastic ascent direction estimate, with K>1 samples reducing variance.

**Theoretical grounding (Theorem G.2):** If the surrogate model has maximum error ε_max, the performance gap between the true optimal topology A* and the proxy-optimal topology A*_proxy is bounded: R(A*, C) − R(A*_proxy, C) ≤ 2ε_max. A perfect surrogate (ε_max=0) would recover the true optimum.

### Training Data Efficiency
Only 50 training samples from the training set are needed. One-time setup cost ≈ 4.0×10^5 tokens, amortized against millions saved during inference (≈ 4.4×10^6 tokens per full test-set run).

## 3. Trade-offs (wins vs loses)

| Wins | Loses |
|------|-------|
| **SOTA accuracy** across 6/6 benchmarks (+3.99 avg over vanilla, outperforms 16 baselines) | **Requires seed data** — must pre-compute baseline topologies to train proxy and generator |
| **Dramatic token savings** — generates sparse topologies, 15% to >5× fewer tokens than dense baselines | **Static topology** — graph is fixed at task start; no mid-execution adaptation if requirements shift |
| **Strong robustness** — only −0.3% accuracy under single-agent failure (vs −1.8% to −13% for others) | **Diminishing returns beyond 4 agents** for current benchmarks |
| **Competitive inference speed** (7.9s) despite 50-step diffusion + ZO, due to sparser agent execution | **Inference overhead** from diffusion sampling (3.2s with no ZO vs 7.9s with K=5) |
| **Data-efficient** — only 50 training samples needed; setup cost rapidly amortized | **Surrogate degradation on OOD topologies** — Top-1 ranking drops from 78.4% (ID) to 72.8% (OOD) |
| **Model-agnostic** — works with GPT-4o-mini, Qwen-3-8B, and extends to harder benchmarks | **Only tested on reasoning/code tasks** — unknown generalization to open-ended dialogue, tool-use chains |
| **Hardware-efficient** — 2.8GB for 5 agents, linear scaling, runs on consumer GPUs | **Two-phase training** (proxy + generator) adds engineering complexity |

## 4. Design Rationale (why this approach)

1. **Diffusion over one-shot generators (VAEs/Gumbel-Softmax):** Communication topologies are discrete and highly structured — a single wrong edge breaks flow. Diffusion's iterative denoising allows the proxy model to intervene at *every* timestep, gently steering generation. VAE-based approaches apply reward only post-generation, losing fine-grained control.

2. **Graph Transformer over GCN/GAT for the generator:** Topology optimization requires capturing long-range dependencies (e.g., cycles, hierarchies). Graph Transformers use global self-attention so edge (i,j) predictions are conditioned on all other nodes — GCN/GAT are locality-bound.

3. **Zeroth-order optimization over gradient-based guidance:** The proxy reward evaluates *discrete* graph samples (non-differentiable). Standard classifier guidance needs ∇_A P(A, C), which does not exist through the Bernoulli sampling step. ZO approximates a gradient-ascent direction using only function evaluations.

4. **Proxy model over direct simulation in the loop:** Running a full multi-agent simulation per candidate per timestep would require K×T = 5×50 = 250 full simulations — infeasible. A lightweight GNN proxy (2-layer GAT, 32-dim) evaluates candidates in milliseconds.

5. **Variance-preserving schedule with {−1,1} scaling:** Centering adjacency values around zero (instead of {0,1}) ensures proper convergence to N(0,I) under Gaussian noise — a standard diffusion practice that prevents distributional drift.

## 5. Limitations & Failure Modes

1. **Seed data dependency:** The surrogate model requires a pre-computed dataset of baseline topologies. While data-efficient (~50 samples), this still imposes a one-time setup cost (~4×10^5 tokens). No cold-start capability for entirely novel agent types without any simulation history.

2. **Static topology only:** Once generated, the communication graph is fixed for the entire task. Cannot adapt mid-execution if the task evolves, new subtasks emerge, or early agent outputs suggest a different collaboration pattern would be better. No time-varying topology evolution.

3. **Agent count saturation:** Ablation shows accuracy plateaus after 4 agents on current benchmarks (GSM8K, MATH, etc.). The tasks themselves may not benefit from larger swarms — not a framework limitation but a benchmark limitation. Framework technically scales to 1000 agents at 4.9GB.

4. **Surrogate model OOD degradation:** Top-1 ranking accuracy drops from 78.4% (in-distribution) to 72.8% (on GTD-generated OOD topologies). This means the proxy may occasionally misrank candidates, steering toward suboptimal graphs. The ZO selection of K=5 mitigates this (Top-2 accuracy remains 89.3%), but larger candidate pools K>5 yield marginal gains.

5. **Limited to reasoning/code benchmarks:** All experiments are on GSM8K, MATH, MultiArith, SVAMP, HumanEval, MMLU, and LiveCodeBench. No evaluation on open-ended dialogue, multi-turn tool-use, retrieval-augmented generation, or long-horizon planning tasks.

6. **Backbone model specificity:** Only tested with GPT-4o-mini and Qwen-3-8B. Unknown how topology benefits scale or change with stronger models (Claude, GPT-4.5/5, Gemini), especially since stronger models may need less structured communication.

7. **Non-differentiable reward landscape:** The ZO approach is a greedy per-step optimization, not global. The surrogate model may have local optima that trap the generation process, and Theorem G.2's bound grows linearly with surrogate error (2ε_max).

## 6. Transfer to Lyra

### The One Transferable Idea

**Proxy-guided zeroth-order optimization during iterative generation** — the technique of using a lightweight surrogate reward model (GNN) to evaluate discrete candidate configurations and select the best at each step of an iterative generative process. This pattern decouples the expensive evaluation (full agent simulation) from the generation loop, enabling real-time multi-objective optimization without differentiability requirements.

### Application to Lyra

Lyra's router/orchestrator could use this pattern to dynamically construct **agent execution DAGs** (not just communication topologies). Instead of fixed workflow templates, Lyra could:
1. Train a lightweight proxy to predict (latency, accuracy, token_cost) for any candidate execution graph
2. At inference, use diffusion or iterative refinement to construct a task-specific execution plan
3. Apply ZO guidance at each construction step using the proxy to balance the multi-objective trade-off

This directly enables Lyra to move from hand-crafted routing heuristics to **learned, task-adaptive orchestration** that trades off speed, quality, and cost on a per-query basis.
