# Adaptive Memory Admission Control for LLM Agents (A-MAC)

**Authors:** Guilin Zhang, Wei Jiang, Xiejiashan Wang, Aisha Behr, Kai Zhao, Jeffrey Friedman, Xu Chu, Amine Anoun (Workday AI)
**Venue:** ICLR 2026 Workshop on Memory-Efficient Agents (MemAgent)
**arXiv:** 2603.04549v1 [cs.AI], 4 Mar 2026
**Code:** https://github.com/GuilinDev/Adaptive_Memory_Admission_Control_LLM_Agents

## 1. Mechanism

A-MAC frames memory admission as a structured scalar decision problem rather than an implicit byproduct of LLM generation. Given a multi-turn conversation history H and an existing memory store M, the system extracts candidate memories {m₁, m₂, ..., mₙ} and decides whether to admit, update, or reject each one.

**Pipeline stages:**

1. **Candidate Extraction & Normalization:** Segment turns into atomic information units, resolve temporal expressions and coreferences, filter low-value content (greetings, acknowledgments). This produces self-contained memory candidates.

2. **Five-Factor Scoring (Equation 1):**
   ```
   S(m) = w₁·U(m) + w₂·C(m) + w₃·N(m) + w₄·R(m) + w₅·T(m)
   ```
   where all features map to [0,1], wᵢ ≥ 0, Σwᵢ = 1. Candidate admitted if S(m) ≥ θ.

3. **Feature Computation (parallel, Algorithm 1):**
   - **Utility U(m):** Single LLM call (Qwen 2.5, temperature=0) rating actionable relevance, likely follow-up questions, persistent preferences. Cached for repeats.
   - **Confidence C(m):** ROUGE-L between candidate and supporting spans in prior turns: `C(m) = max_{s∈Support(m)} ROUGE-L(m, s)`. Rewards grounded overlap; penalizes fabricated details with no textual support.
   - **Novelty N(m):** `N(m) = 1 − max_{m′∈M} cos(ϕ(m), ϕ(m′))` using Sentence-BERT embeddings. Precomputed embeddings for existing memories, one new embedding per candidate.
   - **Recency R(m):** Exponential decay `R(m) = exp(−λ·τ(m))` with λ=0.01/hour (half-life ≈ 69 hours).
   - **Type Prior T(m):** Rule-based pattern matching with POS cues. Higher priors for stable info (preferences, identity statements); lower priors for transient states.

4. **Policy Learning:** Grid search over weight configurations (wᵢ ≥ 0, Σwᵢ = 1) and threshold θ ∈ [0.3, 0.6] via 5-fold cross-validation, maximizing mean validation F1.

5. **Admission Decision (Algorithm 1):** If S(m) ≥ θ, check for conflicts (cosine similarity > 0.85 but differing content). If conflict exists and S(m) > S(m_conflict), merge into higher-scoring representation. Otherwise, admit as new memory.

**Latency budget (per candidate):** Utility (LLM) = 2580ms (97.6%), Confidence (ROUGE-L) = 18ms, Novelty (SBERT) = 32ms, Recency = <1ms, Type Prior = 14ms. Total = 2644ms.

## 2. Results

**Benchmark:** LoCoMo (Maharana et al., 2024) — 30 conversations across personal assistant, technical support, and research collaboration. 15–40 turns each, ~1500 labeled candidate memories. 70/15/15 train/val/test split.

**Main results (Table 1, N=225 test set):**

| Method | Precision | Recall | F1 | Latency (ms) |
|---|---|---|---|---|
| Random | 0.278 | 0.278 | 0.278 | <1 |
| MemGPT | 0.316 | 0.333 | 0.324 | 2765† |
| MemoryBank | 0.368 | 0.583 | 0.452 | 2843† |
| Equal Weights | 0.362 | 0.694 | 0.476 | 2916† |
| A-mem (SOTA) | 0.371 | 1.000 | 0.541 | 3831† |
| **A-MAC** | **0.417** | 0.972 | **0.583** | 2644† |

- A-MAC F1 = 0.583, +7.8% relative over A-mem (0.583 vs 0.541)
- 31% latency reduction vs A-mem (2644ms vs 3831ms)
- Highest precision among all LLM-based methods (0.417), near-perfect recall (0.972)

**Ablation (Table 2):** Type Prior dominates — removing it causes ΔF1 = −0.107 (0.583→0.476). Other features: Novelty ΔF1 = −0.028, Utility −0.023, Confidence −0.015, Recency −0.013.

**Threshold sensitivity (Table 3):** Optimal θ* = 0.55 (validation F1 = 0.571). F1 plateau between θ=0.50–0.60 suggests robustness to hyperparameter selection.

**Cross-domain (Table 5):** Personal F1=0.482, Professional F1=0.338, σ=0.102. Same learned weights transfer without retuning.

## 3. Trade-offs

| Win | Lose |
|---|---|
| +7.8% F1 over SOTA A-mem (0.583 vs 0.541) | LLM call for Utility still dominates latency (97.6% of budget) |
| 31% lower latency than A-mem (2644ms vs 3831ms) | Personal domain F1 43% higher than Professional — domain gap significant |
| Highest precision of any LLM method (0.417) | Still ~2.6s per candidate — not real-time; requires batching for throughput |
| Linear scoring model is fully interpretable (inspect per-feature contributions) | ROUGE-L confidence is surface-level; deeper factuality checks (e.g., NLI) not used |
| Learned weights transfer across domains without retuning | Fixed decay rate λ=0.01/hr is not domain-adaptive; may need tuning per use case |
| Rule-based features (C,N,R,T) execute in <65ms combined | Sentence-BERT embeddings memory cost grows linearly with memory store size |
| Explicit hallucination guard (Confidence feature) | Only 5 features; may miss domain-specific admission signals |

## 4. Design Rationale

The authors argue that existing memory systems suffer from two extremes: heuristic methods (MemGPT, MemoryBank) lack principled hallucination guards and cannot adapt weights across domains; LLM-native methods (A-mem, Mem0) achieve high recall but are opaque, expensive (multiple sequential LLM calls), and hard to audit. A-MAC's hybrid design is the critical insight: reserve expensive LLM inference for one genuinely semantic task (Utility), compute the other four signals via deterministic efficient rules, and learn weightings from data. The linear scoring model was chosen deliberately — not for model capacity, but for interpretability: developers can inspect individual feature scores and weight contributions to understand why specific memories were admitted or rejected, supporting debugging, auditing, and targeted policy improvement.

## 5. Limitations & Failure Modes

1. **Domain gap:** Professional conversations score 43% lower F1 than Personal (0.338 vs 0.482). Type Prior rules (POS-based pattern matching) overfit to explicit preference statements common in personal dialogue but miss implicit professional context.
2. **LLM bottleneck:** Utility LLM call accounts for 97.6% of latency. In resource-constrained or real-time deployments, this is still too slow (~2.6s per candidate).
3. **Surface-level confidence:** ROUGE-L measures n-gram overlap, not semantic factuality. A hallucinated statement paraphrasing prior conversation could score high on Confidence while being factually wrong.
4. **Static decay rate:** Fixed λ=0.01/hr may not generalize — different applications need different forgetting curves (e.g., medical records vs. casual chat).
5. **Embedding cost scaling:** Novelty requires O(|M|) cosine comparisons against all existing memories; Sentence-BERT embeddings grow linearly with memory store size.
6. **Binary admission:** The threshold-based admit/reject decision loses nuanced gradations. Partially useful memories may be discarded entirely.
7. **Single-metric optimization:** Grid search optimizes F1 only; doesn't consider latency budgets, storage constraints, or retrieval quality downstream.
8. **No evaluation on truly adversarial hallucinations:** Tested only on LoCoMo conversational data, not on deliberately injected false claims.
9. **Qwen 2.5 dependency:** Results depend on a specific local LLM for utility scoring; not evaluated with other LLMs (GPT-4, Claude, etc.).

## 6. Transfer to Lyra

**The ONE transferable idea:** Replace Lyra's current implicit/binary memory retention logic with an explicit, interpretable **multi-factor memory admission scorer** that combines (a) a single LLM call for semantic utility assessment with (b) cheap deterministic signals for confidence/novelty/recency/type-prior — producing a learned linear gate score S(m) ≥ θ. This directly addresses Lyra's memory bloat and hallucination-propagation risks in its conversation persistence layer.

**Workstream route:** §4.6 (Memory & Persistence) — specifically the memory admission/retention control sub-component within the agent memory architecture.

**Impact/Effort/Tier:** Impact=4, Effort=3, Tier=**investigate**

The idea is high-impact because Lyra's current memory architecture (documented in memory plans) admits conversation content without explicit reliability checks, risking hallucination propagation. The mechanism is well-defined (5-factor linear scorer) and the paper provides weights, thresholds, and open-source code. However, it needs adaptation: Lyra's memory patterns differ from LoCoMo's conversational format, and the Type Prior rules would need domain-specific retuning for Lyra's agent-tool interaction traces. Effort is moderate (3) because the core architecture is simple (linear scorer + grid search) and the paper provides reference implementations.
