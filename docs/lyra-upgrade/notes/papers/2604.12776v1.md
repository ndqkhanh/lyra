## 1. Mechanism (Step-by-Step)

EVOS PARK is a multi-agent framework for generating coherent long-horizon narratives driven by endogenous character emergence — characters that arise spontaneously from the simulation rather than being scripted. It has three core innovations layered on a multi-agent collaboration substrate.

### 1.1 Narrative Control Spectrum (Narrative Spectrum Configuration)

At initialization (T0), the system is configured into one of three paradigms:
- **HDP (Hierarchical Detailed Planning)**: Rigorous event tree; Director enforces hierarchical constraints for high plot fidelity.
- **SNP (Sequential Narrative Planning)**: Linear Key Nodes; agents are motivation-driven with improvisational freedom between milestones.
- **Free EN (Free Emergent Narrative)**: Only foundational settings; narrative driven entirely by endogenous agent decisions and emergent conflicts.

### 1.2 Multi-Agent Collaboration Architecture

Four specialized agent types:
- **Genesis Agent**: Synthesizes Storyworld Outlook, lore entries, character dynamics from user premise. Initiates the GMS Plan-Correct protocol for offline Role-Location-Plot alignment.
- **Architect Agent**: Operational core of the NOE. Executes World Map & Locations Modularization. Synergizes with Director for the ECGP — executes Ontological Promotion of sparking entities.
- **Director Agent**: Bridges static plans and dynamic execution. Orchestrates continuous feedback with Role Agents, performs Dynamic Spatial Alignment (GMS), and validates sparking alignment.
- **Role Agents**: Execute the Episodic Simulation Scheme. Driven by their RSB as living cognition. Form the endogenous social graph through decentralized interactions.

### 1.3 Emergent Character Grounding Protocol (ECGP)

The ECGP transforms stochastic LLM "hallucinations" into legitimate narrative assets via a 4-stage pipeline:

1. **Sparking via Constraint Violation**: When the LLM hallucinates an uninitialized name despite strict constraints limiting selection to existing characters, ECGP identifies this constraint violation as a *sparking* — a signal of latent narrative necessity, not an error.

2. **Entity Resolution**: The Director Agent intercepts the Spark to perform rigorous verification. Filters genuine new entities from aliases (nicknames, variants of existing IDs). Only structurally novel yet contextually coherent sparking passes.

3. **Ontological Promotion**: Formalizes the transition of a sparking from stochastic byproduct to simulation entity. Driven by *plot-criticality* — the entity's role in advancing the narrative. Elevates hierarchical status of the entity.

4. **Integration & Grounding**: The Architect Agent instantiates a new profile for the promoted character within the Storyworld Outlook and initializes their cognitive state in the RSB. The entity becomes a permanent, consistent component of the world state.

**Equation (conceptual)**: For an existing character set C, when LLM generates a reference to entity e ∉ C, the sparking function S(e) = f_valid(e, narrative_context) → {0,1}. If S(e)=1, ontological promotion P(e) elevates e into C′ = C ∪ {e_with_profile}.

### 1.4 Stratified Narrative Memory (SNM)

A 4-layer hierarchical memory architecture that prevents "social memory stacking" (accumulation of conflicting relational states):

- **Episodic Evolution Buffer (EEB)**: Short-term cache of real-time interactions (event Ei). Staging area before long-term metabolization.

- **Shared World Knowledge Base (SWKB)**: Immutable global truths (lore, worldview). Provides consistent ground truth for all agents.

- **Role Episodic Base (REB)**: Immutable experience log for provenance tracking. Decoupled from immediate decision-making to prevent context pollution.

- **Role Socio-Evolutionary Base (RSB)**: The core mutable storage. Contains agent's current snapshot: personality vectors, social graph edges, goals, current state. Evolves continuously via *in-place updates* — old states are overwritten, not appended.

### 1.5 Reflect-Synthesize-Consolidation Cycle (Event-Driven)

Triggered at the conclusion of each narrative event:

1. **Reflection Trigger**: Raw interactions accumulate in EEB. If interaction intensity exceeds a threshold, the system retrieves relevant context from RSB; otherwise proceeds directly to next event.

2. **Synthesize**: Cognitive workspace computes the evolutionary delta. Contrasts EEB data against established RSB states. Explicitly resolves topological shifts by severing outdated relations (crossed-out edges) and synchronously updating social connections and character profiles.

3. **Consolidation**: Synthesized state committed to RSB via in-place update. Old personality vectors and social edges are overwritten. RSB remains a conflict-free snapshot of current agent reality.

### 1.6 Generative Mise-en-Scène (GMS)

A "Virtual Stage Manager" that enforces Role-Location-Plot (RLP) alignment to prevent narrative-spatial dissonance — where characters appear in logically impossible locations.

**Dual-Phase Process**:
- **Offline Planning Alignment**: Genesis Agent establishes foundational logic by aligning constraints across Role, Location, and Plot dimensions. Ensures initial assignments are logically congruent.
- **Dynamic Spatial Alignment**: Director Agent leverages spatial blocking to synchronize narrative intentions with real-time contexts. Incorporates entity resolution to rectify LLM-induced identity hallucinations (malformed role codes). Uses a Plan-Correct protocol between Genesis and Director for iterative correction.

## 2. Results (Real Benchmark Numbers)

### 2.1 Experimental Setup
- **Scenarios**: 6 genres (Mystery, Classical Drama, Sci-Fi, Modern Drama, Epic Fantasy, Eastern Fantasy)
- **Long-horizon setting**: 15 significant events (~45 scenes), 200k–250k words per run
- **Baselines**: Open-Theatre (script-driven), BookWorld (virtual world simulation), HoLLMwood (writer-editor workflow)
- **LLM Backbones tested**: Gemini-2.5-Pro, DeepSeek-V3.2-Think, DeepSeek-V3.2, Llama3.3-70B, Qwen3-32B
- **Evaluation**: Pairwise LLM-as-a-Judge (Gemini-2.5-Pro for EN, DeepSeek-V3.2-Think for ZH) with position swapping
- **Human validation**: 8 annotators, Cohen's Kappa κ = 0.62–0.76 across paradigms

## 3. Trade-offs

| Aspect | Wins | Costs/Losses |
|--------|------|-------------|
| **Long-horizon coherence** | Resolves social memory stacking and narrative-spatial dissonance; sustained logical consistency across 15+ events | Progressive memory accumulation; RSB/EEB structures grow unbounded with simulation length |
| **Endogenous emergence** | Converts stochastic hallucinations into creative assets (ECGP); infinite world expansion from minimal seed | Requires strong reasoning models; non-reasoning models (Llama3.3-70B, Qwen3-32B) show degraded performance |
| **Narrative control spectrum** | Single substrate supports rigid (HDP), semi-structured (SNP), and free-form (Free EN) paradigms | Free EN mode suffers higher variance and stochasticity; HDP shows less dynamic social evolution |
| **Multi-agent collaboration** | 4 specialized agent types with explicit role boundaries enable complex coordination | 63.6 min for 100 turns (6.9x slower than HoLLMwood's 9.1 min); 38.17s avg/turn latency |
| **Spatial alignment** | GMS eliminates character "lost in space" phenomena; strict RLP alignment | Adds computational overhead per turn for spatial blocking computations |
| **Memory architecture** | 4-layer SNM with in-place RSB updates prevents conflict accumulation | Event-driven reflect-synthesize-consolidate cycle adds per-event processing cost |

## 4. Design Rationale

**Why treat hallucinations as assets ("sparking")?** The authors observe that LLM hallucinations in constrained settings are not random noise but signals of narrative gaps that need filling. Rather than suppressing them (as most systems do), they repurpose them as drivers of endogenous evolution. This is the core philosophical inversion: stochasticity is a feature, not a bug, for open-ended narrative generation.

**Why living cognition (RSB in-place updates) over append-only memory?** Append-only architectures accumulate contradictory relational states (e.g., "friend" and "enemy" simultaneously). RSB with in-place updates ensures agents act from a single, conflict-free snapshot — the agent's internal state is overwritten to reflect the current reality rather than accumulating all historical states. This is analogous to human memory consolidation.

**Why multi-agent over monolithic?** Narrative coherence requires simultaneous management of plot structure, spatial logic, character consistency, and creative emergence — tasks that benefit from specialized agents with distinct responsibilities (Genesis for world-building, Architect for instantiation, Director for real-time orchestration, Role Agents for autonomous interaction).

**Why parametric control spectrum (HDP/SNP/Free EN)?** Existing systems are either too rigid (script-driven) or too chaotic (free emergence). A unified substrate supporting the full spectrum allows users to select the appropriate level of control without switching frameworks.

## 5. Limitations & Failure Modes

1. **Progressive Performance Degradation**: Memory overhead and inference latency increase with simulation length. RSB and EEB grow unboundedly, making very long simulations (100+ events) impractical without manual pruning or compression strategies.

2. **Reasoning Model Dependency**: Performance relies heavily on reasoning-capable LLMs (Gemini-2.5-Pro, DeepSeek-V3.2-Think). Non-reasoning models (Llama3.3-70B, Qwen3-32B) show significant degradation, and ECGP may fail to produce valid sparking when the base model cannot maintain constraint awareness.

3. **Human-Player Interaction Under-Explored**: Evaluation prioritizes agent-to-agent evolution. Responsiveness to unpredictable human inputs is acknowledged as unquantified — a major gap for interactive applications.

4. **No Real-Time Capability**: 38.17s average per-turn latency prohibits real-time or near-real-time applications.

5. **Limited Genre Validation**: Only 6 genres tested; performance on comedy, horror, experimental, or non-narrative formats is unknown.

6. **Single-Evaluator Bias**: LLM-as-a-Judge with only two judges (Gemini-2.5-Pro for EN, DeepSeek for ZH) — no ensemble or cross-model verification. Position-swapping helps but does not eliminate judge-model bias.

7. **No Formal Correctness Guarantees**: The system has no mechanism to detect or recover from narrative "dead ends" where sparking produces characters that are logically impossible to integrate.

## 6. Transfer to Lyra

**The One Transferable Idea**: The **Sparking-to-Ontological-Promotion Pipeline** (ECGP). In Lyra's multi-agent architecture, the idea of treating constraint violations / unexpected outputs from LLMs not as errors but as *signals of latent functional necessity* — and building a protocol to validate, filter, and structurally integrate these — could enable Lyra to autonomously discover new tools, plugins, or agent roles during operation. Specifically: when an agent attempts to use a non-existent tool or capability, instead of rejecting the attempt, Lyra could capture it as a "sparking," validate whether the capability would genuinely advance the task, and auto-generate a scaffold for it.

**Workstream Route**: §4.5 — Adaptive Agent Orchestration / Plugin System (the ECGP pattern maps directly to dynamic capability discovery and tool emergence in Lyra's plugin architecture)

**Impact**: 4 (enables autonomous capability discovery — a qualitatively new behavior for Lyra)
**Effort**: 4 (requires designing entity resolution, ontological promotion, and integration protocols for Lyra's specific action space; significant prompt engineering and validation infrastructure)
**Tier**: Investigate (compelling conceptual match but requires proof-of-concept on Lyra's simpler action space before full investment; the narrative domain mapping to tool-use domain needs validation)
