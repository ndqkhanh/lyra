## 1. Mechanism (Step-by-Step)

MATU quantifies uncertainty in LLM-based multi-agent systems (MAS) by representing reasoning trajectories as a ragged tensor and applying PARAFAC2 (CP-2) decomposition. The reconstruction error becomes the uncertainty score.

### Step 1: Multi-run Trajectory Collection
For a fixed input `x`, run the MAS `N` times (default `N=10`, temperature 0.9). Each run `j` produces a trajectory `τ^(j) = {y^(j,k)_(1:T_k)}` for agents `k=1..K`, where `T_k` is the variable number of steps taken by agent `k`. Each step is a natural language string or tool-call result.

### Step 2: Embedding Multi-step Reasoning
For each step `t` in trajectory `j`, encode the text into a fixed-dimensional vector using a pre-trained embedding model (default: Qwen3-Embedding-0.6B, `d=256`):

```
e^(j)_t ∈ R^d
```

Concatenating across all steps of agent `k` in run `j` yields an embedding matrix:

```
E^(j,k) ∈ R^(T_{j,k} × d)
```

This decouples semantic comparability from surface form; semantically equivalent steps (even from different agents, wordings, or tools) map close together in the latent space.

### Step 3: Ragged Tensor Construction
Stack all embedding matrices across runs and agents into a ragged 3D tensor:

```
X = { E^(j,k) | j = 1..N; k = 1..K }
```

This is a **ragged tensor** because `T_{j,k} ≠ T_{j',k'}` in general — different runs produce different numbers of steps. X is not a standard rectangular tensor `R^{N×T×d}`.

### Step 4: PARAFAC2 (CP-2) Decomposition
Apply CP-2 decomposition, which handles variable-length modes by aligning latent factors across dimensions of varying sizes. CP-2 seeks a rank-`R` approximation:

```
X ≈ X̂_R = Σ_(r=1)^R λ_r · u^(1)_r ⊗ u^(2)_r ⊗ u^(3)_r
```

where `λ_r` are scalar weights and `u^(d)_r` are latent factor vectors that respect the irregular lengths.

### Step 5: Reconstruction Loss as Uncertainty
For each rank `R` from 1 to `R_max`, compute the Frobenius-norm reconstruction loss:

```
L_R = ||X - X̂_R||²_F = Σ_{i,j,k} (x_{ijk} - x̂_{ijk})²
```

The **total uncertainty score** aggregates losses across all ranks:

```
U = Σ_(R=1)^(R_max) L_R
```

A **higher U** indicates trajectories resist low-rank compression (divergent reasoning, unstable communication, fragile consensus). A **lower U** indicates consistent, compressible trajectories (reliable collaboration).

### Theoretical Motivation (Appendix B)
The CP-2 reconstruction loss is mathematically equivalent to the aggregated squared deviations from a learned consensus representation. In classical statistics, `Var(X) = E[||X - μ||²]`. MATU operationalizes this: the low-rank approximation `X̂` plays the role of `μ` (the expected semantic consensus), and the Frobenius norm measures ensemble variance in latent space.

### Key Design Properties
- **Topology-agnostic:** Same tensor structure works for star (AutoGen), chain/round-robin (Camel), and dynamic (AnyMac) topologies.
- **Black-box compatible:** No token probabilities required — works with closed-source APIs (GPT-4o).
- **Interpretable:** Latent factors map to specific error patterns (e.g., a semantic-misinterpretation component shows 2.29× higher mean loading in incorrect vs. correct runs).

## 3. Trade-offs

| Win | Lose |
|---|---|
| First systematic UQ framework for LLM-based MAS — handles multi-step reasoning, inter-agent communication, and topology diversity simultaneously | Inference cost scales **linearly with N** (number of sample runs); requires N=10 runs per query for reliable estimation |
| **Black-box compatible** — works with any LLM API (GPT-4o, Claude, etc.) without token probabilities | Single-pass methods remain 10× cheaper for latency-sensitive applications |
| **Topology-agnostic** — same tensor representation works for star, chain, dynamic topologies without modification | Sensitivity bounded by embedding model quality; degrades in specialized domains where general-purpose embeddings fail |
| **Interpretable latent factors** — CP-2 components map to specific error types with 2.29× separation between correct/incorrect runs | Requires **GPU** for tensor decomposition (single A100-80GB used). Decomposition adds compute overhead beyond inference |
| **OOD detection signal** — uncertainty scores separate ID (0.13) from OOD (0.92) cleanly | Only validated on text-based reasoning; tool-use evaluation limited to HumanEval only |
| Consistent gains across all 3 benchmark datasets (MATH, MoreHopQA, MMLU), 3 MAS frameworks, 3 LLMs, and 2 metrics | Does not provide real-time/interactive uncertainty — computed post-hoc from batch of runs |

## 4. Design Rationale

1. **Why tensor decomposition instead of NLI-based methods?** Single-turn UQ (semantic entropy, eigenvalue methods) applies NLI models to final outputs or concatenated trajectories. NLI models are designed for sentence pairs with limited context windows — they fail on long multi-step reasoning chains and cannot distinguish agent-specific errors from inter-agent misalignment. A tensor captures the full 3D structure (agents × steps × runs) that NLI flattens and loses.

2. **Why ragged tensors (CP-2) instead of standard PARAFAC?** MAS trajectories have inherently variable lengths across runs (different communication patterns, tool invocations, self-correction loops). Standard tensor decomposition requires fixed dimensions. CP-2 was specifically designed for irregular tensor structures and aligns latent factors across variable-length modes without padding or truncation.

3. **Why reconstruction loss as uncertainty?** Theorem: the Frobenius-norm reconstruction error equals the aggregated variance from a learned consensus (Appendix B). A low-rank approximation captures shared structure; high reconstruction error means runs deviate from that shared structure, which is the operational definition of uncertainty. This avoids ad-hoc heuristics and provides a principled statistical foundation.

4. **Why step-level embeddings instead of distance matrices?** Ablation (Fig. 2a) shows that Cosine Similarity and Earth Mover's Distance matrices fed into decomposition lose granular latent signals. Raw embedding matrices preserve step-level semantic nuance, allowing CP-2 to disentangle surface form (verbosity, self-corrections) from semantic content.

## 5. Limitations & Failure Modes

1. **Linear cost scaling with N:** Requires N=10 runs at inference time. Each run incurs the full cost of the MAS. For expensive models (GPT-4o), this means 10× the inference cost per query. In latency-critical production systems, this overhead is prohibitive unless amortized over batched offline evaluation.

2. **Embedding model dependence:** The method decouples semantics from surface form via a frozen embedding model (Qwen3-Embedding-0.6B). In highly specialized domains (legal contracts, medical terminology, niche technical fields), general-purpose embeddings may fail to capture domain-specific semantic nuance, leading to inaccurate uncertainty estimates. Domain-specific embeddings would be required.

3. **Post-hoc only / no real-time feedback:** MATU computes uncertainty from completed trajectory batches. It cannot provide online uncertainty signals during an ongoing multi-agent conversation to trigger intervention, fallback, or human escalation.

4. **Limited tool-use evaluation:** Only tested with a Python interpreter on HumanEval. Performance on more complex tool chains (web search, databases, code execution + API calls in sequence) is unverified.

5. **Single reference LLM for ground truth:** Correctness labels are generated by GPT-5. Any systematic biases in GPT-5's evaluation propagate to the UQ training signal.

6. **Interpretability is preliminary:** The latent factor interpretation protocol (Appendix D) is demonstrated on one MATH problem only. Large-scale automated semantic interpretation across datasets is left as future work.

## 6. Transfer to Lyra

### The One Transferable Idea
**Use tensor decomposition (PARAFAC2) on Lyra's multi-agent reasoning trajectories as a post-hoc reliability signal.** Lyra already executes multi-agent pipelines across its workstreams. By collecting embedding matrices of each agent's reasoning steps across multiple runs of the same plan, constructing a ragged 3D tensor (agents × steps × runs), and computing CP-2 reconstruction loss, Lyra gains a principled, topology-agnostic uncertainty score that can drive fallback routing, consensus voting, or human escalation decisions.

### Workstream Route: §4.4 — Verification & Reliability
This directly feeds Lyra's verification subsystem. The uncertainty score `U` can serve as:
- A gating signal before deploying a plan (high U → verify/revise)
- A routing heuristic for the router (§4.5) to select the most reliable agent backbone
- An OOD detector for inputs that fall outside Lyra's safe operating envelope

### Impact / Effort / Tier

| Dimension | Rating | Rationale |
|---|---|---|
| **Impact** | 4/5 | Uncertainty quantification is a critical missing piece in Lyra's verification stack. MATU provides the first principled UQ method purpose-built for MAS. Integrating it would meaningfully improve reliability, especially for high-stakes automated workflows. |
| **Effort** | 3/5 | Requires: (1) a trajectory logging infrastructure to capture per-step embeddings, (2) integration of a CP-2 decomposition library (e.g., TensorLy), (3) calibration of rank thresholds for Lyra's specific agent topologies. The core algorithm is well-specified and the paper provides reference code. The main cost is the N-run sampling overhead. |
| **Tier** | **Investigate** | MATU is not yet a production-grade reliability tool (post-hoc only, linear cost scaling, limited interpretability). But its principled foundation and consistent empirical gains make it highly worth prototyping. A lightweight pilot on a single Lyra workstream (e.g., verification) with a small number of runs (N=5) would reveal whether the tensor approach generalizes to Lyra's agent architectures. |

### Caveats for Lyra Adaptation
- Lyra's agents may produce highly heterogeneous step content (code, structured JSON, natural language, tool outputs). The embedding model must handle this multimodality or separate embeddings per modality may be needed.
- The 10-run sampling cost may be acceptable for offline plan verification but too expensive for online routing — consider stochastic approximation (fewer runs with confidence intervals).
- Lyra's dynamic routing topology (AnyMac-like) is explicitly validated — static topologies (Camel, AutoGen) show even stronger results.
