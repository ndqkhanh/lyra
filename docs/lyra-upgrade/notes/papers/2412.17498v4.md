## 1. Mechanism (step-by-step)

DRT applies O1-style long chain-of-thought reasoning to neural machine translation in four stages:

### Stage 1: Data Mining (Corpus Construction)

- Source: ~400 English books from Project Gutenberg
- Extract all sentences, filter by length (10–100 words) → **577.6K literature sentences**
- Two-question filter via Qwen2.5-72B-Instruct:
  - Q1: "Does this sentence contain similes or metaphors?" (binary)
  - Q2: "Can a literal translation be understood by native [target] speakers?"
- Keep sentences where Q1 = yes AND Q2 = no → **63K pre-collected sentences**

### Stage 2: Multi-Agent Synthesis Framework

Three agents, each backed by Qwen2.5-72B-Instruct, operate in a structured loop:

**Step 1 — Keyword Identification (Word-Level):** The translator agent identifies keywords \( \mathcal{W}^{\text{src}} = \{w_1^{\text{src}}, ..., w_k^{\text{src}}\} \) from the source sentence and provides target translations \( \mathcal{W}^{\text{tgt}} = \{w_1^{\text{tgt}}, ..., w_k^{\text{tgt}}\} \). This decomposes the sentence into sub-problems before full translation.

**Step 2 — Preliminary Translation:** The translator produces initial translation \( t^0 \) conditioned on source sentence \( s \) and bilingual keyword pairs \( \langle\mathcal{W}^{\text{src}}, \mathcal{W}^{\text{tgt}}\rangle \).

**Step 3 — Refine Loop (k = 1, 2, ..., m):**
```
for each iteration k:
    advisor(s, t^{k-1})      → f^{k-1}   (detailed feedback)
    evaluator(t^{k-1}, f^{k-1}) → s^{k-1}   (numeric score 0-100)
    translator(s, t^{k-1}, f^{k-1}, s^{k-1}) → t^k   (revised translation)
    if score ≥ threshold or max_iter: break
```

The stop condition is a score threshold or maximum iterations reached. Each iteration produces a triplet \(\langle t^k, f^k, s^k\rangle\).

### Stage 3: Long Thought Reformulation

The raw multi-agent trace forms a thought sequence:
\[
\mathcal{P}(s): s \Rightarrow \langle\mathcal{W}^{\text{src}}, \mathcal{W}^{\text{tgt}}\rangle \Rightarrow \langle t^0, f^0, s^0\rangle \Rightarrow ... \Rightarrow \langle t^m, f^m, s^m\rangle
\]

Post-processing steps:
1. **Deduplicate stagnation:** Remove iterations where score did not change (\(s^i = s^{i-1}\)), producing \(\mathcal{P}^{\prime}(s)\) with \(n\) remaining steps
2. **Quality filter:** Discard samples where \(n < 3\) (insufficient chain)
3. **Polish with GPT-4o:** Following Qin et al. (2024), GPT-4o reformulates \(\mathcal{P}^{\prime}(s)\) into fluent self-reflection prose while preserving the reasoning logic
4. **Select best output:** The translation with the highest score \(s^{r_j}\) (not necessarily the last) is the final translation

Final dataset: **22,264 samples** (train: 19,264 / val: 1,000 / test: 2,000), average thought length **527.64 tokens**.

### Stage 4: SFT Training

- Framework: Llama-Factory
- Hardware: 8× NVIDIA A100 (40G), DeepSpeed ZeRO-3
- Hyperparameters: lr=1e-5, batch size=8, 3 epochs
- Cost: 70 GPU-hours (7B), 124 GPU-hours (14B)
- Backbones: Llama-3.1-8B-Instruct, Qwen2.5-7B-Instruct, Qwen2.5-14B-Instruct
- Input format: source sentence → model generates long CoT thought → final translation
- Inference: vLLM, temperature=0.1, repetition penalty=1.05

### Control Baselines

**SFT w/o CoT:** Same backbones fine-tuned on paired sentence-translation from the DRT training set, but with the thought process stripped out (i.e., direct input→output mapping).

## 4. Design Rationale

**Why multi-agent over MCTS?** MCTS (used by O1-Coder, etc.) prioritizes complex multi-step reasoning paths suited for math/code, but the authors argue translation is inherently simpler — you translate once and refine, not explore branching logic trees. The multi-agent loop (translator → advisor → evaluator) mirrors how human translators work: draft, get feedback, revise, score.

**Why mine for similes/metaphors specifically?** Long CoT harms simple translation ("overthinking"). By restricting to sentences where literal translation demonstrably fails (Q2 = no), the authors ensure the thought chain adds genuine value rather than generating superfluous reasoning. This is the key insight that makes long-thought MT viable rather than merely wasteful.

**Why GPT-4o polish?** Raw multi-agent traces are machine-generated and lack fluency. GPT-4o reformulates the trace into natural self-reflection prose while preserving the reasoning structure. This is a data-quality operation, not a knowledge-transfer one — GPT-4o adds style, not content.

**Why Qwen2.5-72B as evaluator agent over GPT-4o?** The evaluator achieves 92.5% accuracy vs human judgment (GPT-4o: 93.5%). The 1% accuracy gap is accepted for cost-effectiveness at scale (63K sentences).

## 5. Limitations & Failure Modes

1. **Language pair monoculture:** English→Chinese only. The framework claims generality but provides zero evidence for other language pairs. Tone, rhetoric, and cultural translation strategies may differ substantially across languages.

2. **No proper automatic evaluation exists for literary MT:** The authors explicitly acknowledge BLEU and CometScore are unreliable for literary translation (CometKiwi achieved only 56% accuracy vs human judgment). This means the only trustworthy numbers are LLM-as-judge (GEA/GRF/GRB) and human evaluation — both of which have their own biases.

3. **Low data yield rate (3.86%):** From 577.6K literature sentences, only 22.3K long-thought samples survive all filters. Scaling to broad-coverage translation would require fundamentally different data strategies.

4. **Inference latency wall:** 11.9–13.9× slowdown makes real-time or interactive use infeasible. The paper explicitly notes O1-like models are unsuitable for "scenarios with high real-time requirements."

5. **Evaluator agent limitation:** The evaluator (Qwen2.5-72B) achieves 92.5% accuracy, meaning ~7.5% of training samples have incorrect quality signals. Error propagation through the refinement loop is unexamined.

6. **Shortcut learning hypothesis:** DRT-14B underperforms SFT-14B on BLEU/CometScore. The authors speculate SFT learns "shortcuts" (domain adaptation via direct mapping) that reference-based metrics reward, but DRT produces semantically richer output that reference-based metrics penalize. This is a hypothesis, not a proven claim.

7. **No ablation on thought chain necessity:** The paper does not study whether the content of the thought chain matters vs. merely generating extra tokens (a "thinking tax"). If longer generation alone improves quality (e.g., via more compute), the specific CoT structure may be incidental.

8. **Refine loop convergence not guaranteed:** The loop stops at score threshold or max iterations. Adversarial cases where the evaluator gives inconsistent scores across iterations could produce degenerate chains.

## 6. Transfer to Lyra

### The One Transferable Idea

**Structured multi-agent refinement loops with explicit scoring for quality-sensitive generation tasks.** DRT's translator→advisor→evaluator loop with iterative score improvement is a generalizable pattern for any Lyra subsystem that produces quality-sensitive output (code, plans, research findings). The key architectural insight is: (a) decompose output into sub-problems first (keyword identification), (b) generate a draft, (c) have separate critic and scoring agents, (d) iterate until score threshold or max steps, (e) only keep trajectories where score actually improved. This maps directly to Lyra's verification subsystem (the evaluator agent pattern) and the planning subsystem (generate→critique→revise→score loop).

### Workstream Route: §4.16 (Reliability) + §4.20 (Planning)

### Impact/Effort/Tier

- **Impact:** 4 — The multi-agent refinement loop with explicit scoring is a core architectural primitive that can upgrade verification, planning, and deep-research subsystems. The literature-specific mining is irrelevant, but the refinement pattern is broadly applicable.
- **Effort:** 3 — Requires implementing a generic RefinementLoop harness (orchestrator + advisor + evaluator agent roles) and integrating with existing Lyra agent infrastructure. The core loop logic is ~200-300 lines; the challenge is prompt engineering for domain-specific scoring criteria.
- **Tier:** **breakthrough** — This is not a standard translation paper; it is a demonstration that structured, long-horizon reasoning chains generated via multi-agent collaboration improve output quality in domains previously considered "too simple" for CoT. The pattern transfers cleanly to Lyra's reliability and planning workstreams.
