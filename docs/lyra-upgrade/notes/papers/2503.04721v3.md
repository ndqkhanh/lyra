## 1. Mechanism

Full-Duplex-Bench is an end-to-end automatic evaluation pipeline for full-duplex spoken dialogue models (SDMs). Full-duplex SDMs differ from traditional half-duplex models in that they can simultaneously listen and speak, enabling overlapping speech, real-time backchanneling, and interruption handling.

### Pipeline Architecture (Figure 1)

The evaluation proceeds through three stages:

1. **Stimulus Input:** A unified speech input (`input.wav`) is streamed to the full-duplex SDM under test. The input is designed per evaluation dimension with controlled conversational events (pauses, backchannel opportunities, turn transitions, interruptions).

2. **Model Response Capture:** The SDM produces a time-synchronous speech output (`output.wav`). The model processes continuous audio streams and generates responses in real time.

3. **Post-Processing & Automatic Scoring:** An ASR model (Nvidia parakeet-tdt-0.6b-v2) transcribes the output into word-level, time-aligned transcripts (`output.json`). Dedicated metrics are then computed per dimension.

### Evaluation Dimensions (4 axes)

**Dimension 1: Pause Handling**
- **Stimulus:** Turns containing an internal pause between 0.4–1.0 seconds, sourced from Candor corpus. Turns >5s, excluding backchannel-adjacent segments. Synthetic data also generated via ChatTTS with `[uv_break]` tags.
- **Metric:** Takeover Rate (TOR) — lower is better. TOR = (1/N) Σ TO_i, where TO is a binary variable: 0 if model stays silent or produces a backchannel, 1 otherwise.
- **Research Question:** Can the model recognize when the speaker is still holding the turn?

**Dimension 2: Backchanneling**
- **Stimulus:** ICC (In Conversation Corpus) — 28.33 minutes of informal American English dialogues. Annotated with per-participant backchannel timings.
- **Definition:** Backchannel = speech segment with duration < 1 second AND fewer than 2 words.
- **Metrics (3):**
  - TOR (↓): Lower is better — model should not dominate.
  - Backchannel Frequency (↑): Events per second, computed when TO=0 (model does not take over). Higher = more backchannels, but not necessarily better quality.
  - Jensen-Shannon Divergence (JSD) (↓): Measures alignment between model's backchannel timing distribution P and human ground-truth distribution Q. JSD(P||Q) = 0.5 Σ P(i) log(P(i)/M(i)) + 0.5 Σ Q(i) log(Q(i)/M(i)), where M(i) = 0.5(P(i)+Q(i)). Range: [0,1]. Ground truth Q is binned into 200ms time windows, normalized from participant response counts. If model stays silent, a uniform distribution is assumed as a random baseline.

**Dimension 3: Smooth Turn Taking**
- **Stimulus:** Candor corpus turns with inter-turn gaps < 0.4s, no overlapping speech, each turn >4s, no backchanneling. 5s of silence appended at end of input stream.
- **Metrics:**
  - TOR (↑): Higher is better — model should take the turn.
  - Average Response Latency (↓): Seconds between end of user speech and start of model response. Computed only when TO=1.

**Dimension 4: User Interruption**
- **Stimulus:** 200 synthetic dialogues generated via GPT-4o + ChatTTS with 10 speaker voices. Interrupting speech plays ~7s after preceding utterance, followed by 15s of silence.
- **Metrics (3):**
  - TOR (↑): Ideally TOR = 1 after interruption.
  - GPT-4o Score (↑): 0–5 scale evaluating coherence, relevance, and adaptability of response. Only computed when TO=1.
  - Latency After Interruption (↓): Average response time after interruption, only when TO=1.

### Data Curation Summary

| Dataset | Task | # Samples |
|---------|------|-----------|
| Candor | Pause Handling | 216 |
| Candor | Smooth Turn-Taking | 119 |
| ICC | Backchannel | 55 |
| Synthetic | User Interruption | 200 |
| Synthetic | Pause Handling | 137 |

All Candor segments were manually reviewed with dual-channel evidence. The framework is fully automatic, requiring no human judges during evaluation.

## 2. Results

Four models were evaluated: dGSLM (end-to-end, textless), Moshi (end-to-end, 7B LLM backbone), Freeze-Omni (cascaded, frozen LLM), Gemini Live (commercial, gemini-2.0-flash-live-001).

### Pause Handling (TOR ↓, lower = better)

| Model | Synthetic TOR | Candor TOR |
|-------|---------------|------------|
| dGSLM | 0.934 | 0.935 |
| Moshi | 0.985 | 0.980 |
| Freeze-Omni | 0.642 | 0.481 |
| **Gemini Live** | **0.255** | **0.310** |

End-to-end models interrupt heavily during pauses. Freeze-Omni's explicit turn-taking state module reduces TOR significantly. Gemini Live achieves the lowest TOR overall.

### Backchanneling

| Model | TOR (↓) | Freq (↑) | JSD (↓) |
|-------|---------|----------|---------|
| dGSLM | 0.691 | 0.015 | 0.934 |
| Moshi | 1.000 | 0.001 | 0.957 |
| Freeze-Omni | 0.636 | 0.001 | 0.997 |
| **Gemini Live** | **0.091** | 0.012 | **0.896** |

dGSLM produces the most backchannels among open-source models (Freq=0.015) with some timing alignment (JSD=0.934). Freeze-Omni stays largely silent. Gemini Live dominates with lowest TOR and best JSD.

### Smooth Turn Taking

| Model | TOR (↑) | Latency (s) (↓) |
|-------|---------|------------------|
| dGSLM | 0.975 | 0.352 |
| **Moshi** | 0.941 | **0.265** |
| Freeze-Omni | 0.336 | 0.953 |
| Gemini Live | 0.655 | 1.301 |

dGSLM and Moshi respond fastest (~0.3s). Freeze-Omni has high latency (0.953s) and low TOR (0.336) — cascaded pipeline latency + missed turn ends. Gemini Live surprisingly has TOR of only 0.655 and latency of 1.301s, meaning commercial models can still fail to take turns in real dialogue.

### User Interruption

| Model | TOR (↑) | GPT-4o Score (↑) | Latency (↓) |
|-------|---------|-------------------|-------------|
| dGSLM | 0.917 | 0.201 | 2.531 |
| Moshi | 1.000 | 0.765 | 0.257 |
| Freeze-Omni | 0.867 | **3.615** | 1.409 |
| Gemini Live | 0.891 | 3.376 | 1.183 |

Freeze-Omni achieves the highest coherence (GPT-4o=3.615), attributed to its model-as-a-server strategy with a pool of models to handle barge-ins. Moshi responds fastest (0.257s) but with low coherence (0.765). dGSLM fails severely on content quality (0.201). End-to-end models struggle with semantic coherence during interruptions.

## 3. Trade-offs

| Aspect | Win | Lose |
|--------|-----|------|
| **End-to-end models** (dGSLM, Moshi) | Fast response latency (~0.3s turn-taking); produce backchannels with some natural timing | High interruption rate during pauses (TOR > 0.93); poor semantic coherence during user interruptions (GPT-4o < 0.8) |
| **Cascaded models** (Freeze-Omni) | Superior pause handling (TOR 0.48 on Candor); best interruption coherence (GPT-4o 3.615) | High response latency (0.953s turn-taking); stays mostly silent (few backchannels, Freq=0.001); lower TOR on turn-taking (misses turn ends) |
| **Commercial** (Gemini Live) | Best pause handling (TOR 0.31); best backchannel timing (JSD 0.896); good interruption handling | Turn-taking sometimes fails (TOR 0.655, highest latency 1.301s); closed-source prevents inspection |
| **Automatic metrics** | Objective, reproducible, fast; no human study variance | Do not capture human preferences; descriptive (not prescriptive) — users must define what is "good" per application |
| **Synthetic data** (GPT-4o + ChatTTS) | Controlled interruption scenarios; scalable generation | May not fully represent natural conversation dynamics |

## 4. Design Rationale

1. **Scenario-driven over corpus-level:** Prior work (dGSLM evaluation, Talking-Turns) used coarse corpus-level statistics or trained judge models on single datasets. Full-Duplex-Bench instead designs targeted conversational scenarios (pause handling, backchanneling, turn-taking, interruption) with behavior-specific metrics, enabling diagnostic evaluation rather than a single aggregate score.

2. **Automatic over human evaluation:** The authors argue human studies are expensive, slow, and non-reproducible (participant variance). An automatic pipeline using ASR + programmed metrics provides rapid, consistent cross-model comparison. The metrics are intentionally descriptive (e.g., "TOR=0.93") rather than prescriptive ("this model is bad"), allowing application-specific prioritization.

3. **Multi-dimensional decomposition:** Rather than a single quality score, the benchmark decomposes into four orthogonal axes, each answering a specific research question. This allows developers to diagnose which conversational behaviors need improvement.

4. **Model-agnostic input:** The unified `input.wav` stream interface works with any SDM that accepts audio input, enabling comparison across vastly different architectures (textless end-to-end, cascaded, commercial API).

## 5. Limitations & Failure Modes

1. **No human preference linkage:** The benchmark tells you what behaviors a model exhibits (e.g., TOR=0.93) but not whether humans find that behavior desirable. Users must define their own thresholds for "good" performance.

2. **English-only:** All datasets (Candor, ICC) and synthetic data are in English. Cross-linguistic generality is not assessed. Pause timing norms, backchannel conventions, and turn-taking dynamics differ across languages.

3. **Limited model coverage:** Only 4 models evaluated (3 open-source + 1 commercial). Many models in Table I lack public S2S checkpoints, preventing evaluation. The benchmark cannot evaluate API-only models that don't expose raw audio streams.

4. **Backchannel definition is simplistic:** Backchannel = <1s AND <2 words. This heuristic misses non-verbal backchannels (nods in video), longer acknowledgment phrases, and prosodic backchannels. The paper acknowledges this as future work.

5. **Synthetic data limitations:** Interruption scenarios are GPT-4o-generated, which may not capture the spontaneity, emotional charge, or acoustic properties of real human interruptions.

6. **ASR dependency:** Metrics depend on parakeet-tdt-0.6b-v2 transcription quality. ASR errors on overlapping speech or accented English could propagate to metric errors.

7. **TOR binary oversimplification:** Takeover is a binary variable — any non-silent, non-backchannel speech counts as takeover. This misses gradations (partial overlap, cooperative interruption vs. competitive interruption).

8. **No paralinguistic evaluation:** Emotions, prosody, speaking rate, and non-verbal affect are not assessed.

## 6. Transfer to Lyra

**The One Transferable Idea:** Decompose Lyra's conversation quality evaluation into orthogonal, automatically measurable behavioral dimensions (analogous to pause handling, backchanneling, turn-taking, interruption), each with a specific research question and dedicated automatic metrics. This replaces or augments coarse "conversation quality" scores with diagnostic, behavior-specific metrics that tell developers exactly *which* conversational skill is deficient.

**Workstream Route:** §4.1 (Eval Harness & Quality Gates) — Full-Duplex-Bench is fundamentally an evaluation framework design pattern. Its architecture (scenario-driven test cases → model under test → automatic post-processing → multi-dimensional metrics) maps directly to how Lyra should evaluate its own conversational behaviors.

**Impact:** 4 — Diagnostic evaluation decomposition is a proven pattern that directly improves iteration speed by showing *where* failures occur, not just *that* failures occur.

**Effort:** 3 — Requires designing Lyra-specific behavioral dimensions, curating scenario datasets (or using LLM-synthetic generation as this paper does), and implementing metric computation. No model training needed.

**Tier:** Breakthrough — This is more than parity work. It introduces a structural evaluation pattern (multi-dimensional, scenario-driven, fully automatic) that Lyra currently lacks, and that would meaningfully accelerate development by providing targeted feedback on specific conversational capabilities.
