## 1. Mechanism

The paper proposes a **three-stage evolutionary framework** for LLM agent memory mechanisms, formalized mathematically and organized by increasing abstraction depth.

### Foundational Formalization
An LLM agent with parameters θ operates via policy πθ:
- at ~ πθ(at | I, ot, mt)  —  where I = system instruction, ot = observation, mt = Retrieve(M, ot)
- M is the externalized memory repository; mt is the retrieved instantiation at time t

### Stage 1: Storage (Trajectory Preservation)
Raw trajectories are preserved with minimal transformation:
- **Trajectory:** τ = ⟨(o₁, a₁), ..., (oT, aT)⟩  —  chronological observation-action pairs
- **Repository:** Mraw = {τᵢ}ᴺᵢ₌₁, τᵢ ∈ T  —  cumulative set of all historical trajectories

**Sub-mechanisms:**
- **Linear:** FIFO token-stream management; Context Window Adaptation (StreamingLLM, SelfExtend, PCW) and Information Sparsification (H₂O eviction by attention scores, Quest query-aware sparsity, LLMLingua perplexity-based compression)
- **Vector:** Encode trajectories into high-dimensional embeddings. Semantic Retrieval (ARMRAG, MemLong, Larimar) vs. Weighted Retrieval (MemoryBank w/ Ebbinghaus Forgetting Curve decay, Stanford Town w/ relevance+recency+importance scoring)
- **Structured:** Tabular (ChatDB, DB-GPT SQL translation), Tiered (MemGPT dual-layer context separation, MemoChat, MemOS), Semantic Graphs (MemLLM triplets, AriGraph world models, GraphReader coarse-to-fine traversal)

### Stage 2: Reflection (Trajectory Refinement)
Semantic transformation Fref: T → S producing refined memory units:
- m′ᵢ = Fref(τᵢ | φ)  —  φ = evaluation criteria
- M ← M ∪ {m′ᵢ}  —  decoupled from original trajectory noise

**Sub-mechanisms:**
- **Introspection:** Error Rectification (Reflexion self-critique, TiM post-reasoning verification, LLM-MapRepair consistency checks), Dynamic Maintenance (Zep entity-relation parsing, Mem0 lifecycle management, CAMA incremental clustering), Knowledge Compression (MemOrb structured reflections, LEGOMem procedural memory decomposition, AgentFold context-folding)
- **Environment:** Environment Modeling (DEAL world-rule inference, ToolMem tool-behavior summarization, CLIN continual adaptation), Decision Optimization (Memory-R1 discrete action RL, MDSF value-annotated trajectories, Self-Goal goal-hierarchy pruning)
- **Coordination:** Multi-agent calibration (MIRIX multi-module coordination, GraphCoGent role-decomposed graph reasoning, CSR collective self-reflection)

### Stage 3: Experience (Trajectory Abstraction)
Fexp is an inductive operator that extracts universal rules K from topologically similar trajectory batches:
- Tbatch = {τᵢ | Sim(τᵢ, τⱼ) > ε}  —  similarity-threshold grouping
- K = Fexp(Tbatch), s.t. |K| ≪ Σ|τ|  —  Minimum Description Length compression
- K serves as a **policy prior** for unseen scenarios (no trajectory-level matching required)

**Sub-mechanisms:**
- **Explicit:** Heuristic Guidelines (FLEX modular compositional heuristics, ArcMemo multi-turn reasoning graphs, G-Memory hierarchical memory tracing, Dynamic Cheatsheet prompt-list), Procedural Primitives (IPS skill-induction as functions, AccelOpt kernel-optimization skills, CASCADE cascading skill execution)
- **Implicit:** Latent Modulation (MemGen "Memory Weaver" latent-token injection, LatentEvolve alternating Fast Retrieval/Slow Integration), Parameter Internalization (AgentEvolver "Experience Stripping" to remove retrieval segments during training, Agent-LV early-experience paradigm, VerlTool RL-tool alignment)
- **Hybrid:** Experience Transfer (EvolveR offline-distillation then online-exploitation, ReasoningBank explicit replay buffer + offline-policy gradient updates, Hybrid-Replay on/off-policy cycling)

### Two Transformative Mechanisms in Experience:
1. **Active Exploration:** Reward-driven (value-guided state-space search), Curriculum-driven (dynamic task-difficulty sequencing), Reuse-driven (historical trajectory abstraction). Operates across Breadth (curiosity-structured experience for unfamiliar environments), Depth (high-order skill extraction for vertical tasks), and Strategy (decision-path optimization for long-horizon planning).
2. **Cross-Trajectory Abstraction:** Contrastive Induction (success-vs-failure boundary delineation), Action Distillation (fine-grained-to-high-order chunking), Code Encapsulation (behavioral patterns → reusable functions), Gradient Internalization (trajectory distribution → model weights). Granularity levels: Shallow (natural-language rules), Intermediate (modular execution skeletons), Deep (model-weight intuition).

## 2. Results

This is a **qualitative survey** with no original experiments. Its value is taxonomic and architectural:

- **Taxonomy coverage:** 200+ papers catalogued across 3 stages, 9 sub-categories, 30+ named systems
- **Benchmark catalog (Table 2):** 22 datasets across Storage (12), Reflection (10), and Experience (4) stages with sizes ranging from 50 (LoCoMo) to 280k (MMNeedle) samples
- **Key observation:** Experience-stage benchmarks are scarce — only 4 exist (StreamBench 9.7k, MemoryBench 20k, Evo-Memory 3.7k, LABench 1.4k), while the qualitative framework is the most advanced stage
- **Structural insight (Table 1):** Reflection outputs refined memory units m′ᵢ tied to original task context; Experience outputs universal rules K detached from any specific scenario, applicable as a policy prior without trajectory-level matching
- **Temporal distribution:** Memory research grew explosively from 2024–2025; Experience emerged as a coherent direction only in H2 2025

## 3. Trade-offs

| Win | Lose |
|-----|------|
| Storage: maximal fidelity, no information loss from transformation | Storage: raw trajectories conflate successes with hallucinations; linear memory expansion degrades performance |
| Reflection: semantic filtering removes noise; m′ᵢ is higher quality than raw τᵢ | Reflection: corrected trajectories still context-tied; induces retrieval cost; leads to trajectory-following behavior (overfitting to successful paths) |
| Experience: universal rules K compress vast repositories; enable zero-shot transfer to unseen tasks | Experience: abstraction risks loss of context-specific nuance; implicit internalization loses interpretability; parameter updates lag behind environmental dynamics |
| Explicit Experience: human-readable, editable, interpretable self-evolution | Explicit: still occupies context window; generalization bounded by natural-language expressiveness |
| Implicit Experience: no retrieval overhead, inference-efficient, latent-space intuition | Implicit: opaque, hard to debug, requires careful training to avoid catastrophic forgetting |
| Hybrid: dynamic accumulate-internalize cycle avoids storage explosion | Hybrid: adds architectural complexity; synchronization between explicit cache and implicit weights introduces latency |
| Active Exploration: proactivity uncovers valuable unseen states | Exploration: risk of distraction/loops without proper termination criteria; exploration-exploitation tension unresolved |

## 4. Design Rationale

The authors argue that existing memory research is fragmented between two weakly-integrated paradigms: OS engineering (MemGPT, MemOS) vs. cognitive science simulation (MemoryBank, Generative Agents). Neither captures the **dynamic evolutionary trajectory** of memory mechanisms. The 3-stage framework is chosen because it reflects real research progression: the field moved from solving the context-window problem (Storage) to addressing quality/hallucination (Reflection), and is now converging on cross-task generalization (Experience). The "Why-How-What" (RQ1-RQ2-RQ3) structure is motivated by the observation that prior surveys (Zhang et al. 2024, Hu et al. 2025b) provided static functional taxonomies without explaining *why* mechanisms transform. The MDL principle (|K| ≪ Σ|τ|) is invoked as the theoretical justification for Experience — compression as generalization, consistent with Solomonoff induction.

## 5. Limitations & Failure Modes

1. **No quantitative comparison:** The survey explicitly acknowledges it provides only qualitative taxonomy. No head-to-head benchmark numbers because (a) different stages have different design objectives, (b) no unified benchmark exists across all three stages, and (c) variations in base models/prompts/environments would make direct comparison misleading.
2. **Recency bias:** Experience stage research emerged in H2 2025; early influential works may be under-represented. Many cited Experience-stage preprints have not undergone peer review.
3. **Stage boundaries are fuzzy:** The authors note that mechanisms may retain characteristics of preceding stages even as their essence transitions — the taxonomy is an evolutionary lens, not a strict classification.
4. **Neglects computational cost analysis:** No discussion of GPU-hours, token costs, or latency overhead for different memory mechanisms.
5. **Multimodal memory gap:** The survey acknowledges that multimodal memory research is "concentrated predominantly within the Storage stage" — Reflection and Experience for multimodal are essentially unexplored.
6. **Experience evaluation crisis:** Only 4 benchmarks exist for Experience stage with no standardized protocol for measuring cross-task transfer or lifelong learning in agent memory.

## 6. Transfer to Lyra

**The ONE transferable idea:** The 3-stage evolutionary framework (Storage → Reflection → Experience) provides a **direct architectural blueprint** for Lyra's memory subsystem. Rather than treating memory as a monolithic vector store, Lyra should implement tiered memory with distinct Storage (linear + vector), Reflection (self-critique loop with environment feedback), and Experience (cross-session skill extraction with explicit heuristic libraries) layers. The formalization K = Fexp(Tbatch) with |K| ≪ Σ|τ| provides a concrete compression target for Lyra's context management.

**Workstream route:** §4.2 (Memory workstream) — this paper is the single best architectural reference found so far for memory subsystem design.

**Impact:** 5 (foundational architecture — defines the memory taxonomy that all other papers build upon)
**Effort:** 4 (requires building 3-tier memory pipeline with cross-trajectory abstraction logic, though existing vector-DB primitives reduce some cost)
**Tier:** breakthrough — this survey resolves the fragmentation in memory research and provides a clear, formalized path for implementation.
