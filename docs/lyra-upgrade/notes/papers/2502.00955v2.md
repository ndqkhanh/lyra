## 1. Mechanism (step-by-step)

### Problem Setup
Multi-agent systems (MAS) are modeled as a **directed graph** G = (V, E) where agents exchange information in topological order A₁ ⊕ A₂ ⊕ ... ⊕ A_M. The topology can be static (predetermined) or dynamic (agents adaptively control flow). Cycles are permitted (multi-round exchanges).

### Phase 1: MCTS Data Synthesis (inherited from Optima)
The synthesis tree starts from a task instruction p:

1. **Selection** — From the candidate node set, select node n = (s, a) using softmax over Q-values:
   - Filter similar nodes via edit distance: `Si,j = edit_distance(ni, nj) / max(|ni|, |nj|)`, keep nodes with `Si,j ≥ 0.25`
   - Select: `n ~ Softmax({Q(n)}ₙ∈Ncand)`

2. **Expansion** — For selected node n, compute new state `s' = Trans(s, a)`. Sample d actions from the next agent in topological order: `{a'₁, ..., a'ⱼ} ~ Aₘ₊₁(s')`.

3. **Simulation** — Roll out the remaining agent chain from the new state to termination: `τᵢ = Simulation(Aₘ₊₂, ..., A_M, s', a'ᵢ)`. All (s, a) pairs along the trajectory become new tree nodes.

4. **Backpropagation** — Compute trajectory reward R(τ) (task score - token penalty + LM loss bonus). Update node Q-values as the mean reward over all trajectories passing through the node:
   - `Q(n) = Q(s, a) = (1/|T(n)|) * Σ_{τ∈T(n)} R(τ)`

5. **Preference Pair Construction** — After k repeats, for each agent at each state, form pairs:
   - `z = (s, a_high, a_low)` where a_high has max Q-value, a_low has min Q-value

### Phase 2: DITS Influence Score Estimation (THE NOVELTY)
The key insight: **DPO loss correlates weakly (<0.2 Pearson) with downstream metrics** (F1, accuracy). Instead, DITS estimates influence on non-differentiable validation metrics.

**Step 1: Define influence via parameter perturbation**
Given optimal params θ* and data point zᵢ with extra weight ε:
```
θ*_{ϵ,zᵢ} = argmin_θ [ (1/|Dtr|) Σ Ltr(zⱼ, θ) + ε·Ltr(zᵢ, θ) ]
```

The influence is defined as the rate of change in validation metric Fval:
```
IFval(zᵢ, Dval) := [Fval(zᵢ, θ*_{ϵ,zᵢ}) - Fval(zᵢ, θ*)] / ε
```

**Step 2: Finite-difference approximation (avoids gradient through non-differentiable Fval)**
Since Fval is non-differentiable, use a one-step gradient descent perturbation:
```
θ*_{ϵ,zᵢ} ≈ θ* - ηε·∇θ Ltr(zᵢ, θ*)
```

This yields the practical estimator:
```
IFval(zᵢ, Dval, θ*) ≈ (1/ε)[Fval(zᵢ, θ* - ηε∇θLtr(zᵢ, θ*)) - Fval(zᵢ, θ*)]
```

Key efficiency: **Only one forward pass on the validation set is needed** per data point (inference), instead of gradient computation through the full model. For Llama-3-8B with S≈2000 tokens, this costs ~6N·S FLOPs vs. TRAK's ~6N·S·V FLOPs or LESS's ~6N·S·V·R FLOPs.

**Step 3: Combined scoring**
```
H(zᵢ) = IFval(zᵢ, Dval, θ) + γ · Q(s, a_high)
```
- γ=1: Combine influence + Q-value (better for Debate tasks)
- γ=0: Influence-only (better for Information Exchange tasks where F1 metric introduces noise in Q-values)

**Step 4: Data filtering and selection**
- Filter: keep pairs where `R(s, a_high) > λ_dpo-filter` and `R(s, a_high) - R(s, a_low) > λ_dpo-diff`
- Rank by H(zᵢ) and select top-α (α=0.5 used in experiments)
- Train with DPO loss on selected pairs

### Phase 3: Iterative Refinement (Algorithm 1)
```
For t = 1 to T:
  1. SFT data collection + fine-tuning from initial model
  2. MCTS synthesis to generate DPO candidate data
  3. Influence score collection on validation set Dval
  4. Influence-based data selection
  5. DPO training on selected data
Return final model θ_T
```

### Computational Cost Comparison (per data point, FLOPs × 10¹⁵):
| Method  | FLOPs Formula | Approx. Cost |
|---------|--------------|--------------|
| **DITS** | 6N·S + 2N·V·S | **0.7** |
| TRAK    | 6N·S·V + 2N·V·d + V·d³ | 4.6 |
| LESS    | 6N·S·V·R + 2N·V·d·R | 18 |

## 3. Trade-offs

| Win | Lose |
|-----|------|
| +2.5% avg performance vs. Q-value selection across 6/7 datasets | Influence estimation adds inference overhead per data point |
| 46% lower total GPU cost for equal/better performance | Requires held-out validation set (min V=20; larger V = better but costlier) |
| Influence scores capture training utility better than Q-values (Pearson r ≈ 0.1 between Q-value and influence) | Not suitable for real-time/streaming data selection (offline only) |
| γ=0 (influence-only) wins when Q-values are noisy (F1 metrics); γ=1 (combined) wins for stable metrics (Exact Match) | γ must be tuned per task type |
| Works across static AND dynamic multi-agent topologies | Not tested on open-ended collaboration (dynamic agent spawning, emergent teams) |
| Generalizes across base models (Llama-3.1-8B, Qwen2.5-7B) | Selection ratio α is a sensitive hyperparameter — too small = not enough data, too large = noise included |
| Iterative synthesis creates positive feedback loop (better model → better data → better model) | Iterative process may reduce data diversity (influence score distributions concentrate with more iterations) |
| Finite-difference estimation 6-25× cheaper than TRAK/LESS | Influence estimator depends on quality of gradient signal from training loss |

## 4. Design Rationale

**Why influence scores over Q-values?** MCTS Q-values are inherited from inference-phase tree search, where they estimate correctness. But the training objective is different: we want data that maximally improves model performance, not data that is "correct." The authors empirically show Q-values and influence scores have a Pearson correlation of only ~0.1, confirming the misalignment.

**Why finite-difference over gradient-based influence?** Classical influence functions (Koh & Liang, 2017) require twice-differentiable loss and gradient computation through the full model. DPO loss correlates weakly (<0.2) with downstream metrics (F1, accuracy), making loss-based influence meaningless. The finite-difference approach (Equation 13) replaces gradient-through-metric with inference-on-validation-set, reducing FLOPs by 6-25× vs. TRAK and LESS.

**Why iterative refinement?** The core hypothesis is a **flywheel**: better model → generates better synthetic data → trains even better model. Empirical results confirm this — 3 iterations of synthesis + training provide larger gains than 16× raw synthesis budget increase, showing that iterative quality improvement dominates brute-force data scaling.

**Why combine influence and Q-value?** When influence estimation is noisy (small V), Q-values serve as a regularizer. When influence estimation is clean (large V, stable metric), γ=0 wins by avoiding Q-value noise.

## 5. Limitations and Failure Modes

1. **No open-ended collaboration coverage**: DITS is evaluated on static topologies (Information Exchange, Debate) and one dynamic topology (DeepSearch). It does not handle dynamic agent spawning, emergent team formation, or environments where the agent graph structure itself changes during execution. These settings introduce substantially higher variance in agent interactions.

2. **Offline-only data selection**: The influence estimator requires multiple inference passes over the validation set per data point. Under strict latency constraints (streaming, real-time MAS), this overhead is unacceptable. The paper explicitly notes that lightweight single-pass approximations remain future work.

3. **Validation set dependency**: Influence estimation accuracy depends on validation set quality and size (V=20 used; performance improves with larger V up to V=100). In domains where validation data is scarce or expensive, DITS's advantage may diminish.

4. **Selection ratio sensitivity**: α=0.5 works well empirically, but performance degrades at extremes (α < 0.3 = too little data; α > 0.7 = noise inclusion). This hyperparameter requires per-task tuning.

5. **Diversity degradation in iterative training**: As the model improves through iterations, the influence score distribution concentrates (Figure 4b), suggesting reduced data diversity. This could lead to overfitting on narrow task patterns.

6. **Q-value estimation noise**: In the Information Exchange task (F1 metric), Q-values are noisier than in Debate (Exact Match), making γ-parameter selection task-dependent.

7. **Model scale limitation**: Only tested on 7B-8B models (SFT) and 32B (inference). Scaling behavior to larger models is unexplored.

## 6. Transfer to Lyra: Influence-Score-Guided Data Selection for Multi-Agent Self-Training

**The one transferable idea:** Replace Q-value-only data selection in Lyra's agent training pipeline with **influence-score-guided data selection**. Lyra can estimate each training sample's contribution to downstream task performance using DITS's finite-difference inference method (Equation 13), which requires only one extra inference pass per candidate data point — feasible within Lyra's existing evaluation infrastructure. This directly addresses a core problem: when Lyra agents engage in multi-turn interactions or multi-agent debate, not all generated training pairs equally improve system performance. DITS provides a principled, computationally tractable way to rank and filter these pairs.

**Workstream route:** §4.2 (Memory & Learning) — Lyra's agent training data curation and preference optimization pipeline. DITS's influence estimation could be integrated as a data quality gate between Lyra's trajectory collection and DPO/RL training steps.

**Impact:** 4 (high) — Directly improves training data quality with proven +2.5% gains; the finite-difference estimator is model-agnostic and compatible with Lyra's existing DPO infrastructure.
**Effort:** 4 (substantial) — Requires implementing the influence estimator (inference on validation set), integrating it into Lyra's data pipeline, and setting up iterative synthesis loops. Validation set curation adds ongoing maintenance cost.
**Tier:** **Breakthrough** — The conceptual shift from "select data by correctness" to "select data by training utility" is well-motivated and empirically validated. The finite-difference approach makes influence estimation practical for Lyra-scale models, and the iterative refinement flywheel aligns with Lyra's architecture as a continuously improving system.
