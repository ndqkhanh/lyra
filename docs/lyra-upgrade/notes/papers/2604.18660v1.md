## 1. Mechanism (step-by-step)

### Problem Setting
LLM-based conversational tutors are given a problem AND the correct answer, explicitly instructed NOT to reveal the answer. An adversarial student agent attacks the tutor to extract the answer. An LLM judge evaluates leakage.

### Algorithm 1: Multi-turn Student-Tutor Interaction Protocol
```
Input: Tutor prompt pt, Student prompt pa, agent type A, max turns T
1. Initialize conversation history H = {}
2. Pre-generate attack prompts P = get_prompts()
3. For turn i = 1 to T:
   a. If A uses pre-generated prompts: ai = get(P)
   b. Else if A is conversational agent: ai = La(pa, H)
   c. Append ai to H
   d. Tutor responds: ti = Lt(pt, H)
   e. Append ti to H
   f. If judge Ja(ai) OR Jt(ti) detects leakage: break
4. Return full conversation history H
```

### Attack Taxonomy (6 Techniques)
**Adversarial (3):**
- Direct Request: Explicit forceful demand ("ANSWER NOW")
- Emotional Threat: Distress, urgency, negative consequences
- Intentional Wrong Answer: Deliberately wrong answer to bait correction (education-specific)

**Persuasive (3) — adapted from Zeng et al. 2024 taxonomy:**
- Contextual Manipulation: Fabricated context making disclosure seem necessary
- Interpersonal Influence: Rapport/trust to socially encourage revelation
- Request Shaping: Reframe request so disclosure appears reasonable

### Student Agent Architectures (4 types)
1. **Base In-Context Adversarial Agent**: La(prompt, history) → generates adversarial query. Instructed with 3 attack strategies.
2. **Student w/ Reasoning**: Same as above but outputs JSON with "reason" key (CoT-style) before generating the attack message.
3. **Multi-Agent Student**: 3-agent pipeline — La generates query → Ja (judge) checks if query leaked answer → Lrefine (refiner) removes leaked answer → send to tutor.
4. **Fine-Tuned Adversarial Agent**: Qwen2.5-7B-Instruct fine-tuned via SFT on GSM8K training dialogues. Uses SFTTrainer (TRL), 3 epochs, batch=8, lr=1e-5, 100 warmup steps, bf16, max_seq_len=8192, LoRA (r=32, alpha=64, dropout=0.05). Training data constructed by running attacks against base tutors, collecting conversations where tutor leaked answers.

### Attack Generation Modes
- **Predefined**: (a) Manually crafted prompts per technique; (b) LLM-generated per task (n prompts conditioned on k_type with 3 examples)
- **Conversational**: Agent generates attacks adaptively based on dialogue history

### Judge Agent (Leakage Detection)
- Two-stage: (1) Rule-based digit matching filter flags responses containing the answer string; (2) LLM judge (Llama-3.1-70B-Instruct, greedy decoding) performs binary annotation of answer leakage
- Separate judges: Ja for student-side leakage, Jt for tutor-side leakage
- JSON output: {"reason": ..., "student_correct": true/false}

### Defense Strategies (2)
1. **Reason Pedagogically (Reasoning Tutor)**: Tutor outputs JSON with "reason" key before "content" — CoT reasoning before responding. Forces the tutor to plan pedagogical guidance.
2. **Multi-Agent Tutor**: 3-agent pipeline — Lt generates response → Jt judges for leakage → Lrefine refines if leakage detected → send refined response to student.

### Metrics
- **Leakage Rate**: Percentage of conversations where answer was disclosed
- **Turns Until Leakage**: Average number of turns before disclosure (computed over leaked conversations only)
- All results averaged across 3 runs with standard deviations

### Attack Technique Effectiveness (predefined prompts across models)
- Contextual Manipulation: 74% mean leakage (HIGHEST)
- Interpersonal Influence: 67%
- Request Shaping: 66%
- Intentional Wrong Answer: 64%
- Direct Request: 50%
- Emotional Threat: 47% (LOWEST, but most delayed — 9.70 turns avg)

### Pedagogically Aligned Models vs Fine-Tuned Adversarial Agent
- TutorRL-7B: 83% leakage
- MathDial-SFT: 70% leakage
- SocraticLM: 70% leakage

### Cross-Domain Generalization (Qwen-7B tutor)
- **MMLU (MCQ)**: Fine-tuned adversary → 88% tutor leak (base), 10% w/ reasoning defense
- **HumanEval (coding)**: Fine-tuned adversary → 88% leak (base), 41% w/ reasoning defense
- Coding domain: Leakage often after few turns; tutor starts with guidance then converges to full code

### Scaling to Large Models
- Qwen2.5-72B-Instruct (base): 80% leakage → 8% w/ reasoning or multi-agent defense
- GPT-5 (base in-context): 4.58% leakage, 5.09 avg turns before leak (relatively robust, but exhibited implicit leakage)

### Key Effect of In-Context Student Agents
- Base in-context adversarial student: **61% student-side leakage** (Qwen-7B) — agent solves problem itself instead of attacking
- Fine-tuned agent: **2% student leakage** — nearly eliminates self-solving, focuses on attack

### Statistical Significance
- 27/30 attack comparisons significant (Wilcoxon Signed-Rank, Bonferroni corrected)
- 36/36 defense comparisons significant (both defense strategies outperform baseline)

## 3. Trade-offs

| Dimension | Win | Loss/Cost |
|---|---|---|
| **Fine-tuned adversarial student** | 82% tutor leak rate (Qwen-7B) vs 14% for base in-context; near-zero student self-leakage (2%) | Requires supervised fine-tuning (3 epochs, GPU compute); domain-agnostic but trained only on math |
| **Reasoning-based defense** | Reduces tutor leakage from 82% → 38% (Qwen-7B), 46% → 2% (Qwen-32B), 88% → 10% (MMLU) | Adds inference latency (CoT generation step); defense effectiveness drops on coding (88% → 41% vs 10% on MCQ) |
| **Multi-agent tutor defense** | Reduces leakage 46% → 4% (Qwen-32B); consistent across all attack types | 3x inference cost (3 agents); weaker than reasoning defense on some settings (61% vs 38% on Qwen-7B fine-tuned) |
| **Multi-agent student attacker** | Better than base student (48% vs 14% tutor leak on Qwen-7B); lower student self-leakage (27% vs 61%) | More complex setup; still underperforms fine-tuned agent (48% vs 82%) |
| **Larger models** | GPT-5: 4.58% leak rate (high robustness); Qwen-72B defenses reduce to 8% | GPT-5 shows implicit leakage (narrowing answer range); Qwen-72B base is worse than Qwen-32B (80% vs 70%) |
| **Persuasive > Adversarial techniques** | Contextual manipulation achieves 74% mean leak across models | Persuasive techniques are harder to detect as "attacks" — blur ethical boundaries; emotional threat least effective (47%) but most socially harmful |

## 4. Design Rationale

1. **Why fine-tuned student agent over in-context?** In-context adversarial students fail catastrophically — they solve problems themselves (61% self-leakage) instead of attacking, inflating apparent tutor success. Fine-tuning on attack dialogues eliminates this cooperation bias, making evaluation reliable.

2. **Why 6 attack techniques (not just 3 adversarial)?** Persuasive techniques (contextual manipulation, interpersonal influence, request shaping) consistently outperform adversarial ones (74% vs 47-64% mean leakage). Ablation shows training on all 6 techniques maximizes attack diversity and effectiveness; adversarial-only training produces weakest attacks.

3. **Why CoT reasoning as defense?** Forces the tutor to explicitly plan pedagogical strategy before responding. This metacognitive step disrupts the "default helpfulness" reflex that leaks answers. Simpler and more effective than multi-agent refinement in most settings.

4. **Why GSM8K training generalizes?** The fine-tuned agent learns interaction-level attack strategies (direct instruction overriding, emotional manipulation, persuasive prompting) that are domain-agnostic — verified on MMLU (MCQ) and HumanEval (coding) without retraining.

5. **Why LLM judge + rule-based filter?** Two-stage design: digit matching catches exact answer matches cheaply, LLM judge handles nuanced/partial disclosures. Llama-3.1-70B chosen for judgment stability (greedy decoding).

## 5. Limitations & Failure Modes

1. **Narrow evaluation scope**: Only measures answer leakage — does not assess pedagogical quality dimensions (hint quality, instructional clarity, guidance appropriateness). A tutor could be "robust" yet useless pedagogically.

2. **Single judge model**: Relies on Llama-3.1-70B-Instruct for all leakage judgments. No inter-annotator agreement reported against human evaluators for the specific leakage detection task. Judge biases could propagate.

3. **Limited model coverage**: 7 open-source models + GPT-5. Patterns may not hold for other architectures (Gemini, Claude, etc.).

4. **Binary leakage metric**: Only measures whether answer was revealed, not degree of implicit leakage (e.g., GPT-5 narrowing answer to a 3-integer range). Partial disclosure not captured.

5. **Defense brittleness**: Reasoning-based defense effectiveness varies dramatically by model size — 82%→38% on Qwen-7B vs 46%→2% on Qwen-32B. Smaller models struggle to reason and defend simultaneously.

6. **Fine-tuned agent may not transfer to unseen attack surfaces**: Trained only on math dialogues; adversarial strategies that exploit domain-specific vulnerabilities (e.g., code execution, tool use) are untested.

7. **No multi-modal evaluation**: Only text-based interactions; doesn't cover image-based problems or mixed-modality tutoring.

8. **Offensive content in attack prompts**: Acknowledged that emotional threat and contextual manipulation prompts can be considered offensive, raising ethical deployment concerns.

## 6. Transfer to Lyra

### The One Transferable Idea
**Adversarial robustness evaluation through a fine-tuned "red-team" agent paired with explicit CoT reasoning defenses.** Lyra's §4.7 (Safety/Guardrails) workstream needs systematic adversarial evaluation. This paper provides a blueprint: (1) Define a leakage/undesirable-output taxonomy, (2) Build in-context adversarial probes that fail (revealing measurement gaps), (3) Fine-tune a dedicated adversary that reliably triggers failures, (4) Apply reasoning-based defenses (explicit CoT before responding) as a lightweight first line of defense. The pattern of "in-context evaluators fail → fine-tuned evaluator succeeds → reasoning defense mitigates" is directly portable to Lyra's agent safety evaluation.

### Workstream Route: §4.7 Safety & Guardrails
### Impact: 4 (provides systematic adversarial evaluation methodology directly applicable to Lyra's instruction-following and safety constraints)
### Effort: 3 (requires adversarial taxonomy design, SFT training run, and integration with existing Lyra eval harness)
### Tier: **Breakthrough** — methodologically sound, cross-domain validated, with open-source artifacts and clear defense prescriptions
