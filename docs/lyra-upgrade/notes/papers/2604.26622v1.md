## 1. Mechanism (step-by-step)

### Core Idea
OCR-Memory shifts agent memory storage from the text domain to the **image domain**, leveraging the visual modality as a high-density, lossless compression medium. A 3B DeepSeek-OCR vision model serves as a specialized optical retriever, separate from the primary reasoning agent.

### Step-by-Step Pipeline

**Step 1 — Trajectory Rendering & Visual Marking.**
After each interaction episode `e`, the agent trajectory `τ^(e) = {x_1, ..., x_Te}` is chunked into segments. Each chunk is rendered as a high-resolution image `I_i^hi` (1024×1024) with **Set-of-Mark (SoM)** annotations: every text segment `s_{i,k}` receives a red bounding box (RGB: 255, 0, 0, 3px width) with a unique numerical index `k ∈ [1, K_i]` rendered as 36pt bold white-on-red Arial text. The memory bank stores:

```
m_i = (I_i, {s_{i,k}}_{k=1}^{K_i}, π_i)
```

where `I_i` is the marked image, `{s_{i,k}}` are the verbatim text segments in a deterministic log, and `π_i` is metadata (timestamp, episode ID).

**Step 2 — Multi-Resolution Aging (Optical Forgetting).**
Memory items degrade in resolution over time based on age `Δt_i`. A two-tier policy is implemented:

```
ℓ_i = ρ(Δt_i),   I_i = ϕ_ℓ(I_i^hi)
```

- **Tier 1 (high-res):** 1024×1024 input → 256 compressed visual tokens — for the 5 most recent interaction steps
- **Tier 2 (low-res):** 512×512 input → 64 compressed visual tokens — for all older history

The DeepSeek-OCR encoder `f_enc` maps each image to compressed embeddings `Z ∈ R^{n(r)×d_latent}` where `n(r) ∈ {64, 100, 256, 400}` depending on input resolution. This achieves ~10× compression ratio of visual tokens relative to raw text tokens.

**Step 3 — Locate-and-Transcribe Retrieval.**
When a new query `q` arrives, the optical retriever `g_θ` scans all `N` memory images and outputs a **binary relevance vector** for each image `i`:

```
ŷ_i(q) = [ŷ_{i,1}, ..., ŷ_{i,K_i}] ∈ {0, 1}^{K_i}
```

Format tokens are constrained to only "0" or "1". The selected global index set is:

```
Ŝ(q) = {(i, k) | ŷ_{i,k} = 1},   1 ≤ i ≤ N, 1 ≤ k ≤ K_i
```

Crucially, the model performs **index selection only** — it does not generate free-form text, eliminating the primary source of hallucination in visual retrieval.

**Step 4 — Calibrated Scoring & Recall-Oriented Selection.**
Rather than using greedy binary outputs, calibrated probabilities are derived from logits:

```
p_{i,k}(q) = exp(z_{i,k}(1)) / (exp(z_{i,k}(1)) + exp(z_{i,k}(0)))
```

A hybrid selection rule ensures coverage:
- **Threshold:** Any segment with `p_{i,k} ≥ τ = 0.4` is retrieved
- **Top-K fallback:** If no segments exceed τ, the Top-5 highest-scoring segments per image are retrieved
- **Global cap:** Maximum 20 text segments per query, prioritized by `p_{i,k}`

```
Ŝ_i(q) = {(i, k) | p_{i,k} ≥ τ} ∪ TopK({p_{i,k}}_{k=1}^{K_i}, K=5)
```

**Step 5 — Deterministic Text Fetching.**
Selected indices are used to fetch the exact verbatim text from stored logs:

```
E = Fetch(Ŝ(q), M) = ⊕_{(i,k)∈Ŝ(q)} s_{i,k}
```

This guarantees **100% evidence faithfulness** — the recovered text is byte-identical to the original stored content, though relevance depends on the quality of index selection.

**Step 6 — Active Recall Up-Sampling.**
When a low-resolution memory item is retrieved (i.e., `∃(i,k) ∈ Ŝ(q) s.t. ℓ_i > ℓ_min`), the image is **re-rendered at high resolution** from the original logs:

```
I_i ← I_i^hi
```

The restored item is exempted from aging decay for the remainder of the episode. This ensures critical memories are available in full fidelity for all subsequent interactions.

### Training Strategy

**Dataset:** Repurposed HotpotQA — each instance has a query `q`, K=10 paragraphs `{p_k}`, and supporting fact indices `F_supp`. Paragraphs are rendered as marked images with SoM identifiers.

**Target:** Binary vector `y = [y_1, ..., y_K]` where `y_k = I[k ∈ F_supp]`.

**Loss:** Weighted Binary Cross-Entropy (teacher forcing):

```
L_BCE(θ) = -Σ_{n=1}^{|D|} Σ_{k=1}^{K} [w_+ · y_k^(n) · log(p_k^(n)) + w_- · (1 - y_k^(n)) · log(1 - p_k^(n))]
```

with `w_+ = 2.0, w_- = 1.0` (penalizes false negatives more heavily).

**Partial Freezing:** Vision encoder `θ_vis` is frozen. Language decoder `θ_dec` fine-tuned via LoRA (r=16, α=32, dropout=0.05) on projection layers (q_proj, k_proj, v_proj, o_proj).

**Resolution Curriculum:** For each training instance, randomly sample a resolution tier `ℓ ~ Categorical([0.3, 0.7])` over {1024×1024, 512×512}, forcing the retriever to work with degraded visual quality during training.

**Optimizer:** AdamW (β₁=0.9, β₂=0.95, weight_decay=0.1), gradient clipping max norm 1.0, cosine LR schedule with peak lr=1e-5, 10% warmup, batch size 128, 3 epochs.

## 3. Trade-offs

| Dimension | Win | Cost |
|---|---|---|
| **Reasoning token budget** | 6.7× reduction (596 vs 3,980 tokens/step) — the scarcest resource | — |
| **Disk storage** | — | 81× increase (1.47 MB vs 18 KB per episode) |
| **Retrieval latency** | — | 5.7× slower (1.7s vs 0.3s per step) |
| **Evidence faithfulness** | 100% (deterministic fetch eliminates hallucination) | — |
| **Retrieval recall** | Recall@10=96.2% vs 82.1% for text RAG | — |
| **Context scalability** | 94.1% Recall@1 at 32k context | — |
| **Training overhead** | — | Requires fine-tuning 3B vision model on HotpotQA (3 epochs) |
| **Memory footprint** | — | Vision encoder parameters must be loaded alongside primary agent |
| **Rendering cost** | — | Image rendering is computationally more expensive than text storage |
| **Low-res degradation** | Adaptive up-scaling recovers fidelity | Static low-res loses 6.4 pp Step SR (39.7% vs 46.1%) |

**Net assessment:** OCR-Memory deliberately shifts cost from the scarce resource (LLM context tokens) toward cheaper resources (disk, preprocessing latency, GPU memory). It is not universally cheaper — it is an architectural trade that pays off when context windows are the binding constraint.

## 4. Design Rationale

**Why visual modality over text compression?** Existing text-centric approaches (summarization, compression, retrieval) face an inherent tension between compression ratio and information fidelity — you either lose details or exceed context budgets. Visual encoding (DeepSeek-OCR) achieves ~10× compression while preserving complete spatial and structural information, sidestepping this trade-off entirely.

**Why index selection over free-form generation?** Visual models hallucinate when forced to read and reproduce text from images, especially at low resolution. The SoM-based index selection transforms retrieval from a generation problem into a classification problem — the model only predicts which segments are relevant, not what they contain. This decoupling of "where" from "what" eliminates hallucination at the evidence recovery stage (100% faithfulness).

**Why multi-resolution aging?** Directly inspired by human memory (vivid recent memories, fading older ones). Low-resolution thumbnails preserve semantic gist sufficient for retrieval decisions, while active up-scaling ensures that once a memory is deemed relevant, it is restored to full fidelity. This achieves the token efficiency of compression without permanently sacrificing detail quality.

**Why separate optical retriever?** Separation of concerns: the optical model handles "what to look at" (retrieval), the primary agent handles "what to do" (reasoning). This allows each component to be optimized independently and prevents the retrieval mechanism from competing for the reasoning agent's context budget.

## 5. Limitations & Failure Modes

1. **Training dependency:** Unlike training-free RAG baselines, OCR-Memory requires fine-tuning a specialized 3B optical retrieval model — adds pipeline complexity and resource overhead.

2. **Rendering computational cost:** Converting interaction logs to marked images is more expensive than direct text storage, and the cost scales with trajectory length.

3. **Disk storage blowup:** 81× more disk per episode (1.47 MB vs 18 KB) — becomes significant for high-throughput agent deployments.

4. **Retrieval latency penalty:** 5.7× slower than text RAG (1.7s vs 0.3s) — may be a bottleneck for latency-sensitive applications requiring sub-second retrieval.

5. **Vision encoder memory footprint:** The DeepSeek-OCR (3B) vision encoder must be loaded alongside the primary reasoning LLM, doubling or significantly increasing GPU memory requirements.

6. **Resolution sensitivity:** Static low-resolution setting loses 6.4 pp Step SR — performance degrades if the dynamic up-scaling mechanism fails to trigger or if base resolution is too low for the domain.

7. **False negatives in index selection:** Despite recall-oriented scoring (τ=0.4 + Top-K=5), the retriever can still miss relevant segments, especially if the visual layout is atypical or text is densely packed.

8. **GPT-4 dependency in evaluation:** Primary experiments use GPT-4 as the reasoning backbone, incurring high API costs. Gains are preserved with Qwen3-32B but absolute numbers drop.

9. **Domain coverage:** Evaluated only on web navigation (Mind2Web) and API interaction (AppWorld) — generalizability to conversational, coding, or embodied agent domains is unproven.

10. **Scaling unverified:** Only tested with DeepSeek-OCR 3B. Behavior with other vision backbones (larger models, different architectures) is unknown.

## 6. Transfer to Lyra

### The One Transferable Idea

**Visual-density memory with index-based deterministic retrieval.** Lyra can encode its long-horizon interaction histories (tool calls, reasoning chains, error traces, user turns) as visually rendered frames with unique segment markers. Instead of using lossy text summarization or fragile semantic similarity for memory lookup, Lyra would use an optical retriever to select relevant "frame segments" by index, then deterministically fetch the exact verbatim text from a reliable log store. This eliminates retrieval hallucination (a known failure mode in Lyra's current memory pipeline) and enables ~6-10× denser packing of historical context within Lyra's constrained context window.

### Workstream Route: §4.2 (Memory Subsystem)

This paper directly addresses Lyra's memory workstream — specifically the trade-off between memory richness and context budget. The visual encoding approach offers a novel architectural alternative to Lyra's existing summarization + text-RAG memory stack.

### Impact Assessment

| Criterion | Score | Rationale |
|---|---|---|
| Impact | 4 | Novel paradigm shift (text→visual memory) with strong empirical gains; 6.7× token savings is transformative for context-constrained agents |
| Effort | 4 | Requires integrating a 3B vision model, building SoM rendering pipeline, fine-tuning on agent trajectories, and refactoring memory retrieval API |
| Tier | **breakthrough** | Not an incremental improvement — represents a fundamentally different approach to agent memory that could define Lyra's competitive differentiation |

### Required Adaptations for Lyra
1. Replace DeepSeek-OCR with a smaller/faster vision encoder (or use multimodal LLM already in Lyra's stack)
2. Build a trajectory-to-SoM-image rendering component
3. Train/fine-tune the optical retriever on Lyra-specific interaction patterns (not just HotpotQA)
4. Integrate the locate-and-transcribe pipeline into Lyra's existing memory manager
5. Add multi-resolution aging with active-recall up-scaling for Lyra's session histories
