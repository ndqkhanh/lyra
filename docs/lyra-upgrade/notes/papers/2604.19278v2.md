## 1. Mechanism (step-by-step)

ETI is a prompt-based, psychology-grounded framework that scaffolds LLM agents with structured representations of their partners' stable behavioral traits. It does NOT require fine-tuning, extra training data, or model modification.

### 1.1 Trait Framework

ETI instantiates the **warmth–competence** model from social psychology (Fiske et al., 2007) through 8 behaviorally-anchored traits:

**Warmth (intent-oriented):**
- Goal Alignment: whether the agent works toward shared objectives
- Collaboration: efforts to coordinate, share relevant information
- Trustworthiness: honesty, commitment-keeping, avoiding deception
- Maliciousness: intentional sabotage beyond self-interest (harming others at self-cost)

**Competence (ability-oriented):**
- Execution Ability: successful execution of chosen actions, regardless of optimality
- Reliability: consistency in performance quality and strategy
- Adaptability: adjusting approach in response to failures or environment changes
- Efficiency: achieving quality outcomes with minimal attempts/effort/wasted resources

Key design choice: warmth and competence are **explicitly decoupled** in definitions (e.g., Ability is "successful execution" independent of intent). This prevents the colloquial conflation of "uncooperative = incompetent."

### 1.2 Inference Procedure (per iteration)

```
Algorithm: ETI Iteration Loop

Input: Agent A, Partners P = {P1,...,Pn}, Task Context T, History H
Output: Action plan + updated trait profiles

1. After each interaction round:
   a. Collect task history: own actions, partner actions, outcomes, communication logs
   b. For each partner Pi in P:
      - Prompt LLM with: scenario description + interaction history + 8 trait definitions
      - LLM produces structured JSON: {trait_name: {rating: 1-7, evidence: "2-3 sentences"}}
      - Rating scale: 1 = "does not apply at all", 7 = "applies completely"
   c. Append profiles to agent context

2. At decision time (plan/act/communicate):
   a. Inject preamble: "Here is some information about your collaborators"
   b. Inject most recent trait profiles for all partners
   c. Inject instruction: "Use this information to make better decisions,
      coordinate better, and improve overall outcomes"
   d. Agent generates next action conditioned on trait profiles

3. Profile maintenance strategies:
   a. Continuous: update every round (default, most adaptive)
   b. Pre-calibrated: infer from N warm-up rounds, then freeze (comparable perf, lower cost)
   c. Cross-task: transfer profiles from one task to another (works for competence,
      asymmetric for cooperation)
```

### 1.3 How Traits Drive Coordination

- **Low warmth** -> agent clarifies intentions, supplies missing information, discounts unreliable input, guards against suspicious partners
- **Low competence** -> agent reassigns tasks, adjusts task decomposition, increases verification/oversight
- **High warmth + low competence** -> agent provides scaffolded support, simpler tasks, more frequent check-ins
- **Low warmth + high competence** -> agent monitors for adversarial exploitation, verifies outputs despite apparent quality

### 1.4 Integration Schema

The inference prompt follows this structure:
```
System: You are an expert at inferring stable traits from interactions.
Inputs:
  {scenario_description}
  {interaction_history}
  {trait_definitions}
Task:
  - Analyze the interaction history
  - Identify stable behavioral patterns (not isolated events)
  - Assign ratings (1-7 or N/A) for each trait
  - Provide 2-3 sentence evidence per trait
Output: {json_template}
```

The injection prompt appends:
```
Trait Profiles:
  {partner_id_1}: {trait_profile_1}
  {partner_id_2}: {trait_profile_2}
Use this information to make better decisions, coordinate better,
and improve overall outcomes.
```

No additional model calls are needed beyond the trait inference step — profiles are generated once per iteration per partner and appended to the agent's context window for subsequent actions.

## 3. Trade-offs

| Win | Lose |
|-----|------|
| 3-29% coordination improvement across all scenarios | ~2x token increase in communication-heavy settings |
| 45-77% payoff loss reduction in controlled games | Inertia after abrupt partner behavioral shifts (profiles emphasize stable patterns, slow to update) |
| Robust under noise (baseline collapses to F1=0.02, ETI maintains F1=0.49) | Model-dependent: GPT's positivity bias (ratings cluster 4-6) produces less informative profiles than QWEN's high-variance ratings |
| Profiles transfer across tasks (cross-task competence F1=0.97) | Adversaries can deliberately project false traits (werewolves exploit trust in Werewolf) |
| No fine-tuning needed (prompt-only, plug-and-play) | Accumulating profiles consume context window (mitigated by caching/pre-calibration) |
| Pre-calibration removes need for continuous updates (comparable performance, lower cost) | Cross-model quality varies: QWEN-generated profiles benefit GPT agents, but GPT-generated profiles degrade QWEN agents |
| Warmth-competence separation prevents trait conflation (uncooperative ≠ incompetent) | Static 8-trait schema may miss task-specific behavioral dimensions |
| Works across collaborative AND competitive settings | Gains attenuated at performance ceiling (o3: 99% WR, only coordination metrics improve) |
| Lightweight diagnostic for model biases before deployment | Social biases in LLMs could reflect/amplify stereotypical trait attributions in real-world deployments |

## 4. Design Rationale

**Why warmth-competence framework?** Decades of human psychology research (Fiske et al., 2007; Cuddy et al., 2008) show these are universal dimensions of social evaluation. Humans naturally use these to decide whom to trust, allocate tasks to, and anticipate behavior. The framework maps cleanly onto MAS failures: warmth addresses goal drift/unreliable cooperation, competence addresses execution errors/cascading failures.

**Why explicit structured profiles vs implicit reasoning?** Baselines already include CoT reasoning about partners (e.g., analyzing past actions in Werewolf). Yet ETI adds substantial gains on top, proving that structured, persistent trait representations provide information that general reasoning about interaction histories does not. The JSON format creates stable, queryable profiles rather than ephemeral reasoning traces.

**Why 8 traits instead of 2 dimensions directly?** Operationalizing warmth/competence through concrete behavioral anchors prevents the colloquial conflation of trait judgments (e.g., "they failed, so they must be uncooperative"). Each trait has a clear, observable behavioral definition independent of others.

**Why prompt-based instead of fine-tuning?** Keeps ETI lightweight, model-agnostic, and immediately deployable. Does not require training data or infrastructure beyond what any LLM API provides. The paper explicitly notes that fine-tuning in multi-agent environments with partner-aware objectives is a promising future direction.

**Why stable/dominant pattern emphasis?** Deliberate design choice: by focusing on dominant patterns rather than isolated events, ETI avoids overreacting to noise. This conservatism is a feature under ambiguity (proven by noisy-condition results) but becomes a limitation under abrupt genuine shifts.

## 5. Limitations & Failure Modes

1. **Model scope constraint**: Only tested on GPT-4o-mini and QWEN3-8B (small general-purpose models). Larger models, fine-tuned models, or heterogeneous model mixtures may behave differently. o3 preliminary tests showed attenuated gains.

2. **Model bias inheritance**: ETI inherits LLM idiosyncrasies. GPT showed sycophancy and positivity bias (ratings clustered mildly positive, never low) producing generic profiles that degrade QWEN agent performance. Model-specific calibration or tuned prompting may be required per deployment.

3. **Adaptability inertia**: Emphasizing stable patterns causes under-weighting of recent evidence after abrupt partner behavior shifts. Post-shift competence F1 dropped (PD: 0.43 vs no-shift 0.89; SH: 0.59 vs no-shift 0.86). Mitigation: recency weighting, sliding context windows, explicit change prompts.

4. **Adversarial vulnerability**: Werewolves in social deduction deliberately project false traits (high trust, low maliciousness) to avoid detection. The severity is context-dependent but represents a fundamental limitation of any partner-modeling approach.

5. **Stereotype amplification risk**: In real-world deployments with demographic/social cues, trait inference could reinforce stereotypes or unfair expectations. No investigation of bias safeguards was conducted.

6. **Scalability concerns**: While prompt-based inference is lightweight per-agent, the combination of profile accumulation across many agents and many rounds could strain context windows. Pre-calibration and cross-task caching mitigate this partially.

7. **Context-dependent trait semantics**: The 8-trait schema is fixed and domain-general, but task-specific behavioral patterns (e.g., "code review thoroughness," "API design quality") may require domain-specific trait definitions for maximum informativeness.

8. **No grounding in real human teams**: All evaluations are with LLM agents or scripted opponents. Whether ETI profiles align with how humans would actually rate agent behavior is untested.

## 6. Transfer to Lyra

### The ONE Transferable Idea

**Structured, persistent partner-trait profiles as a coordination primitive for Lyra's multi-agent fleet.** When Lyra's supervisor daemon or orchestrator agent spawns worker agents, each worker should maintain (and the supervisor should compile) structured warmth-competence profiles of every other agent it interacts with. These profiles inform task routing (skip low-competence agents), verification strategy (intensify review of low-reliability agents), communication targeting (engage high-collaboration agents), and adversarial detection (flag agents with rising maliciousness or falling trustworthiness).

### Workstream Route

**§4.13 Fleet/Swarm Orchestration** — ETI profiles become a capability service consumed by the supervisor daemon and workflow engine. Specifically, the `AgentContext` struct in the orchestration plane should include a `PartnerProfiles` map that persists across sessions (leveraging Lyra's memory consolidation for cross-task trait transfer). The workflow engine's task assignment logic should consult competence profiles; the supervisor's health monitoring should track warmth degradation as an early signal of goal drift.

### Impact/Effort/Tier

- **Impact:** 4 — Directly improves multi-agent coordination with minimal implementation cost. Addresses documented MAS failures (goal drift, error cascades, misaligned behaviors) that Lyra's fleet architecture is vulnerable to.
- **Effort:** 2 — Prompt-only implementation. Requires: (a) trait inference prompt template (~50 LOC), (b) profile injection in agent context (~50 LOC), (c) profile storage/retrieval in memory subsystem (~100 LOC). No model training, no new infrastructure. Can be tested with Lyra's existing agent harness.
- **Tier:** **breakthrough** — Psychology-grounded, structured, persistent partner models are under-explored in harness engineering. ETI provides the first systematic evidence that this approach works across collaborative and competitive settings. Integrating it into Lyra's fleet orchestration would make Lyra one of the first harnesses with explicit social cognition capabilities.
