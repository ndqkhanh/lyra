## 1. Mechanism (Step-by-Step)

### High-Level Architecture

MASS-RAG decomposes RAG into three sequential stages: **evidence distillation** → **candidate answer generation (optional)** → **final answer synthesis**. It instantiates 3-5 role-specialized LLM agents, each receiving the same query `q_i` and retrieved document set `D`.

### Stage 1: Multi-Perspective Evidence Distillation (3 Filter Agents)

Three filter agents process the same retrieved documents from complementary perspectives, producing structured intermediate representations:

**(a) Summarizer Agent** — Abstractive compression
```
R_i^(s) = A_sum(q_i, D)
```
Condenses retrieved documents into a concise, abstractive summary that preserves semantic consistency while highlighting salient, query-relevant information. Does not attempt to answer the query directly. Handles cases where evidence is fragmented across documents.

**(b) Extractor Agent** — Verbatim span extraction
```
R_i^(e) = A_ext(q_i, D)
```
Identifies fine-grained factual spans or sentences that explicitly support the answer, copying evidence verbatim from retrieved documents without paraphrasing. Inspired by extractive QA (Chen et al. 2017, Lewis et al. 2021). Most effective when answers can be directly grounded in explicit text.

**(c) Reasoner Agent** — Cross-document inference
```
R_i^(r) = A_rea(q_i, D)
```
Performs reasoning over retrieved content to infer implicit connections or cross-document evidence not explicitly stated in any single sentence. Articulates how evidence supports the query and the inference steps required. Produces an explicit intermediate evidence representation decoupled from the final answer.

### Stage 2: Candidate Answer Generation (Optional Answer Agent)

When enabled, the Answer Agent independently generates candidate answers from each filtered response:
```
A_i^(j) = A_ans(q_i, R_i^(j)),   j ∈ {s, e, r}
```
This forces the model to commit to a concrete answer under each evidence view. Enabled for factoid QA (TriviaQA, PopQA), disabled for multiple-choice (ARC-Challenge) and long-form QA (ASQA) where early commitment reduces integration flexibility.

### Stage 3: Synthesis

Two variants depending on whether the Answer Agent is active:

**With Answer Agent** (factoid QA):
```
Ŷ_i = A_syn(q_i, {A_i^(s), A_i^(e), A_i^(r)})
```
Integrates intermediate answer hypotheses; explicitly compares and reconciles structured answer representations from heterogeneous evidence views.

**Without Answer Agent** (multiple-choice, long-form QA):
```
Ŷ_i = A_syn(q_i, {R_i^(s), R_i^(e), R_i^(r)})
```
Directly synthesizes from filtered evidence responses.

### Evaluation Metric: Evidence Coverage Rate (ECR)

```
ECR(A_F) = (1/|Q|) Σ_{q∈Q} 1[A_F(q) relevant]
```
Proportion of questions for which a filter agent's response contains ground-truth evidence. Inspired by Answer Inclusion Rate (AIR) from Ruan et al. (2024).

### Uniquely Attributable Subset Construction

To quantify complementarity, the authors identify questions whose ground-truth evidence is captured by exactly one filter agent. This isolates each agent's unique contribution. For Llama3-8B: 609 (TriviaQA) / 108 (PopQA) samples; for Mistral-7B: 559 (TriviaQA) / 85 (PopQA) samples.

## 4. Design Rationale

**Why multi-agent filtering over single-agent?** Prior multi-agent RAG (MAIN-RAG, Chang et al. 2024) uses a single judge agent operating from a monolithic perspective, which limits the system's ability to capture complementary or heterogeneous forms of evidence. MASS-RAG's three-filter design intentionally creates distinct evidence views (abstractive, extractive, inferential) that cover non-overlapping subsets of questions — the Uniquely Attributable Subset analysis proves each agent captures evidence the others miss.

**Why training-free?** Fine-tuning RAG models (Self-RAG, Llama2-FT) is computationally expensive and limits scalability. MASS-RAG achieves better results without any gradient updates by structuring the inference process itself.

**Why separate evidence distillation from synthesis?** Decoupling evidence processing from answer generation allows explicit comparison across heterogeneous evidence views. The model can identify which evidence view is most reliable for a given query rather than conflating retrieval and reasoning in a single pass.

**Why optional Answer Agent?** The Answer Agent is task-dependent by design: it helps when answer hypotheses carry rich semantic content (factoid QA) but hurts when answers are symbolic labels (multiple-choice) or require flexible integration of diverse facts (long-form QA). This architectural toggle is a deliberate flexibility mechanism.

## 5. Limitations and Failure Modes

1. **Synthesis bottleneck:** Individual filter agents often achieve higher accuracy than the synthesis output (e.g., Summarizer 73.7% vs Synthesis 76.7% on TriviaQA-Llama3 — actually synthesis scores higher here, but in other cases not). The synthesis stage does not always resolve conflicting evidence correctly, and weaker backbone models (Mistral) show a wider gap between filter coverage and final answer accuracy.

2. **4-7× inference cost:** Each query requires 3 filter calls + 3 optional answer calls + 1 synthesis call = 4-7 sequential LLM invocations. This makes real-time applications infeasible without optimization.

3. **Fixed retrieval pipeline:** Uses Contriever-MS-MARCO with no reranking or adaptive retrieval. The authors acknowledge retriever design and reranking strategies are treated as fixed rather than independent variables.

4. **Answer Agent degradation on long-form QA:** ASQA performance drops 1.0-2.3% with Answer Agent enabled, because early commitment to individual candidate answers reduces flexibility in integrating distributed information.

5. **No task-specific adaptation:** All experiments use zero-shot prompting without parameter tuning, which may underestimate potential performance with prompt optimization.

6. **English-only evaluation:** Tested only on English QA benchmarks (TriviaQA, PopQA, ARC-Challenge, ASQA). Cross-lingual performance is unknown.

7. **No correctness guarantee:** Inherits hallucinations and biases from backbone LLMs. The system can amplify errors if multiple agents agree on incorrect evidence.

8. **Answer Agent harms PopQA with Mistral:** Table 3 shows PopQA accuracy drops from 61.9% to 60.9% with Answer Agent enabled on Mistral-7B, suggesting weaker models struggle to integrate candidate hypotheses.

## 6. Transfer to Lyra

### The One Idea: Role-Specialized Evidence Filtering with Evidence Coverage Tracking

MASS-RAG's core insight is that **multiple specialized filter agents capture non-overlapping complementary evidence** — proven quantitatively via the Uniquely Attributable Subset analysis. For Lyra, this translates to: instead of a single RAG pipeline that merges all retrieved context into one prompt, deploy 3 lightweight filter passes (summarize → extract → reason) with the same retrieved documents, then synthesize their outputs. Track the Evidence Coverage Rate (ECR) per filter to identify which evidence-processing strategy works for which query type, enabling dynamic agent routing.

### Workstream Route: §4.2 (Context Management / RAG Pipeline)

This directly improves Lyra's retrieval-augmented generation subsystem by structuring evidence processing before answer generation. The ECR metric can serve as a Lyra-internal quality gate for retrieval quality.
