# Sibyl-AutoResearch: Autonomous Research Needs Self-Evolving Trial-and-Error Harnesses, Not Paper Generators
**Authors:** Chengcheng Wang (U. Sydney), Qinhua Xie (East China Normal U.), Wei He (TokenRhythm AI), Jianyuan Guo, Shiqi Wang (City U. of Hong Kong), Chang Xu (U. Sydney)
**Venue:** arXiv:2605.22343v1 [cs.MA], May 21, 2026
**Repository:** https://github.com/Sibyl-Research-Team/AutoResearch-SibylSystem

## 1. Mechanism (step-by-step)

The core insight: existing autonomous research systems complete workflows (propose idea → run experiments → draft paper) but **lose trial experience** because there is no explicit update path from trial signals to later behavior. Sibyl-AutoResearch introduces **Scientific Trial-and-Error Harnesses** — the environment around the agent (state, tools, roles, memory, gates, artifact contracts, compute policies, repair mechanisms) that makes trial-to-action conversion inspectable and enforceable.

### Two Auditable Conversion Units

**Unit 1: Trial-to-Behavior Conversion** (agent-side audit)
```
A conversion event is counted when and only when:
  signal at iteration t  +  trace path  +  update at iteration t+k
```
A signal (success/failure/anomaly observed during a trial) must demonstrably alter a later action:
- Plan mutation (which direction to try next)
- Validation insertion (which checks to run earlier)
- Claim downgrade (how strongly to state a result)
- Branch stop (when to abandon a direction)
- Scheduler policy change (GPU budget reallocation)
- Writing restriction (pilot signal != paper-ready claim)

**Unit 2: Trial-to-Harness-Behavior Conversion** (harness-side audit)
Recurring process failures must alter harness functions:
- Gates (new or hardened decision points)
- Prompt overlays (role-specific lesson injection)
- Telemetry requirements (missing artifact → required field)
- Scheduler policies (costly failure → cheap pre-check)
- Repair tasks (deterministic fixers for recurring failure classes)
- Protected constraints (evidence-integrity rules that self-evolution cannot weaken)

### Seven Harness Functions (H1–H7)

| Function | Observable Commitment |
|---|---|
| H1: Trial orchestration | Earlier evidence changes later plans, dependencies, branch priority, or stopping decisions |
| H2: Evidence maturity | Claims move through explicit maturity states (M0→M4) with validation and scope labels |
| H3: Traceability | Claims and behavior updates link to scripts, configs, logs, results, reviews, and negative evidence |
| H4: Routed research memory | Lessons change checks or priors of the specific roles that need them (not free-form notes) |
| H5: Perspective separation | Objections from critic/skeptic become validation tasks, plan mutations, stopped branches, or claim downgrades |
| H6: Resource-aware trial policy | Failed/wasteful trials change sanity-check order, allocation, monitoring, or recovery |
| H7: Harness self-evolution | Recurring process failures change gates, overlays, telemetry, scheduler policy, repair tasks, or protected constraints |

### Evidence Maturity Ladder (H2 detail)
```
M0: Execution completion
M1: Pilot signal           ← pilot gate
M2: Analysis-ready evidence ← validation gate
M3: Paper-ready evidence    ← claim gate
M4: Audited claim           ← audit gate
```
Each gate can **Allow** (scoped claim), **Downgrade** (refine claim), or **Block** (return to validation). Negative evidence can increase maturity by ruling out false stories.

### SIBYL System Architecture

The file-backed implementation that operationalizes the framework:
- **State machine + task plans** for trial orchestration (H1)
- **Decision gates + validation requirements** for evidence maturity (H2)
- **Workspace artifacts + event logs** for traceability (H3)
- **Reflection postprocessing → Evolution records → Role-specific lesson overlays** for routed memory (H4)
- **Role-separated agents:** planner, experimenter, critic, supervisor, skeptic, methodologist, writer, editor (H5)
- **GPU scheduler, dependency graph, recovery** for resource policy (H6)
- **Evolution records, self-heal tasks, protected constraints** for harness self-evolution (H7)

### Claim-Evidence Boundary
Writing agents consume a **validated claim registry** with maturity labels, artifact links, and validation status. Pilot signals remain usable as pilot signals but cannot be upgraded into paper-ready claims by prose alone. A writer can synthesize validated claims but cannot upgrade a pilot result. This boundary is the mechanism that prevents the "paper completion hides evidence immaturity" failure (F1).

### Memory Routing (H4)
Reflection outputs are **normalized** into issue categories (system, experiment, writing, analysis, planning, pipeline, ideation, efficiency), **converted** into evolution records with severity/frequency/suggested-action/success-patterns, and **injected** as role-specific overlays. The evolution layer computes relevance scores, tracks recurrence, applies decay, and supports re-opening criteria. Effectiveness is measured by behavior change, not memory volume.

## 2. Results (real benchmark numbers)

### Conversion Event Audit (8 high-confidence events)
- **Median conversion latency:** 1 iteration
- **Maximum visible latency:** 3 iterations
- Hand-audited across preserved SIBYL workspace traces

### Recovered-Failure Registry (5 natural failure classes)
| Failure Class | Outcome |
|---|---|
| Duplicate result files | 4 of 5 component replicates byte-identical to another method across nine metrics → duplicate detection + single-source analysis prerequisites added |
| CI inversion | 5 of 7 confidence intervals did not contain point estimates → source-to-paper validation script, CI fixes in next iteration |
| Stale headline numbers | 4.1× ratio persisted after data changed → headline reduced to 2.7× under quality-gated aggregation |
| Feature-count mismatch | Run used 1,024 features, paper claimed 16,384 → claim generation blocked until manifest/run alignment |
| Unsupported statistics | Fabricated Wilcoxon values; α=0.52 claim vs. measured accept rate 0.881 → paper reframed around interference taxonomy |

### Stage-Transition Statistics (1,853 records, 12 audited traces)
- Writing → writing: 405 (self-loops can absorb many iterations without evidence improvement)
- Experiment → experiment: 271 (pilot/full runs dominate execution volume)
- Review → harness: 217 (review/debate returns control to planning/reflection)
- Harness → experiment: 124 (planning/reflection routes lessons back to experiments)
- Validation → experiment: 78 (gates can force additional experiments instead of allowing narrative advancement)

### Internal Review-to-Action Analysis (37 parseable action-plan rows)
- **Score-down rows (n=10):** 8.7 high-severity issues/row, 8.4 focus items/row, 88 visible next-plan tasks (56 experiment/control, 17 validation/artifact, 13 harness/system)
- **Score-up rows (n=10):** 4.0 high-severity issues/row, 7.5 focus items/row
- Score-down rows carry ~2× more high-severity issues than score-up rows

### Case-Specific Numbers
- **Sparse-autoencoder absorption:** 51/53 source-to-paper validation checks pass after script implementation; headline ratio corrected from 4.1× to 2.7×; R²=0.777, ρ=-1.0, p=0.009 for probe-degradation; city-continent recovery 62.7% mean vs. 61.9% expected (d=2.04, p<0.001)

- **Evolution memory ledger:** 416 recurring issue patterns (212 experiment, 89 writing, 84 analysis, 20 system, 4 ideation, 3 pipeline, 3 planning, 1 efficiency); 12/13 workspaces have non-empty outcome records; 173 central-ledger outcome records

SIBYL traces are the only system with trace-evidenced support across all H1–H7. Prior systems (AI Scientist, Agent Laboratory, AlphaEvolve, Reflexion) have paper-described support for some functions but no auditable trace paths.

## 3. Trade-offs (wins vs. loses)

| Wins | Costs / Loses |
|---|---|
| Makes trial experience auditable: every behavior change linked to a signal + trace path + update | Retrospective audit only: no controlled experiments, no injected-failure benchmark run |
| Catches evidence-boundary failures (duplicate results, CI inversion, stale numbers, feature mismatch) before they become paper claims | Co-developed framework and system: traces not independent validation of theory |
| Preserves negative results as belief-calibration events (unsupported speedup claims → interference taxonomy) | Hand-marked conversion count: not scalable, subjective; only 8 events claimed |
| Separates process concerns from paper generation: writing quality can improve while evidence collapses (detected in failed SAE replication) | Generated reviews, not human peer review; three review surfaces disagree in schema and calibration |
| Evidence maturity ladder prevents pilot signals from being upgraded to paper claims by polished prose | Transition counts may include resume/checkpoint repetition |
| Routed memory changes which checks roles perform (not just preserving text in long context) | No held-out harnesses, no independent annotators, no prospective injected failures |
| Harness self-evolution makes infrastructure harder to fool over time | Framework specific to computational AI/ML workspaces; domain generality not tested |
| Explicit protected constraints prevent self-evolution from optimizing polish over integrity | Review scores barely move across iterations even when objections persist (20/22 transitions flat for conservative reviewer) |
| Provides existence proof that conversion paths are recoverable from realistic autonomous-research workspaces | Does not establish comparative performance claim vs. prior autonomous research systems |

## 4. Design Rationale (why this approach)

The paper diagnoses a specific failure: **executable workflows do not produce research judgment**. Existing systems complete research stages (propose, experiment, draft) but lose the experience those stages should have produced. Six failure modes (F1–F6) document where the update path is missing: paper completion hides weak evidence, pilot signals become broad claims, broken metrics persist, memory stays un-routed, more trials don't improve trial policy, and process failures recur because the harness never changes.

The harness-as-unit-of-analysis is chosen because research judgment requires both **agent behavior change** (better plans, stronger validation, narrower claims) AND **infrastructure adaptation** (new gates, better telemetry, repair tasks). Agent-only approaches leave the infrastructure static; agentless approaches cannot produce the domain judgments.

The auditable conversion unit design (signal + trace + update) is chosen because it is **small enough to verify** (one linked event) but **meaningful enough to capture research judgment** (the event must change later behavior). This granularity enables retrospective audit without requiring a held-out test set.

File-backed design (all state, plans, artifacts, reviews, writing stored as inspectable files) is chosen because **auditability requires inspectability**. Without persistent traces, conversion events cannot be recovered or verified.

Role-specific routing (lessons → specific roles, not broadcast) is chosen because **context length does not equal behavior change**. A system can recognize a pattern in text while failing to change the checks performed by each role.

The claim-evidence boundary (validated claim registry with maturity labels consumed by writers) is chosen because **polished writing can outrun evidence quality**. A structural boundary prevents narrative fluency from compensating for weak evidence.

## 5. Limitations & Failure Modes

1. **Retrospective, single-harness evidence.** All traces come from one author-built harness for computational AI/ML workspaces. The framework and SIBYL co-developed, so traces are theory-building/stress-test evidence, not independent validation.
2. **No controlled comparisons.** Conversion count is hand-marked. Recovered-failure registry uses natural (not injected) failures. No head-to-head comparison with prior systems on held-out tasks.
3. **Generated reviews, not human peer review.** The reviewer artifacts are LLM-generated. Three review surfaces disagree in schema and calibration. Within each surface, scores barely move across iterations (20/22 transitions flat for the conservative reviewer) — so optimizing review scores would create another brittle objective.
4. **Transition counts may inflate.** Stage-transition counts (1,853 records) may include resume or checkpoint repetition. Support process-shape claims, not exact execution counts.
5. **No cross-domain evidence.** All workspaces are computational ML/AI (sparse autoencoders, weight decay, diffusion LM, image augmentation). Chemistry, biology, physics, or social science domains untested.
6. **Scalability of manual audit unaddressed.** Hand-marked 8 conversion events is not a scalable evaluation protocol. The proposed evaluation protocols (prospective fixed-budget, injected-failure, cross-project memory, harness-evolution tests) are not executed in the paper.
7. **Harness self-evolution may optimize for process compliance rather than evidence integrity.** Protected constraints are claimed but their enforcement in practice is not demonstrated at scale.
8. **No evidence on whether routed memory suppresses valid exploration.** Negative memory records could become over-generalized bans (the governance section acknowledges this but provides no empirical mitigation evidence).

## 6. Transfer to Lyra

### The ONE Transferable Idea

**Trial-to-Behavior Conversion as an Auditable Unit in Agent Evaluation Harnesses.** The central idea Lyra should adopt is the requirement that every evaluation signal must be explicitly linked via a trace path to a later behavior change (plan mutation, validation insertion, claim downgrade, or harness repair). Lyra's evaluation pipeline currently runs benchmarks and produces scores, but does not verify that those scores actually change subsequent agent behavior. Implementing an evidence maturity ladder (execution → pilot → analysis-ready → audited) and requiring traceable conversion paths from eval signals to behavior updates would transform Lyra's evaluation harness from a score-producing machine into a judgment-accumulating system.

Concrete Lyra adaptation: after each evaluation run, require a conversion audit — for each significant signal (anomalous metric, failed assertion, contradictory baseline), demonstrate that a later planning step, validation check, or harness rule was changed because of it. Store these as versioned evolution records with role-specific routing to planner, verifier, and critique agents.

### Workstream Route
**§4.0 — Evaluation Harness / Verification Infrastructure.** This paper directly feeds the evaluation and verification architecture workstream by providing both (a) the theoretical framework for why eval signals must change behavior, and (b) concrete mechanisms (maturity ladder, conversion audit, role-specific routing, claim-evidence boundary) that Lyra's verification subsystem should implement.

### Scores
- **Impact:** 4 (directly addresses Lyra's core evaluation-into-action gap; the framework is operationalized in working code with recoverable traces)
- **Effort:** 5 (requires building harness infrastructure: audit trails, maturity gates, role-specific memory routing, evolution records, and protected constraints — a multi-month engineering effort)
- **Tier:** **breakthrough** — This is not an incremental improvement to existing eval harness design. It fundamentally reframes what evaluation means in autonomous systems: not "does it complete?" but "did it learn from what happened?" This shift from completion-centric to conversion-centric evaluation is exactly the architectural foundation Lyra needs.
