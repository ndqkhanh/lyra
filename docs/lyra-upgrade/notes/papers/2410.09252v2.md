## 1. Mechanism (step-by-step, with equations/algorithms)

DAVIS is a **model-based planning agent** operating under a **POMDP** (Partially Observable Markov Decision Process) in textual environments. It introduces three interdependent subsystems: a Temporal Knowledge Graph (TKG) World Model, an inner monologue retrieval loop, and an actor-critic execution layer.

### 1.1 POMDP Formulation

```
P = (S, A, T, R, Ω, O, γ)
```
- S: true environment states (not directly observable in text)
- A: available actions
- T(s_{t+1} | s_t, a_t): state transition probability
- R(s_t, a_t): reward function
- Ω: possible observations; O(o_{t+1} | s_{t+1}, a_t): observation probability
- γ ∈ [0,1): discount factor

Since s_t is unobservable, DAVIS maintains a **belief state** b_t (a probability distribution over possible states), updated recurrently from trajectory history:

```
b̂_t = f(τ_{t':t})
```

where `f(·)` is a prompted LLM that extracts relevant state information from the action-observation history τ, updated with each new observation. The agent selects actions via a learned policy: `a_t = π(b_t)`. The objective is to find π* maximizing E[Σ γᵗ r_t | π].

### 1.2 Temporal Knowledge Graph World Model

The WM is a **Temporal Knowledge Graph** G_t = (E, R, T), where:
- E: set of entities at time t
- R: set of relations between entities at t
- T: timestamps associated with each relation

**Construction pipeline** (executed per step):

1. Execute action `a_t` in environment, receive observation `o_{t+1}`
2. Form transition text: `(o_t ∥ a_t ∥ o_{t+1})` — concatenation of current observation, action, and resulting observation
3. LLM **summarizes** the concatenated transition text
4. **Stanford CoreNLP** performs coreference resolution on the summary
5. LLM-based **parsing** extracts entities V_t and relation triples from the resolved text
6. Each extracted tuple `(v_i, e_j, v_k, τ)` is added to the TKG with a timestamp τ:

```
G_{t+1} = G_t ∪ {(v_i, e_j, v_k, τ)}
```

The TKG continuously evolves with agent interactions, enabling causal and temporal reasoning over state transitions.

### 1.3 Inner Monologue Retrieval System (Algorithm 2 — the signature innovation)

This is the **agentic, multi-turn conversational retrieval** that replaces static one-shot RAG. When DAVIS needs to predict a transition or reward, it engages in up to `k` turns of querying its TKG to fill knowledge gaps.

**Algorithm 2 — Transition Prediction:**
```
Input: b̂_t, â_t, k
Output: ô_{t+1}, r̂_{t+1}
1: M ← ∅                              // Initialize inner monologue set
2: i ← 0
3: while i < k or not predicted do
4:     ô_{t+1}, q ← T̂(b̂_t, â_t, M)     // Predict observation, possibly generate a question
5:     r̂_{t+1}, q ← R̂(b̂_t, â_t, M)     // Predict reward, possibly generate a question
6:     if q ≠ ∅ then
7:         M ← M ∪ {(q, graphQA(q))}   // Query KG, store Q&A pair in monologue
8:     end if
9:     i ← i + 1
10: end while
11: return ô_{t+1}, r̂_{t+1}
```

**graphQA(q) execution** (3-phase structured retrieval):

1. **Entity selection**: Narrow to relevant entity types (e.g., PER, LOC), select 2 most relevant entities. Limiting to 2 is computationally efficient while preserving context.
2. **Subgraph expansion & temporal reorder**:
   - Iteratively expand selected entities by adding neighbors → maximal subgraph (ignoring temporal info initially to find all paths)
   - Reorder edges by timestamps → chronologically coherent event sequence
3. **LLM extrapolation**: Pass the temporal sequence as in-context examples for the LLM to extrapolate and generate a coherent, interpretable response.

### 1.4 Planning & Execution Loop (Algorithm 1)

**Algorithm 1 — Planning with Retrieval-Augmented WM:**
```
Input: τ, R
Parameters: L, k
Output: τ
1: for t = 1 to L do
2:     ŝ_t ← f(τ)                               // State estimation from history
3:     â_t ← π(ŝ_t, R, k)                        // Policy: select action via WM + retrieval
4:     τ ← τ ∪ â_t
5:     ô_{t+1}, r̂_{t+1} ← TRANSITION(ŝ_t, â_t)    // Algorithm 2: inner monologue prediction
6:     τ ← τ ∪ {ô_{t+1}, r̂_{t+1}}
7:     if τ violates safety constraints then     // Optional safety gate
8:         Alert supervisor
9:     end if
10: end for
11: return τ
```

The WM generates a predicted trajectory of length L:

```
τ_{t:t+L} = {(ô_i, â_i, ô_{i+1}, r̂_{i+1})}_{i=t}^{t+L-1}
```

### 1.5 Actor-Critic Execution Architecture

**Actor** (`R_a`): Decomposes each high-level plan action `â_t` into executable low-level commands within the environment's action space (25 high-level actions in ScienceWorld). Expands trajectory:

```
τ̂_{t:t+L'} = R_a(τ_{t:t+L})   where L' ≥ L
```

Trajectory is executed step-by-step: `(o_t, r_t, o_{t+1}) = E(â_t)`

**Critic** (`R_c`): An LLM-based evaluation function that compares predicted vs. actual transitions:

```
Δ_t = R_c((ô_t, r̂_t, ô_{t+1}), (o_t, r_t, o_{t+1}))
```

Δ_t is a qualitative **reflection score** on the agreement between prediction and reality. If deviation is significant:
1. Critic updates its **reflection list**: `R_{t+1} = R_t ∪ {(o_t, ŝ_t, Δ_t)}`
2. Critic **triggers replanning** — Algorithm 1 is re-invoked for the new subtask
3. The WM uses updated reflections and inner monologue as additional context

The three learned functions incorporating inner monologue M_t:
- **Policy**: `π(a_t | b̂_t, M_t)` — selects actions informed by KG-retrieved context
- **Transition model**: `T̂(o_{t+1} | b̂_t, a_t, M_t)` — predicts next observation
- **Reward model**: `R̂(r_t | b̂_t, a_t, M_t)` — predicts reward

## 3. Trade-offs (wins vs. losses)

| Win | Loss |
|-----|------|
| **1.8× average score improvement** over 4 baselines on ScienceWorld (65.06 vs. max 33.64); wins 8/9 subjects | **$0.43/action, $43/episode operational cost** — >$3,000 per full experiment, prohibitive for many settings |
| **Structured temporal memory** (TKG) enables multi-hop + causal reasoning that unstructured vector-RAG cannot | **KG dependency bias**: agent prioritizes graph-stored information, struggles with novel scenarios outside 150 training variations |
| **Inner monologue** allows iterative, gap-filling retrieval before committing to actions — dynamic adaptation | **LLM sensitivity**: performance varies with API updates and model version (GPT-4o outperformed GPT-4-turbo contrary to general claims) |
| **Actor-critic with real-time deviation detection** enables error recovery via replanning mid-episode | **Text-only**: no visual/auditory input, cannot serve as embodied agent in real-world labs |
| **Interpretable natural language plans** allow human supervisor review before execution (safety) | **Higher latency** per action due to multi-turn LLM calls in the inner monologue loop (up to k=5 turns) |
| **Generalizes from demonstrations** to new task variations via WM transfer | **Fails on Botany** (26.83 vs. ReAct's 40.83) — suggests TKG is less helpful for domains requiring procedural "common sense" over factual recall |
| Competitive multi-hop QA (HotpotQA F1 73.8 vs. GraphReader 70.0) without domain-specific training | **Reproducibility gap**: relies on commercial LLMs with undisclosed update schedules; no open-source replication pipeline |

## 4. Design Rationale (why this approach over alternatives)

**Why inner monologue over static RAG?** Humans do not retrieve memories statically; we engage in internal dialogue to question, refine, and fill gaps in our understanding. Static RAG (Reflexion, RAP) retrieves once and proceeds — it cannot adapt when retrieval is incomplete. Inner monologue enables iterative, conversational retrieval where each turn's answer may reveal new gaps requiring further queries.

**Why Temporal KG over vector database?** Vector-based retrieval fragments information into unstructured chunks, preventing multi-hop reasoning ("Where did I put the thermometer?" → "In the cupboard" → "Which cupboard?" → "The one in the lab"). TKG preserves relational structure and temporal ordering, enabling causal inference ("The water boiled BECAUSE I heated it, AFTER I placed it on the stove").

**Why actor-critic over sequential plan-then-execute?** Prior systems (Reflexion, RAP) generate full plans then evaluate post hoc. Scientific tasks have compounding effects — a mistake in step 3 may invalidate steps 4-10. DAVIS's critic evaluates every step mid-execution, enabling immediate replanning when reality deviates from prediction.

**Why POMDP over MDP?** Text environments give partial observations via natural language — the agent never sees the "true" state. The belief state formulation acknowledges this uncertainty and formalizes the role of the TKG as a state estimator.

**Why Stanford CoreNLP + LLM over pure LLM for KG construction?** LLMs alone struggle with coreference resolution in procedural text (e.g., "Put it in the cabinet" — what is "it"?). CoreNLP provides deterministic, linguistically grounded resolution that feeds cleaner input to the LLM parser.

## 5. Limitations & Failure Modes

1. **High operational cost** ($0.43/action, $43/episode): The inner monologue loop sends/receives ~43K tokens per action, making DAVIS cost-prohibitive for long-horizon tasks or large-scale deployment. The authors propose future distillation onto smaller open-source models.

2. **Sensitive to LLM quality drift**: DAVIS (GPT-4o) outperformed DAVIS (GPT-4-turbo) on QA benchmarks, contrary to general performance claims for GPT-4-turbo. Commercial API updates introduce non-deterministic behavioral changes that degrade reproducibility.

3. **Biased planning from KG over-reliance**: The TKG is populated from only 150 task variations. When encountering novel scenarios outside graph coverage, DAVIS prioritizes (potentially irrelevant) stored information, degrading planning quality. The Botany failure (26.83) may exemplify this.

4. **No multimodal capabilities**: Cannot process visual, auditory, or sensor data — limiting deployment in real labs where instruments provide visual readouts, sounds indicate equipment states, etc.

5. **Not evaluated in safety-critical real-world contexts**: No testing in domains like remote surgery, chemical lab automation, or aerospace where real-time physical constraints, ethical concerns, and safety protocols are paramount.

6. **Non-reproducible due to proprietary LLM reliance**: Closed-source models with undisclosed update schedules mean exact reproduction is infeasible. Authors advocate for future open-source, model-agnostic evaluation protocols with fixed checkpoints.

7. **Lucky artifact in ablation**: On task 6-1 (Mix Paint), the no-Actor and no-Critic variants outperformed full DAVIS (100.0 and 86.0 vs. 36.4) because they accidentally guessed "focus on" early. This reveals brittleness in the evaluation: small action-space luck can mask real architectural failures.

## 6. Transfer to Lyra

### The ONE Transferable Idea

**Inner monologue retrieval**: Replace Lyra's static one-shot RAG with a conversational multi-turn retrieval loop between the planner and a structured memory graph (TKG). Before committing to a plan, the planner iteratively queries the KG, the KG returns structured subgraph responses, and the planner identifies remaining gaps — repeating up to k turns until confidence is sufficient. This turns memory access from a single lookup into an adaptive, gap-filling dialogue that mirrors how human experts cross-reference knowledge before acting.

### Workstream Route

**§4.2 — Context & Memory**: The inner monologue extends Lyra's context layering by adding an active retrieval phase between context assembly and plan generation. Instead of assembling all context upfront (current Lyra), the planner engages in multi-turn KG retrieval to fill specific gaps discovered during planning, producing a richer, more targeted context.
