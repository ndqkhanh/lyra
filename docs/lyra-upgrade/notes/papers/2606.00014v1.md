# Toward Robust In-Context Learning: Leveraging Out-of-distribution Proxies for Target Inaccessible Demonstration Retrieval
**Hao Xu, Rite Bo, Fausto Giunchiglia, Yingji Li, Rui Song*** — Jilin University & University of Trento — arXiv:2606.00014v1, April 2026

## 1. Mechanism (step-by-step)

DOPA (Demonstration Optimization via OOD Proxy Assessment) is a two-stage framework for retrieving ICL demonstrations when the target domain is completely inaccessible.

### Stage 1: OOD Proxy Estimation

**Construction of dual proxies:**
- **Source proxy** (Psource_proxy): The LLM is instruction-tuned via LoRA on source-domain data (1 epoch, lr=1e-5). This proxy fully adapts to the source distribution.
- **Target proxy** (Ptarget_proxy): The original, unmodified version of the same LLM, preserving its prior knowledge that implicitly covers broader domains.

**OOD score computation:**
For each source-domain sample x, compute the log-perplexity difference:

```
S(x) = log PPL_target_proxy(x) - log PPL_source_proxy(x)
```

where PPL(x) = exp(-(1/m) * Σ log P(wi|w<i)) for autoregressive LLMs.

- Low S(x) → sample has higher perplexity under source proxy, lower under target proxy → more aligned with target domain → prioritized for demonstrations.
- High S(x) → sample is source-domain-specific → deprioritized.

**Theoretical justification (Theorem 1):**
If DKL(P_target ∥ P_target_proxy) ≤ ε_t and DKL(P_source ∥ P_source_proxy) ≤ ε_s, and both distributions have pointwise lower bounds m_t, m_s > 0, then for all x:

```
|log P_target(x)/P_source(x) - log P_target_proxy(x)/P_source_proxy(x)| ≤ ε_t/m_t + ε_s/m_s
```

This certifies that the proxy-based score deviates from the true likelihood ratio by a bounded quantity.

**Lemma 1:** Using a uniform distribution as target proxy yields a looser bound (log|X| - H(P_t))/m_t + ε_s/m_s, justifying the use of the base LLM rather than a uniform prior.

### Stage 2: Multi-Granularity Demonstration Retrieval

**Step 1 — OOD-based filtering:** Source domain samples are ranked by S(x), retaining those below a threshold. Define filtered set D̂_S.

**Step 2 — Similarity-based initialization (Eq. 4):**
For a test sample x_t with SimCSE embedding h_t, select the top-C most similar samples from D̂_S by cosine similarity:

```
D_demo_init = argmax_C {sim(h_xi, h_t)} over i=1..|D̂_S|
```

where C = |Y| for classification tasks, C = 1 for generative tasks.

**Step 3 — Mahalanobis diversity constraint (Eq. 5, Algorithm 1):**
Iterate through remaining samples in D̂_S in similarity order. For each candidate x̂, compute:

```
Div = (2 / (|D|(|D|-1))) * Σ_{i<j} sqrt(D_ij^T Σ^{-1} D_ij)
```

where D_ij = h_xi - h_xj and Σ is the empirical covariance over all samples. If Div_{D} ≤ Div_{D∪{x̂}}, retain x̂. Continue until N × |Y| demonstrations are collected. Mahalanobis distance is preferred over Euclidean because it accounts for feature correlations.

**Step 4 — Fixed label-order construction:** Demonstrations are assembled in a fixed label order to prevent position bias, then fed into the target LLM for ICL inference.

### Hyperparameters
- k (filtering threshold for D̂_S): 800 (determined via sweep)
- N (demonstrations per label): 3 (determined via sweep)
- C (initial candidate set size): |Y| for classification, 1 for generation
- Similarity encoder: SimCSE
- Proxy tuning: LoRA, lr=1e-5, 1 epoch

## 3. Trade-offs

| Win | Loss |
|-----|------|
| Target-domain-free: retrieves aligned demonstrations without ANY target samples | Requires instruction-tuning (LoRA) on source domain, adding upfront compute cost |
| Theoretically grounded: bounded proxy error (Theorem 1) ensures estimation reliability | OOD score S(x) requires running two forward passes (source proxy + target proxy) per candidate sample |
| Cross-model transfer works: proxy built from LLaMA3.2-3B works for closed-source GPT4o-mini/GPT3.5-turbo | Proxy mismatch penalty: using Qwen3-1.7B as target proxy for LLaMA3.2-3B source proxy drops SA from 59.29→56.72 (Table 5) |
| Mahalanobis diversity adds controlled variety without semantic drift (evidenced by close Euclidean distance curves in Fig 4c) | Fixed k=800 and N=3 are pragmatic but suboptimal per-task (Figs 2-3 show task-dependent peaks) |
| Works across 8 LLMs (1.5B to 8B, open and closed) | Gains shrink on stronger models: Qwen3-8B shows marginal improvement (~1%) |
| Outperforms data-augmentation (Rewrite) and gradient-based methods (InfICL) without expensive optimization | Only validated on NLU (classification + NER + QA); untested on reasoning, math, code tasks

## 4. Design Rationale

The core insight is that an **instruction-tuned LLM on source data overfits to source distribution**, while the **original base LLM retains broader prior knowledge** including target-domain patterns. The perplexity ratio between them acts as a domain-discrimination signal without requiring target access. This is inspired by OOD detection literature (Ren et al. 2019; Zhang & Wischik 2022), where likelihood ratios between in-distribution and OOD models detect outliers. The authors chose Mahalanobis over Euclidean distance for diversity because it accounts for inter-feature correlations — critical when demonstrations share latent dimensions (e.g., sentiment intensity and lexical choice are correlated). The two-stage retrieval (OOD filter → similarity → diversity) is designed to be modular: each component can be ablated independently, and the proxy estimation can theoretically accommodate any target-proxy construction as long as the KL divergence remains bounded.

## 5. Limitations & Failure Modes

1. **Proxy approximation error (intrinsic):** Target-domain proxy (base LLM) cannot perfectly capture true target distribution when the shift is extreme (e.g., domain with completely novel vocabulary). Theorem 1 only provides a bound, not zero error. The paper acknowledges this as its primary limitation and suggests future work on more robust proxy estimation.

2. **Proxy-model mismatch degradation:** Using models from different families as source/target proxies degrades performance (Table 5: cross-family drops SA by up to 2.57% vs same-family). This limits applicability when only a single model family is available.

3. **Narrow task validation:** Only tested on classification (SA, TD, NLI), NER, and QA. No evidence for reasoning, math, code generation, or multi-turn tasks.

4. **Fixed hyperparameter brittleness:** k=800 and N=3 are held constant across all tasks/LLMs for simplicity, despite per-task optima varying (Figs 2-3). The k=800 was chosen as a "favorable balance" rather than optimal.

5. **Closed-source proxy reliance:** For API-only models (GPT-4o-mini, GPT-3.5-turbo), DOPA uses LLaMA3.2-3B as a stand-in proxy, which "cannot perfectly replicate" behavior — an acknowledged gap.

6. **Computational overhead:** Every candidate sample requires two full forward passes for perplexity computation, plus instruction-tuning overhead. Not benchmarked against retrieval-only baselines in wall-clock time.

## 6. Transfer to Lyra

**The ONE transferable idea:** Use a dual-proxy perplexity ratio (instruction-tuned vs. base model) as an OOD alignment signal to select demonstrations when the target domain is inaccessible — enabling robust few-shot ICL without target samples.

**Lyra workstream route:** §4.1 (Demonstration Retrieval & Selection). Lyra's demonstration selection currently relies on similarity-based retrieval; DOPA's proxy-based scoring adds a principled OOD-robustness layer that requires no target-domain access — directly applicable when Lyra encounters novel tool APIs, unfamiliar codebases, or domain-shifted user queries.

**Impact:** 3 (meaningful improvement for OOD robustness but narrow task scope). **Effort:** 4 (requires instruction-tuning infrastructure + proxy computation pipeline + Mahalanobis diversity module). **Tier:** investigate — promising mechanism with theoretical grounding but needs validation on Lyra-specific tasks (tool use, code generation, multi-turn reasoning) before committing to implementation. Worth prototyping as an optional demonstration re-ranker.
