## 1. Mechanism (step-by-step)

STITCH (Structured Intent Tracking in Contextual History) is an agentic memory system that indexes each trajectory step with a structured retrieval cue called **contextual intent**, then retrieves history by matching the current query's intent against stored cues.

### Core Idea
For a trajectory T = {s1, s2, ..., sn} where each step st = (rt, at, τt) has agent role, action description, and timestamp, STITCH infers a **contextual intent tuple** ιt = (σt, εt, κt):

1. **σt — Thematic Scope (Partonomy):** A stable segment label tracking the current latent goal. Induced via a sliding-window LLM predictor M_scope that looks at the current step, a history buffer H_scope, and the previous scope label to detect goal-state divergence. When a boundary is detected, a new label is induced; otherwise the step inherits the prior scope. A compressed running summary Σ_σ of the current scope is maintained online to prevent context overflow.

2. **εt — Event Type (Taxonomy):** An action label capturing the operation performed, induced without a pre-defined ontology. A dynamic label-space evolution: generate a seed vocabulary V_ε from the first N_start=50 steps, then for each subsequent step retrieve top-k_event=5 semantically similar labels and prompt an LLM to select/assign. If no suitable label exists, create a new one. Periodic consolidation (every k_update=50 steps) merges near-synonyms.

3. **κt — Key Entity Types (Taxonomy):** The entity classes that determine which attributes matter in-context (e.g., Price, Rating). Induced online via a growing label space V_κ with the same dynamic labeling + periodic consolidation pattern as event types.

### Coreference Resolution via Structural Alignment
When a step st contains ambiguous references (e.g., "Book it"), a context set C_align is retrieved consisting of prior steps sharing the same thematic scope σt and/or compatible event types εt. The step is then rewritten into a disambiguated form s't = M_rewrite(st, C_align), resolving pronouns to canonical entity names.

### Memory Snippet Construction
A canonical summary ct = M_sum(s't, ιt) is generated. The final Memory Snippet mt = (st, ιt, ct) packages raw content, structural intent, and summary.

### Intent-Aware Retrieval
At inference time, given a query q, an LLM produces a **filter configuration** Fq = (Sq, Eq, Kq) specifying target values over the same schema components as ιt (thematic scopes, event types, key entity types), expressed in the same label space.

**Label Density Ranking:** Memory snippets are ranked by the cardinality of their overlap with Fq (number of satisfied constraints in ιt). Among snippets with equal label density, ranking falls back to semantic similarity sim(q, ct). Top-k_retrieve=40 snippets are returned.

### Algorithm Summary (Pseudocode)
```
// Ingestion
for each step st in streaming trajectory:
    σt ← M_scope(st, H_scope, σt-1)  // thematic scope induction
    εt ← M_label(st, Retrieve(V_ε, st, k_event))  // event labeling
    κt ← M_entity(st, V_κ)  // key entity types
    s't ← if ambiguous(st) then M_rewrite(st, C_align) else st
    ct ← M_sum(s't, (σt, εt, κt))
    mt ← (st, (σt, εt, κt), ct)
    store(mt)
    // periodic: consolidate V_ε, V_κ every k_update steps

// Retrieval
Fq ← M_filter(q, {scope_labels}, V_ε, V_κ)
ranked ← sort(memories, key=count_overlap(ιt, Fq), tiebreak=sim(q, ct))
return top-k_retrieve(ranked)
```

## 3. Trade-offs (wins vs loses)

| Win | Lose |
|-----|------|
| Outperforms all baselines on CAME-Bench; largest gains as trajectory length grows (+100% relative on Large) | Higher per-step ingestion cost (multiple LLM calls for σ, ε, κ, summary) vs. lightweight embedding-only baselines |
| Robust across backbone models (gpt-4o-mini, gpt-4.1-mini, gpt-5-mini) — gains from architecture, not frontier model | Buffered label update strategy (N=50) introduces latency before novel event types are formalized |
| Query-time retrieval is much cheaper than full-context LLMs (1.9K vs 266.1K tokens on Large) | Only competitive (not SOTA) on LoCoMo — social/conversational memory with weak goal structure |
| Explicit structural cues provide auditability and interpretability vs. black-box embeddings | Flat event taxonomy struggles with Information Synthesis tasks (Question Type 4) — requires aggregating across multiple fine-grained labels |
| No domain-specific ontology required — labels induced online, generalizes across Travel and Debate domains | Granularity mismatch risk: selecting labels at wrong abstraction level before retrieval irreversibly filters evidence |
| Thematic scope dramatically reduces context noise (removing it causes largest performance drop) | Label density ranking can deprioritize correct evidence if distractors have higher structural overlap |

## 4. Design Rationale (why this approach)

The core motivation is grounded in **Event Structure Theory** (Zacks & Tversky, 2001): humans organize experience using partonomies (hierarchical goal segments) and taxonomies (recurring action categories). STITCH mirrors this dual organization:

- **Why partonomy + taxonomy over flat RAG?** Pure semantic similarity fails when semantically similar facts differ only by context (e.g., "Hotel A price Day 1" vs "Hotel A price Day 2"). Structural cues provide a disambiguation signal orthogonal to content embeddings.
- **Why online label induction over fixed ontology?** Fixed schemas won't generalize across domains. Dynamic label evolution (seed from first 50 turns, expand/consolidate periodically) adapts to any task domain without pre-definition.
- **Why label density ranking over pure semantic ranking?** Structural compatibility (overlap count with Fq) acts as a coarse filter that suppresses semantically-similar-but-contextually-irrelevant content before finer-grained semantic scoring. This is the key mechanism that prevents the "lost in the middle" degradation that afflicts long-context LLMs.

## 5. Limitations & Failure Modes

1. **Ingestion overhead:** Multiple LLM calls per step (scope, event type, entity type, summary) make online ingestion more expensive than embedding-only baselines. Amortized at query time but problematic for real-time high-throughput scenarios.

2. **Buffered label updates:** The k_update=50 buffered strategy stabilizes label space but introduces latency — novel event types emerging mid-buffer are not formalized until the buffer flushes, potentially causing retrieval misses.

3. **Flat taxonomy — synthesis gap:** Fine-grained event labels excel at factual lookup but hinder Information Synthesis (Question Type 4) which requires aggregating across multiple distinct action types. A hierarchical label structure is noted as future work.

4. **Non-inducible label selection (78.4% of errors):** At question time, the model selects labels plausible given trajectory regularities but ungrounded by explicit question cues. Prompt-level constraints alone insufficient.

5. **Granularity mismatch (71.8% of errors):** Irrevocable one-shot label selection at query time commits to a single abstraction level; if wrong, no downstream correction possible.

6. **Weak on open-ended social memory:** On LoCoMo, STITCH underperforms because conversational memory often lacks explicit goal structure — thematic scope and event type provide weak retrieval cues for socially-salient but goal-decoupled information.

7. **Finite benchmark concerns:** CAME-Bench Large partition has only 2 trajectories (61 questions); score stability analysis shows mild sensitivity on Small partition for Question Types 1 and 4. Results do not eliminate all finite-benchmark concerns.

## 6. Transfer to Lyra

### The One Idea
**Intent-indexed memory with multi-dimensional retrieval cues (scope + action type + entity type) to disambiguate semantically similar but contextually distinct history.** Lyra's memory system currently manages long agent trajectories. Adopting STITCH-like contextual intent indexing — automatically inducing thematic scopes (goal segments), event types (action taxonomies), and key entity types from streaming agent traces — would allow Lyra to retrieve context-appropriate memories rather than being misled by surface semantic similarity. This directly addresses the core failure mode where repeated mentions of similar entities under different latent goals cause retrieval interference.

### Workstream Route
**§4.2 Memory Architecture (Plans: 02-memory.md)** — This feeds directly into Lyra's memory subsystem redesign. The structured memory snippet format (raw content + structural intent + canonical summary) aligns with Lyra's planned memory storage and retrieval overhaul.

### Impact/Effort/Tier
- **Impact:** 4 — Large gains possible; STITCH shows +35.6% over strongest baseline on long trajectories in CAME-Bench, with the gap widening as context grows. Lyra's multi-agent long-horizon traces share the same structural properties (interleaved goals, repeated entity mentions under different latent intents).
- **Effort:** 4 — Requires: (a) LLM-based online intent induction pipeline (scope detection, event labeling, entity typing), (b) structural alignment coreference resolution, (c) label density ranking for retrieval, (d) periodic label consolidation. Multiple LLM calls per step add latency; lightweight alternatives (classifier-based labeling) could reduce cost.
- **Tier:** **Breakthrough** — This transforms memory from flat semantic retrieval to intent-aware structured retrieval. The gap between STITCH and baselines only grows with trajectory length, which is exactly Lyra's scaling challenge.
