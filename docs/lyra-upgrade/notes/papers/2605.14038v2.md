# Model-Adaptive Tool Necessity Reveals the Knowing-Doing Gap in LLM Tool Use

**Authors:** Yize Cheng*, Chenrui Fan*, Mahdi JafariRaviz*, Keivan Rezaei, Soheil Feizi (* equal contribution)
**Venue:** University of Maryland, College Park — Preprint, arXiv:2605.14038v2 [cs.AI], 17 May 2026
**Project:** https://github.com/chengez/Tool-Cognition-Action

## 1. Mechanism

The paper decomposes LLM tool-use into a **two-stage pipeline** and measures it against a **model-adaptive definition of tool necessity**.

### 1.1 Model-Adaptive Tool Necessity

Prior work treated "tool necessity" as a static label: a query either needs a tool or not, regardless of which model answers. This paper argues necessity must be **model-dependent** because capability boundaries differ.

**Definition:** For model *f* and query *x*, run *N* independent no-tool inferences at temperature *T* (N=10, T=0.7 in experiments). If *f* answers correctly on **all** *N* runs, *x* lies within *f*'s capability boundary and tool necessity *n_f(x)* = 0 (unnecessary). Otherwise *n_f(x)* = 1 (necessary). This empirical criterion captures reliability: a model that gets it right only 7/10 times should still use a tool.

### 1.2 Two-Stage Cognition-Execution Model

```
x → z_f(x) → a_f(z_f(x))
```
- **Stage 1 (Cognition, z_f):** The model's internal belief about whether a tool is needed. Measured via **linear probing** of hidden states.
- **Stage 2 (Execution, a_f):** The actual tool-call action output as next-token decision.

### 1.3 Linear Probing for Both Stages

For each (token position *t*, layer *l*), train two linear classifiers on hidden states *h_t^{(l)}*:

- **Cognition probe (w_c, b_c):** Predicts model-adaptive necessity *n_f(x)*:
  ```
  Loss = -1/K Σ [ n_f(x_k) log σ(w_c^T h_t(x_k) + b_c) + (1 - n_f(x_k)) log(1 - σ(w_c^T h_t(x_k) + b_c)) ]
  ```
  Optimized with Adam (lr=0.01). Evaluated with **Matthews Correlation Coefficient (MCC)** on 30% held-out test set.

- **Action probe (w_a, b_a):** Same objective but predicts actual tool-call behavior.

### 1.4 Cosine Similarity Between Probe Directions

At each (t, l), compute CosSim(w_c, w_a). A value near ±1 = cognition and action encoded along same axis; near 0 = encoded in orthogonal subspaces. **Key finding:** CosSim collapses to near-zero in late layers at the last token (t=-1, large l) — precisely the position that drives next-token generation.

### 1.5 Two-Stage Error Attribution via Sankey Tracing

Each sample is traced: Factual necessity → Cognition (probe readout at last-token, last-layer) → Action (observed). Samples fall into four categories:
- **Green:** Correct in both stages
- **Red:** Error in stage 1 only (wrong cognition, right action by compensating error)
- **Orange:** Error in stage 2 only (right cognition → wrong action) — **the knowing-doing gap**
- **Purple:** Error in both stages

### 1.6 Confidence Analysis

Post-sigmoid probe output σ(w_c h + b_c) quantifies cognition confidence. Tool-call probability is:
```
P(call) = p(⟨tool-token⟩) / [p(⟨tool-token⟩) + p(best non-tool token)]
```
Plotted against cognition confidence to test whether mismatch occurs near uncertainty regions (σ ≈ 0.5) — it does not; mismatch persists even at σ ≈ 0 or σ ≈ 1.

### 1.7 Datasets

- **Arithmetic:** 4,000 synthetic problems in 3 difficulty groups (easy, larger-short, multi-step) with 13 algorithmic generators
- **TruthfulQA:** 817 factual QA instances
- **Models:** Qwen3-8B, Qwen3-4B, Llama-3.1-8B-Instruct, Llama-3.2-3B-Instruct

## 2. Results

### 2.1 End-to-End Necessity-Action Mismatch (Table 1)

| Model | Arithmetic Mis. | TruthfulQA Mis. |
|---|---|---|
| Qwen3-8B | 41.7% | 31.1% |
| Qwen3-4B | 26.5% | 41.8% |
| Llama-3.1-8B-Instruct | 38.5% | 30.8% |
| Llama-3.2-3B-Instruct | **54.0%** | 32.8% |

Mismatch ranges: **26.5–54.0%** (Arithmetic), **30.8–41.8%** (TruthfulQA).

### 2.2 Dominant Failure Modes (Table 1 breakdown)

- **Arithmetic:** Qwen3-8B overuses tools (UN-C: 38.2% vs N-NC: 3.5%). Both Llama models underuse tools (N-NC: 30.1% and 39.0%).
- **TruthfulQA:** Qwen3-8B reverses to underuse (N-NC: 17.9%). Qwen3-4B reverses to overuse (UN-C: 23.1%). Models are **not consistently biased** — failure mode is domain-dependent.

### 2.3 Necessity Probe MCC (Figure 3)

- **Arithmetic:** Broad mid-to-late-layer regions achieve MCC ≥ 0.4 across all models. Necessity is linearly separable.
- **TruthfulQA:** MCC ≥ 0.4 only in narrow near-last-token, mid-late-layer regions for Llama models. Qwen models much weaker. Surface form in factual QA provides little cue about difficulty.

### 2.4 Action Probe MCC (Figure 4)

Action is **highly separable** across nearly all (t, l) positions on both datasets, with broad regions of MCC ≥ 0.4 and peaks exceeding 0.75 in late layers / last tokens.

### 2.5 Cosine Similarity w_c vs w_a (Figure 5)

- Partial alignment (CosSim ~0.3–0.6) exists in intermediate token-layer positions for Qwen models on Arithmetic.
- **Alignment collapses to near-zero** (orthogonal) at t=-1, late layers for all models — the exact position driving the next-token decision.

### 2.6 Error Attribution (Figure 6 — Sankey diagrams)

**The orange flow (stage-2-only error) dominates all panels.** The red flow (stage-1-only error) is thin. The end-to-end mismatch is overwhelmingly produced in cognition→action transition, not in cognition formation.

### 2.7 Confidence vs Mismatch (Figure 7)

Cognition-execution mismatch points (orange) appear across the full range of σ(w_c h + b_c), including near 0 and 1. **Mismatch is not driven by low metacognitive confidence.**

### 2.8 Explicit Prompting Results (Appendix B, Table 3)

When explicitly prompted for self-assessment ("Is a tool necessary? yes/no"):
- MCC between explicit judgment and actual necessity is poor (Llama-3.1-8B: 0.0712 Arithmetic, undefined on TruthfulQA; Llama-3.2-3B: **negative MCC** -0.04 on TruthfulQA)
- Up to **49.27%** of samples change tool-call behavior vs. task-oriented prompts
- Explicit self-assessment probes diverge significantly from real deployment behavior

## 3. Trade-offs

| Win | Lose |
|---|---|
| Model-adaptive necessity definition captures per-model capability boundaries, unlike static labeling | Requires N=10 inference runs per query to ground necessity — computationally expensive to scale |
| Two-stage decomposition isolates the knowing-doing gap as the bottleneck (not metacognition) | Linear probing is a coarse proxy; cognition may be partially non-linear or distributed |
| Reveals that improving metacognition alone won't fix tool-use reliability — execution translation must also improve | Probe directions becoming orthogonal at late layers is an observation, not a causal proof |
| Action is highly linearly decodable across models (MCC up to 0.75+), suggesting simple steering interventions | Results limited to open-weight 3B–8B models; closed-source frontier models may behave differently |
| Using MCC instead of accuracy handles class imbalance robustly | N=10, T=0.7 is one instantiation; sensitivity to these hyperparameters is unexplored — the authors note this as a limitation |
| Sankey flow attribution cleanly quantifies stage-2 dominance | Explicit self-assessment prompts change behavior on up to ~50% of samples, so probing is necessary — but probing is unavailable for closed-source models |
| Domain-dependent failure modes (overuse vs underuse) argue against one-size-fits-all fixes | No intervention or mitigation method is proposed — purely diagnostic |

---

## 4. Design Rationale

**Why model-adaptive necessity:** Prior work (MetaTool, SMART, ACL 2025 adaptive-tool-use) annotated tool necessity once for all models using a strong LLM judge. This conflates the judge's capability with the tested model's capability. The authors argue that a query solvable by GPT-4 without tools may still require tools for Llama-3B — necessity must be relative. Their empirical grounding via N-shot no-tool inference provides a principled, reproducible criterion.

**Why two-stage decomposition:** End-to-end mismatch alone tells us there is a problem but not where. By separating cognition (internal belief) from execution (action), the authors can localize failures. Stage 2 dominance implicates the decoding/syntax layer rather than the semantic understanding layer.

**Why linear probing over explicit prompting:** Appendix B shows explicit "Is a tool needed? yes/no" prompts yield poor MCC (even negative for some models) and alter behavior on up to 49% of samples. Probing hidden states avoids the task-switching confound and measures subconscious belief.

**Why cosine similarity between probe directions:** Orthogonality of w_c and w_a at the readout position provides a geometric explanation for the knowing-doing gap: the features used for cognition and action occupy nearly independent subspaces where it matters most.

---

## 5. Limitations & Failure Modes

1. **N=10, T=0.7 is a single instantiation.** The sensitivity of mismatch rates to different N and T values is untested. The authors explicitly note this as a limitation (Appendix C).
2. **Open-weight models only (3B–8B).** Probing requires hidden state access, making the method inapplicable to GPT-4, Gemini, Claude, or any API-only model. The knowing-doing gap may differ in scale or nature for frontier models.
3. **Linear probes are a coarse tool.** Non-linear or distributed representations of cognition are not captured. Probe performance (MCC 0.3–0.5 on TruthfulQA) suggests substantial unmeasured signal.
4. **Correlation, not causation.** Orthogonality of w_c and w_a at late layers describes the geometry but does not prove that this orthogonality *causes* the mismatch. Intervention experiments (e.g., activation steering) are absent.
5. **No mitigation proposed.** The paper is purely diagnostic; it identifies the knowing-doing gap and localizes it to the cognition→action transition, but offers no intervention (e.g., representation steering, fine-tuning, or prompting strategy) to close the gap.
6. **Two-domain scope.** Only arithmetic and factual QA are tested. Tool-use in code generation, API orchestration, or multi-turn agent workflows may exhibit different patterns.
7. **Greedy decoding for action collection.** While justified for diagnostic clarity, real deployments use temperature sampling which introduces stochasticity not captured here.

## 6. Transfer to Lyra

**The one transferable idea:** The cognition-execution decomposition and the finding that tool-use failures are dominated by the execution stage (not metacognition) directly applies to Lyra's tool-call architecture. Lyra should **separately measure and optimize the cognition (should-I-call) and execution (do-I-call) paths**, rather than treating tool-use as a monolithic decision. A lightweight linear probe could serve as a runtime guard: if the cognition probe says "call tool" but the action probe says "don't call" (knowing-doing gap detected), route to a fallback or explicit self-assessment prompt.

**Workstream route:** §4.3 (Tool-Use Reliability / Execution) — this finding feeds the adaptive tool-calling reliability workstream by showing that fixing metacognition alone is insufficient; the translation from belief to action is the main bottleneck.

| Dimension | Value |
|---|---|
| **Impact** | 4 (directly diagnoses a core failure pattern in agent tool-use; the geometric orthogonality finding is actionable for steering/intervention) |
| **Effort** | 4 (requires implementing hidden-state probing infrastructure, per-model calibration, and integration with Lyra's tool-call pipeline) |
| **Tier** | **investigate** — diagnostic insight is strong and actionable, but no concrete intervention is provided; value depends on Lyra-specific probing results and steering experiments before full adoption |
