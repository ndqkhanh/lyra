## 1. Mechanism (Step-by-Step)

τ-Voice extends τ²-bench into a full-duplex voice agent benchmark by introducing three components:

### 1.1 Tick-Based Full-Duplex Orchestrator

The orchestrator discretizes continuous audio streams into fixed-duration ticks (τ = 200ms default). Each tick, both parties (agent and user simulator) exchange exactly τ ms of audio, enabling simultaneous bidirectional speech.

**Buffer Formalism (for agent side):**
```
aᵗ = (Bᵗ⁻¹ ⊕ ãᵗ)[0 : τ]           (Equation 1)
Bᵗ = ∅ if interrupted, else (Bᵗ⁻¹ ⊕ ãᵗ)[τ:]  (Equation 2)
```
Where ãᵗ is audio streamed by the API during tick t's wall-clock duration, Bᵗ is the output buffer, and ⊕ denotes concatenation. On interruption, the buffer is cleared, truncating the agent's in-progress response.

**Proportional Text Distribution:** For each utterance, transcript text T is distributed proportionally to audio duration:
```
Tᵗ = T[0 : (A_playedᵗ / A_total) · |T|]
```
This prevents premature turn-taking decisions based on text that has not yet "been spoken."

**Linearization Algorithm:** Overlapping full-duplex speech is converted to sequential messages using rules:
- No overlap: chronological order
- Partial overlap: ordered by start time
- Containment (X inside Y): split Y at X's end, insert X there

**Key innovation:** Simulation time is decoupled from wall-clock time. This breaks the real-time constraint for the user simulator, allowing it to use the most capable LLM (GPT-4.1) without real-time pressure, ensuring reliable instruction following and turn-taking decisions. Crucially, voice agent APIs (OpenAI Realtime, Gemini Live, xAI Grok) index events on audio time rather than wall-clock time, so audio can be sent faster/slower than real-time and the API processes it correctly.

### 1.2 Voice User Simulator Pipeline

Four-stage pipeline (Figure 3):

1. **Text Generation:** User simulator LLM produces natural spoken language with disfluencies ("um", "uh"), fillers, verbalized special characters ("at" not "@"), and terse responses (minimal verbosity mode). System prompt includes rules for spelling characters/numbers with comma-separated letters ("M, E, I"), handling agent silence, and information disclosure strategies.

2. **Speech Synthesis:** Generated text → TTS via ElevenLabs v3 at 24kHz, using 7 voice personas (2 Clean: American accents; 5 Realistic: Bengali, Sichuan Mandarin, French-accented, Maharashtrian Indian English, elderly American).

3. **Audio Environment Simulation:** Three parallel effects applied:
   - **Background noise:** Continuous (chatter, traffic) at 15 dB SNR with ±3 dB drift
   - **Burst noise:** Poisson process at 1.0 events/min (phone rings, dog barks, car horns, engines, sirens) at -5 to +10 dB SNR per event
   - **Out-of-turn speech:** Poisson process at 0.7 events/min — non-directed phrases ("hold on", "give me a moment") and vocal tics (coughs, sneezes)
   - **Dynamic muffling:** 20% per-utterance probability simulating movement away from mic
   - **Telephony degradation:** G.711 μ-law compression at 8kHz
   - **Frame drops:** Gilbert-Elliott two-state Markov model (Good state: 0% loss; Bad state: 20% loss; 2% avg loss rate, 100ms burst, removes 150ms per event)

4. **Turn-Taking Dynamics:**
   - **Wait-to-respond:** 1.0s silence threshold from agent before user responds
   - **Interruption:** LLM-based decision every 2.0s evaluating conversation context (has user heard enough? did agent complete key info?)
   - **Backchannel:** Separate LLM decision every 2.0s with strict frequency guidance (1 per 4-6 sentences); emits "mm-hmm", "uh-huh", "yeah"
   - **Yield policy:** 1.0s overlap when interrupted; 5.0s when interrupting

### 1.3 Evaluation Architecture

**Transcript Injection Optimization:** The simulator receives agent transcripts directly (bypassing ASR on the agent side), ensuring evaluation isolates agent behavior from transcription errors. Annotators found agent speech intelligible in 100% of 91 sampled simulations.

**Task Completion (pass@1):** Deterministic comparison of final database state vs. gold standard, following τ²-bench methodology. Tasks require verifiable state changes (e.g., order status, address fields).

**Voice Interaction Quality Metrics (4 dimensions):**
- **Latency (↓):** Response Latency L_R (time from user utterance end to agent response) + Yield Latency L_Y (time to stop speaking after interruption)
- **Responsiveness (↑):** Response Rate R_R (proportion of user turns receiving response) + Yield Rate R_Y (proportion of interruptions where agent yields within 2s)
- **Interrupt (↓):** Agent Interruption Rate I_A (proportion of turns where agent speaks before user finishes; >100% = multiple interruptions per turn)
- **Selectivity (↑):** Correctly ignoring backchannels S_BC, vocal tics S_VT, and non-directed speech S_ND (yield window 1.0s, response window 2.0s)

### 2.2 Ablation — Impact of Acoustic Factors (Retail domain only)

| Condition | Google | OpenAI | xAI | Avg Δ |
|-----------|--------|--------|-----|-------|
| Clean | 45% | 71% | 48% | 55% |

### 2.3 Voice Interaction Quality (Realistic, aggregated across domains)

| Provider | Latency↓ | Responsiveness↑ | Interrupt↓ | Selectivity↑ |
|----------|----------|-----------------|------------|-------------|
| Google | 1.14s | 69% | 21% | 54% |
| OpenAI | **0.90s** | **100%** | **14%** | 6% |
| xAI | 1.15s | 83% | 84% | **57%** |

**No provider excels at everything.** OpenAI: fastest + most responsive but worst selectivity (responds to 94% of backchannels/tics). xAI: best selectivity but interrupts on 84% of turns (nearly once per turn). Google: lowest interrupt rate but misses 31% of user turns.

### 2.4 Error Analysis (91 failed simulations)

- **Voice-Fragile cohort:** 79% agent errors (34/43); 21% user errors
- **Noise-Fragile cohort:** 90% agent errors (43/48); 10% user errors
- Top error types: Logical (29 total), Transcription (26 total), Hallucination (12 total)
- Inter-rater agreement: 84% initially, 100% after discussion

### 2.5 Statistical Significance

Paired permutation tests (100k permutations, Holm-Bonferroni corrected, 2 runs Retail domain):
- All text→Clean gaps significant (p < 0.001 for Google/xAI; p = 0.032 for OpenAI)
- All Clean→Realistic gaps significant (p < 0.001 OpenAI; p = 0.026 Google; p = 0.044 xAI)

## 3. Trade-offs (Wins vs Loses)

| Dimension | Win | Lose/Cost |
|-----------|-----|-----------|
| **Evaluation Scope** | First benchmark combining task completion + full-duplex + realistic audio in one system | Only 278 tasks; English-only; TTS not recorded speech; no non-English accents besides the 5 personas |
| **Tick-Based Orchestrator** | Fine-grained control over all simulation parameters; reproducibility; enables systematic ablations | Decouples from wall-clock time — may miss real-time pressure effects on agent behavior (authors validated this separately with artificial 5s delays and found no adverse effects) |
| **Transcript Injection** | Isolates agent behavior from ASR errors on agent side; 100% intelligibility in sampled runs | Overestimates agent capability relative to real-world where STT errors cascade; cannot benchmark cascaded ASR→LLM→TTS systems |
| **LLM-Based Turn-Taking** | Richer, context-aware interruption/backchannel decisions vs. threshold-only baselines | Adds non-determinism; LLM decisions may differ from human turn-taking patterns |
| **Realistic Audio Simulation** | Controllable SNR, burst rates, frame drops for systematic ablation | G.711 at 8kHz is narrower than modern VoIP codecs; Poisson processes may not capture real noise burst clustering |
| **Provider Comparison** | Head-to-head comparison reveals architectural tradeoffs (speed vs selectivity vs task completion) | Only audio-native APIs (no cascaded baselines); models all released within 3 months of each other (late 2025-Feb 2026) |
| **Deterministic Evaluation** | Database-state verification eliminates evaluator subjectivity for task completion | No partial credit for near-misses; binary pass/fail may obscure meaningful partial progress |

## 4. Design Rationale

The core insight driving τ-Voice is that existing benchmarks suffer from a **dimensional incompleteness problem**: task-completion benchmarks (τ-bench, τ²-bench) evaluate grounding without voice; conversational dynamics benchmarks (Full-Duplex-Bench) evaluate turn-taking without real tasks. τ-Voice argues these must be evaluated together because **voice compounds task difficulty in ways text does not** — speech lacks punctuation, contains fillers/disfluencies, requires verbal encoding of special characters, and acoustic degradation creates cascading errors across turns.

The tick-based design (rather than real-time streaming) was chosen for **controllability and reproducibility**: "By decoupling simulation time from wall-clock time, our user simulator can use the most capable LLM without real-time constraints." This allows systematic ablation of individual factors (noise, accents, turn-taking separately) that would be impossible in a real-time system. The authors tested this decision by injecting artificial 5-second response delays — observing no adverse effects on agent behavior, validating the design choice.

The transcript injection choice (bypassing ASR on agent output side) was validated: annotators confirmed agent speech was intelligible in 100% of 91 sampled simulations, suggesting minimal impact on evaluation validity while simplifying the testbed.

## 5. Limitations & Failure Modes

1. **English-only with synthetic speech:** All evaluation uses English with TTS rather than recorded human speech. Accent findings via TTS personas are "indicative rather than definitive" (authors' own caveat). No non-English languages tested.

2. **Transcript injection overestimates real-world capability:** By feeding agent transcripts directly to the simulator (bypassing ASR), τ-Voice systematically overestimates agent performance vs. real-world deployment where both sides require ASR. The 79-90% agent-attributed error rate should be lower if STT→LLM→TTS pipelines were used.

3. **Simplified simulator fidelity:** The user simulator has perfect memory, instantaneous tool calls, and is more patient than real users. No user satisfaction, agent speech quality (tone, naturalness), or partial task success metrics. The p95 simulator processing time is ~1.5s — authors argue this is within conversational tolerance.

4. **No cascaded system baselines:** Only audio-native APIs (OpenAI Realtime, Gemini Live, xAI Grok) are evaluated. No ASR→LLM→TTS cascaded baselines, making it impossible to isolate whether the voice-text gap stems from the audio modality per se or from the architecture choices of audio-native models.

5. **Limited domain diversity:** Three domains (Retail, Airline, Telecom) all in customer service. Results may not generalize to other voice agent applications (healthcare, education, home assistants).

6. **Non-determinism from LLMs:** Despite deterministic seeds for audio effects, both agent and simulator LLMs introduce output variance. The 2-run statistical analysis helps but does not fully characterize variance.

7. **Accessibility equity concerns:** The accent ablation reveals severe provider-specific disparities (xAI loses 38% relative on accented speech) — a fairness/equity issue that the benchmark exposes but does not solve. Models evaluated were released late-2025 to early-2026, so findings may quickly become outdated.

## 6. Transfer to Lyra

### The ONE Transferable Idea

**Tick-based discretization of continuous voice interaction for reproducible evaluation with systematic factor ablation.** τ-Voice's orchestration pattern — discretizing continuous audio into 200ms ticks, decoupling simulation time from wall-clock time, and making all conversational dynamics (interruptions, backchannels, noise, accents) independently parameterizable — is directly applicable to Lyra's §4 evaluation infrastructure. Lyra should adopt this pattern for its own voice modality testing: a tick-based test harness that allows turning individual voice-realism factors on/off to isolate which capabilities degrade under which conditions.

### Workstream Route: §4.5 (Evaluation & Benchmarking)

τ-Voice feeds the evaluation infrastructure workstream. Specifically:
- The tick-based orchestrator provides a blueprint for Lyra's voice agent evaluation harness
- The 4-dimensional voice interaction quality framework (Latency, Responsiveness, Interrupt, Selectivity) is an immediate metric template
- The ablation methodology (Clean → +Noise → +Accents → +Turn-taking → Realistic) is a proven evaluation design pattern

### Impact/Effort/Tier

- **Impact: 3** — Voice evaluation is peripherally relevant to Lyra's core text-agent architecture, but the evaluation methodology pattern (controlled factor ablation) is broadly applicable beyond voice
- **Effort: 4** — Implementing a tick-based voice orchestrator requires audio pipeline integration (TTS, environment simulation, turn-taking logic) and voice API adapters; significant engineering
- **Tier: Investigate** — Not a parity requirement, but worth studying for Lyra's evaluation infrastructure design patterns. The tick-based discretization + factor ablation methodology is the transferable insight, not the voice-specific implementation.
