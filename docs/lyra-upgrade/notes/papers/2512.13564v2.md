## 1. Mechanism

The paper proposes a unified three-lens taxonomy for agent memory: **Forms** (what carries memory), **Functions** (why agents need memory), and **Dynamics** (how memory operates and evolves). This replaces the conventional long-term/short-term dichotomy that the authors argue is insufficient for capturing the diversity of 2024–2025 memory mechanisms.

### 1.1 Forms (Section 3): What Carries Memory?

Three principal representational forms:

**A. Token-level Memory** — Information stored as explicit, discrete, externally accessible units (text chunks, dialogue logs, experience trajectories, vector embeddings). Organized by topological complexity:
- *Flat (1D)*: No inter-unit topology. Memories accumulated as sequences or bags of units. Example: MemGPT's operating-system metaphor with Main/External contexts; Reflexion's trajectory-as-short-term + feedback-as-long-term. Fast to append/prune, weak on compositional reasoning.
- *Planar (2D)*: Single-layer structured organization via graphs, trees, or tables. Relations encoded within one plane without cross-layer references. Example: A-Mem's card-based connected memory network; Ret-LLM's triple-based relation-centric tables; MemTree's dynamic hierarchical conversation trees.
- *Hierarchical (3D)*: Multi-layer interlinked structures supporting vertical abstraction. Coarse-to-fine retrieval across abstraction levels. Example: GraphRAG's multi-level community graph indices; HippoRAG's associative indexing KG + passage store; G-Memory's three-tier insight/query/interaction graphs; HiAgent's subgoal-centered hierarchical working memory.

**B. Parametric Memory** — Information encoded in model parameters:
- *Internal*: Embedded directly in model weights via pre-training (LMLM stores retrieval ability), mid-training (Early Experience integrates agent trajectories), or post-training (SELF-PARAM uses KL-divergence distillation without extra parameters). Simple structure, no inference overhead, but requires retraining to update → catastrophic forgetting risk.
- *External*: Stored in auxiliary parameter sets (adapters, LoRA modules, auxiliary LMs). Example: WISE's dual-parameter memory with routing; MemLoRA for on-device; Retroformer's RL-trained auxiliary LM for memorizing successes/failures. Modular, updatable without touching base weights, but influence is indirect.

**C. Latent Memory** — Information carried in internal hidden states (KV cache, activations, embeddings). Three origins:
- *Generate*: Auxiliary models synthesize embeddings to interfere/augment LLM forward pass. Example: Gist tokens compress long prompts; Titans compresses long-range info into online-updated MLP weights; MemGen dynamically generates latent memory fragments via LoRA adapters.
- *Reuse*: Directly propagate prior computational states (KV-cache reuse). Example: Memorizing Transformers with external KV-cache + KNN retrieval; LONGMEM's residual SideNet for persistent KV storage.
- *Transform*: Compress/restructure existing latent states. Example: SnapKV aggregates high-importance prefix KV; PyramidKV reallocates KV budgets across layers; H2O retains only heavy-hitter tokens.

### 1.2 Functions (Section 4): Why Agents Need Memory?

**A. Factual Memory** — Declarative knowledge base for consistency, coherence, adaptability:
- *User factual memory*: Dialogue coherence (MemGPT, MemoryBank, RMM) and goal consistency (RecurrentGPT, A-Mem, M3-Agent)
- *Environment factual memory*: Knowledge persistence (HippoRAG, LMLM, WISE, Zep) and shared access for multi-agent systems (MetaGPT, G-Memory, OASIS)

**B. Experiential Memory** — Procedural knowledge for continual learning and self-evolution, classified by abstraction level:
- *Case-based*: Store raw trajectories/solutions (ExpeL, Memento, JARVIS-1)
- *Strategy-based*: Abstract experiences into workflows/patterns/insights (AWM, ReasoningBank, H2R, PRINCIPLES)
- *Skill-based*: Distill into executable functions/APIs/MCPs (Voyager, LEGOMem, SkillWeaver, ToolGen, Alita with MCP protocol)
- *Hybrid*: Integrate multiple representations (G-Memory, MemEvolve)

**C. Working Memory** — Capacity-limited scratchpad for active context management:
- *Single-turn*: Input condensation (LongLLMLingua, AutoCompressor), observation abstraction (Synapse, VideoAgent)
- *Multi-turn*: State consolidation (MemSearcher, IterResearch, ReSum), cognitive planning (PRIME, Agent-S), hierarchical folding (Context Folding, AgentFold, DeepAgent)

### 1.3 Dynamics (Section 5): How Memory Operates and Evolves

Formalized as three operators acting on a memory state Mt:

**Memory Formation** F(Mt, φt) → Mform_{t+1}: Selectively transforms interaction artifacts φt (tool outputs, reasoning traces, environmental feedback) into memory candidates. Five mechanisms:
1. *Semantic Summarization*: Compress raw interactions into concise natural-language summaries
2. *Knowledge Distillation*: Extract structured triples, entity relations, or graph edges
3. *Structured Construction*: Build hierarchical schemas, tree indices, or relational graphs
4. *Latent Representation*: Encode into continuous vectors or KV-cache entries
5. *Parametric Internalization*: Fine-tune model weights or adapters on accumulated experience

**Memory Evolution** E(Mform_{t+1}) → M_{t+1}: Integrates and maintains the memory base:
1. *Consolidation*: Merge redundant entries, resolve conflicts, abstract common patterns. Example: AriGraph's local→cluster→global consolidation; Zep's community partitioning on temporal knowledge graphs
2. *Updating*: Add new facts, modify obsolete entries, maintain temporal validity. Techniques include confidence-weighted merging and timestamp-based staleness checks
3. *Forgetting*: Remove low-utility information via importance scoring (recency + relevance + access frequency), decay curves (Ebbinghaus-inspired), or RL-trained pruning policies

**Memory Retrieval** R(Mt, oit, Q) → mit: Four-stage pipeline:
1. *Timing and Intent*: When to retrieve — proactive (at task boundaries), reactive (on contextual triggers), or continuous. Fast-slow thinking mechanisms for retrieval timing decisions
2. *Query Construction*: Transform observation + task into retrieval query (direct, decomposed, or LLM-generated)
3. *Retrieval Strategies*: Sparse (BM25), dense (vector similarity), hybrid (fusion of lexical + semantic), or graph-based (two-stage: semantic node identification + topological expansion)
4. *Post-Retrieval Processing*: Re-ranking/filtering (LLM-based evaluators, Q-learning predictors like Memento, fine-tuned rankers like MemGuide with LLaMA-8B), aggregation/compression (ComoRAG's Integration Agent, G-Memory's role-specific customization)

## 2. Results

This is a comprehensive **survey paper** (76 pages, ~400+ cited works) rather than an empirical contribution. It does not report original experimental results. Its primary outputs are taxonomical and analytical:

**Taxonomy Coverage**: The paper catalogs and systematically classifies over 200 agent memory methods across the three-lens framework. Representative methods are cross-indexed in detailed comparison tables (Tables 1-7) spanning:
- Token-level memory: 60+ methods (Table 1, 4 pages)
- Parametric memory: 25+ methods (Table 2)
- Latent memory: 30+ methods (Table 3)
- Factual memory: 35+ methods (Table 4)
- Experiential memory: 40+ methods (Table 5)
- Working memory: 25+ methods (Tables 6-7)

**Benchmark Landscape**: 27 memory-relevant benchmarks catalogued (Table 8) with scale, modality, and capability dimensions, including LongMemEval (500 samples), StreamBench (9,702 samples), LongBench (4,750 samples across 21 tasks), SWE-Bench Verified (466 samples), GAIA (100 samples), xBench (126,486 samples).

**Framework Landscape**: 20+ open-source memory frameworks compared (Table 9) including MemGPT, Mem0, MemOS, Zep, LangMem, Cognee, Memary, Chroma, and Pinecone, assessed by memory type support (factual/experiential), multimodality, and evaluation coverage.

**Key Taxonomic Insight**: The paper demonstrates that short-term/long-term distinctions are emergent from temporal invocation patterns of the unified Formation-Evolution-Retrieval operators, not from discrete architectural modules. Short-term memory emerges from lightweight within-task logging; long-term memory from cross-task episodic updating.

## 3. Trade-offs

| Dimension | Win | Cost/Loss |
|-----------|-----|-----------|
| **Token-level vs. Parametric** | Symbolic, addressable, transparent, auditable, easy to update/add/delete, plug-and-play with closed-source models, no catastrophic forgetting | Requires explicit retrieval infrastructure, context window consumption, retrieval quality dependent, redundancy/noise accumulation at scale |
| **Parametric (Internal) vs. External Parametric** | No inference overhead, no extra deployment cost, supports fluid end-to-end reasoning | Catastrophic forgetting, requires retraining for any update, poorly suited for rapid personalization |
| **Latent Memory (Generate/Reuse/Transform)** | Preserves fine-grained contextual signals, token-efficient, machine-native, convenient modality fusion, intrinsic privacy protection | Information loss during compression, drift/error accumulation over cycles, human-unreadable, hard to debug/audit, additional training overhead for generation modules |
| **Flat (1D) vs. Hierarchical (3D) Token Memory** | Simplicity, scalability, minimal append/prune cost | No relational reasoning, coherence depends on retrieval quality, poor compositional reasoning |
| **Hierarchical (3D) Token Memory** | Multi-level abstraction supports precise retrieval, cross-layer reasoning, richer knowledge encoding | Complex construction and maintenance, high retrieval latency, optimal 3D layout design remains unsolved |
| **Experiential (Strategy) vs. Experiential (Skill)** | Generalizable heuristics for planning across tasks | Performance sensitive to prompt design, less actionable than executable skills |
| **Experiential (Skill)** | Executable, verifiable, modular capability expansion | Requires well-defined tool interfaces, fragile to API changes |
| **RL-driven Memory vs. Heuristic/Prompt-driven** | Adaptive, self-optimizing, can discover novel memory organizations beyond human priors | Training complexity, reward design difficulty, currently limited to narrow task-specific objectives |
| **Retrieval-centric vs. Generative Memory** | Proven, well-understood, grounded in stored evidence | Static, cannot synthesize novel representations tailored to context |
| **Generative Memory** | Context-adaptive, can integrate heterogeneous signals, supports learned self-optimization | May hallucinate or lose grounding, less interpretable, generation quality depends on training |

## 4. Design Rationale

The authors argue that existing taxonomies (long-term/short-term, episodic/semantic/procedural) are **insufficient** for two reasons: (1) rapid 2025 methodological advances — such as memory frameworks distilling reusable tools from experience (Voyager, Alita), memory-augmented test-time scaling (Dynamic Cheatsheet, MemGen), and RL-trained memory managers (Mem-α, Memory-R1) — broke prior classification schemes; (2) **conceptual fragmentation** — papers claiming to study "agent memory" differ drastically in implementation, objectives, and assumptions, with proliferating terminologies (declarative, episodic, semantic, parametric, latent) obscuring clarity.

The "Forms–Functions–Dynamics" triangle is chosen because: Forms capture *representational* diversity (where memory lives), Functions capture *teleological* diversity (why memory exists), and Dynamics capture *operational* diversity (how memory changes over time). This three-axis decomposition allows any memory system to be located in a structured space, revealing that short-term/long-term distinctions are not architectural but **emergent from temporal invocation patterns** of the unified Formation-Evolution-Retrieval operators. The approach also explicitly distinguishes agent memory from related but distinct concepts: LLM memory (model-internal KV management), RAG (static external knowledge access), and context engineering (resource allocation for the context window).

## 5. Limitations and Failure Modes

1. **Taxonomy Boundaries Are Blurry**: The authors acknowledge that the boundary between token-level and latent memory blurs when latent representations are explicitly stored, and the boundary between parametric and latent memory blurs when learned encoders generate latent states. Some methods resist clean classification.

2. **No Empirical Validation**: As a pure survey, the taxonomy's utility is not empirically validated against alternative organizational schemes. No ablation studies compare classification schemes.

3. **Rapid Obsolescence Risk**: The field is evolving so quickly (the paper notes that many 2023–2024 taxonomies are already outdated) that sections of this survey may become stale within months. The authors explicitly invite updates via GitHub issues.

4. **Selection Bias**: Despite claiming comprehensiveness, the survey acknowledges potential omissions due to the rapidly expanding literature. Coverage skews toward English-language, arXiv-accessible work.

5. **Missing Quantitative Cross-Comparison**: The paper does not provide head-to-head benchmark comparisons of different memory architectures, leaving practitioners without clear performance guidance for architectural decisions.

6. **Limited Treatment of Failure Modes**: While Section 7.7 addresses trustworthiness (privacy leakage via prompt-based attacks, hallucination in retrieved memory, lack of explainability), systematic analysis of failure modes (e.g., memory corruption cascades, retrieval-decision mismatches causing silent failures, context pollution from stale memories) is distributed and not consolidated.

7. **Cognitive Science Mapping May Overfit**: The explicit mapping to human cognitive constructs (Atkinson-Shiffrin model, Tulving's episodic/semantic/procedural taxonomy, CLS theory) may constrain thinking about artificial memory architectures that could benefit from non-biologically-inspired designs.

## 6. Transfer to Lyra

**The One Idea**: Apply the **Forms–Functions–Dynamics (FFD) framework** as a design rubric for structurally evaluating and architecting Lyra's memory subsystem. Rather than ad-hoc memory design (which the survey shows is the dominant anti-pattern), Lyra should explicitly answer three questions for each memory component: (1) **Form** — should this knowledge live as tokens (auditable, pluggable), parameters (efficient, internalized), or latents (dense, private)? (2) **Function** — is this serving factual recall, experiential self-improvement, or working-memory scratchpad? (3) **Dynamics** — what are the explicit Formation, Evolution, and Retrieval operators?

**Concrete implications for Lyra**:
- Lyra's current memory (if largely token-level/flat) should adopt at minimum a **Planar (2D) or Hierarchical (3D) organization** with explicit inter-unit relational topology (graph or tree), as the survey demonstrates that flat memory degrades under scale
- Lyra should implement a **separate Experiential Memory pipeline** (not just factual RAG) that distills task trajectories into case/strategy/skill abstractions, enabling genuine self-evolution across research sessions
- Lyra's retrieval should adopt the **four-stage pipeline** (timing → query construction → retrieval strategy → post-retrieval processing) with explicit re-ranking, rather than naive top-k similarity
- For multi-agent Lyra configurations, adopt **G-Memory-style hierarchical shared memory** with role-specific customization of retrieved experiences
