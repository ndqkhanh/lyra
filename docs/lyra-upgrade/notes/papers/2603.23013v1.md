# Knowledge Access Beats Model Size: Memory Augmented Routing for Persistent AI Agents

**Authors:** Xunzhuo Liu (vLLM Semantic Router Project), Bowei He (MBZUAI/McGill, corresponding), Xue Liu (vLLM Semantic Router/MBZUAI/McGill/Mila), Andy Luo (AMD), Haichen Zhang (AMD), Huamin Chen (Red Hat)

**Venue:** arXiv preprint 2603.23013v1 (2026)

**ArXiv ID:** 2603.23013

## 1. Mechanism

The paper proposes a **compound memory-augmented routing strategy** with three components co-located in a routing layer between clients and inference backends:

### 1.1 Cross-Model Memory Injection

```
After each inference call:
  Store(turn_pair) → Milvus vector DB
  Record: {
    text: "[timestamp] Q: <user_query> / A: <model_response>",
    embedding: Matryoshka representation model at full transformer depth,
    user_id: for multi-tenant isolation
  }
  Partitioned by user
```

Memories are **verbatim turn-pairs** (not LLM-generated summaries), avoiding the hallucination risk that causes RAG poisoning when summaries contain fabricated content.

### 1.2 Hybrid Retrieval

At query time, two parallel searches execute:

```
1. Dense search: embed query → cosine similarity against stored embeddings → top-k_d
2. Sparse search: BM25 keyword matching → top-k_s
3. Fusion: reciprocal rank fusion (RRF) combines ranked lists → final top-k
```

Rationale: Dense retrieval captures semantic similarity (e.g., "marital status" ↔ "seeing anyone"); BM25 captures lexical matches (e.g., entity names, dates, technical terms). They are complementary.

### 1.3 Confidence-Based Routing

After the small model (8B) generates a response with injected memory context:

```
Normalized Sequence Probability (NSP):
  NSP = exp( (1/N) * Σᵢ max(log p(tᵢ|t_{<i}), ℓ_min) )

Where:
  N = number of output tokens
  p(tᵢ|t_{<i}) = model's probability for token i given prior tokens
  ℓ_min = -3.0 nats (safety floor to bound sensitivity)

Routing decision:
  if NSP ≥ τ (τ=0.50): ACCEPT 8B answer (cheap path)
  else: ESCALATE to 235B model (expensive path)
```

The threshold τ controls the cost-quality tradeoff. The floor ℓ_min prevents a single low-probability token from dominating the geometric mean.

### 1.4 The Compound Effect

Memory and routing address **orthogonal failure modes**:

- **Routing alone**: 96% of queries stay on 8B, but only 13.0% F1 — the model is confidently wrong about user-specific facts.
- **Memory alone**: Factual grounding but no cost savings — every query pays the fixed per-token rate.
- **Compound**: Routing provides cost savings (96-100% on cheap path); memory ensures those savings come with quality (30.5% F1). Memory transforms "confidently wrong" into "confidently right" without changing routing decisions.

Two prerequisites for synergy: (1) retrieved memories must be relevant and faithful (no RAG poisoning), and (2) confidence signal must be calibrated (log-probabilities must increase when model receives useful context).

|-----------|-----------------|----------------|-----------|---------------|-----|

**Key numbers:**
- Compound achieves **30.5% F1** vs cold 8B at 15.4%: **+15.0 point gain**
- Recovers **69%** of full-context 235B quality (43.9%)

- Single-hop gains: **+28.9 F1** (largest category improvement)
- Temporal reasoning: **-3.8 F1** (memory is counterproductive here)
- Routing: **96% of cold queries** stay on 8B with τ=0.50; with memory, **100%** stay on 8B

## 3. Trade-offs

| Wins | Losses |
|------|--------|
| +15.0 F1 over cold 8B (2× quality) | Temporal reasoning degrades (-3.8 F1 vs cold 8B) |
| 96% cost reduction vs cold 235B | Memory injection adds 1.5-10× input tokens |
| 100% on cheap path with memory | Only tested on one model family (Qwen3) |
| Zero training, zero labeled data | Requires log-probability access (not all APIs expose this) |
| Cross-model memory transfer (large→small) | Cold-start trajectory uncharacterized |
| Improves over time as memory accumulates | Verbatim storage grows unboundedly |
| Simple deployment (single routing layer) | Memory fidelity prerequisite — LLM summaries hurt performance |
| Hybrid retrieval adds +7.7 F1 on LongMemEval | BM25 degrades some categories (multi-session: -2.2, assistant: -3.0) |
| Confidence signal already available (no classifier training) | Log-probabilities can be miscalibrated |

## 4. Design Rationale

**Why verbatim turn-pairs, not LLM summaries:** Preliminary experiments showed LLM-generated memory summaries hurt performance via RAG poisoning — hallucinated content in memories compounds with retrieval noise. Verbatim recording guarantees faithfulness (the original conversation actually happened). This has an architectural implication: the routing layer must observe and store actual request-response pairs, not post-process them.

**Why hybrid retrieval (BM25 + cosine):** Dense embeddings capture semantic similarity ("marital status" ↔ "seeing anyone") but miss exact keyword matches (names, dates, technical terms). BM25 provides the complementary signal. The +7.7 F1 gain on LongMemEval validates this design. Reciprocal rank fusion avoids needing labeled data to learn combination weights.

**Why confidence routing, not a classifier:** A trained router would require labeled escalation data for every deployment. The model's own log-probabilities are always available and require zero training. The key insight is that confidence values don't need to change for routing to work — what matters is that the answer behind the confidence is correct (which memory provides).

**Why small model + memory > large model alone:** Cold 235B (13.7% F1) performs worse than cold 8B (15.4% F1). The large model cannot fabricate its way to user-specific knowledge. Model size determines the ceiling; memory determines how much knowledge is available. For personalization workloads, knowledge access is the binding constraint.

**Why the compound strategy is synergistic:** The 2×2 factorial (memory × routing) reveals routing doesn't enable memory and memory doesn't enable routing — they address orthogonal failures. Routing provides cost savings; memory provides quality. Together they achieve what neither can alone.

## 5. Limitations & Failure Modes

1. **Temporal reasoning degrades (-3.8 F1):** Turn-pair memories are flat temporal snapshots. The model struggles to reason about when facts became true/false, especially when multiple memories conflict (e.g., "Caroline was single in May" vs "Caroline got married in June"). Structured temporal memory representations are needed.

2. **Cold-start trajectory uncharacterized:** Both benchmarks evaluate steady-state scenarios with full memory stores. The paper does not measure how quickly memory accumulates to sustain the synergy, how many queries are needed before the compound strategy becomes effective, or the performance curve during memory bootstrap.

3. **Single model family evaluation:** Only Qwen3-8B and Qwen3-235B were tested. The compound effect may vary across model families with different confidence calibration properties.

4. **Log-probability miscalibration:** The confidence routing relies on the model's own log-probabilities, which are known to be miscalibrated in many LLMs. A miscalibrated model may produce high confidence for wrong answers even with memory, or low confidence for correct answers, breaking the compound synergy.

5. **LoCoMo uses a single conversation:** Only one user's conversation is evaluated, limiting generalization to diverse user profiles and conversation styles.

6. **LongMemEval uses stratified 100-question sample:** Full routing pipeline (retrieve → inject → probe → route) only runs on a subset, potentially missing edge cases.

7. **No production-scale evaluation:** All results are on academic benchmarks. Real user traffic with distribution shift, adversarial queries, and evolving conversation patterns remains untested.

8. **Multi-hop ceiling:** Performance is bounded by top-k retrieval. Questions requiring synthesis across many facts remain challenging (+12.0 F1 gain but still only 20.8% absolute).

9. **Memory store grows unboundedly:** Verbatim turn-pair storage has no pruning or summarization mechanism. At production scale (3M queries/month), the vector database will grow linearly without bound.

10. **Single-language, single-domain:** English-only conversations; the effect on multilingual or code-switching conversations is unknown.

## 6. Transfer to Lyra

**The One Transferable Idea:** For persistent AI agents handling user-specific queries, **compound memory-augmented routing** — where raw conversation turn-pairs are stored, retrieved via hybrid search (BM25 + dense), injected into a cheaper inference path, and gated by the model's own confidence — delivers 2× quality at 1/25th the cost of a large model. The core insight is that **access to conversational knowledge matters more than model scale** for personalization: a small model with retrieved user context outperforms a large model without it.

**Workstream Route:** §4.2 Memory (conversational memory architecture). The paper directly validates Lyra's memory subsystem design with concrete architectural requirements: verbatim turn-pair storage, hybrid retrieval, confidence-gated routing, and cross-model memory amortization.

**Impact:** 4 (directly improves core memory and routing architecture; quantified cost-quality gains; training-free)

**Effort:** 3 (requires: vector DB with hybrid search, log-probability extraction from inference backend, confidence threshold calibration, prompt template for memory injection — all well-defined engineering components with existing open-source implementations)

**Tier:** **breakthrough** — The compound memory+routing synergy with 2×2 factorial ablation is novel, practically validated on two benchmarks, and directly applicable to Lyra's persistent agent architecture. The finding that cold 235B underperforms cold 8B (both without memory) fundamentally reframes the cost-quality tradeoff for personalization agents.
