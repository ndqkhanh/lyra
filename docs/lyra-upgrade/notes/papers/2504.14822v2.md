## 1. Mechanism (step-by-step)

InsightAgent accelerates systematic reviews (SRs) through a three-stage human-centered multi-agent pipeline with an interactive graphical interface.

### Stage 1: Corpus Mapping & Partitioning

1. **RSS Map Projection**: Each article in the corpus is projected as a dot in a radial-based relevance and similarity (RSS) map. Position is determined by:
   - **Relevance to research question**: More relevant articles appear closer to the center.
   - **Semantic similarity**: Semantically similar articles are placed in nearby regions.

2. **Corpus Partitioning**: K-means clustering partitions the corpus into semantically distinct clusters. The optimal number of clusters k is automatically determined by the **Elbow method** (evaluating within-cluster and inter-cluster distances). Across evaluations, the average is 9 clusters.

### Stage 2: Reading and Evidence Synthesis (Multi-Agent)

3. **Agent Initialization**: Each agent receives:
   - A research question `Qi`
   - Inclusion/exclusion criteria (e.g., study type)
   - A summarization requirement (level of detail, analytic focus)
   - Assignment to one cluster + optional reading focus

4. **Record Screening**: Each agent explores from the RSS map center (most relevant) outward. At each step, the agent selects the next article from a **receptive field of 8 nearest neighbors**. This ensures systematic, coherent exploration.

5. **Incremental Evidence Synthesis**: For each relevant article, the agent generates a summary `Sj`. This is merged with existing knowledge using a memory mechanism:

   ```
   Mk+1 = f(Mk, Sj)
   ```

   where `Mk` is the previously stored interim evidence synthesis and `Sj` is the freshly generated summary. This avoids redundancy and builds a coherent subdomain knowledge base.

6. **Provenance Tree**: Every summary merge and evidence update is logged in a **dependency graph** (attribution/provenance structure). Leaf nodes = article-level summaries. Internal nodes = interim syntheses. Color-coding distinguishes contributions from different agents. This enables full traceability.

7. **Three User Interaction Modes**:
   - **Path Navigation**: User drags agent pointer on the RSS map to a missed article; agent reads it next and updates memory.
   - **Chat Navigation**: Natural-language directives (e.g., "Focus on randomized controlled trials") cause the agent to reflect, revise retrieval strategy, and merge/discard findings.
   - **Instruction Navigation**: Direct editing of agent parameters (criteria, summarization format); agent double-checks memory for alignment.

8. **Reflection Phase**: Upon any user intervention, the agent reconciles conflicts in local memory and adjusts reading strategy to match latest directives.

### Stage 3: Final Synthesis

9. All subdomain evidence bases are integrated into a coherent final summary following a user-specified template (Introduction, Study Design, Key Findings, Discussion, Conclusion). Citations use `[citation_number]` format referencing original documents or interim summaries. The dependency tree is updated to reflect final provenance.

### Key Architectural Properties

- **Agent memory isolation**: Each agent's memory remains isolated until final synthesis (specialized perspective per subdomain).
- **Parallel processing**: N agents operate concurrently on N clusters.
- **Prompt templates**: 4 specialized prompts (Retrieve, Read, Synthesize, Reflect) govern agent behavior with structured JSON outputs.

## 2. Results (real benchmark numbers)

### Record Screening (15 SRs, corpus sizes 72-7,356 articles)

| System | Recall % | Precision % | F1 % |
|--------|----------|-------------|------|
| BM25 (Top-100) | 54.30 | 16.50 | 25.3 |
| AutoSurvey (Top-100) | 70.30 | 20.43 | 31.6 |
| InsightAgent_auto (Llama 3.3) | 66.40 | 62.40 | 64.3 |
| InsightAgent (Llama 3.3) | 87.90 | 80.10 | 83.8 |
| InsightAgent_auto (GPT-4o) | 71.10 | 51.90 | 60.0 |
| **InsightAgent (GPT-4o)** | **98.50** | **79.80** | **88.2** |

Key: With human interaction, GPT-4o variant reaches near-perfect 98.5% recall. Precision improvement over AutoSurvey: 79.8% vs 20.4% (3.9x).

### Systematic Review Quality (100-point rubric, 2 independent expert raters per SR)

| System | Score (/100) |
|--------|-------------|
| ChatCite (GPT-4) | 47.1 |
| AutoSurvey (GPT-4o) | 54.0 |
| InsightAgent_auto (Llama 3.3) | 60.9 |
| InsightAgent (Llama 3.3) | 70.2 |
| InsightAgent_auto (GPT-4o) | 62.4 |
| **InsightAgent (GPT-4o)** | **79.7** |

- +27.2% improvement from interaction (62.4 → 79.7, p = 3.43e-7)
- +25.7 points over AutoSurvey (54.0 → 79.7)
- Llama 3.3 with interaction (70.2) beats fully autonomous GPT-4o (62.4)
- First system to reach "practically useful" quality for domain experts

## 3. Trade-offs

| Win | Cost |
|-----|------|
| Time reduction: months → 1.5 hours | Requires active human oversight (not fully autonomous) |
| Near-perfect recall (98.5%) with human interaction | Abstract-only inputs; full-text reading omitted due to cost/context limits |
| 27.2% quality improvement over autonomous mode | Cannot perform statistical meta-analysis (no CI, effect-size pooling) |
| Hallucination rate cut from 53% → 12% | Evidence weighting flat (all studies treated equally regardless of design) |
| Provenance tree enables full citation traceability | Small-scale user study (9 participants, 15 SRs) limits generalizability |
| Three interaction modalities for flexible human-in-the-loop | Interactive mode requires domain expertise; non-experts may not benefit equally |
| Multi-agent partitioning beats single-agent by 8-10 F1 points | Additional LLM API costs scale linearly with cluster count |
| Llama 3.3 + interaction (70.2) beats GPT-4o autonomous (62.4) | Interaction quality depends on LLM backbone (GPT-4o > Llama 3.3 for collaboration) |

## 4. Design Rationale

Why this approach over alternatives:

1. **Multi-agent design mirrors Cochrane Handbook recommendation**: Systematic reviews already recommend assigning different subsets of studies to multiple independent reviewers to reduce individual bias and accelerate screening. InsightAgent operationalizes this as parallel LLM agents.

2. **RSS Map over flat list**: A spatial layout encoding both relevance (radial distance) and semantic similarity (angular clustering) lets both agents and humans understand the corpus structure at a glance, enabling targeted exploration rather than undirected scanning.

3. **Interactive over fully autonomous**: Prior systems (AutoSurvey, ChatCite) operated autonomously and produced generic summaries with untraceable sources. The authors argue high-stakes domains like healthcare demand human oversight for trust and accuracy, and the data bears this out (+27.2% quality from interaction).

4. **Receptive field of 8 neighbors**: Standardizing the agent's next-article selection to 8 nearest neighbors reduces randomness and promotes coherent exploration, mimicking how human reviewers follow thematic threads through literature.

5. **Provenance tree over black-box generation**: In systematic reviews, every claim must be traceable to its source. The dependency graph provides an auditable chain from final conclusion back to individual article summaries.

6. **Elbow method for automatic k**: Avoids manual cluster count tuning and adapts to varying corpus sizes (72 to 7,356 articles).

## 5. Limitations & Failure Modes

1. **Abstract-only reading**: Due to LLM cost and context-length constraints, only titles and abstracts are processed. Critical details in full texts (exact effect sizes, subgroup analyses, detailed methods) are omitted. The system missed mortality comparisons (14.5% vs 15.6%, p=0.12) and exact patient counts (13,085 across 9 RCTs) that were present in full-text human reviews.

2. **No statistical synthesis**: Cannot compute pooled effect sizes, confidence intervals, or perform meta-analysis. This is flagged in 22% of GPT-4o reports.

3. **Flat evidence weighting**: All studies treated equally regardless of design quality (RCT vs observational). Flagged in 31% of GPT-4o reports. Human reviewers typically weight evidence by study design.

4. **Small-scale evaluation**: 9 medical experts, 15 SRs, all biomedical domain. Generalizability to other domains unproven.

5. **Expert-dependent interaction quality**: The interaction benefit assumes domain expertise. Non-experts may provide misleading guidance or miss critical errors.

6. **Hallucinations persist**: 12% of reports still contain invented or misrepresented facts (down from 53% but not zero).

7. **Cost scaling**: Each cluster spawns an independent agent; LLM API costs scale with cluster count (average 9).

8. **No handling of retracted/invalid studies**: The system does not check for retractions or post-publication corrections.

## 6. Transfer to Lyra

**The One Idea**: Multi-agent corpus partitioning with a **provenance tree** for transparent, auditable evidence synthesis. When Lyra needs to synthesize information from a large, diverse corpus (e.g., multiple documents, research papers, or codebases), partitioning the corpus semantically and dispatching parallel LLM agents that each build a local evidence base with explicit merge-dependency tracking enables both (a) higher retrieval accuracy through focused context windows, and (b) full auditability of how each conclusion was reached.

**Workstream Route**: §4.2 (Memory/Context) — the provenance tree is fundamentally a structured memory architecture; also feeds §4.5 (Safety/Verification) because provenance tracking provides verifiability. Secondary alignment with §4.7 (Plugins/Research Tools) if Lyra is used for literature review or knowledge synthesis tasks.

**Analogy for Lyra**: When Lyra processes a large codebase or document set to answer a complex question, partition the corpus into semantic clusters, dispatch parallel sub-agents to each cluster with isolated memories, synthesize via an explicit merge dependency tree that traces every claim back to its source file/line. This replaces flat single-shot retrieval with a structured, auditable synthesis pipeline.
