## 1. Mechanism (step-by-step)

JAW is an end-to-end detection and exploitation framework for agentic workflow hijacking (AWH). It introduces **Context-Grounded Evolution**, which evolves adversarial inputs under three workflow contexts recovered through hybrid program analysis. The pipeline has four stages:

### Stage 1: Path-Sensitive Workflow Analysis (Static)

**Guarded Workflow Graph (GWG) Construction:**
JAW builds a unified control-flow representation for polyglot workflow platforms (GitHub Actions, n8n). The GWG is a directed graph G_W = (V, E, v0, V_A, lambda, iota) where vertices are partitioned into Trigger, Task, Code, Branch, Join, Summary, and Agent Sink types. Each edge e carries a label lambda(e) = (gamma_e, delta_e) consisting of a guard predicate gamma_e over event fields/env vars/outputs and a symbolic state transfer delta_e.

Construction proceeds in two layers: (1) platform-metadata/DSL-binding pass that parses YAML/JSON workflow files and n8n node metadata to build the skeleton with guard-labeled edges; (2) executable-code lowering pass that uses language-specific frontends (Tree-sitter for Bash, CodeQL for JS/TS/Python) to emit normalized GWG fragments for inline code blocks, composite actions, and n8n Code nodes.

**Agent Invocation Path Analysis:**
JAW identifies candidate agent sinks V_A via three signatures: platform-level (n8n AI Agent nodes), registry-level (curated GitHub Actions known to invoke LLM agents), and code-level (CLI invocations of agent tools, LLM SDK calls with tool configuration). For each candidate path pi from unprivileged trigger to agent sink, JAW performs symbolic path execution:

```
Phi_i = Phi_{i-1} AND ||gamma_{ei}||_{Sigma_{i-1}},   Phi_0 = top
Sigma_i = ||delta_{ei}||(Sigma_{i-1})
```

The symbolic store Sigma maps workflow references r in R_W to symbolic terms t or opaque values. Guards and transfers are translated into an SMT-backed fragment supporting equality, inequality, set membership, prefix/contains/match, and status predicates. Path feasibility is determined by satisfiability of Phi_n under the attacker capability model using Z3.

**Event-under-Test (EuT) Synthesis:**
For each feasible path, JAW synthesizes a concrete event template filled with solver model values for attacker-controllable fields. Canary markers are inserted into controllable text fields to enable downstream dynamic taint tracing.

### Stage 2: Dynamic Prompt Provenance Analysis (Dynamic)

**Multi-Runtime Taint Tracking:**
JAW instruments JS/TS and Python runtimes with shadow taint metadata tracking (source origin, canary token, tainted ranges, transformation history). Across workflow handoff boundaries, taint metadata is serialized into temporary canary wrappers embedded in concrete strings. When downstream components read the value, JAW detects the wrapper and reconstructs shadow taint state. This works because workflow expression languages (GitHub expressions, n8n expressions) primarily pass/compose/serialize values rather than rewrite arbitrary substrings.

**Prompt Constraint Extraction:**
At the LLM request sink, JAW extracts two constraint types:
- *Prompt-shaping constraints*: transformations (filtering, sanitization, template insertion, truncation) traced via transformation history from source field to sink span
- *Prompt-framing constraints*: semantic framing derived from the final LLM context (message role, surrounding instructions, delimiters, section headers, untrusted-content warnings), extracted via LLM summarization

### Stage 3: Agent Capability Profiling (Dynamic)

**Tool Extraction:** JAW intercepts model requests to collect structured tool declarations (tools/functionDeclarations in OpenAI/Anthropic/Gemini APIs) across the full agent session.

**Dynamic Capability Probing:** JAW classifies tools into four capability classes (network access, file r/w, subprocess execution, external-service access). For each tool, JAW substitutes probe calls into intercepted model responses and dispatches them through the agent's normal tool executor — bypassing prompt-level and model-level defenses to test code-level defenses in isolation. Each probe is classified as allowed/denied/errored, producing a capability profile that captures the action space available for hijacking.

### Stage 4: Context-Grounded Jailbreak Evolution

A **plan-verify-execute loop** (Algorithm 1) that evolves payloads:

1. **Plan:** The mutator A (Claude Sonnet 4.5) receives a seed from the priority queue, the three workflow contexts (trigger constraints E, prompt constraints C, capability profile T), and the attack goal g. It generates (event payload e_i, expected tool-call chain chi_i).

2. **Verify:** JAW substitutes chi_i into intercepted model responses and executes through the agent's normal tool dispatcher (VerifyChain), testing code-level feasibility independently of prompt/model defenses. If the chain fails code-level checks, failure is recorded in mutation memory.

3. **Execute:** JAW runs the full workflow with payload e_i and checks the goal oracle O_g. The oracle uses three-stage matching: direct match against target secrets, deterministic normalization/decoding (Base64, hex, URL), and LLM-generated decoding scripts (LLM never decides success — only deterministic matching against ground truth does).

4. **Feedback:** AnalyzeTrajectory computes Progress(a_i, g) = k/m where k is the longest prefix of chi_i emitted and accepted. Seeds are priority-ranked by Score(s) = (Progress, -Stall, t_s) in lexicographic order.

## 2. Results

**Zero-Day Vulnerabilities (RQ1):**
- Dataset: 112,568 GitHub workflows across 55,684 repositories (active repos with >=1 commit in past year), 9,154 n8n templates
- **4,174 hijackable GitHub workflows** and **8 hijackable n8n templates** discovered
- Findings span **15 widely-used GitHub Actions** including official actions for Claude Code, Gemini CLI, Qwen CLI, Cursor CLI, OpenCode, OpenHands
- 2 official n8n nodes affected
- Dominant impact: credential exfiltration; also SQL injection and shell RCE via chat triggers in n8n
- Bug bounties from: **GitHub, Google, Anthropic, Snowflake**
- 7 acknowledgments received, 7 mitigations or fixes implemented

**Ablation Study (RQ2) — avg iterations to bypass model/prompt (M.P.) and code defenses:**
- JAW (full): M.P. = 1.0-1.3 iters, Code = 2.3-6.0 iters (consistently succeeds)
- JAW-NoCapProf: M.P. = 1.0-1.3, Code = 2.0-7.0 (mostly succeeds, more iterations)
- JAW-NoPromptProv: M.P. = 1.3-3.3, Code = 2.3-8.7 (struggles on harder targets)
- JAW-NoTrigger: M.P. = 3.0-6.0, Code = F (fails entirely on all configurations)

**Comparison with Baselines (RQ3):**
- AutoDAN-Turbo: beats M.P. on ask-bonk only (no code-level defenses), fails all others at code level
- Search-based (OpenEvolve): beats M.P. on some targets, fails all code-level defenses
- JAW: the only method that consistently bypasses code-level defenses across all 9 model-action pairs

**Performance (RQ4):**
- Static path-sensitive analysis: **52 seconds** average
- Dynamic prompt/capability tracing: **481 seconds** average, $0.62 LLM cost
- Jailbreak evolution: 90% finish within **1 hour** (only entered after prior stages confirm feasibility)
- Implementation: 8,524 lines Python, 2,429 lines JavaScript, 297 lines CodeQL

## 3. Trade-offs

| Gain | Cost/Loss |
|------|-----------|
| First systematic framework for agentic workflow hijacking (no prior academic work) | Requires instrumented runtime execution per target (dynamic analysis is slow) |
| End-to-end exploit synthesis across three defense layers simultaneously (prompt, model, code) | Jailbreak evolution requires expensive LLM calls (Claude Sonnet 4.5 as mutator) |
| GWG approach handles polyglot, cross-repository paths (workflow DSL + JS + Python + Bash) | Cannot analyze dynamically downloaded code or unresolved targets (classified as unknown) |
| Context-grounded evolution far outperforms generic jailbreak methods at code-level bypass | Only supports GitHub Actions and n8n; other platforms need custom frontends |
| Dynamic capability probing tests code-level defenses independently of model behavior | Dynamic taint tracking across heterogeneous runtimes is brittle (relies on canary wrapper preservation) |
| Ethical: all testing on private repos with synthetic secrets, 45-day disclosure window | Responsible disclosure means some PoC payloads withheld from paper |
| Cross-platform GWG abstraction (GitHub Actions + n8n in same representation) | Unbounded loops and complex cycles → path classified as unknown (false negatives) |

## 4. Design Rationale

**Why Context-Grounded Evolution over generic jailbreaking:** Prior jailbreak methods (AutoDAN, GCG, search-based) assume full or near-full control of LLM input. In agentic workflows, the attacker controls only a fragment embedded by workflow templates, and exploitation is gated by three interacting constraints: (a) path feasibility (must reach the agent at all), (b) prompt context (sanitization, framing as untrusted), and (c) code-level tool restrictions. JAW grounds evolution in all three contexts simultaneously because each is a hard constraint — failing any one makes exploitation impossible regardless of how persuasive the payload is.

**Why static path analysis + dynamic provenance over pure static or pure dynamic:** Pure static analysis (e.g., ARGUS) cannot track how data flows into LLM prompts or what tools the agent can actually execute. Pure dynamic fuzzing would be prohibitively expensive for the workflow space. The hybrid approach lets JAW statically filter workflows to those with feasible agent-invocation paths, then dynamically trace only the promising candidates — achieving scale (112K+ workflows) while maintaining precision.

**Why symbolic execution over simple pattern matching for path feasibility:** Agent invocation paths in real workflows cross repository boundaries, involve polyglot guards (YAML expressions, JavaScript conditionals, bash if-statements), and require joint satisfaction of multiple constraints. Symbolic execution with SMT solving is the only approach that can compose these heterogeneous guards into a single satisfiable event template.

## 5. Limitations & Failure Modes

1. **Unknown paths:** Dynamically downloaded code, unresolved dynamic execution targets, and unsupported cycle reasoning produce "unknown" rather than "feasible" classifications — creating false negatives.
2. **Taint tracking fragility:** Cross-runtime taint propagation via canary wrappers fails if an intermediate workflow step rewrites arbitrary substrings (e.g., replacement, slicing). JAW acknowledges this but notes that workflow expression languages rarely expose such operations.
3. **LLM dependency in evolution:** The mutator (Claude Sonnet 4.5) may itself have safety guardrails that limit its ability to generate effective adversarial payloads — a recursive limitation.
4. **Platform scope:** Only GitHub Actions and n8n are supported. Other platforms (GitLab CI, Jenkins, Temporal, etc.) require custom frontends and runtime instrumentation.
5. **Attack goals limited to three types:** Credential exfiltration, unauthorized data access/modification, and unauthorized service requests. More sophisticated multi-step attacks or lateral movement are not evaluated.
6. **Synthetic secret matching:** The oracle relies on matching against known synthetic secrets injected into test environments. In real-world use, secrets would need to be identified first.
7. **Time-bound evolution:** 90% completion within 1 hour suggests 10% of cases exceed this budget — not suitable for time-critical applications.

## 6. Transfer to Lyra

**The ONE transferable idea:** JAW's **Context-Grounded Evolution** framework demonstrates that LLM agents embedded in multi-step workflows have exploitable attack surfaces that span static path conditions, runtime prompt context, and tool capability constraints simultaneously. For Lyra, this means: **any LLM agent deployed within an automation platform (GitHub Actions, n8n, or Lyra's own plugin/workflow system) must be treated as a privileged program whose invocation triggers, prompt construction, tool capabilities, and output channels are jointly controlled.** Specifically, Lyra should adopt the three-context security model: (1) path-level access control ensuring only authorized triggers can invoke agent steps, (2) prompt-construction integrity ensuring attacker-controlled inputs are provably isolated from instruction context, and (3) capability-level enforcement restricting agent tools to least-privilege with allowlists that account for alternative primitives (not just command-name denylists, which JAW proves are insufficient).

**Impact:** 5 — Lyra integrates LLM agents into workflows; without JAW-style analysis, every agent-equipped workflow is a potential hijacking vector. This paper found 4,174 real-world hijackable workflows including official actions from Anthropic, Google, and GitHub themselves. The risk is acute and demonstrated at scale.

**Effort:** 4 — Requires implementing path-sensitive workflow analysis (GWG construction), runtime taint tracking across heterogeneous tool invocations, dynamic capability profiling, and a context-grounded jailbreak evolution loop. Substantial engineering but the paper provides open-source reference implementation and clear architecture.

**Tier:** **breakthrough** — This is the first systematic framework for a previously unexplored vulnerability class. The discovery of 4,174 real-world vulnerabilities spanning official actions from major AI labs (Anthropic, Google) makes this both academically novel and practically urgent. The three-context model (path + prompt + capability) provides a reusable security architecture for any agent-hosting platform.
