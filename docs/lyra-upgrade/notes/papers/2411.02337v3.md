## 1. Mechanism

WEBRL is a self-evolving online curriculum reinforcement learning framework that trains open-source LLMs into capable web agents within interactive environments (specifically WebArena). It operates in two parts:

### Part 1: Supervised Fine-Tuning (SFT) Initialization
- The base LLM (Llama-3.1-8B or GLM-4-9B) is first fine-tuned on the WebArena-Lite training dataset (~1,186 human-annotated demonstrations with oracle trajectories and reward functions).
- The SFT model serves as the initial actor (policy) π₁.
- The critic V₁ is initialized from the SFT model with a randomly initialized value head appended.
- A replay buffer B is seeded with successful SFT trajectories; a failure set F stores instructions the agent fails on.

### Part 2: Self-Evolving Curriculum RL (Phases 1 through N=8)
Each phase cycles through:

**a) Task Generation (self-evolving curriculum):**
- Failed instructions from previous phases serve as seeds.
- GPT-4o generates new instructions via "in-breadth evolving" (Xu et al., 2023) — creating tasks of similar domain but diverse phrasing, using extracted variable values (names, places, products) from the seeds.
- Filtering occurs in two stages:
  1. **Difficulty filter**: The critic evaluates each candidate instruction; only tasks with critic scores between 0.05 and 0.75 are retained — ensuring they are neither trivial nor impossibly hard for the agent's current capability.
  2. **Feasibility filter**: GPT-4o with a rule-based prompt excludes tasks impossible to complete in WebArena (e.g., "send email" on CMS, "track real-time logistics" on OSS).
- 500 new instructions per phase survive filtering.

**b) Rollout & Outcome-Supervised Reward Model (ORM):**
- The actor π_n interacts with the WebArena environment on the new instruction set.
- An 8B-parameter ORM (trained on ~12,200 samples from rollouts + augmented WebArena-Lite data) evaluates whether each trajectory succeeds. It takes as input: (instruction, action history, HTML of final state) and outputs a binary "YES"/"NO" by comparing token probabilities.
- Reward: 1 for success, 0 for failure — received only at trajectory termination (sparse, binary reward). No intermediate process rewards.

**c) KL-Constrained Policy Update (the core RL algorithm):**
- The problem is formalized as a finite-horizon MDP (S, A, R, T) with a maximum-entropy RL objective:

  $$ \max_{\pi_\theta} \mathbb{E}_{I\sim\rho, a_t\sim\pi_\theta} \left[ \sum_{t=0}^T \left( r(s_t, a_t, I) + \beta \log \pi_{\text{ref}}(a_t|s_t, I) \right) + \beta H(\pi_\theta) \right] $$

  where β controls the KL-divergence constraint strength and π_ref is the policy from the previous phase.

- The optimal policy takes the form:
  $$ \pi^*(a_t|s_t, I) = e^{(Q^*(s_t,a_t,I) - V^*(s_t,I))/\beta} $$

- From this, the advantage function relationship is derived:
  $$ \beta \log \frac{\pi_\theta(a_t|s_t,I)}{\pi_{\text{ref}}(a_t|s_t,I)} = A^*(s_t, a_t, I) $$

- The MSE loss for the policy:
  $$ L(\pi_\theta) = \mathbb{E}_\nu \left[ \left( \beta \log \frac{\pi_\theta(a|s,I)}{\pi_{\text{ref}}(a|s,I)} - A^*(s,a,I) \right)^2 \right] $$

  Key design choice: Uses MSE (eq. 11) rather than KL-divergence (eq. 13) to measure distance between π_θ and π*, because KL-divergence (a) restricts training data to π_ref's distribution, (b) cannot decrease probabilities of actions with negative advantage, and (c) when π_ref fails to capture past successes, KL-based sampling cannot reuse those experiences.

**d) Advantage Estimation:**
- A value network V is trained using cross-entropy loss:
  $$ L(V) = -\mathbb{E}_\nu [ r(s_T, a_T, I) \log V(s,a,I) + (1 - r(s_T, a_T, I)) \log(1 - V(s,a,I)) ] $$
- Generalized Advantage Estimation (GAE) computes advantages with λ=0.5, combining next-step and final-step terms:
  $$ A(s_t, a_t, I) = \lambda [r(s_t, a_t, I) + V(s_{t+1}, I) - V(s_t, I)] + (1-\lambda)[r(s_T, a_T, I) - V(s_t, I)] $$
- Discount factor γ = 0.9.

**e) Experience Replay Buffer with Actor Confidence Filtering:**
- Only successful trajectories are stored.
- During training, actions from the replay buffer are filtered by perplexity computed by the current actor: actions with perplexity in range [1/0.95, 1/0.5] are included.
- This removes both overly familiar data (perplexity < 1/0.95 → model already knows it) and data too challenging (perplexity > 1/0.5 → causes distribution shift).
- Historical data is limited to 2x the size of current interaction data to prevent old data from dominating.

**f) Phase transition:** π_{n+1} becomes the new actor and π_ref for the next phase. Successful trajectories are added to replay buffer B; failed instructions go into F for next-round seed generation.

### Gradient Mechanics
The gradient of the policy loss decomposes into three multiplicative factors:
$$ \nabla_\theta L(\pi_\theta) = -2\beta \underbrace{\mathbb{E}_\nu [A^*(s,a,I)}_{\text{update direction}} \underbrace{-\beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}}_{\text{KL constraint}} \underbrace{\nabla_\theta \log \pi_\theta(a|s,I)]}_{\text{SFT loss}} $$

- When A^* > 0 (action is beneficial): increase probability, moderated by KL gap from π_ref.
- When A^* < 0 (action is detrimental): decrease probability; KL constraint prevents excessive reduction if π_θ is already far below π_ref.

### Action Space
13 action types: Click, Hover, Type, Search, Press, Scroll Up/Down, Select Dropdown Option, New Tab, Tab Focus, Close Tab, Goto, Go Back, Go Forward, Exit. Actions include `# Element:` comments naming the operated element and `# Note:` comments capturing relevant page information.

### Key Performance Metrics
- **8B model improvement:** 4.8% → 42.4% (8.8× gain via WEBRL)
- **9B model improvement:** 6.1% → 43.0% (7.0× gain via WEBRL)
- **70B model improvement:** 12.7% → 49.1% (3.9× gain via WEBRL)
- **vs. GPT-4-Turbo:** 42.4% vs 17.6% (2.4× better)
- **vs. best prior open-source (AutoWebGLM):** 42.4% vs 18.2% (2.3× better)
- **vs. DigiRL (previous best RL):** +12.1% absolute on 8B, +11.5% on 9B
- **Scaling effect:** WEBRL gain from 8B→70B: +6.7% absolute; SFT gain: only +2.4%

### Error Type Analysis (Llama3.1-8B)
WEBRL reduces:
- "Get Stuck Midway" (looping): significantly lower than SFT/Filtered BC (RL optimizes cumulative reward, not per-step likelihood)
- "Fail to Recover": curriculum learning teaches recovery actions gradually
- "Stop at Wrong Page": lowest error rate
- "Fail to Make Reasonable Attempt": lowest error rate

### Task Length Scaling
- SFT and Filtered BC performance declines sharply as task steps increase.
- DigiRL improves medium-length tasks but struggles beyond 10+ steps.
- WEBRL maintains higher performance on long-horizon tasks (≥10 steps) due to curriculum learning progressively increasing difficulty.

### ORM Evaluation
- **OUR ORM (8B):** 80.8% test accuracy, 79.4% rollout accuracy
- GPT-4 (same text input): 71.9% / 71.2%
- Captioner + GPT-4: 72.6% / 73.3%
- GPT-4V: 71.2% / 70.5%
- The 8B ORM outperforms GPT-4/GPT-4V by ~9% absolute.

### Ablation Results (Llama3.1-8B, final SR at phase 8)
- **Full WEBRL:** 42.4%
- **w/o replay buffer:** degrades over time (loses access to earlier experiences)
- **w/o KL constraint:** degrades more slowly than w/o replay buffer but underperforms full WEBRL
- **w/o KL & replay buffer:** worst degradation (REINFORCE with baseline quickly overfits current phase)
- **w/o curriculum learning (fixed task set):** 34.5% (plateaus at lower ceiling)
- **w/ failed trajectories in replay buffer (instead of only successful):** slower and more volatile improvement

### Replay Buffer Perplexity Analysis
| Perplexity range | SR |
|---|---|
| [1, ∞] (all) | 29.1 |
| [1, 1/0.95] (too easy) | 27.9 |
| [1/0.95, 1/0.5] (moderate difficulty) | **31.5** |
| [1/0.5, ∞] (too hard) | 23.0 |

### β (KL constraint coefficient) Analysis
- β = 0.01: performance deteriorates (too weak KL constraint → overfit)
- β = 0.1-1: good with replay buffer
- β = 2-10 (w/o replay buffer): performance declines (overly restricts policy updates)
- With replay buffer: performance stays high even at large β (diverse replays stabilize)

## 3. Trade-offs

| Win | Lose |
|-----|------|
| 8.8× improvement over base 8B model (4.8%→42.4%) | Requires GPT-4o as task generator (external API dependency) |
| Surpasses GPT-4-Turbo and GPT-4o on WebArena-Lite by 2-3× | Computationally expensive: 8 phases of full RL training + rollouts + ORM training |
| Open-source model success rivals prompt-engineered proprietary systems | ORM training requires 12,200 labeled samples (substantial data engineering) |
| Self-evolving curriculum adapts to model's current capability | Task generation quality depends on GPT-4o prompt engineering; may degrade with weaker models |
| KL-constrained update prevents catastrophic forgetting across phases | KL constraint is symmetric — can prevent exploration of genuinely better policies if β too large |
| Replay buffer with perplexity filtering prevents overfitting to old data | Replay buffer only stores successful trajectories; valuable information in failed trajectories is discarded |
| Off-policy learning (more sample-efficient than PPO) | Binary reward signal is extremely sparse — advantage estimation is noisy |
| ORM (8B) outperforms GPT-4/GPT-4V for outcome judgment | ORM only sees final state HTML; may miss task completion evidence in intermediate pages |
| 13 action types provide expressive action space | Action space cardinality is large (all clickable elements) — high variance in policy gradients |
| Works across diverse websites (Reddit, GitLab, CMS, Map, OSS) | Map performance degrades in later phases (trade-off with OSS/CMS gains) |

## 4. Design Rationale

**Why self-evolving curriculum over fixed task set:** DigiRL and other prior work use a static set of tasks. Fixed tasks either waste time on already-mastered tasks or overwhelm the agent with impossible ones. WEBRL's dynamic generation ensures each phase presents tasks at the boundary of the agent's capability (critic score 0.05-0.75), enabling continuous improvement without plateaus. The task generation from failures ensures the curriculum targets specific weaknesses.

**Why KL-constrained policy update over standard REINFORCE/PPO:** Web interaction data is expensive to collect (each rollout takes many steps in a live environment). PPO is on-policy and requires large amounts of fresh interaction data per update — impractical. Standard REINFORCE causes rapid overfitting to the current phase's data, forgetting previous knowledge. The KL-divergence constraint against the previous phase's policy acts as a soft anchor, allowing learning new tasks while retaining competence on old ones. The authors also argue MSE loss (eq. 11) is superior to KL-divergence loss (eq. 13) because it allows off-policy data and can decrease probabilities of bad actions.

**Why off-policy + replay buffer:** The replay buffer stores successful trajectories from all phases. Since web tasks only provide a binary reward at termination, reusing past successes prevents forgetting and provides more training signal. The perplexity-based filtering ensures only moderately challenging data (neither trivial nor impossible) is replayed — this is a form of automatic curriculum within the buffer. The filter range [1/0.95, 1/0.5] was empirically determined to balance the stability-plasticity trade-off.

**Why train an ORM instead of using GPT-4:** A local 8B ORM enables autonomous evaluation of generated tasks without costly API calls. It achieved 80.8% accuracy, outperforming GPT-4 (71.9%). The ORM is trained on augmented WebArena-Lite data + rollouts with the environment's reward function as ground truth.

**Why only successful trajectories in replay buffer:** Failed trajectories have final reward 0, which gives negative advantage to ALL actions in the trajectory, including correct intermediate steps. This mislabeling degrades training (confirmed by experiment: including failed trajectories causes "slower and more volatile performance improvement").

## 5. Limitations & Failure Modes

1. **Catastrophic forgetting on Map tasks:** The Map (OpenStreetMap) site shows performance decline in late phases (falling from ~40% peak to ~36%), hypothesized as a trade-off with gains in OSS/CMS. The KL constraint is insufficient to prevent cross-task interference.

2. **ORM hallucination risk:** The ORM only evaluates the final state's HTML, not the full trajectory. Tasks where success evidence exists on intermediate pages (e.g., "add to wish list" where the confirmation appears briefly then redirects) may be mislabeled. ORM accuracy is 80.8%, meaning ~19% of rewards are incorrect — this noise propagates through RL training.

3. **GPT-4o dependency for task generation:** The self-evolving curriculum requires GPT-4o to generate new instructions. Quality and diversity of generated tasks depend on the proprietary model. Replacing GPT-4o with a weaker open model would likely degrade curriculum quality.

4. **WebArena-only validation:** All experiments are on WebArena-Lite. No evidence the framework transfers to other web environments (Mind2Web, WebShop, etc.) or real websites. The feasibility filter is WebArena-specific.

5. **Sparse reward brittleness:** Binary reward at trajectory end is extremely sparse. Even with curriculum learning, the advantage estimator is noisy (GAE with λ=0.5 is a heuristic). For tasks requiring 10+ steps, the credit assignment problem remains severe.

6. **Computational cost undisclosed:** The paper does not report total GPU hours, number of rollouts, or training wall-clock time. Training involves: SFT + 8 phases × (GPT-4o task generation, rollout collection, ORM evaluation, actor training, critic training). This is likely very expensive.

7. **No safety/alignment evaluation:** Web agents that can click, type, and navigate autonomously raise safety concerns (accidental purchases, data deletion, posting content). No safety metrics are reported.

8. **β and λ are hand-tuned:** The KL coefficient β and GAE λ=0.5 were set manually. These may not generalize to other environments or model scales without re-tuning.

9. **Replay buffer size constraint:** Historical data is capped at 2× current interaction data. This may be insufficient for preserving knowledge from very early phases, especially with N=8 cycles.

10. **"Get Stuck Midway" errors still present:** While reduced relative to baselines, WEBRL agents still loop and fail. The framework does not include explicit loop detection or recovery mechanisms.

## 6. Transfer to Lyra

**The One Transferable Idea:** The perplexity-based actor confidence filtering mechanism for experience replay — storing only successful trajectories and filtering replays by perplexity in [1/0.95, 1/0.5] so the agent trains on moderately difficult examples, avoiding both trivial memorization and overwhelming distribution shifts. This is a lightweight, principled data selection strategy that can be applied to any RL-trained agent system regardless of domain.

**Workstream Route:** §4.1 (Memory Systems) — the replay buffer with perplexity-based confidence filtering directly improves the agent's ability to retain useful past experiences while avoiding both forgetting and overfitting. It can be integrated into Lyra's episodic memory management: instead of storing all past interaction-success pairs indiscriminately, store only successful trajectories and filter retrieval by a confidence/uncertainty metric analogous to perplexity.

**Impact:** 4/5 — Directly applicable to Lyra's memory architecture; no external dependencies; addresses a known failure mode (catastrophic forgetting in online learning agents).

**Effort:** 3/5 — Requires: (1) computing perplexity/confidence scores on stored experiences using current policy, (2) adding a filtering threshold layer before replay, (3) determining appropriate threshold ranges for Lyra's domain. The core math is straightforward (perplexity = exp(cross-entropy loss)).

**Tier:** breakthrough — This is a novel, empirically validated approach to adaptive experience replay that bridges curriculum learning and memory management. It advances beyond simple FIFO or random replay buffers.
