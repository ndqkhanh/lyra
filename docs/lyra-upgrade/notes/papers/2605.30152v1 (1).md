# Do Proactive Agents Really Need an LLM to Decide When to Wake and What to Anchor?
Xiaoze Liu, Ruowang Zhang, Amir H. Abdi, Michel Galley, Zhikai Chen, Siheng Xiong, Xiaoqian Wang, Jing Gao (Purdue University, Microsoft, Michigan State University, Georgia Institute of Technology)
arXiv:2605.30152v1 [cs.CL], 28 May 2026

## 1. Mechanism (step-by-step, with equations/algorithms)

The paper reformulates the always-on path of proactive agents as a **heterogeneous temporal graph learning (TGL)** problem rather than a language-modelling problem. The core insight: user activity streams are natively structured as (actor, verb, object, timestamp) tuples rendered as text; flattening to token sequences loses entity linkage, so the round-trip (structure -> text -> recovered structure via LLM) is wasteful.

**Step-by-step pipeline:**

1. **Graph Construction (deterministic, rule-based):** Each session's event stream is converted into a heterogeneous temporal graph Gₜ = (Vₜ, Eₜ). Vₜ contains:
   - **Event nodes**: one per timestamped user action (e.g., "opened 'email_filter.py' in VSCode")
   - **Entity nodes**: extracted entities of 5 classes — app (from installed-application registry), file (by extension → MIME database), URL (by regex), query (by search-verb templates), artifact (by document-class noun patterns)
   - **Type nodes**: coarse semantic categories (file_ext, file_topic, app_type, url_domain, query_lang)
   
   Edges Eₜ encode:
   - `has_entity` (event → entity), `belongs_to` (entity → event, reverse)
   - Forward temporal edges (t → t+1, past-informs-future)
   - Backward temporal edges (t+1 → t, future-informs-past) — used during training only
   - Self-loops with learned relation embeddings
   - Edge channels collapsed to 5 relation types for the GNN

2. **Node Featurisation:** Each node gets a concatenated 832-dimensional feature vector:
   - `text_emb`: 768-dim frozen BGE-base-en-v1.5 sentence embedding of the surface label
   - `type_emb`: 32-dim learned embedding indexed by node type (10 types)
   - `dt_emb`: 32-dim learned MLP over log(1 + Δt) where Δt = seconds since previous event (event nodes only; 0 for entity nodes)
   - Projected via `Linear(768 + 32 + 32 → 256)` to GNN hidden dimension

3. **TGL Backbone (shared encoder):** 3 relation-aware GATv2 layers (Brody et al., 2022):
   - 4 attention heads, head dimension 64, concatenated
   - 32-dim edge embedding (one per edge relation type) fed into attention
   - Residual + LayerNorm + GELU + Dropout(0.2) around each layer: `x ← LN(x + Drop(GELU(GATv2(x, e, edge_emb))))`
   - Jumping Knowledge head (Xu et al., 2018): `hⱼₖ = concat(layer₀, layer₁, layer₂, layer₃)` → 1024-dim

4. **Dual Readout Heads (one forward pass):**
   - **Trigger head** (applied only to event nodes):
     `Linear(1024 → 256) → GELU → Dropout(0.2) → Linear(256 → 1)` → logit
     Per-event trigger probability: `p_trig(t) = σ(logit_trig(t))`
     
   - **Routing head** (applied only to entity nodes):
     `Linear(1024 → 256) → GELU → Dropout(0.2) → Linear(256 → 1)` → logit
     Per-entity routing score: `s_rout(v) = σ(logit_rout(v))`

5. **Joint Training Loss:**
   - Trigger loss: `L_trig = BCE(logit_trig, y_trig; w⁺ = 0.15)` — positive class down-weighted to 0.15 to combat label imbalance
   - Routing loss: `L_rout = BCE(logit_rout, y_rout)`
   - Combined: `L = 0.3·L_trig + 1.0·L_rout`
   - AdamW (lr=3e-4, weight_decay=1e-4, grad clip 1.0), batch=32 sessions, 2 epochs (~5 min on 1×A6000)

6. **Supervision Labels:**
   - Trigger: y_trig = 1 if assistant proposed non-null task at that event, else 0 (from ProactiveAgent training set)
   - Routing: apply the same deterministic extractor to proposed-task text, match extracted surface forms back to entity nodes in event graph; events without matched graph entity excluded from routing loss

7. **Inference (strictly causal):**
   - Drop backward temporal edges; zero input features of future event nodes (t′ > t)
   - Fixed threshold τ = 0.5 (natural sigmoid boundary) — no per-backbone tuning
   - If p_trig(t) ≥ τ → fire, route top-k (k=20) entities by s_rout to downstream agent
   - If p_trig(t) < τ → abstain, no downstream LLM call
   - Cached streaming serving: recurring entity embeddings (apps, file_ext, type nodes) precomputed; only event text + genuinely fresh entities encoded per event

8. **Downstream Language Agent:** A frozen instruction-tuned LLM receives session history (last 5 events), current observation, and the routing list as structured JSON. Prompt enforces: treat first routing entry as anchor, quote surface text inline, lead with deliverable (not verb mirror), single sentence ≤150 chars, never invent artifacts. Same prompt serves all 14 backbones with no per-model tuning.

**Total parameters:** 110.4M (1.16M trainable + 109M frozen BGE encoder). BF16 resident footprint: ~220 MiB.

## 2. Results (real benchmark numbers with units)

**Main Results on ProactiveAgent Test Set (14 backbones):**
- TGL improves F1 on **every single backbone** (range +3.1 to +46.0, mean +16.7)
- Best gains: Qwen3-8B +46.0 (vanilla 26.14 → 72.14), Qwen3-4B +28.2, DeepSeek-V4-Pro +26.6
- Smallest gains (strongest models already well-calibrated): Claude-Opus-4.7 +5.4 (74.44 → 79.86), GPT-5.4 +3.1 (73.47 → 76.57)
- TGL+Qwen2-7B (F1=70.68) beats proactively fine-tuned Qwen2-7B-Proactive (F1=66.47)

**Trigger Architecture Comparison (Table 2):**
- TGL AUC (must-fire): **0.738** vs. best LLM (Qwen3-0.6B LoRA): 0.668 (+7.0 pp)
- TGL AUC (can-skip): **0.658** vs. best LLM (Qwen3-8B): 0.618 (+4.0 pp)
- TGL AUC (must-skip): **0.639** vs. best LLM (Qwen3-8B): 0.597 (+4.2 pp)
- TGL Brier score: 0.308 (well-calibrated) vs. LLM triggers: 0.58-0.66 (poorly calibrated)
- TGL ECE: 0.334 vs. LLM triggers: 0.59-0.66
- TGL Trigger std (oracle threshold drift across 14 backbones): **0.035** (smallest) vs. LLM: 0.14-0.26, BGE: ≥0.36
- Full-SFT ProactiveAgent trigger AUC: 0.505 (chance-level)

**Latency (per event):**

**Resource Footprint:**

## 3. Trade-offs (wins vs loses table)

| Win | Loss / Cost |
|------|-------------|
| TGL trigger 11.13 ms vs LLM trigger 40-1,157 ms (4-83× faster) | Requires 220 MiB resident memory for BGE encoder + GNN weights |
| TGL AUC 0.738 (must-fire) vs best LLM 0.668 (+7 pp) | Requires deterministic entity extraction rules (regex-based, platform-specific engineering) |
| One TGL checkpoint + single threshold (τ=0.5) serves all 14 backbones with no per-backbone tuning | Only evaluated on offline RM-judge protocol; no live user study — subjective user experience unmeasured |
| F1 improves on every backbone (mean +16.7), no regression | Graph construction is platform-specific (desktop entity ontology vs. mobile schema); requires per-platform adaptation |
| Trigger probability distribution is continuous and well-calibrated (Brier 0.308, 0% at extremes) | BGE text encoder dominates forward cost (~70% of latency); competitive only because entity caching avoids re-encoding |
| Causal inference (backward edges dropped at test time) → no future leakage | Training uses bidirectional temporal edges; the model may rely on patterns only visible bidirectionally, weakening causal performance |
| Drop-in compatible with fine-tuned downstream agents — F1 improves while saving ≥21% LLM calls | Routing labels derived from proposed-task text via deterministic extractor — extraction failures silently reduce supervision quality |
| Consumer-laptop deployable (13.99 ms, 267 MiB peak) — activity stream stays on-device for privacy | Only tested on English (desktop) and Chinese (mobile) benchmarks — cross-lingual generalization unknown |
| Trainable in 5 minutes on a single A6000 | Inference limited to 64-event session cap — longer sessions require graph truncation |

## 4. Design Rationale (why this approach)

1. **Structure-native over text-recovered**: The authors argue that rendering structured event tuples as text and asking an LLM to recover structure is a "round-trip the system never had to take." Since user activity logs are already templated (e.g., "The user opened '{file}' in {app}."), the native representation is a heterogeneous temporal graph. Using a GNN directly on the graph avoids the information loss of flattening entity-event many-to-many relationships into token sequences.

2. **Shared hidden state prevents trigger-context drift**: By producing the trigger probability and routing scores from the same hidden state in one forward pass, the two decisions cannot disagree about their supporting evidence. The ablation shows this is empirically load-bearing: replacing routing entities with random ones costs -8.6 F1 even when trigger and prompt are held constant.

3. **LLM reserved for what it is good at**: The trigger decision is a simple binary classification over structured data — overkill for a reasoning model. The downstream agent only needs the LLM's language generation capability to turn a small structured handoff into a fluent sentence. This division of labor minimizes expensive LLM calls.

4. **Calibration over raw accuracy**: TGL's trigger produces a continuous probability distribution centered on [0.55, 0.85] vs. the LLM triggers' collapse to score extremes (95-98% in [0,0.05)∪[0.95,1]). This enables a single deployment threshold (τ=0.5) that works across all backbones — operational simplicity that non-graph triggers cannot match.

5. **Graceful hardware degradation**: GNN message-passing is memory-bound rather than compute-bound, so TGL degrades only ~25% when moving from server to laptop (11.13→13.99 ms), while LLM triggers degrade 4-14× (the dense matmul prefill is GPU-bound). This makes TGL viable on consumer hardware without quantization or distillation.

## 5. Limitations & Failure Modes

1. **Offline evaluation only**: All results use the released ProactiveAgent RM-judge protocol. No user study or live deployment evaluation — subjective user experience (interruption timing, attentional cost, acceptance rates under real cognitive load) is entirely untested.

2. **Activity-stream privacy dependency**: The always-on trigger processes sensitive data (file names, URLs, search queries, app switches, demographic fields on FingerTip). On-device deployment mitigates this but does not eliminate the privacy concern — standard data minimization, opt-out, and retention controls are still required.

3. **Platform-specific graph construction**: The entity extractor relies on regex rules and platform-specific ontologies (desktop app registry, MIME database, TLD conventions). Porting to a new platform requires re-implementing the extraction layer — the graph *principle* transfers but the *instantiation* does not.

4. **64-event session cap**: Per-session graphs are capped at 64 events. Sessions longer than this require truncation, losing older context that may be relevant for trigger decisions on long-running work sessions.

5. **Supervision quality depends on deterministic extractor reliability**: Routing labels are derived by applying the entity extractor to proposed-task text and matching against graph entities. If the extractor fails to match an entity (e.g., the proposed task references a file by a different surface form), that event contributes no routing signal even though the task text is valid.

6. **Bidirectional training → causal inference gap**: Training uses both forward and backward temporal edges for richer session context; inference drops backward edges for causality. This gap may cause performance degradation for trigger decisions that benefit from future context (e.g., inferring that a file-open event is significant because the next event shows extensive editing).

7. **No exploration of personalization at scale**: The Discussion sketches a personalization path (fine-tune only the small TGL model on per-user feedback) but this is never experimentally validated.

8. **Cross-lingual and cross-domain generalization untested**: Only evaluated on English (desktop ProactiveAgent) and Chinese (mobile FingerTip). Performance on other languages or activity domains (e.g., enterprise software, creative tools) is unknown.

## 6. Transfer to Lyra (the one idea + §4.x workstream + Impact/Effort/Tier)

**The ONE transferable idea:** Replace Lyra's always-on context monitoring with a lightweight temporal graph encoder that jointly produces trigger decisions and semantic routing — the expensive LLM call only fires when the trigger clears threshold, and receives a structured entity-anchor list rather than raw text. This directly addresses Lyra's §4.2 (Context & Attention) workstream by giving the context engine a fast, calibrated gating mechanism that stays on-device and preserves the privacy of user activity streams.

**Workstream route:** §4.2 — Context & Attention (the always-on signal monitoring layer)

**Impact: 4** — Substantial latency reduction (11 ms vs. 100-1000+ ms for LLM-based monitoring), well-calibrated trigger probability, and the routing mechanism provides grounded entity context rather than free-text inference. The drop-in composability with existing fine-tuned agents means Lyra could adopt this without retraining downstream components.

**Effort: 3** — Requires implementing deterministic entity extraction rules for Lyra's domain (coding + research workflows), training a small GNN (~1.2M params, ~5 min on a single GPU), and integrating the cached streaming serving protocol. The graph construction layer is the main engineering cost (platform-specific regex rules, entity ontology mapping). The GNN architecture and training recipe are directly transferable from the paper.

**Tier:** breakthrough — This paper provides a principled, empirically validated answer to a core architectural question for proactive agents: what runs on the always-on path vs. what is gated behind it. The TGL approach beats all LLM-as-trigger baselines on every metric (AUC, calibration, latency, footprint) and generalizes across 14 diverse backbones. For Lyra, which aims to be a proactive coding/research assistant, this pattern could transform the context engine from a costly continuous LLM-polling loop into a fast, private, well-calibrated graph-powered gate.
