## 1. Mechanism (step-by-step)

PosterForest is a **training-free, hierarchical multi-agent framework** for Scientific Poster Generation (SPG) with two main stages:

### Stage 1: Hierarchical Paper-to-Poster (Section 3.2)

**Step 1: Parse into Raw Doc Tree (T_Raw).** A Parser Agent (A_Parse) extracts the structural hierarchy of the input paper D into a rooted tree:

```
T_Raw = A_Parse(D)                                          (Eq. 1)
```

Each node v ∈ V_Raw represents a document element (title, section, subsection, paragraph, figure, table). Directed edges (u → v) denote parent-child containment. The parser uses Docling for PDF-to-Markdown conversion and an MLLM (e.g., GPT-4o) with a structured JSON prompt to extract hierarchy and asset cross-references.

**Step 2: Content Refinement → Content Tree (T_Content).** A content refinement agent (A_Refine) prunes, merges, and summarizes:

```
T_Content = A_Refine(T_Raw)                                 (Eq. 2)
```

Each content node c = (t, s) encodes a semantic type t (paragraph, figure, table) and semantic content s (summarized text, caption, visual data). Redundant nodes are pruned, closely related content is merged, and verbose paragraphs are condensed.

**Step 3: Layout Initialization → Layout Tree (T_Layout).** A deterministic layout initialization function derives spatial organization from content statistics:

```
T_Layout = O_Layout_Init(T_Content)                         (Eq. 3)
```

Each layout node l = (r, x) specifies region type r (row split, column split, panel) and spatial attributes x (normalized position, width, height, aspect ratio). The tree follows recursive row/column partitioning — the standard in poster layout modeling (Qiang et al., 2016, 2019).

**Step 4: Merge into Poster Tree (T_Poster).** Content and layout are unified:

```
T_Poster = O_Merge(T_Content, T_Layout)                     (Eq. 4)
```

Each poster node w is a heterogeneous node jointly encoding semantic attributes (from T_Content) and spatial attributes (from T_Layout). The merge aligns the content hierarchy with the layout partition. The initial tree is denoted T_Poster^(0).

### Stage 2: Hierarchical Modification Planning (Section 3.3)

This stage performs **iterative refinement** across two nested granularities:

#### Inner Loop: Poster Tree Traversal (Node-level, Section 3.3.1)

A top-down traversal from root to leaves, where each node is updated considering its parent's propagated state and its descendants' structural context:

**Layout Agent (A_Layout):** For each layout node l_i, optimizes geometric attributes (region ratios, alignment, spatial distribution) by aggregating semantic statistics of all descendants:

```
l_i^(t+1) = A_Layout(l_i^(t), P̃(l_i), D(l_i))              (Eq. 5)
```

where P̃(l_i) is the updated parent information and D(l_i) is the set of all descendants of l_i. The Layout Agent uses a legibility-balance heuristic (see Figure A7 in Appendix): it compares perceived text size and structural complexity of figures across panels, then decides direction (LEFT/RIGHT/TOP/BOTTOM) and delta ∆ ∈ [0,5] for proportional enlargement of the harder-to-read panel.

**Content Agent (A_Content):** For each content node c_i, refines textual density and semantic abstraction:

```
c_i^(t+1) = A_Content(c_i^(t), P̃(c_i), D(P(c_i)))          (Eq. 6)
```

where D(P(c_i)) is all descendants of the parent layout node. The Content Agent operates in two modes: **Expand** (when content density < 100%, splits bullets, adds key concepts/methods/results) and **Condense** (when density > 100%, merges bullets, removes overlap with siblings). Target density: 80-100% fill ratio.

#### Outer Loop: Iterative Tree Refinement (Tree-level, Section 3.3.2)

After a full node-level traversal completes, a **Global Feedback Agent (A_Feedback)** evaluates a rendering image of the current poster tree:

```
(F̂_Global, π_Continue) = A_Feedback(T_Poster^(t))          (Eq. 7)
```

The agent assesses three criteria: (1) visual organization (alignment, whitespace, figure-text balance, overflow), (2) textual structure (redundancy, truncation, missing context, uneven verbosity), (3) hierarchical balance (section order, parent-child locality, heading consistency, grouping coherence). It outputs a binary signal π_Continue ∈ {0,1}.

If π_Continue = 1, another full tree traversal is triggered:

```
T_Poster^(t+1) = O_Traverse(T_Poster^(t), F̂_Global)        (Eq. 8)
```

The process repeats up to **K = 2 iterations** (empirically found to yield stable results). The final poster tree T_Poster* is then rendered into an HTML poster.

### Key Data Structures

- **Poster Tree:** A heterogeneous tree where each node carries both semantic content (text bullets, visual assets) and layout attributes (position, size, region type, split ratio). This is the paper's core innovation — a unified intermediate representation.
- **Volume ratio:** Fraction of available panel space currently filled; Content Agent targets 80-100%.
- **Layout delta ∆ ∈ {0,1,2,3,4,5}:** Continuous legibility adjustment signal from Layout Agent.

### Ablation Results

- **Without hierarchical tree:** Sections become disordered, figures appear under wrong headings (e.g., performance table under Introduction instead of Experiments).
- **Content Agent only:** Text redundancy reduced, but suboptimal panel arrangements.
- **Layout Agent only:** Better spatial organization, but suboptimal figure scaling and text overflow.
- **Both agents combined:** Balanced layout + redundancy removal = "well-organized posters with appropriate information density and visual harmony."

### Dataset
100 paper-poster pairs from Paper2Poster benchmark (extended PosterSum) for quantitative eval; 15 recent paper-poster pairs from NeurIPS/CVPR/ACL for qualitative/user studies.

## 3. Trade-offs

| What PosterForest Wins | What PosterForest Loses |
|------------------------|------------------------|
| Training-free (no instruction tuning or regressor fitting needed) vs. P2P (requires training) and Paper2Poster (requires regressor) | Multiple MLLM API calls per poster (Parser + Refine + Layout Init + K × per-node Content/Layout agents + K × Feedback agent) → higher inference cost and latency |
| Hierarchical document understanding preserves section-subsection-paragraph relationships | Flat-content baselines (P2P, Paper2Poster) may produce simpler/faster one-pass results |
| Joint content-layout optimization through shared Poster Tree, preventing misplacement of figures/tables | Requires reliable document parsing (depends on Docling quality); poorly structured papers may degrade |
| Recursive refinement (up to K=2 passes) with global feedback catches errors that single-pass pipelines miss | Feedback agent evaluates from image rendering → adds a VLM call; K=2 means up to 3x VLM calls just for feedback |
| Content Agent's volume-ratio targeting (80-100% fill) avoids truncated text and oversized figures | May still not achieve optimal content density (acknowledged limitation) |
| 59.2% human preference vs. 27.2% for next-best baseline | Requires GPT-4o level MLLM; weaker MLLMs (Qwen variant scores lower: 3.72 vs 3.76) |

## 4. Design Rationale

**Why hierarchical tree instead of flat pipeline:** Existing methods treat papers as linear text sequences, ignoring section-subsection relationships. This causes figure-table misplacement (Figures in Conclusions sections). A tree representation naturally preserves document hierarchy and enforces parent-child locality for visual elements.

**Why multi-agent collaboration instead of single-agent reasoning:** Scientific poster generation requires balancing content fidelity, layout efficiency, and visual coherence — objectives that are difficult to optimize jointly within a single reasoning process. Separate Content and Layout agents with role specialization and iterative feedback enable complementary optimization.

**Why training-free:** Prior work (P2P instruction tuning, Paper2Poster regressor fitting) adds complexity and dataset dependency. Training-free operation using only standard LLM APIs enables immediate practical deployment without curated poster datasets.

**Why K=2 tree-level iterations:** Empirically, one additional refinement pass after the initial tree is sufficient for stable, visually balanced results. More iterations yield diminishing returns.

**Why legibility-based layout (not area-based):** Layout Agent prioritizes perceived text size and diagram complexity over raw figure area, preventing the common failure where a large-but-simple diagram dominates a panel at the expense of a small-but-dense chart with critical axis labels.

## 5. Limitations and Failure Modes

1. **Suboptimal content density:** Generated posters "may not always achieve optimal content density, which can lead to less efficient space utilization." Content Agent targets 80-100% fill but may underfill or overfill.

2. **Weak evaluation metrics:** The paper explicitly acknowledges "the lack of robust quality metrics may limit the comprehensiveness of quantitative evaluation." The MLLM-as-a-Judge metric (GPT-4o scoring on 1-5 scale) has known limitations for capturing subtle visual qualities and subjective preferences valued by humans.

3. **Parser dependence:** The entire pipeline depends on Docling for PDF-to-Markdown conversion quality. Poorly structured papers (e.g., scanned PDFs, unusual formatting) will degrade downstream performance.

4. **MLLM-dependency:** Performance drops with weaker MLLMs (PosterForest-Qwen: 3.72 Overall vs. PosterForest-4o: 3.76), and the entire pipeline is infeasible without access to frontier MLLMs.

5. **Cost/latency:** The multi-agent iterative refinement requires many API calls (Parser × 1 + Refine × 1 + per-node Content/Layout agents + up to K Feedback calls + final rendering), making it more expensive than single-pass pipelines.

6. **ACM-specific bias:** Training-free but prompting strategies and evaluation were designed for computer science papers (NeurIPS/CVPR/ACL/ICML/ECCV); generalizability to other scientific domains (chemistry, biology, medicine) with different figure/table conventions is untested.

7. **No diversity/creativity control:** The framework optimizes for faithfulness and structural clarity but provides no mechanism for controlling visual identity, color scheme, or layout style — standardized colors/fonts were forced for fair evaluation.

## 6. Transfer to Lyra

**The ONE transferable idea:** The **Poster Tree** — a unified heterogeneous tree representation where each node jointly encodes semantic content AND spatial layout attributes, enabling multi-agent recursive refinement through top-down propagation of parent state + aggregation of descendant context.

This is directly applicable to Lyra's document understanding and structured output capabilities. Lyra could adopt a similar "unified semantic-spatial tree" for any task requiring joint optimization of content structure and visual/spatial organization (e.g., generating structured reports, dashboards, slides, or other formatted outputs from unstructured research inputs). The key insight is that **splitting content and layout agents with a shared tree representation enables each agent to focus on its specialty while maintaining consistency through the tree** — the layout agent propagates spatial constraints downward, and the content agent adapts textual density upward.

**Workstream Route:** §4.6 (Multi-Agent Architecture & Orchestration) — specifically the agent specialization patterns and inter-agent communication via shared structured representations.

**Impact:** 4 (Directly improves Lyra's ability to produce structured, well-organized outputs; the hierarchical tree pattern generalizes beyond posters to any document-to-structured-output task)

**Effort:** 3 (Requires implementing tree representation, recursive traversal, and two specialized agents; training-free design means no dataset curation needed; standard LLM APIs sufficient)

**Tier:** Breakthrough (Novel representation + multi-agent architecture yielding 2.2x human preference over next-best method)
