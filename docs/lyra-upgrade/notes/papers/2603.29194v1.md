## 1. Mechanism

The Multi-Layer Memory Framework (MLMF) decomposes dialogue history into three memory layers with adaptive retrieval gating and retention regularization. The mechanism operates as a constrained state-transition process formalized in Algorithm 1.

### 1.1 Memory Decomposition (Eq. 2)

The memory state at session t is a triple:

$$M_t = \{M_t^{(w)}, M_t^{(e)}, M_t^{(s)}\}$$

- **Working Memory** $M_t^{(w)}$: token-level encoding of the current session $S_t$ within a bounded window of size k, enforced by a capacity projection $\Pi_{C_w}$. Preserves temporal locality and recent task-relevant signals.

$$M_t^{(w)} = \Pi_{C_w}(\phi_w(S_t)) \quad \text{(Eq. 4)}$$

- **Episodic Memory** $M_t^{(e)}$: recursively accumulated session summaries via exponential moving average with decay $\alpha \in [0,1]$:

$$M_t^{(e)} = \Pi_{C_e}\left(\alpha M_{t-1}^{(e)} + (1-\alpha)\psi(S_t)\right) \quad \text{(Eq. 5)}$$

Lower $\alpha$ emphasizes abstraction; higher $\alpha$ preserves detail. This prevents abrupt forgetting.

- **Semantic Memory** $M_t^{(s)}$: entity-event graph $\mathcal{G}_t$ abstracted from episodic summaries via $\mathcal{A}(M_t^{(e)})$, with conflict resolution against a similarity threshold $\tau_s$. Enforces stable persona and event structure.

$$M_t^{(s)} = \Pi_{C_s}\left(M_{t-1}^{(s)} \cup \mathcal{A}(M_t^{(e)})\right) \quad \text{then} \quad M_t^{(s)} \leftarrow \text{RESOLVE}(M_t^{(s)}, \tau_s) \quad \text{(Eq. 6)}$$

### 1.2 Adaptive Retrieval Gating (Eq. 7)

At each turn, a softmax-weighted retrieval mechanism selects relevant content across all three layers:

$$\gamma_i = \frac{\exp(\beta \cdot \text{sim}(x_t, M_t^{(i)}))}{\sum_{j \in \{w,e,s\}} \exp(\beta \cdot \text{sim}(x_t, M_t^{(j)}))}, \quad R_t = \sum_{i \in \{w,e,s\}} \gamma_i M_t^{(i)}$$

Where $\beta$ controls retrieval sharpness (temperature parameter). This dynamically prioritizes layers based on current input relevance.

### 1.3 State Fusion (Eq. 8)

Cross-attention fusion between current input $x_t$ and retrieved memory $R_t$:

$$z_t = f_\theta(x_t, R_t)$$

With an entropy bound constraint: $H(z_t) \leq \epsilon$ to regulate information flow.

### 1.4 Retention Stability Regularization (Eq. 9-10)

The key innovation — a regularization term that penalizes abrupt shifts in the semantic embedding space:

$$\mathcal{L}_{\text{ret}} = \sum_{t=1}^{T} \|E(M_t^{(s)}) - E(M_{t-1}^{(s)})\|_2^2$$

Where $E(\cdot)$ projects semantic memory to entity embeddings. Combined with generation loss:

$$\mathcal{L} = \mathcal{L}_{\text{gen}} + \lambda \mathcal{L}_{\text{ret}}$$

This jointly optimizes response fluency and cross-session memory consistency.

### 1.5 Algorithm 1: Full Procedure

```
Input: Sessions {S_1,...,S_T}, bounds (k,α,β,λ), capacities (C_w,C_e,C_s)
For t = 1 to T:
  1. M_t^{(w)} ← Π_{C_w}(φ_w(S_t))           // Bounded working encoding
  2. Ŝ_t ← ψ(S_t); M_t^{(e)} ← Π_{C_e}(α·M_{t-1}^{(e)} + (1-α)·Ŝ_t)  // Episodic EMA
  3. G_t ← A(M_t^{(e)}); M_t^{(s)} ← Π_{C_s}(M_{t-1}^{(s)} ∪ G_t)  // Semantic graph
  4. RESOLVE conflicts in M_t^{(s)} via τ_s threshold
  5. r_i ← ⟨x_t, M_t^{(i)}⟩; γ_i ← softmax(β·r_i)  // Layer importance
  6. R_t ← Σ γ_i·M_t^{(i)}; z_t ← f_θ(x_t, R_t)    // Fused representation
  7. y_t ← argmax_y P_θ(y | z_t)                    // Response
  8. L_ret ← ||E(M_t^{(s)}) - E(M_{t-1}^{(s)})||²₂  // Stability loss
  9. θ ← θ - η∇_θ(L_gen + λ·L_ret)                  // Joint parameter update
```

## 3. Trade-offs

| Win | Loss |
|-----|------|
| +8.65% absolute retention improvement over 6 temporal periods vs. parameter-memory baseline | Requires three separate memory subsystems (working, episodic, semantic) — implementation complexity |
| −1.7% absolute false memory rate (5.1% vs 6.8%) | Conflict resolution step (RESOLVE) adds per-session computational overhead, unscaled |
| −6.58% absolute context usage (58.40% vs 64.98%) — runs under tighter budget | Three hyperparameters (α, β, λ) plus three capacity limits (C_w, C_e, C_s) require tuning per benchmark |
| +1.4× decoding throughput improvement (10.4× vs 9×) | Semantic graph construction A(·) requires entity extraction pipeline not detailed in paper |
| Retention gains achieved *without* increasing context window — anti-correlation between retention quality and context usage | Only evaluated on dialogue benchmarks (no code, no tool-use, no multimodal tasks) |
| Joint optimization of generation + retention via single scalar λ | No latency or wall-clock measurements reported — throughput figures are relative to baselines only |

## 4. Design Rationale

The authors argue that prior approaches fall into a false dichotomy: **efficiency-focused methods** (KV eviction, context compression) reduce token cost but do not stabilize semantic retention across sessions, while **retention-focused methods** (parameter memory, retrieval augmentation) improve recall but suffer from uncontrolled false memory accumulation. The MLMF design explicitly targets this gap by coupling **hierarchical decomposition** (separating short-term tokens from long-term abstractions) with **retention regularization** (penalizing abrupt entity-embedding shifts). The three-layer architecture mirrors cognitive science models of human memory (working/episodic/semantic), chosen because each layer addresses a distinct timescale: immediate interaction (working), session-level summary (episodic), and persistent persona/entity knowledge (semantic). The adaptive gating mechanism avoids fixed retrieval heuristics by letting the model learn layer importance dynamically per input. The retention stability objective (Eq. 9) is the architectural keystone — it provides an explicit gradient signal for semantic continuity, absent from all prior baselines.

## 5. Limitations and Failure Modes

1. **Narrow benchmark scope**: Evaluated only on dialogue benchmarks (LOCOMO, LOCCO, LoCoMo). No results on code generation, tool-use, reasoning, or multimodal tasks. Unknown whether the three-layer decomposition generalizes beyond conversational settings.

2. **No absolute latency/throughput numbers**: Reports only relative speedups (10.4× vs 9×). No wall-clock time, GPU-memory, or FLOP measurements. Cannot assess production deployment cost.

3. **Unclear entity extraction**: The semantic graph constructor A(·) is described as mapping episodic summaries to entity-event graphs, but the implementation details (NER model, relation extraction, graph storage format) are omitted.

4. **arXiv category mismatch**: Listed under cs.CV (Computer Vision) rather than cs.CL, suggesting potential submission error.

5. **Hyperparameter sensitivity not analyzed**: α (decay), β (retrieval sharpness), λ (regularization weight), and three capacity limits (C_w, C_e, C_s) are tuned per benchmark. No sensitivity analysis or guidance for choosing these values in new domains.

6. **Industry affiliation with limited track record**: Authors are from "Fulloop" which has minimal publication history; results should be treated as preliminary until independently reproduced.

7. **Single evaluation protocol**: All experiments use identical decoding settings controlled by the authors. No evaluation of robustness to different decoding temperatures, model architectures, or prompt formats.

8. **Scalability ceiling unknown**: Only validated on dialogues averaging ~16.6K tokens and 27.2 sessions. Behavior at 100K+ tokens or 100+ sessions is untested.

## 6. Transfer to Lyra

### The One Transferable Idea

The **retention stability regularization loss** ($L_{\text{ret}} = \sum \|E(M_t^{(s)}) - E(M_{t-1}^{(s)})\|_2^2$) is the most transferable concept. It provides a simple, differentiable mechanism to penalize semantic drift across sessions/turns by computing the L2 distance between consecutive entity embeddings. This can be injected into Lyra's existing memory subsystem as an auxiliary loss term during memory consolidation, requiring only that Lyra maintain an entity embedding projection of its semantic state. The cost is minimal — one additional forward pass on the entity embedder per consolidation step plus an L2 computation.

### Workstream Route: §4.2 Memory

This feeds directly into Lyra's memory subsystem overhaul (§4.2), specifically the cross-session state stability problem described in the memory subsystem plans (02-memory.md). The regularization objective provides a principled alternative to ad-hoc retention heuristics.
