# STAR-Teaming: A Strategy-Response Multiplex Network Approach to Automated LLM Red Teaming
**MinJae Jung, Junghwan Kim, YongTaek Lim, Kihyun Kim, Chaeyun Kim, Minwoo Kim** (DATUMO INC.) — arXiv:2604.18976v1 [cs.CL], April 2026

## 1. Mechanism (step-by-step)

STAR-Teaming combines a Multi-Agent System (MAS) with a probabilistic multiplex network for automated black-box LLM red-teaming. The core insight is recasting the intractable high-dimensional search space of attack strategies into a tractable structure via community detection and inverse statistical mechanics.

**Step 1 — Warm-up Log Generation.** The attacker LLM generates jailbreak prompts from seed malicious requests with temperature > 0 (no strategies yet). Target LLM responds. Scorer LLM rates responses 1–10. Strategy extractor LLM performs comparative analysis on differing-score attack pairs to extract named strategies with definitions. This produces ~500 (strategy, response) pairs at <$1 cost.

**Step 2 — Multiplex Network Construction.** Two parallel networks are built:

*Response Network:* Text embeddings e_r for each unique target response → cosine similarity matrix S_r (N_l × N_l) → adjacency matrix A_r via threshold α_r = 0.85 (Eq 1) → Leiden community detection → community membership vectors G(r): for each response r_l, h_l = one-hot vector of length N_J.

*Strategy Network:* Text embeddings e_stg for strategy names/definitions → similarity matrix S_stg (N_k × N_k) → adjacency matrix A_S via threshold α_stg = 0.9 (Eq 3) → Leiden community detection → community membership vectors H(S): for each strategy s_k, h_k with h_ki = 1 if s_k ∈ C(S)_i, else −1/(N_I−1). The negative term serves dual purpose as regularizer and probability redistributor. Default output: N_J = 50 response communities, N_I = 15 strategy communities → mapping matrix Z of only 750 parameters.

**Step 3 — Inverse Ising Problem Optimization.** The energy of a response-strategy pair is defined via Hamiltonian:

```
E(r_p, s_q) = − Σ_ij Z_ij O^ij_pq
```

where O^ij_pq = G(r_p)_j · H(s_q)_i encodes the co-occurrence of response community j and strategy community i. The probability follows the Boltzmann distribution p(x) ∝ exp(−E(x)). Parameters Z* are learned by maximizing log-likelihood (Eq 6–7), which is convex with a unique global optimum (proved in Appendix C via positive semi-definite Hessian). Gradient ascent update:

```
Z^{t+1}_ij = Z^t_ij + lr · (Σ_{(r_p,s_q)∈D} O^ij_pq − N_D ⟨O^ij⟩)
```

The first term is empirical co-occurrence; the second is expected co-occurrence under the current model. Lifelong variant weights by scorer score f_sc(r_t): positive for success, negative for failure, penalizing ineffective strategy-response couplings (Eq 12). Training convergence: ~0.02 seconds for 750 parameters.

**Step 4 — Probabilistic Strategy Sampling.** Given new response r′, its community G(r′) is determined by cosine similarity to community centroids (winner-takes-all). Strategy community sampling probability:

```
P(H(s_k) | G(r′), Z) ∝ exp(β · Σ_j Z_kj G(r′)_j)
```

The logit for strategy community k is Z·G(r′). Temperature β is adaptively scheduled so top-3 strategy communities carry ~80% of probability mass (Algorithm 2). Larger β = exploitation; smaller β = exploration. Once a community is sampled, a specific strategy is drawn from its member nodes.

**Step 5 — Iterative MAS Loop.** Attacker generates jailbreak prompt using sampled strategy + seed. Target responds. Scorer evaluates. If score < 8.5, resample strategy via network, retry. Up to 140 attempts per seed. Three tempering stages: (a) first 20 attacks without strategy, (b) up to 100 strategic attacks, (c) exploration phase where LLM invents novel strategies, avoiding prior failures.

**Step 6 — Dynamic Network Expansion (Optional).** When novel responses or strategies emerge, modularity-based criterion decides community assignment (Eq 13):

```
∆M = max_{c∈C} ∆Q(n, c) − λ · ∆Q(n, c_new)
```

If ∆M < 0, create new singleton community; otherwise absorb into best existing one. λ controls plasticity (λ→0 = highly adaptive, λ→∞ = static). Dynamic variant achieves ASR 77.3% vs 71.0% static, with fewer iterations (52.4 vs 61.1).

## 3. Trade-offs

| Win | Cost / Trade-off |
|---|---|
| +13.5pp ASR over best baseline (AutoDAN-Turbo) on HarmBench | Requires initial warm-up phase (50 seeds, 500 response-strategy pairs) — cold-start problem |
| 2.2× fewer iterations and 2.7× fewer tokens than TAP | Performance depends on attacker LLM quality — weaker attacker models yield lower ASR (e.g., Llama2-7b as attacker drops ASR from 71.0% to 61.3%) |
| Interpretable community structure reveals which strategy types exploit which model families | Static network topology drifts over extended deployment — centroids not retroactively re-optimized |
| Dynamic expansion adapts to novel strategies at runtime (+6.3pp ASR) | Introduces hyperparameter λ — poorly tuned λ causes either excessive fragmentation or failure to recognize novelty |
| Extremely small parameter count (750 for Z matrix) enables sub-second optimization | Relies on LLM-based scorer for training signal — scorer errors propagate through Z updates (though empirically robust at 95.1% Unsafe agreement) |
| Diverse strategy sampling (Gini 0.19 vs 0.36, Self-BLEU 0.25 vs 0.46) | Strategy extraction and prompt engineering require significant human design effort |
| Lifelong learning from both successes and failures | Optimal network size is dataset-dependent (peak at 250 nodes, degrades at 1500) |
| Network construction costs <$1 (gpt-4o-mini) | Sensitive to warm-up seed source — using test-set seeds inflates performance (73.8% vs 71.0%) |

## 4. Design Rationale

**Why a multiplex network instead of embedding-similarity retrieval?** The authors empirically demonstrate (Figure 4–5, Table 2) that embedding-similarity retrieval concentrates samples on a few strategies regardless of their actual effectiveness (Pearson correlation −0.08), producing redundant attacks. The multiplex network restructures the search space into semantic communities, enabling diverse sampling that is *positively* correlated with strategy effectiveness (Pearson 0.81).

**Why the Inverse Ising Problem rather than RL or bandits?** The Inverse Ising formulation is convex with a provably unique global optimum (Appendix C), guaranteeing convergence. Compared to a Multi-Armed Bandit baseline (Table 7: 69.0% vs 71.0%), the network approach explicitly captures *structural* relationships between strategy communities and response patterns that a flat reward signal cannot. The configuration space is O(N) via one-hot encoding rather than O(2^N), keeping Z tractable.

**Why community detection (Leiden) rather than treating strategies individually?** The Strategy Network analysis (Figure 7–8) reveals high semantic redundancy — many differently-named strategies correspond to functionally identical patterns. Community detection resolves this redundancy, and the Leiden algorithm achieves near-perfect intra-community semantic coherence (K = 0.998 for strategies, 0.882 for responses; vs random baseline 0.778/0.562 in Table 5).

**Why dynamic expansion via modularity?** Static topologies cannot incorporate novel strategies discovered during attacks. The modularity-based criterion provides a principled, parameter-free (beyond λ) method to decide whether a new node deserves its own community or should merge — grounded in the well-established modularity optimization framework (Blondel et al., 2008).

## 5. Limitations & Failure Modes

1. **Prompt Engineering Dependency.** Every agent (attacker, scorer, strategy extractor) is an LLM whose quality depends on prompt design. Weak prompts degrade the entire pipeline. No automated prompt optimization is provided.

2. **Community Centroid Drift.** During extended deployment, community centroids are never retroactively re-optimized. New strategies/responses may shift the semantic meaning of a community, but the fixed centroids become progressively less representative. The authors acknowledge periodic re-initialization as future work.

3. **Single-Scorer Bottleneck.** The entire training signal for Z depends on one scorer LLM. While human agreement is high (95.1%), the 4.9% false-positive rate on BeaverTails and 17.8% on WildGuard means some ineffective strategies receive positive reinforcement. Ensemble scoring improves agreement (+1.7–7.3pp) but at 3.7× cost.

4. **Cold-Start Problem.** Requires a warm-up phase with pre-defined seed prompts. For entirely new domains without existing adversarial seeds, the framework cannot bootstrap. The exploration phase (Appendix F) mitigates but does not eliminate this.

5. **Attacker Model Sensitivity.** ASR drops from 71.0% to 61.3% when switching from Gemma-1.1-7b to Llama2-7b as attacker (Table 6, G1 vs G5). The framework inherits the attacker LLM's creative limitations.

6. **Optimal Network Size Instability.** Performance peaks at 250 nodes and degrades at 1500 (68.8%), suggesting the optimization can be overwhelmed by noise in large networks. No principled method to determine optimal size a priori.

7. **Limited to Text-Only Attacks.** Framework is designed for text-based jailbreak prompts. Multimodal (vision, audio) red-teaming is explicitly deferred to future work.

## 6. Transfer to Lyra

**The One Idea:** Replace Lyra's flat, embedding-similarity-based retrieval of adversarial examples with a **multiplex network that clusters strategies and responses into semantic communities, learns a small coupling matrix Z (~750 parameters) via convex maximum-entropy optimization, and probabilistically samples strategies conditioned on observed response patterns.** This converts an intractable high-dimensional search into a tractable, interpretable structure that actively learns which strategies work against which model behaviors.

**Workstream Route:** §4.17 (Safety/Red-Teaming) — directly applicable to Lyra's adversarial robustness evaluation and safety-jailbreak detection pipeline.

**Impact/Effort/Tier:**
- Impact: 4 — The multiplex network approach offers a general architectural pattern for structuring combinatorial search spaces, applicable beyond red-teaming to any Lyra subsystem where strategy/action spaces need efficient exploration.
- Effort: 3 — Core components (Leiden community detection via `python-igraph`, Boltzmann MLE via `scipy.optimize`, embedding via any encoder) are well-supported in Python. The main cost is warm-up data collection and prompt engineering for strategy extraction.
- Tier: **breakthrough** — This is a genuinely novel architecture for search-space compression that Lyra can adopt across multiple workstreams (red-teaming, retrieval augmentation, agent strategy selection). The 750-parameter Z-matrix pattern generalizes: any two-layer relationship can be modeled this way.
