# OmniDiagram: Advancing Unified Diagram Code Generation via Visual Interrogation Reward

**Authors:** Haoyue Yang, Xuanle Zhao, Xuexin Liu (Institute of Automation, CAS), Feibang Jiang (UCAS), Yao Zhu (Zhejiang University)
**Venue:** arXiv preprint 2604.05514v1, April 7, 2026
**Code:** https://github.com/Haoyue-Yang/OmniDiagram

## 1. Mechanism (step-by-step)

OmniDiagram is a two-stage training framework that unifies diagram code generation across three tasks (Diagram-to-Code, Diagram Editing, Text-to-Code) and three languages (LaTeX, Mermaid, PlantUML) -- a 3x3 task-language matrix. The core innovation is VIVA (Visual Interrogation Verifies All), a reinforcement learning reward mechanism that evaluates diagram fidelity through targeted visual question answering rather than brittle syntax rules or pixel matching.

### Stage 1: Supervised Fine-Tuning (SFT)

**Base model:** Qwen2.5-VL-3B/7B-Instruct

**Training data:** M32 Diagram -- 196k samples (31k open-source + 165k synthesized), plus 77k reasoning-enriched samples. Data is synthesized via a top-down, scenario-driven pipeline using Gemini-2.5-Flash: topic -> scenario -> structured data -> code-image pairs. An error-correction loop with execution feedback filters 300k candidates into 165k high-quality, executable samples.

**SFT objective:** Standard next-token prediction loss:
```
L(θ) = -E(x,y)[Σ log P(yt | x, y<t; θ)]
```

**Data splitting:** Stratified clustering via perceptual hashing partitions data 8:1 into SFT and RL training sets, ensuring balanced distribution across diagram types and difficulty levels.

### Stage 2: VIVA Reinforcement Learning

**VIVA core mechanism (4-step loop):**

1. **Offline Question Generation:** For each RL training sample, generate N visual questions (N=10 per sample) conditioned on the instruction/input image. Questions target topological structure (connection logic), semantic consistency (text accuracy), and aesthetic attributes (colors, shapes). All ground-truth answers are "Yes" when the diagram is correct, enabling task-agnostic scoring. Questions are pre-generated offline by GPT-4.1-mini.

2. **Candidate Code Generation:** For each input x, the policy model πθ generates G=4 candidate codes {o_i}.

3. **Online VQA Evaluation:** Each candidate is rendered to an image. Non-renderable candidates get reward R=0. Rendered candidates are evaluated by a VQA model (Qwen3-VL-32B as reward model) answering the pre-generated questions.

4. **Composite Reward:** Final reward combines VIVA and format components:
```
Ri = α * (1/N) * Σ S(VQA(oi, qk)) + (1-α) * Rfmt
```
where α=0.9, S(·) is a graded scoring function allowing intermediate values (e.g., 0.5 for partial correctness), and Rfmt ∈ {0,1} enforces code structure adherence.

**GRPO optimization:** Candidates are ranked by reward, advantage is computed via group normalization:
```
Âi,t = (Ri - mean({Rj})) / std({Rj})
```
The clipped GRPO objective:
```
J_GRPO(θ) = E[min(r_i,t(θ) * Âi,t, clip(r_i,t(θ), 1-ε, 1+ε) * Âi,t)]
```

**Variance stability proof:** The authors prove that averaging N graded QA scores reduces reward variance compared to binary rewards. Under an equicorrelation model with factor ρ:
```
Var[Racc] = (1/N²) * [Σ σ²_k + 2 Σ ρ √(σ²_k * σ²_l)]
```
Each graded QA score satisfies Var[Xk] ≤ μk(1-μk), with intermediate values producing lower variance than Bernoulli binary rewards. This lower-variance signal leads to more stable policy gradients.

**Hardware:** 8 H800 GPUs for policy training. SFT: ~12h (3B) / ~16h (7B). RL: ~20h (3B) / ~26h (7B). Reward model (Qwen3-VL-32B) deployed in FP16, ~64GB VRAM per GPU.

## 3. Trade-offs

| Win | Lose |
|-----|------|
| Unifies 3 tasks x 3 languages in ONE model vs task-specific models | Requires rendering engine per language (LaTeX/Mermaid/PlantUML) |
| VIVA reward avoids brittle prompt templates and pixel-matching | Needs external reward model (Qwen3-VL-32B, ~64GB VRAM) running alongside policy training |
| 3B model beats GPT-5-mini and 72B baseline on execution rate | SFT-to-RL pipeline must be sequential; pure RL fails (30.2% exec) |
| VQA-based feedback handles multi-modal non-bijective mappings | Computationally heavy: 20-26h RL training on 8xH800 GPUs |
| Graded scoring (partial credit) reduces reward variance vs binary | Fixed α=0.9 between VIVA and format rewards; no task-specific tuning |
| Reasoning data helps Diagram Editing task (+1.4pp) | Reasoning hurts Diagram-to-Code execution rate (from 93.0 -> 89.3) due to "Syntax Tax" |
| Robust to smaller reward models (30B-A3B performs similarly to 32B) | Offline question generation adds pre-processing step (~1h for 25k samples) |
| VIVA is task-agnostic and language-agnostic | Relies on proprietary models (GPT-4.1-mini, Gemini-2.5-Flash) for data synthesis |

## 4. Design Rationale

The authors ground VIVA in cognitive science (Flavell's 1979 metacognition framework): humans verify complex tasks like diagram generation not through holistic similarity comparisons but by systematically checking structural and semantic constraints through targeted questions. Two categories of existing visual feedback approaches are rejected: (a) fixed prompt templates -- brittle and susceptible to prompt hacking by the evaluator model; (b) global visual similarity -- biases toward superficial structural resemblance at the expense of fine-grained detail accuracy. The decoupling of question generation (offline) from answer verification (online) is a deliberate architectural choice that reduces the discriminative burden on the reward model, enabling robust performance even with smaller verifiers. GRPO is chosen over PPO/DPO primarily for its demonstrated efficiency in code generation RL settings (DeepSeek-R1 lineage), though this choice is listed as a limitation warranting further comparison.

## 5. Limitations & Failure Modes

**Stated limitations (Section 5):**
1. Fixed reward weighting α between VIVA and format rewards; task-specific or dynamic adjustment unexplored
2. Only GRPO explored; comparison with PPO, DPO, or other RL paradigms within VIVA framework needed
3. Significant computational overhead from external models for data synthesis and evaluation

**Observed failure modes (Appendix F.2, Table 5):**
- **LaTeX reference errors** (33 errors in 3B, 23 in 7B): Model loses consistency in diagrams with dense connections and complex coordinate systems. Larger models help but do not eliminate.
- **PlantUML syntax errors** (83 errors in both 3B and 7B): Stagnant across model sizes -- a persistent bottleneck with strict domain-specific languages. Multi-layer nesting and recursive structures cause hierarchical block management failures.
- **Mermaid syntax errors** (52 errors in both scales): Similar pattern -- topological complexity is the primary challenge.
- **Pure RL mode collapse** (without SFT): Model generates only Mermaid code, ignoring instruction-specified language. Negligible execution rates for LaTeX and PlantUML.
- **"Syntax Tax" with reasoning (Chain-of-Thought):** Explicit reasoning output during generation consumes context window and disrupts syntactic structure maintenance, causing execution rate drop from 84.7% to 69.5% while valid renderings show higher visual quality. Direct inference with internalized reasoning is superior.

## 6. Transfer to Lyra

**One transferable idea:** VIVA's core mechanism -- generating instance-specific verification questions offline that query rendered/diagrammatic output for structural and semantic correctness, then using VQA scores as a smooth reward signal -- can be directly adapted for Lyra's verification subsystem (§4.3 Verification & Self-Correction). Instead of binary compile/pass checks, Lyra could generate targeted visual/semantic interrogation questions for its own outputs (code, diagrams, documents) and use intermediate scoring to provide smoother, more stable feedback for self-correction loops.

**Workstream:** §4.3 (Verification & Self-Correction / Continuous Quality Assurance)

| Dimension | Rating | Notes |

| Impact | 4 | Smooth graded verification feedback is directly applicable to Lyra's output validation; VIVA's decoupled question-generation/verification architecture is lightweight to adopt |

| Tier | **breakthrough** | Novel verification paradigm (interrogative VQA reward) that replaces brittle binary checks with graded, semantically-aware feedback -- a significant upgrade over current verification approaches |
