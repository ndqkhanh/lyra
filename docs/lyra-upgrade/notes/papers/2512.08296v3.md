## 1. Mechanism (Step-by-Step)

### 1.1 Formal System Model

An agent system S = (A, E, C, Ω) consists of:
- **A** — n agents {a₁…aₙ}, each defined by (Φᵢ, Λᵢ, Mᵢ, πᵢ) where Φᵢ is the LLM reasoning policy, Λᵢ is the tool-call action space, Mᵢ is internal memory, and πᵢ is the decision function mapping observation histories hᵢ,ₜ to actions.
- **E** — shared environment
- **C** — communication topology (Independent, Centralized, Decentralized, Hybrid)
- **Ω** — orchestration policy

At each timestep: αᵢ,ₜ = πᵢ(hᵢ,ₜ), oᵢ,ₜ = E(αᵢ,ₜ), and the history appends: hᵢ,ₜ₊₁ = hᵢ,ₜ ⊕ (αᵢ,ₜ, oᵢ,ₜ), subject to context-window truncation when |h| > MAX_TOKENS.

### 1.2 Five Topology Ablations

The authors design a structural ablation across two dimensions (orchestrator presence + peer communication):

| Architecture | Comm. Topology | LLM Calls | Seq. Depth | Overhead |
|---|---|---|---|---|
| SAS (Single-Agent) | none | O(k) | k | 0% |
| MAS-Independent | aggregator-only | O(nk)+O(1) | k | 58% |
| MAS-Centralized | orchestrator→workers | O(rnk)+O(r) | r | 285% |
| MAS-Decentralized | all-to-all debate | O(dnk)+O(1) | d | 263% |
| MAS-Hybrid | hierarchical+peer | O(rnk)+O(r)+O(p) | r | 515% |

Where k = max iterations/agent, n = agent count, r = orchestrator rounds, d = debate rounds, p = peer rounds. All runs are compute-matched (mean 4,800 reasoning tokens per trial).

### 1.3 Core Regression Model (Equation 1)

The scaling principle is a mixed-effects regression with 20 parameters:

```
P = β₀ + β₁(I−Ī) + β₂(I−Ī)² + β₃log(1+T) + β₄log(1+nₐ)
  + β₅log(1+O%) + β₆c + β₇R + β₈Ec + β₉log(1+Aᵉtrace)
  + β₁₀P_SA + β₁₁(I×Ec) + β₁₂(Aᵉtrace×P_SA)
  + β₁₃(O%×T) + β₁₄(R×nₐ) + β₁₅(c×I)
  + β₁₆(Ec×T) + β₁₇(P_SA×log(1+nₐ))
  + β₁₈(I×log(1+T)) + β₁₉(Aᵉtrace×T) + ε
```

Key predictors: Intelligence Index I (42–71 range, mean-centered at 57.5), tool count T, agent count nₐ, single-agent baseline P_SA, coordination efficiency Ec = S/(Turns/Turns_SAS), overhead O%, message density c, redundancy R (cosine similarity of outputs), and trace-level error amplification Aᵉtrace.

All predictors standardized (μ=0, σ=1) after log transforms on right-skewed variables.

### 1.4 Decision Boundary for MAS vs SAS

```
P*_SA (standardized) = −β₄/β₁₇ ≈ 0.040/0.236 = 0.170
```

Denormalized threshold: **P_SA ≈ 0.45**. When single-agent baseline exceeds 45%, multi-agent coordination yields diminishing or negative returns.

### 1.5 Key Mechanistic Constants

- **Turn-count power law:** T = 2.72 × (n+0.5)^1.724 (R²=0.974, exponent 95% CI [1.685, 1.763])
- **Message saturation:** S = 0.73 + 0.28 ln(c), R²=0.68, p<0.001
- **Error absorption:** Absorb = (E_SAS − E_MAS)/E_SAS; Centralized achieves best containment via orchestrator verification bottleneck
- **Information gain:** ΔI = ½log(Var[Y|s_pre]/Var[Y|s_post]), computed via 10 Monte Carlo traces per state (τ=0.7)

### 1.6 Three Coordination Regimes

```
(i) Under-coordination (O% < 100): ΔS ≈ +2–4%, mechanisms not engaged
(ii) Optimal band (200% < O% < 300%): Ec ≈ 0.16, strongest error absorption  
(iii) Over-coordination (O% > 400%): Ec ≈ 0.11, protocol complexity dominates
```

### 1.7 Evaluation Protocol

260 total configurations: 4 benchmarks × 9 models × 5 architectures (180 configs) + 2 benchmarks × 8 models × 5 architectures (80 configs). Claude Sonnet 3.7 excluded from SWE-bench/Terminal-Bench (deprecated Feb 2026). 50–100 instances per config; 20-instance subsets for Docker-heavy benchmarks. 5-fold cross-validation with experiment-level holdout. All prompts, tools, and compute matched across architectures.

## 3. Trade-Offs (Wins vs Loses)

| Win | Lose | Magnitude |
|---|---|---|
| MAS improves decomposable tasks (Finance) | MAS destroys sequential tasks (PlanCraft) | +80.8% vs −70.0% |
| Centralized reduces logical contradictions | Centralized is 3.1× less token-efficient | 9.1% contradiction rate vs 21.5 successes/1K tokens |
| Decentralized excels at parallel exploration (BrowseComp +9.2%) | Decentralized fails at sequential constraint satisfaction (PlanCraft −41.5%) | +9.2% vs −41.5% |
| Higher model intelligence (I) yields linear returns | Returns are erased without correct architecture alignment | β_I = 0.126 vs Ec×T = −0.096 |
| Redundancy helps when P_SA < 0.45 | Redundancy becomes wasteful when P_SA > 0.45 | β_R×nₐ = 0.024 but is context-dependent |
| Centralized best error absorption (4.4×) | Centralized creates bottleneck: 3.8× more turns than SAS | Aᵉtrace = 4.4 vs 27.7 turns |
| Adding agents increases parallelism | All-to-all message complexity super-linear, T ∝ n^1.724 | Extrapolation: 157 turns at n=10 |
| Multi-agent works on low-complexity domains (D < 0.40) | Multi-agent degrades on high-complexity domains (D > 0.40) | 0%→+80.8% below threshold, 0%→−70% above |
| ACI better predicts agentic performance | Intelligence Index and ACI only correlated r = 0.45 | R²_CV improves from 0.373 → 0.413 |
| SAS most token-efficient | SAS worst at decomposable tasks | 67.7 vs 13.6 successes/1K tokens but 0.349 vs 0.631 on Finance |

## 4. Design Rationale

**Why regression over architecture labels:** The authors deliberately chose continuous empirical coordination metrics (Ec, Aᵉtrace, R, c, O%) rather than categorical architecture dummies because prior work showed no universal pattern when using labels alone. The five architectures are treated as a structural ablation isolating two key dimensions (orchestrator presence, peer communication). This allows attribution to *mechanisms* rather than "more agents."

**Why agentic vs non-agentic distinction matters:** Prior MAS evaluations on non-agentic benchmarks (GSM8K, HumanEval) showed monotonic improvement via ensemble voting. Agentic tasks introduce sequential error compounding, divergent world states (34% overlap after 10 interactions), and coordination tax — fundamentally different dynamics. The paper explicitly rejects the "more agents is all you need" [Li et al. 2024] hypothesis.

**Why matched compute:** Without equalizing total reasoning tokens across SAS and MAS, gains could be attributed to raw compute increase rather than architectural coordination — an essential confound control that prior work ignored.

**Why ACI over static Intelligence Index:** The moderate correlation (r = 0.45) between static benchmark composites and dynamic agentic performance validates the intuition that "what matters is how good the model is at agentic tasks, not at answering trivia."

## 5. Limitations and Failure Modes

1. **Small cluster count (G=6):** All dataset-level predictors suffer from cluster-robust SE inflation (up to 2.9×). Only single-agent baseline survives both cluster-robust and Holm-Bonferroni corrections. Most interaction terms are *directional patterns*, not confirmed effects.

2. **No cross-family model mixing in main experiments:** All 260 configurations use homogeneous model families. The heterogeneous-mixing experiments (13 configs, Appendix F) show centralized heterogeneous underperforms homogeneous strong-model baseline by a mean 12.6 pp — no clean evidence that model mixing helps.

3. **Limited benchmark diversity:** Only 3 task types represented well (web browsing, finance, Minecraft planning). No embodied, multi-user, long-horizon temporal, or vision-language tasks.

4. **Small instance subsets:** SWE-bench and Terminal-Bench use only 20 instances each → bootstrap CIs of ±20 pp per cell. Individual per-model, per-architecture estimates are noisy.

5. **Prompt sensitivity not explored:** All architectures use identical prompts (by design), but models are known to be prompt-sensitive. Architecture-specific prompt optimization may change ranking.

6. **Cross-domain generalization limited:** LODO cross-validation confirms the regression cannot predict absolute performance across structurally diverse domains without dataset-specific parameters. The 87% selection accuracy is for *within-domain* relative rankings.

7. **No long-horizon evaluation:** Maximum trajectory length controlled; real-world deployments with unbounded interaction lengths may exhibit different scaling.

8. **No non-text modalities:** The framework treats agents as text-only; multimodal agent systems (vision-language, code+vision) are outside scope.

## 6. Transfer to Lyra

### The One Transferable Idea

**The capability-saturation decision boundary (P_SA ≈ 0.45): deploy single-agent when baseline success exceeds ~45%; architect multi-agent only when task decomposability is high and baseline is below threshold.** Lyra's multi-agent swarm can use this as a gating function: before spawning a multi-agent sub-system, measure the single-agent baseline on the task category, compare against the ~45% threshold, and route accordingly. The Ec×T trade-off (β=−0.096) provides a second gate: tool-heavy tasks (>5 tools) amplify coordination tax, so multi-agent dispatch should be avoided or use minimal-overhead decentralized topology.

### Workstream Route
**§4.13 (Swarm/Fleet): Multi-Agent Architecture and Topology** — this paper's five-topology structural ablation, coordination metrics, and decision boundary directly inform Lyra's swarm orchestration policy.

### Impact/Effort/Tier
- **Impact:** 4 — Direct optimization of multi-agent dispatch, replaces heuristic with data-driven gating. Saves tokens by avoiding unnecessary agent fanout.
- **Effort:** 3 — Requires building a performance tracker per task-category (P_SA estimator) and a gating function in the swarm orchestrator, plus adopting Ec/metric monitoring. No new infrastructure.
- **Tier:** **breakthrough** — This is the first principled quantitative rule for "when to use multi-agent" with a measurable decision boundary (87% selection accuracy), replacing the dominant heuristic approach in Lyra's swarm dispatch.
